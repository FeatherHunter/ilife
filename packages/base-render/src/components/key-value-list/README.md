# key-value-list · 档案行

**一句话**：一串「字段：值」的清单 —— 值是主角、标签是配角，**不画点线**，值右对齐成列。

**形态**：本件只落地**形态 A「档案行（两列，值右对齐）」**——出处＝原型墙 `.scratch/ui-组件墙/parts-02-读数与账目.mjs` 的 `.c-kv-row`（2026-09 用户裁定落地的那一形态），按层规重写（原型是一次性代码：无判据、无错误处理、读的是墙稿变量）。
形态键住 `KEY_VALUE_FORMS` 闭集（今天只有 `rows` 一格）——**加第二形态是在闭集里加一格，不是新开一件**（形态是骨架，不是地址）。

## 何时用它（选型三条）

| 你要的 | 用 |
|---|---|
| 一串「字段：值」的**静态**档案（用户档案／物品参数／证件／账户信息） | **本件** |
| 一份账的读数逐项列成账（标签 →点线→ 值，右对齐等宽数字） | `ledger-rows`（账目行） |
| 字段的**旧值 → 新值**对照 | `renderChangeRows`（区块层） |
| 可录入的字段（值即入口） | `renderParamForm`（区块层）／`editableValue` |

**点线不归本件**：点线是「一份账」的语汇（读者顺着点线找右端的数）；档案行是「一件事的字段」，字段与值之间**不画点线**，靠两列列距分家。

## 入参

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `rows` | `KeyValueRow[]` | 必填 | 逐行档案（下表）。空数组＝本件一个字都不出 |
| `heading` | `string` | — | 小标题（`用户档案`／`物品参数`）。不给＝不出标题行 |
| `form` | `'rows'` | `'rows'` | 形态键（闭集；闭集外一律 `badInput`）。形态类走槽位表里的 `form-rows`（`ilife-block-key-value-list-form-rows`） |
| `extraClass` | `string` | — | 附加类名（空格分隔，逐个过类名正则） |

`rows` 的每一行：

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `label` | `string` | 必填 | 字段名。**非空** |
| `value` | `string` | 必填 | 值（**已是给人看的样子**：取整／千分位／单位归调用方）。**非空**；缺值写 `—` |
| `note` | `string` | — | 值的后缀说明（`还需减 3.4 kg`）：住在值位那一格的**下一行**，随值一起右对齐 |
| `num` | `boolean` | `false` | 值是数字串：走等宽字面（多行值右对齐时这一档才真对齐） |

**缺值写成 `—`**（`KEY_VALUE_MISSING`）：空串不是缺值，是错（说不出「这一项到底有没有值」）。

## 契约与不变量（判据逐条断）

1. **值右对齐**（形态 A 的识别特征）：值位 `justify-self:end` ＋ `text-align:right` ⇒ 同一张档案里所有行的值右缘成列；`fs-h3` ＋ 字重 700 压住标签（`fs-sm` ＋ `ink-2`）。
2. **不截断**：长值／长字段名／长说明一律 `overflow-wrap:anywhere`（**永不 `…` 截断**）——值里的日期、金额、单号都是关键语义。
3. **窄宽两档**：容器宽 390 与 1280 下**零横向溢出**（`scrollWidth ≤ clientWidth`）；窄档（<400px）两列收成一列（字段名一行、值一行，都靠左端）。
4. **仅隔行一条发丝线**：行与行之间有线，字段与值之间**无线**（那一段由列距承担）。
5. **各套皮肤下标记逐字节相同**：皮肤只换样式段（取值表），标记一个字节不动。
6. **零 DOM／零内联脚本**：模块代码剥掉字面量后不出现 `document.`／`window.`／`navigator.`；标记里没有 `<script>`、没有 `on*=`。
7. **样式只经 `skinVar()` 读皮肤**：组件里不出现手写的 `var(--ilife-…)`；不写 `:root`／`!important`；不定义新 token 名；全部规则 scope 在 `.<prefix>page-ui` 之下。
8. **响应式一律容器驱动**：本件设 `container-type: inline-size`（它自己就是容器）；收列走 `@container` ＋ `minmax(0,…)`；本件**一条 `@media` 都没有**。
9. **无障碍地板**：`<dt>`／`<dd>` 是原生定义列表配对（读屏按「字段：值」读）；行高下限 `KEY_VALUE_MIN_ROW_PX`（44px，档案行常被包成"改这一项"的入口）；`:focus-visible` 给 2px 可见焦点；数字 `tabular-nums`。

## 常见错法

- 用点线撑起「字段 … 值」（点线归 `ledger-rows`；两件都用点线，读者就分不出"一份账"与"一件事"）；
- 值与标签同级同重（读者分不出哪一半是主角）；
- 值左对齐却一行一个长度（多行扫读时值不成列，右对齐才是本形态的意义）；
- 值太长就用 `…` 截断（单号／日期／证件号截断后不可用）；
- 用 `value: ''` 表达缺值（应当给 `—`）；
- 把可改的字段当成本件（本件是**静态读数**；要"值即入口"用 `editableValue`）。

## 关系

- 与 `ledger-rows` 的分工：`ledger-rows` 是**一份账的读数**（点线 ＋ 合计行），本件是**一件事的字段**（两列 ＋ 无点线）。同一页里前者常是"这一段的合计"，后者是"这一项的参数"。
- `stat-inline` 是本件的**行内**版本（一句里嵌几个数）：要成列用本件，要一句话用 `stat-inline`。
- 样式由页面按需挂 `keyValueListCss()`（加法式：不调它、不挂 `.ilife-page-ui` 的页零命中）。
- 本件暂不提供族汇总入口（同族第二件落地后，由先成立的那件立汇总，照 `sheetCss()` 先例）。
