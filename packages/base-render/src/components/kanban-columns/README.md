# kanban-columns · 看板列

**一句话**：几列并排、列头带计数与「＋」，一件事住在某一列里；**点一张卡拿起，再点目标列那枚收纳按钮，卡就挪到那一列**（手机上同一套标记走得通）。拿起的那张卡站起来，其余每列浮出一条落点线（写出「放这里＝标记为哪一列」），底下多一枚「取消选中」。

它替掉的两种错法：①「想做／在做／做过了混在一张清单里，靠一个字区分」；②「东西摆在哪一列全靠备注里写一句」。

**形态**：本件只落地**形态 `status`「按状态分列」**——出处＝原型墙 `.scratch/ui-组件墙/新件/parts-交互与流程.mjs` 第 88 件的 A 档「按状态分列（含一次挪动与一个空列）」（2026-09 用户三个形态逐格打分，A 档 4/4/4），按层规重写。形态键住 `KANBAN_COLUMNS_FORMS` 闭集（今天只有 `status` 一格，**格号 A 不是接口名**）——**加第二形态是在闭集里加一格，不是新开一件**；闭集外的值一律报 `BlocksError`。同件 B 档「按位置分列 ＋ 列内二级组」打分未过（3/3/3）、**不落**，它的类与规则一个都不搬。

## 何时用它（选型四条）

| 你要的 | 用 |
|---|---|
| 一组东西按**状态**分开摆，人还要把它们从一列挪到另一列（做菜的想做／在做／做过了） | **本件** |
| 只改「完成没有」，分不分列是数据里定死的 | `task-list`（勾选清单） |
| 顺序由人来排、与状态无关 | `drag-sort`（拖拽排序清单） |
| 一件事分几步走完，只看走到哪一步（只读） | `step-flow`（只读步骤条） |

用在哪：私家大厨的「这顿做哪几道」（想做／在做／做过了）、备忘备忘录的心愿按状态归堆、居家管家的待买／已买。

## 入参

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `id` | `string` | 必填 | 看板 `id`（同页唯一，事件 `detail.id` 就是它）。**只许标识符字符** |
| `columns` | `KanbanColumn[]` | 必填 | 各列（**2–4 列**，顺序就是屏上的顺序；**给空列就显式给 `cards: []`**） |
| `pickedKey` | `string` | — | 选中态：被选中那一张卡的机器键（须命中一张卡）。不给＝谁也没选中 |
| `activeCol` | `number` | `1` | 窄档当前列（1 起，≤列数）。**宽档下它不画出来**（几列本来就并排） |
| `form` | `'status'` | `'status'` | 形态键（闭集；闭集外一律 `BlocksError`） |
| `extraClass` | `string` | — | 附加类名（空格分隔，逐个过类名正则） |

**列（`columns` 的每一个元素）**

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `key` | `string` | 必填 | 机器键（事件 `detail.from`／`to` 就是它）。**只许标识符字符**，整份看板内唯一 |
| `name` | `string` | 必填 | 列名（如「想做」）。**非空、且不能只有空白**；长了**换行**，绝不截断 |
| `purpose` | `string` | — | 这一列是干什么的（如「待做的菜」）：列头的第二级字。不给＝列头只有两行 |
| `unit` | `string` | `件` | 计数单位（如「道」；屏上写「2 道」）。给了就不能只有空白 |
| `cards` | `KanbanCard[]` | 必填 | 这一列的卡（**至多 20 张**；**空数组＝设计过的空列**，不是缺席） |

**卡（`cards` 的每一个元素）**

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `key` | `string` | 必填 | 机器键（事件 `detail.key` 原样送出）。**只许标识符字符**，整份看板内唯一（与列键也不许撞） |
| `title` | `string` | 必填 | 卡标题（如「葱油饼」）。**非空、且不能只有空白**；长了**换行**，绝不截断 |
| `meta` | `string` | — | 卡副语，一行一句人话（如「30 分钟 · 面点」）。给了就不能只有空白 |

**入参纪律（两条，判据逐条断）**：

1. **上屏的文字全空白＝拒**（`badInput`）：`'   '` 会在屏上留一块**看得见的空白**（无字列名／无字卡／无字计数单位）。空串＝未给（与全层 `optText` 同口径），**只有空白＝拒**。
2. **入参表以外的键一律拒**（顶层、列、卡三处都是）：多给的键（多半是打错名）不许静默吞掉。

## 契约与不变量（判据逐条断）

1. **整卡就是那颗按钮**：一张卡＝一枚 `<button>`（卡里**没有第二颗按钮**）。点它＝选中，**再点同一张＝取消**，**点另一张＝改选**（单选用一条 `pick` 表达：新的那一张取代旧的）。
2. **挪动不走拖拽**：选中之后，**每一列**都露出／启用一枚 44 高的收纳键（`放到「在做」`）；点哪一列就收到哪一列。**选中卡所在列**的那一枚按不动（卡本来就在这一列）。没有拖拽手势，也没有方向键那一路——手上一根手指就够。
3. **空列是合法态**：`cards: []` 出设计过的空槽（虚线框 ＋ 两句话），**列头与计数一直在**；列里最后一张被收走时，运行时段当场补出空槽（空列不许消失，否则人不知道能往哪儿收）。
4. **挪完四处读数一起重写**（真读数，不是留着旧的）：卡上 `data-ilife-kanban-state`、卡上那枚状态（记号 ＋ 列名）、两端列的计数、底下那句状态句。**收到的卡排在那一列最后**。
5. **状态不只靠颜色**：每列一枚记号（`●`／`▸`／`✓`／`◆`，按列序取）＋卡上写出它现在在哪一列（字）＋落点线写「放这里＝标记为哪一列」——色只是第三重。
6. **列名与计数永不截断**：长了换行；样式段里没有 `text-overflow`／`line-clamp`／`nowrap`。
7. **窄档一列一屏**：本件宽度小于 600px 时，列区一次只留当前那一列，顶上出来一条**分段切换（N 枚真按钮**，当前那一段挂 `aria-pressed="true"`）；宽档整条切换不出（几列本来就并排）。**判的是本件自己的宽度**（`@container`），不是视口宽度——嵌进侧栏／面板时照样按自己的宽度折。
8. **零键盘依赖**：`⌘`／`Esc`／方向键那一路一个都没有，也没有「按住才怎样」；`:focus-visible` 只是给真实键盘用户的无障碍地板。
9. **触控地板**：卡 ≥56 高、收纳键／加键／分段 ≥44 高，卡与卡之间留 8px 缝。
10. **松手才报数**：选中／挪动／取消／加各派发一条**冒泡** `CustomEvent`（`detail` 见下）；本件**不写库**，写库归页面。
11. **样式只经 `skinVar()` 读皮肤**；**宽度只许容器判**（媒体查询只判悬停与减动效）。
12. **幂等**：`<html>` 上一枚 `data-ilife-kanban-runtime` 拦住重复注入（同一段脚本注两次也只绑一次）；每块看板上记一枚 `data-ilife-kanban-bound` 读数。
13. **加法式**：不挂本件事的页面零命中、逐字节不变；换皮肤只换样式，标记逐字节相同。

## 交互契约（页面侧）

```html
<!-- 样式段与标记：kanbanColumnsCss() ＋ renderKanbanColumns(input)；外层挂 .ilife-page-ui 与皮肤类 -->
<script>/* buildKanbanColumnsJs() 产出的那段文本 */</script>
<script>
  document.addEventListener('ilife:kanban-pick', (e) => {
    const { id, key, from } = e.detail;      // 选中了哪一张、它现在在哪一列（只读数，不写库）
  });
  document.addEventListener('ilife:kanban-move', (e) => {
    const { id, key, from, to } = e.detail;  // 卡从哪一列挪到哪一列：按 to 写库，再重渲染
    if (id !== 'kanban-dinner') return;
    setColumn(key, to);
  });
  document.addEventListener('ilife:kanban-cancel', (e) => {
    const { id, key } = e.detail;            // 取消选中：卡原样不动
  });
  document.addEventListener('ilife:kanban-add', (e) => {
    const { id, column } = e.detail;         // 点了某一列的「＋」：往哪一列加，弹什么由页面定
  });
</script>
```

**事件（`detail` 逐字段）**

| 事件 | 什么时候 | `detail` |
|---|---|---|
| `ilife:kanban-pick` | 点一张卡选中（点另一张＝改选，也是这一条） | `{ id, key, from }`：`from`＝它现在在哪一列 |
| `ilife:kanban-move` | 选中之后点了某一列的收纳键 | `{ id, key, from, to }`：两端都是列的机器键 |
| `ilife:kanban-cancel` | 点取消键，或再点同一张卡 | `{ id, key }`：卡原样不动 |
| `ilife:kanban-add` | 点列头那枚「＋」 | `{ id, column }`：往哪一列加（本件不写库） |

## 常见错法

- **把拖拽做成唯一通路**（卡点不动，只能按住拖）——手机上等于没有这个功能；通路是「点卡 ＋ 点目标列的收纳键」，拖拽本件一个字节都不做；
- **空列一空就把列头一起撤掉**——人不知道还能往哪儿收；空列只换内容，列头与计数一直在；
- **挪完不重写计数与卡上那枚状态**——屏上写着「2 道」而列里只剩一张，比没有读数更坏；
- **只靠颜色区分状态**（列换个底色，卡上什么都不写）——色不是唯一信息，记号（形）与列名（字）至少再给一样；
- **列名或计数截断**（`…`）——是哪一列、有几件，截掉一个字都不行；
- **三列同挂在一屏上硬挤**（窄容器里三根细柱）——窄档就是一列一屏 ＋ 分段切换，宽度按**本件自己的宽度**判；
- **拿它当勾选清单**（只改完成没有）——那是 `task-list`；**拿它当排序清单**——那是 `drag-sort`。

**有意偏离原型的地方**：

| 原型里是 | 落地是 | 为什么 |
|---|---|---|
| 挪动靠把卡拖到另一列 | 点卡拿起，再点那一列的收纳键 | 触屏优先法条：拖拽不许是唯一通路；收纳键是每列一枚**看得见、点得到**的按钮 |
| 手机上一列一屏靠横向滚动 | 分段切换（N 枚真按钮）＋ 一列一屏 | 横向滚动在看板上是灾难（触屏优先法条第二节 `kanban-columns` 那一条） |
| 列头「＋」是一枚图标 | 图标 ＋ 44×44 命中盒 ＋ 无障碍名「往「想做」里加一张」 | 触控地板与无障碍名；图标本身没有名字 |
| 列数不限 | 2–4 列、每列至多 20 张 | 再多请调用方先分组（那是调用方的活，不是本件的活）；超过就报 `BlocksError` 而不是默默挤 |
