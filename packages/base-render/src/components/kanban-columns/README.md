# kanban-columns · 看板列

**一句话**：几列并排、列头带计数与「＋」，一件事住在某一列里（**B 档**的列里再挂一层二级组，最小单位是一行物件）；**点一行拿起，再点目标列那枚收纳按钮，那行就挪到那一列**（手机上同一套标记走得通）。拿起的那一行站起来；`status` 档另给出「其余每列一条落点线 ＋ 一枚取消选中」，`grouped` 档不画落点线（靠各列那枚收纳键的字说话，一屏只留一层话）。

它替掉的两种错法：①「想做／在做／做过了混在一张清单里，靠一个字区分」；②「东西摆在哪一列全靠备注里写一句」。

**形态（两档，都是加法）**——出处＝原型墙 `.scratch/ui-组件墙/新件/parts-交互与流程.mjs` 第 88 件的 A／B 两档（2026-09 用户三格逐格打分：A 档 4/4/4 已落地、B 档 3/3/3 ⇒ 优化后 4/4/4 补落），按层规重写。形态键住 `KANBAN_COLUMNS_FORMS` 闭集（**格号 A／B 不是接口名**，键取骨架名）；闭集外的值一律报 `BlocksError`（不静默降级——降级会让调用方以为自己拿到了另一种骨架）。

| 形态键 | 骨架 | 列＝ | 列里装什么 | 最小单位 | 列壳 |
|---|---|---|---|---|---|
| `status`（缺省；**原有那一档，逐字节不动**） | 按状态分列 | 状态（想做／在做／做过了） | `cards`：各列一串卡 | 一张卡 | 纸面 ＋ 发丝线 |
| `grouped` | 按位置分列 ＋ 列内二级组 | 位置（玄关／厨房／卧室） | `groups`：各列一串组，组里是一行行物件 | 一行物件 | ＋ `--shadow` 浮起一档（纸族本就是 `none`） |

`grouped` 档**减层**（「层次由边多改边准」）：组一道 `KANBAN_COLUMNS_GROUP_EDGE_PX`（3px）竖边、组名行底下一道 1px 发丝线，物件行**不再各挂一根竖边**（原型那儿一根组边里再嵌五根行边，左沿六条边在读）。

## 何时用它（选型四条）

| 你要的 | 用 |
|---|---|
| 一组东西按**状态**分开摆，人还要把它们从一列挪到另一列（做菜的想做／在做／做过了） | **本件** |
| 只改「完成没有」，分不分列是数据里定死的 | `task-list`（勾选清单） |
| 顺序由人来排、与状态无关 | `drag-sort`（拖拽排序清单） |
| 一件事分几步走完，只看走到哪一步（只读） | `step-flow`（只读步骤条） |

用在哪：私家大厨的「这顿做哪几道」（想做／在做／做过了）、备忘备忘录的心愿按状态归堆、居家管家的待买／已买。

## 入参

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `id` | `string` | 必填 | 看板 `id`（同页唯一，事件 `detail.id` 就是它）。**只许标识符字符** |
| `columns` | `KanbanColumn[]` | 必填 | 各列（**2–4 列**，顺序就是屏上的顺序；空态请显式给空的那个数组） |
| `pickedKey` | `string` | — | 拿起态：被拿起那一行的机器键（`status` 档＝一张卡、`grouped` 档＝一行物件；须命中看板里真有的那一行）。不给＝谁也没拿起 |
| `activeCol` | `number` | `1` | 窄档当前列（1 起，≤列数）。**宽档下它不画出来**（几列本来就并排） |
| `form` | `'status'` \| `'grouped'` | `'status'` | 形态键（闭集，见上表；闭集外一律 `BlocksError`） |
| `extraClass` | `string` | — | 附加类名（空格分隔，逐个过类名正则） |

**列（`columns` 的每一个元素）**：`key`／`name`／`unit` 两档共用，装东西那个键**按形态分**。

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `key` | `string` | 必填 | 机器键（事件 `detail.from`／`to` 就是它）。**只许标识符字符**，整份看板内唯一 |
| `name` | `string` | 必填 | 列名（如「想做」／`grouped` 档如「玄关」）。**非空、且不能只有空白**；长了**换行**，绝不截断 |
| `unit` | `string` | `件` | 计数单位（如「道」；屏上写「2 道」）。**两档共用一个单位**（`grouped` 档的组计数也用它）。给了就不能只有空白 |
| `purpose` | `string` | — | **只有 `status` 档许给**：这一列是干什么的（如「待做的菜」）：列头的第二级字。不给＝列头只有两行。`grouped` 档给了就报 `BlocksError`（那一档列头只留读数，旁白不上屏） |
| `cards` | `KanbanCard[]` | **`status` 档必填** | **只有 `status` 档许给**：这一列的卡（**至多 20 张**；**空数组＝设计过的空列**，不是缺席） |
| `groups` | `KanbanGroup[]` | **`grouped` 档必填** | **只有 `grouped` 档许给**：这一列的二级组（**至少一组**，顺序就是屏上的顺序；一列合计**至多 20 行**） |

**组（`groups` 的每一个元素，只有 `grouped` 档）**

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `name` | `string` | 必填 | 组名（如「出门要带」）。**非空、且不能只有空白**；永不截断。组**没有机器键**：本件不拿它当数据，落点由结构定（收进来的行走这一列**最后一组**的末尾） |
| `items` | `KanbanGroupItem[]` | 必填 | 组里的物件行（**给空数组 ＝ 设计过的空格**：组名与组计数照常在，屏上不写旁白） |

**物件行（`items` 的每一个元素，只有 `grouped` 档）**

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `key` | `string` | 必填 | 机器键（事件 `detail.key` 原样送出）。**只许标识符字符**，整份看板内唯一（与列键也不许撞） |
| `label` | `string` | 必填 | 物件的名字（如「雨伞」）。**非空、且不能只有空白**；长了**换行**，绝不截断 |
| `value` | `string` | — | 物件的量（如「1 把」「30 g」）。不给＝这一行只有名字（那一格不画，**不写「—」也不写 0**）。给了就不能只有空白 |

**卡（`cards` 的每一个元素，只有 `status` 档）**

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `key` | `string` | 必填 | 机器键（事件 `detail.key` 原样送出）。**只许标识符字符**，整份看板内唯一（与列键也不许撞） |
| `title` | `string` | 必填 | 卡标题（如「葱油饼」）。**非空、且不能只有空白**；长了**换行**，绝不截断 |
| `meta` | `string` | — | 卡副语，一行一句人话（如「30 分钟 · 面点」）。给了就不能只有空白 |

**入参纪律（两条，判据逐条断）**：

1. **上屏的文字全空白＝拒**（`badInput`）：`'   '` 会在屏上留一块**看得见的空白**（无字列名／无字卡／无字计数单位）。空串＝未给（与全层 `optText` 同口径），**只有空白＝拒**；**零宽字符那类不可见字符同样算空白**——`\u200b`（零宽空格）、`\ufeff`、`\u00ad`、`\u200e`／`\u200f`、`\u2060` 都算；`String.prototype.trim()` 剥不掉它们（它们不是 Unicode WhiteSpace），件先把这一段剥掉再判。
2. **入参表以外的键一律拒**（顶层、列、卡三处都是）：多给的键（多半是打错名）不许静默吞掉。**自有的不可枚举键与原型链上继承来的键同样算**（只走 `Object.keys` 会漏掉这两类；件查的是自有的全部键名 ＋ `for…in` 整条链）。

## 契约与不变量（判据逐条断）

1. **整行就是那颗按钮**：`status` 档一张卡＝一枚 `<button>`（卡里**没有第二颗按钮**），`grouped` 档一行物件同理。点它＝拿起，**再点同一行＝取消**，**点另一行＝改选**（单选用一条 `pick` 表达：新的那一行取代旧的）。拿起的那一行挂 `is-picked`（＋ `aria-pressed="true"`）——**渲染期与运行时段写的是同一个类名**：只在渲染期写它的话，真机上点出来的拿起态就是没有那一档形。
2. **挪动不走拖拽**：每一列**一直带着**一枚 44 高的收纳键（`放到「在做」`，它不藏起来）；选中一张卡之后那些收纳键**启用**，点哪一列就收到哪一列。**选中卡所在列**的那一枚按不动（卡本来就在这一列），没选中时整排按不动。没有拖拽手势，也没有方向键那一路——手上一根手指就够。
3. **空列是合法态**：`cards: []` 出设计过的空槽（虚线框 ＋ 两句话），**列头与计数一直在**；列里最后一张被收走时，运行时段当场补出空槽（空列不许消失，否则人不知道能往哪儿收）。
4. **挪完四处读数一起重写**（真读数，不是留着旧的）：卡上 `data-ilife-kanban-state`、卡上那枚状态（记号 ＋ 列名）、两端列的计数、底下那句状态句。**收到的卡排在那一列最后**。
5. **状态不只靠颜色**：每列一枚记号（`●`／`▸`／`✓`／`◆`，按列序取）＋卡上写出它现在在哪一列（字）＋落点线写「放这里＝标记为哪一列」——色只是第三重。
6. **列名与计数永不截断**：长了换行；样式段里没有 `text-overflow`／`line-clamp`／`nowrap`。
7. **窄档一列一屏**：本件宽度小于 600px 时，列区一次只留当前那一列，顶上出来一条**分段切换（N 枚真按钮**，当前那一段挂 `aria-pressed="true"`）；宽档整条切换不出（几列本来就并排）。**判的是本件自己的宽度**（`@container`），不是视口宽度——嵌进侧栏／面板时照样按自己的宽度折。
8. **零键盘依赖**：`⌘`／`Esc`／方向键那一路一个都没有，也没有「按住才怎样」；`:focus-visible` 只是给真实键盘用户的无障碍地板。
9. **触控地板**：卡 ≥56 高、**一行物件 ≥44 高**、收纳键／加键／分段 ≥44 高，相邻两行之间留 **8px** 缝（`KANBAN_COLUMNS_GAP_PX`；`grouped` 档组与组之间更宽一档）。拿起的行自己往上挪 2px（`KANBAN_COLUMNS_LIFT_PX`，「站起来」那道形），所以**它与上面那行之间那道缝是 8−2＝6**——全件只此一处允许压掉地板，其余每一道缝一律 ≥8；两枚常量上都写着这条口径，判据按它们算。
10. **松手才报数**：选中／挪动／取消／加各派发一条**冒泡** `CustomEvent`（`detail` 见下）；本件**不写库**，写库归页面。
11. **样式只经 `skinVar()` 读皮肤**；**宽度只许容器判**（媒体查询只判悬停与减动效）。
12. **幂等**：`<html>` 上一枚 `data-ilife-kanban-runtime` 拦住重复注入（同一段脚本注两次也只绑一次）；每块看板上记一枚 `data-ilife-kanban-bound` 读数。
13. **加法式**：不挂本件事的页面零命中、逐字节不变；换皮肤只换样式，标记逐字节相同。**两档之间也是加法**：`grouped` 的类与规则一条不落地挂在 `.is-grouped` 之下（`status` 档的标记与样式逐字节不变），加第三档就是往 `KANBAN_COLUMNS_FORMS` 里再加一格、再加一支骨架。
14. **`grouped` 档的减层**（「层次由边多改边准」）：组边一道 `KANBAN_COLUMNS_GROUP_EDGE_PX`（3px）＋ 组名行底下一道 1px 发丝线；**物件行不带自己的竖边**（行上那道 2px 是透明色的槽位，只为「拿起时不横跳」），拿起的那一行换成主色侧标。全档只有这两处边。
15. **`grouped` 档一屏只留一层话**：列头一行「列名 ＋ 计数」、组名行一行「组名 ＋ 组计数」、物件行一行「名字 ＋ 量」；**没有落点线、没有空槽那两句旁白**，行里也不再重复列名与组名。原型里那些旁白（列头第二级字「进门这一块」那类、以及随格的 `c-kan-cap` 长口径）**一个字节都不搬**：`grouped` 档的列不许给 `purpose`，给了就是 `BlocksError`。
16. **`grouped` 档的挪动落点**：收进来的行落进目标列**最后一组**的末尾（组是那一档的格子，落在列身上就成了没有组头的孤儿行）；落地后**两端的列计数与那两组的组计数一起重写**（组计数也是读数，错一个数屏上就在说谎）。空掉的组只把计数写成 0，组名行一直在。

## 交互契约（页面侧）

```html
<!-- 样式段与标记：kanbanColumnsCss() ＋ renderKanbanColumns(input)；外层挂 .ilife-page-ui 与皮肤类 -->
<script>/* buildKanbanColumnsJs() 产出的那段文本 */</script>
<script>
  document.addEventListener('ilife:kanban-pick', (e) => {
    const { id, key, from } = e.detail;      // 选中了哪一张、它现在在哪一列（只读数，不写库）
  });
  document.addEventListener('ilife:kanban-move', (e) => {
    const { id, key, from, to } = e.detail;  // 卡从哪一列挪到哪一列：按 to 写库，再重渲染
    if (id !== 'kanban-dinner') return;
    setColumn(key, to);
  });
  document.addEventListener('ilife:kanban-cancel', (e) => {
    const { id, key } = e.detail;            // 取消选中：卡原样不动
  });
  document.addEventListener('ilife:kanban-add', (e) => {
    const { id, column } = e.detail;         // 点了某一列的「＋」：往哪一列加，弹什么由页面定
  });
</script>
```

**事件（`detail` 逐字段）**

| 事件 | 什么时候 | `detail` |
|---|---|---|
| `ilife:kanban-pick` | 点一张卡选中（点另一张＝改选，也是这一条） | `{ id, key, from }`：`from`＝它现在在哪一列 |
| `ilife:kanban-move` | 选中之后点了某一列的收纳键 | `{ id, key, from, to }`：两端都是列的机器键 |
| `ilife:kanban-cancel` | 点取消键，或再点同一张卡 | `{ id, key }`：卡原样不动 |
| `ilife:kanban-add` | 点列头那枚「＋」 | `{ id, column }`：往哪一列加（本件不写库） |

## 常见错法

- **把拖拽做成唯一通路**（卡点不动，只能按住拖）——手机上等于没有这个功能；通路是「点卡 ＋ 点目标列的收纳键」，拖拽本件一个字节都不做；
- **空列一空就把列头一起撤掉**——人不知道还能往哪儿收；空列只换内容，列头与计数一直在；`grouped` 档空掉的组同理（组名行与那个 0 一直在）；
- **挪完不重写计数与卡上那枚状态**——屏上写着「2 道」而列里只剩一张，比没有读数更坏；`grouped` 档还要把**两端的组计数**一起重写，不然组名行那一句就是旧的数；
- **只靠颜色区分状态**（列换个底色，卡上什么都不写）——色不是唯一信息，记号（形）与列名（字）至少再给一样；
- **列名或计数截断**（`…`）——是哪一列、有几件，截掉一个字都不行；
- **三列同挂在一屏上硬挤**（窄容器里三根细柱）——窄档就是一列一屏 ＋ 分段切换，宽度按**本件自己的宽度**判；
- **在 `grouped` 档往屏上补旁白**（列头第二级字「这块地方是干什么的」、空组的「这一格现在是空的」）——一屏只留一层话：那一档的列头与组名行就是读数，旁白一律写进说明书，别写进屏面；
- **`grouped` 档给错东西**（列里给 `cards`、给 `purpose`、物件行只有空白串的量）——一律报 `BlocksError`：静默收下会让调用方以为画出来了；
- **拿它当勾选清单**（只改完成没有）——那是 `task-list`；**拿它当排序清单**——那是 `drag-sort`。
