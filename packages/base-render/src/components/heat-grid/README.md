# heat-grid · 热力格

**一句话**：行是一个维度（时段／周次）、列是星期，每一格的**深浅**表示量的大小（**形态 A**＝行时段 × 列星期 ＋ 峰值符号），**必带一档色键**。

## 何时用它（选型四条）

| 你要的 | 用 |
|---|---|
| 「哪一格更忙」——两个维度交叉处的量 | **本件** |
| 「哪几天有记录」——一维的有无 | `punch-strip`（打孔格带，同族已落地） |
| 「这一整块怎么分的」 | `stacked-bar`（构成条，同族） |
| 「离目标多远」——一个数对一个目标 | `progress-ring`（进度环，同族） |

用在哪：作息管家（作息热力）／卡路里（摄入或运动热力）／私家大厨（下厨热力）。

## 入参

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `title` | `string` | 必填 | 卡头标题（`作息 · 一周`） |
| `stamp` | `string` | — | 卡头右端那句（`3 月 9–15 日`／`单位：条`）；不给＝不出 |
| `unit` | `string` | — | 读数单位（`条`／`千卡`）：色键的数字区间要用它；不给＝区间只有数字 |
| `rows` | `{label,values}[]` | 必填 | 各行：**1–12 行**，`label` 非空串，`values` **恰好 7 个数**（≥ 0 的有限数） |
| `weekdays` | `string[]` | `['周一'…'周日']` | 列头，**恰好七枚**（列维度就是一周七天） |
| `levelStops` | `number[]` | `[2,4,6]` | 分档上界，**恰好三个、严格递增的非负整数**；改它会把色键区间一起改 |
| `facts` | `{label,value,sub?}[]` | — | 右侧读数（合计／峰值／最忙那一格）；不给＝不出那一列 |
| `note` | `string` | — | 脚注一句人话；不给＝不出 |
| `form` | `'matrix'` | `'matrix'` | 形态闭集（本件只落地形态 A）；闭集外报 `BlocksError` |
| `extraClass` | `string` | — | 附加类名（空格分隔，逐个过类名正则） |

`facts[].value` 收「已经是给人看的样子」的串；缺值写成 `—`（`HEAT_GRID_MISSING`），**不许写 0、不许留空**。

**行（`rows` 的每一个元素）**

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `label` | `string` | 必填 | 行标签（`00–04`／`第 1 周`），**永不换行、永不截断** |
| `values` | `number[]` | 必填 | 这一行**恰好七个**读数（与 `weekdays` 逐列对齐，≥ 0 的有限数） |

## 示例入参

本件**唯一一份**示例入参（皮肤矩阵判据拿它渲染本件、必须能**直接**渲染成功）：
`rows[].values` 必须**恰好 7 个数**（一周七天，与 `weekdays` 逐列对齐）——
按类型派生的样例一行只给一个数，画不出七天这一维。

```json 示例入参
{
  "title": "作息 · 一周",
  "stamp": "09-21 – 09-27",
  "unit": "条",
  "rows": [
    { "label": "00–04", "values": [7, 6, 5, 6, 7, 2, 1] },
    { "label": "04–08", "values": [6, 6, 6, 5, 6, 3, 2] },
    { "label": "08–12", "values": [4, 5, 4, 4, 4, 3, 3] },
    { "label": "12–16", "values": [2, 2, 3, 2, 2, 4, 5] },
    { "label": "16–20", "values": [3, 4, 4, 3, 3, 5, 6] },
    { "label": "20–24", "values": [5, 5, 6, 6, 5, 7, 6] }
  ],
  "facts": [
    { "label": "合计", "value": "183 条", "sub": "六行 × 七天逐格相加" },
    { "label": "最忙那一格", "value": "周一 00–04（7 条）" }
  ],
  "note": "深浅按 levelStops 分四档；▲ 只点先出现的峰值那一格"
}
```

六行 × 七列＝42 格，`values` 逐行给满七个数；分档用的 `levelStops` 走缺省 `[2,4,6]`，
故色键上的区间是 `0`／`1–2`／`3–4`／`5–6`／`7 以上`。

## 契约与不变量

- **色键与实际着色同一份真值**：`heatGridLevel(value, levelStops)` 是本件唯一的着色函数——
  格子的 `is-l<n>` 与色键上那几段数字区间都从它出（缺省档：`0`／`1–2`／`3–4`／`5–6`／`7 以上`）。
  **读者按色键数格子一定数得对**，这条判据是断出来的，不是看出来的。
- **深浅不是唯一信息**（三条通路）：① 色键给逐档数字区间；② **第一处**峰值格带 `▲`（`HEAT_GRID_PEAK_MARK`；
  并列最大值只点先出现的那一格——全点上会把网格点花，并列几格由右侧 `facts` 去说）；
  ③ 每格 `title` 写「行 · 列：值」，右侧 `facts` 给数字。全零的网格**不点**峰值符号（没有峰值）。
- **窄档不靠横滑**：列宽 `minmax(0,1fr)`、行标签列 `max-content`（宽度由标签自己定）⇒
  七列在任何容器宽度下都摊在容器内；窄容器（`@container ≤ 460px`）只把行高压到 22px、列距收到 1px，
  **不减列、不藏 `overflow-x`**（减列就是把一周砍成半周）。
- **行标签永不换行、永不截断**（它是这一行的坐标）；`facts` 的数字列同办。
- 五档深浅**全部算出来**：`is-l0` 是主文字往卡面混 7%（"空"那一档），`is-l1`…`is-l4` 是强调色往卡面混
  28%／52%／78%／100%；强调色变黑时自动退化成灰阶，浅端仍与卡面分得开。
- 宽度只由 `@container` 判（阈 460px），**不写任何 `@media` 宽度查询**（视口宽 ≠ 组件宽）。

## 常见错法

- **只画深浅不给色键** ⇒ 颜色成了唯一信息，读的人只能猜"深的是多还是少"；
- **行列对不齐**：`values` 少一个数会让整行错位（本件当场报 `BlocksError`，不静默补齐）；
- **把一周砍成半周**：窄档减列省下的宽度不值得丢信息 —— 本件的窄档只改行高；
- **拿本件当一维格带**：只有"哪几天有记录"这种一维有无，走 `punch-strip`。

## 关系

- 与 `summary-head` 配对：头给总量，本件给"分布在哪个时段、哪一天"；
- 与 `stacked-bar` 同族（形状与比例）：**一块怎么分**用构成条，**哪一格更忙**用本件。
