# confirm-strip · 二次确认条

**一句话**：删记录之前的那一问 —— 上面把**要删的逐条点名**（名称 ＋ 旁证 ＋ 值）、**删几条**、**能不能撤销**三件事摆清楚，下面两个按钮：左安全（「再想想」）、右危险（按钮上自己写着动词与条数：「删掉这 3 条」）。

**形态**：本件只落地**形态 A「清单式：把要删的列出来」**——出处＝原型墙 `.scratch/ui-组件墙/parts-09-选择与反馈.mjs` 的 47 二次确认条（2026-09 用户裁定落地的那一形态），按层规重写（原型是一次性代码：无判据、无错误处理、读的是墙稿变量）。
形态键住 `CONFIRM_STRIP_FORMS` 闭集（今天只有 `list` 一格）——**加第二形态是往闭集里加一格，不是新开一件**（形态是骨架，不是地址）。

## 何时用它（选型三条）

| 你要的 | 用 |
|---|---|
| 删记录之前**问一句**：删什么、删几条、能不能撤销 | **本件** |
| 只是告知（「已保存」「已复制」），不需要表态 | `toast`（提示条） |
| 出错了要用户重试／看原因 | `error-receipt`（错态） |
| 分段落的删除确认（要标题、要图标、要滚动） | 后续的 `dialog`（对话框）——本件是**条**，不是浮层 |

**没有要删的东西就不走本件**：`items` 必填且非空（「说不出删哪几条」的那一问不成立），空态因此**不适用**——本件没有「空态」这一档。

## 入参

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `dangerVerb` | `string` | 必填 | 危险动词（**动词打头**，「删掉」「永久删除」「丢弃」）。**不许**是「确定」这类空词、**不许**带空白，闭集外一律 `badInput` |
| `count` | `number` | 必填 | 删几条（整数 ≥1），**必须等于 `items` 的条数** |
| `items[]` | `ConfirmStripItem[]` | 必填 | 要删掉的每一条（非空数组，逐条点名） |
| `items[].name` | `string` | 必填 | 这一条叫什么（长名换行，不许 `…`） |
| `items[].meta` | `string` | — | 旁证：时间／域／账户／分类 |
| `items[].value` | `string` | — | 值：金额／热量／字数（右对齐等宽数字，永不截断） |
| `undoable` | `boolean` | 必填 | 能不能撤销（**必须表态**） |
| `undoHint` | `string` | — | 撤销入口与保留期（`undoable: true` 时**必填**；`false` 时给了即 `badInput`） |
| `loss` | `string` | — | 不可撤销的后果话（只在 `undoable: false` 时有效；不给＝`CONFIRM_STRIP_LOSS_DEFAULT`） |
| `title` | `string` | — | 题面（缺省由本件拼「要删掉这 3 条吗？」；自己写时也要点名条数） |
| `unit` | `string` | `'条'` | 量词 |
| `keepLabel` | `string` | `'再想想'` | 安全按钮的字 |
| `backup` | `boolean` | `false` | 要不要出「删之前先备份」那一项 |
| `backupLabel` | `string` | — | 备份项的措辞（只在 `backup: true` 时有效） |
| `state` | `'rest' \| 'busy' \| 'disabled'` | `'rest'` | 状态三档；`disabled` 时**必填** `disabledHint`，其余状态给了 `disabledHint` 即 `badInput` |
| `disabledHint` | `string` | — | 为什么现在不能做（如「这一天已经锁定，先解锁再删」） |
| `form` | `'list'` | `'list'` | 形态键（闭集） |
| `extraClass` | `string` | — | 附加类名（空格分隔，逐个过类名正则） |

**本件自己拼出来的三处字**（调用方写不出来、也就不用写）：题面（缺省「要删掉这 3 条吗？」）、危险按钮（恒为 `<动词>这 <条数> <量词>`）、状态行（`busy` 时「正在删掉这 3 条…」）。

## 契约与不变量（判据逐条断）

1. **点名**：`items` 逐条上屏（名称／旁证／值），`items.length === count`（对不上即 `badInput`），条数另落 `data-ilife-confirm-count`（页面重算与事件都读这个机器读数，不从字面抠数字）。
2. **危险按钮写动词**：按钮的字**没有**「确定／确认／好」这一档（`CONFIRM_STRIP_BARE_WORDS` 闭集当场拦），且恒带条数 —— 「按下去会怎样」写在按钮上。
3. **位置**：安全动作在左、危险动作在右（`margin-left:auto`）；标记顺序 ＝ 读屏顺序 ＝「先给退路、再给危险」（窄容器下改一列时顺序不变）。
4. **危险档不靠单色**：① 左边 4px 危险色粗条 ＋ 危险软底；② `undoable: false` 时整条换 `3px double` **双线框**、危险按钮字重提到 800；③ 徽标（`可撤销`／`不可撤销`）与后果话前半句（`可以撤销`／`不能撤销`）**都是字**。把色抽掉，三套皮肤下仍读得出「重」——大字报刊皮肤下强调色是墨黑，只靠红的危险档在那里会塌。
5. **三态不跳版**：`rest`／`busy`／`disabled` 只改按钮可点性与状态行的字；状态行**恒占位**（`min-height:1.5em`）⇒ 三态互切时高度逐像素不变（判据在真机上量）。
6. **触控目标 ≥44×44**：两个按钮的命中盒与备份项整行都不小于 `CONFIRM_STRIP_TOUCH_MIN_PX`（44）；相邻目标间距 ≥8px。
7. **两档几何**：容器宽 390 与 1280 下**零横向溢出**（`scrollWidth ≤ clientWidth`）；`name`／`meta` 可换行、`value` 不换行也不截断（关键语义不截）。
8. **三套皮肤下标记逐字节相同**：皮肤只换样式段（取值表），标记一个字节不动。
9. **零 DOM／零内联脚本**：模块代码剥掉字面量后不出现 `document.`／`window.`／`navigator.`；产出的标记里没有 `<script>`、没有 `on*=` 内联事件处理器；DOM 只出现在 `buildConfirmStripJs()` 产出的文本里。
10. **样式只经 `skinVar()` 读皮肤**：不写手写的 `var(--ilife-…)`，不写 `:root`／`!important`，不定义新 token 名，全部规则 scope 在 `.<prefix>page-ui` 之下；窄档只走 `@container`（判本件自己的宽度），媒体查询只判设备能力（`hover`／`pointer`／`prefers-reduced-motion`）。
11. **无障碍地板**：`role="group"` ＋ `aria-label`（题面）；状态行 `role="status"`（禁用／执行中的原因写在控件旁边）；`:focus-visible` 给 2px 可见焦点（按钮与备份复选框都有）；`disabled` 时 `cursor:not-allowed`；长串 `overflow-wrap:anywhere`。

## 运行时（`buildConfirmStripJs()`）

| 事件 | 谁派发 | `detail` |
|---|---|---|
| `ilife:confirm` | 点危险按钮 | `{ action: 'danger', count, unit, irreversible, backup }` |
| `ilife:confirm-cancel` | 点安全按钮，或焦点在本条内按 `Esc` | `{ action: 'keep', count, unit, irreversible, backup }` |

- **委派 ＋ 幂等**：`document` 上一枚 `click`、一枚 `keydown`；页面里放两份运行时也只派发一条事件（守卫写在 `document.documentElement` 上），绑定后逐条打 `data-ilife-confirm-bound`。
- **按不动就不派发**：按钮 `disabled`、或这条的状态不是 `rest` → 一个字节都不派发。
- **本件不碰数据**：页面接事件自己删记录；要出「正在删…」就在重渲染时给 `state: 'busy'`。
- **无脚本降级**：这段不跑时，删什么、删几条、能不能撤销照常可读，只是按不动。

## 常见错法

- 按钮写「确定」/「取消」—— 读的人不知道按下去会删掉什么（本件直接把空词拦在渲染期）；
- 只说「要删掉这 3 条？」却不把三条列出来 —— 用户得回上一屏比对；
- 「可撤销」只写在颜色里（没有那句「去哪儿撤销、保留多久」）—— 说了可撤销就要说得出入口；
- 不可撤销却只把红色加深 —— 抽掉色就没了分量（本件还有双线框与字重）；
- 拿本件当「通用确认框」（要标题、要表单、要滚动）—— 那是 `dialog`（浮层）的活；
- 在同一页摆两条确认条 —— 用户分不清哪一条在问哪件事（一次问一件）。
