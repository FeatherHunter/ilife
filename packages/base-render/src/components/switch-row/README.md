# switch-row · 开关行（**重做件**）

**一句话**：设置页的一行 —— **标签 ＋ 说明句**（左）／**固定一枚状态字**（中）／**开关本体**（右）。
开与关**三样同时给**：**形**（轨道实心／空心 ＋ 滑块贴左／贴右）、**字**（`已开`／`已关`）、**色**（`ok` 只是第三样）。

**为什么重做**：原型墙里这一件的三个形态在中性皮肤下 4 分、在纸面与报刊下都是 **2 分**，
是 60 件里**唯一一处跨形态系统性缺陷**（出处：`.scratch/ui-组件墙/重做设计口径.md` 第 1 节）。
病根只有一条 —— **开与关只靠一个颜色**。皮肤把强调色换成墨黑（大字报刊）或暖红（小票纸）之后，
「已开／已关」就读不出来了。重做后这条不再成立：**把配色全抽掉，靠滑块位置与状态字照样分得开**
（判据里有一条真机断言就是这么量的：注掉全部颜色后再量一遍滑块离左右边的距离与状态字）。
形态键住 `SWITCH_ROW_FORMS` 闭集（今天只有 `row` 一格）——**加第二形态是在闭集里加一格，不是新开一件**。

## 何时用它（选型三条）

| 你要的 | 用 |
|---|---|
| 一个**开／关**的设置项，要写清"打开会怎样" | **本件** |
| "这几项里选一个"（互斥、有多个选项） | `radio-cards`（未落地，原型墙 09） |
| "这几项里勾若干项"（多选、可全不选） | `multi-checks`（未落地，原型墙 09） |

**开关没有"未设置"这一档**：`checked` 缺席就报 `BlocksError`（说不出开还是关，屏上就该没有它）。

## 入参

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `name` | `string` | 必填 | 机器键（变更事件与载荷按它定位）。**非空** |
| `checked` | `boolean` | 必填 | 开还是关。**必须是布尔**（`"1"`／`1` 一律拒） |
| `label` | `string` | 必填 | 这一行的名字（`记完自动同步飞书`） |
| `note` | `string` | 必填 | 说明句：**打开（关掉）会怎样**。必填（后果写不清的开关＝读者只能一个个试） |
| `caliber` | `string` | — | 口径行（这一行影响什么、什么时候生效） |
| `error` | `string` | — | 错误说明：写在控件旁边，输入 `aria-describedby` 指向它（**不只染色**） |
| `disabled` | `boolean` | `false` | 禁用；**必须同时给 `disabledReason`** |
| `disabledReason` | `string` | — | 为什么不能开（如「还没定训练计划，先定计划才能开」） |
| `loading` | `boolean` | `false` | 更新中：状态字换成「更新中」，期间翻不动（被翻就回弹，不静默接受一次会被丢弃的改动） |
| `form` | `'row'` | `'row'` | 形态键（闭集；闭集外一律 `BlocksError`） |
| `extraClass` | `string` | — | 附加类名（空格分隔，逐个过类名正则） |

## 契约与不变量（判据逐条断）

1. **形**：轨道关＝**空心**（透明底 ＋ 一圈 1px 发丝线）、开＝**实心**（填充 ＋ 同色边）；
   滑块关时贴左内距 3px、开时贴右 —— 行程 `SWITCH_ROW_THUMB_TRAVEL_PX = 24px`
   （＝轨道内宽 54 − 滑块 24 − 两侧内距 3＋3）。**离左右边的距离本身就是开合读数**。
2. **字**：开关旁**固定一枚状态字**（`已开`／`已关`／`更新中`，写成子文本，**不用 CSS 生成内容**，
   所以它不依赖样式表更不依赖颜色）；说明句写在标记里并挂 `aria-describedby`；
   禁用态把"为什么不能开"写在控件旁边。
3. **色**：`ok` 只是第三样信号；**零阴影**下轨道的边界靠 `line` 那一圈发丝线立（不是投影，
   小票纸与大字报刊两套皮肤零阴影、圆角接近 0，靠"浮起来"表示关系在那儿都会塌）。
4. **真语义、真键盘**：整行是一枚 `<label>`，里面是一枚原生 `checkbox[role=switch]` ——
   点哪儿都能翻、`空格` 就能翻、读屏器念得出名字与说明。
5. **触控目标 ≥44×44**：开关本体的命中盒是 `56×44`（视觉盒是里面那条轨道 56×32），
   整行也是命中区；`:focus-visible` 给 ≥2px 可见描边（画在轨道那一圈）。
6. **只在真翻时派发**：`ilife:switch-change`（`detail = { name, label, checked, prev }`）；
   禁用与更新中一律**回弹**到 `data-ilife-switch-checked` 那个值，不派发。
7. **三档皮肤下差别只在"形"的取值上**（圆角、字面、线的深浅）：同一堆标记在三套皮肤下**逐字节相同**；
   **开合读数三套皮肤下逐值相同**（滑块行程与状态字不随皮肤变）。
8. **样式只经 `skinVar()` 读皮肤**：不出现手写的 `var(--ilife-…)`、不写 `:root`／`!important`、
   不定义任何自定义属性；全部规则 scope 在 `.ilife-page-ui` 之下（不挂 = 零命中）。
9. **响应式一律容器驱动**：本件设 `container-type: inline-size`；窄容器（< 380px）下文字独占一行、
   状态字与开关落到第二行两端。只有两条 `@media`，判的都是设备能力（`hover:hover`／`prefers-reduced-motion`）。

## 常见错法

- 说明句只写"是否开启同步"（要写**打开会怎样**：往哪儿写、失败怎么办）；
- 禁用却不写原因（读者只能猜；渲染期就会拦）；
- 把开合只做成"变绿／变灰"（这正是本次重做要修的病）；
- 状态字只在 hover 或只让读屏器知道（**视觉上也要有字**）；
- 用 CSS 生成内容（`::before{content:"已开"}`）当状态字（换皮／关样式就丢，标记里查不到）。
- 把开关本体做成 32px 高的小圆点（视觉盒可以小，**命中盒必须 ≥44×44**）。

## 关系

- 与 `radio-cards`／`multi-checks` 的分工：本件是**一个二值项**（开／关），那两件是"选一个"／"勾若干"。
- 与 `task-list`（未落地）的分工：勾选清单是"做完没有"（列表语义），本件是"这个设置开不开"（配置语义）。
- 样式由页面按需挂 `switchRowCss()`，运行时挂 `buildSwitchRowJs()`（加法式：不调不挂的页零命中）。
