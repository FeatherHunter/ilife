# slider-row · 滑块行

**一句话**：一条轨道 ＋ 两端各一枚走一档的键 ＋ 一排常用档，**右侧永远同步一个大数字**。
它替掉的是「只能填一个数、不知道这个数在区间里偏哪头」——轨道底下「底 ＋ 已填」两段给的就是"偏哪头"。

**形态**：本件只落地**形态 A「滑块＋常用档＋加减」**——出处＝原型墙 `.scratch/ui-组件墙/parts-08-表与输入.mjs`
的 `.c-sl.c-sl-a`（2026-09 用户裁定落地的那一形态），按层规重写（原型是一次性代码：无判据、无错误处理、
读的是墙稿自己的变量）。形态键住 `SLIDER_ROW_FORMS` 闭集（今天只有 `track` 一格）——
**加第二形态（双色轨道／刻度尺）是在闭集里加一格，不是新开一件**。

## 何时用它（选型三条）

| 你要的 | 用 |
|---|---|
| 数值在一个**连续区间**里挑，且"挑到哪儿"本身是读数（热量目标／预算／库存下限） | **本件** |
| 一个有上下限、**按档走**的数量（份数／份量／数量），要能一按一档 | `number-stepper` |
| 一个已经算好的**任意值**（不含区间语义）就地改一处 | `editable-value` |

## 入参

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `name` | `string` | 必填 | 机器键（变更事件与载荷按它定位）。**非空** |
| `value` | `number \| null` | 必填 | 当前值。`null` ＝ **未设置**（右侧写 `—`，拖动／按键／点档都会把它定下来）；**缺席＝错** |
| `min` | `number` | 必填 | 区间下限（含） |
| `max` | `number` | 必填 | 区间上限（含）。必须 > `min`，且**必须落在步长格子上** |
| `step` | `number` | 必填 | 步长（> 0，小数位 ≤ 6） |
| `unit` | `string` | — | 单位（`卡`／`元`／`件`） |
| `label` | `string` | — | 名字（`热量目标`）：进 `aria-label`、`aria-valuetext` 与事件 `detail.label` |
| `presets` | `number[]` | — | 常用档（点一下直接落到那一档）。每枚必须落在 `[min, max]` 的格子上、不许重复 |
| `caliber` | `string` | — | 口径行：区间与常用档怎么定的 |
| `error` | `string` | — | 错误说明：写在控件旁边，控件 `aria-describedby` 指向它（**不只染色**） |
| `disabled` | `boolean` | `false` | 禁用；**必须同时给 `disabledReason`** |
| `disabledReason` | `string` | — | 为什么不能拖（写在控件旁边，并被 `aria-describedby` 指到） |
| `loading` | `boolean` | `false` | 更新中：状态字换成「更新中」、大数字宽度锁住不跳版、期间不接输入 |
| `form` | `'track'` | `'track'` | 形态键（闭集；闭集外一律 `BlocksError`） |
| `extraClass` | `string` | — | 附加类名（空格分隔，逐个过类名正则） |

## 示例入参

本件**唯一一份**示例入参（皮肤矩阵判据拿它渲染本件、必须能**直接**渲染成功）：
`max` 必须**大于** `min`，且 `max`／`value`／`presets` 每一枚都要**落在步长格子上**（`min ＋ k × step`）——
按类型派生的样例把 `min`／`max` 都给成 `1`。

<!-- 示例入参：皮肤矩阵判据拿它渲染本件，必须能直接渲染成功 -->
```json 示例入参
{
  "name": "calorie-target",
  "label": "热量目标",
  "value": 1800,
  "min": 1200,
  "max": 3000,
  "step": 50,
  "unit": "卡",
  "presets": [1500, 1800, 2100, 2400],
  "caliber": "区间 1,200–3,000 卡，加减每次 50 卡；常用四档是按目标体重算的"
}
```

`1200 ＋ k × 50` 这条格子上的每一档都落得到：`max` 是 `1200 ＋ 36 × 50`、`value: 1800` 是 `1200 ＋ 12 × 50`。

## 契约与不变量（判据逐条断）

1. **右侧那个大数字永远同步**：拖动（`input`）、按档、按 ±（`click`）三条路都写同一枚 `-number`；
   数字走等宽字（`font-variant-numeric: tabular-nums`），位数变了不跳版。
2. **变更事件只在落定时派发**：拖动过程只同步读数；松手（`change`）与按档／按键派发
   `ilife:slider-change`（`detail = { name, label, value, prev, unit }`，`prev` 读的是**已落定**的那个值）。
   "拖回原位"不产生事件。
3. **键盘与读屏器走原生**：轨道是本件的自绘底条 ＋ 一枚原生 `<input type="range">`（透明轨道 ＋ 自绘拇指）
   —— `←`／`→` 各走一档、`aria-valuenow`／`aria-valuetext` 都是原生给的，本件不另造一套。
4. **触控目标 ≥44×44**：两端键、常用档、轨道（含拇指）都是 44 高；相邻触控目标留 8px 缝（不做连体键）。
5. **到边界给字，不给灰**：值到下限／上限时对应那枚键落 `disabled`，状态字位写「已到下限」／「已到上限」——
   `accent` 在小票纸与大字报刊两套皮肤里接近墨色，只靠颜色读不出"还能不能再按"。
6. **未设置是设计过的空态**：`value: null` → 大数字写 `—`、已填比例 0、状态字「未设置」。
7. **样式只经 `skinVar()` 读皮肤**：不出现手写的 `var(--ilife-…)`、不写 `:root`／`!important`、
   不定义任何自定义属性；全部规则 scope 在 `.ilife-page-ui` 之下（不挂 = 零命中）。
8. **响应式一律容器驱动**：本件设 `container-type: inline-size`；窄容器（< 380px）下轨道独占一行。
   只有两条 `@media`，判的都是设备能力（`hover:hover`／`prefers-reduced-motion`）。
9. **数学口径**：`value`／`presets`／`max` 都必须在步长格子（`min ＋ k × step`）上并落在 `[min, max]` 里；
   越界或不在格子上**渲染期就报 `BlocksError`**（否则右侧大数字与拇指位置会对不上）。

## 常见错法

- 用 `value: undefined` 表达"还没定目标"（未设置要显式给 `null`）；
- 把 `max` 给成一个走不到的值（`min=1200, step=50, max=3010`）——最后一档永远落不到；
- 想在拖动过程中就重算整页（`input` 一路风暴）：本件把事件放在**落定**时，读数同步本来就是实时的；
- 只把边界做成"变灰"（读不出是"到底了"还是"坏了"——状态字那一枚就是为这来的）;
- 在 `presets` 里塞一个越界的值（点一下就会跳出区间）。

## 关系

- 与 `number-stepper` 的分工：本件在**连续区间**里挑位置（轨道是骨架）；`number-stepper` 按**档**加减（键是骨架）。
- 与 `scale-bar` 的分工：`scale-bar` 是**只读**的比例形状（值／目标），本件是**可改**的输入控件；
  两者画线的几何常量各住自己的目录（本件不引用 `scale-bar`）。
- 样式由页面按需挂 `sliderRowCss()`，运行时挂 `buildSliderRowJs()`（加法式：不调不挂的页零命中）。
