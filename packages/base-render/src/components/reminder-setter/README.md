# reminder-setter · 提醒设置

**一句话**：给一条提醒设三件事——**什么时候响 ／ 提前多久 ／ 走哪条通知**，一行只做一个决定；日期与时间不走精确拖点，走两枚 44×44 的步进键夹一枚读数（手机上「点得到」）；设完底下**一行复述**读出现在设的是什么（`每天 2026-09-26 22:30`）。

它替掉的两种错法：①「提醒只有一个小铃铛，点开只有一个时间格，重复与提前量根本没法设」；②「设了每天却按单次响，想提前提醒只能把时间提前十分钟，结果记的是错的时间」。

**一屏只有三层话**（2026-09-25 用户口径：原型里写了好多文字、看起来很混乱）：**它是什么**（抬头「「记体重」的提醒」）＋ **现在设的是多少**（选中态、两枚读数、唯一那行复述）＋ **能按什么**（三排可点项）。同一个数只印一次（机器读数住在根上的 `data-*`），读数一行说完。**原型里的旁白与口径句一句都不上屏**——「挑一次或重复，别混着猜」「可选，给容易忘的事留一道」「可多选，至少留一条；全关掉这条提醒就不存在」「免打扰时段（23:30–07:00）里会顺延…」这些话留在本说明书里，不进屏面。

**形态**：本件只落地**形态 `decisions`「一行一个决定」**——出处＝原型墙 `.scratch/ui-组件墙/新件/parts-交互与流程.mjs` 第 89 件的 A 档（2026-09 起用户逐格打分，三套皮肤都打 4 分），按层规重写。形态键住 `REMINDER_SETTER_FORMS` 闭集（今天只有 `decisions` 一格，**格号 A 不是接口名**）——**加第二形态是在闭集里加一格，不是新开一件**；闭集外的值一律报 `BlocksError`。同件 B 档「一天刻度上摆点，再改这个点的三个决定」打分未过、**不落**，它的类与规则（刻度基线、选中点引线、图例）一个都不搬。

## 何时用它（选型五条）

| 你要的 | 用 |
|---|---|
| 设一条**会响的东西**：什么时候响、重不重复、提前多久、走哪条通知 | **本件** |
| 选一段**区间**（× 月 × 日 到 × 月 × 日），选完就完事 | `date-range`（日期区间） |
| 一组**预设时间段**，用来**查**数据（近 7 天／本月） | `window-picker`（窗口选择） |
| 只读地看「还有多久到期」 | `due-row`（到期行） |
| 一次勾一批（多条待办各勾一下） | `multi-checks`（多项勾选） |

用在哪：备忘录的提醒（记体重／吃药）、作息管家的日程、记账的还款提醒、卡路里的喝水与补记提醒。

## 入参

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `id` | `string` | 必填 | 机器键（事件 `detail.id` 就是它）。**只许标识符字符** |
| `title` | `string` | 必填 | 给哪条提醒设（如「记体重」）。**非空、且不能只有空白**；屏上写「「记体重」的提醒」 |
| `repeats` | `ReminderSetterOption[]` | 必填 | 什么时候响那一排（**2–4 档**，顺序＝屏上顺序） |
| `repeat` | `string` | 必填 | 现在选的是哪一档（须命中 `repeats` 里的一枚） |
| `time` | `string` | 必填 | 提醒时间 `HH:MM`（24 小时制）。**分钟要落在 5 分钟那一档上**（改法是步进键，落不到的点屏上点不出来） |
| `startDate` | `string` | 必填 | 第一次从哪一天 `YYYY-MM-DD`（必须是真实存在的一天） |
| `leads` | `ReminderSetterOption[]` | 必填 | 提前多久那一排（**2–4 档**） |
| `lead` | `string` | 必填 | 现在选的是哪一档（须命中 `leads` 里的一枚） |
| `routes` | `ReminderSetterOption[]` | 必填 | 走哪条通知那一排（**1–4 档**；形是方框＝这条可以多选） |
| `chosen` | `string[]` | 必填 | 勾上的通知档（`routes` 里的键，**0–4 个**；给 `[]`＝屏上照实读成「没有通知，不会响」） |
| `form` | `'decisions'` | `'decisions'` | 形态键（闭集；闭集外一律 `BlocksError`） |
| `extraClass` | `string` | — | 附加类名（空格分隔，逐个过类名正则） |

**一档可选值（`repeats`／`leads`／`routes` 的每一个元素）**

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `key` | `string` | 必填 | 机器键（事件 `detail.value`／`state` 里原样送出）。**只许标识符字符**，同一排内唯一 |
| `label` | `string` | 必填 | 屏上那一档的名字（如「每天」／「提前 10 分钟」／「系统通知」）。**非空、且不能只有空白**；长了换行，绝不截断 |

**入参纪律（三条，判据逐条断）**：

1. **上屏的文字全空白＝拒**（`badInput`）：`'   '` 会在屏上留一块**看得见的空白**（无字提醒名／无字档名）。空串＝未给（与全层 `optText` 同口径），**只有空白＝拒**；**零宽字符那类不可见字符同样算空白**——`\u200b`、`\ufeff`、`\u00ad`、`\u200e`／`\u200f`、`\u2060` 都算；`String.prototype.trim()` 剥不掉它们（它们不是 Unicode WhiteSpace），件先把这一段剥掉再判。
2. **入参表以外的键一律拒**（顶层与每一档里都是）：多给的键（多半是打错名）不许静默吞掉。**自有的不可枚举键与原型链上继承来的键同样算**（只走 `Object.keys` 会漏掉这两类；件查的是自有的全部键名 ＋ `for…in` 整条链）。
3. **改不到的值＝拒**：时间的分钟不在 5 分钟格子上、日期不是真实存在的一天、选中的档不在那一排里、同一排里键重了、`chosen` 里的键不在 `routes` 里——一律报 `BlocksError`（给了也点不到的值，比不给更坏）。

## 契约与不变量（判据逐条断）

1. **一行一个决定**：三行——什么时候响 ／ 提前多久 ／ 走哪条通知；宽档左标签右控件（标签列宽上限 `REMINDER_SETTER_LABEL_PX`），窄档折成上下两段（标签仍在控件上面）。
2. **三排可点项都是真按钮**：整枚就是命中盒（≥`REMINDER_SETTER_TOUCH_PX` 高、相邻留 `REMINDER_SETTER_GAP_PX` 缝）；**没有拖拽、没有方向键、没有键帽**——手上一根手指就够。
3. **日期与时间「点得到」**：`22:30` 与 `2026-09-26` 各由**两枚 44×44 的步进键**（`−`／`＋`）夹着，一步 5 分钟、一步 1 天；跨零点绕回（`23:55` 再加一步是 `00:00`）；日期按 UTC 算（不随本机时区跳一天）。**读数永不截断**（样式段里没有省略手段）。
4. **选中态照法条**：有文字的选中面＝底 `accent-soft`、字 `accent-text`、描边 `accent`；**勾与方框走主色实底**（那上面只有一枚勾，没有正文级小字）。
5. **勾选槽位固定**：单选那枚的勾选位**未选也留** `REMINDER_SETTER_TICK_PX` 宽——勾上时不把档名顶歪，一排胶囊的左右沿齐平。
6. **状态不只靠颜色**：选中＝形（勾 ＋ 胶囊／实心方框）＋ 字（档名 ＋ 字重 700）＋ 色（软底）；单选是胶囊、多选是方框，**形状本身就是「这条可以多选」**。
7. **三个决定的隔线走发丝线**：`line` 那一档（比它更淡的线在 `neutral` 下几乎看不见，三块会摊成一片白纸）；卡自己带一层 `shadow`（`paper`／`broadsheet` 的取值本就是 `none`）。
8. **一条通知都不勾＝合法态**：`chosen: []` 时那行复述读成「没有通知，不会响」，**控件不变灰、也不弹解释**（本件没有任何按不动的控件：每一枚在任何状态下都点得动）。
9. **屏上是真读数**：机器读数住在根上的 `data-ilife-reminder-time`／`data-ilife-reminder-start`（**不从 DOM 文本反推**）；改完三处屏面一起重写（时间读数、日期读数、唯一那行复述）。
10. **复述那句口径只有一处**：`reminderSetterRecap()`（渲染期与运行时段**同一份源码**，运行时的 JS 文本里嵌的就是它）；步进同理（`reminderSetterStepTime`／`reminderSetterStepDate`／`pad2`）。
11. **松手才报数**：每次改动派发**一条**冒泡 `CustomEvent`（`detail` 见下）；本件**不写库**，写库归页面。
12. **窄档零横向溢出**：宽度只许容器判（本件自己声明 `@container` 容器；媒体查询只判悬停与减动效，**一条视口宽度查询都没有**）；窄档下时间与日期读数照原样换行，**不 `…` 截断**。
13. **加法式**：不挂本件的页面零命中、逐字节不变；换皮肤只换样式，标记逐字节相同。
14. **幂等**：`<html>` 上一枚 `data-ilife-reminder-runtime` 拦住重复注入；每张卡上记一枚 `data-ilife-reminder-bound` 读数。

## 交互契约（页面侧）

```html
<!-- 样式段与标记：reminderSetterCss() ＋ renderReminderSetter(input)；外层挂 .ilife-page-ui 与皮肤类 -->
<script>/* buildReminderSetterJs() 产出的那段文本 */</script>
<script>
  document.addEventListener('ilife:reminder-setter-change', (e) => {
    const { id, part, value, state } = e.detail;
    // part ∈ repeat／lead／route／time／start；value＝改动那一下的键或新读数
    // state ＝ { repeat, time, startDate, lead, routes }：改完之后的全量读数（按它落盘）
    if (id !== 'rem-weight') return;
    save(id, state);
  });
</script>
```

**事件（`detail` 逐字段）**

| 事件 | 什么时候 | `detail` |
|---|---|---|
| `ilife:reminder-setter-change` | 换一次档／勾掉或勾上一条通知／按一下步进键 | `{ id, part, value, state }`：`part` 是改的是哪一个决定（`repeat`／`lead`／`route`）或哪一格步进（`time`／`start`），`value` 是那一枚的机器键或新的 `HH:MM`／`YYYY-MM-DD` 读数，`state.repeat` 是**那一档的名字**（渲染期与运行时段读的是同一份事实），`state.routes` 是勾上的机器键（顺序＝屏上顺序） |

## 常见错法

- **把时间做成一个精确拖点或一个只能打字的格子**——手机上拖不准、打字要弹键盘；本件是两枚步进键夹一枚读数（点得到、看得见）；
- **把「至少留一条通知」写成一句话或把最后一枚勾灰掉**——屏上多一层话，或者留一枚按不动的控件；正确做法是**照实读出后果**（「没有通知，不会响」）；
- **在屏上加旁白**（「可选，给容易忘的事留一道」这种）——一屏只留一层话，说明住在 README 里；
- **把重复档做成自由文本**（`每天`／`每隔一天` 混着猜）——档名由调用方给成有限几档，机上只认机器键；
- **只改选中态不重写复述**——屏上写着「每天 22:30」而刚点的其实是「就这一次」，比没有读数更坏；
- **单选那枚不留勾选槽位**——勾上时档名被顶歪，一排胶囊左右不齐（这正是原型近两轮修掉的那一处）。

**有意偏离原型的地方**（原型＝`.scratch/ui-组件墙/新件/parts-交互与流程.mjs` 第 89 件 A 档；逐行指得出原型里的原文，没原文的就不是偏离）：

| 原型里是 | 落地是 | 为什么 |
|---|---|---|
| 时间与日期是两枚 `<input type="text">`（打字填 `22:30`／`2026-09-25`） | 两枚 44×44 的步进键（`−`／`＋`）夹一枚读数，一步 5 分钟／1 天 | 触屏优先法条：日期与时间要「点得到」；打字把键盘当成了通路。步长写进常量，时间的分钟必须落在格子上（落不到的值屏上点不出来，故入参拒掉） |
| 三行标签下各有一句解释（「挑一次或重复，别混着猜」「可选，给容易忘的事留一道」「可多选，至少留一条；全关掉这条提醒就不存在」） | 一行都不上屏；「可多选」由**方框这个形**说，「至少留一条」由复述照实读出后果（`没有通知，不会响`） | 用户口径：原型里写了好多文字、看起来很混乱；一屏只留一层话 |
| 复述块是「设完是这样」＋一整句（`每天 22:30 提醒「记体重」；到点准时响一次；走系统通知。`）＋「下一次 09-25 22:30」＋一句免打扰说明 | **一行**：`每天 2026-09-26 22:30` | 读数一行说完；免打扰那句是旁白（它属于提醒引擎的规则，不属于这一屏） |
| 「下一次 09-25 22:30」由原型直接写死 | 改成 `每天 <起始日> <时间>`——**件算得出来的那一件事** | 下一次什么时候响要日历语义（每周几／每月某天／今天过了没），件拿的是**不透明档名**，算不准的读数不该印在屏上；起始日 ＋ 时间是件真算得出来的 |
| 抬头写「「记体重」的提醒 3 个决定」 | 只写「「记体重」的提醒」 | 「3 个决定」是元信息（数下面有几行），不是「它是什么」；一屏只留一层话 |
| 通知那三枚与单选一样是胶囊（靠文案「可多选」区分） | 多选走**方框**、单选走**胶囊**（形状分家） | 形状自己说得出「这条可以多选」，那一句文案才能从屏上撤掉 |
| 只有选中那枚写「✓」 | **未选的单选胶囊也留 14px 勾选槽位** | 原型近两轮的优化点：勾上时不顶歪档名，一排胶囊左右沿齐平 |
| 三块之间的横线写死 `1px solid var(--line2)`（更淡的那一档） | 走 `line`（发丝线）那一档 | 原型近两轮的优化点：更淡的那档在 `neutral` 下几乎看不见，三块会摊成一片白纸 |
| 卡片没有投影 | 卡加一层 `shadow` | 原型近两轮的优化点：`neutral` 那一套里它是一张平摊的白纸；零投影的几套皮肤本来就取 `none`，不吃损 |
