# rank-list · 榜单

**一句话**：按名次排的榜 —— 前三名各占一张卡（第 1 名居中、读数大一号、顶边更粗），第 4 名起逐行；**每一名都给**名次、名称、条、值、占比。

**形态**：本件只落地**形态 A「领奖台」**——出处＝原型墙 `.scratch/ui-组件墙/parts-03-对照与榜单.mjs` 的 `.c-rank-list-a`（2026-09 用户裁定落地的那一形态），按层规重写（原型是一次性代码：无判据、无错误处理、读的是墙稿变量）。
形态键住 `RANK_LIST_FORMS` 闭集（今天只有 `podium` 一格）——**加第二形态是在闭集里加一格，不是新开一件**（形态是骨架，不是地址）。

## 何时用它（选型三条）

| 你要的 | 用 |
|---|---|
| 按名次排的**前几名**：名次＋名称＋条＋值＋占比 | **本件** |
| 一个窗口内部的分布（名称 ｜ 条 ｜ 数值），**不排名次** | `renderDistributionRows`（分布条行） |
| 一个窗口的读数格（若干不排名的 KPI） | `renderKpiCard`（读数小卡） |

**名次归调用方**：`rows` 的顺序就是名次（第 1 项＝第 1 名）。本件不排序、不并列、不算合计。

## 入参

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `rows` | `RankListRow[]` | 必填 | 逐名（下表）。`[]` ⇒ 空串 |
| `unit` | `string` | — | 单位（`元`／`次`／`卡`）：每格跟一枚小字；不给就不出 |
| `caliber` | `string` | — | 口径行：数怎么算的、占比按什么合计；不给＝不出这一行 |
| `form` | `'podium'` | `'podium'` | 形态键（闭集；闭集外一律 `badInput`） |
| `extraClass` | `string` | — | 附加类名（空格分隔，逐个过类名正则） |

`rows` 的每一名（元素字段表）：

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `name` | `string` | 必填 | 名称（「超市买菜」／「鸡蛋灌饼」）。**非空**；长了换行，不许 `…` |
| `value` | `number` | 必填 | 这一名的值。**有限数且 ≥ 0**（不是串） |
| `share` | `number` | 必填 | 占比，**0–100**（越界即错，本件不夹取）。口径归调用方 |
| `note` | `string` | — | 名称下的副语（「早餐 · 1 个」）；不给＝不出这一行 |

**为什么给数不给串**：条长与数字必须同源 —— 给串的话，条长只能由调用方另算一份百分比，「条长按 A、数字写 B」的榜迟早出现。显示串由本件统一出（千分位、最多两位小数、尾零去掉）；占比写成一枚 `xx.x%`。

**为什么占比由调用方给**：窗内合计常常大于本表之和（末尾那行往往是「其他 N 笔」聚合行），本件算不出那个分母，也不该猜。

## 契约与不变量（判据逐条断）

1. **条长同源**：宽度 ＝ 这一名的值 ÷ **全榜最大值**（＝ 100% 的那一名就是榜首）。每一名都给条。
2. **领奖台与逐行区**：前三名（`RANK_LIST_PODIUM_SIZE`）进卡，第 4 名起进逐行区；宽档靠 `order` 把第 1 名摆到中间，**DOM 顺序始终是 1→2→3**（读屏与键盘顺序不乱）。
3. **第一名的三样差异**（色不是唯一信息）：顶边更粗且走强调色 ＋ 读数 × `RANK_LIST_FIRST_VALUE_SCALE` ＋ 名次走强调色的文本档。换到墨黑强调的报刊皮肤，粗顶边与大字号照样读得出。
4. **条不挤名字**：逐行区那一格是「名称 ＋ 条」上下叠着（条在名称下面另起一行）——窄档把名称挤成竖排的路被堵死。
5. **零横向溢出**：容器宽 390 与 1280 两档 `scrollWidth ≤ clientWidth`；名称／副语／口径行一律 `overflow-wrap: anywhere`；样式段里没有 `text-overflow`／`line-clamp`／`white-space: nowrap`（读数值那一格**故意不写** `nowrap`）。
6. **窄档**：容器窄于 `RANK_LIST_NARROW_PX`（560px）时，领奖台三张卡改竖排一列、名次回到自然顺序；逐行区四列不动。
7. **响应式一律容器驱动**：本件设 `container-type: inline-size`；窄档调整走 `@container`；本件**一条 `@media` 都没有**。
8. **三套皮肤下标记逐字节相同**：皮肤只换样式段（取值表），标记一个字节不动。
9. **零 DOM／零内联脚本**：模块代码剥掉字面量后不出现 `document.`／`window.`／`navigator.`；产出的标记里没有 `<script>`，也没有 `on*=` 内联事件。
10. **样式只经 `skinVar()` 读皮肤**：组件里不出现手写的 `var(--ilife-…)`；不写 `:root`／`!important`；不定义新 token 名；全部规则 scope 在 `.<prefix>page-ui` 之下，且只读本件自己的类名。
11. **无障碍地板**：文字色取 `ink`／`ink-2`／`accent-text`（三套皮肤下都过对比地板）；条是装饰（值已以文本上屏）故 `aria-hidden`；`:focus-visible` 给 2px 可见焦点。

## 常见错法

- 只给名次与数值（读者读不出第一名与第二名差多少）—— 条就是把那点差摊开的那一样；
- 只给条不给数（读者读不出准值）—— 值与占比两列必须在；
- 把「其他 N 笔」聚合行当普通行却不说明（口诀：**它进 `name`，口径进 `caliber`**）；
- 让调用方自己排好序却还在本件里再排一遍（名次归调用方，本件不排序、不并列）；
- 窄档硬撑三张卡并排（每张卡里的名称与读数都被挤成竖排）；
- 用条长当跨段的份额读（领奖台卡与逐行区的轨道宽度不同：跨段比份额看占比那一列）。

## 关系

- 与 `renderDistributionRows`（分布条行）的分工：那一件是**不排名次的分布**（占比按窗内合计）；本件是**排名次的榜**（前三名有领奖台）。
- 与 `renderChartBlock`（图表区块）的分工：那一件给图的形状（折线／柱／环）；本件给的是名次清单，榜里不画图。
- 样式由页面按需挂 `rankListCss()`（加法式：不调它、不挂 `.ilife-page-ui` 的页零命中）。
- 本件暂不提供族汇总入口（同族第二件落地后，由先成立的那件立汇总，照 `sheetCss()` 先例）。
