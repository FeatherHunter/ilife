# wizard-shell · 分步录入壳

**一句话**：一趟多问的录入，**一屏只问一句** —— 一条细进度（N 格）→ 读数行「第 n / N 问」→ 大字问题 →
这一问的答法（选项／填空）→ 脚行「上一问／跳过／继续」。它渲染的是**当前那一问**这一屏：整趟有几问、走到第几问由页面给。

它替掉的两种错法：①「5 组字段一屏灌下来，填到一半不知道还剩几步、也不知道哪些已经填过」；
②「填到第 3 步退出去，回来从第 1 步重来」——本件把「当前是第几问」写在根属性上，页面拿它当草稿的坐标。

**形态**：本件只落地原型墙 `.scratch/ui-组件墙/新件/parts-交互与流程.mjs` 第 84 件里**用户打 4/4/4 的那一档＝形态 B「一问一屏（大字问题 ＋ 一条细进度）」**（原型类名前缀 `.c-wiz`），按层规重写
（原型是一次性代码：无判据、无错误处理、读的是墙稿变量）。形态键住 `WIZARD_SHELL_FORMS` 闭集（今天只有 `one` 一格）——
**加第二形态是在闭集里加一格，不是新开一件**（形态是骨架，不是地址）。

## 何时用它（选型三条）

| 你要的 | 用 |
|---|---|
| 一趟**多问**的录入：每问一句话 ＋ 一种答法，问与问之间有先后（首次建档／录物品／初始化） | **本件** |
| 只画「走到第几步」的**只读**步骤条（里面没有答法、没有动作） | `step-flow`（步骤流） |
| 打断式浮层里塞一小段表单（关掉就丢、一次问完） | `dialog`／`drawer-sheet` |

用在哪：卡路里（首次建档）／私家大厨（录入食谱）／居家管家（录物品）／记账（初始化）。

与 `step-flow` 的分工是**容器与指示器**：本件带答法、带推进、带草稿坐标；`step-flow` 只画状态。
与 `dialog`／`drawer-sheet` 的分工是**一整页与浮层**：本件是一整页，草稿留在页里。

## 入参

**这一件渲染的是「当前那一问」这一屏**：`index`／`total` 说的是这一屏在整趟里的位置，页面握着整趟的数据。

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `name` | `string` | 必填 | 机器键（单选组名与件内 `id` 的前缀）。**非空**；同一页内唯一 |
| `question` | `string` | 必填 | 大字问题：这一问在问什么。**非空**；长了换行，不许 `…` |
| `index` | `number` | 必填 | 当前是第几问（**0 起**，整数） |
| `total` | `number` | 必填 | 一共几问（**2–12**，且必须大于 `index`） |
| `options` | `WizardShellOption[]` | 必填 | 选择问的候选（**至少 1 条**）。给了它就不给 `fields` |
| `fields` | `WizardShellField[]` | — | 填空问的格子（**至少 1 格**；填空问必填，与 `options` 恰好给一个） |
| `value` | `string \| null` | `null` | 这一问**已答**的机器值。`null` ＝ 还没答；给了串必须命中一条选项 |
| `why` | `string` | — | 为什么要问这一句（写在问题下面，弱文字） |
| `aside` | `string` | 按 `index` 算 | 读数行的次段；第 1 问上就是「上一问」按不动的那句原因 |
| `hint` | `string` | — | 脚行左端那句（答完这一问会发生什么，如「答完这句就能生成买菜清单」） |
| `nextLabel` | `string` | 末问「完成」／其余「继续」 | 主键上那枚字 |
| `skippable` | `boolean` | `true` | 这一问能不能跳过。`false` ＝ **不摆**那枚「跳过」 |
| `loading` | `boolean` | `false` | 推进中：三枚键一起按不动，主键原地换成 `loadingText`（宽度锁住不跳版） |
| `loadingText` | `string` | `保存中` | 推进中主键上那枚字（只在 `loading` 时给） |
| `disabled` | `boolean` | `false` | 整壳禁用（如这一趟已经交过了）；**`disabledReason` 必填** |
| `disabledReason` | `string` | — | 整壳禁用的原因（写在脚行上方那一行；说不出为什么不许＝读者只能猜） |
| `error` | `string` | — | 这一问的错（写在控件旁边 ＋ `aria-describedby` 指着它；与 `disabled` 不同时给） |
| `confirmText` | `string` | `这一问不用填，读完按继续` | 没有答法那一问的空态那句话 |
| `form` | `'one'` | `'one'` | 形态键（闭集；闭集外一律 `badInput`） |
| `extraClass` | `string` | — | 附加类名（空格分隔，逐个过类名正则） |

**选项（`options` 的每一个元素）**

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `options[].value` | `string` | 必填 | 机器值（`<input value>` 与事件 `detail.value`）。**非空、这一问内唯一** |
| `options[].title` | `string` | 必填 | 选项标题（选项上那行主字）。**非空** |
| `options[].desc` | `string` | — | 选项说明（选了会怎样，一句话）。**不写 `；` 与三连顿号**——那是拿符号顶替版式 |

**填空（`fields` 的每一个元素）**

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `fields[].name` | `string` | 必填 | 字段机器名（`data-ilife-wizard-field` 与事件 `detail.fields` 的键）。**非空、这一问内唯一** |
| `fields[].label` | `string` | 必填 | 字段标签（屏上那行字）。**非空** |
| `fields[].value` | `string` | — | 已填的值（回退到这一问时的复填） |
| `fields[].hint` | `string` | — | 标签下面那句提示（如「不填也能继续」） |
| `fields[].kind` | `'text' \| 'number'` | `'text'` | 输入类型（闭集）；`number` 另带 `inputmode="decimal"` |

**入参违规一律抛 `BlocksError`**（`bad-input`），不静默兜底：静默降级会让调用方以为已经生效。
两边自相矛盾的组合同样拒：`options` 与 `fields` 同时非空、`value` 给了却没选项、`loadingText` 没跟着 `loading`、
`disabled` 与 `disabledReason` 缺一、`error` 与 `disabled` 同时给（一行里两个「为什么」会互相盖住）。

## 契约与不变量（判据逐条断）

1. **一屏只问一句**：`question` 必填，且是这一屏唯一的大字（`fs-h1`，四套皮肤下都 ≥ 正文的 1.8 倍）。
   没轮到的问**不渲染**——那是原型 A 档（两栏：左步骤／右表单）的骨架，两档不可混。
2. **回退恒在场**：脚行永远有「上一问」；在第 1 问上它是原生 `disabled`，**为什么按不动**写在读数行的次段里，
   按钮用 `aria-describedby` 指过去（不是靠一句 `title` 挂着）。
3. **进度那 N 格＝`total`**：走过／正走／没到三档。无文字的条在皮肤语汇里**只有 `accent` 一档实底**，
   所以正走那一格靠**高一档的形**（4px → 6px）＋ `aria-current="step"` ＋ 读数行那个「第 n / N 问」分辨，
   **不借 `ink` 当第二档颜色**（那是"拿字色当面"，见 `docs/base/base-render/选中态与皮肤语言.md`）。
4. **选中那一条（有文字的选中面）**：`accent-soft` 底 ＋ `accent-text` 字 ＋ `accent` 描边，
   再加两重非颜色标记——左端 4px 竖条（形）＋ 标记位里的对钩（字）。皮肤「大字报刊」下强调色＝墨黑，只染色会塌。
5. **触控地板**：一条选项 ≥56px 高、三枚键 ≥44×44、相邻触控目标间距 ≥10px（地板是 44 与 8）；
   选项与三枚键**都点得到**，没有"只有悬停／只有某种输入设备才到得了"的通路。
6. **答法三种，互不叠**：`options`（真单选，整条 `<label>` 是命中区）／`fields`（填空）／
   两者都不给 ＝ **确认屏**（设计过的空态，写清"这一问不用填"）。
7. **状态矩阵**：`rest`／`:hover`（包在 `@media (hover:hover) and (pointer:fine)` 里，且**不是唯一通路**）／
   `:active`（`scale(.98)`，≤80ms）／`:focus-visible`（2px 可见描边）／`disabled`（`cursor:not-allowed` ＋
   **虚线框＋透明底＋弱文字三样**，不只是染色）／`loading`（原地换字、宽度锁住）／`error`（写在控件旁边 ＋
   `aria-describedby`）／`empty`（确认屏那句话）。
8. **宽度只听容器**：本件设 `container-type: inline-size`，窄容器（`@container ≤560px`）只把脚行折成
   「提示句独占一行 ＋ 三枚键均分一行」；**零 `@media` 判宽度**、窄档零横向溢出（`scrollWidth ≤ clientWidth`）。
9. **不截断**：问题／选项标题／说明／脚行那句一律**换行**；样式段里没有 `text-overflow`／`line-clamp`／
   `white-space: nowrap`／`overflow-x`。产出文本里不出现 `·` 与 `；`（拿符号顶替版式是设计债）。
10. **零 DOM／零内联脚本**：模块代码剥掉字面量与注释后不出现 `document.`／`window.`／`navigator.`
    （DOM 只出现在 `buildWizardShellJs()` 产出的文本里）；标记里没有 `<script>`、没有 `on*=`。
11. **样式只经 `skinVar()` 读皮肤**：组件里不出现手写的 CSS 变量；不写 `:root`／`!important`；不定义新 token 名；
    全部规则 scope 在 `.<prefix>page-ui` 之下，且一条选择器里作用域只出现一次。
12. **加法式**：不调 `wizardShellCss()`／`buildWizardShellJs()`、不挂 `.ilife-page-ui` 的页零命中，逐字节不变。
13. **各套皮肤下标记逐字节相同**：皮肤只换样式取值，标记一个字节不动。

## 交互契约（运行时，`buildWizardShellJs()`）

| 动作 | 行为 |
|---|---|
| 点一条选项 | 原生单选：那一条 `checked`，根上的 `data-ilife-wizard-value` 就地改写 ＋ 派发 `ilife:wizard-pick` |
| 再点同一条 | 机器值没变 ⇒ **不派发**（免得上游把同一次选择算两遍） |
| 点「上一问／跳过／继续」 | 派发 `ilife:wizard-go`（`go` ＝ `back`／`skip`／`next`），带上这一屏的 `index`／`value`／`fields` |
| 按不动的那一枚 | 原生 `disabled`，点击不派发（运行时段另有一道 `btn.disabled` 拦） |
| 重复注入 | 只绑定一次（文档根上 `data-ilife-wizard-runtime`）——页面同时挂别家运行时也安全 |
| 不跑脚本 | 选项照样按 `checked` 显示选中态、三枚键照样是按钮，只是不派发事件、不写机器值属性 |

**运行时段不自己推进**：走到哪一屏是页面的数据（页面握着整趟的问题与已答值），运行时段只把「按了哪一枚」报出去。
事件（冒泡 `CustomEvent`，`detail`）：

```ts
'ilife:wizard-pick' → { name, index, value, title, prev }        // title 是选项标题（人话），prev 是改前机器值
'ilife:wizard-go'   → { name, index, go, answered, value, fields } // fields ＝ 这一屏所有填空的现值（键＝字段机器名）
```

页面接法：`root.addEventListener('ilife:wizard-go', …)` 里换下一屏（用同一个 `name` 重渲染、把
`index + 1`、`value` 换成下一问已答的值）——**不引入任何全局**。

## 常见错法（别这么干）

- ❌ 把整趟的问都渲染出来（那是两栏那档的骨架）→ ✅ 一屏一屏渲染，`index`／`total` 只说位置。
- ❌ 拿 `index` 当「已答了几问」用：跳过的那一问也往前走了 → ✅ 已答值与草稿由页面握着，本件只报事件。
- ❌ 第 1 问上把「上一问」藏起来或按不动却不说为什么 → ✅ 摆着它，并把原因写在读数行的次段里。
- ❌ 拿颜色区分"走过"与"正走"（无文字的条只有一档颜色）→ ✅ 当前那格高一档 ＋ 读数行那个「第 n / N 问」。
- ❌ 选中态只把边框染成强调色：皮肤「大字报刊」下强调色＝墨黑，与未选中的黑边几乎同色 → ✅ 竖条 ＋ 对钩两重非颜色标记。
- ❌ 用 `value: ''` 表达"还没答"：说不出「答的是哪一个」 → ✅ `value: null`（或不给）。
- ❌ 主键上写 `white-space: nowrap`：调用方给一长串标签时按钮会把卡片顶出屏 → ✅ 让它换行（宽了顶出屏比换行难看）。
- ❌ 推进中用 `transitionend` 之后才改状态：`prefers-reduced-motion` 下过渡被关掉，界面卡在半路 → ✅ 状态由页面给，过渡只动 `transform`。

## 有意偏离原型的地方（及理由）

1. **次段文案**：原型写「前面 2 问答完了，随时能回」→ 本件写「前面 2 问**走过**，随时能回」。
   理由：跳过的那一问没答，说"答完了"是假话（`skippable` 是本件的一等入参）。
2. **选项说明里的 `；`**：原型示例里带分号 → 本件的示例与文案一律不用（渲染面文字门：可见文本里的 `；`／`·` 是设计债）。
3. **按不动的键**：原型是「软底压软底」（禁用底色与脚行底色同色 ⇒ 按不动的那枚在脚行里等于没画）→
   本件改成**虚线框 ＋ 透明底 ＋ 弱文字**三样（只染一层颜色读不出来）。
4. **「跳过」那枚**：原型恒在场 → 本件在 `skippable: false` 的问上**不摆**（"看着能点、点了没反应"是不许留的中间档）。
5. **主键不加 `white-space: nowrap`**（原型有）：长标签会把卡片顶出屏。
6. **推进中主键保住实心底**：字已换成「保存中」，一按下去就变虚框会让读者以为取消了。

## 关系

- 与 `step-flow`：那是**指示器**（只画走到第几步），本件是**容器**（步骤 ＋ 答法 ＋ 推进 ＋ 回退）。
- 与 `radio-cards`：那是**一问**的一组单选卡（组名 ＋ 选项 ＋ 读数）；本件把「问」这个框立起来，
  选项只是其中一种答法（要更厚的选项卡时，页面把 `radio-cards` 放在本件的答题区里，两件不互抄）。
- 与 `dialog`／`drawer-sheet`：截断式浮层装不下 5 步表单、关掉就丢；本件是一整页。
- 样式与运行时由页面按需挂（加法式：不调它们、不挂 `.ilife-page-ui` 的页零命中）。
- 本件暂不提供族汇总入口（「交互与流程」族里后落地的那件若先立汇总，照 `sheetCss()` 先例接上）。
