# goal-stairs · 目标阶梯

**一句话**：把「到哪一天要成、分几段走、每一段最晚哪天动手」从**目标日往回倒推**出来，
画成一段一行的日程：行头说这一段是什么、窗口开在哪天、走到哪一步了；行里那条轨道把这一段
在整段日程上**占了哪一截**画出来，上面一根竖线是今天。

**形态**：本件只落地**形态 C「倒推日程（每段最晚何时动手）」**——出处＝原型墙
`.scratch/ui-组件墙/新件/parts-数据与仪表.mjs` 第 66 件（同一件的 A 分段台阶／B 里程碑轴还没全过，故不落），
按层规重写（原型是一次性代码：无判据、无错误处理、读的是墙稿变量）。
形态键住 `GOAL_STAIRS_FORMS` 闭集（今天只有 `C` 一格）——**另外两档日后过了，是在闭集里加一格，不是新开一件**。

它替掉的两种错法：**只有一个总进度条**（看不出分几段、也看不出每段最晚什么时候动手）与
**只写目标日、不写每段的最晚动手日**（到期那天才发现来不及）。

## 何时用它（选型四条）

| 你要的 | 用 |
|---|---|
| 「分几段走、每段最晚哪天动手、来不来得及」——**沿时间读次序与期限** | **本件** |
| 「每个目标到了几成」（两数之比，没有先后、没有期限） | `progress-list`（多目标进度） |
| 「走到第几步了」（步骤没有数量刻度、没有期限、没有倒推） | `step-flow`（步骤条） |
| 「一个值落在刻度的哪一格」（没有段、没有窗口） | `scale-bar`（刻度条） |

用在哪：卡路里 · 体重分段目标；记账 · 还款／储蓄进度；作息管家 · 达标天数。

## 入参

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `title` | `string` | 必填 | 卡头标题（`倒推到 12-07 还清`） |
| `today` | `string` | 必填 | 今天（`09-24`）：卡头那句「竖线＝今天 09-24」用它。**上屏的样子由调用方定**（写不写年份、怎么写都行） |
| `todayPct` | `number` | 必填 | 今天在整轴上的位置（0–100 的有限数）：轨道上那根竖线落在这儿 |
| `steps` | `GoalStairsStep[]` | 必填 | 分段（**2–8 段**，按先后的次序给） |
| `form` | `'C'` | `'C'` | 形态闭集；闭集外报 `BlocksError` |
| `note` | `string` | 本形态的口径句 | 口径行；**给了就整句替换**那条例行口径 |
| `extraClass` | `string` | — | 附加类名（空格分隔，逐个过类名正则） |

**分段（`steps` 的每一个元素，按先后的次序给）**

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `from` | `string` | 必填 | 这一段两端的读数：起点（`12 万`） |
| `to` | `string` | 必填 | 这一段两端的读数：终点（`8 万`） |
| `start` | `string` | 必填 | 这一段**最晚动手的那天**（`09-01`），也就是它窗口开的那天：行头写「窗口 09-01 起」，轨道上写「最晚 09-01」 |
| `startPct` | `number` | 必填 | 最晚动手日在整轴上的位置（0–100 的有限数）：轨道上那枚标签落在这儿 |
| `endPct` | `number` | 必填 | 窗口右端在整轴上的位置（0–100 的有限数，**严格大于** `startPct`） |
| `state` | `'done'｜'now'｜'plan'` | 必填 | 这一段到哪一步了：已达成／进行中／还没开始 |

**必填与缺省分两处说清**：`steps` 与它每个元素里的六个字段、`title`、`today`、`todayPct` 是**必填**；
`form`（缺省 `'C'`）、`note`（缺省＝本形态那句口径）、`extraClass`（缺省＝不加）可以不给。
**必填的字段少一个就报错**——画不出位置的段不该上屏，件里**不替调用方猜一个位置**
（猜出来的图会指着一截并不存在的窗口）。

**分段是一张密表**：`steps` 里**每个下标上都要真有一段**（`new Array(2)` 这种稀疏数组一律拒——
洞会被跳过去、段数却照算，卡头写着「二段」而表里一行都没有）。

**轴由调用方定**：位置一律是**百分数**（整轴左端 0、右端 100），轴从哪天到哪天、跨不跨年是调用方的口径，
件里不猜。日期串只上屏、不参与算数（取整、补零、写不写年份都归调用方）。

## 示例入参

本件**唯一一份**示例入参（皮肤矩阵判据拿它渲染本件、必须能**直接**渲染成功）：
`steps` 至少要 **2 段**（本件上限 8 段），每段的 `endPct` 必须**严格大于** `startPct`——
按类型派生的样例只给一段，说不出「分几段走」这件事。

<!-- 示例入参：皮肤矩阵判据拿它渲染本件，必须能直接渲染成功 -->
```json 示例入参
{
  "title": "倒推到 12-07 还清",
  "today": "09-24",
  "todayPct": 38,
  "steps": [
    { "from": "12 万", "to": "9 万", "start": "09-01", "startPct": 4, "endPct": 26, "state": "done" },
    { "from": "9 万", "to": "6 万", "start": "10-01", "startPct": 30, "endPct": 55, "state": "now" },
    { "from": "6 万", "to": "3 万", "start": "11-01", "startPct": 58, "endPct": 80, "state": "plan" },
    { "from": "3 万", "to": "0", "start": "12-01", "startPct": 84, "endPct": 98, "state": "plan" }
  ]
}
```

四段的窗口带按 `startPct`→`endPct` 依次排开、今天的竖线落在 `38`（在第 2 段的窗口 30–55 里）；
`state` 只吃 `done`／`now`／`plan` 三格，两端的读数（`12 万 → 9 万`）只上屏、不参与算数。

## 契约与不变量（判据逐条断）

1. **位置只有一处算**：`startPct`／`endPct`／`todayPct` 三个百分数既决定窗口带的两端，也决定
   「最晚」那枚标签与今天那根竖线落在哪儿——**读者按带子量出来的位置，与行头写的字说的是同一件事**。
2. **状态靠形 ＋ 字 ＋ 色三样**：行头写状态字（`已达成 ✓`／`进行中 ▶`／`还没开始 ○`，三枚形各不相同）＋
   窗口带左侧 2px 侧标（形）＋ 带色（色：达标走 `ok`、进行中走 `accent`、还没开始走次要面、
   过期走 `danger`）。**色不是唯一信息**，色盲下也分得出。
   **三笔账说清楚**：那条带是**无文字的条**（`aria-hidden`，带里没有字），状态字在**行头**；
   `.state` 自己不画底（背景透明）⇒ **它压的是宿主页的底**（卡面走 `surface`、裸页走 `ground`），
   判据就按「字真压的底」断（页底那一档归皮肤层的地板判据，件不背）。
3. **过期点名**：窗口**整段**落在今天那根竖线左边、这一段又没达成 ⇒ 行头多写一枚「来不及 ✕」
   （窗口正好压在竖线上不算过期；已达成的那段即使窗口过去了也不算迟到）。
4. **标签四向都不出轨道**：最晚动手日那枚标签是**在流里**的网格项（位置靠百分比外边距，外边距的百分比
   按轨道宽算），标记落在轴的右半边时**改贴右缘往左长**（`.is-right`）——两种情况下都用得上整行宽度，
   日期长了它自己换行、**轨道跟着长**（`min-height` 只是地板）：不截断、不外溢、上下也不顶出
   （绝对定位＋定高轨道时，两行的日期会上下各顶出 5.8px）。
   今天那根竖线的位置用 `clamp()` 夹在轨道内 2px（`left: 100%` 时它会顶出右缘）；
   它上下各让出 2px 是**有意的**——游标要在带子上看得见。
5. **窄宽两档换结构**：容器宽 320／390／620／1280 下**零横向溢出**（`scrollWidth ≤ clientWidth`）。
   缺省那一份是**宽档**：「行头那一列（`GOAL_STAIRS_HEAD_COLUMN_PX`）‖ 轨道」并排；
   本件自己的宽度 ≤ `GOAL_STAIRS_NARROW_MAX_PX`（＝宽档阈值 `GOAL_STAIRS_WIDE_PX` − 1）时换成上下两行。
   判的是本件自己的宽度，故它嵌进侧栏／面板／卡片里照样对（本件不写任何 `@media` 宽度查询；
   `@container` 那一支写 `max-width` 不写 `min-width`——缺省那一份必须是完整的一份版式）。
6. **各套皮肤下标记逐字节相同**：皮肤只换样式段（取值表），标记一个字节不动。
7. **零 DOM／零脚本**：模块代码剥掉字面量后不出现 `document.`／`window.`／`navigator.`；
   产出的标记里没有 `<script>`，也没有 `on*=` 内联事件。
8. **样式只经 `skinVar()` 读皮肤**：组件里不写手写的 `var(--ilife-…)`；不写 `:root`／`!important`；
   不定义新 token 名；全部规则 scope 在 `.<prefix>page-ui` 之下。几何只用自己的
   `--goal-stairs-start`／`-end`／`-now` 三个行内属性（不占 `--ilife-*` 那个命名空间）。
9. **无障碍地板**：文字色只取 `ink`／`ink-2`／`accent-text`／`ok`／`danger` 几档；`:focus-visible` 给 2px 可见焦点；
   长串 `overflow-wrap: anywhere`；窗口带与今天那根竖线是 `aria-hidden`（它们说的是行头与卡头已经说过的字）——
   段名、窗口句、状态字、「最晚哪天」都是**真文字**，读屏念得出。
10. **本件没有交互、也没有运行时段**：没有一处可点元素（故**没有 `runtime.ts`**），没有 `transition`／`animation`
    （故 `prefers-reduced-motion` 下没有什么会卡在半路，也没有状态依赖 `transitionend`）；
    页面不挂它时零命中、逐字节不变。

## 常见错法

- **拿它当进度条**：本件读的是**次序与期限**，不是「已完成多少」；「到了几成」走 `progress-list`；
- **把位置交给件里猜**：轴与位置（三个百分数）是调用方的口径，件里不按日期重算一遍——
  两处各算一次必然走散；
- **窗口两端一样宽**：`endPct` 必须**严格大于** `startPct`，否则这一段占了多久读不出来，当场报错；
- **`state` 想省掉**：哪一段算进行中是业务口径，件里不猜——不给就报错，不静默当作「还没开始」；
- **只落一段**：`steps` 少于 2 段当场报错（一段读不出先后，也就倒推不出来）；多于 8 段请调用方先并段；
- **把「来不及」当成一个状态传进来**：它是件里从**今天的竖线**与窗口两头算出来的（整段在竖线左边、
  这一段又没达成），传进来必然会与画面上的位置对不上；
- **在 `title`／`note`／`from`／`to`／`start` 里写 `·` 或 `；` 或并列三段以上**：
  仓库的**分隔符门**对可见文本零豁免（`test/separator-probe.mjs`），需要分割就说明这里该有设计。
