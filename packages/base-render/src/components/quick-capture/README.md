# quick-capture · 快速录入条

**一句话**：写一句话（`午饭 32 元 现金`），它认出来的几格就摆在这一行下面——每格读成 `「午饭」＝ 餐饮 改`，**哪格认错了点哪格改**（点那一格摊开它自己的候选，点一枚就改好）；认得出的一枚「存」就录进去。

它替掉的两种错法（原型墙那一格的原文）：①「随手记一笔也要开浮层、填 6 格、再点保存」；②「一句话里说了三件事（吃了什么／多少钱／哪张卡），人得自己拆成三格」。

**一屏只有三层话**（2026-09-25 用户口径：原型里写了好多文字、看起来很混乱）：**写的那一句话**（输入框里的字）＋ **它认出来的几格**（每格：原文那一截 ＋ `＝` ＋ 认成的值 ＋ 改）＋ **能按什么**（分开填／存、记过的那几条）。同一个数只印一次。**原型里的旁白与口径句一句都不上屏**——「解析成」「这样记过的」以及句尾那些说明都留在这份说明书里。

**形态**：本件只落地**形态 `oneline`「一行式录入 ＋ 解析预览」**——出处＝原型墙 `.scratch/ui-组件墙/新件/parts-交互与流程.mjs` 第 86 件的 A 档（2026-09 起用户逐格打分，三套皮肤都打 4 分），按层规重写。形态键住 `QUICK_CAPTURE_FORMS` 闭集（今天只有 `oneline` 一格，**格号 A 不是接口名**）——**加第二形态是在闭集里加一格，不是新开一件**；闭集外的值一律报 `BlocksError`。同件 B 档「常驻速记条 ↔ 完整表单」打分未过、**不落**，它的类与规则（常驻条、折叠抽屉、六格表单）一个都不搬。

**本件不猜词**：一句话怎么拆成几格、每格认成了什么，**由调用方给**（`cells`）。「午饭」是哪一类、`32 元`该记成 `32.00` 还是 `3.20`，那是各技能自己的词表；件只负责把它摆成「一行 ＋ 几格」并守住可达性。人改了某一格之后，件把**那一格**原地重写并报一条事件——**不重算别的格**。输入框里的字变了，件把新句子报出去（`change`），由页面重算解析预览并重渲染。

## 何时用它（选型五条）

| 你要的 | 用 |
|---|---|
| 一句话里带好几个字段，**认得出就存、认错了就地改** | **本件** |
| 一格格填的字段组（认不出来时的**退路**） | 页面上的表单件；本件的「分开填」把这件事**报出去**，表单不归本件 |
| 改一个**已经写好**的值 | `editable-value`（可编辑值） |
| 选一个实体（账户／物品放在哪儿），选完就完事 | `relation-picker`（关系选择器） |
| 打断式容器：开一个浮层、填完再关 | `dialog`／`drawer-sheet` |

用在哪：记账（记一笔）、卡路里（补记一餐）、备忘录（随手记一条）、作息管家（补一条）。

## 入参

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `id` | `string` | 必填 | 机器键（根上的发现锚与事件 `detail.id`）。**只许标识符字符** |
| `text` | `string` | 必填 | 现在写着的那一句话（屏上也印这一串）。**非空、且不能只有空白** |
| `cells` | `QuickCaptureCell[]` | 必填 | 一句话拆出来的几格（**1–6 格**，顺序＝屏上顺序）。**由调用方算**：件不猜词 |
| `recent` | `string[]` | — | 「记过的」那几条（0–4 条；点一条＝把那句话填回输入框）。不给＝不出这一条带 |
| `form` | `'oneline'` \| `'drawer'` | `'oneline'` | 形态键（闭集；闭集外一律 `BlocksError`）。`oneline`＝一行式录入 ＋ 解析预览；`drawer`＝常驻条（一行）↔ **推开的 6 格** |
| `extraClass` | `string` | — | 附加类名（空格分隔，逐个过类名正则） |

**一句话拆出来的一格（`cells` 的每一个元素）**

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `key` | `string` | 必填 | 这一格的机器键（事件 `detail.key`，如 `category`）。**只许标识符字符**，表内唯一 |
| `value` | `string` | 必填 | 这一格现在认成的那一枚：**必须命中 `choices` 里的一枚**（屏上那一串就是它的名字） |
| `choices` | `QuickCaptureChoice[]` | 必填 | 这一格能改成的那几枚（**1–6 枚，含现在这一枚**）。一枚都不给＝这一格改不了，那种值不许做成格 |
| `from` | `string` | 与 `label` 恰给一个 | 原文那一截（如 `午饭`；屏上印成 `「午饭」`）＝这一格是从这句话里认出来的。**非空、且不能只有空白** |
| `label` | `string` | 与 `from` 恰给一个 | 这一格叫什么（如 `日期`）＝原文里没写、**补上的**（屏上不带引号，形是虚线边框） |

**一格能改成的那一枚（`choices` 的每一个元素）**

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `key` | `string` | 必填 | 机器键（事件 `detail.value` 就是它）。**只许标识符字符**，同一格内唯一 |
| `label` | `string` | 必填 | 屏上那一串（如 `餐饮`／`32.00`／`现金账户`）。**非空、且不能只有空白**；长了换行，绝不截断 |

**入参纪律（三条，判据逐条断）**：

1. **上屏的文字全空白＝拒**（`badInput`）：`'   '` 会在屏上留一块**看得见的空白**（无字的一句话／无字的一格／无字的一枚候选）。空串＝未给（与全层 `optText` 同口径），**只有空白＝拒**；**零宽字符那类不可见字符同样算空白**（`\u200b`、`\ufeff`、`\u00ad`、`\u200e`／`\u200f`、`\u2060`），`String.prototype.trim()` 剥不掉它们，件先把这一段剥掉再判。
2. **入参表以外的键一律拒**（顶层、每一格、每一枚候选里都是）：自有的不可枚举键与原型链上继承来的键**同样算**。
3. **改不到的值＝拒**：一格现在认成的那一枚不在它的候选里（屏上那一串从哪来？）、`from` 与 `label` 两个都给或都不给（不知道印哪一条／这一格没有名字）、同一格里键重了、格数或候选数越界——一律报 `BlocksError`。

## 契约与不变量（判据逐条断）

1. **写的那一行**：行首一枚三个字的小签 ＋ 输入框（那句话本身）＋ 「分开填」（次动作：无底、发丝线、次字色）＋ 「存」（主按钮）。四件同一行；窄容器下输入框先占满一行，两颗按钮跟着走，**主按钮不许掉行**。
2. **解析预览的每一格都能点**：整枚就是那颗按钮（命中盒＝整枚 ≥`QUICK_CAPTURE_TOUCH_PX`，相邻留 `QUICK_CAPTURE_GAP_PX` 缝）。点那一格摊开**它自己的候选带**（一次只摊开一格，其余先收）；再点一下收起。
3. **「哪格认错了点哪格改」一根手指走完**：点那一格 → 点一枚候选（≥44×44）就改好；「不改」是取消（收起、值一动不动、**不派事件**）。**打字不是唯一通路**：记过的那几条点一下就把那句话填回输入框。
4. **改一格是三处一起翻**：机器读数（格上的 `data-value`）、屏上读数（`-to` 那一格的字）、候选带里那一枚的选中态（`is-on` ＋ `aria-current` ＋ 勾）——只改一处就会在屏上自相矛盾。
5. **「哪一枚是现在这一枚」只有一处口径**：`quickCaptureChoiceOn()`；渲染期标它、运行时段翻它，跑的是**同一份源码**（运行时的 JS 文本里嵌的就是它的 `toString()`）。
6. **状态不只靠颜色**：摊开那一格＝形（描边加粗，走 `inset` 不动布局）＋色（软底）＋`aria-expanded`；**补出来的那一格**＝形（虚线边）＋结构（不带引号、只有格名）＋色（弱文字）；候选带里现在那一枚＝形（勾 ＋ 固定 `QUICK_CAPTURE_TICK_PX` 槽位）＋色（软底 ＋ 主色字 ＋ 主色描边）＋字（候选名 ＋ 字重 700）。
7. **主按钮的底走 `accent-text`**（不是 `accent`）：`accent-ink` on `accent` 在 `neutral` 只有 4.02，正文级按钮字过不了 4.5 的文本地板；`accent-text` 那一档四套都过（paper 6.84／broadsheet 18.82／neutral 5.69／ink 6.63）。口径同 `dialog`／`drawer-sheet` 的实底键。
8. **屏上是真读数**：那一句话住在根上的 `data-ilife-quick-capture-text`（与输入框里的字是同一件事的两处摆法，一起写）；每一格现在的机器键住在格上的 `data-ilife-quick-capture-value`。**不从屏上的字反推机器键**。
9. **读数永不截断**：每一格的读数与候选名没有省略手段（样式段里没有 `text-overflow`／`line-clamp`／`nowrap`），窄档只换行。
10. **窄档零横向溢出**：宽度只许容器判（本件自己声明 `@container` 容器；媒体查询只判悬停与减动效，**一条视口宽度查询都没有**）。
11. **「分开填」与「存」只报数**：`存` ⇒ `ilife:quick-capture-save`（`detail.cells` 是每一格现在的读数）；`分开填` ⇒ `ilife:quick-capture-split`。本件**不写库**、也不开表单。
12. **加法式**：不挂本件的页面零命中、逐字节不变；换皮肤只换样式，标记逐字节相同。
13. **零键盘依赖**：标记与文案里没有键帽与方向键语汇，运行时段不接任何键盘事件；`:focus-visible` 只留给真实键盘用户（那是无障碍地板，不是通路）。
14. **幂等**：`<html>` 上一枚 `data-ilife-quick-capture-runtime` 拦住重复注入；每张卡上记一枚 `data-ilife-quick-capture-bound` 读数。

## 交互契约（页面侧）

```html
<!-- 样式段与标记：quickCaptureCss() ＋ renderQuickCapture(input)；外层挂 .ilife-page-ui 与皮肤类 -->
<script>/* buildQuickCaptureJs() 产出的那段文本 */</script>
<script>
  document.addEventListener('ilife:quick-capture-change', (e) => {
    const { id, text } = e.detail;      // 那一句话变了：按它重算 cells 并重渲染（本件不猜词）
    if (id !== 'qcap-lunch') return;
    rerender(id, parse(text));
  });
  document.addEventListener('ilife:quick-capture-pick', (e) => {
    const { id, key, value, to } = e.detail;   // key＝哪一格，value＝新机器键，to＝新读数
  });
  document.addEventListener('ilife:quick-capture-save', (e) => {
    const { id, text, cells } = e.detail;      // cells 顺序＝屏上顺序；按它落盘
  });
  document.addEventListener('ilife:quick-capture-split', (e) => {
    const { id, text } = e.detail;             // 「分开填」：开字段表单归页面
  });
</script>
```

**事件（`detail` 逐字段）**

| 事件 | 什么时候 | `detail` |
|---|---|---|
| `ilife:quick-capture-change` | 输入框里的字变了，或点了一条记过的 | `{ id, text }`：`text` 是新句子（机器读数，与输入框里的字同值） |
| `ilife:quick-capture-pick` | 点了一枚候选（那一格已经改完） | `{ id, key, value, to }`：`key` 是哪一格、`value` 是新的机器键、`to` 是新的屏上读数 |
| `ilife:quick-capture-save` | 点了「存」 | `{ id, text, cells }`：`cells` ＝ `[{ key, value, to }]`，顺序＝屏上顺序 |
| `ilife:quick-capture-split` | 点了「分开填」 | `{ id, text }`；**形态 `drawer`** 下这一枚是**抽屉开关**（摊开／收起那 6 格），`detail` 多一枚 `open`＝现在摊开着没有 |

## 常见错法

- **把「解析」写进件里**——件的入参是**已经拆好的几格**；词表住在各技能（铁律一：能力自治）。件里塞一个正则去猜「午饭」是哪一类，就是两处各算一遍同一件事。
- **改了一格却只重写那一串字**——屏上读着「餐饮」而格上的机器读数还是旧的，页面按 `detail` 落盘就落错了；三处（机器读数／屏上读数／候选带选中态）必须一起翻。
- **把「改」做成一个只能打字的格子**——手机上要弹键盘、还要自己记着有哪些合法取值；正确做法是**点那一格摊开它自己的候选**（词表由调用方给）。
- **在屏上加旁白**（「认不出来的字段在这儿补」这类）——一屏只留一层话，说明住在本 README 里。
- **让「补出来的那一格」与认出来的格子长得一样**——用户会以为那句话里真写了日期；形上要分开（虚线边 ＋ 不带引号）。
- **主按钮用 `accent` 实底 ＋ `accent-ink` 字**——`neutral` 那套只有 4.02，13px 的按钮字过不了文本地板；走 `accent-text` 做底。
- **一格都不给候选**——那一格改不了，却长得和别的格一样 ⇒ 用户点了半天没反应；这种值不该做成格（入参当场拒）。

**有意偏离原型的地方**（原型＝`.scratch/ui-组件墙/新件/parts-交互与流程.mjs` 第 86 件；A 档与 **B 档**
（2026-09-26 补分：中性／小票纸／大字报刊三套皮各 4 分，照**砍过字的那一版**落地）逐行指得出原型里的原文，
没原文的就不是偏离）：

| 原型里是 | 落地是 | 为什么 |
|---|---|---|
| 「改」只是格尾一枚记号，原型没写点它之后发生什么 | 点那一格摊开**它自己的候选带**（词表由调用方给；收起时 `hidden`），末一枚是「不改」＝取消 | 触屏优先法条要「点得到、一根手指走完」：候选由调用方给，件不猜词；一次只摊开一格，屏上不留第二层话 |
