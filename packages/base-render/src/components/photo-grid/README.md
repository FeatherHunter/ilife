# photo-grid · 照片网格

**一句话**：一格格照片（身材照、物品照、保修凭证）——每格＝**定形框**（`aspect-ratio`）＋**四角取景角标** ＋ **底部题注条**（日期／位置），末尾一格是虚线框「加一张」。

**形态**：本件只落地**形态 A「网格 ＋ 加一张」**——出处＝原型墙 `.scratch/ui-组件墙/parts-11-加量池.mjs` 的 `.c-p4-grid`。

**这一件是重做件**（原型 3/3/3）。改掉的是什么：原型拿「渐变底 ＋ 细网纹」当照片占位，三套皮肤下都只是**一块灰**——读者看不出那是相片位。重做后一格由三样定形（定形框／取景角标／题注条），**没有真图时也一眼读出「这里放一张照片」**，而真图到位时**一格尺寸一个字节都不变**（同一个框、同一个比例）。

## 何时用它（选型三条）

| 你要的 | 用 |
|---|---|
| 一**组**同等地位的照片，格上有日期／位置，末尾留一个加号 | **本件** |
| 两**张**照片比着看（前／后）＋ 变了多少 | `photo-compare`（前后对比） |
| 单张照片占满一块（带图注与口径行） | `media`（图片容器，页面级形状件） |

## 入参

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `photos` | `PhotoGridItem[]` | 与 `groups` 二选一 | 平铺的格（不按月分组时用）。空数组 ⇒ 空态 ＋ 只剩「加一张」那格 |
| `photos[].alt` | `string` | 必填 | 这一格该放什么照片（「正面 · 晨起」）。**非空**：占位格上唯一说得清「放什么」的话；真图时也是 `alt` |
| `photos[].src` | `string` | — | 图源；不给＝占位格（相机记号 ＋ `alt`） |
| `photos[].date` | `string` | — | 日期（「09-25」）：进题注条，也进分组的「几天」计数 |
| `photos[].caption` | `string` | — | 题注说明（「侧面」「沙发 · 修复前」） |
| `photos[].count` | `number` | — | 这一格是几张叠着（同一天多张）；`>= PHOTO_GRID_MIN_STACK` 才出角标 |
| `photos[].size` | `string` | — | 一行读数（「1120×1480 · 1.8 MB」） |
| `groups` | `PhotoGridGroup[]` | 与 `photos` 二选一 | 按月分组：组头写月份与「几天 · 几张」（由本件算） |
| `groups[].month` | `string` | 必填 | 组头（「2026 年 9 月」）。**非空** |
| `groups[].note` | `string` | — | 组的补充（「共 4.2 MB」），顶到组头右端 |
| `ratio` | `'4-5' \| '1-1' \| '3-4' \| '4-3'` | `'4-5'` | 定形框比例（闭集）。**整墙同一档**——那才是「网格」 |
| `addLabel` | `string` | `'加一张'` | 末尾那格的字 |
| `addHint` | `string` | — | 末尾那格的补充（「支持 JPG／PNG，单张 ≤ 10 MB」） |
| `add` | `boolean` | `true` | 给 `false` 就不出末尾那格（只读归档页用） |
| `note` | `string \| string[]` | — | 脚注口径（「按拍摄日期分组」）。串＝一句话；数组＝分段 |
| `form` | `'grid'` | `'grid'` | 形态键（闭集；闭集外一律 `badInput`） |
| `extraClass` | `string` | — | 附加类名（空格分隔，逐个过类名正则） |

## 契约与不变量（判据逐条断）

1. **占位读得出是相片**：没给 `src` 时，框里同时出 ① 四角取景角标 ② 中央相机记号 ③ 那句 `alt`；框自己一圈**虚线**（与真图格的实线是**第二样差别**，不只靠底色）。有 `src` 时反过来：只有真图 ＋ 实线框，相机记号与虚线都**不出**。
2. **定形框与题注在产物里断得到**：框上的类带比例档（`…-frame-4-5`），`aspect-ratio` 就写在那个类上；题注走 `<figcaption>`（照片与它的题注本来就是一格一件事）。
3. **不跳版**：真图与占位**共用同一个框**（同一个比例、同一圈边框）⇒ 同一页换数据时，格的尺寸一个像素都不动。
4. **同一天多张有角标**：`count >= PHOTO_GRID_MIN_STACK`（2）才出「N 张」，1 张不出（标了是噪音）。
5. **成组**：给了 `groups` 就出组头（月份 ＋ 「几天 · 几张」）；平铺时**不出现**组头（不出空壳）。「几天」＝题注条上出现过的**不同日期**个数，不解析日期本身。
6. **`photos` 与 `groups` 恰好给一个**：两个都给／都不给一律 `badInput`（说不清这一页按不按月分、有没有照片）。
7. **末尾那格是内容格，不是按钮**：虚线框 ＋ 加号。要它可点，由调用方在外面包一层 `<button>`／`<label>`（本件不另造动作入口——与 `note-block` 不造编辑入口同一条口径）。
8. **窄宽两档容器驱动**：窄档两列、宽档三列（阈值 `PHOTO_GRID_THREE_COL_PX`）；判的是**本件自己的宽度**（`@container`），不是视口宽度。
9. **零阴影下层次仍在**：框靠一圈发丝线 ＋ 四角角标，题注条靠**软底色 ＋ 上发丝线**，组头靠底线。
10. **样式只经 `skinVar()`**：不写手抄的 `var(--ilife-…)`、不写 `:root`／`!important`、不新增 token 名；scope 在 `.<prefix>page-ui` 之下。

## 常见错法

- 拿一块纯色／渐变当照片占位 —— 读者看不出那是相片位（本件重做的就是这一条）；
- 有图时不给框上比例 —— 图一到位整页往下推，读者眼前一跳；
- 把「加一张」做成实心按钮混在照片格里 —— 读者分不清哪格是照片、哪格是入口；
- 给 `count: 1` 求一个「1 张」角标（标了是噪音，本件按 `PHOTO_GRID_MIN_STACK` 自动不出）；
- 同一面墙混两种比例 —— 那不是网格，是两件事，拆成两块。

- 用在哪：卡路里（身材照）／居家管家（物品照、保修凭证）。
- 样式由页面按需挂 `photoGridCss()`（加法式：不调它、不挂 `.ilife-page-ui` 的页零命中）。
- 本件不带运行时（没有必须靠脚本才成立的交互）。
