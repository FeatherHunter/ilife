# number-stepper · 数量步进

**一句话**：它替掉的是这两种错法 —— 「只能敲键盘填数量」（手机上够不到"精确到 0.5"）与「加减按钮小到点不中」。
屏上是一行：标签 ＋ 状态字，下面 **`− n ＋` 三个可点区**，再下面一排**常用值**，最后一行口径（步长与取值范围怎么定的）。

**形态**：本件只落地**形态 A「标准：加减＋常用值排」**——出处＝原型墙 `.scratch/ui-组件墙/parts-08-表与输入.mjs`
的 `.c-ns.c-ns-a`（2026-09 用户裁定落地的那一形态），按层规重写（原型是一次性代码：无判据、无错误处理、
读的是墙稿自己的变量）。形态键住 `NUMBER_STEPPER_FORMS` 闭集（今天只有 `standard` 一格）——
**加第二形态是在闭集里加一格，不是新开一件**（形态是骨架，不是地址）。

## 何时用它（选型三条）

| 你要的 | 用 |
|---|---|
| 一个有上下限、按档走的**数量**（份数／份量／数量），要能一按一档、也能一眼看到常用档 | **本件** |
| 数值在一个**连续区间**里挑，且"挑到哪儿"本身就是读数（热量目标／预算／库存下限） | `slider-row` |
| 一个已经算好的**任意值**（不含档位、不定上下限）就地改一处 | `editable-value` |

## 入参

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `name` | `string` | 必填 | 机器键（变更事件与载荷按它定位）。**非空** |
| `value` | `number \| null` | 必填 | 当前值。`null` ＝ **缺值**（写成 `—`）；**缺席＝错** |
| `min` | `number` | 必填 | 下限（含）。 |
| `max` | `number` | 必填 | 上限（含）。必须 > `min`，且**必须落在步长格子上** |
| `step` | `number` | 必填 | 每次加减的步长（> 0，小数位 ≤ 6） |
| `unit` | `string` | — | 单位（`份`／`g`／`件`）：小一号跟在值后，不参与机器口径 |
| `label` | `string` | — | 数量的名字（`份数`），进 `aria-label` 与事件 `detail.label` |
| `presets` | `number[]` | — | 常用值（点一下直接落到那一档）。不给＝不出这一排；每枚必须落在 `[min, max]` 的格子上、不许重复 |
| `caliber` | `string` | — | 口径行：加减步长与取值范围怎么定的 |
| `error` | `string` | — | 错误说明：写在控件旁边，控件 `aria-describedby` 指向它（**不只染色**） |
| `disabled` | `boolean` | `false` | 禁用三枚可点区；**必须同时给 `disabledReason`** |
| `disabledReason` | `string` | — | 为什么不能动（写在控件旁边，并被 `aria-describedby` 指到） |
| `loading` | `boolean` | `false` | 更新中：状态字换成「更新中」、值位宽度锁住不跳版、期间不接点击 |
| `form` | `'standard'` | `'standard'` | 形态键（闭集；闭集外一律 `BlocksError`） |
| `extraClass` | `string` | — | 附加类名（空格分隔，逐个过类名正则） |

## 契约与不变量（判据逐条断）

1. **三个可点区，两边各 ≥44×44**：−／＋ 与值位（第三个可点区）都 ≥44×44，常用值也 ≥44 高；
   **相邻触控目标留 8px 缝**（`NUMBER_STEPPER_GAP_PX`）——连体键在手机上最容易被误点（对原型的**有意偏离**）。
2. **值位即入口**：点值位在同一格里换上 `<input type="number">`（与值位同盒模型 ⇒ 不跳版），
   `Enter`／失焦提交、`Esc` 取消；越界或不在格子上的数**留在编辑态** ＋ 控件旁边的错误行（`aria-describedby`）。
3. **到边界给字，不给灰**：值到下限／上限时对应那枚键落 `disabled`，状态字位写「已到下限」／「已到上限」——
   `accent` 在小票纸与大字报刊两套皮肤里接近墨色，只靠底色深浅读不出"还能不能再按"。
4. **常用值选中态形＋字＋色三样**：`aria-pressed="true"` 那一枚走**强调面**（软底 `accent-soft` ＋
   主色字 `accent-text` ＋ 主色描边 `accent`）**并加粗**。旧写法「实心反白」(`accent` 底 ＋ `accent-ink` 字)
   已按 `docs/base/base-render/选中态与皮肤语言.md` 第三节清掉：有文字的选中面一律软底 ＋ 主色字 ＋ 主色描边。
5. **变更事件只在真变时派发**：夹到同值不派发、编辑器原样提交不派发（`detail = { name, label, value, prev, unit }`）。
6. **样式只经 `skinVar()` 读皮肤**：本件不出现手写的 `var(--ilife-…)`、不写 `:root`／`!important`、
   不定义任何自定义属性；全部规则 scope 在 `.ilife-page-ui` 之下（不挂 = 零命中）。
7. **响应式一律容器驱动**：本件设 `container-type: inline-size`（它自己就是容器）；窄容器（< 340px）下值位独占一行
   （两枚 ± 与值位挤一排会把数字压窄）。只有两条 `@media`，判的都是设备能力（`hover:hover`／`prefers-reduced-motion`）。
8. **数学口径**：`value`／`presets`／`max` 都必须在步长格子（`min ＋ k × step`）上，并落在 `[min, max]` 里；
   越界或不在格子上**渲染期就报 `BlocksError`**（不许静默吸附——静默改数是本件最不许出现的行为）。

## 常见错法

- 用 `value: undefined` 表达"还没填"（缺值要显式给 `null` → 屏上写 `—`）；
- 把 `max` 给成一个走不到的值（`min=0.5, step=0.5, max=6.2`）——最后一档永远落不到；
- 在常用值里塞一个越界的值（点了就会跳出范围）；
- `disabled` 了却不写 `disabledReason`（读者只能猜为什么不能动）；
- 只把禁用态做成"变灰"（颜色一变，读者读不出是"到底了"还是"坏了"——状态字那一枚就是为这来的）；
- 把本件当金额输入用（金额有两位小数与千分位口径，走 `editable-value`＋账目件）。

## 关系

- 与 `editable-value` 的分工：本件是**数量控件**（有上下限、按档走、有常用档）；`editable-value` 是**任意值**的就地编辑。
- 与 `slider-row` 的分工：本件按**档**走（离散、可重复按），`slider-row` 在**连续区间**里挑位置。
- 样式由页面按需挂 `numberStepperCss()`，运行时挂 `buildNumberStepperJs()`（加法式：不调不挂的页零命中）。
