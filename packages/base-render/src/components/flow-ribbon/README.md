# flow-ribbon · 流向带

两张名单之间的**多对多**对应：左边每一个来源往右分出几股、右边每一个用途由几股汇成。三个骨架（形态）：

- `sankey` **桑基带**——左来源／右用途，**带宽＝金额**，两侧**同一把尺子**；
- `matrix` **交叉矩阵**——行＝来源、列＝用途，格里的条长与深浅都按**全表最大格**算；
- `rails` **两条构成轨＋中间汇合读数**——每格宽度＝这一格占总额的比例，两条轨同一总额、各自拉满 100%。

三者问的是同一个问题（谁养谁），**吃同一份数据**；形态只换骨架，不换口径。

## 何时用

- **用**：一笔钱／一批货从几张来源名单流进几张用途名单，读者要顺着一条带子从来源扫到用途；
  或者要一眼看出「哪一笔流量最大」（桑基）、「三个来源分别喂了哪几类」（矩阵）、
  「进项与出项各是什么构成、对不对得上」（两条轨）。
- **不用**：
  - 一条链（总额一路加减到明细）走 `invoice-lines`——链式表达不了「三笔来源养四类用途」；
  - 单层构成条（一段＝一个占比）走 `stacked-bar`——一条轨说不出「谁汇进谁」；
  - 要时间轴、要阈值线走 `cash-waterline`；要两个读数之间的关系走 `scatter-fit`。
- **窄容器（<620px）优先 `rails`**：桑基的带子在 320／390 档会细到看不出对应关系。
  桑基在窄档**照旧按同一把尺子画**（一处几何都不改）——它不会坏，只是不好读。

## 入参

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `title` | `string` | 必填 | 卡头标题（`钱从哪来、花到哪去`）。 |
| `sources[].name` | `string` | 必填 | 来源名单（左列／矩阵行），1–6 股，**顺序＝显示顺序**；名字非空、至多 12 字符、不许重名。 |
| `uses[].name` | `string` | 必填 | 用途名单（右列／矩阵列），1–4 类；同上（上限 4 是窄档约束：一格只有 60 出头，再多放不下金额）。 |
| `links[].from` | `string` | 必填 | 一笔流量的起点，必须是 `sources` 里的名字。 |
| `links[].to` | `string` | 必填 | 这笔流量的终点，必须是 `uses` 里的名字。 |
| `links[].amount` | `number` | 必填 | 这笔的金额（**正**的有限数）。同一对 `from → to` 只许一笔。 |
| `stamp` | `string` | — | 卡头里那枚时间窗（`09-01 – 09-24`）；不给＝不出。 |
| `form` | `'sankey'｜'matrix'｜'rails'` | `sankey` | 形态键（闭集；闭集外的值一律报错，不静默降级）。 |
| `unit` | `string` | `元` | 钱的单位：只上屏，不参与算数。 |
| `note` | `string` | — | 口径行；不给＝本件按形态写一句自己的口径（那句里带这把尺子的换算）。 |
| `extraClass` | `string` | — | 附加类名（空格分隔；逐个过类名正则）。 |

**名单里的每一项都必须至少出现在一笔流量里**：没有流量的那一项高度是 0，画出来是一条看不见的线
（按 0 画是错、按 1 画是编数据），故一律报错、请调用方把它从名单里去掉。

```js
renderFlowRibbon({
  title: '钱从哪来、花到哪去',
  stamp: '09-01 – 09-24',
  sources: [{ name: '工资' }, { name: '其他' }, { name: '上期' }],
  uses: [{ name: '餐饮' }, { name: '日用' }, { name: '储蓄' }, { name: '结余' }],
  links: [
    { from: '工资', to: '餐饮', amount: 3180 }, { from: '工资', to: '日用', amount: 1960 },
    { from: '工资', to: '储蓄', amount: 2000 }, { from: '工资', to: '结余', amount: 860 },
    { from: '其他', to: '结余', amount: 1500 }, { from: '上期', to: '结余', amount: 2100 },
  ],
});
```

## 契约

- **一件一目录**：`attrs.ts`（标记契约）／`fields.ts`（格式化与校验小件）／`model.ts`（读入参→选骨架→写口径句）／
  `forms.ts` ＋ `forms-rails.ts`（三骨架的几何：桑基与矩阵住前者，构成轨住后者）／`render.ts`（纯函数产标记）／
  `style.ts` ＋ `style-forms.ts` ＋ `style-rails.ts`（唯一样式来源：卡头名单脚注住前者，桑基矩阵住中者，构成轨住后者）／本文件。
- **形态是骨架，不是地址**：形态由 `input.form` 给定，**不随容器宽窄换**（换的是排版，见下）。
- **色只读皮肤**：一切颜色／圆角／字面／字号经 `skinVar()` 读 token；来源那一列的色阶是从 `accent`
  往 `surface` 掺出来的淡洗（权重 46／36／29／23／18／14），矩阵的深浅与构成轨的两层同理——**没有一处写死色值**。
- **宽度只听容器**：窄档一律 `@container`（阈值 620px）；本件不写任何按视口宽度的媒体查询。
- **零键盘依赖**：本件是纯静态图，标记里没有可点元素、也没有任何键位；调用方若把某一行或某一格包成入口，
  样式段里已经备好 44×44 的命中盒与可见焦点环（`:focus-visible`）。

## 不变量（判据逐条断）

1. **一个总额、一把尺子**：总额＝所有流量之和；`每 1% ＝ 总额 ÷ 跨度`，跨度＝`100 − 2 × (较多那一列的节点数 − 1)`。
   桑基两列**共用**这个跨度——**两侧的「每像素＝多少钱」恒等**，故左边一股与右边一格可以横着比。
2. **每段几何与它的读数同源**：桑基一个节点的高、一条带子两端的上下沿之差、矩阵一格的条长、
   构成轨一格的宽度，四个数**全部**＝`金额 ÷ 同一分母 × 同一个跨度`（判据从**印出来的读数**反推这些比值）。
3. **一条带子两端一样高**：`l2 − l1 ＝ r2 − r1`（＝这笔金额 × 同一把尺子）；同一节点的子带**恰好铺满**它。
4. **每一条读数恰好印一次**：桑基节点框高不够、或名字／金额比框宽时，这条读数整条搬到图下的名单里
   （框里只留一条无文字的图形）——**不压字、不 `…` 截断**。矩阵的空格写 `—`（不是 0）。
5. **进 ＝ 出**：两侧是同一批流量的两种数法，故 `Σ 来源 ＝ Σ 用途 ＝ 总额` 是结构事实，不是调用方要保证的事。
6. **构成轨的格宽加起来恰好 100.0%**（最大余数法分配，不会因为各自四舍五入差出 0.1% 的缺口）；
   窄到放不下百分数的格子不出字，但**它的读数在轨下的名单里一个不少**。
7. **确定性**：同一份入参渲染两次逐字节相同；标记不带皮肤类（换皮只换取值）。

## 数值字段与未知键（本批新立的口径，判据逐条断）

**两条数值闸**（每一处收数字的字段都过）：
1. **非有限**（`NaN`／`Infinity`／`-Infinity`）⇒ `badInput()` 抛 `BlocksError`；
2. **可加性溢出**：`|a| + |b| > Number.MAX_VALUE`（两笔同量级读数相加就成 `Infinity`，图上会写出 `1e+308`／`NaN`）⇒ `badInput()`。闸在 `fields.ts 的 reqMagnitude()`，上界常量 `FLOW_RIBBON_MAGNITUDE_MAX`（＝`Number.MAX_VALUE ÷ 2`）。
   - 判据是**相加会不会溢出**，不是"好不好读"——`1e21`／`1e-7` 这类**照旧合法**（本件有边界自证守着，别误杀）。

**表外的键一律拒**：顶层与**每个嵌套对象层**都查键（`flow-ribbon` 的 `assertKeys`：**自有属性 ＋ 原型链双查**）。
理由：未知键静默吞＝把 `amount` 写成 `ammount` 那种笔误会让屏上静静少一块，而调用方看不到任何报错。这条口径由 `test/跨件不变量.test.mjs` 第 ③ 组守着。

## 常见错法

- **两列各自归一**：左列按左列总额、右列按右列总额各画各的 ⇒「带宽＝金额」只在自己那一列成立。
  本件用一个总额 ＋ 一个跨度，判据按「像素比 ＝ 读数比」断死。
- **格宽按文字宽度排**（`flex: 0 0 auto` 不给 `width`）：占比根本没画出来。本件的格宽写在 `width` 上。
- **条长按本行最大算**：每行最深的那一格看起来一样重要。本件按**全表最大格**。
- **把「进 ＝ 出」交给调用方去保证**：两个数各写一遍就会走散。本件从流量汇总出来。
- **拿节点框当读数唯一去处**：资本里最细的那一股放不下名字与金额，硬塞就会截断——
  本件的做法是搬到名单里，读数一个不少。
