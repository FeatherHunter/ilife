# bulk-bar · 批量操作条

**一句话**：上面一列可勾的条目；选中 ≥1 条时**底下浮出一条操作条**（已选数 ＋ 选中读数 ＋ 动作按钮 ＋ 一句提示）；点一枚带**预演**的动作，就地展开确认面——**改之前先看见会改哪几条、哪条不适用**。

**形态**：本件只落地名册点名的**形态 A「选中后浮出来的操作条（底部）」**——出处＝原型墙 `.scratch/ui-组件墙/新件/parts-交互与流程.mjs` 的 `.c-bulk-a`（2026-09 用户裁定，三套皮肤 4/4/4），按层规重写（原型是一次性代码：无判据、无错误处理、读的是墙稿变量）。
形态键住 `BULK_BAR_FORMS` 闭集（今天只有 `A` 一格）——**加第二形态是在闭集里加一格，不是新开一件**。
同一件里的 B 档「抽屉式批量编辑」打分未过、**不落**；但它那层信息（「改之前能看见会改哪几条」）按工单留在本形态里：以**条内就地确认面**（`actions[].preview`）承载，不新建抽屉、不新建浮层。

## 何时用它（选型四条）

| 你要的 | 用 |
|---|---|
| 「勾几条，一起改一个字段」，改之前还要看清**会改哪几条** | **本件** |
| 「挑几条」——只负责勾、勾完没有下文 | `multi-checks`（多选清单） |
| 「一件破坏性的事，只问一句确定／撤销」 | `confirm-strip` |
| 「一直挂在页脚那儿的静态动作栏」 | `action-bar` |

判据一句话：**勾完要拿这几条一起做一件事，而且这件事值得先看一眼影响面** → 用它。
反过来说：不需要先看影响面的批量动作（例如「全选后导出」）不需要预演——那几枚动作不给 `preview` 就是直接派发。

## 入参

|---|---|---|---|
| `name` | `string` | 必填 | 机器键（事件 `detail.name`；确认面与错态的行内 `id` 拿它拼）。**非空、同页唯一** |
| `items` | `BulkBarItem[]` | 必填 | 条目（`BULK_BAR_ITEM_MAX`＝至多 200 条）。**给空数组 ＝ 出设计过的空态**（不是留白），那时操作条也不出（选中 0 条） |
| `items[].key` | `string` | 必填 | 机器键（原生 `<input value>` 与事件 `detail.keys`）。**非空、清单内唯一** |
| `items[].title` | `string` | 必填 | 行主字（如「餐饮 · 午餐」）。**非空** |
| `actions` | `BulkBarAction[]` | 必填 | 操作条上的动作。**至少要有一项** |
| `actions[].key` | `string` | 必填 | 动作键（事件 `detail.action`）。**非空、一排内唯一** |
| `actions[].label` | `string` | 必填 | 按钮上的字（**写动词**：「改分类」「删除」，别写「确定」）。**非空** |
| `countUnit` | `string` | `条` | 计数单位（屏上写「3 条已选」） |
| `tail` | `string` | — | 选中读数的尾段（如「合计 361.50」）。**选择一变就换成 `—`**（见不变量 5） |
| `hint` | `string` | — | 操作条底下那句提示（按不动的按钮就指它当说明） |
| `emptyText` | `string` | `没有可挑的条目` | 空态那句字 |
| `openAction` | `string` | — | 渲染时就展开哪一枚动作的确认面（**必须命中一枚带预演的动作**） |
| `form` | `'A'` | `'A'` | 形态键（闭集；闭集外一律 `badInput`） |
| `extraClass` | `string` | — | 附加类名（空格分隔，逐个过类名正则） |

下表是 **`items[]` 一格里面**的字段（名字不带前缀；上一张表的 `items[].…` 行是同一批字段的必填口径）：

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `key` | `string` | 必填 | 机器键（同上）。**非空、清单内唯一** |
| `title` | `string` | 必填 | 行主字。**非空** |
| `note` | `string` | — | 行副语（小字，如「09-25 · 现金」） |
| `reading` | `string` | — | 行右端读数（金额／条数，**已是给人看的样子**）。**永不 `…` 截断** |
| `selected` | `boolean` | `false` | 一开始就选中 |
| `disabled` | `boolean` | `false` | 勾不动：`<input disabled>` ＋ `cursor: not-allowed` |
| `disabledReason` | `string` | — | 勾不动的原因（**写出来**，不只染色；只在 `disabled: true` 时给） |

`actions[]` 的其余格：

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `tone` | `'plain' \| 'danger' \| 'primary'` | `'plain'` | 色档：素／不可逆／主动作（一排里至多一枚主按钮） |
| `preview` | `BulkBarPreview` | — | 这枚动作的预演：给了 ⇒ 按下去**先展开确认面**；不给 ⇒ 按下去直接派发事件 |
| `disabled` | `boolean` | `false` | 按不动（原因由操作条底下那句 `hint` 承担：**标了 `disabled` 就必须给 `hint`**，否则抛 `badInput`） |
| `busy` | `boolean` | `false` | 正在跑：字**原地换掉**（`正在改分类`）、按钮尺寸与动作排换行都不变（忙碌那枚字出流，不参与固有宽）、按钮按不动 |
| `error` | `string` | — | 这一枚动作的错态那句字（写在按钮旁边 ＋ `aria-describedby` 指它） |

`preview`（预演）：

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `title` | `string` | 必填 | 确认面标题（「批量改分类」）。**非空** |
| `rows` | `BulkBarPreviewRow[]` | 必填 | 逐条预演（**至少一条**，至多 50 条） |
| `cap` | `string` | — | 标题右端那句（「已选 3 条 · 改完能整批撤回」） |
| `valueLabel` | `string` | `改成` | 「改成」那枚标签的字 |
| `value` | `string` | — | 输入框里的现值 |
| `recent` | `string[]` | `[]` | 「最近用过」那几枚（点了填进输入框；至多 6 枚） |
| `summary` | `string` | 按预演算 | 脚上那句结论（缺省 `会改 2 条 · 跳过 1 条`） |
| `submitLabel` | `string` | 按预演算 | 主按钮的字（缺省 `改这 2 条`） |
| `cancelLabel` | `string` | `取消` | 取消那枚的字 |

`preview.rows[]`（预演里的逐条）：

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `keep` | `boolean` | 必填 | `true`＝这条会改；`false`＝跳过 |
| `to` | `string` | 必填 | 改后的值。**非空** |
| `from` | `string` | — | 改前的值（带删除线；跳过的那条可以不给） |
| `note` | `string` | — | 这一条的说明；**跳过的那条必填**（要写清为什么） |

**入参违规一律抛 `BlocksError`（`bad-input`）**，不静默兜底：形态闭集外、重键、空标题、`keep` 非布尔、跳过的行不写原因、`openAction` 未命中带预演的动作、`disabledReason` 与 `disabled` 不配套、动作 `disabled: true` 却没给 `hint`、**数组里有洞**（`new Array(n)` 这种稀疏数组：`map` 会跳过洞、渲染那一头才抛 `TypeError`）——逐条当场报错，并点名到 `input.<路径>`。

同页 `id` 由 `name` 与动作键拼出来（`bulkBarConfirmId`／`ErrorId`／`HintId`／`CountId`）：**逐字符编码**（`[A-Za-z0-9]` 照抄，其余写成 `_` ＋ 码点十六进制 ＋ `_`），所以中文件名／动作键不会撞成同一个 `id`——`aria-controls` 反查（运行时按 `id` 找确认面）点哪一枚就开哪一块。`name` 仍须**同页唯一**（同名的两块条拼出同名 `id`，那是调用方违约）。

## 契约与不变量（判据逐条断）

1. **真复选语义**：原生 `<input type="checkbox">` ＋ **整行是 `<label>`**（命中区 ≥52px 高）；勾选框的命中盒 44×44，视觉盒 24×24，原生框铺满命中盒（视觉隐藏走 `opacity:0`，**不是** `display:none`——那会把键盘可达性一起干掉）。
2. **勾选态至少两重非颜色标记**：勾选框里的对钩 `✓`（字）＋ 选中行左端的 2px 强调色侧标（形）；底色只是第三重。皮肤「大字报刊」下强调色＝墨黑，只染色的选中态在那里会塌。
3. **选中 0 条 ⇒ 整条 `hidden`**：移出可点范围与读屏顺序，**不只是变透明**（原型那条硬要求）。`display:flex`／`display:grid` 会压过浏览器默认的 `[hidden]{display:none}`，所以样式段里**显式重写**了 `[hidden]`。
4. **条不盖条目（在本流位置上）**：操作条**在流内**（自己占一行）＋ `position:sticky; bottom:0`。在流内 ⇒ 滚到宿主下沿时条顶不低于最后一行（条目与条不重叠，**粘住位移为 0**）；`sticky` ⇒ 宿主比视口高时条仍贴在视口底部**够得着**（这是「列表一长，条会被滚出屏幕、批量操作反而做不到」的解法，也是它比「纯静态在流内」多出来的那点代价：**粘住时它盖在正滚过的那几行上**，宿主整体在视口之外时浏览器会把位移夹到宿主上沿）。粘住时它是**不透明**的：`surface` 实底 ＋ 一条 `accent` 上边线（**不是**普通发丝线——它是这条操作条与「选中了哪些条目」同源的记号；原型那条 3px 零模糊外圈在纸上留不下来，改由它承担，取值与 `style.ts` 里那一条逐字对齐）＋ **皮肤自己的投影档**（paper／broadsheet／ink 的 `shadow` 本就是 `none` ⇒ 那三套下不动，neutral 下才浮起来）。**不用半透明**盖住条目。
5. **过期的读数不许留在屏上**：`tail`（如「合计 361.50」）是按**当时那份选择**算出来的；选择一变它就假了 ⇒ 运行时换成缺值符号 `—`，并派发 `ilife:bulk-change` 请调用方按新选择重渲染；勾回原样则复原。**本件不自己算金额**：算钱的口径只有一处（住 `multi-checks` 那边），本件只显示调用方给的读数。
6. **预演先于动作**：带 `preview` 的动作按下去**只展开确认面**（同时只开一块）；确认面里逐条写清「会改／跳过」（形 `✓`／`⊘` ＋ 字 ＋ 色三样都在），跳过的**必须写为什么**；主按钮的字按「会改几条」算，一条都改不了时它是 `disabled` 的。不带 `preview` 的动作按下去直接派发事件。
7. **触控地板**：一行 ≥52px（整行命中区）、勾选框 44×44、动作按钮与「最近用过」胶囊 ≥44×44、预演一行 ≥44px；相邻触控目标间距 ≥8px。**没有任何一处把键盘当通路**：确认与取消都是看得见、点得到的按钮（`:focus-visible` 的 2px 可见焦点只留给真实键盘用户）。
8. **状态矩阵**：`rest`／`:hover`（包在 `@media (hover:hover) and (pointer:fine)` 里，且**不是唯一通路**）／`:active`（按钮与胶囊 `scale(.98)`，80ms，只碰 `transform`）／`:focus-visible`（2px 可见描边）／`disabled`（`cursor: not-allowed` ＋ 写出原因；**动作标 `disabled: true` 时必须给 `hint`**，否则抛 `badInput`——没有说明的灰按钮不许出现在屏上）／`busy`（原地换字：忙碌那枚字**住在正常那枚字里面、绝对定位在它这块上**（横向按按钮内距外扩，所以它那块正好是按钮的可用宽度，忙碌字再长也只在按钮内部消化）——**出流 ⇒ 一个字都不参与按钮的固有宽**，不然「正在 ＋ 按钮字」会把动作排顶成两行；换字时按钮尺寸、动作排换行纹丝不动）／`error`（写在按钮旁边 ＋ `aria-describedby`）／`empty`（设计过的空态）。状态一律同步改写属性与文本，**不依赖 `transitionend`**；`prefers-reduced-motion` 下把过渡直接关掉。
9. **选中态照四档口径**：整行选中＝底 `surface-2` ＋ 左端 2px `accent` 侧标（行内主字仍 `ink`）；勾选框（无文字的格）＝`accent` 实底 ＋ `✓`；主动作按钮（**有文字的选中面**）＝底 `accent-soft` ＋ 字 `accent-text` ＋ 描边 `accent`，**不是**强调实底（正文级字压在 `accent` 实底上，neutral 那套只有 4.02，过不了 4.5 的文本地板）；不可逆那一档＝`danger` 字 ＋ `danger` 描边。**任何一处都不拿 `ink` 系当面**。
10. **窄宽两档**：容器宽 390 与 1280 下**零横向溢出**（`scrollWidth ≤ clientWidth`）、条里不出现横向滚动容器；长标题／长读数／长提示／长按钮字一律 `overflow-wrap:anywhere` 折行，**永不 `…` 截断**（金额、日期、状态尤其不许）。宽度只许听容器：窄档走 `@container`，媒体查询只判设备能力。
11. **零 DOM／零内联脚本**：模块代码剥掉字面量与注释后不出现 `document.`／`window.`／`navigator.`（DOM 只出现在 `buildBulkBarJs()` 产出的文本里）；标记里没有 `<script>`、没有 `on*=`。
12. **样式只经 `skinVar()` 读皮肤**：组件里不写手写的 `var(--ilife-…)`；不写 `:root`／`!important`；不定义新 token 名；全部规则 scope 在 `.<prefix>page-ui` 之下。

## 交互契约（运行时，`buildBulkBarJs()`）

| 动作 | 行为 |
|---|---|
| 勾／取消一行 | 已选条数**原地改写**；条按「>0 出、=0 `hidden`」显隐；展开着的确认面**自动收起**（它是按旧选择算的）；派发 `ilife:bulk-change`（`detail = { name, keys, count }`） |
| 点一枚带预演的动作 | 就地展开**这一枚**的确认面（同时只开一块；再点同一枚＝收起），按钮上 `aria-expanded` 跟着改 |
| 点一枚不带预演的动作 | 直接派发 `ilife:bulk-action`（`detail = { name, action, keys, value: null }`） |
| 点「最近用过」一枚 | 把它的字填进输入框（并把光标送进去）；不派发任何事件 |
| 点「取消」 | 收起确认面 ＋ 焦点还给按它的那一枚按钮（焦点不掉在 `hidden` 的元素上） |
| 点「改这 N 条」 | 派发 `ilife:bulk-action`（`detail = { name, action, keys, value }`）——**本件不写库**，也不自动收起（页面按事件重渲染，或给那一枚动作标 `busy`） |
| 重复注入 | 只绑定一次（文档根上的 `data-ilife-bulk-runtime`） |
| 不跑这段脚本 | 勾选与条按渲染时那份选择照常（原生复选），只是不派发事件、确认面不会展开 |

事件都冒泡到文档，页面用 `document.addEventListener(…)` 接自己的处理，**不引入任何全局**。

## 常见错法（别这么干）

- ❌ 把「会改哪几条」做成一句「已选 3 条」——那没说**改完长什么样** → ✅ 给 `preview.rows` 逐条写清「旧值 → 新值 ＋ 说明」，跳过的那条写上为什么。
- ❌ 给不带 `preview` 的破坏性动作指望本件替你问一句 → ✅ 破坏性动作走 `confirm-strip`／`dialog`；本件收的是**要改的那个值**＋预演。
- ❌ 用「确定」当按钮字：读的人不知道要确定什么 → ✅ 写动词（「改分类」「删除」「改这 2 条」）。
- ❌ 把合计写死在 `tail` 里让运行时自己算 → ✅ `tail` 是调用方给的读数，选择一变本件就换成 `—` 并派事件；算钱归调用方（口径只有一处）。
- ❌ 一排里放两枚主按钮：等于没有主按钮 → ✅ `primary` 一排一枚。
- ❌ 靠坐标／`hidden` 让它「看着消失」：条还在读屏顺序与可点范围里 → ✅ 选中 0 条时整条 `hidden`。
- ❌ 在标记或文案里写键帽（`Esc`／`⌘`／方向键）：手机上看到键帽会以为界面坏了 → ✅ 确认与取消都是真按钮。

## 关系

- 与 `multi-checks` 的分工：那件管**怎么勾**（全选、分组、合计，它底下那排动作**一直在**）；本件管**勾了以后干什么**（条**只在选中 ≥1 条时出现**，动作按下去先给一份预演）。两件都在页面上时，勾选本体应该只留一份（别让同一批条目挂两套勾选框）。
- 与 `confirm-strip` 的分工：那件收「确定／撤销」两个词（不可逆动作的二次确认）；本件收**要改的那个值**并先给影响面。
- 与 `action-bar` 的分工：那是静态底栏（不管有没有选中，一直挂在页脚）；本件随选择出现与消失。
- 样式与运行时由页面按需挂（加法式：不调 `bulkBarCss()`／`buildBulkBarJs()`、不挂 `.ilife-page-ui` 的页零命中）。
- 动作只派发事件：**落库／改分类归页面脚本与技能命令**，本件不写数据。
- 本件暂不提供汇总入口（同族第二件落地后，由先成立的那件立汇总，照 `sheetCss()` 先例）。
