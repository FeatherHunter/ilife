# radar-profile · 多维画像雷达

**一句话**：一个对象在几根互不同单位的轴上的形状；**三个形态**（`polygon` 多边形雷达（本期／上期两条轮廓）／
`wedge` 极区扇图（半径＝得分，达标环）／`rail` 展平成轴表（基准带＋我的位置））问的是同一个问题：
**这个对象偏在哪几根轴上**。

它替掉的三种错法：把几根轴合成一个总分（偏科被抹平）／六条进度条各读各的（看不出形状）／
拿其中一根轴的绝对值当整体结论（轴与轴不是同一个单位）。

## 何时用它（选型四条）

| 你要的 | 用 |
|---|---|
| 「一个对象在多个指标上偏成什么形状」 | **本件** |
| 「同一个指标上多个对象／多个期间的对照」 | `compare-columns`（双列对照）／`rank-list`（榜单） |
| 「多目标各自已达到多少」 | `progress-list`（每行是「已达到 ÷ 目标」的两数之比，没有形状、没有基准带） |
| 「两个读数之间是什么关系」 | `scatter-fit`（相关性散点：那是两个读数之间的关系，不是一组读数各自的位置） |

用在哪：卡路里（体测／体脂围度页）／作息管家（月度画像）／记账（支出结构自评）。

## 入参

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `title` | `string` | 必填 | 卡头标题（如「体测画像」） |
| `axes` | `RadarProfileAxis[]` | 必填 | 几根轴（**3–8 根**）；顺序即从正中开始**顺时针**的次序 |
| `form` | `'polygon'`／`'wedge'`／`'rail'` | `'polygon'` | 形态闭集；闭集外报 `BlocksError` |
| `stamp` | `string` | — | 卡头那枚时间窗（本期，如 `09-24`）；不给＝不出 |
| `pastStamp` | `string` | — | 形态 `polygon` 用：上期的时间窗（`08-24`），写在图例里 |
| `goal` | `number` | `80` | 形态 `wedge` 用：达标线（0…100） |
| `note` | `string` | 本形态的口径句 | 脚注一句人话；**给了就整句替换**那条例行口径 |
| `extraClass` | `string` | — | 附加类名（空格分隔，逐个过类名正则） |

**文本字段的口径**：可选文本（`stamp`／`pastStamp`／`note`）**空串＝未给**（与全层 `optText` 同口径）；
**全空白串一律拒**（`'   '` 会在屏上留一块空白）。必填的 `title` 与轴名同办。

**给别的形态才认的字段一律拒**（收下却不画＝静默丢数据）：`polygon` 才认轴上的 `past` 与 `pastStamp`；
`wedge` 才认 `goal`；`rail` 才认轴上的 `note` 与 `band`。

**轴（`axes` 的每一个元素）**

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `label` | `string` | 必填 | 轴名，**至多 6 个字**（浮在图的四周外侧，长了会顶宽容器）；**永不 `…` 截断** |
| `score` | `number \| null` | 必填 | 本期得分（0…100）；`null` ＝ **缺测**（整根不落图、读数写 `—`，**不当 0 分算**） |
| `past` | `number \| null` | — | 形态 `polygon` 用：上一期的得分（同上，可缺测） |
| `note` | `string` | — | 形态 `rail` 用：这一根的口径说明（`BMI 18.5–24`），写在轴名下面一行小字里 |
| `band` | `{ low: number, high: number }` | — | 形态 `rail` 用：基准区间（0…100，`low ≤ high`）；不给＝这一行只画基线与自己那根竖线 |

**示例入参**（本件唯一一份，皮肤矩阵判据拿它渲染本件、必须能**直接**渲染成功）：
按类型派生的样例只给一根轴（数组恒只给一个元素），而本件**轴少于 3 根当场报错**，故这里显式写一份：

<!-- 示例入参：皮肤矩阵判据拿它渲染本件，必须能直接渲染成功 -->
```json 示例入参
{
  "title": "体测画像",
  "form": "polygon",
  "stamp": "09-24",
  "pastStamp": "08-24",
  "axes": [
    { "label": "体重", "score": 62, "past": 58 },
    { "label": "体脂", "score": 71, "past": 74 },
    { "label": "肌肉", "score": 84, "past": 80 },
    { "label": "水分", "score": 55, "past": 53 },
    { "label": "骨量", "score": 78, "past": 78 }
  ]
}
```

上例走 `polygon` 形态（五根轴 ＋ 本期／上期两条轮廓）。换 `wedge` 就把轴上的 `past` 与 `pastStamp` 去掉、
加一个 `goal`；换 `rail` 就给轴加 `band`——**给别的形态才认的字段一律报错**。

## 契约与不变量

- **坐标只有一处算**（`scale.ts`）：`percentOfScore()` 把 0…100 的得分映射成 0…100 的占比，
  `radiusOfScore()` 再把占比乘上半径——**网格三圈的半径、多边形的顶点、扇区的半径与外沿、轨道上那根竖线、
  轴名的锚点百分比**全部从这两支出。**网格半径与印在刻度条上的那三个数是同一份真值**
  （`RADAR_PROFILE_RINGS`，里圈 33 分／中圈 66 分／外圈 100 分）：读者按刻度读点，读出来的就是那个读数。
- **图上的字一律是 HTML**：内联 SVG 只画网格与数据（SVG 里的字会随画布缩放，窄容器里读数先糊），
  轴名是绝对定位的 HTML，`left`／`top` 是同一套映射给出的百分比。
- **缺测的轴整根不画**：辐条、顶点、扇区、竖线一起不画，读数与表里写 `—`——**不当 0 分算**。
- **状态四档照法条**：本期轮廓＝`accent` 实线 ＋ 强调色淡洗的面（无文字的图形）；
  上期轮廓＝`ink-2` 虚线（弱一层就是它的语义）；达标／未达标＝`ok`／`warn`（语义档）；
  形态 `rail` 里「在带内」走灰字（状态做减法），只有出带的那一行才上 `warn` 与软底。
- **色不是唯一信息**：轴名与读数都印在图上、达标线画成虚线圆环、未达标逐根写出差的分数、
  差那一格给方向字形与正负号（`▲ +14`／`▼ −7`／`持平`）、图例里印出达标分。
- **读数永不截断**：图的四周按 `RADAR_PROFILE_MAX_LABEL_CHARS` 留出内距（轴名上限与内距读同一个常量），
  读数表的三列是 `auto`（格子跟着数字走）、轨道的读数是 `nowrap` ＋ `clamp()` 压在轨道里。
- **窄档不靠横滑**：宽度一律 `@container` 判（`RADAR_PROFILE_NARROW_PX`＝460／`RADAR_PROFILE_WIDE_PX`＝760，
  两份样式文件读同一份常量）；窄档只把读数表与轴表**收一档**（轴表收成两行），**一列不减**、不藏 `overflow-x`。
- **本件没有可点元素、没有运行时段**：纯静态图（无 `runtime.ts`）；页面不带它时零命中、逐字节不变。
  `:focus-visible` 的地板照留（调用方把某一行包成入口时焦点必须看得见）。
- **样式只有一份出口**：`radarProfileCss()` 汇总同目录 `style.ts`（卡壳／图／轴名／刻度条／读数表／图例）
  与 `style-forms.ts`（扇区段／轴表段）两份源码件——**拆分只为行数**（本包告警线 350），取值一个字节都没变。
- **用词纪律**：本件生成的字里不出现 `·`／`；`／并列顿号连排（仓库的分隔符门对可见文本零豁免）；
  圆心那个数是**平均分**（几根轴加起来没有意义，所以不叫「总分」）。

## 常见错法

- **拿本件当"多对象对比"**：雷达的几根轴不是同一个单位，只比形状；要对比两组对象走 `compare-columns`；
- **把缺测填成 0**：那样凹进去的地方会读成「这根很差」，而事实是「这根没测」——本件要求显式给 `null`；
- **轴名写长句**：超过 6 个字当场报错（它浮在图的四周外侧，长名字会把图挤没）；
- **轴少于 3 根或多于 8 根**：三根以下围不成形状，八根以上窄档上挤在一起——两种都当场报错；
- **形态与字段对不上**：选 `wedge` 却给轴 `band`、选 `rail` 却给 `goal` 都会当场报错，不静默降级；
- **全缺测**：一根轴的读数都没有就没有形状可画，当场报错（该显示空态的是调用方）；
- **`rail` 那条带读成"目标值"**：色带是这一根的**正常区间**（`low` 到 `high`），不是「要达到多少」——
  要「已达到 ÷ 目标」走 `progress-list`。

## 判据（`test/radar-profile.test.mjs`）

① 渲染契约：三形态各自的槽位与枚数／**刻度与坐标同一份真值**（从**印出来的刻度条**反推半径基准，
再把每个顶点、扇区半径、轨道竖线的位置对回它自己的读数）／缺测轴**不落图**且写 `—`／
三形态的缺槽分支／转义面／**全部**非法入参分支（每个都断 `BlocksError`）；
② 样式与零 DOM 纪律（scope 恰一次、零 `@media` 宽度查询、零颜色字面量、零手写 `var(--ilife-…)`、
零键盘语汇、零可点元素、两处容器阈值只有一处来源）；③ 加法式（不开＝逐字节不变）；
④ **四档几何**（真机 headless Chrome ＋ CDP：容器 **320／390／620／1280** 下零横向溢出、
轴名与读数零截断、顶点全在图框里；含长标题／六字轴名／全满分三种压力样例；起不来则退确定性几何判据）；
⑤ 皮肤纪律（四套皮肤下标记逐字节相同、真机上达标扇区取 `ok`、未达标取 `warn`）。

## 关系

- 与 `progress-list` 的分工：那是多目标进度（每行一个比值），本件是一个对象在几根轴上的形状；
- 与 `compare-columns`／`rank-list` 的分工：那两件都在**一个**指标上比多个对象／期间；
- 与 `scatter-fit` 的分工：那是两个读数之间的关系（点云／趋势），本件是一组读数各自的位置。
