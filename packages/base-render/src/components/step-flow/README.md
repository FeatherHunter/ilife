# step-flow · 步骤条

**一句话**：**做到第几步了**——竖排逐步：左列节点（✓／双环内点／虚线空圈 ＋ 序号）＋ 名称、状态字、估时实耗、说明。

## 何时用它（选型四条）

| 你要的 | 用 |
|---|---|
| 一步一步走、要看出"现在该做哪一步" | **本件** |
| 一行一条、可勾选（买菜清单／盘点／待办） | `task-list`（勾选清单） |
| 一笔在途的事走到哪个阶段（分期／保修／证件） | `status-row`（状态台账行） |
| 还剩几天到期、每行一个动作 | `due-row`（到期行） |

## 入参

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `steps` | `StepFlowStep[]` | 必填 | 逐步；空数组且无 `absentLine` ⇒ 空串 |
| `steps[].title` | `string` | 必填 | 这一步做什么（`备料`／`下肉煸炒`） |
| `steps[].state` | `'done' \| 'now' \| 'todo'` | 必填 | 三态之一（**同时只能有一个 `now`**） |
| `steps[].stateWord` | `string` | 三态默认词 | 覆盖状态字（默认 `已完成`／`正在做`／`未开始`） |
| `steps[].estimate` | `string` | — | 估时（`估 6 分`） |
| `steps[].actual` | `string` | — | 实耗（`实 7 分`）：已完成／当前的步才有 |
| `steps[].description` | `string` | — | 说明（可长；当前那一步尤其要有） |
| `steps[].note` | `string` | — | 一句强调（`比预计多用了 2 分钟`） |
| `steps[].noteTone` | `'plain' \| 'warn'` | `plain` | 强调的语气 |
| `title` | `string` | — | 小标题（`辣椒炒肉 · 第 3 / 5 步`） |
| `count` | `string` | — | 右侧读数（`预计还要 6 分钟`） |
| `foot` | `string \| string[]` | — | 脚注（`总估时 16 分`／`已用 9 分`）：数组＝逐段一枚 |
| `absentLine` | `string` | — | 空态那一句（`这道菜还没有步骤`）：它是"没什么"，不是一步 |
| `form` | `'vertical'` | `vertical` | 形态键（闭集；本件只落地形态 A「竖排带说明」） |
| `extraClass` | `string` | — | 附加类名（空格分隔） |

## 契约与不变量

- **三态靠「字 ＋ 形 ＋ 色」三样一起给**：节点＝实心圆带 ✓ ／ 双环带内点 ／ 虚线空圈带序号；
  状态字＝底线（已完成）／实底块（正在做）／虚线框（未开始）；连线＝实线（走过的）／虚线（没走的）
  ⇒ 「大字报刊」皮肤下强调色＝墨黑，形状与线型照样分得开。
- **同时只能有一个"当前步"**：两个 `now` 会让读者不知道现在该做哪一步；归一化期就拦（`badInput`）。
- 节点列定宽（`STEP_FLOW_NODE_COLUMN_PX`＝34）⇒ 逐步节点竖排在同一列、连线一条直；连线从节点下方量起。
- 名称／状态字／估时三槽各自独立；估时实耗走等宽数字、`white-space:nowrap`（不许被 `…` 截断）；
  说明与强调句才允许长、允许换行（`overflow-wrap:anywhere`）。
- 缺值写成 `—`（`STEP_FLOW_MISSING`）：不许写 0、不许留空。
- 本件**零 DOM、零动效、零可点元素**；窄档由**容器**决定（`@container ilife-step-flow`，断点 440）。

## 常见错法

- 三态只换个圆点颜色（黑白打印／色盲下全塌）⇒ 形状 ＋ 记号 ＋ 状态字三样都要有。
- 估时实耗混在一句里（「大概 6 分钟，我用了 7 分钟」）⇒ 分两槽，同一条线上对得齐。
- 一步写成一段正文（读者找不到"现在该做什么"）⇒ 当前步要有状态字与说明；步名要短。
- 拿本件当进度条使（要一根横条看比例）⇒ 那是 `scale-bar`／`progress-ring` 的活。
- 让页面自己画"第 3 步高亮"（两处各记一份当前步）⇒ 当前步由 `state: 'now'` 说，只此一处。
