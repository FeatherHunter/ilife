# page-head · 页头

**一句话**：一页最上面那段 —— 眉标（技能名 · 域）／页标题（`<h1>`，一页恰好一个）／**主读数（第二行大字）**／副题（时间窗／范围／条数）／口径行（这一页的数字怎么算的）／可选右上工具位。

**形态**：本件只落地**形态 B「读数当第二行」**——出处＝原型墙 `.scratch/ui-组件墙/parts-01-纸面与页头.mjs` 的 `.c-page-head.hero`（2026-09 用户裁定落地的那一形态），按层规重写（原型是一次性代码：无判据、无错误处理、读的是墙稿变量）。
形态键住 `PAGE_HEAD_FORMS` 闭集（今天只有 `hero` 一格）——**加第二形态是在闭集里加一格，不是新开一件**（形态是骨架，不是地址）。

## 何时用它（选型三条）

| 你要的 | 用 |
|---|---|
| 一页的**开头那段**：谁看这页／这页叫什么／主读数／范围／怎么算的 | **本件** |
| 一页的**唯一主要读数**单独成块（页中、不带上头的眉标与标题） | `summary-head`（主数字头） |
| 一段内容的开头一行（小节标题 ＋ 计数 ＋ 动作） | `section-head`（未落地，见原型墙 04） |

**没有主读数的页不走本件**：主读数是本形态的识别特征（`reading.value` 必填）。其余形状（时间窗条／侧挂仪表卡／报头数据带）在原型墙里是另外三个形态，裁定落地的只有本形态。

## 入参

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `skill` | `string` | 必填 | 技能名（眉标主段，「卡路里」）。**非空** |
| `title` | `string` | 必填 | 页标题（`<h1>`）。**非空**；长了换行，不许 `…` |
| `reading` | `{ value; unit?; denominator?; note? }` | 必填 | 主读数（下表） |
| `domain` | `string` | — | 域（眉标次段，「看本周饮食」）；不给＝眉标只有技能名 |
| `sub` | `string \| string[]` | — | 副题：时间窗／范围／条数。串＝一段；数组＝逐段一枚 `<span>` |
| `caliber` | `string \| string[]` | — | 口径行：这一页的数字怎么算的。串＝一句话；数组＝分段（段间一条发丝线） |
| `tool` | `string` | — | 右上工具位：**只放一句读数或一枚状态字**（不放按钮） |
| `form` | `'hero'` | `'hero'` | 形态键（闭集；闭集外一律 `badInput`） |
| `extraClass` | `string` | — | 附加类名（空格分隔，逐个过类名正则） |

`reading` 的四格：

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `value` | `string \| null` | 必填 | 主读数（**已是给人看的样子**：取整与千分位归调用方）。`null` ＝ **缺值**（写成 `—`） |
| `unit` | `string` | — | 单位（`卡`／`元`／`件`）：小一号跟在值后 |
| `denominator` | `string` | — | 分母／标尺（`/ 1,800 卡`），排在主读数之后 |
| `note` | `string` | — | 值后的说明（`七日合计`）；与单位不是一回事 |

**缺值与空串是两件事**：`value: null` → 屏上写 `—`（缺值写成 `—`，与「0」区分）；`value: ''` → `badInput`（说不出「这页到底有没有数」）。

## 契约与不变量（判据逐条断）

1. **尺度**：主读数字号**严格大于**页标题，且**不小于正文的 2 倍**。样式里只写一个数（`PAGE_HEAD_READING_SCALE = 2.2`，读数是页标题的 2.2 倍），皮肤只给 `fs-h1` 一档 ⇒ 三套皮肤下比值都成立（2.2×`fs-h1`÷`fs-body` ＝ 4.11／4.68／4.11）。
2. **不截断**：长标题／眉标／副题**不许 `…`**（可以换行）；样式段里没有 `text-overflow`／`line-clamp`／`white-space: nowrap`／`overflow: hidden`。
3. **窄宽两档**：容器宽 390 与 1280 下**零横向溢出**（`scrollWidth ≤ clientWidth`）、主读数不被裁、标题不掉字。
4. **各套皮肤下标记逐字节相同**：皮肤只换样式段（取值表），标记一个字节不动。
5. **零 DOM／零内联脚本**：模块代码剥掉字面量后不出现 `document.`／`window.`／`navigator.`；产出的标记里没有 `<script>`，也没有 `on*=` 内联事件。
6. **样式只经 `skinVar()` 读皮肤**：组件里不出现手写的 `var(--ilife-…)`；不写 `:root`／`!important`；不定义新 token 名；全部规则 scope 在 `.<prefix>page-ui` 之下。
7. **响应式一律容器驱动**：本件设 `container-type: inline-size`（它自己就是容器），折行靠内在尺寸 ＋ `flex-wrap`，窄档调整走 `@container`；本件**一条 `@media` 都没有**（媒体查询只许判设备能力，不许判宽度）。
8. **无障碍地板**：文字色只取 `ink`／`ink-2`／`accent-text` 三档（各套皮肤下对 `ground`／`surface` 都 ≥4.5:1；`accent` 是非文本档，只出现在那枚方点的底色上）；`:focus-visible` 给 2px 可见焦点；长串 `overflow-wrap: anywhere`；缺值写成 `—`。

## 常见错法

- 把口径写成一句灰字塞在标题下面 —— 读者分不清哪行是标题、哪行是算法说明；
- 主读数与标题**抢同一行**（或与标题同级同字号）—— 窄容器下标题被挤成一列孤字，读数被压成正文大小；
- 用 `value: ''` 表达缺值（应当 `null` → `—`）；
- 长标题用 `…` 截断（关键信息不许截；要短就调用方自己短）；
- 在工具位放按钮（按钮归 `action-bar`；工具位只放一句读数或一枚状态）；
- 同一个数在首屏说两遍（页头说了、结论句再说一遍）。

## 关系

- 与 `summary-head` 的分工：本件是**页的开头那段**（带眉标与 `<h1>`），`summary-head` 是**页中的读数块**（带印章与脚行）。同一页里两者都出现时，页头那段是主读数、页中的只能是别的口径（否则就是上面第 6 条错法）。
- 样式由页面按需挂 `pageHeadCss()`（加法式：不调它、不挂 `.ilife-page-ui` 的页零命中）。
- 本件暂不提供族汇总入口（同族第二件落地后，由先成立的那件立汇总，照 `sheetCss()` 先例）。
