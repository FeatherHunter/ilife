# gantt-timeline · 甘特时间线

**一句话**：把「什么时候做什么、谁在做、还差什么才能开始」画成一行一条的横条——
**一行＝一条资源**（灶位／设备／台面），段落按状态给形，空档段照实画出来，另有一条**关键路径**带标着 1 起的顺序号。

落地的这一档是原型墙 `.scratch/ui-组件墙/新件/parts-数据与仪表.mjs` 第 61 件的**形态 C「资源泳道（灶位）× 关键路径带」**
（用户在**三套**皮肤上逐格 4/4/4——墙只给 A／B／C 三个别名；同一件的 A 单日泳道／B 周甘特表**没有**落地，等复看后再单独派活）。

它替掉的两种错法：**只列时间点的清单**（看不出并行的时候哪条资源被占住）与
**用一条 24 小时的连续占比表达并行的多件事**（那是 `hour-band`：无行、无依赖、答不出「哪条空着」）。

## 何时用它（选型四条）

| 你要的 | 用 |
|---|---|
| 「一餐多道菜并行的时候，哪条灶位什么时候空」 | **本件** |
| 「单日 24 小时怎么分配的」（一条带状占比，无行无状态） | `hour-band`（时段带，同族） |
| 「同一条量程上比长短的若干区间」（无开始／时长／结束三列读数） | `range-bar`（区间条，同族） |
| 「一个指标排序」「两个指标的关系」 | `rank-list`／`scatter-fit` |

用在哪：私家大厨（跟着做：一餐多道菜并行）／作息管家（今天那页：一条泳道＝一类事）。

## 入参

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `title` | `string` | 必填 | 卡头标题（`红烧肉套餐 90 分钟`） |
| `lanes` | `GanttTimelineLane[]` | 必填 | 资源泳道（1–8 条；**行序＝给的次序**） |
| `keyPath` | `GanttTimelineKeyPath` | — | 关键路径带（单独一条泳道，段上标 1 起的顺序号）；不给＝不出这一行 |
| `milestones` | `GanttTimelineMilestone[]` | — | 里程碑（零时长的点，**每个占一行**，排在泳道之后）；不给＝不出 |
| `cursor` | `GanttTimelineCursor` | — | 「现在」游标（竖线 ＋ 线上一枚字，如 `14:20`）；不给＝不画 |
| `cellMinutes` | `number` | `5` | 每格几分钟（格数 ＝ 时间跨度 ÷ 它）；**段的起止与里程碑都必须是它的整数倍** |
| `spanMinutes` | `number` | 按数据算 | 时间跨度（分钟）：缺省取「落在最晚的那一处」（段末／里程碑／游标），再向上补满整格 |
| `tickText` | `string[]` | 分钟数 | 刻度文字（**枚数 ＝ 算出来的刻度数**）：24 小时那种轴写 `['00:00', '06:00', …]` |
| `axisName` | `string` | `分钟` | 刻度行左端那枚量名（窄档折到刻度之上，**任何一档都看得见**） |
| `stamp` | `string` | `<n> 条泳道` | 卡头中间那枚（`4 条灶位`） |
| `tail` | `string` | — | 卡头右端那句读数（`上桌 21:25`） |
| `note` | `string` | 本件口径句 | 口径行；给了就整句替换 |
| `form` | `'C'` | `'C'` | 形态闭集；闭集外报 `BlocksError` |
| `extraClass` | `string` | — | 附加类名（空格分隔，逐个过类名正则） |

**泳道（`lanes` 的每一个元素）**

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `label` | `string` | 必填 | 资源名（`灶 炒锅`／`电饭煲`）；长了换行、不截断 |
| `note` | `string` | 按被占用的分钟数算 | 行左端的读数（`占用 65 分`／`未占用`） |
| `segments` | `GanttTimelineSegment[]` | 必填 | 这条资源被占用的段；**空数组 ＝ 整段时间都空着**（画一条整段的点线块） |

**段（`segments` 的每一个元素）**

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `from` | `number` | 必填 | 起始分钟（≥ 0，**落在格线上**） |
| `minutes` | `number` | 必填 | 时长（正数，**整数格**；空档段至少 2 格） |
| `state` | `'done' \| 'doing' \| 'wait' \| 'plan' \| 'idle'` | `'plan'` | 段的状态；`idle` ＝ 空档段（点线块 ＋ 块里写分钟数） |

|---|---|---|---|

| `keyPath.label` | `string` | `关键路径` | 这条泳道的名字 |
| `keyPath.note` | `string` | `不能并行的 <段数> 段` | 这条泳道的读数 |
| `steps[].name` | `string` | 必填 | 这一段的动作名（`切配`） |
| `steps[].minutes` | `number` | 必填 | 这一段的时长（正数，整数格） |
| `milestones[].at` | `number` | 必填 | 落在第几分钟（≥ 0，**落在格线上**） |
| `milestones[].label` | `string` | 必填 | 名字（`上桌`）——写在行左端，轨迹里只有那枚 `◆` 与它旁边再写一遍的名字 |
| `milestones[].note` | `string` | `<分钟数> 分 里程碑` | 行左端的读数 |
| `cursor.at` | `number` | 必填 | 游标落在第几分钟（≥ 0；超出数据末端时时间跨度跟着它延长） |
| `cursor.label` | `string` | 必填 | 线上那枚字（`14:20`） |

## 契约与不变量

- **落位只有一处算**：`scale.ts` 把「分钟 → 第几格／占几格／百分比」算成一份轴域，
  段的 `grid-column`、空档块、里程碑那枚 `◆`、游标那条竖线、**刻度数字写在哪几格**全部从它出
  ⇒ 读者按刻度数条一定数得对。
- **格是精度**：段的起止与里程碑必须是 `cellMinutes` 的整数倍，不是的**当场报错**，
  不"描到最近的格线"（描歪的条会让人读出一个错的时间）。判的是**格号**本身（相对容差 1e-12）：
  `minutes: 1e-9` 这种"看着像 0"的时长照拒——它按格画出来是一整格，读数却写「占用 1e-9 分」，
  画的宽度与读数不符。
- **格数由轴域算**（6–24 格）：跨度太短就补到 6 格，超 24 格报错（请把 `cellMinutes` 调粗）。
  刻度数字最多 6 枚，写在哪几格也是算出来的。
- **时间跨度按数据算**：段末／里程碑／游标里最晚的那一处就是下界，`spanMinutes` 只当「至少到这儿」。
- **一段资源同一时刻只做一件事**：同一条泳道里两段压在一起当场报错（那是数据错，不该画出来）。
- **色不是唯一信息**：状态给三样——**形**（`✓` 已完成／`▶` 进行中／`⋯` 等待／`▷` 未开始／`◆` 里程碑）、
  **字**（图例逐档写 `已完成`／`进行中`／…／`里程碑`）、**色**（底与边）。图例**只列这一段里真的出现过的档**：
  有一条关键路径才列「关键路径」，有里程碑才列「里程碑」（那枚 `◆` 不带字面解释就是哑的）。
- **选中／填充四档守法则表**：关键路径段里那枚顺序号、游标上那枚时间、图例那几枚都**有正文级的字** ⇒
  走 `accent-soft` 底 ＋ `accent-text` 字 ＋ `accent` 描边；只有「进行中」那根**不带短字**的条是**无文字的实底**
  （条上只有 `▶` 这类图形）。那根条一旦带了 `label`（段里那枚短字），就在标记里带一枚 `is-labelled`，
  与关键路径段同档改走软底——`accent-ink` on `accent` 在 neutral 皮肤下只有 4.02，正文过不了 4.5 的文本地板
  （判据从样式段读那条规则的底与字，四套皮肤逐套实算）。
- **窄档零横向溢出靠换行，不靠截断**：名字、读数、口径行一律 `overflow-wrap:anywhere`；
  本件**不写** `overflow:hidden`、不写 `text-overflow`、不写 `…`。刻度数字的宽度上限＝相邻两枚之间的格数，
  游标那枚字**在流里自己占一行**：横坐标＝「线 ＋ 4px」，可用宽度＝线到轨迹那一侧边缘（至少半条轨迹）
  ⇒ 字长了就在那一行里换行、**把行往下推**，既不横向溢出、也不盖住第一条泳道（判据断「字底 ≤ 第一条 row 顶」）。
- **窄宽两档只听说容器**：`@container` 判宽度——窄档标签折到轨迹之上（一行＝名字 ＋ 读数 ＋ 整条轨迹），
  宽档（≥620px）标签列回到左侧（96px ＋ 轨迹）。**零 `@media`**（视口宽 ≠ 组件宽）。
- **本件没有运行时段**：这是纯静态图（没有 `runtime.ts`）——**没有可点元素**，故也不谈命中盒：
  条、空档块、里程碑点、游标都只是读数；页面不带它时零命中、逐字节不变（加法式）。
- **本件没有「缺值」这一档**：读数要么由调用方给（空串＝未给），要么由本件从别的读数算出来；
  真的没有就**整枚不出**（不写 0）。`—` 留给有缺值语义的件。
- **缺省口径句是这一件的读数纪律**，不是装饰：不给 `note` 就用它。

## 常见错法

- **拿它当「一条时间轴」用**：本件一行＝一条**资源**；任务是落在资源行上的段。没有资源可分的单日占比走 `hour-band`。
- **把不能并行的步骤拆到不同泳道里**：那几步是**关键路径**（单独一条带 ＋ 顺序号），拆开就读不出「这一餐最少要多久」了。
- **段的起止不对格线**：`from: 7`、`cellMinutes: 5` ⇒ 当场报错。要么把时间对齐，要么把 `cellMinutes` 调细。
- **空档段只给一格**：块里那枚分钟数放不下（要拆成好几行），本件拒收——把短空档并进相邻段，或干脆不列。
- **同一泳道两段重叠**：数据错，本件报错而不是"画在上面"（那样读者会把两条都当成占用）。
- **一屏十条以上泳道**：读不出「哪条空着」，本件收在 8 条以内；再多请调用方分页。
- **`tickText` 枚数给错**：刻度枚数是算出来的（跨度 ÷ 每格 → 每几格一枚），给错了当场报错。

## 判据（`test/gantt-timeline.test.mjs`）

① 渲染契约：骨架逐层对得上／**刻度与落位同一份真值**（段的 `grid-column` 从刻度区间反算得回原分钟数，
画出来的格数与读数一致）／无障碍名逐句对账／图例只列出现过的档（含里程碑）／
转义面／**全部**非法入参分支（每个都断 `BlocksError`，含里程碑负数与"看着像 0"的时长）；
② 样式与零 DOM 纪律（scope 恰一次、零 `@media`、零颜色字面量、手写 `var(--ilife-…)` 按该件**全部** `style*.ts` 扫、
零 `overflow:hidden`／`text-overflow`；「进行中 ＋ 短字」那一档逐套皮肤实算文本地板）；
③ 加法式（不开＝逐字节不变）；④ 两档几何（真机 headless Chrome ＋ CDP：容器 390 与 1280 下零横向溢出、
条不跑出轨迹、刻度与图例零截断、**游标那枚字的底不越过第一条 row 的顶**）；
⑤ 皮肤纪律（四套皮肤下标记逐字节相同）；⑥ 零死代码与单一来源（件里每个 `export` 都得有人用；
状态类名只许从 `ganttTimelineStateClass()` 出——条与图例那枚形共用一份拼法）。

## 关系

- 与 `hour-band` 的分工：那是单日 24h 一条的连续占比（无行、无状态、无格刻度）；
- 与 `range-bar` 的分工：那是同一条量程上比长短的多泳道区间（无开始／时长／结束三列读数、无里程碑、无空档段、无依赖、无游标）；
- 与 `calendar-month` 的分工：那是「哪一天有什么」的日格，本件读的是「哪条资源什么时候空」。
