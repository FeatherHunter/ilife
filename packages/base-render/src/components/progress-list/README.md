# progress-list · 多目标进度

**一句话**：一页上三四个目标各自走到哪儿 —— 每行＝**目标名 ＋ 状态字**／**当前 / 目标（＋单位）**／**条**／**一句「还差多少」**。

**形态**：本件只落地**形态 A「四行清单」**——出处＝原型墙 `.scratch/ui-组件墙/parts-11-加量池.mjs` 的 `.c-p2-list`（2026-09 用户裁定落地的那一形态），按层规重写（原型是一次性代码：无判据、无错误处理、读的是墙稿变量）。
形态键住 `PROGRESS_LIST_FORMS` 闭集（今天只有 `rows` 一格）——**加第二形态是在闭集里加一格，不是新开一件**。

## 何时用它（选型三条）

| 你要的 | 用 |
|---|---|
| 一次看**好几个目标**各走到哪儿（热量／饮水／运动／体重；预算；盘点进度） | **本件** |
| 只有**一个**读数、带标题与刻度 | `scale-bar`（刻度条） |
| 只列读数、**不带目标** | `metric-grid`（读数格） |

本件与 `scale-bar` 的分工：`scale-bar` 是**一条**（一个值对一个目标），本件是**一页多行**，且每行自带「还差多少」那句人话。

## 入参

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `rows` | `ProgressListRow[]` | 必填 | 目标行（下表几行走同一张表：`rows[].x`） |
| `rows[].label` | `string` | 必填 | 目标名（「热量」）。**非空**；长了换行，不许 `…` |
| `rows[].current` | `number \| null` | 必填 | 当前值。`null` ＝ **未记录**（写成 `—`，与 `0` 区分） |
| `rows[].goal` | `number` | 必填 | 目标值。**有限数且 > 0**（分母为 0 算不出比例 ⇒ `badInput`） |
| `rows[].unit` | `string` | — | 单位（`卡`／`毫升`／`千克`）：接在目标值后，也接在「还差多少」句尾 |
| `rows[].display` | `string` | — | 当前值的显示字（千分位之类）；不给＝本件排（`1,189`） |
| `rows[].goalDisplay` | `string` | — | 目标值的显示字；不给＝本件排 |
| `rows[].remainText` | `string` | — | 「还差多少」整句；不给＝本件按状态算（见下） |
| `rows[].state` | `string` | — | 状态字（覆盖算出来的那句，如「落后 1 天」） |
| `rows[].tone` | `'none' \| 'ok' \| 'warn' \| 'danger'` | 按状态 | 语气档：**只改条的色**，不改语义 |
| `heading` | `string` | — | 小标题（「今天四个目标」） |
| `note` | `string \| string[]` | — | 口径行：这批目标怎么算的。串＝一句话；数组＝分段 |
| `emptyLine` | `string` | — | 一行都没有时出的人话（「这个账本还没定目标」） |
| `form` | `'rows'` | `'rows'` | 形态键（闭集；闭集外一律 `badInput`） |
| `extraClass` | `string` | — | 附加类名（空格分隔，逐个过类名正则） |

## 契约与不变量（判据逐条断）

1. **状态由本件算，且必带状态字**：`current > goal` → `over`（「已超」）；`current >= goal` → `done`（「已达标」）；其余 → `on-track`（「进行中」）；`current === null` → `blank`（「未记录」）。每档都有一枚**状态字**上屏 ⇒ **色不是唯一信息**（换到墨黑强调的皮肤，读起来丢不掉状态）。
2. **条的比例由本件算**：`current / goal` 夹在 `0..100` 落内联 `style="width: …%"`；调用方**不传宽度**（传了就有第二个事实源）。超目标只把 `aria-valuenow` 报成真实值（可 > 100），条本身仍画满。
3. **「还差多少」是本形态的第四段**：`还差 611 卡`／`刚好达标`／`已超 2.4 千克`／（未记录时不出）。整行独占，不跟条抢宽度。
4. **缺值写成 `—`**，且未记录那行**不出 `aria-valuenow`**（报了就是撒谎）；`current: ''` 不是缺值，是错。
5. **数字只有一条排法**：`formatProgressNumber`（最多两位小数、去尾随 0、千分位、自算不依赖 locale）；等宽数字 `font-variant-numeric: tabular-nums`，多行上下对齐。
6. **窄宽两档容器驱动**：本件设 `container-type: inline-size`（它自己就是容器），窄于 `PROGRESS_LIST_NARROW_PX`（360px）时目标名与状态字改走上下两行；本件**一条 `@media` 都没有**。
7. **零阴影下层次仍在**：行间靠**发丝线**，条靠**轨的软底 ＋ 一圈发丝线**，字重分主副 —— 不靠投影、不靠大圆角。
8. **样式只经 `skinVar()`**：不写手抄的 `var(--ilife-…)`、不写 `:root`／`!important`、不新增 token 名；全部规则 scope 在 `.<prefix>page-ui` 之下。

## 常见错法

- 把「当前 / 目标」塞进条里当标签 —— 条一窄，字先没；
- 只给一条进度条、不给状态字 —— 换皮换成墨黑强调后，「到没到」只能靠长度猜；
- 让调用方自己算百分比传进来 —— 同一个事实两处算，偏差无处可查（本件就是要替掉这一步）；
- 用 `current: 0` 表达「还没记」（应当 `null` → `—`）；
- 拿本件当「一个数」的展示件：一个读数带刻度走 `scale-bar`。

## 关系

- 用在哪：卡路里（热量／饮水／运动／体重四目标）／记账（预算）／居家管家（盘点）。
- 样式由页面按需挂 `progressListCss()`（加法式：不调它、不挂 `.ilife-page-ui` 的页零命中）。
- 本件不带可点元素；要「点进目标详情」，由调用方在行上包链接（`:focus-visible` 地板已在样式段里给好）。
