# compare-columns · 双列对照

**一句话**：两个窗口逐项并排 —— 左侧窗口（上月 / 之前 30 天）的值与条、中缝那一列的项名、右侧窗口（本月 / 最近 30 天）的值与条，最后一格是**差额单独一行**，再下面是口径行。

**形态**：本件只落地**形态 A「背靠背条形」**——出处＝原型墙 `.scratch/ui-组件墙/parts-03-对照与榜单.mjs` 的 `.c-compare-columns-a`（2026-09 用户裁定落地的那一形态），按层规重写（原型是一次性代码：无判据、无错误处理、读的是墙稿变量）。
形态键住 `COMPARE_COLUMNS_FORMS` 闭集（今天只有 `back-to-back` 一格）——**加第二形态是在闭集里加一格，不是新开一件**（形态是骨架，不是地址）。

## 何时用它（选型三条）

| 你要的 | 用 |
|---|---|
| **两个窗口**逐项并排，还要看得出「哪一项在拉差额」 | **本件** |
| 单个窗口的「名称 ｜ 条 ｜ 数值」分布（同一个窗口内部的占比） | `renderDistributionRows`（分布条行） |
| 一条记录的「改前 → 改后」（同一项的新旧值） | `renderChangeRows`（新旧值行） |

**只列两窗都有的项**：交集归调用方算。本件没有「这一侧缺值」这一档 —— 缺一边的项不是对照项，硬塞进来会让差额的含义变味（差额 ＝ 各共同项之差的和）。

## 入参

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `leftLabel` | `string` | 必填 | 左窗口名（「上月」／「之前 30 天」）。**非空** |
| `rightLabel` | `string` | 必填 | 右窗口名（「本月」／「最近 30 天」）。**非空** |
| `rows` | `CompareColumnsRow[]` | 必填 | 逐项：`{ label, left, right }`（下表）。`[]` ⇒ 空串 |
| `unit` | `string` | — | 单位（`元`／`次`／`卡`／`分钟`）：每格与差额各跟一枚小字；不给就不出 |
| `sense` | `'neutral' \| 'up-good' \| 'down-good'` | `'neutral'` | 差额的语气（闭集，下表） |
| `caliber` | `string` | — | 口径行：这两个窗口起止是什么、差额怎么算的；不给＝不出这一行 |
| `form` | `'back-to-back'` | `'back-to-back'` | 形态键（闭集；闭集外一律 `badInput`） |
| `extraClass` | `string` | — | 附加类名（空格分隔，逐个过类名正则） |

`rows` 的每一行（元素字段表）：

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `label` | `string` | 必填 | 项名（「餐费」／「睡眠时长」）；住中缝那一列，长了换行、**不许 `…`** |
| `left` | `number` | 必填 | 左窗口这一项的值。**有限数且 ≥ 0**（不是串） |
| `right` | `number` | 必填 | 右窗口这一项的值。同上 |

**为什么给数不给串**：条长与数字必须同源 —— 给串的话，条长只能由调用方另算一份百分比，「条长按 A、数字写 B」的对照表迟早出现。显示串由本件统一出（千分位、最多两位小数、尾零去掉）。

`sense` 三档（**涨是好是坏由调用方定，本件不猜**）：

| 档 | 含义 |
|---|---|
| `'neutral'`（缺省） | 只给方向字形与正负号，不上语义色 |
| `'up-good'` | 涨＝好（作息变长、运动变多）：涨走 `ok`，跌走 `danger` |
| `'down-good'` | 跌＝好（支出变少、摄入变少）：跌走 `ok`，涨走 `danger` |

## 契约与不变量（判据逐条断）

1. **条长同源**：两侧的条共用一条刻度 —— 宽度 ＝ 这一侧的值 ÷ 两窗共同的最大值（＝ 100% 的那一格就是最大值）。所以条长可直接比，且差额与条长差对得上。
2. **差额单独一行**：差额 ＝ 各共同项「右 − 左」之和（四舍五入到两位小数），落在 `.ilife-block-compare-columns-diff` 那一行，标签恒为「差额合计」。
3. **方向不只靠色**：涨／跌／持平一律「字形（▲／▼／＝，`aria-hidden`）＋ 正负号（`＋`／`−`）」，色阶是可选的第三样。持平永不着色。
4. **零横向溢出**：容器宽 390 与 1280 两档 `scrollWidth ≤ clientWidth`；长项名、长读数、长口径行一律 `overflow-wrap: anywhere`；样式段里没有 `text-overflow`／`line-clamp`／`white-space: nowrap`（值那一格**故意不写** `nowrap`：长读数宁可换行也不许顶破容器）。
5. **窄档不塌成三条竖线**：宽档（≥ `COMPARE_COLUMNS_NARROW_PX` ＝ 560px）三列并排；窄档每项改排**三行**（项名一行、左窗一行、右窗一行），表头行收起、两窗改由每行自己的窗口名领读。
6. **响应式一律容器驱动**：本件设 `container-type: inline-size`（它自己就是容器），窄档调整走 `@container`；本件**一条 `@media` 都没有**。
7. **三套皮肤下标记逐字节相同**：皮肤只换样式段（取值表），标记一个字节不动。
8. **零 DOM／零内联脚本**：模块代码剥掉字面量后不出现 `document.`／`window.`／`navigator.`；产出的标记里没有 `<script>`，也没有 `on*=` 内联事件。
9. **样式只经 `skinVar()` 读皮肤**：组件里不出现手写的 `var(--ilife-…)`；不写 `:root`／`!important`；不定义新 token 名；全部规则 scope 在 `.<prefix>page-ui` 之下，且只读本件自己的类名。
10. **无障碍地板**：文字色取 `ink`／`ink-2`／`accent-text`／`ok`／`danger`（三套皮肤下都过对比地板）；条是装饰（值已以文本上屏）故 `aria-hidden`；`:focus-visible` 给 2px 可见焦点；单位走 `<small>` 跟在数字后。

## 常见错法

- 两侧各写一张表（读者要自己找同一项在两处的两行）—— 并排就是为了省这一步；
- 只报差额不报两侧（读者不知道差额从哪来、哪一项在拉）；
- 给「只有一边有的项」编一个 0 凑数（那是另一句话：「本月新出现 1 类，未计入对照」，写进口径行）；
- 把百分比外部算好再传进来（条长与数字两条口径，迟早对不上）；
- 用色阶表达涨跌却不给字形与正负号（换一套皮肤就丢了语义）；
- 窄档硬撑三列（项名与两侧读数各被挤成一列孤字）。

## 关系

- 与 `summary-head` 的分工：本件是**两个窗口之间的对照**；一页的「主要读数」仍归主数字头。
- 与 `renderChangeRows`（新旧值行）的分工：那一件讲**同一条记录改前改后**（两槽：旧 → 新）；本件讲**两个窗口的同一个项**（两侧各带条与值，差额单独一行）。
- 与 `renderDistributionRows`（分布条行）的分工：那一件是**一个窗口内部**的分布（占比按窗内合计）；本件的两侧各是一个窗口，占比不在本件口径里。
- 样式由页面按需挂 `compareColumnsCss()`（加法式：不调它、不挂 `.ilife-page-ui` 的页零命中）。
- 本件暂不提供族汇总入口（同族第二件落地后，由先成立的那件立汇总，照 `sheetCss()` 先例）。
