# date-range · 日期范围

**一句话**：**起止两格 ＋ 一排快捷档 ＋ 一个月的格子**，底下那句口径点名「当前按 哪一档、从哪天到哪天、共几天」
（六个技能都在选"看哪一段"）。

**形态**：本件只落地**形态 B「日历缩略」**——出处＝原型墙 `.scratch/ui-组件墙/parts-08-表与输入.mjs`
的 `.c-dr.c-dr-b`（2026-09 用户裁定落地的那一形态），按层规重写（原型是一次性代码：无判据、无错误处理、
读的是墙稿自己的变量）。形态键住 `DATE_RANGE_FORMS` 闭集（今天只有 `calendar` 一格）——
**加第二形态（可点的区间条／两格＋快档）是在闭集里加一格，不是新开一件**。

> 交接备注：工单里对形态 B 的括注写成「下拉＋一句口径／起止两格＋快捷档」——那句其实是**另一个件**
> （`window-picker` 的形态 B「下拉＋一句口径」＝`.scratch/ui-组件墙/parts-c.mjs`）的说明。
> 名册与原型墙两处都说 `date-range` 的形态 B 是**日历缩略**，本件按名册＋原型落；
> 「起止两格＋快捷档＋一句口径」这三样都收在本骨架里（见下），两边的意思都照顾到了。

## 何时用它（选型三条）

| 你要的 | 用 |
|---|---|
| 「看哪一段」：起止任选，还要有一眼看得出的常用档（本周／本月／近 7 天） | **本件** |
| 只选**一个**日期（不是一段） | `editable-value`（`kind: 'date'`） |
| 一页只读的区间条（不许改） | 未落地（原型墙 05 的 `range-bar`） |

## 入参

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `name` | `string` | 必填 | 机器键（变更事件与载荷按它定位）。**非空** |
| `from` | `string \| null` | `null` | 起点（`YYYY-MM-DD`，真实存在的日期）；`null`／不给 ＝ 未选 |
| `to` | `string \| null` | `null` | 终点（含这一天）；两端都给时必须 `from ≤ to` |
| `label` | `string` | — | 这一段的名字（`看哪一段`），进 `aria-label` 与事件 `detail.label` |
| `presets` | `{key,label,from,to}[]` | — | 快捷档。`key` 是机器键（事件 `detail.preset`）、`label` 上屏；同一件里 `key` 不许重复 |
| `month` | `string` | 起点 → 终点 → 今天 | 日历正显示哪个月（`YYYY-MM` 或 `YYYY-MM-DD`）；都没有＝**不出日历那一块**（空态） |
| `today` | `string` | — | 今天（**由调用方给**：渲染是纯函数，不读机器时钟）；不给＝不标"今天"那一格 |
| `caliber` | `string` | — | 补的一句口径（挂在组件自己那句后面，段间一条发丝线） |
| `error` | `string` | — | 错误说明：写在控件旁边，控件 `aria-describedby` 指向它（**不只染色**） |
| `disabled` | `boolean` | `false` | 禁用；**必须同时给 `disabledReason`** |
| `disabledReason` | `string` | — | 为什么不能改（写在控件旁边，并被 `aria-describedby` 指到） |
| `loading` | `boolean` | `false` | 更新中：状态字换成「更新中」，期间不接点击与输入 |
| `form` | `'calendar'` | `'calendar'` | 形态键（闭集；闭集外一律 `BlocksError`） |
| `extraClass` | `string` | — | 附加类名（空格分隔，逐个过类名正则） |

## 契约与不变量（判据逐条断）

1. **「按的是哪一档」三处同时给**：命中的那一枚快捷档 `aria-pressed="true"` ＋ 带 ✓ ＋ 走**强调面**
   （软底 `accent-soft` ＋ 主色字 `accent-text` ＋ 主色描边 `accent`）＋ 加粗（**形**）；
   状态字写「当前按 本周」（**字**）；口径句再点名一次「本周：09-19 到 09-25，共 7 天（含首尾）」（**句**）。
   不在任何一档上时写「自定义区间」，两端都未选时写「还未选」。
2. **点日历里的一天＝改离它更近的那一端**：在 `[from, to]` 左边就改起点、右边就改终点、落在区间内就改更近的那一端；
   两端都未选时那一天自成一段（`from = to = 那天`）。两端始终保证 `from ≤ to`。
3. **翻月只看不动数据**：换的是"看哪个月"，没有换窗口 ⇒ **不派发**事件（`PageUp`／`PageDown` 同）。
4. **变更事件**：`ilife:range-change`，`detail = { name, label, from, to, days, preset, prevFrom, prevTo }`
   （`days` **含首尾**；`preset` 是命中的 key，自定义时 `'custom'`，未选时 `'none'`）。
5. **键盘**：日历格用 roving tabindex（整块**恰有一枚** `tabindex="0"`：起点格 → 今天格 → 本屏第一格），
   方向键在格间移动、`Home`／`End` 到本行首尾、`PageUp`／`PageDown` 翻月；`Tab` 不会被困在 42 个格子里。
   键盘与精确输入的另一条路是**起止两格**（原生 `input[type=date]`）。
6. **触控目标 ≥44×44**：翻月键、快捷档、起止两格、每一格天都不小于 44。
   独立相邻控件（翻月键之间、快捷档之间、起止两格之间）留 8px；**日历格之间只留 4px**——
   7 列 × 44px 是硬约束，格间的缝是**矩阵缝**、不是两个独立动作之间的间隔（本轮有意偏离原型，见下）。
7. **样式只经 `skinVar()` 读皮肤**：不出现手写的 `var(--ilife-…)`、不写 `:root`／`!important`、
   不定义任何自定义属性；全部规则 scope 在 `.ilife-page-ui` 之下。
8. **响应式一律容器驱动**：本件设 `container-type: inline-size`；窄容器（< 420px）下起止两格竖排。
   只有两条 `@media`，判的都是设备能力（`hover:hover`／`prefers-reduced-motion`）。
9. **日期算术一律按 UTC**（`monthCells`／`rangeDays`／`shiftMonth`／`isIsoDate` 都是纯函数），
   与运行时段用同一套口径；`today` 由调用方给 ⇒ 渲染结果与机器时区无关、可逐字节对账。
10. **宽度地板**：日历的 7 列 × 44px 需要约 340px 的容器宽。低于它时格子会窄于 44（7 列是硬约束），
    此时请用起止两格——判据在 390 与 1280 两档量的都是 ≥44。

## 常见错法

- 用 `from: ''` 表达未选（未选是不给，或显式给 `null`）；
- 只给一端就当"已经选好"（**只要缺一端整段就算未选**：不假装它是）；
- 让渲染去读"今天"（`new Date()`）：本件的 `today` 由调用方给，判据才能逐字节对账；
- 快捷档的 `key` 重复（事件 `detail.preset` 就说不清是哪一档）；
- 把"翻月"也当成一次窗口变更去派发事件（换的只是看哪个月）；
- 日历里点一天时把另一端也一起改掉（本件只改更近的那一端，另一端保留）。

## 关系

- 与 `window-picker`（未落地）的分工：那一件是「分段＋起止」的窗口条；本件是**日历缩略**（以月为单位看）。
- 与 `editable-value` 的分工：本件选的是**一段**（两端一起），`editable-value` 选的是**一个**值。
- 样式由页面按需挂 `dateRangeCss()`，运行时挂 `buildDateRangeJs()`（加法式：不调不挂的页零命中）。
