# photo-compare · 前后对比

**一句话**：两张照片叠着，中间一根可拖的竖线 —— 并且**三个读数一起给**：**拖动**（看得见的裁切边）＋ **两张的日期标签**（左／右角）＋ **数值差值行**（70.8 → 68.4 千克，Δ −2.4 千克）。

**形态**：本件只落地**形态 A「拖动对照」**——出处＝原型墙 `.scratch/ui-组件墙/parts-11-加量池.mjs` 的 `.c-p5-vwrap`。

**这一件是重做件**（原型 3/3/3）。改掉的是什么：原型只给了一个能拖的竖线，**读者拖完读不出「变了多少」**。重做后差值行成了必填（`deltas` 空数组直接 `badInput`），日期标签各贴在自己那张的角上，窄档退成左右并排 ＋ 差值条 —— 拖动是入口，数字才是结论。

## 何时用它（选型三条）

| 你要的 | 用 |
|---|---|
| 两**张**照片比着看 ＋ 变了多少（身材照前后、修复前后） | **本件** |
| 一**组**同等地位的照片墙（带日期／位置，末尾可加一张） | `photo-grid`（照片网格） |
| 两个**数字列**对照（不带照片） | `compare-columns`（双列对照，未落地） |

## 入参

| 字段 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `before` | `PhotoCompareSide` | 必填 | 前一张（下面几行走同一张表：`before.x`） |
| `before.date` | `string` | 必填 | 前一张的日期（「08-30」）。**非空**；与 `after.date` 不许相同 |
| `before.alt` | `string` | 必填 | 这一格该放什么照片（「正面」）。**非空** |
| `before.src` | `string` | — | 图源；不给＝占位格（取景角标 ＋ 相机记号 ＋ `alt`） |
| `before.caption` | `string` | — | 题注条里的说明（「沙发 · 修复前」） |
| `before.size` | `string` | — | 题注条里的一行读数（「1120×1480 · 1.8 MB」） |
| `after` | `PhotoCompareSide` | 必填 | 后一张（同 `before` 的五格；`after.date` 必填） |
| `deltas` | `PhotoCompareDelta[]` | 必填 | **数值差值行**（本件重做补上的那个读数）。空数组＝错 |
| `deltas[].label` | `string` | 必填 | 读数名（「体重」）。**非空** |
| `deltas[].before` | `string` | 必填 | 前值（「70.8」）。**非空** |
| `deltas[].after` | `string` | 必填 | 后值（「68.4」）。**非空** |
| `deltas[].change` | `string` | 必填 | 变了多少那句（「−2.4 千克」／「可比」）。**非空** |
| `deltas[].tone` | `'down' \| 'up' \| 'same'` | `'same'` | 方向档：只改视觉（正负号已写在 `change` 里） |
| `verdict` | `string` | — | 窄档差值条那句话（「比 08-30 轻 2.4 千克」） |
| `note` | `string` | — | 底下那句口径（「拖照片上那根竖线：左边 08-30，右边 09-25」） |
| `position` | `number` | `50` | 拖动竖线的初始位置（0–100，按 `step` 对齐） |
| `form` | `'drag'` | `'drag'` | 形态键（闭集；闭集外一律 `badInput`） |
| `extraClass` | `string` | — | 附加类名（空格分隔，逐个过类名正则） |

## 契约与不变量（判据逐条断）

1. **没有差值行的前后对比是错的**：`deltas: []` 一律 `badInput` —— 本件重做就是为了「变了多少」这句。
2. **三个读数一起给**：拖动（裁切边 ＋ 竖线）、**日期标签**（左／右角，各贴在自己那张上）、**差值行**（前值 → 后值 ＋ 变了多少）。只给拖动那一版正是被打回 3 分的那一版。
3. **色不是唯一信息**：差值行有**方向记号**（↓／↑／＝）与**正负号**，颜色只是第三样 —— 皮肤把强调色换成墨黑或暖红，方向照样读得出。
4. **门槛可操作**：拖动条是**原生 `range`**（`←`／`→` 各一档，`step` ＝ `PHOTO_COMPARE_STEP`），命中盒铺满台面，把手本体 `PHOTO_COMPARE_MIN_HIT_PX`（44×44）—— 不靠脚本才成立；`:focus-visible` 给 2px 可见焦点。
5. **同一份标记两档**：宽档两张**叠着**（后一张从左边裁），窄档（< `PHOTO_COMPARE_NARROW_PX`）同一对 `<figure>` **左右并排** + 差值条上屏，拖动条收起 —— 不是两套标记，判定条件是**本件自己的宽度**（`@container`）。
6. **一个位置一处存**：竖线、把手、裁切三处都从根上的局部自定义属性 `--photo-compare-split` 算；运行时只写它一个值（`input`＋`change` 委派，进页按当前值补画一次 —— 表单还原／前进后退后也自洽）。
7. **占位读得出是相片**：定形框（`aspect-ratio`）＋ 四角取景角标 ＋ 相机记号 ＋ 题注条（与 `photo-grid` 同一套做法）。
8. **零阴影下层次仍在**：台面靠一圈发丝线，题注条靠软底色，差值行靠**发丝线 ＋ 缩进**。
9. **样式里零动效**：这一段没有 `transition`／`animation`／`@keyframes`，拖动是直接操作 —— 「减动效」档下没有东西会卡在半路。

## 常见错法

- 只给拖动、不给差值 —— 读者拖完还是不知道「变了多少」（原型就是这样被打回的）；
- 后一张从左边裁开、题注却左对齐 —— 字落在被裁掉的那半边里，等于没写；
- 用一个小滑块代替把手（命中盒 < 44×44）—— 手指点不中；
- 两张标成同一天（本件直接 `badInput`：同一天没有「前后」）；
- 拿本件当照片墙用：那是 `photo-grid`。

## 关系

- 用在哪：卡路里（身材照前后）／居家管家（修复前后）。
- 样式由页面按需挂 `photoCompareCss()`；运行时段由页面把 `buildPhotoCompareJs()` 拼进共享 helpers 槽（**无脚本降级**：不跑也读得出——服务端渲的初值就在竖线与裁切上，只是拖不动）。
- 拖动位置那一个自定义属性是本件**自己的几何量**（不是皮肤 token，也不经 `skinVar()`；名字不带 `--ilife-` 前缀，与皮肤名单不相干）。
