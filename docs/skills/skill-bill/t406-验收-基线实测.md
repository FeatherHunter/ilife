## 四、与基线相关的风险

- **基线里没有既有红。** `node --test "packages/skill-bill/test/*.test.mjs"` 实测 `pass 57` / `fail 0`、退出码 0（`test-baseline.txt`、`test-exitcode.txt`），所以 t406 之后新出现的红都应算本次改动弄红的，没有「本来就红」的豁免。
- **`packages/skill-bill` 下未提交改动 0 条。** `git status --short packages/skill-bill` 跑两次都无输出、退出码 0（`git-status.txt`、`git-status-recheck.txt`，行数 0），这个技能目录开工前是干净起点。
- **但全仓工作树是脏的，脏点不在本技能目录。** 全仓 `git status --short` 共 94 行，按顶层归类为 `packages` 59 条、`docs` 19 条，其余为仓根 `.tmp-*` 与 `.scratch_*` 临时文件（`git-status-root.txt`、`git-status-root-summary.txt`），提交时别把别处的改动一起带上。
- **产物比源码新只证明文件时间，不证明内容一致。** 本轮按「不存在或比源码旧」的判定没有跑编译，因而没有编译退出码，「dist 与 src 一致」这件事本次真跑没有证据（`step2-dist.txt`）。
- **实施者一动 `src`，产物立刻过期。** `dist\cli\cmd_read.js` 是 2026-09-14 12:36:34、最新源码是 2026-09-12 19:50:00（`step2-dist.txt`），两者只差时间戳；写入域改完 `src` 后必须重跑 `npx tsc -b packages/skill-bill` 并记退出码。
- **本基线只覆盖本包测试。** 测试命令匹配的是 `packages/skill-bill/test/*.test.mjs`（10 个文件、11 个 suite、57 个用例），别的包与仓根测试入口一概没跑，不能拿这份基线当「全仓绿」。
- **源码时间戳集中，只能当弱证据。** `src` 下 25 个 `.ts` 的修改时间全部落在 2026-09-12，最新与次新只差 32 分钟（`src\cli\cmd_read.ts` 19:50:00、`src\output.ts` 19:18:25，见 `test-greps.txt`），更像检出或批量写入的时间戳，不能读成源码被改了 25 次。
- **重定向日志是 UTF-16LE，读法要配对。** 本机 `*>` 写出头字节 `FF FE`（`test-baseline.txt`、`git-status-root.txt`），普通按 UTF-8 逐字节读会失败，抄汇总行与退出码时走 `Get-Content`，退出码另外单独记在 `test-exitcode.txt`（ASCII）。
- **测量窗口里工作树还在被别的活改动。** 全仓 `git status --short` 从 94 行涨到 100 行，新增的 6 条落在 `packages/base-render`、`packages/skill-calorie` 与 `.changeset`（`git-new-entries.txt`），与本技能一条都不沾；验收时别把这 6 条算到 t406 头上。
- **交付物所在目录整体未跟踪。** `docs/skills/skill-bill/` 下受控文件数为 0，git 只折叠成一行 `?? docs/skills/skill-bill/`（`git-status-docs.txt`、`skillbill-doc-dir.txt`），本次交付的这份 Markdown 也在里面，提交时要整目录一起加。
- **临时输出不污染工作树。** `.scratch/` 在 `.gitignore` 第 5 行被忽略（`gitignore-check.txt`），本节所有原始输出落盘都不会给工作树添脏。
