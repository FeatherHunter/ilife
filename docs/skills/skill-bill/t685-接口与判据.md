## 一、两层机制：骨架件（公共层）＋ 页头件（各技能）

### 1.1 骨架件（公共层·新件）

**它管什么**：拼出完整 HTML 文档的**不可变部分**——`<!doctype html>` 起、`</html>` 止的骨架，head 里的三个槽位与资源位，样式资产的拼接。**它不知道**这是哪个技能、哪一页、页头长什么样、页里有哪些块。

| 项 | 值 | 出处／理由 |
|---|---|---|
| 文件名 | `docShell.ts` | 与公共层既有的 `helpShell.ts`（帮助页的壳）同族同构：`*Shell.ts`＝某类文档的壳 |
| 对外名 | `renderDocShell` | 一个文件对外只这一个名字（铁律五） |
| 住哪 | `packages/base-render/src/` | 两侧技能都已依赖公共层；公共层零反向依赖 |

**入参（4 字段，一个可选）**：

| 字段 | 类型 | 含义 | 出处 |
|---|---|---|---|
| `docTitle` | `string` | head 的 `<title>` 文本 | 两侧现有件同名同义（`skill-calorie` / `skill-bill` 的 `docPage.ts`） |
| `bodyHtml` | `string` | 正文（已拼好的整段 HTML，通常是一个 `<section>` 页壳） | 两侧现有 `content` 改名——`content` 在两侧同时指「正文」和「复制载荷」，同名两义是走散的种子 |
| `extraCss` | `string` | 技能侧补丁样式（拼在 `buildStyleSheet().css + blocksCss()` 之后） | 账单侧现有四段补丁（`DESKTOP_CSS` / `TOAST_CSS` / `KV_CSS` / `EXIT_CSS`）就是它 |
| `charts` | `boolean?` | 要不要注入图表助手资源（并在骨架里留 `<!--CHARTS-HELPERS-->` 位） | 卡路里现有 `charts` 位；账单不需要图表页，不传即不注入 |

**不吃的**（写在这里防长胖）：页头语义（眉标／徽章／结论摘要／副标题）、块位序列、任何能力名或域名词、任何可选开关式的"顺带统一"。

**资产口径**（沿用两侧现有写法，不改）：

```
sharedCssText   = buildStyleSheet().css + '\n' + blocksCss() + (extraCss ? '\n' + extraCss : '')
sharedHelpersJs = buildSharedHelpersJs()
chartsHelpersJs = charts ? buildChartsHelpersJs() : undefined
产物            = fillTemplate({ template, assets, content: bodyHtml }).html
```

**判据**：删掉它，两侧就得各自再写一遍 doctype／head／三槽位序／资产拼接——不是白占一层（铁律五）。**产物判据**：两侧改走它之后，**产物逐字节相同**。

### 1.2 页头件（各技能→薄件）

**它管什么**：技能自己的页面口径——页头语义（眉标怎么取、要不要类型徽章、有没有结论摘要行、副标题怎么写、槽位与页标记）＋ 自己的补丁样式；正文拼好后**交给骨架件**。

| 技能 | 现有件 | 现有入参字段数 | 改造后 |
|---|---|---|---|
| skill-calorie | `src/shared/docPage.ts`（161 行） | 11（含 `metaLeft` / `badge` / `summary` / `printable` / `pageUi` 与 A／B 双路） | 保留全部字段与 A／B 双路；**只把「拼 doctype／槽位／资产」那段换成调 `renderDocShell`** |
| skill-bill | `src/shared/docPage.ts`（130 行） | 5（`docTitle` / `title` / `eyebrow` / `subtitle` / `content`） | 同上；四段补丁样式改走 `extraCss`；`pageShell.ts`（唯一调用点）一行不改 |

**硬口径**：卡路里那 **110 处调用点一行不碰**；`pageShell.ts`（账单侧 34 处调它的地方）一行不碰。

### 1.3 层与层的边界（一句话版）

- 骨架件：**文档壳**（机制，零领域词）；
- 页头件：**页头语义 ＋ 补丁样式**（技能自己的口径）；
- 页型表：**块位序列**（各域自己的策略词汇，见姊妹件）；
- 场景件：**只声明差异值**（数据）。

## 二、判据的可判形态

票面原判据「每场景差异声明 ≤ 20 行」已降为**试算脚手架**、不进验收（实测：同一批 36 个函数，严格口径中位数 6 行、宽松口径 12.5 行，两口径差 4 倍；既能随意变绿，也本来就在线内）。验收改用下列两条。

### 2.1 判据甲 · 改一次版式只动一处

**它代替什么**：代替「改一次版式要动 41 处」这个真正怕的后果。

**判读形态**（三个读数同时成立才算过）：

| # | 读数 | 怎么取 |
|---|---|---|
| 甲-1 | 改版式的文件数 **= 1** | `git diff --name-only` 只出现**一个**文件（该版式所属的那一份页型表／模板） |
| 甲-2 | 未受影响的页产物 **sha256 不变** | 改版式前后各跑一遍样例页，逐页 sha256 相同 |
| 甲-3 | 受影响的页产物**按预期变化** | sha256 的变化集合 **=** 该版式覆盖的页集合（不多不少） |

**样例页从哪来**：用**隔离的合成库**跑真交付出口（`spawn dist/cli/cmd_read.js <key> --params … --html <临时文件>`），读回落盘 HTML——与账单现有页面测试同一形状（`test/t411-query-skeleton.test.mjs:33-43`、`test/t410-lock.test.mjs:30-48`）。

**为什么这条比行数硬**：行数只量「写了多少」，这一条量「改一处会牵动多少页」——后者才是 issue 真正要防的东西。

### 2.2 判据乙 · 场景件里不许有块序

**判读形态**（两条，任一触发即红）：

| # | 读数 | 怎么取 |
|---|---|---|
| 乙-1 | 场景件的 import 清单里**没有块位渲染函数** | 扫 `src/<域>/scene-*.ts`（及该域的场景声明件）的 import：出现 `base-paint/blocks` 的块位函数（`renderKpiGrid` / `renderDataTable` / `renderChips` / `renderListRows` / `renderParamForm` / `renderDetailSection` / `renderCopyBlock` / `renderFeedbackBlock` / `renderEmptyBlock` / `renderDisclosure` / `renderPreBlock` / `renderChartBlock`）即红 |
| 乙-2 | 场景件里**没有块位拼接** | 扫同一批文件的正文：出现整段 HTML 字面量（`'<section'` / `'<div class="ilife-` 之类）或块位渲染函数调用即红 |

**允许场景件 import 的**：取数件、域内共用小件（值加工／文案／缺项判定）、`shared/docPage.js` 这一级的**页面出口**（如果该域仍需要按场景分头出页），以及自己那份页型表。

### 2.3 两道门的落点与自证

- **落在哪条缝**：真交付出口（spawn ＋ `--html` 落盘读整页）。**不**新增「直调内部件」的测试缝——那正是本包测试面口径第 2 条（生产不走的缝不算缝）禁止的。
- **门的形式**：脚本门（`packages/skill-bill/scripts/` 下一个新脚本）＋ 靶向测试；形状照本包既有的两道门（`check-warning-line.mjs` 的「红五类逐条点名 ＋ 末段给修法」、`check-page-assert.mjs` 的 `--selftest`）。
- **自证（防假绿）**：拿**当刻的写入域场景件当负向样本**跑一遍，判据乙必须**当场变红**；把块位调用换成域内共用小件后必须**回绿**。这一步证明门不是只能报绿。
