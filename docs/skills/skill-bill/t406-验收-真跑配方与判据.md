### 1. `SKILLS_DB_PATH` 是**目录**，不是数据库文件

- `packages\skill-bill\src\cli\cmd_read.ts:44` 起：只读环境变量、只判非空，不做任何路径归一；`cmd_read.ts:45` 未设置时 `fail(1, ...)`（退出码 1）。
- `packages\skill-bill\src\fetch\paths.ts:10` 起：`resolveDbDir()` 逐字返回该值；`paths.ts:21` 起 `resolveDbPath()` 才拼文件名。
- 结论：它是**放库文件的目录**，真实数据库文件＝`<SKILLS_DB_PATH>\biscuit_accountant.db`（`paths.ts:7` 的 `DB_FILENAME`）。
- 实测：`SKILLS_DB_PATH=D:\ilife\.scratch\t406-run\db` → 首次跑完该目录里只有 `biscuit_accountant.db`（20480 字节）。给的是文件路径时 `mkdirSync`＋`join` 会把库文件塞进一个同名目录里，别这么传（这一句为**推断**，依据是 `paths.ts:22`、`paths.ts:23` 的 `mkdirSync(dir)`＋`join(dir, filename)`；未实测）。

### 2. 相对路径会落到「当前工作目录」，不是仓根

- `paths.ts:18` 逐字返回，`paths.ts:22` 只用 `mkdirSync`＋`join`，没有 `resolve()`；`paths.ts:34` 才把两边的路径 `resolve()` 后再比。
- 实测（run08，cwd＝`D:\ilife`）：`SKILLS_DB_PATH=rel-db` → 生成 `D:\ilife\rel-db\biscuit_accountant.db`（20480 字节），退出码 0；stderr 原文含 `写入 rel-db\biscuit_accountant.db` 与 `NOTE: 记账 DB 已初始化：rel-db\biscuit_accountant.db`（日志里回显的就是没归一过的相对串）。
- 风险：换个 cwd 或换个进程（技能由 `SKILLS` 侧唤起）就换一个库，回执里也拿不到绝对位置。**一律给绝对路径**。

### 3. `BILL_FORCE_PROD`：非系统临时目录写库的开关

- `packages\skill-bill\src\fetch\paths.ts:32` 起：`assertWritablePath()` 判「`resolve(dbPath)` 是否以 `resolve(tmpdir())` 开头」；不在 temp 下且 `BILL_FORCE_PROD !== '1'` 就抛错，错误文本含 `拒绝写入非 tmp 路径` 与 `BILL_FORCE_PROD`，`cmd_read.ts:551` 把它转成 `fail(1, ...)`。
- 取值：**只有字符串 `'1'` 才算开**（`paths.ts:33` 是 `=== '1'`）；`true`／`yes`／`0` 都等于没开。开了以后 stderr 会多一行 `[skill-bill] BILL_FORCE_PROD=1: 写入 <dbPath>`（`paths.ts:41` 起）。
- 挂载点：会改数据库的命令，其前置守卫在 `cmd_read.ts:150`（`bill.record.add`／`bill.record.update`）；查询命令不受影响。
- 结论：临时库放到 `.scratch\` 下（不是 `%TEMP%`）时，**必须** `BILL_FORCE_PROD=1`，否则连记一笔都进不去。

### 4. 新库会自动建表（无需先「初始化」）

- `packages\skill-bill\src\fetch\db.ts:43` 起 `openBillDb()`：`db.ts:54` 先看 `bills` 有没有列，没有就把 `initialized` 记成 `true`；`db.ts:56` 起跑 `CREATE TABLE IF NOT EXISTS bills` ＋ 两个索引，`db.ts:60` 缺列时补 `deleted_at`。

### 5. 不给 `--html`：只写库，不落回执页

## 四、验收命令模板（可直接复制）

### 0. 先看这条：JSON 参数怎么传才不会碎

`--params` 的值是一串带双引号的 JSON。在本机实测的 PowerShell（5.1）环境里，**内联**把 JSON 写在单引号里会被参数解析吃掉内层双引号，到达 node 时已经变成 `{category:餐饮/外卖/午餐,...}`，命令以 `ERR 2: --params 须为 JSON`（退出码 2）收场。实测对照：

- 内联 `node ... --params '{"category":"餐饮"}'` → node 收到 `["{category:餐饮}"]`（双引号没了）；
- 内联 `--%` 停止解析写法 → 更糟，收到带反斜杠的 `{\"category\"...}`，CLI 直接报未知参数；
- **把命令写进 `.ps1` 文件再执行（`pwsh -NoProfile -File 那个文件`）→ node 收到 `["{\"category\":\"餐饮\"}"]`，正常解析**。

所以下面前四段命令模板，推荐整段存成 `.ps1` 文件执行（本次实测就是这样跑通的：四段全退出码 0，产物字节数与第二节完全一致）。如果你在自己的交互窗口里逐行粘，先拿 `node -e "console.log(process.argv[2])" '{"a":"b"}'` 试一下引号有没有活下来，碎了就改走文件。

## 五、风险与禁忌

每条禁忌后面跟的是本次实测后的正面做法。

1. **不许把 `SKILLS_DB_PATH` 指向老技能真实数据库**（`D:\2Study\StudyNotes\SKILLS\饼干记账`）。正面做法：所有真跑都把 `SKILLS_DB_PATH` 设成 `.scratch\t406-run\` 下的空目录，跑完只在那个目录里看结果；要确认自己没指向老库，先 `Test-Path` 一下准备用的路径是不是自己在 scratch 下建的。
2. **不许写老技能目录下任何文件**（库、回执页、临时文件都算）。正面做法：产物一律 `--html D:\ilife\.scratch\t406-run\...\*.html`（绝对路径），不写相对路径、不把输出目录设到老技能目录里。
3. **不许拿真实账本当试验场**。正面做法：真跑前先建临时库，跑完用临时库的 `db\biscuit_accountant.db` 做核对（本次实测的库只有三行、20480 字节）；需要真实数据时只做「读」，不跑 `bill.record.add`／`bill.record.update`。
4. **不许靠相对 `SKILLS_DB_PATH`**（实测：它会按当前工作目录解释，换 cwd 就换库，日志里也回显相对串）。正面做法：始终给绝对路径；如果确实用了相对路径，先在 scratch 里确认生成位置再继续。
5. **不许省 `BILL_FORCE_PROD=1` 却说「命令没跑通」**——非 `%TEMP%` 路径写库会被隔离守卫拦下（`paths.ts:32` 起，`cmd_read.ts:550` 转成退出码 1），真实原因是不在 tmp 下且开关没开。正面做法：临时库配合 `$env:BILL_FORCE_PROD = '1'`，并且知道它只认字符串 `'1'`；看到 stderr 里 `BILL_FORCE_PROD=1: 写入 <路径>` 就说明开关确实生效、写的就是你以为的那个库。
6. **不许把 `--html` 省掉还等回执页**。正面做法：两条命令都带 `--html <绝对路径>`；不给 `--html` 时退出码仍是 0、但只有 stdout 里的五字段 envelope（`cmd_read.ts:540` 起），没有 `delivery` 也没有页。
7. **不许把 `--html` 指到不存在又没权限建的目录**。正面做法：先 `New-Item -ItemType Directory -Force` 建好产物目录；落盘失败会被 `cmd_read.ts:547` 转成退出码 5（`ERR 5: 落盘失败`），别把它当成取数失败。
8. **不许只给 `id` 就期待 `bill.record.update` 成功**。正面做法：改写给至少一个字段（`category/amount/time/account/ledger/currency/note`），撤销／恢复显式写 `op`（`{"op":"undo","id":N}`／`{"op":"restore","id":N}`）。
9. **不许在内联命令里赌 `--params` 的引号**。正面做法：把命令写进 `.ps1` 文件再跑（第四节 0 条），或者先用 `node -e` 探一下引号有没有活下来；碎了就改走文件，别怀疑 CLI。
10. **不许把 `packages\skill-bill\dist\` 当成源码改**。正面做法：产物只当运行入口用（本次实测 `dist\cli\cmd_read.js` 已存在，**没有**重跑 `tsc`）；要改行为改 `src\`，再按仓内口径重新构建。
