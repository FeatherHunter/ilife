每条给：**结论／理由／可判形式（跑哪条命令 → 看哪个读数 → 等于什么）／落点票**。

### 裁定 1 · 页面最大一个字写内容，眉标只写「命令名 · 人话归属」

- **结论**：页面最大一个字写「页面名 ＋ 窗口／日期」；眉标一行小字写「命令名 · 人话归属」。**参数名、常量名、英文内部标识符、脚本路径一律不上屏。**
- **理由**：老侧页脚把源脚本路径印成字面（`query_view.html:217` 恒印 `scripts/record_bill.py {type} --json`，`分析/analysis_view.html:254` 恒印 `scripts/analysis/cli.py`，`账户/account_view.html:166` 印 `scripts/account/cli.py summary --json`），既与实际分域路由对不上（缺陷 D6／D16），对用户也无意义；另一个极端是老侧 h1 由脚本按唤醒词改写（`query_view.html:206`／`expense_form.html:129`）——两边都不取。
- **可判形式**：跑本域全部读命令 → 产物可见文本里**不出现** `scripts/`、`.py`、`.json`、`bill.`、`_` 形态的内部标识符（如 `record_add`／`MEAL_WINDOWS` 那类）→ 全不出现才算实施。
- **落点**：各页票。

### 裁定 2 · 结果型页三条恒出：页内导航 ＋ 口径说明行 ＋ 来源脚注

- **结论**：结果型页面恒出**页内导航**（各区块锚点）与**来源脚注**（数据来源 · 窗口 · 条数）；有口径内容的页面另出**口径说明行**。三条都走公共层，页面本地不造。
- **理由**：老侧只有「header ＋ 离线条 ＋ 页脚」这一薄恒显层（`query_view.html:113-119` 的骨架实测只有 4 个挂载点），内容一长就失去定位；老页脚是唯一近似物，且印的是脚本路径（裁定 1）。
- **可判形式**：跑本域全部读命令 → 每张产物各含**一个**页内导航块（`ilife-block-toc`）＋ **一行**来源脚注（`ilife-block-caliber`，含窗口与条数）；口径类页面另含一行口径说明 → 三条齐才算实施。
- **落点**：各页票；`src/shared/sourceLine.ts` 按卡路里 `packages/skill-calorie/src/shared/sourceLine.ts:24` 的形状搬进来（**放共用位，不许各域各写一份**）。

### 裁定 3 · 图表必须可读数，且不画无效图元

- **结论**：折线／柱图必须带纵轴可读刻度；**零值不出柱身**；点数不足时不画半截线，改出说明句；跨空档用**同色虚线**并把「哪几天无记录」写进图下口径句。
- **理由**：**老侧在这条上是反面**——`分析/analysis_view.html:320` 逐月 `categoryBar` 不跳过 `expense === 0` 的月，`:833` 逐周几不跳过 `count === 0` 的星期，`:1088-1098` 的 `categoryBar` 对 `total === 0` 仍输出完整一行「0.00 元 · 0 笔」＋ 0 宽条形（缺陷 D12）。
- **前置**：公共层的图表能力由 `base-render/src/charts.ts` 与 `spec/charts.ts:8`（8 种 `CHART_KINDS`）提供；**卡路里那条「纵轴刻度／点密度／均线」的教训同源**（`t425` 裁定 5）。页面侧不另算量程、不写色值。
- **可判形式**：跑含图表的本域命令 → 产物在纵轴处读到刻度读数；零值处**无柱身**；点不足时读到说明句；无记录日不出现在图元里而在口径句里被点名 → 四条齐才算实施。
- **落点**：analysis 域票（唯一有图的域）＋各页票。

### 裁定 4 · 缺值一律 `—`，空窗出空态句与引导句

- **结论**：可见文本缺值写 `—`（不写 `0`、不写空串、不拿缺省值顶替、**更不许渲染 `undefined`**）；窗口内一条记录也没有时，整页仍是完整页（标题＋空态句＋来源脚注都在），空态句后接一句「怎么记第一条」的引导句。
- **理由**：新侧已有这条口径；**老侧在这条上两头都有教训**——① 反面：`update_confirm.html:110` 的 `esc(String(r[1]))` 渲染字面 `undefined`，`installment_confirm.html:107-109` 拼串后 filter 失效渲染「undefined 元」与「undefined 期」；② 正面：`联动/receipt.html:132` 的 `row()` 空值加 `empty` 类显示「未填写」，`开始使用/init_status.html:145` 零值正确显示「现有记录 0 条」（不吞 0）。
- **可判形式**：把窗口换到无记录区间跑 → 产物仍是完整文档、含空态句与来源脚注；有记录但某字段缺时该处读数等于 `—`；**全产物 grep 不到字面 `undefined` 与 `NaN`** → 三条都成立才算实施。
- ****空窗 ≠ 空库**（沿用卡路里 `t425` 裁定 4 的澄清两态不互斥）：**窗口为空**（有命令、有窗口、窗口内零记录）⇒ 本条适用，出完整页；**库为空**（整个库没数据）⇒ 走 `exit 4` ＋ `ERR 4: 取数失败（缺失阻断）`、**不落盘**，这是既有设计行为、**不变**。后续任何票不得据本条去改空库的 `exit 4`。
- **落点**：各页票。

### 裁定 5 · 过程型页：复制区恒双按钮、无同名标题、日志第 4 段写命令原文

- **结论**：过程型页（采集／确认／向导）的复制区出**「复制数据」＋「复制日志」两颗按钮**，**不出任何与按钮同名的标题**；日志六段齐，**第 4 段（调用链）是渲染命令原文（含本次参数）**，照抄可重跑。
- **理由**：新侧已站在这条裁决一边（`copyArea.ts` 的去重口径与按钮形态）；老侧在这条上是**半成品**——写入 5 件的 `#actionbar-zone`（`expense_form.html:83` 等）由公共层注入两通道，但**页面本地只有一颗「📋 确认复制」按钮**，两套复制入口并存且语义重叠。
- **段序订正**：段序正本是 `packages/base-render/src/spec/text.ts:25` 的 `LOG_SECTIONS`＝**①场景标识②AI思考链③数据结构④调用链⑤时间戳版本⑥异常**；命令原文属**第 4 段「调用链」**。仓里旧文写「第 3 段」的是陈旧说法（`t425` 已订正），**以 `spec/text.ts` 为准**。
- **可判形式**：跑本域全部写命令与向导命令 → 每张产物各含两颗按钮、**无**与按钮同名的标题；日志文本**第 4 段**等于本次命令原文（含参数）→ 两条齐才算实施。
- **落点**：各页票。

### 裁定 6 · 过程型采集页不画「同形空卡」

- **结论**：采集页在字段还没值时，**不出**「金额／分类／账户／账本／时间」五张同形「未给」读数卡；「还缺什么」由**缺项标签 ＋ 缺项表 ＋ 字段卡**三处承担。
- **理由**：五张同形空卡只是把「还缺什么」说五遍（`src/record/collectBody.ts:16-18` 已按此整改并留档）；老侧对应的毛病是**零值照画**：`目标/budget_view.html:191-196`＋`:203` 与 `saving_view.html:190-195`＋`:202` 在空态时**先画 4 个全 0 读数卡再挂空态**——而同一个技能里的 `账户/account_view.html:188-191` 反而**提前 return、不画读数卡**（同域两套做法）。
- **可判形式**：把采集页的所有可缺字段清空跑 → 产物里**不出现**值位为「未给」／`—`／`0` 的读数卡网格；缺项标签与字段卡**都在** → 两条都成立才算实施。
- **落点**：各页票（write 域 #689 已有先例）。

### 裁定 7 · 一个形状只许一处定义（页面本地不许自造第七种）

- **结论**：页内形状只用公共层的形状件与区块；**同一个形状（进度条／占比条／键值行／堆叠条／结论条／口径行）全仓只许一处定义**，页面本地不写 CSS、不写色值、不写断点。
- **理由**：老侧这条是**血汗教训**——24 件各带自绘 `<style>`（写入 5 件各一份色板，四份还缺 `--purple`；`query_view.html:23` 与 `分析/analysis_view.html:23` 各写死 `max-width:920px`）；老侧自己的设计审查结论逐字「这不是"设计系统"，是"设计联邦"」（`docs/skills/skill-calorie/t161-老技能HTML清单.md:130` 引老侧 `设计审查报告.html`）。
- **可判形式**：产物 grep `<style` → **命中 1**（公共层样式段）；grep 颜色字面（`#` 三位／六位十六进制、`rgb(`、`hsl(`）→ 在页面装配件里 **0 命中**；grep `@media` → 在页面装配件里 **0 命中** → 三条齐才算实施。
- **落点**：各页票；公共层缺形状时**开公共层票**，不在页面里补。

### 裁定 8 · 一命令一页；同域同形共用一份装配件；一张老页 ≠ 一张新页

- **结论**：产物层面**一命令一页**（不靠 `display:none` 切视图）；装配层面**同域同形的场景共用一份装配件**（先例：`src/shared/collectBody.ts` 只服务记支出一条词、其余族各有装配体——「共用件是从第二个用法里长出来的」）。**拆分颗粒度按新侧的块序与差异位定，不按老页的张数定。**
- **理由**：老侧一张页扛多词（`expense_form.html` 4 词／`flow_confirm.html` 6 词／`query_view.html` 15 场景／`分析/analysis_view.html` 25 场景／`联动/receipt.html` 2 型／`backup.html`＋`backup_list.html` 共 1 词 2 场景），而**老侧 `type` 与「页」本来就是 1:1**（38 张互斥视图压 2 张模板）——按 `type` 一页一条搬即可，**不需要发明新粒度**。
- **可判形式**：每条命令跑 `--html` → 产物落盘；产物 `<section>` 上的 `data-page` 与 `data-slot` 是本命令自己的值（不是复用别的命令的页）；同一族的产物**共用同一个装配函数的调用点**（读源码可得）→ 两条齐才算实施。
- **落点**：各页票。

### 裁定 9 · 缺项阻断：缺什么就不给复制

- **结论**：**任一行缺金额或分类三级未填**等必填缺失时，页面**不出复制指令块**，改出缺项阻断条（走 `renderFeedbackBlock` 的 `danger` 位）＋ 一行口径写清缺哪几项。
- **理由**：老侧这条是**缺陷**——`batch_confirm.html:136-149` 缺金额只改视觉（横幅＋标红），`:168-170` 的复制按钮**无任何校验**，照样把含空金额的条目行拼进 prompt（`:161`）。同批的 `flow_confirm.html:214-228` 却有超支警示——同一技能两套严格度。
- **可判形式**：把一条必填清空跑该命令 → 产物里**不出现**复制指令块，出现缺项阻断条且阻断条点名缺哪一项；把它填上再跑 → 复制指令块出现 → 两条都成立才算实施。
- **落点**：各页票（write 域 #689 已有 `src/shared/blockedSlots.ts`）。

### 裁定 10 · `link` 域按 `non-exec` 收口：词与 HELP 保留，执行层不承接、不产 HTML

- **结论**：`link` 域的两条词（买东西／吃饭）**保留路由与 HELP**；**执行层不承接、不产 HTML、不计入缺口**。老侧三张联动页（`purchase_confirm.html`／`meal_confirm.html`／`receipt.html`）**不补页**。
- **理由**：#681 的「两条已定的口径」已定；家法出处＝卡路里 `packages/skill-calorie/src/triggers/routeSpec.ts:59` 逐字「`kind: 'non-exec'` ⇒ `bucket` 与 `reason` 必有，且 `key`／`cli` 不出现」（＝非执行即无命令；#681 与 #683 §八 都引的是同族件的轮廓行，**真正的不变式在本行**）。老侧跨技能也是**单向人工搬运**：`居家管家/SKILL.md:684` 逐字「居家管家不直接调用对方 CLI（跨技能物理隔离，单工闭环）」——**没有一处模板互相调用**（全 `SKILLS` 树扫 `meal_confirm|purchase_confirm` 零外部命中）。
- **保留的部分**：三条可继承的**文案与交互**（采集页**之前**就预告联动、联动卡标题带具体对象名、把执行路径写进界面）**转记到 write 域的回执页**（`receipt.html:145-155` 的形态落 write 的落库后回执），不随页删除。
- **可判形式**：跑「买东西」／「吃饭」→ exit 0；产物**不是**整页（不为它落域整页）；HELP 里这两条场景**能查到**；`test/bill-split.test.mjs` 的出 scope 断言不动 → 四条齐才算实施。
- **落点**：#681 本体图（口径）＋ #686 机器面（断言）。

### 裁定 11 · 老侧做法与用户自家原则相撞时：按原则，并把差异写进 §二

- **结论**：当**老侧自己的做法**与**用户已确权的自家原则**相撞时——**按原则、不按老侧**，并在 §二 对应行写清「老侧怎么做／新侧怎么做／为什么以新侧为准（原则出处）」。
- **本条的唯一触发实例**：老侧**回执页的退出口**（`联动/receipt.html:78-80` 的 `.actions` 里放「↩ 撤销这笔」；本件实测 `:79` 就是这个按钮，`t407-页面块清单-16词.md:66` 也把它记为「回执页撤销出口（危险色按钮）」）与用户逐字原则「**深底浮动块与页脚按钮一律不出现在结果型 HTML 里**」相撞。**新侧取原则**：撤销出口走**复制区**（`src/shared/copyArea.ts` 的 `undoExit`），不出页脚按钮。依据逐字：`t401-融合设计.md:44` 与 #419 已裁「深底块一律不出现在结果型 HTML 里」。
- **理由**：本条是双向口径的**边界条件**。双向说的是「老侧长板吸收 ＋ 新侧长板保留」，**不含**「老侧与用户原则相撞的那部分也照吸」——原则是用户自己定的长板，已确权，优先级高于老侧的历史做法。
- **可判形式**：产物里出现**复制区**（含撤销出口）；产物里**不出现**独立的页脚按钮组（`<footer>` 内无按钮元素）→ 两条都成立才算实施。**本条一经新实例触发，必须追写进 §二**；不追写即为没执行本条。
- **落点**：各页票（首例＝write 域回执页，#689）。
