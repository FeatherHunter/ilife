## 三、横向归纳（跨页共性问题）

1. **390 宽一律横向溢出 136 px（32/32 页）**：文档宽 526 px 对 390 px 视口，右缘内容在屏外，表现为「账户」卡只剩半个字、表格末列（来源／为什么是它／为什么挡住）被切、底部「复制数据／复制」只剩左半、状态条与说明行中途断句。本批最伤的一处，且不是某页偶发。
2. **三列卡片网格在 390 宽放不下（27/32 页）**：采集页与回执页的「金额／分类／账户」行，第三列被右缘裁。不裁的只有 3 页：记退款-回执页、记借出-回执页、记借入-回执页——同批里已有能放下的写法，可直接照它改。
3. **状态条与徽章是「·」串（32/32 页全命中）**：采集页一律收在「… · 待补槽位 · 未写库（已阻断）」，回执页一律收在「… · 写库成功」；最普遍的形制是 `记支出 · 支出（金额取负数） · bill.record.add · …`。
4. **徽章、字段卡小字、字段表把内部名印上屏（32/32 页全命中）**：`bill.record.add`／`bill.record.update`、「L1/L2/L3 三级」、`category`、`amount`、`id`、`source_id`、`deleted_at`、`L3 即名目`；标题下的摘要行还带 `id=2`、`prompt`、`(expense)`／`(income)`／`(lend)` 这类英文括注。
5. **采集页固定「缺一项就不写库」三列表＋「写库指令」JSON＋「复制 prompt」三块（16/16 采集页）**：三块常占半页以上，讲的都是「命令怎么跑」，不是「这笔账是什么」。
6. **回执页下半页是字段表／diff 表（16/16 回执页）**：`本次写入的字段与值`（`id / category / amount / time / account / ledger / currency / note`）、`影响行数 1 行`、`写入字段 7 项`、撤销与恢复两页的 `op / id` 表——用户这一屏要的是结果，不是这些表。
