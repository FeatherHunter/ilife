## 逐条：原话 / 原图 / 改前 / 改后 / 为什么

### 条目 2 · 查某天的账（`query_date`）
- **原话**：`2.查某天的详情页的日期选择框不明显，不好看`
- **原图**：`D:\ilife\docs\skills\skill-bill\assets\bill-help-26\图02-查某一天的账-弹窗.jpg`
- **改前**：模板给 `kind='date'` 直接出一个原生 `<input type="date">`。空值时框里是一行灰字 `年/月/日`，右侧一个小日历字形；要点到那个字形才出日历，点框身只会把光标放进年月日的某一段。
- **改后**：`[📅] 选择日期` 整盒可点（盒里那个原生 date 输入框留着当取值口，1px 透明、不可点）；空值显示占位文字「选择日期」而不是灰的 `YYYY/MM/DD`；右侧三枚快捷胶囊 `今天 / 昨天 / 前天`；选中后盒里显示 `2026-10-13（周二）`，下面写 `会写成：2026-10-13`。
- **为什么**：用户说「不明显」，根子是两点 —— 空值那行灰字长得像已经填好的值；可点区域只有右边一个小图标。整盒可点 ＋ 明确的占位词解决了这两点；周几是顺带补的，用户在原话里没要，属于待裁决项。

### 条目 3 · 查最近（`query_recent`：`limit` / `sort` / `recent_days`）
- **原话**：`3. 查最近的详情页 这些输入框没有重点，看起来都是灰色的。`
- **原图**：`D:\ilife\docs\skills\skill-bill\assets\bill-help-26\图03-查最近记录-弹窗.jpg`
- **改前**：三个槽位都是「框里一行灰提示」，且整段折在「选填 3 项」里；哪个必填哪个选填看不出重点。
- **改后**：条数＝胶囊 `10／20／50`＋旁边原生的数字框；近几天＝胶囊 `近7天／近30天／近90天`；排序＝下拉（`时间从近到远`／`时间从远到近`／`金额从大到小`／`金额从小到大`，默认第一项）；三个槽位都有「选填」小签与「会写成：…」；**条数 与 近几天 互斥**：选一边就把另一边灰掉并清空，旁边写「二选一，已清空另一项（条数 空着）」。
- **为什么**：原话抱怨的是「没重点」，所以正面回答是必填/选填小签＋把灰提示换成能点的胶囊。互斥不是新规矩 —— 真页 `query_recent` 的 `prompt_template` 本来就写着「近几天与条数二选一」，控件把它变成看得见的约束。

### 条目 5 · 查周（`query_week.week`）
- **原话**：`5. 查某周查某月的详情页需要支持周和月的选择器`
- **原图**：`D:\ilife\docs\skills\skill-bill\assets\bill-help-26\图01-HELP首页-按时间9张卡片.jpg`
- **改前**：一个文本框，提示「如 本周、上周、5月第2周；非 ISO 周，不用周选择器」—— 要人自己写对这句话。
- **改后**：相对胶囊 `本周／上周／上上周`；「选某一周 ▾」展开面板 `‹ 2026年10月 ›`，每行 `第2周　10-12(周一) ~ 10-18(周日)　起 2026-10-12`，点中的行高亮、选完自动收起；盒里显示 `10月第2周`，下面写 `会写成：10月第2周　（10-12 ~ 10-18，2026-10-12 ~ 2026-10-18）`。
- **为什么**：**故意不用 `<input type="week">`** —— 那是 ISO 周（周一算一周、跨年周号会跳），而声明 hint 明说「非 ISO 周」，写出去的值必须是「5月第2周」这种人话表达式，所以面板负责把「月内第几周」算出来。口径写在面板里：周一起算、周一落在本月的算一周、跨月的周归它周一所在的月（月初那几天接在上个月最后一周里，所以 10-01~10-04 属于「9月第4周」）。
- **待裁决**：「月内第几周」有两种数法 —— 数法 A：把含 1 号的那一周算第 1 周（10-01 那周＝第1周，10-12 那周＝第3周）；数法 B（本原型采用）：只数月内那几个周一（10-05＝第1周，10-12＝第2周）。本原型按 B 做，好处是每一周都能在某一月列表里点到、不出现「月初四天不属于任何一周」；坏处是它与「把日历第一行当第1周」的直觉不一致。

## 已知缺口与你大概会质疑的地方（诚实清单）

1. **`showPicker()` 在无头 Chrome 里不可用**：驱动里把 `input.showPicker` 换成一个计数器再点盒子，验的是「点盒子会调它、不抛异常、焦点落在这个 input」。真 Chrome 里点盒子会真的弹出系统日历；不支持 `showPicker()` 的浏览器上，补丁给一行明确提示（「这个浏览器没有 showPicker()…」），不静默失败。
2. **日期都是按「页面当天」算的**：胶囊里的「今天」「本月」「最近7天」用的是浏览器当天的本地时间（本次是 2026-10-13）。技能侧的时间口径（时区、跨日）不归原型管。
3. **星期几是我加的**：原话只说「不明显、不好看」，`2026-10-13（周二）` 这个后缀没经用户确认；不想要可以只显示日期。
4. **「月内第几周」的数法**：见条目 5 的待裁决项（数法 A vs B）。真要落地得先定这个，否则「5月第2周」各人理解不同。
5. **排序的默认值会真的写进提示词**：默认选「时间从近到远」＝用户不碰它也会带上这个值。如果希望「不碰＝不写」，得把默认改成第一项「不限（按时间从近到远）」。
6. **改后态把原生的 ⓘ 提示按钮一起藏了**：新控件的语义由胶囊与「会写成」承担，但声明里的 hint 全文在改后态看不见。要保留的话得把那个 ⓘ 挪进新控件。
7. **看预算与储蓄目标的槽位在真页是「选填」**，所以控件折在「选填 N 项」里；截图是展开了拍的。
8. **本原型的「改前」是 03:26 那份生成物的样子**：工作树里 `packages/` 正被另一个会话改着，声明件与这份真页在个别字段上已经不一致（例：这份真页把 `query_date` 标成必填、hint 是「必填；格式 YYYY-MM-DD…；默认看今天请用查今天」，而工作树的声明件写的是「日期(选填)、空＝今天」）。原型一律以**真页数据**为准，因为那是用户此刻看到的东西。
9. **真改的落点**（不在本票范围，供讨论）：模板 `packages/base-render/assets/help-template.html` 的 `fieldControlHTML()`／`mountFields()`（`kind` 白名单里已经有 `period` 这种「组合控件」的先例）＋ 各域 `declaration.ts` 的 hint／kind；结果列表「看详情」带入 id 的落点在 `packages/skill-bill/src/query/list-copy.ts`。
