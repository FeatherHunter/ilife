# 视觉基线（#1079／#1080 的像素尺子）

**这把尺子量的是「同一份 HTML 截两次，差多少像素」。**
没有它，落地票只能对着「0」这个理想值读，而实际渲染总有抗锯齿等残差。

**#1079／#1080 的差异像素比一律相对本文件的四行读数来读。**

## 口径（不许为了让自己变绿而改）

- **只许用 `vision_html_screenshot` ＋ `vision_pixel_diff`**（纯像素运算，结论可复现）。
- **不许用 `vision_describe` 之类模型判断下基线**——`docs/agents/视觉验收墙.md` §7 明写
  「视觉模型是提示器，不是证据——它可能判对，也可能**编出产物里根本没有的页名**」。
- 同一台机器、同一个浏览器、同样的 `width`／`height`／`fullPage` 参数。
- `threshold = 16`（每通道差 ≤16 视为相同）。

## 怎么读这四行

**1. 基线是 0，不是「一个小数」。** 票面预期「实际渲染总有抗锯齿等残差」——实测在这台机器、
这个浏览器上，**同一份 HTML 截两次连一个字节都不差**。所以：

> #1079／#1080 的判据是 **差异像素比 = 0**。**没有容差可吸收**：任何非零都是真差异。

**2. 零残差意味着这把尺子分辨力最高。** 遗留出口里那条「基线读数与真实差异同量级、判据失去分辨力」
的情形**没有发生**——基线 0，真实差异只要 >0 就能分辨。**不需要重定基线。**

**3. 零基线也意味着「这台机器上任何非零都可疑」。** 若某次比对出现非零差异，
先怀疑**产物真的不同**，其次才怀疑机器。换机器／换浏览器版本**必须重测本表**——
本表是**机器限定**的读数，不是普适常数。

**4. 复现步骤**（任何人都能重跑）：

```
① node docs/skills/skill-bill/1073-proto-check.mjs docs/skills/skill-bill/proto docs/skills/skill-bill/proto/manifest.json
   -> 115 件；缺失 0 -> 可发      （确认比对的两份 HTML 与入库时逐字节相同）
② vision_html_screenshot(source=docs/skills/skill-bill/proto/frozen-993/<件>  width=<W> height=<H> fullPage=true)   ×2
③ vision_pixel_diff(original=<第 1 次> rebuilt=<第 2 次> threshold=16)
```

**注意**：截图工具的输出文件名按**内容**派生，同一份 HTML 截两次会**写到同一个文件**。
要做自比，**第一次截完立刻另存**，再截第二次——否则第二次覆盖第一次，比的是同一份文件跟自己。
