## 四 给骨架票的取舍建议

判据：① 服务端渲染静态页 vs 老侧客户端 JS 现场渲染 ⇒ 纯渲染机制一律舍；② 用户真要看的（KPI／明细／空态／复制数据日志）⇒ 留；③ 版式在新仓有公共层可替 ⇒ 改成公共层组件。

| 块 | 档 | 理由 |
|---|---|---|
| 自绘样式层（`:7-109`） | 舍 | 纯渲染机制：静态页版式应由公共层 CSS 出，技能里不留样式副本 |
| 共享样式位／payload 注入位（`:110`·`:121-122`） | 舍 | 客户端注入机制，静态产出没有 payload 注入环节 |
| 页面骨架 `container`（`:113-119`） | 改 | 用公共层页面骨架，别在技能里重画容器与间距 |
| 工具函数（`:128-145`） | 改 | 金额/日期/转义格式化下沉公共层，技能只传值 |
| 主路由 `init` ＋ type 分发（`:147-201`） | 舍 | 客户端路由；静态页由服务端决定出哪些块 |
| 启动 DOMContentLoaded（`:543-545`） | 舍 | 同上 |
| 页头 header（`:203-210`） | 改 | 标题＋副标题＋时间跨度的内容要留，版式换公共层页头 |
| 页脚 footer（`:212-219`） | 改 | 保留生成时间；`type` code 与老命令串对用户无意义，可去 |
| 错误态 `renderError`（`:221-232`） | 留 | 失败要能看、能复制，属 5 状态兜底硬需求 |
| 动作区 复制数据/复制日志（`:234-247`） | 改 | 能力必须留；改成服务端预渲染出复制内容＋公共层 actionBar |
| KPI 行 6 处（`:255-260`·`:288-293`·`:408-413`·`:424-428`·`:453-456`·`:472-476`） | 留 | KPI 是用户第一眼要看的数（笔数/支出/收入/净额…） |
| KPI 卡组件 `kpiCard`（`:489-496`） | 改 | 换公共层 KPI 卡（字号档／配色档） |
| 过滤芯片 filter-chip（`:280`·`:287`） | 留 | 让用户核对 AI 解析出的筛选条件与占比口径，防误解 |
| 明细列表块（`:267-272`·`:300-303`） | 留 | 记录明细是查询的核心交付 |
| 记录列表组件 `recordsList`（`:522-534`） | 改 | 换公共层列表；200 条上限改成服务端截断＋明确提示（或分页） |
| 分类聚合卡 ＋ `categoryBar`（`:261-266`·`:294-299`·`:509-520`） | 改 | 分类/金额/笔数/占比的内容要留，条形版式换公共层 |
| 未还列表自绘（`:432-443`） | 改 | 字段（direction/target/note/amount）要留，版式换公共层列表 |
| 空态 `emptyState` 8 处（见第二节第 25 行） | 留 | 空结果必须说清「没数据」，不能给空白页 |
| 离线提示条（`:173-175`） | 改 | 若保留离线态语义，由服务端出提示块；客户端缓存探测不复用 |
| 对比卡 ＋ change-badge（`:325-344`·`:499-507`） | 舍 | 17 词无人用（对比属分析域），本骨架不承担 |
| 图表挂钩 `charts.donut`（`:369-374`·`:536-540`） | 舍 | 只有 breakdown 用，17 词里没有该路径；要图交给分析骨架＋公共图表 |
| monthly／overview／stats 分支（`:307-322`·`:378-402`） | 舍 | 属分析域（看月度/看总览/做统计），查询骨架不搬 |

结论：骨架页必须留的三块 —— **KPI 行**（笔数/支出/收入/净额，按 type 决定出几格）、**记录明细块**（含分类聚合与过滤芯片）、**空态**；复制数据/复制日志作为能力保留、实现换公共层。
