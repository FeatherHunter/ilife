## 二 · 结构设计（第二步）

新增的目录树与每件职责（都住在既有能力目录 `src/record/` 与共用位 `src/shared/` 里，不新开层级）：

```
src/record/
  collect.ts        按 kind／op 取场景件 → 叫它的 collect(input)          【对外 1 件：recordCollectDoc（＋转出 slots 两件）】
  receipt.ts        按 op／kind 取场景件 → 叫它的 receipt(input)          【对外 1 件：recordReceiptDoc】
  slots.ts          RecordSlot ／ RECORD_SLOTS ／ missingSlots            【对外 2 件 ＋ 1 型】
  scene.ts          CollectInput ／ ReceiptInput ／ Scene ／ SCENES ／ sceneFor 【对外 5 件（含 2 型）】
  collectBody.ts    现通用采集页装配体                                     【对外 1 件：collectBody】
  receiptBody.ts    现通用回执页装配体                                     【对外 1 件：receiptBody】
  scene-expense.ts … scene-restore.ts（16 件）                           【每件对外 1 件：SCENE】
src/shared/
  candidatePick.ts  候选单选                                               【对外 3 件】
  rowEditorTable.ts 逐行可编辑表                                           【对外 3 件】
  diffTable.ts      diff 表                                                【对外 3 件】
```

落点表（`kind`／`op` 值 → 场景件）**只有一处定义**：`src/record/scene.ts` 的 `SCENES`，16 行，与
`docs/skills/skill-bill/t407-场景落点清单.md` 逐行对得上。取件规则（也是 `sceneFor` 的全部判定）：

1. `kind` 非空且认得 → 该 kind 的场景件（13 条 `bill.record.add` 有 preset 的）；
2. `op` 是 `undo`／`restore` → 撤销／恢复那两件；
3. `key` 是 `bill.record.update` → 改记录那一件；
4. 其余 → 记一笔那一件（`bill.record.add` 无 kind 的通用词，也是认不得的 kind 的兜底）。

**共用件被哪两处用**：三个新块本票不接页面（红线：不改可见行为），件头写明将来谁用——
`candidatePick` 给特殊收支族（记退款／报销到账／记借出／记借入／记收回／记偿还）与批量与修正族
（改记录／撤销／恢复）；`rowEditorTable` 给批量录入与特殊收支族的流程三段式第二段；
`diffTable` 给改记录与后票的「撤销前预览」。
