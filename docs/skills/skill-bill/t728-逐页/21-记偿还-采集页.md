## 3 设计方案：这一页该长成什么样

一句话：**这页的骨架是对的（三段式：选原记录 → 填这一笔 → 确认复制），错的是它把「读数摘要」当成了首屏主体，还把三个「不用填也有值」的格摊成了三张大卡。** 设计目标是：390 档首屏能同时看到「还差哪 3 项」和「7 个格」，1280 档不再出现半行空白。

### 3.1 重排块序（改 `packages/skill-bill/src/write/template-flow.ts:289-311` 那份 `content` 数组）

现在是：`徽章行 → 5 张卡 → chip 行 → 3 张卡 → 提示条 → 缺项 chip 行 → 第1段 → 第2段 → 第3段 → 折叠区 → 口令 → 复制区 → 页脚`。

改成：

```
徽章行（采集页 · 还没写库）
缺项条    ← 现在被埋在「第 3 段」下面折叠区里，提到最上：3 枚 chip（分类／金额／借入记录编号）
摘要带    ← 由「5 张卡」降级成一行（见 3.2）
第 1 段   借入记录（候选 / 空态）
第 2 段   偿还这一步（7 格表单）
第 3 段   结果（这一笔补什么 ＋ 原记录改什么）
口令 + 复制区（主操作在这里，出成主色按钮）
折叠区    ← 只留口令原文（机器用），不再重复缺项
页脚
```

**为什么更好看**：现在这一页最贵的位置（首屏 526px）被 4 个「未给」占着；缺项 3 项却在页尾折着。把缺项条提到最上，用户打开就先看到「差哪 3 项、各差在哪一段」，三段式才真正变成一张待办清单而不是一份读数表。这一条对应用户第 3、4 条。

### 3.2 摘要从「5 张卡」改成「2 张卡 ＋ 一行 chip」（改 `scene-repay.ts` 的 `cards`／`chips`）

- `packages/skill-bill/src/write/scene-repay.ts:52-57` 的 `chips`：把 4 条改成 3 条 —— 删掉 `'分类 ' + crumbOf(CATEGORY)`（D4 的第 ② 处），保留 `偿还记负数`／`原记录 #未还 换 #已还`／`金额不动`，并把**账户／账本／时间**三格的值并进来（写成 `'账户 ' + …` 这类一格一件事的形状），这正是 `scene-borrow.ts:60` 已经在用的形状。
- `packages/skill-bill/src/write/summaryRow.ts:78` 的 `summaryCards()`：给返回值加一个「必需格只有前两格」的口径 → 采集页第一组只出 **2 张卡**（金额＝未给、分类＝借贷 › 偿还）。
- **效果（390 档实测换算）**：第 1 组从 526px 降到约 **212px**（2 卡 ＋ 12px 间隙），省下约 **314px**；首屏 844px 里就能放下「缺项条 ＋ 2 张卡 ＋ 第 1 段候选 ＋ 第 2 段开头」。
