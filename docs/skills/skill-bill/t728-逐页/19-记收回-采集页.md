## 2 缺陷清单

### D1（高）390 档读数卡被**同一张样式表里的后一条规则**打回单列，5 张卡纵向叠成 500px

- **在哪**：页首读数卡组①「金额／分类／账户／账本／时间」五张卡在 390 档的排列；读数卡组②「收回金额／借出原记录／未收净差」同理。

  `@media (max-width: 640px) { .ilife-page-ui .ilife-block-kpi-card-grid { grid-template-columns: repeat(2, minmax(0, 1fr)); gap: 10px; } }`，它上面挂着注释逐字写着「读数卡：两格并排（150px 下限在 358px 可用宽里正好两格，不再被 auto-fit 挤成三格）」；
  更靠后另有一条 `@media (max-width: 400px) { .ilife-page-ui .ilife-block-kpi-card-grid { grid-template-columns: minmax(0, 1fr); } }`。
  390 **命中后者**（390 是这面墙的量尺）。实拍 390 全页 y=190→690 这一段，五张卡各占 x=16→374 整行，卡高 83-94px，五张连缝隙约 **500px**（＝全页 2908px 的 17%、首屏 844 的 59%），而这 500px 里印出来的字只有 4 个 22px 的「未给」＋1 行「借贷 › 收回」＋5 行 12-13px 灰字。
  按同表 640 档那条注释的口径，358px 可用宽两格＝每格 174px ≥150px 下限，**是完全排得下的**。作者写「正好两格」的那一档，恰恰被后加的一条覆盖掉。
- **严重度**：高
- **归属**：全族共用（公共层 `pageUi.ts` 的两条断点规则互相抵消）；本页的触发条件是「一组给了 5 张卡」

### D2（高）1280 档「一行四张」撞上 5 张卡：末行只剩「时间」一张，右侧 **669px** 整片空

### D3（高）7 个输入格与页面底色**同一个色值**、且无边框 —— 屏幕上，它们不存在

- **在哪**：段②「分类／收回金额／时间／账户／账本／币种／备注」七格。390 与 1280 两档同样。

  实拍 390 档：这块蓝底从 y≈2375 到 y≈2730 = **355px**，是整页最高的一块（全页 2908px 的 12%）；里面是 18 行 12px 等宽文本。内容逐字含 `请加载「饼干记账」技能，帮我记一笔收回。`、`借出记录：<借出记录编号>`、`收回金额：未给　收入记正数`、`账户：<钱回到哪张卡>`、`① 记一笔收入…② 原记录 #<借出记录编号> 的备注把 #未还 换成 #已还，金额不动`。
  同一串字节在产物里存了**两份**：`<pre>` 正文一份，紧邻按钮的 `data-t="…"` 属性一份（body 内 `这一笔还差 3 项，逐项补齐：` 出现 **2 次**）。
  更别扭的是 label 与按钮标签：label 说「照这句跟助手说一遍」，按钮说「这一句可以**直接**复制」——两句话都在解释「这是可以照着说的」，而按钮本身已经叫「复制给助手」。
- **严重度**：中
- **归属**：全族共用（公共层 `pre-block` 块 ＋ `copyArea.ts` 的 `data-t`／`<pre>` 双份）

### D11（中）「还差 3 项」在页面上说了 **4 遍**；「候选只列带 #借出 且还带 #未还 的记录」说了 2 遍

- **在哪**：① 页头副题（y≈90）；② 段③ 徽章内文（y≈2265）；③ 载荷首行 `这一笔还差 3 项，逐项补齐：`（y≈2400）；④ 折叠区里的 `❌ 还缺 3 项，补齐再记`。
- **证据**：`[regex]::Matches(body,'还差 3 项').Count = 4`、`还缺 3 项' = 1`。
  另一处：`候选只列带 #借出 且还带 #未还 的记录` 在提示条 `.ilife-block-feedback-block-note-detail`（390 档 y≈385-450 的蓝底条）与段①口径行 `.ilife-block-caliber`（y≈1335）里**各出现 1 次，共 2 次**——提示条那一条还多给半句「一条都没有就直接反问」，而这半句的意思又被空态卡的「列表里一条都没有」第三次说出来。
  `没有可选的借出记录编号`（15px 粗体标题）与其正下方 18px 粗体正文里的 `列表里一条都没有`，相距不到 30px，说的是同一件事（见 D6）。
- **严重度**：中
- **归属**：本族共用（`summaryRow.ts`／`blockedSlots.ts`／`feedback-block-note` 三处各产出一次同一事实）

### D12（中）折叠摘要与它体内的第一个标题**同名**；缺项表三列里有**两列同值**

- **在哪**：页尾 `<details>`。
- **证据**：产物 `<summary class="ilife-block-disclosure-summary">还缺什么，以及补齐后照抄的那条</summary>` 与 body 内第一个子节点 `<h2 class="ilife-block-feedback-block-title">还缺什么</h2>` —— 展开后「还缺什么」在同一张三行内出现两次。
  折叠区里的缺项表（`.ilife-block-data-table`），三行单元格逐字为：
  `还缺哪一项=分类` / `是什么=分类` / `为什么写不进去=这一项没给`
  `还缺哪一项=金额` / `是什么=金额` / `为什么写不进去=这一项没给`
  `还缺哪一项=原记录编号` / `是什么=借出记录编号` / `为什么写不进去=没给：收回要指名销哪一笔的 #未还，不拿最近一笔顶替`
  —— **三行里有两行的第 1、2 列是同一个字符串**；第 3 行的第 1、2 列是同一个东西的两个名字（`原记录编号` vs `借出记录编号`）；第 3 列在第 1、2 行也是同一句 `这一项没给`。这张表实际只承载 **3 条独立信息**，印了 9 格。
  另外这张表在 ≤640 档会走公共层的「表格卡片化」：`.ilife-block-data-table:has(td[data-label]) thead { display:none }` ＋ `td::before { content: attr(data-label) }` ⇒ 390 档展开后每格自带列头，3 行 × 3 格 = **9 次列头印刷**，其中「还缺哪一项 分类 ／ 是什么 分类」这种同值对会并排出现两次。这一条与共用底 §5 已查实的「窄屏两列表逐行重复表头」是同一类，但触发条件更早：**列本来就是同义的**，收窄只是把它放大。
- **严重度**：中
- **归属**：本族共用（本包缺项表装填处 ＋ 公共层 `renderDataTable` 的卡片化）

### D13（中）三排同形胶囊承担**三种语义**；第二排的位置还把它错挂到了段① 名下

- **在哪**：胶囊排①「采集页／分类按三级挂靠／还没写库」（y≈143）；排②「收回记正数／分类 借贷 › 收回／原记录 #未还 换 #已还／金额不动」（y≈728）；排③「分类／金额／借出记录编号」（y≈1230）。
- **证据**：三排都是 `.ilife-block-chip-row > .ilife-block-chip`（`background:var(--soft)`、`border:1px solid var(--line)`、`color:var(--blue2)`、`border-radius:999px`、`min-height:30px`），390 档实拍三排的胶囊像素形状完全一致。可它们的语义分别是：① **这是什么页**（元信息）、② **这一笔的记账规则**（策略，见 D5）、③ **还缺哪三项**（缺口清单）。排③ 还是静态 `<span>`，没有 `href`，看着像页内导航却点不动。
  排③ 的位置更具体地错了：它排在 `第 1 段` 段头**之前**（产物顺序 `chip-row → span.badge 第 1 段 → caliber → empty-block`），视觉上读起来像「第 1 段 = 分类、金额、借出记录编号」这一段的三个子项；实际它是全页的缺口清单。
- **严重度**：中
- **归属**：全族共用（chip 形状 ＋ `blockedSlots.ts` 的排位）

## 3 设计方案：这一页该长成什么样

**现在这页的病，一句话**：这是一个「填 7 格、认 1 笔」的页，屏幕上却排了 **22 个平铺元素、10 颗同形胶囊、5 行灰口径、2 块蓝色等宽载荷、5 颗按钮**；而真正能打字的 7 个格**在画面上不存在**（D3），第一段整段是空的却排在必填字段前面（D4），桌面末行空掉 669px（D2），同一批事实被说 2-4 遍（D5／D11）。手机整页 **2908px ＝ 3.4 屏**，第一个可交互格在 2.0 屏处。

**改成「一块状态牌 → 一张字段表 → 一段可选认领 → 一条照抄」四层，整页从 3.4 屏收到 ~1.8 屏。**

### ① 页头：缺项从「五处复述」收成一条**缺口尺**（改 `pageParts.ts` 一处 + `blockedSlots.ts` 一处）

- 副题「还差 3 项，缺的在下面标出来了」→ 换成**缺口尺**：一行 `还差 3 项` + 一条细进度条，条上 7 个刻度对应 7 个字段，已定的实心、缺的空心描边；后面只列缺项名。这一条用一个形状说完「差多少、差在哪」，替掉现在的副题 ＋ 胶囊排③ ＋ 段③ 徽章里的计数 ＋ 折叠区「还缺 3 项」＋ 载荷首行（D11 的 4 遍收到 1 遍）。
- 排① 的 `还没写库` 从 `-danger` 降到 `-empty`（`background:#f0f0f3; color:var(--fg2)`，仓内已有这一档，**不新造色**）；`分类按三级挂靠` 从首屏移除，挪进页尾那个 `<details>` 里跟「数据结构／调用链」放一起（那里已经在说实现口径）。
- 改哪一条：`.ilife-status-badge-danger` 在**这一处调用点**换成 `-empty`（公共层的类保留，不动）；副题的产出改 `write/pageParts.ts`。

### ② 字段区：读数卡组① ＋ 参数表**合成一张看得见的表**（改 `template-flow.ts` 块序 + 公共层一条）

- 把「5 张读数卡（第一组）+ 7 个 param-form 格」合成 **一张 7 行 32px 的字段表**：左列字段名（13px `--fg2`），右列值（15px `--fg`），行右端一个状态字形（实心点＝已定／空心方框＝缺／`缺省` 小标＝可不填）。7 行 ≈ 224px，替掉 390 档现在的 **500px（卡组①）＋ 590px（表单）＝ 1090px**。
- 值的字重就是状态，不再写一个 22px 的「未给」去占位——有缺省值的（时间＝今天 12:00、账户＝默认账户、账本＝默认账本）**直接显示缺省值**，不要「未给」，因为这一项确实不用填（治 D1 的一半：五张卡里那四个「未给」有三个是假缺口）。
- 读数卡组②（收回金额／借出原记录／未收净差）里的 `收回金额` 与组① 的 `金额` 是同一个字段 ⇒ 只留一处；`未收净差 未算` 是结果不是字段 ⇒ 挪到段③ 的一句话里。
- **公共层一条改动**：`.ilife-block-param-form-input { background: var(--bg); border: 0 }` → `background: var(--card); border: 1px solid var(--line)`，焦点态保留现有白底＋蓝框＋蓝光。**一行改动，全族所有含表单的页同时从「隐形格」变成「看得见要填的表」**（D3）。

### ③ 段序：把「认领借出记录」从**第一段**挪到**必填之后**，并把它做成可折叠的第二段（改 `template-flow.ts` 块序）

- 顺序反过来：**段① = 收回这一步**（分类／收回金额／时间／账户／账本／币种／备注，必填在前）→ **段② = 认哪一笔借出**（候选为空时整段收成一行：`借出记录　库里没有 #未还 的借出，回收回编号或新记一笔借出`，右侧一个 `缺` 标记，不要那张 880×148 的空白卡）→ **段③ = 记完变什么**（一句话）。
- 空态那一块：删掉「没有可选的借出记录编号」这个 15px 的 `<h2>`（它比下面的 18px 正文小 3px，是层级倒挂，D6），卡内文字降到 15px/600 或 13px/400，`.ilife-empty` 的 `padding: 48px 20px` 收到 `16px 20px` ⇒ 卡从 148px 降到 ~70px，整段从 384px 降到 ~120px（D4 ＋ D6 一起治）。
- 改哪一条：`.ilife-block-empty-block-title` 与 `.ilife-empty-text` 二选一留（现在的两档字号互相打脸）；`.ilife-empty` 的 padding 一档。

### ④ 四颗策略胶囊 → 一个**「这一笔怎么记」的小卡**（改 `summaryRow.ts` 一处）

- 段② 那张字段表下面挂一行**规则条**：`收回记正数` / `分类固定 借贷 › 收回` / `原记录 #未还 → #已还` / `金额不动` 四条，用 **两列表格**（左 12px `--fg3` 规则名、右 13px `--fg` 值），而不是四颗蓝胶囊；关键是**它同时取代段②／段③ 的口径行**（D5 的四条 ×2 收到 ×1）。`→` 用层级字形（`#未还 → #已还`），替掉现在胶囊里的空格拼法。
- 为什么这样更好看：四条规则现在是「四颗看起来一样的胶囊，其中两颗有键两颗没键」，读的人得先猜哪颗是键、哪颗是值；改成两列表之后，键与值各占一列，四条并排比一次就看完（用户第 5 条）。

### ⑤ 段头：从游离徽章 → **有数字位的分组头**（改 `write/pageParts.ts` 一处）

- `<span class="ilife-status-badge …">第 1 段　借出记录：未认准</span>` → 一个**块内**的分组头：`①` 序号字形（`--fg3`，24px）＋ 段名（15px/600 `--fg`）＋ 右侧状态小字（12px `--fg3`），三件各占一格位置，`：` 与 U+3000 全部退场（D8）。三段各给不同层级：段①（要填）用 `--blue2` 序号、段②（可认领）用 `--fg2`、段③（结果）用 `--ok` 系——**层级由字形颜色出，不由同一个琥珀胶囊出**。
- 同时给这三行 `<h2>`／`<h3>` 语义：现在全页三段段头在文档大纲里根本不存在（D8）。

### ⑥ 页尾：355px 蓝墙 → **四行可照抄的清单**（改公共层 `pre-block` 一档 + `copyArea` 一处）

- `.ilife-block-pre-block-code` 加 `border: 1px solid var(--line)`（现在没有 border，8px 圆角与浅蓝底都白做）。
- 载荷**一个字不改**（硬约束 4），改的是**形状**：默认收进段② 已有的那个 `<details>` 里（这一页已经有一个 `还缺什么，以及补齐后照抄的那条` 折叠，载荷跟它做的是同一件事，合并成一张），外面只留一行「给助手的一句」+ `复制给助手` 主按钮（`-ghost` → `-primary`）。
- `复制数据`／`复制日志` 收到次级：1280 档不再各占 436px，改成靠右一排；390 档保持并排 175px（现有的 44px 触摸区规则不受影响）。
- 删掉重复的那份：`<pre>` 正文与按钮 `data-t` 是同一串字节的两份（body 内该串出现 2 次），保留一份即可。

**为什么这样比现在好看**（对应用户六条）：
- 第 3 条（审美）：现在最丑的三处——**看不见的输入格**、**桌面末行一张孤卡＋669px 空洞**、**一堵 355px 的等宽蓝墙**——都在这一层被治掉；
- 第 4 条（文字不冗余）：`还差 3 项` 从 4 遍降到 1 遍，四颗策略胶囊的四条规则从 2 遍降到 1 遍，`不填就记到默认账户／账本／时间` 从 2 遍降到 1 遍（本页 grep 计数各为 2），三级分类的两种记法收敛成一种（D7）；
- 第 5 条（该设计而不是拿符号串）：段头里的 U+3000 全角空格、胶囊里的空格拼键值、载荷里 `没给：收回要指名销哪一笔的 #未还` 的连环冒号——三处都改成由版式出分隔；
- 第 1／2 条（两端自适应）：390 档第一段从 384px（全空）收到 ~120px、第一组卡从 500px 收到 ~224px，第一个能打字的格从 2.0 屏提到首屏内；1280 档不再有 669px 的空行、也不再有一张 880×148 只装两行字的白卡。
