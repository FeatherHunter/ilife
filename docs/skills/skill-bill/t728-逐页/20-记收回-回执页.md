## 2 缺陷清单

### D1 窄屏把每一行都印一遍表头，「哪一项」一屏 12 次

**在哪**：`#sec-detail` 那张两列表「写进去的项与值」，390 档的**每一行**。
**证据**：`getComputedStyle(td,'::before').content` 实测 `"哪一项"`（8 条）/ `"记成什么"`（8 条）；
td 的 `display:flex; justify-content:space-between`，td 宽 356px（x=17 → right=373）；
行高 56px（tr0）与 57px（tr1～tr7）逐行相同 ⇒ 8 行＝8×2 条标签行，**16 处标签文本**，
连 390 档唯一可见的那个 caption 一起算，「哪一项」共 12 次。
**严重度**：高。**归属**：全族共用（公共层）——是 `pageUi.ts` 第 ⑥ 段
（`@media (max-width:640px)` 里 `.ilife-page-ui .ilife-block-data-table:has(td[data-label]) td::before`）
把「行头列」摊成「每格一个列头」的通则；本页的两列都是 `cell-left`，于是每一格都拿到一个列头。

### D2 同一批事实在页面上印两遍：卡片一次、明细表再来一次

**在哪**：`#sec-kpi` 的 8 张卡 与 `#sec-detail` 的 8 行，是**同一批键值**。
**证据**：卡片 label 实测为 `金额 / 分类 / 账户 / 账本 / 时间 / 状态 / 这次记了几笔 / 配对标签`；
明细表 8 行的行名实测为 `记录编号 / 分类 / 金额 / 时间 / 账户 / 账本 / 币种 / 备注`。
两处值逐值相同：金额 500.00、分类「借贷/收回」、时间 `2026-09-14 12:00:00`、账本「生活」、账户（两处都空）。
`rowDetail()`（`packages/skill-bill/src/write/write.ts:70`）构造的 8 行与 `summaryCards()`
（`summaryRow.ts:78`）的 6 格是**两条各自独立的取值路径**，谁也不知道对方已经把同一件事印过一遍。
表里真正多出来的只有 `币种 人民币` 与 `备注`（空）两项。
**严重度**：高（用户要求 4「文字不能出现冗余」正面命中）。**归属**：本族共用——
`template-flow.ts:322-329` 的块序列，16 张回执页同构同病。

## 3 设计方案

**病根一句话**：这一页把「同一批事实」当成两种东西印了两遍（卡＋表），再给每一遍配一句自指的话；
于是 8 个真值被 8 张高卡＋8 行双标签表拆成了 2.5 屏。

### 3.1 事实只印一次：卡片网格换成**两行可读的摘要带 ＋ 一张键值表**

**改哪一个件的哪一条**

1. `packages/skill-bill/src/write/template-flow.ts:322-329` 的 `blocks` 数组：
   `navBlock(renderKpiGrid([...]), 'sec-kpi', '读数')` 这一块**整块撤掉**，
   页内导航从 4 项收到 3 项（`明细 / 撤销 / 复制`）。
2. `packages/skill-bill/src/write/receiptParts.ts:35` 的 `reconcileDisclosure`：
   它现在重印「记录编号 125 / 写入时间 …」两条已在正文的事实 ⇒ 把这条折叠区**删掉**
   （`receiptParts.ts` 的注释自己写着「这次记了几笔与写进去的项已在上方卡片上，这里不重写」，
   它守住了「几笔」，没守住「编号」）。
3. `#sec-detail` 那张表升级为**全页唯一的事实载体**，并从「两列表」改叫键值表：
   `write.ts:70` 的 `rowDetail()` 把 `记录编号` 与 `写入时间` 一起收进这 8 行（`写入时间`
   今天只活在折叠区里），行名沿用 `fieldLabelOf`。

**为什么比现在好看**（对应用户第 5 条）：8 张卡的信息量只有 8 个短值，却占了 853px；
一张键值表把同样的 8 项收进 1 屏，且读者是「一列键、一列值」对齐扫读，不再需要在两个区块之间对答案。

### 3.2 窄屏的键值表：一屏一表，列头只出一次

**改哪一个件的哪一条**

- 公共层 `packages/base-render/src/pageUi.ts` 第 ⑥ 段（`@media (max-width:640px)` 里那段
  `.ilife-block-data-table:has(td[data-label])`）加一条**优先形态**：
  当 `tbody` 的 `td[data-label]` 只有 2 列且**表头组相同**时，窄屏走
  「4 行 × 2 组并列的键值网格」，`td::before` 的 `content: attr(data-label)` 只在第一组出一次，
  其余格以 `grid-area` 定位、不重复列头；两列非同类（如「哪一项 / 记成什么」之外的三列表）
  仍保留今天的逐格列头形态（今天的行为不删，只让位给优先形态）。
- 同一段里给值格补 `min-width: 0; text-align: right` 的确认（今天值已经右对齐，
  但标签 158px ＋ 值 336px ＝ 494px 已经越过 356px 的单元格宽的一半 ⇒ 必须让 `::before` 可缩）。

**为什么比现在好看**（对应用户第 5 条）：现在是「8 行 × 2 条标签行」，用户看到的是
16 条一模一样的「哪一项 / 记成什么」；改成 4 行 × 2 组之后，同一批事实只用 4 条行、每行 2 组，
标签量从 16 条降到 4 条，表高从 491px 降到 ~240px。

### 3.3 桌面档的表格收边：给表格一个 880px 的文字列宽，给键值表一个可读列宽

**改哪一个件的哪一条**

- 公共层 `packages/base-render/src/pageUi.ts` 第 ⑧ 段那条满铺 `:where()` 名单里
  **把 `.ilife-block-data-table` 从「满铺」改成「满铺但内容列有上限」**：
  给 `.ilife-block-data-table-table` 加 `max-width: 880px`（与正文列同宽）＋
  `margin-left: 0`（左对齐，不居中），表容器仍满铺（保留它的圆角外框与横滑兜底）。
- 公共层 `blocks.ts` 的 `@media (min-width:641px) { td.cell-left:first-child { width: 1% } }`
  **改成 `width: 6em`**（定宽左列，不再让第一列被挤到 80px）。
- 两张表合流之后，右列内容吃满剩余宽：`125` 不会再顶着 798px 的空列。

**为什么比现在好看**（对应用户第 1、3 条）：现在桌面档第二列 798px、内容 24px～142px ⇒
74.6%～86.7% 的表宽是空白，读起来像「表格坏了」；收边之后一页只有一条文字列宽（880px），
标题、正文、表格、页脚同一条左边线，宽屏不再空荡也不散。

### 3.4 卡片改成「摘要带」，一行放得下 8 个短值

**改哪一个件的哪一条**

- 公共层 `packages/base-render/src/blocks.ts` 的 `block-kpi-card` 区：
  值 22px/700 → **17px/700**、`line-height: 1.2`（值高 26.4 → 20.4）；
  `.ilife-block-kpi-card { padding: 14px → 12px 14px }`；
  加一条 `.ilife-block-kpi-card-grid-compact`（新修饰类，本包 opt-in），
  窄屏 `grid-template-columns: repeat(2, minmax(0,1fr))`。
- 公共层 `packages/base-render/src/pageUi.ts` 第 ⑦ 段那条
  `@media (max-width:400px) { … grid-template-columns: minmax(0,1fr) }`
  **只对非 `-compact` 网格生效**（写成 `:not(.ilife-block-kpi-card-grid-compact)`——
  保住「390 档不许出现被挤扁的三格」，同时让 8 个短值的读数组能两格并排）。

**为什么比现在好看**（对应用户第 1、2 条）：390 档现在 8×97.9＝853px 且每张卡右半边空着；
改完 4 行 × 2 格（`金额/分类`、`账户/账本`、`时间/账本`、`状态/笔数`）× ~72px ≈ 320px，
一屏能看到「值 ＋ 撤销 ＋ 复制」三件事——这就是 help html 那种「一屏一件事」的适配能力。
