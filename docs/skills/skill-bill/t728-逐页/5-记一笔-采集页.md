### 缺陷 1（高 · 全族共用（公共层））七格表单控件零可见边界：输入框底色与页底**逐值相同**

**在哪**：第 2 段下面那张字段卡，`分类`／`金额`／`时间`／`账户`／`账本`／`币种`／`备注` 七格全中（手机 x16..373、y761..1258；桌面 x200..1079、y766..1250）。

**证据**：
- 行扫描（`GetPixel`，逐像素比色）：手机 y=800（`分类` select 内部、文字下方）从 x=0 到 x=389 **整行都是 `#f5f5f7`**；桌面 y=786（`分类`／`金额` 那一行）从 x=190 到 x=1090 除字形外同样全是 `#f5f5f7`。
- 页底也是 `#f5f5f7`（产物 `body{background:var(--bg)}`，`--bg:#f5f5f7`）；控件规则是 `.ilife-block-param-form-input{border:0;background:var(--bg);border-radius:8px}`（产物样式第 1833–1845 行，真源 `packages/base-render/src/blocks.ts:2356-2367`）。
- 390 档「这是一格」唯一的线索：`分类`／`账本` 两枚 select 最右侧那个 `▾`（落在 x≈370），以及 `*`（`#c0392b`）。框、面、边界一个都没有。
- 对照：同一页的空态卡是 `1px solid var(--line)` ＋ 白底（实测卡内 (200,549)=`#ffffff`）、第 N 段白条也是白底 —— 这套设计语言是有「面」的，只有真正要填的控件把它丢了。

**为什么算高**：用户第 3 条（是否符合 UI 设计师审美）与第 6 条（视觉审查）直接落在这里；上一轮维护者判「非常丑陋」，这一条是「看起来不像一张表」的根因——七格靠 12px 灰标签 + 一行浮字撑场面，桌面档同样中招（1280 档 x200..628 与 x652..1080 两块 428px 的空地）。

**归属**：全族共用（公共层）——规则住 `base-render`；凡用 `renderParamForm` 的页一起变。

### 缺陷 4（高 · 全族共用（公共层））全页唯一的一枚主按钮是死的；可见区一颗主按钮都没有

**证据**：
- 产物字节：`<button type="button" class="ilife-copy-btn ilife-copy-btn-primary ilife-copy-btn-wide">补齐了，说一遍试试</button>` —— **既没有 `data-action-id`、也没有 `data-t`**。
- 产物自带的那段脚本（第 2333–2352 行）是全页唯一的点击委派：先 `node.closest("[data-action-id]")`，取不到就 `return`；取到了还要 `btn.getAttribute("data-t") === null → return`。⇒ 这枚按钮**点了什么都不会发生**。
- 同块另一枚 `<button … class="ilife-action-btn ilife-action-btn-ghost" data-action-id="ilife-blocked-write">⛔ 先补齐（2 项）</button>` 有 id 却没有 `data-t` ⇒ 同样落进 `return`。

## 3 设计方案：这一页该长成什么样

一句话：**这一页是「一张待填的表 ＋ 一条缺项摘要 ＋ 一段可复制的口令」三件事；现在它被排成了「三段解释 → 一个空盒子 → 最后才给表」。把表提到前面，把空盒子拆进它的那一格，把三段白条换成一个能装内容的段头。**

### 改动 1 块序：待填的表提到首屏（对应用户第 1／6 条）

- 改哪一条：`packages/skill-bill/src/write/template-expense.ts:161-215` 的 `content[]` —— 把 `fieldCardOf(...)`（现 `:192-198`）从 `collectSectionTitle({no:2})` 之后提到**页头正文第一块**（`typeBadge` 之后、`progress` 之前）；`collectSectionTitle({no:2})` 保留在它上头半格，作为这张卡的小标题（形状见改动 4）。
- 为什么好看：390 档第一个可填格从 y=761 提到 **y≈180**（省掉 580px 的解释墙），首屏一眼就是「这是要填的表」；被挪走的解释（口径行、预填标注、缺项折叠）全部沉到第 2 段之后，变成「有疑问再展开」的那一层。
- 信息一条不少：所有块一个不删，只换序。

### 改动 2 控件补回「面」（对应用户第 3 条；本方案里最要紧的一条）

- 改哪一条：公共层 `packages/base-render/src/blocks.ts:2356-2367` 的 `.ilife-block-param-form-input` —— `border: 0` 改 `border: 1px solid var(--line)`，`background: var(--bg)` 改 `background: var(--card)`；`:focus` 那条已有 `border-color: var(--blue)`，把 `background: var(--card)` 从 focus 态里去掉（静止态已经是白的）。`--fg3` 那条不新增色值，只用既有 token。
- 为什么好看：静止态一眼能数出「有七格、格有多宽、从哪点到哪」；卡片（白面＋1px 线）与页底（`#f5f5f7`）本来就分得开，控件只要跟卡片同一条口径，整页立刻从「一段带标签的文字」变成「一张表」。这条同时解掉缺陷 1，并且**一行 CSS 影响本族所有表单页**，不用各页补。

### 改动 3 空态收进它自己的那一格（对应用户第 4／6 条）

- 改哪一条：删掉 `template-expense.ts:151-158` 生成、`:190` 拼进去的 `emptyNote(...)` 那一块（连同 `没有可选的历史账户` 小标题与 183px 的卡）；把这句话降级成 `账户` 格的**内注**：`slot('account', …)` 的 `hint` 在「库里没有带账户的记录」时换成 `库里还没有带账户的记录，空了就记到默认账户。`（即现在两句的合并句，一句顶三句），随 `.ilife-block-param-form-field` 排在 label 与控件之间，12px `--fg2`。
- 为什么好看：114px 的空白 + 一个 18px 的大字标题消失，页面少一整块「什么都没说」的白面；「账户为什么是空的」回到它该在的位置（离 `账户` 那一格 0px，而不是 400px）。信息量不减：三句变一句，语义完全覆盖。

### 改动 4 段头换形状（对应用户第 5 条）

- 改哪一条：`packages/skill-bill/src/write/collectFrame.ts:33-36` 的 `collectSectionTitle` —— 不再走 `renderConclusionBar`（46px 白条 ＋ 3px 蓝左边），改成两件小东西：一行 **12px `--fg2` 的段序号字形**（`1`／`2`／`3`，落在左侧一个 20px 的圆角方格里）＋ 同一行 15px `--fg` 的短标题，整行上面压一条 `1px solid var(--line)` 分隔线（或干脆只留序号圆点）。
- 为什么好看：三条通栏白条把页面切三段，换成「线 ＋ 序号 ＋ 标题」后纵向从 138px 收到约 66px，「第 N 段」从一个独立块变回标题的前缀；三段的重音不再一样重（前一版三条同形同高，读者分不出哪一段是主体）。序号的层级字形也顺手替掉了「第 N 段」这种拿汉字当编号的写法。

### 改动 5 预填来源回到看得见的地方（对应用户第 4／5 条）

- 改哪一条：`packages/skill-bill/src/write/photoEscape.ts:139` 的 `hint: prefillHint(...) ?? s.hint` —— 改成 `hint: s.hint`（原生提示回归），另在 `label` 行尾挂一枚 12px 的 `预填` 小胶囊（`--soft` 底、`--blue2` 字，与页头胶囊同一形状口径），来源原文写进这枚胶囊的 `title`／`aria-label`；`prefillNote.prefillHint`（缺陷 3 的破句生成处）不再喂给 placeholder。`prefill: 'caliber'` 那条「来源写在格子里」的口径行随之删掉（它承诺的事改由胶囊承担）。

### 改动 6 「缺什么」收成一条状态行（对应用户第 4 条）

- 改哪一条：页头下这三件合成一行 —— 副题 `缺的就是下面这几项。`、进度行 `补齐这 2 项就能记进账本`、缺项胶囊行 `分类`／`金额`。作成一条 `还差 2 项 ▸ [分类] [金额]`：数字用 15px 600，两个缺项用改动 5 那种小胶囊（同形状），整行与 H1 之间保留副题位。
- 为什么好看：390 档省下约 60px，且「差什么」从三处变成一处；页头只留一个视觉重音。

### 改动 7 复制区：主次分明、按钮不再撑宽、少两句废话（对应用户第 1／3／4 条）

- 改哪一条：`packages/skill-bill/src/write/template-expense.ts:199-213` 的 `promptCopyArea(...) ＋ collectSectionTitle(3) ＋ copyArea(...)` —— 三块合成一条底部动作栏：主按钮 `复制给助手`（`ilife-copy-btn-primary`，真动作、真 `data-t`），次按钮 `复制数据 ▾`／`复制日志` 走 ghost；桌面档给这条栏 `max-width: 520px`（回收 `.ilife-action-bar` 手机档那个上限），手机档三枚按 `grid-template-columns: 1fr 1fr`＋主按钮跨两列。
- 同时删两处字面：按钮标签 `复制给助手：这一句可以直接复制` → `复制给助手`；小标题 `这一段就是补齐后要发给助手的话` → `发给助手的话`。
- 为什么好看：桌面档两颗 436px 空按钮消失（缺陷 11），页面上第一次出现「哪一颗是主」；按钮标签回到动作本身，说明性文字不再占 CTA 的位置。

### 改动 8 公共层那枚假主按钮：要么给动作，要么别做成按钮（对应用户第 3 条）
