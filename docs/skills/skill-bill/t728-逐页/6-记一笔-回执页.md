## 3 设计方案：这一页该长成什么样

### 3.0 先看清这一页是什么

这一页的内容其实是**一张收据**：一笔钱、一个分类、一个账户、一个账本、一个时刻、一个编号，加一句「存好了」，再加三个可复制的出口。现在它被摊成 **8 张读数卡 + 8 行两列明细 + 15 行重复提示 + 4 颗导航胶囊**，同一批事实讲了 3 遍，占掉 390 档 2813px 里的 2025px（72%），而**真正能点的东西（复制数据 / 复制日志 / 撤销）被压进最后 300px**。

目标：**一张干净的收据**。每一件事只在一个地方出现一次；所有「标签：值」串与「A，B，C」串改成有形状的版式；两端同一种读法，只变列数。对应维护者六条：要求 4（去冗余）、要求 5（分隔符换设计）、要求 1/2（两端自适应）。

### 3.1 读数区从 8 张卡收成 3 张卡（**这条最省事、收益最大**）

- **改哪一个件的哪一条**：`packages/skill-bill/src/write/template-expense.ts` 的 `receiptPage()` 里 `navBlock(renderKpiGrid([...facts, receiptStatusCard(input.receipt, input.writtenDetail), ...tailCardsOf(spec.cards, input)]), 'sec-kpi', '读数')`（第 253–257 行）这一处：
  - `...facts`（金额／分类／账户／账本／时间 5 格）只留 **金额** 与 **分类**；
  - `receiptStatusCard` 留（「已改动」是真结论）；
  - `tailCardsOf(spec.cards, input)` 的「这次记了几笔 / 写进去的项」**撤掉** —— 它们是「这一页做了什么」的自我汇报，与 `receiptParts.ts:33` 已经删掉的「回执格式 / v1（写库回执）」是同一类（用户拿它没有动作可做）。
- **配套一条（可选，但建议一起）**：`packages/base-render/src/pageUi.ts` 的 ⑦ 段（第 160–166 行）删掉 —— 让 390 档保持 ⑥ 段设的**两格并排**。**这条有前置**：只有当读数卡里不再有 `2026-09-14 12:00:00` 这种 19 字长值（也就是 D6 的成因）时，两格并排在 390 才成立；否则 176px 的卡里它会折成两行。
- **为什么这样比现在好看**：390 档读数区从 **852px 掉到约 310px**（2 格 × 2 行 + 1 格），首屏立刻空出来，维护者第一眼看到的不再是一屏白卡；1280 档从 4×2 变 3×1 一行排开。**信息一条不少**——账户／账本／时间／币种／备注 都还在下面的收据单上（账户那格按 D3 补上「未给」）。

### 3.2 明细表从「两列表格」变成「收据条目列」（两端同一种读法）

- **改哪一个件的哪一条**（三处，全在公共层）：
  1. `packages/base-render/src/pageUi.ts` 的 `pageUiCss()` 第 120–158 行那段 `:has(td[data-label])` 卡片化规则：**只在表格列数 ≥3 时才摊卡**（加一条 `:not(:has(th:nth-child(3)))` 的排除，或按 `th` 个数分支）。**两列的键值表在窄屏仍是一行**（左标签、右值），而不是两行。
  2. `packages/base-render/src/blocks.ts` 的 dataTable 区：`td.cell-left:first-child` 已经 `width: 1%`，再给值列一条上限 —— `tbody td:last-child { max-width: 24em; text-align: right }`，让 1280 档的值列**收在正文列右侧**，不把 797px 全吞。
  3. 同一区加一条点线引导（用既有 token，零新色值）：`tbody td:first-child { flex: 1 1 auto }` + `tbody td:first-child::after { content: ""; flex: 1 1 auto; margin: 0 10px 4px; border-bottom: 1px dotted var(--line) }` —— 这一条同时解决 390 档「标签在 x28、值在 x361、中间 274px 死白」的问题。
  4. 空值占位：`src/write/write.ts` 的 `rowDetail()` 对空串输出 `未给`（与 `summaryRow.ts:89` 同词），**行不删**。
- **为什么这样比现在好看**：对应用户要求 5——「哪一项 / 记成什么」这 16 个标签**本身就是拿列头当分隔符**；取消列头之后改由**版式**出分隔（左标签、右值、中间点线）。
  - 390 档：明细表从 **481px 降到约 8×32 + 表头 ≈ 290px**，文字线从 16 条减到 8 条，那两个「记成什么」悬空标签自然消失。
  - 1280 档：每一行从「左侧 206px 有字、右侧 658px 死白」变成「值贴右、点线引过去」——**收据感立刻出来**，这是这一页最像收据的地方。

### 3.3 退出口：删掉那颗假红钮，把撤销做成真按钮

- **改哪一个件的哪一条**：`packages/skill-bill/src/shared/copyArea.ts` 的 `undoExit()`（第 143–161 行）：
  - `EXIT_TITLE = '想反悔（撤销这一笔）'`（148 行）删 —— 它与按钮同屏逐字重复（全页 `撤销这一笔` 出现 4 次）；
  - 那颗按钮**要么真绑动作**：给它 `data-t` 指向撤销指令（那段字面量本来就在复制载荷里），label 改成它真做的事名（例如「复制撤销指令」）；**要么就不要做成按钮**（`copyArea.ts:143` 的注释说它「故意不绑动作」，那就别用满饱和红 + `cursor:pointer` + `:active{transform:scale(.96)}` 的按钮壳）；
  - `EXIT_NOTE`（149 行）那句四小句拆成一句：「撤销走「复制撤销指令」；撤销后记录还在，可随时恢复。」并把 `（记录编号 N）` 删掉（编号在收据单上，全页已出现 5 次）；
  - `packages/skill-bill/src/shared/docPage.ts` 里 t410 那条 `:has([data-action-id="ilife-exit-undo"]) { grid-template-columns: 1fr; width: 100% }`（单钮独占整行）随块一起撤。
- **为什么这样比现在好看**：对应用户要求 4 与 6 —— **一页里最响的元素必须是唯一该点的那个**。现在全页视觉权重最高的是一块点不动的红。

### 3.4 重复提示：从「15 行文字墙」变成「一句结论 + 一张可展开的小表」

- **改哪一个件的哪一条**：`packages/skill-bill/src/write/duplicateNote.ts` 的 `duplicateNote()`（第 87–118 行）：
  - 第 93–95 行那三个字段的拼串断掉，改成**结构化行**：回执页（`mode === 'static'`）只出**前 3 条 + 一条「还有 12 条」**，15 条全部放进 `renderDisclosure`（是既有件，事实一条不少）；
  - 表体用 `renderDataTable` 三列（`编号` / `时刻` / `金额`）—— 因为分类与这里相同、账户是「没设置」，重复印 15 遍没有信息；
  - 那句 `detail`（「对的是 2026-09-14 这一天，金额 -12.50，分类 餐饮」，现在用一个半角空格加一个 `，` 混着当分隔符）与标题已经同义，缩成一句或不写。
- **为什么这样比现在好看**：390 档这块从 **692px 降到约 130px**（0.82 屏 → 0.15 屏），而且信息不减。这正是要求 5 的正面答案。

### 3.5 页头收干净

- **改哪一个件的哪一条**：
  - `packages/skill-bill/src/write/write.ts:177` 的 `summary`：删掉 `（记录编号 ${r.id}，这一页可以复制）` 整段；
  - `packages/skill-bill/src/write/typeBadge.ts:60` 的 `方向按金额符号判`：这是**实现口径**（它说的就是「看符号」），而且读数卡「金额」的说明「支出（取负数）」已经具体讲过一遍 —— 删这一颗；
  - 同一处的 `回执`（块名）删 —— 用户不需要知道这一页的类型名；
  - `packages/skill-bill/src/write/userWording.ts:127` 的两句话：第二句「要反悔就点下面的「撤销这一笔」」与退出口重复，删；第一句「这一笔已经记下了，不用再做什么。」与绿徽章「这一笔已保存」重复，删。
- **为什么这样比现在好看**：390 档页头从 4 行 + 2 条灰口径降到 3 行，且没有一句在自我复述；首屏多让出约 70px 给读数区。

### 3.6 把 `|` 分隔改成真版式（脚注 + 眉标）

- **改哪一个件的哪一条**：`packages/base-render/src/blocks.ts` 里两条 `> span + span { border-left: 1px solid rgba(210,210,215,.6) }`（caliber 区与 pageShell-eyebrow 区）：
  - 换成**间距 + 字色分层**（首段 `--fg2`、后段 `--fg3`），或每段前面给一个 12px 小标签字形；
  - 并且**换行后首项不画分隔**（现在 `flex-wrap:wrap` 下第二行开头那根线就是 `> span + span` 不管换行照画 —— 390 档 y≈2745 那根悬空线）；
  - 更彻底：把脚注改成三个带小标签的事实格，用 `renderKpiGrid` 的既有形状（`数据来源` / `时间` / `条数`）。
- **为什么这样比现在好看**：这是用户要求 5 **逐字点名**的那一类（`|` 代设计）。探针查的是字节，查不出 CSS 边框，所以这条只能靠人看、也只能在版式上治。

### 3.7 宽屏动作条给一条上限

- **改哪一个件的哪一条**：`.ilife-action-bar { max-width: 520px }` 后面那条 `@media (min-width: 641px) { .ilife-action-bar { max-width: none } }` —— 把它删掉（保留 520px），或给宽屏档一条 `max-width: 640px`（520 与 640 都是既有值）。
- **为什么这样比现在好看**：1280 档两颗 436×44 的按钮收成 2×约 310px，4 个字的标签不再孤零零悬在巨大胶囊正中；红钮那条同源，一起收。

### 3.8 近白面收敛 + `--fg3` 债一起还

- `blocks.ts` feedbackBlock 区的 `background: var(--soft)` 改 `var(--card)`，改由**左侧 3px 语义色条**（warn 用仓内既有 `#ff9500`，与 `kpi-card-bar-mid` 同源值）承担「这是警告」；
- `td::before` 与 `th` 的 `color: var(--fg3)` 改 `var(--fg2)`（`blocks.ts:1824` 已经在 `kpi-card-detail` 上这么改过，同一条判据、同一个理由）；
- 390 档明细表取消列头之后，`--fg3` 那 16 处的对比度债自然归零。
- **为什么这样比现在好看**：对应用户要求 6 与共用底 §5 第 5 条「整体发灰、显得脏」。这一页现在有 **5 种近白填充**（`--bg:#f5f5f7` / `--card:#ffffff` / `--soft:#f5f8ff` / `#fff5e0` / `#e6f7ec`）全挤在 3% 的亮度带里，最暗与最亮只差 3.9%；边界全靠 `--line:#d2d2d7` 的 1px 描边，读起来就是一片白。收敛到两种面之后，卡片才重新有「面」。

### 3.9 落地顺序（给收口席位）

1. 先做 3.1（本包 `template-expense.ts`，**只动一处**，390 收益最大）；
2. 再做 3.2（公共层三处，**32 张页会一起变**，这也是最该先统一的一条）；
3. 3.3 / 3.4 / 3.5 各是本包一处，可并行；
4. 3.6 / 3.7 / 3.8 是公共层，做完与第 2 步一起重出一批截图。

## 5 不许做的

1. **不为了好看牺牲信息**：账户与备注那两行现在是空的（D3），但**行要留**，改成打「未给」占位，不许删行；重复提示的 15 条一条不许少，只许从「全摊开」改成「3 条 + 展开收全」。
2. **不用 `；` / `·` / `|` 把字段串回来**。`duplicateNote.ts` 那 15 行现在用的是 `（）、：，` —— **换字符不算设计，换形状才算**（要求 5 的原意）。同理 D7 不许把 CSS 竖线换成文本 `|`。
3. **不写页面本地样式、不新造色值、不新造断点**。断点只许取 `400 / 640 / 820 / 1001 / 1200`；色值只许取仓内既有 token。
4. **不把已经修好的四类打回去**：来源脚注 `·` 串、眉标 `·`、H1 与徽章重复、层级值 `/`。注意 3.6 动的是「脚注分隔的**手法**」，不是把 `·` 请回来。
5. **主色 `--blue:#007aff` 不许改**；禁 `--r-xl` / `--pink`；深色区除 B-12 toast 外禁入。
6. **分隔符门不许弄红**：这一页现状节点级 0／行级 0，改完必须仍是 0。
7. **别把 3.1 与 3.2 拆成两轮**：读数卡收窄之后，「账户／账本／时间」的唯一落点是明细表 —— 如果明细表还带着「缺值不占位」（D3）和「值列吞 797px」（D2），收窄读数卡就变成了丢信息。

## 6 打分

## 7 本席的取证脚本（只读，未落盘任何文件）

两处测量都是**当场跑、只看输出、不写文件**：

1. 产物字节计数：`[regex]::Matches($c, 'data-label="哪一项"').Count` 一类，跑在 `Get-Content -Raw -Encoding UTF8` 的产物全文上。
