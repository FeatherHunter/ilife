## 2 缺陷清单

**证据**：

  - 手机 `分类` select 内部 `(300,795)` = **RGB(245,245,247)**

### 缺陷 3（高 · 本族共用）页面承诺「来源写在格子里」，4 处预填标注 3 处写在永不渲染的属性上，唯一渲染的那处是病句

**在哪**：字段卡里 `时间`／`账本`／`币种`／`账户` 四格。这一条的源头是页头下面那句 `预填标注：下面几格已经替你填上，来源写在格子里。`（桌面 y 354..364）。

**证据**（产物第 2213 行可直接 grep 的字节）：
- `<input class="…-input" name="time" value="2026-09-19 12:00:00" placeholder="已经替你填上 2026-09-19 12:00:00，缺省值" />` —— `value` 非空，`placeholder` **永不渲染**。
- `<input class="…-input" name="currency" value="人民币" placeholder="已经替你填上 人民币，来自记录编号 114" />` —— 同上。`来自记录编号 114` 这 9 个字在页上一个像素都没画出来。
- `<select … name="ledger"><option value="" disabled>已经替你填上 生活，来自记录编号 114</option><option value="生活" selected>生活</option></select>` —— 写标注的那一枚选项既 `disabled` 又没 `selected`，**永不显示**。
- `<input class="…-input" name="account" value="" placeholder="已经替你填上 ，缺省值" />` —— 四格里唯一真渲染出来的一处，也是一句读不通的话：`填上` 与 `，` 中间挂着一个空插值。手机 y 878 那一行的墨迹色实测 **RGB(117,117,117)**，桌面 y 866..877 同值。
- 病句怎么来的：`packages/skill-bill/src/write/prefillNote.ts:79` 是 `return hit === undefined ? undefined : '已经替你填上 ' + hit.value + '，' + hit.from;` —— 无条件下 `已经替你填上 X，` 这个壳；而账户的 `value` 按**该件自己第 33 行**的注释就是空串（「账户缺省是空串＝落库默认」）。括号里的附注随后被 `src/write/pageParts.ts:89` 的 `shorter()` 用 `/（[^）]*）/g` 抹掉，`缺省值（库里还没有可用的账户，留空＝落库默认）` 只剩 `缺省值`。
- 同一格三句话互相打架：空态卡内正文说 `账户这一格现在是空的。`，它的下句说 `账户为空就记到默认账户。`，而这一格自己的可见文字说 `已经替你填上 ，缺省值`。

**严重度**：高。
**归属**：本族共用（`prefillNote.ts` ＋ `pageParts.ts`）。实测同族的 `t410-页-记支出-采集页.html` 与 `t410-页-记一笔-采集页.html` 也各印 1 处 `已经替你填上 ，缺省值`。

## 3 设计方案：这一页该长成什么样

**总方向**：现在这一页是「三张空壳白卡 ＋ 七格裸文字 ＋ 一段被折叠藏起来的东西」。目标形态是**一眼看完的填空单**：上半页一张卡把「缺什么、怎么补、口令是什么」说完；下半页一张白底描边的表单，七格各自有形状；底部只留一条出口。

下面每条都写清「改哪一个件的哪一条」。

### 改动 1 段落标题换件：给「段头」一个能装子件的形状

- **改哪一个件**：`packages/base-render/src/blocks.ts` 的 `block-conclusion` 区（1500-1510 行）。
- **改哪一条**：新增一条 `.ilife-block-conclusion:has(> .ilife-block-conclusion-body)` 的两件套形态 —— 段号 `第 N 段` 降成 12px `--blue2` 的上标位、标题行 15px 保持，子件（段的真内容）进卡、占卡内第二段；没有子件时逐值不变（保住「桌面档不变」这条既有保证）。配套把 `padding` 从 `12px 16px` 提到 `14px 16px`、`row-gap: 8px`。
- **谁调用**：`packages/skill-bill/src/write/collectFrame.ts:33-37` 的 `collectSectionTitle` 改成 `renderSectionCard({ no, title, body })`；由 `template-expense.ts:171-173 / 191-199 / 200-213` 把原本紧跟其后的块（口径行 / 字段卡 / 复制区）当 `body` 传进去。
- **为什么比现在好看**（对应用户第 5 条）：现在是「一段话的标题和它的内容被切成两个不相干的形状」，读者得靠 21px 空白去猜从属关系——这正是第 5 条说的「用符号（这里是空白）简化了 UI 展示的设计」。改成段头装子件后，**分组由卡的边界给出**，第 1 段卡从「192px 标题 + 688px 空白」变成标题＋真内容，880px 宽不再是空壳。

### 改动 2 输入控件补回可见的「面」

- **改哪一个件**：`packages/base-render/src/blocks.ts` 的 `block-param-form-input`（2356-2367 行）。
- **改哪一条**：`background: var(--bg)` → `var(--card)`；`border: 0` → `1px solid var(--line)`；`:focus` 那条去掉「从 0 变 1px」的跳动（基态已经 1px）。`select`／`input` 同一条规则。
- **为什么**：现在七格内部采到 RGB(245,245,247)、与页底逐值相同，用户看不出哪里能点。改完是「白底 + `--line` 描边」，而这**正是同一页空态卡已有的语言**（`.ilife-empty`），表单与空态卡从此是一套「面」，不再是「一堆裸字」。一条规则治 32 页（对应第 3、6 条）。

### 改动 3 空态卡收成一条轻提示

- **改哪一个件**：`packages/base-render/src/style.ts:664-672` 的 `.ilife-empty`；文案侧改 `packages/skill-bill/src/write/emptyNote.ts` 与 `scene-income.ts:34-37`。
- **改哪一条**：`padding: 48px 20px` → `20px 16px`，并在 `@media (min-width: 1001px)` 里给 `14px 16px` ＋ `text-align: left`；`block-empty-block-title`（`blocks.ts:2387`）与 `emptyNote` 的 `text` **二选一**——只留标题，正文改成一句「这格先空着，落库时用默认账户」。
- **为什么**：桌面档 155px 里 113px 是空白，这一块占了一屏的 1/8；收成 ~64px 后它从「一块白板」变成「一条说明」，第 2 段跟着上移，首屏信息密度直接上来。宽屏不再居中也去掉了「空房间中央的一句话」那种观感（对应第 1、3 条）。

### 改动 4 预填标注回到看得见的地方

- **改哪一个件**：`packages/skill-bill/src/write/prefillNote.ts:77-80` 的 `prefillHint`；挂载点改 `src/write/photoEscape.ts` 的 `fieldCardOf`。

### 改动 6 两排胶囊分开形状

- **改哪一个件**：`packages/base-render/src/blocks.ts` 的 `block-chip` 区（1651-1674 行）加一枚 `.ilife-block-field-tags`；本包改 `collectFrame.ts:26-30` 的 `collectMissingTags` 去调它。
