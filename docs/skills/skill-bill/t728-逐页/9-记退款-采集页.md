## 3 设计方案：这一页该长成什么样

### 一句话立意

**把「八张空卡 ＋ 三枚琥珀段标 ＋ 两张不会读的表」改成一件事：一张「待补清单」，顶部一条进度，底部一条口令。**

现在这一页在视觉上是一堵墙（墙上有 7 个「没有」），改完它应该像一张**填了一半的单子**：已定的那一条最亮、缺的那三条最显眼、要抄的那句话在最下面等着。

### 改法 1（公共层 `blocks.ts` · 空态与有值分家）——对应缺陷 1、6

- 改哪一个件：`packages/base-render/src/blocks.ts:1804` 的 `.ilife-block-kpi-card-value`。
- 加一条 `-empty` 修饰（或按语义在 `renderKpiCard` 写类名）：空态走 `font-size: 15px; font-weight: 600; color: var(--fg3)`，并把值位换成一枚可数的小形状（例如 `3 / 8` 的细进度弧或 `待补` 胶囊）；**有值仍走 22px/700 `--fg`**。
- 为什么好看：22px/700 的黑字是这一页最贵的资源，现在 7 个被「没有」占了。腾出来之后，屏幕上唯一的大字就是 `退款 › 冲销`，以及页头那条进度 —— 视线第一跳落在「这笔已经定了什么」，第二跳落在「还差几项」。
- 顺带把 「金额／未给／还没给」 这种一格说两遍的写法收成一句。

### 改法 2（公共层 `blocks.ts` · 输入框给「面」）——对应缺陷 2

- 改哪一个件：`blocks.ts:2356` 的 `.ilife-block-param-form-input`。
- `border: 0; background: var(--bg)` → `border: 1px solid var(--line); background: var(--card)`；`:focus` 保留现在的蓝框不动；补 `::placeholder { color: var(--fg3) }`。
- 为什么好看：同页的读数卡本来就是白底 ＋ 1px 描边 ＋ 阴影（产物 1426–1434 行），输入框是唯一的例外。给它同一张「面」，表单立刻从「7 行灰字」变成「7 个等着填的格」，而且和第 1 段那个下拉（`<select>`）看起来是同一族控件。

### 改法 3（公共层 `pageUi.ts` · 窄屏表格换形状）——对应缺陷 3、13

- 改哪一个件：`packages/base-render/src/pageUi.ts:148-149`（`td::before { content: attr(data-label) }`）。
- ≤820 档不再逐格印列头。改成：**一张表只印一次列头（印在 caption 行里，用它现有的 `--fg3` 小字），行内改用 `flex` 版式出层级**——左位是第一列（等宽 13px `--fg2` 的编号），中位是第二列（15px `--fg`），右位由 `-cell-right` 那一列（等宽 `--fg`）贴右；常量列（这里 6 行全同的 `时间`）由本包声明「不逐行印」，提到 caption 里说一次。

### 改法 6（公共层 `blocks.ts` ＋ 本包 `template-flow.ts` · 段落标有形状）——对应缺陷 5、10

- 改哪一个件：新增 `block-step-head`；调用点 `template-flow.ts:300` 的 `flowSteps`。

- 为什么好看：现在三枚琥珀胶囊既不是「状态」也不像「标题」（它和顶部的 `还没写库` 是同一个形状），整页的章节层级全靠颜色在喊。换成序号圆点之后：颜色回到「状态」一件事上，序号回到「章节」这件事上 —— 这正是用户第 5 条要的「用版式出分隔，别用标点」。

### 改法 7（公共层 ＋ 全族 · 空态形状分工）——对应缺陷 1、11

- 改哪一个件：`blocks.ts` 的 `block-chip` 与 `ilife-status-badge` 一族。现在一页 **11 枚同形状胶囊**在承担 5 种语义（页面类型 / 行为规则 / 写库状态 / 缺哪几项 / 段号）。

### 改法 8（本包 `template-flow.ts` · 把「还差 N 项」做成进度形状）——对应缺陷 1、10

- 改哪一个件：`template-flow.ts:313`（subtitle）＋ `:299`（`collectMissingTags`）＋ `:191/199/240`（那四句文字）。

### 改法 9（本包 · 文案收口）——对应缺陷 8、9、11

- 改哪一个件：`template-flow.ts` 的 `first.caliber` / `first.pick` / `blockedFold`。
- 逐条：
  - `候选只列支出记录，每条附一句「为什么是它」。` → 把 `why`（`:188`）真的摆进候选（作为该行在窄屏的一行副文、在宽屏的第 5 列），**或者**删掉这半句。**不许一句都不做**（现在是承诺了没兑现）。

  - 缺项表三列 → 两列 `缺哪一项 / 怎么补`，补法写可执行的（`写正数，如 120`）；字段名统一成 `原支出编号`。
  - 复制区四处标题（`还缺什么，以及补齐后照抄的那条` / `口令原文（照上面那句跟助手说）` / `补齐后照这句跟助手说一遍` / `复制给助手：这一句可以直接复制`）统一成一个词，例如 `补齐口令`。

### 改法 10（公共层 `controls.ts` · 未选的下拉给占位项）——对应缺陷 4

- 改哪一个件：`renderParamForm` 的 select 分支。

- 为什么好看/对不对：这一条不只是好看 —— 现在屏幕上「未认准」和「#114」并存，是在**说两个不同的事实**。改完两端只剩一个事实。

### 改法 11（全族 · 分隔符纪律补一条门）——对应缺陷 5、14

- 改哪一个件：`packages/base-render/test/separator-probe.mjs` 的判据面。

### 优先级（给合成那一步用）

1. 改法 2（输入框的「面」）与改法 3（窄屏表格换形状）——**32 页全中，且都在公共层**，一次改动收益最大。

## 5 不许做的（自检）

- **事实一条都不许少**：本席列的所有改法都只动「给人看的那一面」。`bill-cmd-read bill.record.add --params '{"kind":"refund","category":"<分类>","amount":"<金额>","source_id":"<原支出编号>"}'` 这条口令、6 条候选的编号/金额/时间、`共 0 条`、`数据来源 记账库（只读）` 都逐字保留。
- **不把 `；`／`·`／`|` 用回来**：改法全部落在「用版式出层级」，且提出把门补上 U+3000（现在是门查不到而不是没用）。
- **不写页面本地样式**：11 条改法逐条标了落点（`blocks.ts` / `pageUi.ts` / `controls.ts` / `template-flow.ts` / `separator-probe.mjs`），**0 条落在页面本地**。
- **不越硬约束**：主色 `--blue:#007aff` 不动；未用 `--r-xl`／`--pink`；未在深色区加东西；断点只用 `400／640／820／1001`（改法 5 复用 641 那一档，不新造值）。
- **不弄丢手机端配方**：44px 触摸区（按钮/折叠条实测 44–45px）、安全区内距（x=16）、页码正文不贴边，全部保留。
- **不改已经修好的 4 类**：本页 `separator-probe` 行级/节点级 0 命中，本席没有任何改法会把它弄红。

## 6 评分

- `score_before` = **45**／100。理由：页头（眉标／H1／副题／分隔线）是干净的，两端都无溢出、无横向滚动，分隔符门绿，44px 触摸区齐；但**一屏里 7 个大字在说「没有」**、**8 个输入控件与页底逐值同色**、**手机端 79% 的一屏在重复 24 次列头**、**桌面 656px 的孤儿行和 436px 的空壳按钮**、**下拉框已选 `#114` 而三处文字说没预选**、**正文里在向第三人称交代「请用户…」**、**承诺了一列「为什么是它」却没这一列**。这些不是「不够高级」，是**指得出位置的丑**与**指得出位置的不通**。
- `score_after_proposal` = **91**／100。理由：11 条改法全部有明确落点，其中 4 条（2／3／4／5）是一次性公共层改动、收益覆盖 32 页；本页自己的病（空态、段标、冗余文案、未选下拉）各有一条对得上。不给更高，是因为：① 本席没动手，落地后还要两端重截复核；② 改法 8 里「把三处 `还差 3 项` 收成一条进度」会改变页高，要与回执页的对照墙一起复看；③ 改法 3 的窄屏形状一变，32 张页的手机墙要整体重出。
