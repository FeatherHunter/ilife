## 3 设计方案：这一页该长成什么样

这一页真正要用户做的只有两件事：**挑哪一条记录**、**改哪一格改成什么**。现在的块序把「缺什么」播报 4 遍、把「20 条记录」用两张视图印两遍，而唯一的必填控件在第 1.28 屏之外。方案按「改哪一个件的哪一条」逐条给。

### 3.1 把「查缺」从 5 张卡降成 5 行槽位清单

- **改哪一条**：`packages/base-render/src/blocks.ts` 的 `kpiCard` 区（第 1750–1830 行）——新增一族 `block-slot-rows`：`grid` 或 `flex` 纵列，每行 ≥44px（保住触摸/扫读高度），行内三段 `[槽位名 13px/600 --fg2] [层字形：未给 15px/600 --fg] [一句说明 12px --fg2]`，行与行用 `border-top: 1px solid var(--line)` 分隔（复用手上已有的分隔手法，不引入新 token、不引入新断点）。
- **本页改哪一处**：`src/write/template-update.ts` 里那 5 个 `kpiCard(...)` 调用换成 `slotRows(...)`，块位条数不变、数据一字不改。
- **为什么比现在好看**：现在 5 个槽位全空，却被排成 **5 个各 97px 的大白块**（合计 528px），眼睛要在 5 块一模一样的白里做 5 次无差别扫描，而且每块内部还是「金额／未给／还没给」三行说同一件事。改成一屏可扫的 5 行清单之后，「哪几格空着」一眼看完，页高从 528px 收到约 5×44 ＝ 220px（**省 308px，首屏直接多出 0.37 屏**）。对应**用户要求 5**：5 个并列项该由版式出结构，不是各给一个方块。

### 3.2 候选表：窄屏从「每格重印列头」改成「一条一卡」

- **改哪一条**：`packages/base-render/src/pageUi.ts` 第 2059–2096 行那一段（`…:has(td[data-label]) td::before { content: attr(data-label) }`），并**删掉 `blocks.ts` 第 1607–1624 行那份重复定义**（两处都在 `@media (max-width:640px)` 内、写的是同一条 `content: attr(data-label)`）。窄屏改成：
  - `thead` 继续 `display: none`（现在就是）；
  - `tr` 作条目卡（保留 `border-top`，**斑马纹从 `td` 挪到 `tr` 上**——现在 `blocks.ts` 第 1551–1553 行 `.…tbody tr:nth-child(even) td { background-color: var(--bg) }` 在窄屏把整条染成一块灰板，实测白 114px／灰 96px 两条不等高，看着像排版坏了）；
  - 只让**每条第 1 格**印一次「记录编号 114」作为卡头；
  - 其余 3 格排成一行（`display:flex; justify-content:space-between`）：`餐饮 改过` ／ `-20.00` ／ `09-14 19:00`。宽度账：390 − 32（安全区内距）− 20（格内距）＝ 338px，三段实测约占 26 ＋ 52 ＋ 40 ＝ 118px，放得下。
- **为什么比现在好看**：20 条从 **2134px 收到约 20 × 56 ＝ 1120px（省 1014px，整页短 27%）**，80 次列头复读一次不剩，斑马纹重新变成等高的条。对应**用户要求 2**（手机端适配参考 help html：help 的窄屏是「一格两行」，不是「每格把表头重印一遍」）。

### 3.3 把唯一的必填控件做成有形状的洞

- **改哪一条**：`packages/base-render/src/blocks.ts` 第 1833–1844 行 `.ilife-block-param-form-input`：`border: 0` → `border: 1px solid var(--line)`，`background: var(--bg)` → `background: var(--card)`（两枚都是既有 token）。第 1830 行的必填星号 `#c0392b` 换成与状态徽章同一支红（`#a83228` 或提成 token），全页只留一个红。
- **为什么比现在好看**：全页唯一「要你动手」的东西现在与页面底色逐字节相同、零边界，用户扫过去只看见两个孤零零的字 `#114` 和一颗原生箭头。给上 1px `--line` 边＋白底之后，它在灰底上是一个明确的「洞」——1.28 屏之后终于有一个「这里要你填」的信号。

### 3.4 页头把「缺几项」收成一处，删掉错位的孤立 chip

- **改哪一条**：`src/write/template-update.ts` 的 chip 行 ＋ `src/write/blockedSlots.ts`。
  - chip 行现在 3 枚（`挑一条记录`／`方向按金额符号判`／`先挑一条记录`），合并成 1 枚状态徽章：`缺 1 项：记录编号`——把「缺几项」与「缺哪一项」两件事并成一句，同时吃掉 D9 里那枚重复的 `挑一条记录`。
  - 删掉 `第 1 段` 条带下面那枚孤立 chip `记录编号`（D7）；「缺的是记录编号」这条事实由 3.4 的那枚徽章承担，一条不少。
- **为什么比现在好看**：顶部现在是 3 枚药丸平铺、下面又挂一枚孤零零的，看起来像标签没地方放；合成一枚之后页头回到「眉标／标题／副题／一枚状态」四级干净层级，而且**第一眼就告诉人缺的是哪一项**（现在那枚 chip 反而落在条带下面，与它要说明的那组卡语义错位）。

### 3.5 `第 1 段`／`第 2 段` 条带从「卡」降成「标题行」

- **改哪一条**：`packages/base-render/src/blocks.ts` 第 1500–1510 行 `block-conclusion`（`renderConclusionBar`）。现在它是 46px 高的白卡片 ＋ 3px 蓝左条，1280 档里文字只占 x=218..约 400，**x=400..1079 共 679px＝77% 是空白的**。给它一条「无子元素时走标题行」的档：`border-left` 收 0、`background: transparent`、`padding: 4px 0`、下距 8px——即**章节标题**而不是**结论条**。（这条要落在公共层，因为它由 `renderConclusionBar` 产出、全仓都在用；保守做法是本页改用已有的 `block-detail-section` 标题形态，不动公共层。）
- **为什么比现在好看**：46px 白条里塞 12 个字，读者先把它当一张卡、再发现里面是空的——这是「假卡」。降成标题行之后「第 1 段 先看这一笔缺什么」读起来是分组标题，页高还省 46×2 ＝ 92px。

### 3.6 把折错了地方的那块搬回第 1 段

- **改哪一条**：`src/write/template-update.ts` 的块序 —— 把 `<details>还缺什么，以及补齐后照抄的那条</details>` 从 `第 2 段 先挑一条记录` 底下**搬到 `第 1 段 先看这一笔缺什么` 底下**，并**默认展开**（`<details open>`）。
- **为什么比现在好看**：现在标题说「先挑一条记录」，紧跟的第一块却在讲「还缺什么」；而这一页唯一能真正推进事情的（口令原文 ＋ `⛔ 先补齐（1 项）`）被折起来，下面 2134px 的 20 条重复行却全展开——层级整个反了。搬过去之后第 1 段＝「缺什么＋怎么办」，第 2 段＝「挑哪一条＋改什么」，跟标题逐字对上。

### 3.7 三条口径行改写成「给人看的一行」，并合成键值行

- **改哪一条**：`src/write/recordPicker.ts` ＋ `src/write/template-update.ts`，走已有的键值行／事实条形状（不新造类名家族）：
  - 第 3 句 `库里共 120 条未撤销的记录，本页列最近 20 条（按时间倒序）。` → 两格键值行：`能改的记录　20 条` ／ `库里未撤销　120 条`（一行两格，数字进值位）。
  - 第 2 句 `候选未预选（不给默认选中）：请用户从列表里指明是哪一条，再跟助手说一遍。` → 换成对用户说的 `默认不替你选，请自己挑一条`。**事实（没预选）一字不少，只把主语从助手换成用户**——这一页是给用户看的。
  - 第 1 句 `以下 20 条候选依据相同：还没撤销过 可以改。` → `这 20 条都还没撤销过`。
- **为什么比现在好看**：三行同字号同灰度的说明文堆在一起像脚注，读的时候分不出哪句是「数」哪句是「理由」；两条键值行 ＋ 一行口径之后，条数变成可看的数，理由变成一句人话。对应**用户要求 4**（文字不能冗余和不合理）与**要求 5**（并列信息用版式出层级）。

### 3.8 页脚那一格补上限定语

- **改哪一条**：`src/write/sourceNote.ts` 第 40–41 行 `collectSourceNote` 的交法与 `src/shared/sourceLine.ts` 第 60 行：把 `共 0 条` 那一格说成 `本次写入 0 条`。
- **为什么比现在好看**：同页出现 `共 20 条`（候选）、`共 120 条`（库）、`共 0 条`（页脚）三个数，只有第三个没有限定语，读者会以为库里是空的。**值一个数字都不动**（`collectSourceNote` 的 0 是「本次改动笔数」，源码注释已写明），只补限定语；`data-t` 复制载荷里不含这一句，复制载荷逐字节不变。
- **注意**：这一条改的是可见文案，事实与载荷都不变，但**要维护者在合票时点头**。

### 3.9 页尾复制区收成一条动作条，宽度由标签定

- **改哪一条**：`packages/base-render/src/blocks.ts` 的 `copy-btn`／`action-row` 区。
  - `复制给助手：这一句可以直接复制` → `复制这句口令`（4 字，落进 210px 以内）；
  - `复制数据 ▾` 与 `复制日志` 不再平分版心：加一条 `@media (min-width: 1001px) { .ilife-page-ui .ilife-action-row .ilife-copy-btn { flex: 0 0 auto; } }`（用既有 1001 档，不新造断点）。
- **为什么比现在好看**：880px 里摆两个 436px 的胶囊装 4 个汉字，读起来像两个空占位；收到标签宽之后页尾是「一句口令 ＋ 三个等高的复制动作」，密度与页头一致，也不再出现同一族按钮 210/436/436 三种宽度。

### 3.10 红色收成一支

- **改哪一条**：`blocks.ts` 的 status-badge／error／op-head／param-form-required 四处，把 `#a83228`／`#c0392b`／`#ff3b30` 收成一支（建议以现有的 `#a83228` 为准，另两支删），橙同理（`#a25b00` 与 `#b25000` 留一支）。不新增 token、不动 `--blue`。

## 5 不许做的（这一页实施时的红线）

1. **事实一条不许少**：20 条记录、4 个字段、5 个槽位、`还缺哪一项／是什么／为什么写不进去` 三列、页脚三个数——一条都不能删（3.4／3.7／3.8 都只改框法与主语，不删事实）。
2. **`；`／`·`／`|` 不许用回来**：`node packages/base-render/test/separator-probe.mjs <产物>` 节点级与行级必须仍是 **0／0**（现在是 0／0，别弄红）。`餐饮　改过`（U+3000）也不许拿它当分隔——那条要么走版式、要么落进 `block-row-marker` 那种已有形状。
3. **不许写页面本地样式**：本页不许出现 `<style>`、不许写色值、不许写断点；断点只许取 `400／640／820／1001／1200`（顺手把 `blocks.ts` 第 1776 行那个 `1024` 收进闭集，见 D3）。
4. **不许改主色**：`--blue:#007aff` 不动；禁 `--r-xl`／`--pink`；深色区除 B-12 toast 外不进。
5. **别把已修的弄回去**：来源脚注 `·` 串、眉标 `·`、H1 与徽章重复、层级值 `/`——本页现在是干净的（分隔符门 0／0 为证），改版式时别顺手把 `·` 加回来。
6. **手机端不许丢**：触摸目标 ≥44px（现在两枚复制按钮 44px、下拉框 44px，别收小）、安全区内距、正文不贴边。
7. **32 页共用一张样式表**：任何一条改公共层的规则，出改动集时必须**一次改全 32 页并一起复验**（含回执页），不能只让这一页好看。

## 6 打分

- **`score_before` ＝ 41／100**。给这个数的理由（都是能指认位置的数）：维护者点名「非常的丑陋」的那条缺陷（窄屏逐行重印表头）在本页是 **80 次**，是回执页 16 次的 5 倍；全页唯一可操作的控件（必填下拉框）**与页面底色逐字节相同**、零边界；桌面档把 5 张卡排成 4＋1，右段 639×99px 全空；手机档 5 张卡吃掉首屏 62.6%，第一个可点的东西在 1.28 屏之外；页脚 `共 0 条` 与同页 `共 20 条`／`共 120 条` 三数并列、只有它没有限定语。这不是「整体不够高级」，是五处能指到像素位置的具体破损。
