## 3 设计方案：这一页该长成什么样

**一句话**：这一页现在是一份**写给维护者看的执行回执**，不是一张**给用户填的表**。它把「还没写库、缺 2 项」用四套形状说了 14 遍，把要填的三格三格全塞在首屏折线以下，而三格的底色和页底同一个色。改的方向是**把状态压成一处形状、把表单提到首屏、让每一个「空」都有边界**。

改法按层分，每条都写清「改哪一个件的哪一条」。

### 3.1 公共层 `packages/base-render/src/blocks.ts`（32 页同时受益）

- **B1｜给要填的格子一条边界。** 改 `.ilife-block-param-form-input`：`border: 0; background: var(--bg)` → `border: 1px solid var(--line); background: var(--card)`；`:focus` 那条把 `background` 从 `--card` 改回来时不必再动。
  *为什么比现在好看*：现在框内与框外实测**同一个 `#f5f5f7`**（D-3），要填的格子比只读的白卡更「没有实体」；一条 1px 的 `--line` ＋ 白底让「能填的东西」和「读的东西」用同一种视觉语言，也对上用户第 6 条「触摸目标要看得出来」。
  （零字面色值：`--line`／`--card`／`--bg` 都是既有 token，不新增色值。）
- **B2｜「空」只许有一种灰。** 新增 `.ilife-block-param-form-input::placeholder { color: var(--fg3) }`，并给 select 的空态一条同级规则 `.ilife-block-param-form-input:has(option[value=""]:checked) { color: var(--fg3) }`。
  *为什么*：现在全件 `::placeholder` 规则 **0 条**，输入框走浏览器默认 `#757575`，而 select 用真 `<option>` 冒充提示、渲染成 `#1d1d1f`（D-9）——**分类那格的空态看起来已经填好了**。`:has()` 在本仓已经在用（`pageUi.ts` 的表格卡片化就是 `:has(td[data-label])`），不新造机制。
- **B3｜把「怎么给」从控件里搬出来。** 新增 `.ilife-block-param-form-hint`（控件正下方一行 12px `--fg2`），`renderParamForm` 把 `hint` 渲染到这里而不是只塞 `placeholder`／空 `<option>`。
  *为什么*：`支出为负、收入为正` 是**口径**不是例子，placeholder 一输入就消失；搬出来之后 select 也不必再拿一枚 option 冒充提示（B2 就只剩兜底）。
- **B4｜节标题不再是一张满宽空卡。** 给 `.ilife-block-conclusion` 加 `@media (min-width:1001px){ width: fit-content; min-width: 260px; }`。
  *为什么*：现在 879px 宽的白卡里只有 134px 的字，三张卡各 46px 高（D-7）——85% 的空白在替三个字撑场面。
- **B5｜两枚按钮不许同权。** `.ilife-action-row` 在 ≥1001 档按钮 `flex: 0 0 auto`（现在被拉成两枚各 434px，每枚 87% 空白），并让 `复制数据` 取 `copy-btn-primary`、`复制日志` 退成次要按钮或一行注脚。
  *为什么*：`复制日志` 是排障口，和用户唯一要用的 `复制数据` 同宽同高同色，等于把「选哪个」这件事推给用户（D-4 后半）。
- **B6｜页脚退到底层。** 给来源脚注那一处（`collectSourceNote` 的输出）一个「脚注」位：上边距 ≥24px（或一条极细分隔线），字号仍 12px、颜色仍 `--fg2`（**不降到 `--fg3`**，共用底 §5 第 5 条已经判过 `--fg3` 压 `--bg` 发灰）。
  *为什么*：现在页脚距按钮行 22px、同 12px 灰字，读起来是按钮行的一部分。

### 3.2 公共层 `packages/base-render/src/pageUi.ts`

- **P1｜三格表单不许留半格空洞（D-4）。** 给「带 `options` 的那一格」一个修饰类（`renderParamForm` 在 `blocks.ts` 侧加 `.ilife-block-param-form-field-select`），⑪ 那条里补 `grid-row: span 2`；其余格保持自动流。
  *效果*：三格 ⇒ 左列「金额」「时间」两格、右列「分类」一格跨两行，**零空洞**；而且「分类」拿到了它真正需要的高度——它的候选有 10 项，现在挤在一枚 44px 高的 select 里。
  *替代方案（更保守）*：`.ilife-block-param-form-field:last-child:nth-child(odd){ grid-column: 1/-1 }`，最后一格跨两列——至少不留半格。
  两条都只用既有断点 `1001`，不新增断点。

### 3.3 本包（`packages/skill-bill/src/write/`、`src/shared/`）

- **S1｜段号不上屏（D-7）。** 改 `collectFrame.ts:33-37` 的 `collectSectionTitle`：不再拼 `'第 ' + no + ' 段 ' + title`，`no` 改成画在左竖线上一枚序号字形（或干脆不画），标题只留中文。同时 `第 3 段 补齐了再请助手记` 这一节的**标题要与内容对齐**（内容是复制区，标题就该是「这几句可以直接复制」）。

### 3.4 创意：把「三要素」做成一张**三格账单卡**（替代 S2 的胶囊行，我更推荐这一条）

在 S2 的基础上再往前一步：**三枚胶囊升级成一张卡上的三格**——

- 每格上边写槽位名（金额／分类／时间），下边写状态（`还没填` 或真值）；
- 未填的格：虚线边框 ＋ `--fg3` 字；已填的格：实线边框 ＋ `--fg1` 字；
- 卡右上角一枚进度徽章 `0 / 3`；
- 点一格滚到对应输入格（同页锚点，不需要新机制）。

*为什么这样比现在好看（对应六条）*：
① 用户一眼看出「3 格里亮了 0 格」——这正是「补齐这 2 项就能记进账本」那句话的可视化，对上第 5 条「展示的信息要生动形象」；
② 它**替代**那张三行表，而表里的每个事实都还在（哪三样、各是什么状态）；
③ 现在是「三行 × 两线 ＝ 六线，每线前头挂一句列头」，读者要竖着读才读对一个配对（D-5）；三格卡是横着一眼读完，**形状本身就在说「三样要凑齐」**；
④ 它同时是表单的锚，把首屏的状态与第二屏的表单连成一条线。

*另一条创意（对应 D-10 的首屏空洞）*：**首屏补一枚明确的岔路。** 这一页的场景是「一张图都没交上来」，但页上没有任何一句告诉用户图该交到哪、也没有出口（产物里 `type="file"` 计数 = 0，这是本仓的既有口径：「本仓不做上传控件」）。既然不做上传，那至少要在状态条旁边给两枚明确的下一步：`去助手那边交图` 与 `直接手填下面三格`——而不是把「走三要素文字填空」埋在一段灰字的第二句里。改完首屏就有可点的东西（现在首屏唯一可点的是排障折叠的把手）。
