## 3 设计方案：这一页该长成什么样

### 3.0 先说这一页是什么

它是一张**回执**（`data-status: ok`、`shape: receipt`）。回执的第一读物是「**多少钱、进到哪、能不能反悔**」，不是一块 8 格仪表盘。现在的页子把「凭证」做成了「看板」：8 张等权读数卡 ＋ 一个 380px 的文字墙 ＋ 一张 490px 的表 ＋ 一条 876px 的红条，**没有主角，也没有一件事是靠版式说的**。

设计目标：**一张「已入账」凭证** —— 抬头一行、金额一格、事实一条、动作一排；需要核对的细节收到一处，默认不展开的东西不占首屏。

块序只能改一处：`packages/skill-bill/src/write/template-expense.ts` 的 `receiptPage()`（第 230–295 行）的 `blocks` 数组。**不许动场景件**（`check-scene-shape.mjs` 判据乙的乙-2／乙-3 会红），文案差异仍由 `scene-reimburse.ts` 给值。

### 3.1 抬头：三行小字 ＋ 两行胶囊 → 一行抬头 ＋ 一条段控

- **改哪一个件的哪一条**：
  1. 副题不再倒引擎串。`write.ts:177` 那句 `已记录：${category} ${amount}（${唤醒词}）（记录编号 ${id}，这一页可以复制）` 是 envelope 的 message 原文，**改由 `template-expense.ts` 的回执支路拼一句人话**：「出行 -100.00，已写进「生活」账本」。`（记报销）` 与 H1 逐字重复、`（记录编号 121，这一页可以复制）` 下面就是复制按钮，两截删掉。
  2. 删掉 `scene-reimburse.ts:56` 的 `receiptNext`（「这一笔已记下，撤销见下方按钮。」）—— 它说的那件事，下方按钮自己会说，而且它现在说的是 1500px 之外的东西。
  3. `typeBadge.ts:61` 的「分类按三级挂靠」是型认不出时的**兜底口径**，它不上抬头，下沉到明细表脚注。
  4. `nav.ilife-block-toc` 四枚在 390 档实测只占 `x=16..247`（右边空 127px），改成贴视口顶的**横滑段控**（复用公共层 `pageUi.ts` ⑥ 已经在写的 `flex-wrap:nowrap; overflow-x:auto`，只是加 `position:sticky`）。
- **为什么好看**：390 首屏现在被「眉标＋H1＋两行副题＋3 枚胶囊＋一行口径＋4 枚胶囊」占掉 `y=24..266`（242px），金额卡要到 y=389 才出现。收成「抬头 2 行 ＋ 段控 1 行」后首屏能多放两格读数。对应要求 3（像设计师做的版）与要求 4（去冗余）。

### 3.2 读数：8 张等权卡 → 1 张金额主卡 ＋ 1 条事实带 ＋ 1 条状态行

- **改哪一个件的哪一条**：`template-expense.ts:253-257` 那条 `renderKpiGrid([...facts, receiptStatusCard(...), ...tailCardsOf(...)])`；值的口径分别住 `summaryRow.ts:78-93`、`receiptParts.ts:24-29`、`pageParts.ts:101-121`。三处**只改组合与档位，不改值的出处**。
- **形态**：
  - **金额单独一格**：值走 34px 档（现 22px），侧别与方向取 `summaryRow.ts:56-61` 的既有取值（支出负号、侧别色用既有语义色），一格就是全页唯一的视觉重心。
  - **分类／账户／账本／时间 4 格合成一条紧凑事实带**：每格 `12px 标签 + 15px/600 值`，用 1px 分隔线而不是卡片边框 —— 四格从 4×98px＝392px 收到约 2×56px＝112px。
  - **状态／记了几笔／写进去的项 3 格收成一条状态行**：状态做成一枚 `ilife-status-badge`，两个计数做成一枚 `ilife-block-chip`（现成的胶囊组件），**不再各占一张 98px 的卡**。
- **为什么好看**：390 档 853px（32.4% 页高）压到约 240px，页高从 2629px 落到约 2000px；主次靠**尺寸差**（34/22/15）而不是靠颜色；信息一条不少，「-100.00」第一次成为页面的第一读物。对应要求 3。
- **同时治 N2 的根**：删掉公共层 `pageUi.ts` ⑦ 的 `@media (max-width:400px)` 单列（或把阈值改到仓内既有的 **360 之外不取**——即整条删掉），让 ⑥ 的「两格并排」在 390 档真的生效。这条是**要求 2「手机端适配参考 help html」**的直接对应：HELP 的 640 档单列是有意的，而这里两条规则互相抵消，结果 390 档永远走最差的那一支。
- **顺带治 N4**：`summaryRow.ts:89` 的 `不填就记到默认账户` 是**填写前**的条件句，回执页不该有。改法二选一 —— ① 把 `scene-reimburse.ts:63` 的 `dropDefaultHints` 改 `true`（这一格一改其实挺干净：它只作用本页；`scene-expense.ts:48` 是另一件、另一页，不受影响）；② 更准：`summaryCards` 的说明只在**值未给**时出，且那句改成回执口径「库里没这一格，落在默认账户」。账户值缺时一律写 `—`（对齐 `sourceNote.ts:25-26` 的既有口径）。

### 3.3 明细：窄屏「键值行」，宽屏「两列对开」

- **改哪一个件的哪一条**：
  1. `packages/base-render/src/pageUi.ts` ⑥ 里 `td::before{content:attr(data-label)}` 那一族选择器（产物 CSS 2087–2093 行）—— **窄屏不再印列头文本**。键名本身就是层级，不需要再印一遍「哪一项／记成什么」；改成「一条键值行：键 `--fg2` 左、值 `--fg` 加粗右」，行高 44px（同时满足触摸区）。
  2. `packages/base-render/src/blocks.ts` 的 data-table：`≥820` 档把这 8 行排成**两列对开**（一行放两组键值），让 880px 被列数吃掉；`≥641` 档那条 `width:1%` 保留（列宽不该由最长键名决定，而该由版式决定）。
  3. `packages/skill-bill/src/write/write.ts:70-81` 的 `rowDetail`：账户／备注为空时给 `—`，不给空串。
  4. 计数一致：`rowDetail` 的「记录编号」不是 `ADD_FIELDS` 里那 7 项之一 —— 要么把它拿出去（编号进副题或脚注），要么把 caption 从「写进去的项与值」改成「这一条现在的值」。**改一处即可让 7 与 8 自洽**。
- **为什么好看**：390 档表体从 **490px** 收到约 **200px**，且每一行变成「键左值右」的一条干净键值行；1280 档从「每行 75%–95% 是白」变成四格真排开。用户第 5 条的原话就是「该用这些符号简化 UI 展示的设计」——现在的做法正相反：**该由版式出的层级，被 16 行重复文字顶替了**。

### 3.4 重复提示：文字墙 → 等宽清单

- **改哪一个件的哪一条**：`packages/skill-bill/src/write/duplicateNote.ts:87-118` 的 `lines` 那一段（`hits.map(h => '记录编号 …（…）：…，…，账户…')` 拼成长句数组）。
- **形态**：结论一行说在标题里（「同一天同金额同分类，已经有 7 笔」——数字一个不改），下面出一张**等宽清单**：编号一列（右对齐、`tabular-nums`）、时刻一列、账户一列；**金额与分类不再逐条复述**（7 条同额同分类，复述 7 遍 `-100.00`／`出行` 是纯噪声，而且是这页 16 个「出行」里的一大半）。条目多时（>3）折进一个 `details`，默认只露前 3 条。
- **为什么好看**：390 档从 **380px** 收到约 **190px**；重复信息用**对齐**表达（等宽列就是版式出的层级），不再用「，」串长句，也不再从词中间折断「出行」。对应要求 4 与要求 5。

### 3.5 动作区：一颗真按钮 ＋ 两颗次按钮；红的不再满列

- **改哪一个件的哪一条**：`packages/skill-bill/src/shared/copyArea.ts:156-161` 的 `undoExit()`（把 `EXIT_MARK_ACTION` 那枚改成**真动作**：给它 `data-t` = 撤销指令，点了就走既有的 `copy()` 通道），加产物 CSS 1980–1986 行那条本包补丁（按选择器归属判：它选中 `.ilife-block-copy-block:has([data-action-id="ilife-exit-undo"])`，而 `ilife-exit-undo` 只由本包产出 ⇒ 这条留本包，删掉 `grid-template-columns:1fr` 与 `width:100%`）。
- **形态**：三颗并排成一组，「撤销这一笔」做实现（填充、危险色）、「复制数据」「复制日志」做描边（既有 `ilife-copy-btn-ghost`）；`h2「想反悔（撤销这一笔）」`删掉（与按钮文案重复），`EXIT_NOTE` 里「点下面那颗「复制数据」」这半句删掉（它否定上面的按钮）。
- **为什么好看**：现状 1280 档是一条 **876×44** 的满列实心红 —— 成功页上最亮最大的一块，却什么都不做；**版式重量与语义重量反了**。降级成三颗同高同级之后，页面的色彩重心回到内容本身；同时 N1 那个「点了没反应的死按钮」一并消失。对应要求 4 与要求 6（用户要求「视觉上仔细审查，找到不合理之处」）—— 这是这一页最不能留着的一条。

### 3.6 去冗余：对账折叠并进脚注，导航 4 枚 → 3 枚

- **改哪一个件的哪一条**：删掉 `packages/skill-bill/src/write/receiptParts.ts:35-45` 的 `reconcileDisclosure` 整块（或留件不留块），`template-expense.ts:265` 去掉那个 `navBlock`，`template-expense.ts:281` 的 `receiptSourceNote` 扩成「来源／时间／条数／记录编号／写入时间」五段 —— 版式**沿用既有 `sourceLine`／`blocks.ts` 的 `.ilife-block-caliber:has(>span)` 那条**（flex 行 ＋ 相邻 `<span>` 之间的 1px `border-left`），**不加任何标点当分隔符**。
- **为什么好看**：现在「对账」这枚导航指到一个 **45px 高的闭合白条**（390 档 `y=2253..2298`），用户点进去什么都看不到，而它那两行与页副题、页脚三处重复。并进脚注后，导航从「读数／明细／对账／复制」收成「读数／明细／复制」三枚，页内不再有指向空壳的链接。对应要求 4。

### 3.7 去灰：两个状态词回到文档里，两处灰阶抬到合格档（公共层小改，全族受益）

1. `packages/base-render/src/pageUi.ts` ⑩：现在「已完成／注意／未通过／提示」四词由 CSS `content` 生成（body 里 `已完成` 0 次、`注意` 0 次）⇒ 不可选中/搜索/朗读。改由模板出真文字（给 `blocks.ts` 的 feedback-block 增加一个 `iconText` 入参，`pageUi.ts` ⑩ 退回只做尺寸），治 N8。
2. `blocks.ts` 的 `.…-note-icon-ok` 前景由 `#1f8c3d` 调一档到合格（现 **3.871:1**；同页 `-warn` 的那枚是 4.808:1，同形不同标准），治 N11。
3. `blocks.ts` data-table 的 `th` 与 `pageUi.ts` ⑥ 的 `td::before` 色由 `--fg3` 改指 `--fg2`：**3.623:1 → 5.071:1**，压在斑马行上 3.327:1 → 4.664:1。**不新增色值、不改 `--blue`**，只用仓内既有 token，治 K3。
4. `blocks.ts` 的 `.ilife-block-feedback-block-note` 底色：`--soft #f5f8ff` 对页底 `--bg #f5f5f7` 实测 Δ=(0,3,8)、对比度 **1.024:1**（像素验证：390 档 y=320 横扫 → `(245,245,247)` 到 `(245,248,255)`，只有蓝通道差 8）⇒ 消息卡读成「一个洞」不是「一张卡」。改走 `.ilife-block-conclusion` 已经在用的手法（白底 ＋ 左侧 3px 语义色条）。
