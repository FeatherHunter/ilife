## 一 病与根因（诊断结论）

列表查询页族 9 张页在桌面档（>820px）下，`#list` 是两列栅格，**空态卡只占左半列**，右半屏整片空白。

根子不在栅格、在类名：#870 把页面壳从老公共层的 `hm-*` 类名切到 `base-render` 的 `ilife-*` 类名时，
模板里那条「空态卡跨满两列」的规则漏改——

- 产出侧 `src/render/memoPageAssets.ts:149-157`（`window.emptyState`）吐 `class="ilife-empty"`；
- 消费侧 `templates/memo_query.html` 写的是 `#list .hm-empty{grid-column:1/-1}`；
- 选择器对不上 ⇒ 规则空转 ⇒ 空卡落进两列栅格的第一列。

**判定它是新仓迁移缺陷而非老技能遗留**：老公共层 `SKILLS\公共组件\assets\base.js:608-616` 的 `emptyState()`
吐的正是 `hm-empty`（样式住同目录 `base.css:231-244`），老模板那两条规则与老公共层同名同字，老技能下本来是活的。

**补充判据（排除的候选）**：① 不是 `ilife-empty` 缺样式——页内 `.ilife-empty` 一族五条全在；
② 不是模板没注入 `sharedCssText`（`ilife-empty` 的样式就在注入产物里）；③ 不是 390 档断言口径漏（该档本就单列，物理上看不见）。

```
产出侧  src/render/memoPageAssets.ts（window.emptyState）──→  class="ilife-empty"
消费侧  templates/memo_query.html                        ──→  #list .hm-empty{grid-column:1/-1}
                                                              ↑ 选择器对不上 ⇒ 规则空转
```

**不改渲染件**：`ilife-empty` 是公共层冻结契约的类名（`renderEmptyState` ＋ `buildStyleSheet()` 的 `emptyState` 区），
改渲染件等于自造第二处类名定义。
