## §三 `dupFacts` 改判的两页：页内导航链接与章节标题同串

`首次使用` 静态候选 3 组、`首次使用-向导` 静态候选 2 组，逐组核对渲染后的 DOM：

| 页 | 串 | 两处在哪儿 |
|---|---|---|
| 首次使用 | 待处理项 | `<nav class="ilife-block-toc"><a href="#sec-pending">` ＋ `<h2 id="sec-pending">` |
| 首次使用 | 待办指引 | 同上（`#sec-todo`） |
| 首次使用 | 验证清单 | 同上（`#sec-verify`） |
| 首次使用-向导 | 待办指引 | 同上（`#sec-todo`） |
| 首次使用-向导 | 验证清单 | 同上（`#sec-verify`） |

判 **0**（改判）的理由：这是**页内导航的两端**（跳转锚与落点标题），不是「同一事实在一页说两遍」。旁证两条：
① 判分引擎的 `toc` 腿反以此为**正面项**（#832 记：sync 域缺页内目录时 D5 由 25 掉到 16，补回后回 25）；
② 同一结构在另 8 页列表页上也是 `tocEl=1`，静态候选同样读不到它们（`<nav>` 里的锚文字被 `<a>` 包着，仍属可见文本）。
