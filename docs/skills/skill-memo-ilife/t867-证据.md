## §六 硬缺口：静态面 ≠ 载荷渲染面（本票翻出来的一条，读数可复现）

**现象**：备忘录的产物页把内容放在页内 `<script id="payload" type="application/json">` 里、由页内脚本渲染；四件读数里靠静态读的那部分（`sep.json` 的可见文本、`facts.json` 的 DOM 六列与两列机器候选）先剥掉 `<script>` 整段，于是**看不到脚本渲染出来的文字**。

**复现（本仓现场，可重跑）**：

```powershell
# ① 静态面：这一页在渲染后有点号并列、有半角逗号、有重复串，静态候选却是 0
node docs/skills/skill-memo-ilife/t867-dom-probe.mjs --dir docs/skills/skill-memo-ilife/t867-夹具-页群 --quiet
#    实测：同步报告 候选 dupFacts=0 english=0（sep.json 也只有 L342 那一处 R1）
# ② 渲染面：同一页的标题、四块指标卡明细、错误明细都由脚本渲染（行号即出处）
#    L418／L424 渲染 '同步完成 · 1 个错误'（点号并列）；L419 与 L458 渲染的串用半角逗号；
#    L374 渲染出来的两个复制按钮与静态 L344／L345 那两个同名
```

**这条缺口值多少**：`同步报告` 的 H1 少算 1 处（渲染出来的 `·` 没进 `sep.json`）、H7 少算 2 处、H3 少算 3 处 —— 本票把它**写在人核档的取值里**（`出处=渲染后 …`，判「改判」并写理由），但**机器读数面本身没治**：三件 reader 的语义按票面「一行语义不动」，本票不改它们。

**建议去向**（本票不自行开票，按 `docs/agents/编排纪律.md`「遗留当场开票」的三问先摆事实）：能复现（上面两条命令）；有归属（这份链的读面归 [#869](https://github.com/FeatherHunter/ilife/issues/869) 六列机审与 [#868](https://github.com/FeatherHunter/ilife/issues/868) 引擎的读数目录，但「静态 vs 渲染」是四件共同的前提，落在谁身上要由地图定）；是已承诺的目标吗（八张域票与 [#834](https://github.com/FeatherHunter/ilife/issues/834) 收口都要用这两门判据，读面缺一半会直接影响判分）。
