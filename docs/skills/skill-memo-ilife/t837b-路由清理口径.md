# #837b · 路由表清理四问：口径（#858 落盘）

**这份是什么**：裁定票 [#842](https://github.com/FeatherHunter/ilife/issues/842) 四条结论的**实施口径**
（四条全部按推荐 A 拍板），由实施规格 [#858](https://github.com/FeatherHunter/ilife/issues/858) 落盘。
**代码守架构、文档守第一性**：这份只写「结论是什么、依据在哪、净变化多少」，不重述实现细节
（实现与读数见同目录 `t858-实施-证据.md`）。

## 一 · 四条结论

### ① `飞书授权`：词退役，命令键保留只读诊断两档

- **结论**：判据原文「HELP HTML 中都没有的 我们不开发。**除非老技能也有**」里的「也有」按**词／场景**读——
  老技能完整命令面里**没有 `auth` 这个子命令**，授权只是 `scripts/feishu_auth_helper.py` 一件辅助件；
  HELP 的 30 个场景里也没有授权场景（授权是「首次使用」场景流程里的一步）。
  故：**唤醒词退役**，`memo.auth` **键保留**（`status` 授权状态 ／ `diag` 任务域自检，两档**只读**、
  显式才跑、默认零写）；三支引导（`init`／`qr`／`poll`）退役，报错**统一指去同一段飞书安装指引**。
- **依据（现场，本票复跑）**：`test/route-cleanup-858.test.mjs` ⑤——`routeWakeword('飞书授权')` 抛
  `POLICY_NO_MATCH`；`step:"status"` 与 `step:"diag"`（`dryRun`）两档 exit 0；`init`／`qr`／`poll`
  三支 exit 2 且报文带 `lark.prompt`（＝面板「复制安装指引」那段全文的唯一真相处）。
- **三处指同一段**：配置读回执（`memo.config.read` 的 `lark.prompt`）／失败回执（`larkSetup` 格）／
  健康诊断（`memo.config.check` 的飞书那条）。代码先行于本票（#759／#760），本票为**追认**。

### ② `废弃提醒`：词随行退役，能力保留在独立废弃支

- **结论**：判据「老技能也有」这条读作**命令身份**——老侧 `dismiss <id>` 有子命令与命令表中文名
  （`references/schema.md:94`），但 **`SKILL.md:839` 那一段没有 `- 唤醒词:` 行**（同域邻段都有）。
  故：唤醒词退役、行从速查表撤掉；**能力保留**在 `memo.remove` 的 `mode:"abandon"` 支上——
  废弃只把提醒标 `dismissed`、**笔记保留**，且**不经删确认闸**（与真删那两档分层）。
- **已废弃语义与调用形写在两处**：① HELP 资产里「看提醒」场景的**状态说明**
  （`scripts/help-assets.data.mjs` 的 `hint:status`：`有效(默认)/已废弃(废弃=撤下这条提醒,笔记保留)`）；
  ② **看提醒产物页**的复制区说明行（`src/remind/run.ts` 的 `copyLog.thinking`，带调用形
  `memo.remove --params '{"mode":"abandon","id":<提醒 id>}'`）。
  为什么不把命令形写进 HELP 页：那份资产自带可见文案闸（`gen-help-assets.mjs` 的 `VISIBLE_FORBIDDEN`
  禁 `memo.` 与 `--`），且「命令不上 HELP 页面」是 #226 U6 的既定裁决——**本票是减法票，不改那条裁决**。
- **依据（现场）**：探针 ③——`routeWakeword('废弃提醒')` 抛 `POLICY_NO_MATCH`；按键跑
  `memo.remove {mode:"abandon",id}` exit 0、回执写「笔记保留」、`memo.detail` 仍能读到那条笔记、
  有效视图里不再出现、已废弃视图里出现。

### ③ 别名：全部退出联动速查，词只住 HELP 资产、**条条仍可按词路由**

- **结论**：**总表只列场景主名、一场景一行**；别名不上速查表，仍以别名身份住 HELP 资产的 `aliases`，
  且**按词仍能路由**（撤的是**行**，不是**词**）。技能说明里「其余唤醒词是场景别名，**住上一节索引块**」
  那句改成「只住 HELP 资产的 `aliases`」。
- **依据**：现仓 `SKILL.md:89` 自述与本次对账口径冲突（#842 Q③ 已裁：两个口径只能留一个）。
  探针 ②——HELP 资产的 12 条别名**没有一条**出现在速查块里；每一条都仍在某场景的 `aliases` 里；
  **12 条条条**能被 `routeWakeword` 命中并回原场景的键。
- **三条别名原来是「登记了但接不住」**（#855 的验收探针 `t855-验收-命令自治.mjs` 把 `初始化`／`新手`／
  `完成打卡` 挂在 `PENDING_WORDS` 名下，票面点名归本票）：本票把三条接进词面——
  `初始化`／`新手` → `memo.init`（场景 `memo_init_setup`，住 `src/init/routes.ts`）、
  `完成打卡` → `memo.update {done:true}`（场景 `memo_complete_wish`，住 `src/wish/routes.ts`）。
  不接的话「说「初始化／新手」有人带」这条用户故事不成立、且 `t855` 那张在册待办永远清不掉。
- **长式别名（`记情绪日记` 一族）**：老侧是历史漂移的野生写法（`t821-唤醒词对账.md` §3-Q4），
  主名维持短式（`记情绪`），长式留别名词位——HELP 资产**一条都不用改**。

### ④ `memo.stats`：整条退役

- **结论**：三处全无依据——**零唤醒词**、**HELP 无场景**、**老技能 21 个子命令无 `stats`**
  （出处 `t821-唤醒词对账.md` §4 末、`t234-cli-inventory.md` §4：老 `memo_cli.py` 里
  `stats`／`统计`／`汇总`／`总览`／`overview`／`kpi` 命中数 = 0）。正是「路由表可能过度开发了」的另一面。
  四处同步删：命令键声明、envelope 的形状分配、速查一句话、（生成物与分派表随 `pnpm gen` 重导）。
  **再调按未知键报错**（exit 3）。
- **依据（现场）**：探针 ④——`memo-cmd-read memo.stats` exit 3 且报文写「未知联动 key」；
  `MEMO_KEY_SHAPES` 里既没有这个键、也再没有任何键取 `stat` 形；`SKILL.md` 全文不再出现 `memo.stats`。

## 三 · 派生链（改一处即全链重导）

**各域路由声明**（`src/<域>/routes.ts`，一个唤醒词一条记录、`order` 是全表顺序权威）
→ `pnpm gen` 出 `src/triggers/routes.generated.ts`（记录面）
→ `buildHelpLookup()` 按「词＝它服务场景的主名」筛出**一场景主名一行**
→ ① 构建期注入 `SKILL.md` 的「联动速查」块（`scripts/build-help.mjs`）；
② `memo.help.lookup --params '{"mode":"lookup"}'` 那份速查表的载荷（`src/cli/cmd_read.ts`）。

**手写中转层已拆掉**：旧 `src/triggers/wakewords.ts`（31 词手写表）随本票**删件**——
它曾是速查的第二上游，与记录面必然漂移（旧表缺 4 条主名、多 5 条别名、还多一条无场景的
`废弃提醒`）。删除后「一条唤醒词的事实」只剩两处可查：**声明面**（各域 `routes.ts`，人手改的那处）
与**记录面**（生成物，机器写）。

**行数口径的两种读法与取舍**（写明理由，免得下次再飘）：

- 读法甲（本票采用）：**一场景一行 ⇒ 30 行**。`备忘改分类` 服务两张场景卡（单条 `memo_change_category_single`
  ／批量 `memo_batch_change_category`），故这个词出现两次、命令不同（`memo.update` ／ `memo.batch`）——
  老侧 HELP 自己也是两张卡共用一词。
- 读法乙（**未采用**）：按唯一词去重 ⇒ 29 行。**否掉的理由**：`docs/skills/skill-memo-ilife/t855-验收-命令自治.mjs`
  的速查面判据要求「**每个有词面的键**都要在速查面有行」，去重会把 `memo.batch`（只有批量那一格的词指向它）
  整键挤出表外，让批量向导在速查里彻底找不到。
- **运行期那侧的并列消歧与本表无关**：裸词「备忘改分类」在 `src/triggers/routing.ts` 里按「最长匹配 ＋ 同长
  取声明 `order` 小者」走单条那条；批量那一格由它的**别名** `批量改分类` 到达（别名不进表、但路由命中）。
