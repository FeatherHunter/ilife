## 七 如实记的缺口与偏离

1. **正例不是 34 格整批**：仓内今天能拿到的真产物是 27 件（search 7／memo 7／wish 7／mood 3／sync 1／init 2）；`checkin` 与 `remind` 两域尚无产物（`.scratch/t830` 是空目录）。故正例是「7 件真产物按册子名造册的一个批」，走的是同一套链（`t856-gen-audit-list.mjs` → 机审件）；**34 格整批重跑与逐格缺陷清单归 [#834](https://github.com/FeatherHunter/ilife/issues/834)**。`.scratch/t856-验收` 那 34 件是**合成占位产物**，本件对它红在 ①（34 件全无 820 断点）——`t856` 自己写明「收口时替换为真产物重跑」，故不拿它当正例。
2. **两处口径刻意不进红，写在读数件里**：触屏两件（`-webkit-tap-highlight-color`／`touch-action`）与断点集越界（今天真产物带 300／480／520／980／1120）；理由与去处见 `t869-机审读数.md` §二②。这是**如实记的边界**，不是漏判——把它们并进红，34 件会一次全红、等于没判。
3. **一处对 `t407` 的偏离**：英文那一列只剔回显型单元格，模板里写死在表格里的页面文案照判（理由：首次使用报告表里的「装飞书 CLI」正是地图点名的内容债，剔掉就判瞎了）。见 `t869-机审读数.md` §3.1 末段。
4. **现场扫出并已修掉的一处误报**：同步报告页里那条 HTML 注释 `<!-- … err>0 … -->` 带一个 `>`，不先剥注释就会把注释尾巴当可见文本点名（第一轮扫出 `0) ===== -->` 命中半角标点那一列）。已按 `t407`／居家件口径先剥注释，复跑后该命中消失，剩下的 `lark-cli auth status` 是真命中。
