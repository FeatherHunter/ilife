# t695 证据：skill-memo-ilife 路径类取值改读配置文件、删掉全部环境变量读取

票：[其余四家技能侧：路径常量改读配置文件，删掉全部环境变量读取](https://github.com/FeatherHunter/ilife/issues/695)
口径出处：「配置的存与生效口径裁定」（#675）的解决评论——每技能一份 YAML 配置文件为**唯一真相**，
默认 `~/.ilife/memo.yaml`（`os.homedir()` 派生、平台无关），`ILIFE_CONFIG_DIR` 设定且非空即整体接管
（**它同时是测试隔离的唯一口子**），数据目录默认 `~/.ilife/data/` 首次读自动建；环境变量读取全删。

## 四、行为面的两处如实交代

1. **`MEMO_MEDIA_DIR` 的语义升级归 #712**：本票只把它的**取值口**从环境变量接到配置项 `media.dir`
   （默认值仍是 `media`，逐字等于改造前的常量）；「前缀 vs 真目录」的判定改动全在 #712 那一票。
2. **`lark.cliPath` 报错文案**：显式值不可用时抛的 `LARK_UNAVAILABLE` 现在指向配置项
   （`lark.cliPath 不可用：<路径>（这一项住 ~/.ilife/memo.yaml，改完保存即生效）`），不再提环境变量。
