# t695 证据：skill-memo-ilife 路径类取值改读配置文件、删掉全部环境变量读取

票：[其余四家技能侧：路径常量改读配置文件，删掉全部环境变量读取](https://github.com/FeatherHunter/ilife/issues/695)
口径出处：「配置的存与生效口径裁定」（#675）的解决评论——每技能一份 YAML 配置文件为**唯一真相**，
默认 `~/.ilife/memo.yaml`（`os.homedir()` 派生、平台无关），`ILIFE_CONFIG_DIR` 设定且非空即整体接管
（**它同时是测试隔离的唯一口子**），数据目录默认 `~/.ilife/data/` 首次读自动建；环境变量读取全删。

## 一、改动件

| 件 | 动作 | 一句话 |
|---|---|---|
| `src/config.ts` | 新建 | 备忘录那份默认值表 ＋ 读／写／重置三个薄转调 ＋ `splitDirSegments`（随 `e4808516` 提交） |
| `src/cli/config.ts` | 新建 | 三个配置 key `memo.config.read/write/reset` 的唯一定义地；不是唤醒词命令 |
| `src/fetch/paths.ts` | 新建 | 库目录＝配置 `db.dir`（空串＝数据目录）、库文件名＝`db.name`（空串＝`memo.db`）；不建目录（备忘的库由用户／老技能建） |
| `src/fetch/db.ts` | 改 | `memoDbFile()` 用 `dbFilename()`；注释里 `SKILLS_DB_PATH` 的说法改成配置项 |
| `src/fetch/feishu.ts` | 改 | 显式 lark 路径改读配置 `lark.cliPath`；`LARK_CLI_PATH` 与 `APPDATA` 两个环境变量读取**删除**，`%APPDATA%` 那一档改由 `os.homedir()` 派生 |
| `src/fetch/auth.ts` | 改 | 二维码落点缺省值改读配置 `lark.qrDir`（空串＝系统临时目录下的 `memo_feishu_qr`） |
| `src/help/manifest.ts` | 改 | 三个落点值（`memo_html` 扁平一段、两个产物主体）从配置取，常量改成取值函数 |
| `src/cli/cmd_read.ts` | 改 | 预检不再读 `SKILLS_DB_PATH`；三个配置 key 在预检与形状表之前拦下；**读配置算库目录这一步套上人话报错**（裸抛会吐一整段 node 崩溃栈） |
| `src/policy/media.ts` | 改 | 附件目录取值口（#712 的判定件）改读配置 `media.dir`——**这一处随 #712 的提交 `8268373c` 入仓**（同一工作区，两个席在飞） |
| 四个插件烟囱测试 | 改 | `plugin-{chef,home-ilife,memo-ilife,schedule-ilife}/test/smoke.test.mjs` 里 `SKILLS_DB_PATH` 换 `ILIFE_CONFIG_DIR`（技能侧不再认那个变量；不改这一个，仓根全量测试与 CI 会红） |

## 四、行为面的两处如实交代

1. **`MEMO_MEDIA_DIR` 的语义升级归 #712**：本票只把它的**取值口**从环境变量接到配置项 `media.dir`
   （默认值仍是 `media`，逐字等于改造前的常量）；「前缀 vs 真目录」的判定改动全在 #712 那一票。
2. **`lark.cliPath` 报错文案**：显式值不可用时抛的 `LARK_UNAVAILABLE` 现在指向配置项
   （`lark.cliPath 不可用：<路径>（这一项住 ~/.ilife/memo.yaml，改完保存即生效）`），不再提环境变量。
