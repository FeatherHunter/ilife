## 三 · 矛盾与查不清

1. **M-04 查重键与实际写入的标题不一致（矛盾）**：查重把**未截断**的 `content` 作为 `--query` 去搜（`feishu_sync.py:313`：`        existing_guid = _search_feishu_task_by_due_and_summary(due_iso, content)`），而创建时标题写的是 `content[:200]`（`feishu_sync.py:327`）。正文超过 200 字时，远端存的是截断标题，查重却按全文比对（`feishu_sync.py:266`：`        if item_summary == summary and item_due_at.startswith(due_iso):`），等值条件不可能成立 → 长正文心愿的建前查重实际失效，会重复建 task。
2. **M-04 覆盖范围窄于注释给人的印象（口径差）**：注释写「add 前先查飞书 task 列表，如果同 summary + due 的 task 已存在，直接复用其 guid」（`feishu_sync.py:288`），但代码把整段查重锁在 `if due_iso:` 里（`feishu_sync.py:312`）。**无 due 的心愿完全没有建前查重**，同内容同分类再 add 一次就会再建一个飞书 task。
3. **M-11 与 M-08 的本地/远端一致性缺口（如实记录，不判对错）**：`delete_note` 是先 `conn.commit()` 删本地（`memo_cli.py:407`：`        conn.commit()`），之后才调远端 `complete_wish_sync`（`memo_cli.py:417`）。远端失败只进 `feishu_sync_results` 的 `synced:false`（`memo_cli.py:421`），本地已不可回滚，且没有任何补偿队列／重试入口——下一轮 `sync-from-feishu` 也补不回来，因为该 task 的 `description` 反查需要 `notes.feishu_task_guid` 匹配（`feishu_sync.py:633`），而本地行已被删除，只会落进 `skipped_no_local_note`（`feishu_sync.py:640`：`            result["skipped_no_local_note"] += 1`）。
4. **查不清（属于代码之外的口径，代码无判据）**：飞书上「已完成的测试任务／已完结的心愿 task」长期堆积由谁清理，代码里没有任何路径，也没有用户可跑的命令入口——`feishu_sync.py` 子命令表（`feishu_sync.py:927` 起）与 `memo_cli.py` 子命令表（`memo_cli.py:1544` 起）都没有面向 task 的清理命令。此项只能记「代码未提供清理路径」，不能推断产品意图。
