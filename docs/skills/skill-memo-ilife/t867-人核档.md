## §一 四列各是什么、凭什么填

| 列 | 进哪条算式 | 填法（谁给数、凭什么） |
|---|---|---|
| `english` | H7 命中处数（每处 −1）；同时进 D3 的折算明细 | **机器候选**＝静态可见文本节点里「露英文词或半角标点」的节点数（`t867-dom-probe.mjs`）；**人核判分**在候选上判真伪，判「采纳候选」或「改判＋理由」 |
| `dupFacts` | H3 命中处数（每处 −2）；同时进 D3 与硬扣分 | 同上（机器候选＝页身域里按文本全等成组的重复节点，每组记 `count−1` 处） |
| `d1` | D1＝`15 − d1`（满权 15） | **纯人核扣分位**：机器给不出这一维，靠视觉模型按基准 §4.1 的 D1 判据（内容列、卡等高、数值列、缺值形状、色仅用令牌）逐条判，扣几分要写理由 |
| `d2` | D2＝`20 − d2`（满权 20） | 同 `d1`，判据是基准 §4.1 的 D2（主角元素、同级标题、同列对齐、无一片灰小字、间距节奏） |
| `d4cut`（可选） | D4＝`15 − 破格档×5 − d4cut` | 人核位：三档虽全绿、但 1440 档「只多留空」的观感债（基准 §4.2 ③）。写了就带上，不写按 0 |

两条边界（写在前面，免得两处走散）：

1. **机器能读的不进人核位**：字号、触摸目标、三档溢出、分隔符串、内部标识符这五类由机器读数直接进 D3／D5 与硬扣分（`sep.json`／`resp.json`／`fmt.json`），人核档**不重复计价**——所以「字号 11px」「勾选框 13×13」这类债不落 `d1`／`d2`。
2. **真冗余的判法**：同一串文字在页面上出现 `n`（`n ≥ 2`）次、去掉一处不损失信息 ⇒ 计 `n−1` 处；**「逐条如实报」不算**（列表里逐条列同名文件、逐条报同一个提示文案是如实报，不是冗余——基准 §4.2 的同款例外）。这条与机器候选的算法同口径，所以候选之外的调整必须是「排除假阳性」或「补渲染面」，两种调整的写法不同，见 §二。

## §二 出处怎么写（机器可判）

出处一律以 `静态 ` 或 `渲染后 ` 开头，两种写法对应两种判分，装配器按这个分流查：

| 出处写法 | 什么时候用 | 装配器会查什么 |
|---|---|---|
| `静态 #3 #17 …` | 值取自或调整自**静态可见文本**（`facts.json` 的候选就是从这上面算的） | 每个 `#节点号` 必须**落在机器候选的节点号里**（编不出来的出处）；取值 > 0 时至少要有一个 `#节点号` |
| `渲染后 <区块名／脚本行号／选择器>` | 值取自**渲染后**的页面（视觉模型看的就是渲染后的页面） | 出处里出现 `L<行号>` 时必须 ≤ 该页源文件行数；写 `渲染后` 的列**必须**判「改判」（静态候选覆盖得了的，不该走这条） |

## §三 载荷渲染面：本链的已知缺口（逐页取值会用到，别当噪声看掉）

备忘录的产物页**把内容放在页内 `<script id="payload" type="application/json">` 里，由页内脚本渲染**（真产物实测：`同步报告` 的标题、四块指标卡的明细行、错误明细都由脚本渲染）。而四件读数里的**静态**面（`facts.json` 的 DOM 六列与两列候选、分割符门的可见文本）都要先剥掉 `<script>` 整段 —— 于是：

- **静态面看不到脚本渲染出来的文字**：同一页在渲染后有半角标点、有重复串、甚至有点号并列，静态候选却是 0；
- 这不是「候选是上界」也不是「候选是下界」，而是**两个不同的量**：候选量的是「静态可见文本里的处数」。

本档的处置：静态候选照旧作锚（可复算），**渲染面的处数由视觉模型判分并写进「渲染后」出处**，改判的理由里点名是哪几处、由哪几行脚本渲染。⇒ 这是本链交给上游的一条真缺口，读数链本身不动三件 reader 的语义（票面「一行语义不动」），缺口另开票处置（见 `t867-证据.md` §六）。
