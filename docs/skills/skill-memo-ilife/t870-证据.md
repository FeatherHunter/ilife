### 4.1 反例甲：把共用件里的 44px 改回 40px → 触摸档读数必红

改的是公共层唯一一处判据数值 `PAGE_LIMITS.touchMinPx`（`packages/base-render/src/pageUi.ts`，44 → 40），量的是 `t516` 的三档「触摸档 <44px」合计：

| 态 | 读数 | 点名 |
|---|---|---|
| 绿向（改前） | **0 处** | — |
| 红向（44 → 40） | **30 处** | `button.copy@82x40`（390／768／1440 三档各点名）、`button.copy@78x40` |
| 还原 | **0 处** | — |

原文点名：

```text
删备忘_…@390：["button.copy@82x40","button.copy@82x40"]
删备忘_…@768：["button.copy@82x40","button.copy@82x40"]
删备忘_…@1440：["button.copy@82x40","button.copy@82x40"]
备忘改分类-批量-向导_…@390：["button.copy@78x40","button.copy@78x40"]
```

**这条同时证明了另一件事**：改前基线那 33 处触摸档不足，**不在**「公共层 44px 那一条」的覆盖面上（那是模板自持的表单控件尺寸），是本次另行补齐的（见 §六 第 3 条）。

### 4.2 反例乙：把 `pageUi` 位去掉（页面根类不写）→ 安全区与窄屏配方必不生效，读数点名

改的是七份模板的版面根类（`class="wrap ilife-page-ui"` → `class="wrap"`），量的是真浏览器里的三件事：

| 态 | `rootHasClass` | `bodyMarker` | `toastCloseHit44`（配方生效的可读数） |
|---|---|---|---|
| 绿向（改前） | `true` | `true` | **`true`** |
| 红向（去掉根类） | `false` | **`false`** | **`false`** |
| 还原 | `true` | `true` | **`true`** |

`toastCloseHit44` 是 `.ilife-page-ui .ilife-toast-close::after` 那条配方规则算不算得出 44×44 覆盖层——**就是「配方生不生效」本身**。根类一去掉，整段配方（断点集、触摸区 ⑤、安全区 ⑥、宽屏 ⑧、桌面 ⑪、toast 命中区 ⑫）一条都不落，读数立刻为假。

### 4.3 两条反例的结论行

```text
OK   甲：公共层 touchMinPx 44→40        绿向 0 → 红向 30 → 还原 0
OK   乙：版面根类去掉 ilife-page-ui      绿向 true → 红向 false → 还原 true

RESULT: 变异自证 PASS（两条都成立）
```

## 七 一次实测：`input[type=checkbox]` 的 `min-height` 到底生不生效

修 §六 第 3 条之前先验了这一条（写死 `min-height` 在表单控件上常被浏览器忽略，不能凭猜）：

```text
A：直接给 checkbox 设 min-height/min-width  →  [44, 44]   ← 生效
B：同 A（外面套一层盒子）                    →  [44, 44]
C：只把祖先盒子撑到 44（checkbox 本身不动）  →  [13, 13]   ← 不生效

判据：拿 .c 的祖先盒子当命中区不算，读数器量的是元素自己的 box ⇒ 必须落在 checkbox 本身上。
```

故 §六 第 3 条直接把两个尺寸写在 `input[type=checkbox]` 上。
