**两条实操教训（都写进电池脚本／挡板的头注释，免得下次再踩）**：

1. **Windows 的 `copyFileSync` 保留源文件 mtime** ⇒ 还原后源码比 `dist` 还旧，`tsc -b` 判「已是最新」不重编，`dist` 里留着改坏那一版。故还原后必须把源码 mtime 拨到当下，并**断言产物里真有／真没有那段行为**——只看用例红绿不够。
2. **挡板不许自造命令**（本票真踩过）：首轮我把删远端写成 `task +delete`（按 `+create／+update／+complete` 那一族的形状猜），挡板也照着认了它——于是用例全绿，**是假绿**。一手核对（本机 lark-cli 1.0.82 的 `task --help` 逐行）证明短路里根本没有 `+delete`，真形状是**原生 resource** `task tasks delete --task-guid <guid>`（`high-risk-write`，须带 `--yes`）。教训：**挡板只认真命令，认不出的必须大声失败**，否则「对拍／接缝」证明不了任何真机能跑通的事。
