# 墙生成器预演：备忘录形状的产物能不能直接铺墙（#825 的输入）

**谁读**：[验收形制 #825](https://github.com/FeatherHunter/ilife/issues/825) 与 [收口 #834](https://github.com/FeatherHunter/ilife/issues/834) 开工前先读。这一页量的是**改造成本**，不是猜的。

**两条一句话结论**：

1. **墙生成器**：卡路里那份**一行都不用改**，把产物目录当参数传过去就能铺备忘录的墙 —— 备忘录只要交一份清单。
2. **链路总表生成器**：**与墙相反**，路径写死在件内、**不可参数化** —— 备忘录要照它的形状**自己写一份**（约 94 行）。

**怎么来的**：2026-09-20 编排会话把一个**备忘录形状**的产物目录铺给**卡路里那份墙生成器原样跑**（`docs/skills/skill-calorie/scene02-验收墙/gen-wall.mjs`，**一行都没改**）。

## 一 结论先行：**生成器一行都不用改，备忘录只需要交一份清单**

`gen-wall.mjs` 的位置参数已经把产物目录当参数收（`node gen-wall.mjs [产物目录] [输出名] [宽] [高]`），所以把它指向备忘录的目录就能用。**唯一的输入是 `manifest.json`**。

| 清单字段 | 要求 | 出处 |
|---|---|---|
| `rows[].seq` | 必填 | `gen-wall.mjs:70` 的必填校验 |
| `rows[].kind` | 必填（页型，如「结果型·列表页」） | 同上 |
| `rows[].wake` | 必填（唤醒词） | 同上 |
| `rows[].file` | 必填，**就是最终发布名** | 同上（`:25-27` 写明「发布名全仓只此一处算，别处不许再拼」） |
| `rows[].check` | 可选（「这一格该确认什么」） | 骨架 §6.3-1 |
| `mf.notShipped[]` | 可选，索引页会单列「有意不出产物及其原因」 | 骨架 §3-4 |
| `mf.readings` | 可选，索引页的「本批机器读数」段原样上屏 | 本件件头 `:36-44` |

## 三 备忘录这一侧要补的两件事

### 3.1 一份清单（必交）

清单**要入仓**（`gen-wall.mjs:60` 明确「清单须入仓，别让墙猜文件名」）。按 #822 冻结册子时一次定死 `seq`／`kind`／`wake`／`file`／`check` 五个字段。

### 3.2 ⚠️ 发布名规则有一个**已知会撞名**的点

生成器把 `file` 当唯一键，所以**只要清单里名字不重复就没问题**。会撞的是**「发布名 ＝ 唤醒词 ＋ `.html`」这条规则本身** —— 备忘录的 `备忘改分类` **一词两场景**（`memo_change_category_single` 单条 与 `memo_batch_change_category` 批量），照那条规则两条都要 `备忘改分类.html`。

预演里我是手工避开撞名的（`备忘改分类-批量.html`）。⇒ **#822 裁发布名规则时必须给「一词多场景」留出区分位**（加形态后缀、或直接按场景 id 命名）。这一条与 `research/wall-and-linkage-reference.md` §一 的三处补法之一对得上。

### 3.3 还缺一件「逐条真跑 ＋ 快照」的件（`--stage` 那一路）

`--stage` 那一路要先有产物才能铺。卡路里那边靠 `scene02-验收墙/restage.mjs` ＋ `t279-真跑.mjs` 的 `scene02Routes`／`buildSnapshot`／`readOne` 来「逐条真跑再快照」；**备忘录没有等价的件**，得先写一件（否则只能手工把产物复制进目录）。

预演里我走的是「手工复制 ＋ 直接出墙」，所以 `--stage` 这一路**没验**。

## 四 链路总表那一半：**与墙生成器相反，它不可参数化**

顺手量了另一半（requirement 2 要的那份「prompt → 唤醒词 → 命令 → HTML 绝对路径」）。

| 件 | 产物目录能不能当参数传 | 实测 |
|---|---|---|
| **墙生成器** `scene02-验收墙/gen-wall.mjs` | **能**（位置参数收了产物目录） | 指向备忘录目录 → 直接出墙，**一行未改** |
| **链路总表生成器** `t369-链路总表.mjs` | **不能** —— 路径写死在件内 | 直接跑 → `链路总表：13 行；链接 18 条；缺失 0 -> 可发`、**exit 0**，但它出的是**卡路里那张表**（读的是 `join(root,'t369-验收')` 的清单 ＋ `packages/skill-calorie/src/triggers/scene-08-body.ts`） |
| **链路总览生成器** `t268-链路总览.build.mjs` | **不能** —— 同样写死自己的 `t268-链路清单.json` | 同型 |

⇒ **结论：链路总表要照 `t369` 的「形状」自己写一份（约 94 行），不是把它指过来。** 形状照抄部分（`t369-链路总表.mjs` 已是最省的骨架）：一页静态表，列＝**序 ／ prompt 示例（可复制）／ 唤醒词 ／ 命令 ／ 参数 ／ 页型 ／ 产物绝对路径（点直达）**；链接走同目录相对路径、显示文本写绝对路径；末尾死链自检（缺链 exit 1）。

⚠️ **别被「它跑通了 exit 0」误导** —— 那次跑通是把卡路里那张表**又出了一遍**（幂等重出，改了同一个文件），跟备忘录无关。

## 五 这次没验的

- **`--stage` 那一路**（要先把「逐条真跑＋快照」的件写出来）。
- **60 格以上的规模**：预演只铺了 8 格；仓规 §6.3-4 说「几十格是舒适区」、产物带大图时要按页族拆墙 —— 备忘录 64 格最终要不要拆 2–3 张，到 #825 定。
- **总索引页的「机器读数」段**：预演的 `readings` 是我手填的样板值。`gen-wall.mjs:36-44` 自己写了这个坑 ——「清单每行 `check` 里嵌的字节字样**不会跟着刷新**，单格核字节请直接量文件本身」。
