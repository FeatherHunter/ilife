# t837 命令面口径（四问决议）

地图：[#820](https://github.com/FeatherHunter/ilife/issues/820)。本票：[#837](https://github.com/FeatherHunter/ilife/issues/837)。

## 目标

四问定死命令面形状（开几条命令、参数面长什么样、删的确认从哪来），让 `#823` 与 8 张域票开工。最终服务 MAP 目标：HELP 30 场景底层走通、按 `types` 出页、链路总表可点开。

## 边界

不碰 `src/config.ts`、`packages/plugin-memo-ilife/**`、老技能仓库（仓外只读）；连接层禁 DDL；不切分支。

## 风险（先说）

`删心愿`／`删打卡`／`删情绪日记`三行指向 `memo.update`（只改分类、不删）。修法已定：改指 `memo.remove`。本口径只定确认来源。

## 决策一：Q④ 首次使用 —— 新开渲染命令 `memo.init`

- **结论**：新开一条渲染型命令 `memo.init`，照旧侧 `init-report --data <JSON>` 形状。
- **参数面**：必填 `data`（诊断 JSON `{items:[{name,status,desc,action}], todos, verify}`，同老契约）。
- **落点**：`memo_html/初始化报告.html`，接线 `templates/init_report.html`。
- **完成标准**：库不在也能跑（开库前分派，同 `memo.help.lookup` 位置）；只渲染，不建库不写配置。
- **依据**：老技能有真命令（`memo_cli.py:1673-1680`）；HELP 有场景卡（`memo_init_setup`，`types: 向导／采集／回执`）。
- **对抗审查（对 MAP）**：复用 `help.lookup` 省一个命令，但一命令两形状（`list` vs `receipt`），且“看帮助”与“帮我搭好”意图混淆，域票实现时会猜错分支，直接威胁 30 场景走通。新开则形状干净，代价仅命令面＋1。

## 决策二：Q⑤ 时间语义 —— `start`＋`end` 按创建时间，`timeRange` 退役

- **结论**：认 HELP 的 `start`＋`end`（双 `YYYY-MM-DD`），按 `created_at` 过滤倒序；`timeRange` 一词退役。
- **参数面**：`memo.search` 新增创建时间区间通道，与排期 `due` 正交可叠加；`start`／`end` 双必填，`category` 可选，`limit` 默认 20；`start > end` 报错。
- **依据**：HELP 可填字段（`search.ts:81-85`）与老 `search-date`（`created_at BETWEEN … ORDER BY created_at DESC`）两边一致；月份形零出处。
- **对抗审查（对 MAP）**：月份形改动最小，但表达不了区间，且现实现丢槽位等于列全表，链路总表“按时间搜”一行永远点不开。A 多一条过滤通道，但让该行真走通。

## 决策三：Q⑥ 设提醒 —— 新开写命令 `memo.reminder`

- **结论**：新开写命令 `memo.reminder`（只做 INSERT 提醒行）；`memo.create` 的两步合一（记提醒）不动。
- **参数面**：`note_id` 可选（给了校验存在，不给即独立提醒）、`remind_at`、`content` 必填、`repeat_type` 默认一次性（一次性必须有 `at`），同老 `add_reminder` 落盘形状。
- **依据**：老写 `remind [note_id]` 与读 `reminders/completed/due` 分开；HELP 两场景分立（`记提醒`两步合一 vs `设提醒 note_id 可选`）。
- **对抗审查（对 MAP）**：给 `memo.create` 补 `noteId` 最小改动，但一写命令两条路，域票测试缝多一倍；复用读命令 `memo.remind`（`list` 形）则读写混形，破形状分配。新写命令与 Q④相加共＋2，但让“给既有笔记挂提醒”从走不通变为走通，且读写各归各。`#658` 已落地的 `memo.create` 不拆。

## 决策四：Q⑦ 删确认 —— 用户说删即确认＋分层闸

- **结论**：用户按唤醒词说删即 `confirm:true`；级联另设闸。
- **口径**：单条无关联直删；有超限提醒先出清单（含提醒数）再要 `withReminders:true`；批量（≥2）一律先出清单（只回 JSON，不另出整页）；`废弃提醒`走 `abandon` 支，不经此闸。
- **依据**：老 `delete` 非交互直删，但有两道闸（无 `--with-reminders` 有关联则报错；有 `active` 无 `-y` 则交互确认）。
- **对抗审查（对 MAP）**：每次反问最保险，但打断自动化（老 `-y` 即为此），且与 30 场景“删即删”体验不符；无脑直删则误删提醒。分层闸让单条跑通、批量不翻车，链路“删X”三行改指后可安全执行。

## 实施约束

- **代码守架构**：一条命令事实只住 `src/<能力>/commands.ts`，共用位由 `pnpm gen` 派生；一个命令一种 envelope 形状；结构照 `docs/agents/structure.md`，行数告警线 350（LF）。
- **文档守第一性**：唤醒词是约定、命令是能力；字段名以 HELP 为准，不自造第二个说法。

## 验收

本票验收＝四问逐条有结论、有依据、落在本文件；无需跑门。实现由 `#823` 与域票承接。
