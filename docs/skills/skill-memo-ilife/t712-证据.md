**判定口径**（三条）：
1. 附件目录解析成绝对路径，且必须真的存在、真的是目录；不是就抛 `POLICY_BAD_INPUT`，文案点名读了哪个值、当前指向哪、该怎么办——不静默降级、不替人建目录；
2. 传入路径与附件目录都归一成绝对路径算相对路径：空串（就是目录自己）／以 `..` 开头（穿出去）／绝对（换盘）一律拒；相对值按当前工作目录解（照老实现），老技能那种「以目录名开头」的相对值（`media/x.jpg`）照样认；
3. 落库仍是相对路径（`notes.media_path` 取值形状一字不改）。

## 五、老规则 vs 新判定（对照读数，说明本票改掉了哪一类）

老规则＝仓外老实现 `备忘录/script/memo_cli.py:106-116` `_resolve_media_path` 的规则原样转写（`v.startsWith(配置值 + '/')` 即放行，再切掉那段）。同一组输入喂两边（`runId=f5203d34-…` 那次测试的 stdout）：

```
CASE ① 目录内          输入="media/img.jpg"                  老规则=放行（"img.jpg"）  新判定=放行（"img.jpg"）
CASE ③ 同开头不同目录   输入="mediafoo/x.jpg"                老规则=拒               新判定=拒
CASE ④ 带 .. 穿出去     输入="media/../../mediafoo/x.jpg"    老规则=放行（"../../mediafoo/x.jpg"） 新判定=拒
CASE ④′ 就是目录自己    输入="media"                          老规则=放行（""）        新判定=拒
RESULT: 老放行→新拒 2 条 —— ④ 带 .. 穿出去；④′ 就是目录自己
```

**读法**：④ 是票面点名的「恰恰拦不住它本来要拦的那件事」——老注释写着要拦穿出去的路径，实际放行并把 `../../mediafoo/x.jpg` 原样存下来；新判定拒。①（目录内的正常值）两边落库值逐字相同 ⇒ 正常路径行为一字未变。③ 的相对写法两侧都判「不在目录里」，只是理由不同（老规则把它当不以 `media/` 开头的**文件名**，新判定按路径算）；真出口那条用**绝对路径**喂，两侧也都拒，理由同 ②。
