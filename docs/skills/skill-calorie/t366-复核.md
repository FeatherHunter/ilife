作者取：**属性照老正本 0／100**；提示句与校验句**同用 `(0, 100) mm`**（同源 `caliperRangeText()`），与命令层 `src/fetch/body.ts:114` 的 `CALIPER_MIN_MM < v < CALIPER_MAX_MM` 同结论。

**复核席结论：认。** 三条依据，复核席自己查过原文：

1. 裁定 3 的原文口径是「数字**照老正本**」，而「数字」在票面定义里就是**属性**（票面逐字引 `:300-329`／`:346` 的属性行）⇒ 属性取 0／100 是对票面的严格执行。
2. 老页自己两套（属性闭 ＋ JS 开）是**老页的既有事实**，本票没有把它变坏；本票要消的是**同页两处文案**（`wizardDocs.ts` 的 `(0, 100) mm` 与 `wizardPlate.ts` 的 `!(>0 && <100)`）不一致——这一条**已达成**：两处现由 `caliperRangeText()` 一处派生。
3. 方向性判断复核席认账：**页面比命令宽**会出现「页面放行、命令跑不通」的假闭环；**页面比命令严**只会多给一句解释。实测证明严的那一方向是安全的：输入正好 0 或 100 时，复制区出的是 `// 皮褶值需在 (0, 100) mm 之间:… 当前异常`，**不会给出一条跑不通的命令**。

**残留（S3，非缺陷，登记不转票）**：HTML 属性仍是闭区间，所以「框里能填 0 或 100」与「复制区拒收 0 或 100」并存。这与老页同病，且作者在证据 §八・3 已如实登记为「本票唯一一处口径判断」。将来若要彻底一致，改法是**属性也取开区间**——HTML `min` 表达不了开区间，只能落 `min=0.1/max=99.9`（会偏离老正本属性）或加页面脚本，两者都比现状差 ⇒ **维持现状**。

### 口径② 老页 `:179-181` 越界当场红框 ＝ 登记「老页交互未移植」，只落「提示行 ＋ 缺项清单」

**复核席结论：结论认（红框确实未移植、也确实不该按已落记），但作者给的理由『本仓预检页零脚本』不实，必须改口。**

- **不实之处（实测）**：产出的预检页**有 1 个内联 `<script>`**——`shared/docPage.ts` 注入的 `buildSharedHelpersJs()`（复制按钮绑定与 toast 的页面运行时；实测 `<script` 命中 1 处，`on*=` 内联 handler 0 处）。所以「零脚本」不成立；成立的是「**零业务脚本／零内联 handler**」。作者在 §三・② 与 §八・1 两处都写了「零脚本」，**作为边界事实报错了**。
- **但结论仍站得住，且真正该引的依据是基准本身**：`t395-融合基准.md:42`（第 13 项）的「融合口径」列逐字只要求两层——「预检确认页必须有这两层：**字段旁的提示行＋复制区的缺项清单**」，**红框不在要求内**；§二-补 `:47-52` 那张「老页交互未移植登记」表里登记的是**数字动画**与**贴底靠粘的复制条**，**没有**红框这一行 ⇒ 作者「同 §二-补 的登记口径」这句引得也不准（红框本就不在 §二-补 表内，它被排除在判据外是靠 `:42` 那一列，不是靠 §二-补）。
- **更硬的补充理由（复核席给）**：要做到与老页等价的「越界当场红框」，得让公共层 `ParamFieldInput` 带错误位（或给预检页加业务脚本）；前者属公共层票（与作者 §八・1 的下一手一致），后者与「页面自足、不加业务脚本」的既有惯例冲突。**两层（提示行＋复制区清单）已把「出错被静默吞掉」这一风险堵住**——实测越界必出注释句，用户/ AI 都看得见。

⇒ **裁定：红框按「老页交互未移植」记，可以；但证据件里「零脚本」两处措辞要改成「零业务脚本／零内联 handler」，并把依据从 §二-补 改成 `t395-融合基准.md:42` 的融合口径列。** 属**本票范围内的表述更正**（证据件，不是实现），作者回填一行即可，不必重跑。
