## 四、5 条裁定（本图强制基准；2026-09-14 对抗复核改判后版本）

每条给：结论／理由一句话／可判形式（跑哪条命令 → 看哪个读数 → 等于什么）／落点票。

### 裁定 1 · 皮褶钳模式的体脂率不给手改（方向保留，落地前置 #397）

- 结论：预检确认页按 `source` 分模式——`source=home_caliper` 时体脂率**只读**（展示 JP7 公式＋7 点总和，自动算）；非皮褶钳来源允许手填。命令行直传路径**维持放行**（与 #358 的裁定一致）。
- **前置**：`ParamFieldInput`（`packages/base-render/src/blocks.ts:517-523`）只有 `name／label／value／hint／required`，`renderParamForm` 在 `:559-562` 只渲染这五个 ⇒ **`readonly` 现在落不下去**，要先走 **#397**。同批必须加文案「体脂率可留空，由命令按 7 点换算」，否则只读之后用户无路可填、页面空转。
- 理由：老页把「皮褶钳＝公式算」写死成策略（`body_composition_wizard.html:596-621`），手改会让页面读数与入库算式两套口径。
- 可判形式：跑 `calorie-cmd-read calorie.view.composition-wizard`（皮褶钳来源）→ 剥标签后读两处读数：① 体脂率输入框带 `readonly`；② 可见文本含「体脂率可留空，由命令按 7 点换算」＋「7 处总和」＋ JP7 公式串 → 两条都成立才算落地。反向：`calorie-cmd-read calorie.body.composition-add --params '{"source":"gym","bodyFatPct":18.5}'` → `exit 0` 且库内 `body_fat_pct=18.5` → 等于：直传放行未被拦。
- 落点：#366（页面侧）＋前置 #397。

### 裁定 2 · 缺值可见文本一律 `—`，复制数据保留原始空值

- 结论：保留（与 #359 同源：`packages/skill-calorie/src/body/bodyDocs.ts:80` 已经这么做；老正本 `body_measurements_view.html:334`／`:385`／`:533`）。两条约束：① **判据拆两条**——表体（#360 → #361 链）与表头＋复制区（#361）各一条；② **复制区口径**：可见文本写 `—`，**复制数据（给命令执行的 payload）保留原始空值／语义**，两者不混。
- 理由：老技能就是这个口径，用户已习惯；空串看起来像丢数据，而把 `—` 写进 payload 会把「缺」变成一个真值。
- 可判形式：跑 `calorie-cmd-read calorie.view.body-measure`（窗口内造一条缺项记录）→ 读数一：剥标签后可见文本里该格内容**等于** `—`，且全文不出现连续两个空单元；读数二：同一页复制数据文本里该字段是空值（`""` 或字段缺位），**不含** `—` → 两个读数各自等于期望值才算落地。
- 落点：#360／#361（表体链）、#361（表头与复制区）。

### 裁定 3 · 单位与精度（数字全部照老正本；前置 #397）

- 结论：皮褶 7 点 `step=0.1／min=0／max=100`（老正本 `body_composition_wizard.html:300-329`，**不是** `step=1`）；围度**逐部位区间**（老正本 `body_measurements_wizard.html:181-253`：胸／腰／腹／臀／肩 `20–200`，大腿 `10–100`，小腿 `10–80`，臂 `10–60`，前臂 `10–50`，**不是**统一的 `0–300`）；体脂率 `step=0.01／min=0／max=60`（老正本 `body_composition_wizard.html:346`，与现状同）。同票还要消掉同页两套口径的矛盾：`packages/skill-calorie/src/body/wizardDocs.ts:130` 的提示写 `(0, 100) mm`，而 `packages/skill-calorie/src/body/wizardPlate.ts:169` 的校验写 `!(>0 && <100)`，两处要一致。
- **前置**：`step／min／max` 同样要被 `renderParamForm` 渲染出来，走 **#397**。
- 理由：老页把范围写进属性（`:300-329`／`:181-253`），新页只写提示却不带步长，浏览器默认步长会把 0.1 判成非法；而同页两份口径互相打架，用户与实现各看一套。
- 可判形式：跑 `calorie-cmd-read calorie.view.measure-wizard` 与 `calorie-cmd-read calorie.view.composition-wizard` → 剥标签后读各输入框的 `step／min／max` 三属性：围度逐部位等于上表区间、皮褶 `0.1／0／100`、体脂率 `0.01／0／60` → 等于落地。再跑一条：同一页可见文本与校验文案对同一位只说一套数（不出现 `(0, 100) mm` 与 `max=100` 之外的第三个数）。
- 落点：#366（页面侧）＋前置 #397。

### 裁定 4 · 全量模式（不带部位）也出图，且 KPI 一起定（并入 #360）

- 结论：看围度趋势不带部位参数时也出趋势图——自动挑「最近有数据的部位」，并在图上标注所选部位。**KPI 必须同批定**：`packages/skill-calorie/src/body/bodyPlate.ts:129-133` 只在 `metric` 有值时算 `trend`，而 `packages/skill-calorie/src/body/bodyDocs.ts:119` 的 KPI「趋势点」取 `v.trend.length` ⇒ 全量时会「有图 ＋ 趋势点 0 天」自相矛盾；全量时「趋势点」要显示**所选部位的点数**（或改标签）。
- 理由：老页部位筛选是筛选而不是开关（`body_measurements_view.html:165-167`），全量落空态等于用户白跑一条命令；而一页上 KPI 与图打架比空态更糟。
- 可判形式：跑 `calorie-cmd-read calorie.view.body-measure`（**不带** `metric`）→ 三个读数：① 剥标签后可见文本含「<部位>趋势」（图是自绘，抓不到 SVG，所以判据写在可见文本上）；② 图区**不是**空态句；③ KPI「趋势点」读数**等于**所选部位的数据点数（用 `sqlite3` 在窗口内数出期望值）→ 三个都成立才算落地。反向：传一个库里无数据的部位 → 图区出空态、图注仍写该部位 → 说明标注随参数走。
- 落点：#360。**#361 必须严格排在 #360 之后**（同一分支 `packages/skill-calorie/src/body/bodyDocs.ts:123`）。

### 裁定 5 · `source=all` 的趋势按来源分组（只限体成分；前置 #398）

- 结论：保留但两处收紧：① **只限体成分**——围度没有来源列，老页也没有来源概念；② **现状根本跑不通**：`SOURCE_CHOICES` 只三个值（`packages/skill-calorie/src/kcal.ts:18`），`packages/skill-calorie/src/fetch/body.ts:202` 按字面来源名过滤，`trendComposition`（`:222-225`）的语句恒带 `AND source = ?` ⇒ 传 `all` 无记录 → `packages/skill-calorie/src/body/bodyPlate.ts:66` 抛 missing-data。所以要**依赖 #398**（数据层先支持不按来源过滤／按来源分组）。**不禁止**趋势。
- 理由：口径不同的设备混成一条线会得出假趋势；但粗暴禁掉趋势等于砍功能——老页正是「提示＋分来源」（`body_composition_view.html:139-141`／`:151`）。
- 可判形式：跑 `calorie-cmd-read calorie.view.body-composition --params '{"source":"all"}'` → 三个读数：① `exit 0`（改前读数先记进证据，改前不等于 0）；② 剥标签后可见文本含「来源不可直接对比」；③ 按来源分组的组数**等于** `SELECT COUNT(DISTINCT source) FROM body_composition WHERE COALESCE(is_deprecated, 0) = 0` 的读数 → 三个都成立才算落地。
- 落点：#362，前置 #398。
