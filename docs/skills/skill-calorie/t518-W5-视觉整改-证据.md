## 二 · B · 裁定 J（#466 量纲）

**裁定原文**（编排者 2026-09-16，逐字）：「`calorieDeficitEta` 门槛写『≥14 天**摄入+运动**记录』，读数写『N 天**摄入或运动**记录』——前后量纲词 AND／OR 不一致；实施席 ⑤ 只覆盖体重／摄入／营养目标三条路径。**裁定**：与『门槛与读数同一量纲』这条判据冲突 ⇒ **本票关票前修掉**，并按 #466 的判据补一条断言（该路径的红／绿两行机器读数）。」

**改法**（`src/analysis/simulate2.ts::calorieDeficitEta`，一行）：读数段 `df.length + ' 天摄入或运动记录'` → `df.length + ' 天摄入+运动记录'`。

**为什么是「改读数」而不是「改门槛」**：`deficit` 在 `series.ts:239` 的算法是 `calories === null ⇒ deficit = null` ⇒ 这一支能读到的天数**本来就是「摄入（＋运动）」那些天**，不含「只有运动、没有摄入」的天。量纲词写成并集（或）会把读者引到一个**不存在**的口径上（那几天既没进分子、也没进分母）；门槛的 AND 口径才是与算法同源的那一个。⇒ 统一到**交集口径**。

**断言件**：`packages/skill-calorie/test/analysis-deficit-eta-466.test.mjs`（**新增**，5 条：2 条 #466 ＋ 3 条 W5 视觉守卫）。#466 两条判的正是「可判真假」那两件：
- ① 门槛段的量纲词与读数段的量纲词**逐字相等**（剥掉数字与 `≥` 后比）；
- ② 读数＝`series[].deficit` 里**非空**的条数（不是窗口长度，也不是并集口径），并要求读数段**不许**出现「或运动」。

**红／绿两行（变异自证 m2，`.scratch/t518/W5-mut2.log`）**：

```

        build(mut) exit=0
MUT-RED  m2 :: 断言件 exit=1   AssertionError: 门槛与读数不同量纲（改前是 AND／OR 混用）：门槛=≥14 天摄入+运动记录 读数=13 天摄入或运动记录
RESTORE  m2 相等=true sha_after=a6af05b56197 字节 14855

```

**范围外发现（只登记）**：`src/render/insightPlate.ts:195` 的缺省文案写「数据不足，无法预测（需≥14 天摄入+运动记录）」——措辞与门槛同量纲（交集），**方向一致**，本窗未动。
