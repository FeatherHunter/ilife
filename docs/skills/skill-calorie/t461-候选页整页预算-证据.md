# t461 · 删照候选页体积退让（整页预算）· 证据件

票：`#461 场景 09：删照候选页体积退让（候选页 18.8 MB 超 1 MiB，比照 #438 口径）`（父图 `#159`）。

## 一、对抗式复核：缺陷今天还在吗 —— 在，而且已复现

先按要求「跑 `calorie.view.photo-picker`（隔离库造超预算数据）」。夹具：备份原样复制 ＋ 把候选窗内若干张
换成 **~390 KB**（都**小于** #527 当时设的单张上限 400 KB，即旧口径「合法内嵌」的那一档）。
**改前实测：产物 1,157,410 B ＞ 上限 1,048,576 B**（`.scratch/t461/probe-budget.mjs`，`RESULT: bytes=1157410 limit=1048576 over=1`）。

⇒ 结论：**真缺口**。票面说对了——#527 只给了「单张 400 KB」上限，整页字节仍可被多张累加顶破（1 MiB 上限管不到）。

## 二、改法（照 #438 口径，不另起一套）

`packages/skill-calorie/src/photo/pickerDoc.ts` 改成与 `galleryDoc.buildPhotoListDoc` **同一套**两步法：

1. **先算底子**：`shell(contentOf([], new Map()))` —— 不含任何候选内嵌字节的整页；
2. **再按预算逐张试嵌**：`embedPhotosWithinBudget(photosDir, v.candidates, baseBytes, PHOTO_LIST_PAGE_MAX_BYTES)`
   （`PHOTO_LIST_PAGE_MAX_BYTES` 从 `galleryDoc.ts` 引，**值不动**，仍是 1024*1024）；
3. **兜底三轮**：仍超限就逐轮收回最大的内嵌（`skipReason` 记「体积预算未内嵌」）；
4. **退让不静默**：页顶出 `notice()` 提示块（照 #438 的句形）「还有 N 张没进这一页」＋替代操作，
   退让那张在自己的格位上出**同规格占位件**并点名文件；读数卡「能看」只留**文件缺失**那一档（同一事实一页一处）；
5. `PICKER_INLINE_MAX_BYTES`（400 KB）**保留**给**快照**那一张用（它是「放大给你看」的价值核心，#461 不许削）。

**中途自查出一处自伤（已修）**：首版把快照的字节**无条件**计进底子——快照若是 3 MB 的原图（仍走占位、不上页），
这 3 MB 会把预算吃光，候选一张都嵌不进来（交付样张 09-14 当场从 361,420 B 掉到 95,156 B、缩略图 2 → 0）。
改法：**只有真会上页的字节才算进底子**（`snapInlined = dataUri != null && bytes <= PICKER_INLINE_MAX_BYTES`），
与 `snapshotHtml` 用**同一个判据**。修后两件交付样张**逐字节回到原值**（见 §四）。
