# #548 证据 · 定体重目标只给 kg 时不许抹掉 goal_deadline

现象（`.scratch/t548/probe.log` 的复现读数）：只给 kg 时 `calorie.goal.weight` 把 `daily_goal.goal_deadline`
写成 NULL，紧接着念「看即将到期的目标」exit 4「无到期目标（daily_goal.goal_deadline 缺失）」。

## 一、影响清单（一行一个件 ＋ 一句话理由）

- `packages/skill-calorie/src/goal/goalStore.ts`：`setWeightGoal` 的 SET 列表改按当刻传入的字段派生——没传的列**整个列不进 SQL**（不是写 NULL）；返回里新增 `written`，如实报本次进过 SET 的列表。
- `packages/skill-calorie/src/goal/write.ts`：回执 `writtenFields` 改报 `r.written`；三个可选参数「键在且不是 undefined」才进 `input`；摘要里「（截止 …）」只在本次真写过截止且有值时才出。
- `packages/skill-calorie/test/goal-weight-deadline-548.test.mjs`：新建四条用例（临时种子库 ＋ 真 CLI ＋ 只读回读）。
- `docs/skills/skill-calorie/t548-证据.md`：本件。

读过后确认不用动：`src/goal/set.ts:102-122`、`src/goal/goalExtraPlate.ts:38-58`、
`src/fetch/nutritionGoal.ts:68-89`（#127 的语义正本）、`src/weight/figures.ts:137-157`。

## 二、改法与判据

**`goalStore.ts`**：件内小件 `hasOwnInput(obj, key)` ＝ `Object.hasOwn` 且值不是 `undefined`——
「没传」（键不在，或 CLI 参数没给而调用方写成 `undefined`）＝不写这一列；
「传了空值」（`""`／`null`）＝按空值写（清空这一列，这是 `iso()` 改前就有的口径，本票不改）。
`kg` 恒写；`deadline`／`startKg`／`startDate` 各自独立判断，只把「键在」的列推进 `sets`／`vals`。
返回里新增 `written: string[]`；`deadline`／`startKg`／`startDate` 没写时回读原值上报（不把「没传」谎报成「写成了 null」）。

**`write.ts`**：调 `setWeightGoal` 前先把三个可选参数挑成 `input`（键不在就不放进去）；
`writtenFields: r.written`；删掉只此一用的 `provided` 导入。

**与调查结论的两处偏差（以源码为准，照 §1 要求说明）**：
① 调查结论给的 `hasOwnInput` 只判「键在不在」不够——`write.ts` 原先把四个键**无条件**写进 `input`
（`startKg: params['startKg']` 在没传时是 `undefined`），只判键会把「没传」认成「键在」，
实测四列全被写回 NULL（四条用例全红）。故 `hasOwnInput` 收成「键在且不是 undefined」，`write.ts` 同轮只放真键在的参数。
② 调查结论第三条预期 `CALORIE_TODAY=2026-09-07` 时 `daysLeft`＝12：`calorie.view.goal-expiring` 的「今天」
取机器时钟（`buildGoalExpiringView:42` 不读 `CALORIE_TODAY`），钉死天数会随跑测日期漂，用例只钉 `daysLeft` 存在，
另传 `withinDays: 365` 让窗口判据不飘。

## 五、没做／要接手的

- `affectedRows` 走 SQLite `total_changes()` 增量，只算「行」不算「列」：只改 `weight_goal` 也报 1。
  用例不拿它当「改了几个字段」的判据，字段多少只看 `writtenFields`。
- `startKg`／`startDate` 同一原则一起办到了（没传就不写那两列），但「起点体重→当前」那类页在老库上
  会继续沿用旧起点值——要不要另开票由编排者定，本票不改它的显示口径。
- `deadline:""` 的口径按旧 `iso()` 钉成「显式空串＝清空」；若编排者要「空串等于没传」，本条判据要反过来。
