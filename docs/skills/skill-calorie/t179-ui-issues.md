## 一、编排者已列的七条（逐条复核）

**1. 卡片小标题与表行直接露技术词 → 成立**
- 现象：卡下小字 `op=update`、`sqlite:total_changes`、`age、gender、heightCm、activityLevel`；表行 `记录 id`／`id 口径 = singleton`／表题 `档案现值（user_profile#1 单例行）`；眉标 `M5 契约 v1`、页尾标题 `M5 整行（旧版等价物）`。
- 不合理：这些是库列名、SQL 函数名与内部编号，用户（本人记账／健身用）读不懂，也不知道该拿它们做什么；页面上最该读的两行（发生了什么、写了哪些值）反而最难读。
- 建议：卡片小字改成「本次写入」「写入时间」这类人话或删掉；表行改「记录编号」并把 `id 口径` 整行去掉（单例行恒为 1，对用户无信息量）；`M5 契约 v1`／`M5 整行（旧版等价物）` 统一改成「对账信息」并收进页尾一个折叠区。
- 证据：`shots-ascii/receipt-set-390.png`（三张卡小字）、`shots-ascii/receipt-update-390.png`（页尾代码块）；源码 `packages/skill-calorie/src/profile/setup.ts:269-278`、`src/profile/update.ts:31-34,42`、`src/profile/view.ts:75`、`src/render/receipt.ts:70-72`。

**2. 英文枚举没本地化 → 成立**
- 现象：设活动量回执摘要 `已设活动量：moderate→very_active`；写入字段卡 `age、gender、heightCm、activityLevel`；结果页 `活动量 moderate`、`性别 male`；预检确认页「档案现值」表同样写 `moderate`／`male`。
- 不合理：这些值用户输入时说的是中文（界面自己就写「活动量（久坐/轻度/中度/活跃/高度活跃）」），出页却回英文；同页预检页的卡片已经写「中度活动」，说明中文说法现成。
- 建议：出页一律走中文映射——活动量用 `packages/skill-calorie/src/analysis/utils.ts:37-43` 现成的五档标签（久坐／轻度活动／中度活动／活跃／高度活跃），性别用 `src/render/wizardPort.ts:190` 现成的 `male→男／female→女`；写入字段卡与摘要改中文列名（身高／年龄／性别／活动量）。库里的英文枚举与 stdout 的 JSON 不动，只改给人看的那一层。
- 证据：`shots-ascii/receipt-activity-390.png`、`shots-ascii/view-profile-390.png`、`after-profile-wizard-seeded-390.png`；摘要源头 `src/cli/write.ts:836`（`'已设活动量：' + before + '→' + after`）、`src/cli/write.ts:232-235`（改档案逐字段对照拼原值）。

**3. 「无变化 否」是双重否定 → 成立**
- 现象：设置档案／设活动量回执的表末行 `无变化 | 否`；改档案回执把它做成一张卡：小标题「无变化」＋大字「否」。
- 不合理：要读两遍才知道「有改动」，而且「否」在两种排版里一个当表格值、一个当指标值与「1 行」「2 项」并列，读者会以为它是一个数量。
- 建议：改成一句直白的状态（`状态：已改动`／`状态：无改动`），或直接用状态徽章；不要既放卡片又放表行。
- 证据：`shots-ascii/receipt-set-390.png`（表末行）、`shots-ascii/receipt-update-390.png`（第四张卡）；源码 `src/profile/setup.ts:280`、`src/profile/update.ts:34`。

**4. 「动作」卡把动作名当指标值 → 成立**
- 现象：三张回执的第一张卡「动作／设置档案（小字 op=update）」，与旁边「影响行数 1 行」「写入字段 4 项」并列。
- 不合理：其余卡是量，这一张是名字，用户没法比较；页标题已经写着「设置档案 · 回执」，卡片重复一次标题。
- 建议：删掉这张卡（页面标题已表意），或把首卡改成状态类（把第 3 条的「已改动／无改动」放这里）。结果页同理：首卡小标题「档案视图」与页标题重复。
- 证据：`shots-ascii/receipt-set-1440.png`（三卡并排）、`shots-ascii/view-profile-1440.png`（首卡「档案视图」）；源码 `src/profile/setup.ts:269`、`src/profile/view.ts:61`。

**5. 顶部 M5 行层次最弱却信息最密 → 改口径**
- 现象：设置档案／设活动量两张把 M5 整行放在页副标题（15px 灰字，390 下折两行）；改档案那张把摘要放副标题、M5 行挪到页尾浅灰代码块。副标题里的「影响 1 行」「字段 age,gender,heightCm,activityLevel」与下面两张卡是同一份数据。
- 不合理：真正的毛病不是「层次弱」，而是①同一数据在一页出现两遍（副标题＋卡片），用户要判断哪个算数；②三张同类页把同一行摆在两个不同位置，每次都要重新找。
- 建议：副标题只留一句人话（如「已写入你的基础档案」），M5 整行统一收进页尾「对账信息」折叠区（三页同一位置），卡片保留「影响行数／写入字段」。
- 证据：`shots-ascii/receipt-set-390.png` 与 `receipt-update-diff-390.png` 对照；源码 `src/profile/setup.ts:295`（副标题＝m5Line）vs `src/profile/update.ts:42,54`（页尾 pre 块＋摘要副标题）。

**6. 缺「复制日志」 → 成立**
- 现象：五张页都只有「复制数据」一个按钮（探针实测交互件：四张回执 1 个、结果页 2 个＝复制按钮＋折叠区标题）。
- 不合理：出问题时要靠日志复盘（复制出去的是 `ok: true` ＋ 一句摘要，看不到字段与命令），老技能有「复制数据 ＋ 复制日志」两个必备按钮。
- 建议：**只登记一条**——「复制日志」等通用组件落地后接入，本票不设计该组件。公共层已经备好：`renderCopyBlock` 支持 `logText`／`logActionId`，缺省文案「复制日志」就在 `ACTION_BAR_DEFAULTS.copyLogLabel`。
- 证据：`packages/base-render/src/blocks.ts:592-627`（给了 `logText` 就出第二个按钮）、`packages/base-render/src/spec/controls.ts:274-275`；页内现状 `dataCopyArea('复制数据', …)` 只给数据（`src/shared/docPage.ts:68-70`）。

**7. 桌面端复制按钮 40px → 改口径**
- 现象：390 档实测按钮 358×44（达标）；1440 档 520×40，探针在四页的 1440 档各报「不足 44 的 1 个」。
- 判定：桌面鼠标场景不必 44px（44 是触控口径），`packages/base-render/src/style.ts:339-344` 已明写「窄屏抬到 44px，桌面沿用冻结值 40px」，#179 的交付口径也照此写。所以**页面不算错**；冲突在**本图 #152 的 UI 硬门槛文字**——它写「触控目标 ≥44px」且不分宽度档，量测脚本因此在 1440 报不达标。
- 建议：本票不改页面、不动共享层冻结值；把门槛文字改成「窄屏 ≥44px／桌面 ≥40px」，或另立共享层票改 `ACTION_BAR_DEFAULTS.minHeightPx`。本条按「待裁决的口径冲突」写进新票，不当缺陷修。
- 证据：`.scratch\t179\shots179.log` 四页 1440 行、`.scratch\t179\shots179\设置档案回执-1440.json:16-23`（`w:520,h:40`）；`packages/base-render/src/spec/controls.ts:273-279`。

## 二、本次新查出的条目（编排者未列）

**8.【新】一页之内同一数据两种写法 → 成立**
- 现象：预检确认页（有档案那份）上方卡片写「当前活动量 中度活动」，同一页「档案现值（改前值）」表里写 `moderate`；性别卡片在别页写 `male`，而本技能别处已写「男」。
- 不合理：同一页自相矛盾，用户会以为这是两个不同字段；本地化只做了一半。
- 建议：档案现值表也走第 2 条的中文映射（`src/profile/setup.ts:188` 取值处统一过映射）。
- 证据：`after-profile-wizard-seeded-390.png`（卡「中度活动」＋表 `moderate` 同屏）；源码 `src/profile/setup.ts:233`（已映射）vs `:188`（原值）。

**9.【新】复制区的三处排布问题 → 成立**
- 现象：①标题与按钮同名重复——先一行黑体「复制数据」，再一颗胶囊按钮也写「复制数据」（预检确认页两组都是）；②桌面端内容左对齐（x=240）而按钮居中（x=460 起、520 宽），与卡片／表左界不齐；③预检确认页两个复制区规格不一：`复制 prompt（必走）`是 12px 灰小标题、按钮却叫「复制指令」，下面 `复制数据` 是黑体大标题＋按钮同名，「prompt／指令／数据」三套叫法。
- 不合理：同一功能在一页里有两种标题规格、两种叫法；居中按钮让页面左右都不齐。
- 建议：标题与按钮二选一（留按钮、标题写成「复制」或去掉）；按钮与内容左界对齐（或整块居中）；预检确认页两处统一成一个规格与一个叫法（建议按钮都用「复制指令／复制数据」，标题只留一处）。
- 证据：`shots-ascii/receipt-set-1440.png`（标题左、按钮居中）、`after-profile-wizard-empty-1440.png`（两组不同规格）；实测 `.scratch\t179\shots179\设置档案回执-1440.json:79-96`（action-bar x=460 w=520 vs body x=240）。

**10.【新】预检确认页折叠标题写死「空库无改前值」，有改前值时照写 → 成立**
- 现象：有档案那份页面的折叠标题仍是「改档案 5 项（另含备注；空库无改前值）」，而同页卡片写着「改前值 有／档案已在库」。
- 不合理：同一页两句话互相打架，用户会怀疑自己的档案到底在不在。
- 建议：标题按状态分支（空库才写「空库无改前值」；有档案写「参考上方改前值」），或直接去掉括号后半句。
- 证据：`after-profile-wizard-seeded-390.png`（标题与卡片同屏）；源码 `src/profile/setup.ts:238`（静态标题）。

**11.【新】空值四种写法＋两张常空卡 → 成立**
- 现象：同一产品里「没有值」写成四种：预检确认页「改前值 无」、结果页「目标 未设」、结果页「最新体重 —」、回执表兜底 `n/a`；预检确认页五张卡里「当前活动量」「最近体重」在空库时都是「—」，390 档第三行只剩「最近体重」一张卡独占一行。
- 不合理：用户分不清「无／未设／—／n/a」是不是同一件事；两张空卡的占位比信息多。
- 建议：统一成一个词（建议「未填写」或「未设置」）；空库时把「当前活动量／最近体重」两张卡改成一句空态说明，或与「改前值」卡合并。
- 证据：`after-profile-wizard-empty-390.png`（第三行孤卡）、`shots-ascii/view-profile-390.png`；源码 `src/profile/setup.ts:231-234,277`、`src/profile/view.ts:63-64`。

**12.【新】眉标把英文词渲染成全大写，且眉标本身写的是流程 → 成立**
- 现象：预检确认页眉标显示「基础信息 · 写前预检（填表→复制 PROMPT→AI 写库）」（源码是小写 `prompt`，共享样式的 `text-transform: uppercase` 把它抬成全大写）；回执页眉标写「M5 契约 v1」。
- 不合理：中文页面里突然出现全大写英文（还有「AI 写库」「prompt」「M5 契约」），像开发日志；眉标本该只标明这页属于哪个功能。
- 建议：眉标只留「基础信息 · 预检确认」／「基础信息 · 写后回执」；流程说明与 `M5 契约` 字样移进对账折叠区；共享样式的 `text-transform: uppercase` 对中英混排眉标要么去掉、要么只对纯英文标识使用。
- 证据：`after-profile-wizard-empty-390.png`／`-1440.png`（`PROMPT`）；源码 `src/profile/setup.ts:259,294`，样式实测产物 `.ilife-block-page-shell-eyebrow{text-transform:uppercase}`。

**13.【新】复制出去的文本，页名一处是中文动作名、一处是内部命令名 → 待定（低优先）**
- 现象：三张回执复制出来是「【calorie · 设置档案】／【calorie · 设活动量】／【calorie · 改档案】」，结果页与预检确认页复制出来是「【calorie · calorie.view.profile】／【calorie · calorie.view.profile-wizard】」。
- 不合理：这段文本会粘进对话里给用户看到，内部命令名对用户没有意义，还与另外三页不成一体。
- 建议：页名统一写中文（结果页写「查档案」、预检确认页写「档案预检」）。**注意**：这一处只在粘贴后可见，不是页面上的可见文案，优先级低。
- 证据：`src/profile/view.ts:85`、`src/profile/setup.ts:243` vs `src/profile/setup.ts:286`、`src/profile/update.ts:45`。

**14.【新】预检确认页给用户的 prompt 话术不通顺 → 成立**
- 现象：复制出去的话术是「请帮我改档案到卡路里」（另两条同理「设置档案到卡路里」「设活动量到卡路里」）；同一段里还有半角冒号与全角冒号混用（`- 写入词:改档案` 与摘要里的 `：`）。
- 不合理：这是用户要粘给 AI 的原话，读起来不像人话（「到卡路里」是内部系统说法）。
- 建议：改成「请帮我把卡路里的基础档案改成下面这些值」这类自然句；标点统一。
- 证据：`after-profile-wizard-seeded-390.png`（代码块首行）；源码 `src/profile/setup.ts:139-142`。

**15.【新】预检确认页活动量五档表：一列五行同一句话 → 成立**
- 现象：「TDEE 影响」列五行全是「—（缺身高/年龄/性别/体重，不算）」；列头写「入库值」「TDEE 影响」，表题写 `TDEE ＝ 基础代谢（Mifflin-St Jeor）× 系数`。
- 不合理：五行同字既占宽又没信息量；「入库值」「TDEE」「Mifflin-St Jeor」对用户是天书。
- 建议：整列缺数据时只写一句（如列头下注「缺体重，暂不算」）或整列收起；列头改「写入值」「预计每日消耗」，公式收进折叠区的说明行。
- 证据：`profile-wizard-empty.html`（表体）/ 源码 `src/profile/setup.ts:194-207`。
