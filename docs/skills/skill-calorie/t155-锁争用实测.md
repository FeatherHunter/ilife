## 三、成因（可修）

`522` 与 `523` 的运行形如：

```
tooling/run-locked.mjs --ticket 522 --child-timeout-ms 2700000 -- dsh --profile visionreview "…"
```

⇒ **一整个代理会话跑在门锁里面**。它单次平均持锁：523 约 53 s／次（21 次），522 约 253 s／次（6 次，最长 25 分钟）。

**而这件活按本仓自己的规矩不需要持锁**：`docs/agents/视觉验收墙.md` §5 明说"墙页与产物落 `.scratch/`（不必入仓）"、"生成器脚本入仓"——渲染 HTML、截图、滚墙**都不改工作区**，按 `subagent-concurrency-protocol.md` §2 的清单，它们是"不需要持锁"的那一类。

## 四、建议（需要跨 session 决定，故上报）

1. **把视觉复核移出门锁**：只在该会话真正写文件的那几秒持锁；渲染与截图一律不持锁。**这一条预计把 71% 的锁时间还给所有票。**
2. 若不能改，**把两条线错开时段**。
3. 本图的自我约束（不等对方改也能做）：席位不发超过锁的吞吐；每次持锁只做一件小事；抢锁一律 `--poll-ms 2000`。
