## 三、失真读数、失真原因、判定

- **正确读数**：`food_log 行数=306`、`id=306`、`note=""`（空串）；页上 9 格 vs 库内那一行 **9/9 一致**、`mismatch=[]`。
- **失真读数**：`行数=76`、`id=76`、`note=null`（该行还把库行 JSON 里的 `sodium_mg`／`sugar_g`／`fiber_g`／`created_at`
  四个字段省略掉、并在中段写成 `...` 省略号，与 probe.log 的原字节 JSON 也不相同——属**抄录时改写**的第二处痕迹）。
- **失真原因**：**形似把 75 天循环当行数**——300（＝75×4）与 305（＋饮水）都在同一量级，
  而 76 与 75 只差 1，像是把「75 天」这个循环上界当成了行数、或把 `75 天 × 四餐`里的小数误记，
  既不合 306 也不合 305；从「76 = 75 + 1（写进的那一行）」这种半对半错的形态看，是把**天数**当成了计数单位，
  再随手加上本次写入的 1 行。无论取哪种解释，它与落盘产物都不相等。
- **判定**：这是一处**记录失真（转录差错）**，不是产品缺陷：
  - 产品行为由落盘产物作证（`probe.log`／`probe-summary.json` 双证，读数 306／9/9），**未受影响**；
  - 失真只落在证据件 §4 的那一行抄录文字上；
  - **不影响 #603 的其余结论**：该探针的结论（裁定4 的 9 行表逐格等于库内那一行，9/9、不符 0）在失真行之外的
    L190／L34／L12／L221 各处写的都是 **9/9**，与落盘产物一致，未被这行带偏；PASS 与五维打分的依据（门禁 83/83、
    族测试 269/267/2、场景10 82/79/3、边界两路、变异红绿两行）**都不引用这一行的 76**。
- **更正触达范围（本席自己 grep 核过）**：失真值只出现在证据件 L184 **一处**（对全文 `76` 逐行点过：另三处
  L136／L157／L158 分别是 hunk 行号与页 sha 子串，与本行无关）；该失真自原提交 `eb43611d` 起即存在，
  证据件的三笔后续提交（blob `6fc1254c`→`378a6bb5`→`52bf393f`）都**没有动过 L184**，故至今未更正。
