## 1. 营养目标算式

两条路：手工指定（只做自洽性检查）和智能推荐（G1.2，三套模板 + 档案推算）。

### 1.1 手工设置：不推荐，只查自洽

`set_nutrition_goal(calorie_goal, protein_goal, carbs_goal, fat_goal, water_goal=None)` — `nutrition_goal.py:41`

- 四个数原样落 `daily_goal`（固定 id=1），`water_goal` 可选（`nutrition_goal.py:90-99`）
- 自洽性：`calculated = protein_goal*4 + carbs_goal*4 + fat_goal*9`，`diff = calculated - calorie_goal`（`nutrition_goal.py:84-85`）
- 判定线 `abs(diff) <= 50`：合规才打印 `自洽性：换算 X 卡（差异 ±Y）✅`（`nutrition_goal.py:111-112`）；**不自洽时一句都不打印**——文件头注释写着「相差 > 50 卡给警告」（`nutrition_goal.py:12`），实现里没有这句警告

### 1.2 推荐值（G1.2）：`recommend_nutrition_goal`

签名 `recommend_nutrition_goal(profile='cut', weight_kg=None, height_cm=None, age=None, gender=None)` — `nutrition_goal.py:186`；`profile` 必须是 `cut`/`maintain`/`bulk`，否则 `raise ValueError`（`nutrition_goal.py:197-198`）。

**第一步 · 定四个基础数**（`nutrition_goal.py:200-207`，取值来源见 `_profile_basis` `:154-183`）

| 项 | 来源顺序 | 兜底 |
|:--|:--|:--|
| 体重 w | 显式参数 → 最新一条 `weight_log.weight_kg`（`ORDER BY date DESC, id DESC`，`:147`） | `70.0` |
| 身高 h | 显式参数 → `user_profile.height_cm` | `175.0` |
| 年龄 a | 显式参数 → `user_profile.age` | `30` |
| 性别 g | 显式参数 → `user_profile.gender` | `'male'` |
| 活动量 | `user_profile.activity_level` | `'moderate'` |

**第二步 · 基础代谢与每日消耗**（`nutrition_goal.py:209-211`）

```
bmr  = 10 * w + 6.25 * h - 5 * a + (5 if g == 'male' else -161)   # Mifflin-St Jeor
tdee = bmr * get_activity_factor(activity_level)                   # 活动系数
```

活动系数唯一来源 `analysis._utils.get_activity_factor`（`nutrition_goal.py:21`）；档案读不到或该列为空时用档位 `'moderate'`（`nutrition_goal.py:157`、`:178`）；导入失败时回退常量 `1.55`（`nutrition_goal.py:23-24`）。

**第三步 · 按模板分配**（`nutrition_goal.py:213-218`）

```
cal     = int(tdee + calorie_adj)
protein = int(w * protein_g_per_kg)
fat     = int(cal * fat_pct / 9)
carbs   = max(int((cal - protein * 4 - fat * 9) / 4), 0)
water   = int(w * water_ml_per_kg)
```

模板常量，照抄 `nutrition_goal.py:133-140`：

| 模板 | 中文名 | calorie_adj | 蛋白 g/kg | 饮水 ml/kg | 脂肪占比 | 每周速率 kg |
|:--|:--|--:|--:|--:|--:|--:|
| `cut` | 减脂 | `-500` | `2.0` | `35` | `0.25` | `0.5` |
| `maintain` | 维持 | `0` | `1.6` | `30` | `0.30` | `0.0` |
| `bulk` | 增肌 | `+400` | `1.8` | `30` | `0.25` | `0.4` |

中文名表 `PROFILE_LABELS`（`nutrition_goal.py:138`）；每周速率表 `PROFILE_WEEKLY_RATE`（`nutrition_goal.py:139-140`），注释给的换算式是 `kg/周 ≈ 热量缺口 × 7 / 7700`。

几条硬事实：
- **碳水没有独立常量**，一律取余量 `(cal - 蛋白×4 - 脂肪×9) / 4`，下限 0（`nutrition_goal.py:217`）
- 脂肪按**热量的百分比**折 9 kcal/g（`nutrition_goal.py:216`）
- 蛋白和饮水都按**体重 kg** 折算（`nutrition_goal.py:215`、`:218`）
- 全部 `int()` 截断，顺序不能换：先算 cal，再算 lipid，最后用截断后的整数算碳水

**自洽性校验**（推荐路径）：`calculated = protein*4 + carbs*4 + fat*9`，`diff = calculated - cal`（`nutrition_goal.py:221-222`）；`abs(diff) > 50` 时往 `plan_reasons` 追加一行 `⚠️ 自洽性校验：宏量换算 X 卡，与热量目标差 ±Y 卡（>50 建议复核）`（`nutrition_goal.py:231-232`）；返回值另带 `self_check: {calculated_kcal, diff_kcal}`（`nutrition_goal.py:248`）。

**返回结构**（`nutrition_goal.py:234-249`）：`profile`、`profile_label`、`tdee`、`bmr`、`calorie_goal`、`protein_goal`、`carbs_goal`、`fat_goal`、`water_goal`、`weekly_rate_kg`、`basis{weight_kg, height_cm, age, gender}`、`plan_reasons`、`missing`、`self_check`。人话解释共 5 行（`nutrition_goal.py:224-230`），第 5 行写作 `预计每周减重速率 X kg（Δ{cal} - TDEE {tdee}）`。

## 2. 体重目标算式

全在 `weight_goal.py`（169 行，写入 `:32`、读取 `:78`）。这个文件**没有** `if __name__ == '__main__'` 段，只有函数。

### 2.1 输入四项与缺省

`set_weight_goal(weight_goal, deadline=None, start_weight=None, start_date=None)` — `weight_goal.py:32`

| 项 | 缺省怎么取 | 依据 |
|:--|:--|:--|
| 目标 kg | 必传，**不校验正负、不校验离谱** | `weight_goal.py:32`、`:51-55` |
| 截止日 | 可不传，存 NULL | `weight_goal.py:32`、`:53` |
| 起点体重 | 不传 → 最新一条 `weight_log.weight_kg`（`ORDER BY date DESC LIMIT 1`，**没有 id 次序**）；连一条体重记录都没有 → **起点体重直接等于目标体重**（自指） | `weight_goal.py:46-48` |
| 起始日 | 不传 → 今天 `date.today().isoformat()` | `weight_goal.py:49-50` |

落库：UPDATE `daily_goal` id=1 的 `weight_goal / goal_deadline / start_weight / start_date`，影响 0 行则 INSERT（`weight_goal.py:51-62`）。

⚠️ `start_weight` / `start_date` **只写不读**：算进度用的是「最新一条体重记录」，不是设的起点。

### 2.2 进度与建议速率

`get_weight_goal()` — `weight_goal.py:78`，返回五元组 `(weight_goal, deadline, days_left, None, calorie_adjustment)`。

```
current_weight, current_date = 最新一条 weight_log（ORDER BY date DESC LIMIT 1）   # :96
days_left = (deadline - current_date).days                                        # :109-111
gap              = current_weight - weight_goal     # kg，正数 = 要减            # :116
required_daily   = gap / days_left                  # kg/天                       # :117
calorie_adjustment = int(required_daily * 7700)     # kcal/天，正数 = 要造缺口     # :118
```

- 常量 **`7700 kcal/kg`**（`weight_goal.py:8` 文档、`:118` 使用）
- 第 4 位 `daily_change_rate` **恒为 None**，是留空位不是算出来的（`weight_goal.py:121`）
- `current_date` 用的是**最新一条体重记录的日期**，不是今天（`weight_goal.py:96-110`）——体重要是三天没记，天数就从三天前起算
- 只有 `days_left is not None and days_left > 0` 才算速率（`weight_goal.py:115`）

返回 None / 三项 None 的分支：
- 没设目标（无行或 `weight_goal` 为空）→ `None`（`weight_goal.py:90-92`）
- 设了目标但没有一条体重记录 → `(weight_goal, deadline, None, None, None)`（`weight_goal.py:98-100`）
- 截止日格式非法（非 `%Y-%m-%d`）→ 静默 `days_left = None`，不报错（`weight_goal.py:112-113`）

### 2.3 速率合理性的安全范围与提示文案

安全线 **`±1000 kcal/天`**，作用在**换算后的热量调整**上，不直接作用在 kg/周上。判定与文案在 `print_goal_progress`（`weight_goal.py:157-167`）：

| 条件 | 输出文案 |
|:--|:--|
| `calorie_adj > 1000` | `⚠️ 警告：每日需增加 {calorie_adj} kcal 缺口（极端目标，建议调整目标或延期）` |
| `0 < calorie_adj <= 1000` | `建议：每日需增加 {calorie_adj} kcal 缺口` |
| `calorie_adj == 0` | `状态：完美匹配，按当前节奏可达成目标` |
| `-1000 <= calorie_adj < 0` | `建议：每日需减少 {abs(calorie_adj)} kcal 缺口（当前进度超前）` |
| `calorie_adj < -1000` | `⚠️ 警告：当前进度大幅超前，建议适当增加摄入` |

边界细节：
- `1000` 和 `-1000` **本身不算警告**，判据是严格大于／严格小于（`weight_goal.py:158`、`:162`）
- 判定用的是 `int()` 截断后的值，所以 `required_daily * 7700` 落在 `1000..1001` 会被截成 `1000`，不触发警告
- 报告里另有一行按 kg 打印："每日需减/增 X kg"（`weight_goal.py:155-156`），取的是 `abs(required_daily)`，正负决定写「减」还是「增」

不设目标时的提示（`weight_goal.py:128`）：
`⚠️ 未设定体重目标，请说「设定体重目标 73kg」或「设定体重目标 73kg 目标日期 2026-07-01」`

没有体重记录时（`weight_goal.py:140`）：`⚠️ 未记录体重，无法计算进度`

### 2.4 按 kg/周 的建议速率

`weight_goal.py` 里**没有**按 kg/周的推荐值，也没有 kg/周的安全区间。这四份文件里唯一的 kg/周常量是模板表 `PROFILE_WEEKLY_RATE`（`nutrition_goal.py:139-140`）：

- 减脂 `0.5`、维持 `0.0`、增肌 `0.4`
- 换算式写在注释里：`kg/周 ≈ 热量缺口 × 7 / 7700`（`nutrition_goal.py:139`）
- 是**写死的常量**，不是运行时算的：`-500 kcal` 对应 500×7/7700 ≈ 0.45 → 记 0.5；`+400 kcal` 对应 400×7/7700 ≈ 0.36 → 记 0.4

所以「建议速率」在新仓里只有两套口径：模板固定的 0.5/0.0/0.4 kg/周，和体重目标反推的 `gap / days_left`（kg/天，再乘 7700 转成热量调整）。两者之间老技能没有任何一致性检查——定体重目标时不会拿 0.5 kg/周去比。

## 3. 缺失与边界

总口径先说结论：**推荐路径编默认值 + 记一份缺项清单，绝不报错**；**手工设置路径硬报错，直接 `return False`**。没有任何一处写「缺×不算」。

### 3.1 档案缺项：`_profile_basis` 的完整逻辑

`_profile_basis(weight_kg, height_cm, age, gender)` — `nutrition_goal.py:154-183`

1. 默认值先放调用方传进来的值（`nutrition_goal.py:156-157`）：
   `{'weight_kg': weight_kg, 'height_cm': height_cm, 'age': age, 'gender': gender, 'activity_level': 'moderate'}`
2. 查 `user_profile` id=1 的 `age, gender, height_cm, activity_level`（`:161`），查询异常或表不存在按"没有行"处理（`:162-163`）
3. **读不到行** → `missing = ['年龄', '性别', '身高']`（`:179-180`）。此时调用方显式传入的 age/gender/height 仍然留在默认值里，而且**不会被记进 missing**——这是 `:156` 先铺值、`:179` 才覆盖 missing 的先后造成的
4. **读到行但某列为 NULL** → 逐列记进 missing：年龄 `:168-169`、性别 `:170-171`、身高 `:174-175`
5. `activity_level` 为 NULL 或没有行 → 取档位 `'moderate'`，**不记 missing**（`:178`）
6. **体重不来自 `user_profile`**，来自参数或 `weight_log` 最新记录（`:200-201`）；为 None → `missing.append('体重')`（`:181-182`）

紧接着无条件兜底（`nutrition_goal.py:204-207`）：

```
w = defaults['weight_kg'] or 70.0     # 缺体重 → 70 kg
h = defaults['height_cm'] or 175.0    # 缺身高 → 175 cm
a = defaults['age']       or 30       # 缺年龄 → 30 岁
g = defaults['gender']    or 'male'   # 缺性别 → male
```

由此四条边界：

| 四要素缺口 | 老技能怎么办 | 依据 |
|:--|:--|:--|
| 缺身高 | 编 `175.0`，同时在 `missing` 里写「身高」 | `:174-175`、`:205` |
| 缺年龄 | 编 `30`，同时在 `missing` 里写「年龄」 | `:168-169`、`:206` |
| 缺性别 | 编 `'male'`，同时在 `missing` 里写「性别」 | `:170-171`、`:207` |
| 缺体重 | 编 `70.0`，同时在 `missing` 里写「体重」 | `:181-182`、`:204` |
| 档案整表读不到 | 三要素全进 missing，`activity_level` 取 `'moderate'`（**不进 missing**），推荐照常出 | `:179-180`、`:178` |
| 缺活动量 | 静默取 `'moderate'`，不记 missing | `:157`/`:178` |

要紧的点：
- **不报错**。档案全缺也照样返回完整推荐（`:234-249`），`missing` 只是一个字符串列表（`:247`），没有任何确认命令拦着。
- **不写「缺×不算」**。算法全程用兜底值参与计算，BMR、TDEE、宏量都照算。
- 判空用的是 `or`，所以 **0 值也算缺**：身高 0、年龄 0、体重 0 都会被换成兜底值。
- `missing` 的文案是中文短名：`年龄`／`性别`／`身高`／`体重`（`:169`、`:171`、`:175`、`:182`）。

### 3.2 性别判定的边界

`(5 if g == 'male' else -161)`（`nutrition_goal.py:210`）：只有字符串**正好等于** `'male'` 才按男性算；`'female'`、`'女'`、`''`、其它写法一律走 `-161`（女性项）。也就是说除了 `'male'` 以外，**所有非空值都当女性**，没有第三分支，也没有报错。

### 3.6 `goal_manager.py` 与算式无关

它只做暂停／恢复／查状态三件事，写 `daily_goal.goal_paused`（1=暂停，0=正常，`goal_manager.py:4-6`、`:59-63`、`:87-91`）。不参与任何推荐值或校验算式。暂停时的口径是「记录照常，仅目标暂停（完成度显示不计入暂停期）」（`goal_manager.py:74`），恢复提示说「重启所有目标」（`:75`）。另：目标全未设时 `get_paused_state` 返回 `{'paused': False, 'paused_at': None}`（`goal_manager.py:46-47`）；查表异常返回 None（`:42-44`）。
