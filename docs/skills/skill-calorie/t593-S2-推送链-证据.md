## 三 · 票内定的口径

### 1. 请求形状（票面逐字落实）

- 接口 `POST https://trains.xunjiapp.cn/api_upsert_trains_for_llm_v2`（老 `upsert.py:53-54`）；
  包体五键 `schema_version=train_open_api_v2／client_request_id／dry_run／include_full_data／res`（老 `:90-96`）；
- `res[].datestr` 用传入 `YYYY-MM-DD` 原样（**不转时间戳**，老 `push.py:104`），同串进幂等键前缀（老 `:153`）；
- `localid=0`（新建；更新语义归 #610 的 `overlay-plan`）、`start=end=0`（老 `:105-108`）；
- `movements[].name` **原样上报**（老 `push.py` 不 import `catalog`；`t607` 故意送`不存在动作XYZ`并断言原样发出）；
- set 只留 `done=false＋weight＋unit＋reps`（老 `:95-100`），`weight` 缺时回退 `load`，缺省 `"0"／"kg"／"0"`；
- `client_request_id` 缺省自动生成（老 `upsert.py:77-79`）；`push` 按 session 现生成 `{date}_{label}_{uuid8}`（老 `push.py:153`）。

### 2. 限频档位决议（票面点名“本票内定”）

- **按段逐个守**：每次 upsert 调用前都看“距上次过去了多久”，窗内睡够再调（老“睡够再调”保留，`push.py:157-158`；`--dry-run` 不守不记，老 `:156` 同述）；
- **跨天／跨进程也守**（把“跨天不守”当缺陷修掉）：上次时刻落盘 `~/.mavis/xunji_push_rate.json`
  （与读侧 `xunji_bridge_rate.json` 分开，老 `auth.py:40` 同目录先例），不同进程的两次 `push-plan` 照样排开；
- 老明确不守的三处保留：`--dry-run`（老 `:156`）、`overlay-plan`（单次调用，归 #610）、读侧 15s/30s 缺省关（归 #608）；
- 代价诚实写明：N 天×多段的串行推送总等待变长（正确性优先；`run-sync` 归 #610，届时照此口径排队）。
