## 二、老实物口径（新仓对账点，出处精确到行）

1. **紧迫度**（`render_goal_progress.py:353-360`）：`days_left<=3`→高；
   否则 `rate_needed>1.0`→高、`>0.5`→中、其余低；
   `rate_needed=(current-weight_goal)/(days_left/7)` 且只在 `need>0` 时算（`:349-352`）；
   表头口径句 `:373`。新仓 `buildGoalExpiringView`（`goalExtraPlate.ts:38-58`）**没有紧迫度字段**，
   整页只分 `expiring` 两态——票面要的“紧迫度”在新仓是缺口，整页化时只补呈现（取数口径另开票裁）。
2. **偏差**（`render_goal_progress.py:251-293`）：`pct=实际/目标*100`（`:263`），
   偏差行 `pct%`（`:268`），平均偏差 `mean(pct-100)`（`:272`，结论句 `:292`）。
   新仓 `GoalVsActualView` 走 80%-120% 完成带＋`trendAvg`（`goalExtraPlate.ts:107-136`），
   页上无“平均偏差”一行——同上，呈现缺口记账，不在本票取数内。
3. **预测日与置信度**（`render_goal_progress.py:420-454`）：达成日复用 `weight_milestone.est_date`；
   置信度按 `|actual_daily_change_kg|>0.02`→高、否则中、缺省低（`:435-437`）。
   新仓 `weightTarget`（`simulate.ts:114-135`）是线性外推＋`eta=末日+round(daysLeft)`，
   `feasible=0.5-1.0kg/周`，`:119` 注释承认与老家有意偏离——“预测日口径一致”的断言只能钉
   新仓自己的 `eta/daysLeft/ratePerWeek` 可复跑值，不能写成“与老家同值”。
4. **体重进度完成%**（`render_goal_progress.py:481-486`）：`(起点-当前)/(起点-目标)*100`，
   起点取 `daily_goal.start_weight` 快照，缺失显 `—` 不回退（`:473-474` 注释）。
   新仓 `buildGoalWeight` 无完成%字段——同 §二.1 处理。
