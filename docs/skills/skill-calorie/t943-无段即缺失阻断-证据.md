# #943 · 落地训练族：无段可落地即缺失阻断（不再回成功回执页）

现场来源：用户报「执行落地训练，无论什么异常都给一张虚假数据的回执 html；无计划可以落地，拿到的是演练版本」。
调查件：`docs/skills/skill-calorie/落地训练-预演回执-调查.md`。本件只记**改动与判据**。

## 一、改了什么（一句话）

「落地训练」「落地到本周末」「落地到本月底」在**该日期／该范围里一段可落的训练段都没有**时，
不再回 `ok:true` ＋ `items[0].status='成功'` ＋ 整页回执，改按技能冻结的缺失阻断口径报出：
`fail(4, '…没有可落地的训练段：<为什么 ＋ 下一步>')`，不落页、不进任何子进程。
连带：批量实跑**只跑有训练段的天**（休息日跳过），于是推送／回写天数不再把休息日数成「已落地的一天」。

## 八、#7 · 「例」列两态：能翻的翻成实跑，翻不动的把两态写进技能面

**先纠正票面记的根因**：票面写「根因＝`#99` 示例门 ＋ 种子无 `xunji.key`」。实测比这多一层——
**给种子补上训记挡板（`xunji.cli` 指 fixture）之后，落地链仍然过不去**：

```

```

第一步「补计划」调的是**作息技能** `schedule.plan.write`，它的远端门要本机 `lark-cli` 已登录
（`packages/skill-schedule/src/fetch/feishu.ts:157`；本地写照走、远端不在场即 `exit` 非 0，是裁定 A6② 的设计）；
而 `#757` 已把跨技能出口的配置缝删掉（改成按包布局推断），种子**没有**可用的挡板口——
要挡只能往兄弟包的 `dist/cli/cmd_read.js` 里塞文件（共享工作区里动别人产物，不接受）。

**因此**：「落地那三条示例＝实跑形态」在 `#99` 门规下**结构上做不到**（门要「照抄即跑 ⇒ exit 0」，
而这条链的第一步在这套环境里必然非 0）。落到实处的改法：

1. **能翻的两条翻成实跑形态**：`calorie.workout.xunji-push`／`calorie.workout.xunji-backfill`
   只碰训记，种子的训记入口可按配置指挡板（生产自己留的那一个口，`xunjiRunner.ts` 件头）——
   示例现在是 `--params '{"date":"<日期>"}'`（实跑），照抄即真同步／真拉取。
2. **落地三条保持预演形态**（`dryRun:true`），并把**两态写进 `SKILL.md`「联动速查」节首**
   （在 AUTO 标记之外，重生成不会冲掉）：例＝预演（只看不写）；**要真落地就把 `dryRun` 去掉**，
   预演页第一位也印着实跑命令原文；并写明这条链要往外写三处（作息写飞书日历要本机飞书命令行已登录／备忘／训记要 KEY）。

## 九、#8 · 调查结论：`calorie.workout.xunji-push` 的「0 段」同类形态

**是同一类，危害小一档，改法可与 #943 对齐。**

- `src/workout/xunjiPush.ts:72-79` 的 `daySessions` 与落地链原来那副同形：只在「无计划／缺开始日期」抛 `exit 4`，
  空天回空表；`:132-152` 的 `writeXunjiPush` 之后**无条件**调 `push-plan`，拿 0 段读数也回
  `ok:true` ＋ `items[0].status='成功'` ＋ 整页（页上 KPI 写「待推送段 0 段／当天没排练（空天）」）。
- 与 #943 的差别：0 段时它**不写任何东西**（`push-plan` 空调用），而落地链 0 段时还会去推送／回写；
  它也没有批量那种「把空天算成已落地一天」的错账。
- 现状被用例钉着：`test/t614-同步与拉取.test.mjs:136` ①b「push dryRun 空天走通（这天没排练，段数 0，**仍 exit 0 口径**）」。
- 另一条 `xunji-backfill` 不读计划（它读训记），**不吃**这一形态。
- 建议（待裁定）：照 #943 同法——这天 0 段即缺失阻断 `exit 4` 点名；同批把 `t614` ①b 翻过来。**本票不动**。
