# 命令登记纪律

**这份管什么**：一条命令的事实**住哪儿**、汇总位**谁生谁改**、老命令**谁搬谁删**。
范围＝ `packages/skill-calorie`。其他技能包（bill／chef／home／schedule／memo）照这份执行时，
把下面所有 `calorie` 字样换成本件名即可——本份只管形状，不管那份的命令内容。

**最长的一句**：**一条命令的事实只有一个定义地，就是它自己的能力目录；所有汇总位都是那个定义地的派生件。**

## 一 · 为什么要有这份（违反它会坏在哪）

这条形状不是审美，是为了解掉一个已经算过的账。改前：一条命令的事实（键／形状／标题／代表唤醒词／示例／处理函数）
散在 8 个以上的位置；各图 session 同时改命令时，**必须写同一批汇总位**，于是每次并行都撞同一支笔。
`docs/skills/skill-calorie/命令登记与分派-冲突为何消失.html` 把这份账逐处对过：改前 6 处共用写点，改后 0 处。

所以**成立要件**是三条**同时为真**，缺一条这份形状就塌：

1. **确定性**——同一份声明跑两次 `pnpm gen`，产物逐字节相同；
2. **哈希锁**——产物入仓且「产物 ≠ 生成器输出」即可判定为假；
3. **机器校验在 CI 里真跑**——判定不靠人记得跑，靠 CI 每轮跑。

**「我们用了生成器」不是目的。** 生成器只是达成上面三条的手段：一个不接 CI 的生成器、
一个产物不入仓的生成器、一个排序不确定的生成器，三者都满足不了任何一条。
判据要问的是「这三条现在是不是同时为真」，而不是「有没有 `scripts/gen-cli.mjs` 这个文件」。

## 二 · 四条形状

### 形状一 · 新命令只声明在自己能力目录

一条命令的六件事写在 `src/<能力>/commands.ts` 的那一行里（`kind`／`key`／`shape`／`title`／`wakeWord`／`example`），
处理函数住同一个目录。**加一条命令要改的就是这一处加它那个子功能文件。**

坏在哪：写进汇总位就等于给所有并行 session 建了一个共用写点，冲突面立刻回来；
写两处声明，同一件事迟早算出两个结果（`docs/agents/structure.md` 铁律二）。
机器拦：生成期同键两处声明直接抛（`packages/skill-calorie/scripts/gen-cli.mjs` 的 `merge()`），
`src/cli/registry.ts` 的运行期查表再拦一道。

`example` 是**必填且非空**的字段，没有退回路径（`wakeWord` 可缺，缺了速查表退回键名；`example` 不行）。
它要的是**照抄即能跑**，不是「有个串就行」——生成期只拦空／缺，
**跑不跑得通由 `pnpm help:examples:check` 拦**，而那道门今天带着票外既有红。
所以示例**先在本地跑通再提交**，别把恒红的门当兜底。

### 形状二 · 汇总位由生成器写，人只在两种情形碰

汇总位＝那些把各家声明汇到一处的文件。**哪些文件在名单里，以 `pnpm gen:check` 的输出为准**
（它逐件打 `GEN-CHECK ok <路径>`），别抄一份名单进纪律——那几个文件正在变成生成物，名单必然过期。

人碰汇总位只有两种情形：

- **新增一个能力**——建它的 `src/<能力>/commands.ts`（**恰好导出一个声明数组**，多导一个数组生成器即抛），
  并在该能力的 `index.ts` 再导出那个数组（生成的 `registry.ts` 从 `../<能力>/index.js` 取）；
- **框架级变更**——生成器本身、类型形状、共用底座。

**这两种情形都要先抢 `gate.lock` 并广播**（抢锁口径见 `docs/subagent-concurrency-protocol.md` §2／§2.4，
勿照抄旧脚本）。理由：这一刻你写的是所有并行 session 都要用的东西，写完之前别人不能在同一条链上跑。

**生成物手改无效**：`pnpm gen:check` 比对盘上文件与生成器输出，不等即红并逐行指出第一处差异。
看到红就去改权威声明，然后 `pnpm gen` 重生成。

**生成器读的是编译后的声明**（`dist/`），所以「声明变了但没重建」会被一道**陈旧守卫**拦住并报 `GEN-STALE FAIL`
——它拦的是**假绿**（拿旧声明当事实），不是浪费你一步。守的判据以生成器实际实现为准
（`packages/skill-calorie/scripts/gen-cli.mjs` 的文件头写着口径）；被它拦住时**照它的医嘱重建**
（根 `package.json` 的 `build` 里带的打印记那一步不能绕过，别直接调 `tsc`）。
照做后仍红的，是守卫自身的缺陷，**报告编排者，别自己删文件、别改门**。

### 形状三 · 老命令就地搬迁，清单只许变短

还没搬的命令住 `src/cli/legacyCommands.ts`（过渡期住处，**只进不出**）。搬一条：

1. 拷声明进 `src/<能力>/commands.ts`（**要补 `example`**，那份清单里已经有了，照抄）；
2. **手删 `legacyCommands.ts` 里那一行**——一个键恰住一处，两边都声明生成器就抛；
3. 随搬迁数**下调棘轮上限**（显式动作，得在评审里说出来）。

坏在哪：不删那行就是同一个键两个定义地，生成期与运行期各抛一次；
棘轮上限不下调，清单就退化成第二个手写汇总位——「只许变短」从一句约定变成没人守的空话。

机器拦：`packages/skill-calorie/test/legacy-ratchet-295.test.mjs` 三条断言——
清单外的新键进不来、条数与行数只许下降、一个键恰住一处。

### 形状四 · 两道机器门 + 一个必须手跟的口径

| 门 | 在哪 | 谁加 `case` 谁变红 |
| --- | --- | --- |
| 生成物门 | `pnpm gen:check`（CI 里 `build-test` 作业真跑） | 手改任一件生成物即红 |
| 棘轮 | `packages/skill-calorie/test/cmd-registry-294.test.mjs` | 往分派层加 `case` 即红 |

分派层两个文件的**允许清单只许变短**，`case` 只许随搬迁减少。要加新命令就住能力目录，别往 switch 里加分支。

**还有一处必须手跟、且没有门替你算**：新键要能被唤醒词命中，`src/triggers/routing.ts` 得有一条路由。
它是手写路由表、与冻结的场景表按位对齐（19 字段 sha 是 #180 重导的锚），**天生不可从 `commands.ts` 派生**。
加／删一条命令仍要动它，动前**抢锁**，**只加／删自己那一行**。
漏了它会红在两处：`test/calorie-routing-81.test.mjs` 的「路由覆盖数 ≠ 权威声明数」与
`packages/skill-calorie/test/cmd-registry-294.test.mjs` 的「代表唤醒词路由回同键」。
**删**命令时它更早暴露：`routing.ts` 的 `RouteKey` 是编译期约束，删了声明直接过不了 `packages/skill-calorie` 的类型门。

## 三 · 判据（照这三条查，别查感觉）

1. **加一条命令，`git status` 里除声明与生成物之外还有没有手写文件？**
   有，就是这份形状还没做到。实测口径：已搬迁的读命令 `test/` 下 0 件；
   写命令另有逐键落库断言要补（见《照抄说明》）。
2. **手改一件生成物，`pnpm gen:check` 红不红？**
   红＝门有鉴别力；绿＝门坏了。基线红不是放宽门的理由。
3. **搬完一条，`legacyCommands.ts` 与棘轮上限是不是都变小了？**
   没变小＝「只许变短」没被执行。

## 四 · 本份不写的两件事（写明为什么）

- **不列共用位名单**：那几件正在变成生成物，名单必然过期。判据是
  `pnpm gen:check` 的逐件输出，以它为准（生成器 `packages/skill-calorie/scripts/gen-cli.mjs`）。
- **不抄行数基线、条数上限**：它们住在两个棘轮文件里
  （`packages/skill-calorie/test/cmd-registry-294.test.mjs`、`legacy-ratchet-295.test.mjs`）。
  查基线去读那两个文件，不读这份。
  **量行数用节点口径**：棘轮的冻结值是 `readFileSync(f,'utf8').split('\n').length - 1` 算出来的，
  和记事本／`Get-Content` 显示的行数不是同一个数；口径错了会对着文件怀疑棘轮误报。
