## §1 目标与适用范围

**对象**：场景 03「体重」的 **58 条唤醒词**（口径见 issue 154 正文：`场景 03 体重 的 58 条唤醒词在 DSH 里都能从头走到尾`），对应老技能 13 张体重实物：明细／曲线族 1 张（`weight_history.html`）、对比 1 张（`weight_compare.html`）、复盘 1 张（`weight_review.html`）、波动 1 张（`weight_volatility_v2.html`）、总览 1 张（`weight_dashboard.html`）、记体重回执 1 张（`weight_log_receipt.html`）、批量补录／批量删除回执 2 张、通用写改删回执 1 张（`crud_receipt.html`）、体重目标 3 张（`goal_weight.html`、`goal_weight_result.html`、`goal_progress.html`）、今日主页共享壳 1 张（`home_dashboard.html`）。

**适用范围（两条口径，不区分「新写」与「改旧」）**：

1. **模板开发**：新做体重族页面（含新加结果型页、写后回执页、预检确认页）时，页面形状按本规范 §4＋§5 写。
2. **逐页修复**：改任何一张既有体重页面时，也按本规范执行 —— 老技能该继承的亮点不许在改的过程中丢掉，新仓该保的优点不许为「照抄老实物」而拆掉。

**为什么要这份规范（一句话）**：**老技能有 UI 亮点（阈值线与量程处理、回执四段、软横幅、空态两种写法等）必须继承；老技能的已知短板（图表实现分叉、Y 轴无数值、单点口径分歧、静默消失、死代码残留等）不许退回；新仓已经立起来的架构优点（单一装配、复制三格式、日志六段、profile 式口径单点定义等）必须保留。** 三件事同时成立，页面才是「老新融合」而不是二选一。

## §5 新页面最小 UI 契约（逐条勾选）

适用范围：**新做**的体重族页面，以及**逐页修复**过的页面。七组全勾才算出活；每组最后一格是「看一眼就知道」的肉眼验收点。

### 5.1 图表必传 options

- [ ] 每张折线／柱状图都传 `options`（不许只传 `items`）：`packages/base-render/src/spec/charts.ts:68-86` 的公共位 ＋ `LineChartOptions`（`:88-109`）
- [ ] 纵轴可读数：传 `yTicks`（数字或 `false` 都要显式写，`:98`）；数值格式走 `format`（`:74`）
- [ ] 横轴标注口径显式写：`labels`（`'edge'`／`'all'`／`'none'`／`'select'`，`:78`），并知道 `'select'` 是「首＋极值＋尾」三点而不是等距刻度
- [ ] 量程在取数层算好再传 `yMin`／`yMax`（`:81-82`）：体重设最小跨度＋上下留白；页面里不许出现第二条量程算式（对照 §2 第 2 条）
- [ ] 要画的横线／竖线（目标线等）走 `markLine`（`:103`），且只画在量程内的；越界改写进 KPI 的 `detail`（对照 §2 第 1 条）
- [ ] 图表类型从 8 种里选（`spec/charts.ts:8`），一律经 `renderChartBlock`（`blocks.ts:315`）；页面里没有 canvas、没有第三方图表库
- [ ] **肉眼验收**：不悬停也能从图上读出一个纵轴数值；目标线要么看得见、要么在 KPI 里读到。

### 5.2 徽章 status 映射

- [ ] 卡片徽章只传 `ok`／`warn`／`danger`／`empty`（`spec/controls.ts:312`），非法值会被回落成 `empty`（`blocks.ts:215`）—— 所以不许自造状态名
- [ ] 提示图标只从 5 种里选（`spec/controls.ts:186`）；页内静态提示走 `notice`（`copyArea.ts:177-187`），不另开提示通道
- [ ] 同一页里同一种状态只用同一个词（「无改动／已改动」这一处双重否定式表述一页只出现一次，`shared/receiptParts.ts:19-27`）
- [ ] **肉眼验收**：扫一眼徽章颜色能不能对上话里说的状态（说「异常」就有警示色，说「正常」就不是灰底）。

### 5.3 结论块唯一形态

- [ ] 页面要下判断，只用一种形态：`renderDisclosure({ title: '结论', contentHtml: '<p>…</p>', open: true })`（现成写法 `weight/compare.ts:219-221`）
- [ ] 一页最多一块；不许出现「小结／总结／点评」第二种叫法，也不许把结论散在 KPI 的 `detail` 里
- [ ] 结论句由取数层算出的结构化字段拼成，页面不做自然语言解析（对照 §3 第 11 条）
- [ ] **计数口径（2026-09-14 裁定）**：「一处」判的是**可见页面**，不是 HTML 源码里的字面出现次数。复制载荷里那句 `'结论'` 原句（§5.4 要求进载荷，三种格式各序列化一次，故源码里会多出 3 次）**不计入**；同理，若为了把源码计数压成 1 而给载荷键改名，那正是本条禁止的「第二种叫法」，**不许**这么干。
- [ ] **肉眼验收**：在页面上找「结论」两个字，只找到一处，且默认是展开的。

### 5.4 复制载荷＝所见（text／json／csv）

- [ ] 复制区按 `copyArea({ prompt?, data?, log? })` 组（`shared/copyArea.ts:116`），数据位自动出「复制数据 ▾ ＋ 三格式菜单」（`:143-159`）
- [ ] 三种格式都在：`text`（给人看）／`json`（存档）／`csv`（表格导入），口径 `COPY_FORMATS`（`spec/text.ts:12`）
- [ ] 载荷里的数字＝页面上的数字：指标经 `metricsOf` 冻结投影（`docPage.ts:64-70`），缺值不当 0
- [ ] 有数据位就有日志位：日志六段齐（`copyArea.ts:36-39`、`:167-175`），**第 4 段是渲染命令原文、第 3 段是库文件名 ｜ 来源**（段序正本 `packages/base-render/src/spec/text.ts:24-25`），照抄能重跑

- [ ] **肉眼验收**：点开三格式各复制一次，粘进纯文本编辑器，数字与页面逐个对得上。

### 5.5 页脚数据来源行

- [ ] 每页都有一行数据来源，写清「哪张库 ／ 哪个窗口 ／ 多少条」（现成写法 `diet/nutritionPortDocs.ts:60`）
