## 裁定一 · 目标变更历史的数据基础 → 甲（按现值派生，**不加表**）

**判**：维持今天的做法——由 `food_log` 按日聚合、对照 `daily_goal` 现值判达成，不新增目标变更表。

**判据与出处**：

1. **老技能自己就没有历史表。** `D:\2Study\StudyNotes\SKILLS\卡路里\scripts\goal_history.py` 件头第 4–5 行逐字写着：
   > 基于 food_log + daily_goal：按日聚合实际 vs 目标，判定每日达成（80%-120% 带）。
   > 无独立历史表，从现有数据推导（daily_goal 单行表，goal 变更前值不落库）。

2. **它取的是现值、判的是同一根线。** 同件 `:68-70` 取目标：
   `SELECT calorie_goal, protein_goal, carbs_goal, fat_goal, water_goal FROM daily_goal WHERE id = 1`；
   `:88` 判定 `status = '完成' if 80 <= pct <= 120 else '未完成'`；`:83-84` 无记录日记 `无记录` 且**不进两个计数**；`:92-95` 计数。
   → 「改过目标之后，过去的日子该按当时的目标判还是按今天的目标判」这个问题，**老实物的答案是「按今天的目标判」**，不是新仓的疏漏。

3. **新仓已经同口径落地，加表反而是新口径。** `src/fetch/goalHistory.ts:38-73`：同样的 80%-120% 判定带、同样的 `完成／未完成／无记录` 三态、同样的 `completedCount／incompleteCount` 计数、目标同样取 `daily_goal WHERE id = 1`（`:42-45`）。这条取数已经进了读命令的读数面：`src/goal/read.ts:30-37`（`completedCount`／`incompleteCount` 进 metrics）。「看目标历史完成」这个词的 prompt 本身也写着达标带与两项计数（`src/triggers/scene-06-goal.ts:28`）。

4. **schema 侧没有第二处落点。** `src/schema.ts` 11 张表逐张看（`:21,28,36,46,51,60,65,73,78,83,97`）：`daily_goal` 是**单行表**，`:28-34` 七列 ＋ `:214-221` 的增量列迁移，没有目标变更表，也没有任何一张表记「某天的目标是多少」。

**为什么不做乙（加表）**：老实物当年没做；加了就引入一条**与老实物不同的判定口径**（历史按当时目标判 vs 按现值判），而这句话在老技能里本就是「按现值回算」的意思。要换口径得**另开票**，并说清用户能感知到的差别（同一段历史，换过目标之后两种算法给出不同的完成天数）。

## 裁定二 · 一键定全套目标的组合写命令 → **不加**

**判**：不新增组合写命令。「一键」的语义＝**一次给齐三类推荐值**（预检页），不是一次写库。

**判据与出处**：

1. **三条写命令都在册、各有入口**：`src/goal/commands.ts:33-35`（`calorie.goal.set`／`calorie.goal.water`／`calorie.goal.weight`，`shape: 'receipt'`，各有一条代表性写词）。
2. **「一键定全套目标」这个词今天就有出口，出口正是预检页**：`src/goal/routes.ts:21`
   → `calorie-cmd-read calorie.view.goal-wizard --params '{"profile":"cut","wake":"一键定全套目标"}'`；页面命令在册 `src/goal/commands.ts:43`。
3. **预检页是 11 条带空位写词的共同落点，且「确认」这一步已经落地**：`SKILL.md:75`（`calorie.view.goal-wizard` 承接定营养目标／定营养目标(自动算)／定体重目标／定体重目标(自动算截止)／定体重目标(含起始日)／定饮水目标／定饮水目标(自动算)／一键定全套目标／改营养目标／改体重目标／改饮水目标共 11 条；暂停／重启无空位不出页）；用户「确认」＝复制页面上的 prompt 回给 AI（地图 Decisions 第 5／6 条）。
4. **组合命令会把「先给我看再采纳」压成一次不可见的写**：三条写命令各出一张回执（`shape: 'receipt'`），合成一条就没有「逐项确认」这一步了。
5. **成本不为零**：新增命令还要再登记三处（`src/cli/keys.ts`／`packages/base-combos/combos.yaml`／`scripts/build-help.mjs` 的 `exampleFor`），且会改一串钉死的命令计数。
