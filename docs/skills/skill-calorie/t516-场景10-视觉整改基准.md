## 六 · HELP 参考的正确读法（能抄什么、不能抄什么）

**先钉一件事：HELP 有两代，配方不可混用**（出处 [`t161-勘察-响应式与视觉配方.md`](t161-勘察-响应式与视觉配方.md) §1.0）：

| | 现行（仓内装配件） | 老产物（技能目录里落盘的 HTML） |
|---|---|---|
| 来源 | `packages/base-render/assets/help-template.html` | `卡路里_HELP_20260731_201530.html` |
| 断点 | **500／501／820** | **600／601–900** |

### 6.1 **断点与字号降级都不能抄**

- 现行 help 模板的窄档是 **500px**，比页面族的 **640px** 更窄；直接抄会把页面在 512 档压成更紧的一版，与「页壳 640 档」打架。
- 老产物的 **600／601–900** 是另一套（`.container/.hero/.cat-block` 那一族类名），本 31 页里一条都没用。
- help 的字号阶梯（12／13／14／17／26 那套）与 §5.2 的五档**不是一套**，抄它＝另立第二真相源。

### 6.2 **可以抄的是形态**（用户在要求②要的是这个）

`<details>` 三级折叠（域→组→场景）、列表收内距、吸顶搜索、固定底栏这三样＋搜索，都是**形态**，照抄结构、**不抄数值**；落到本 31 页就是 `renderDisclosure`（`blocks.ts:850`）＋ 章节层级。

### 6.3 可复用的公共层 640 档三件

| 件 | 出处 | 说明 |
|---|---|---|
| 页壳 padding | `blocks.ts:1227` 的 `@media (max-width: 640px)` 块（`:1229` 生效值） | `padding: 20px 16px 60px`、页标题 26px |
| 数据表紧凑档 | `blocks.ts:1638` | 不靠左右滑动看全 |
| KPI 二列 | `blocks.ts:1500` | `repeat(2, minmax(0,1fr))` |

### 6.4 `.ilife-help-shell-grid` 的裁定

**事实**：定义在 `packages/base-render/src/style.ts:794`（宽屏 `repeat(2,minmax(0,1fr))`，`gap:12px`）与 `:1174`（≤640 塌单列）；**全仓 `.ts` 只有这 2 处命中（就是定义本身），31 页 DOM 零使用**——它是「已导出未使用」的件。

**裁定：选 (b)——在公共层加页面族侧的对应件，`help-shell-grid` 留给 help 模板自己用。**

理由三条：

1. **类名前缀就是归属声明**。`ilife-help-shell-*` 是 help 模板那一族的名；页面族 31 页用它 ⇒ 同一件被两族各写一份装配，正是本图要消灭的「第二真相源」。
2. **本图要的两处网格，一处已有、一处真缺**：KPI 二列公共层已有（`blocks.ts:1500`）；真正缺的是 **641–820 过渡带**（G-1）与「并排卡」。缺什么补在哪里，比跨族复用一个 help 件干净。
3. **(a) 的先例风险大于它的收益**：一旦允许跨族复用一个未使用的件，后面任何票都可以复用别族的件，归属边界失效；而 (a) 的全部收益只是省下一条 `@media` 规则。

**如果编排者另有裁定（要选 (a)）**：必须同时给出「跨族复用允许清单」的具名机制（哪几个件可跨族用、谁批准、在哪登记），不能按一次性豁免开——否则本裁定与「件名即归属」的纪律冲突。
