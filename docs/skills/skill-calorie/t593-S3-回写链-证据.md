## 三 · 票内定的口径

### 1. 范围（只能「结束日＋往前 N 天」，默认 1 天）

- `[end-days+1, end]`，新在前（老 `backfill.py:190-193` 的循环、`__main__.py:101` 同述；起始日倒算不支持）；
- 默认 **1 天**：照 `backfill_range` 签名 `days=1`（老 `:165`），不照 docstring「默认 2」（老 `:166-170`，文档错了）——`BACKFILL_DEFAULT_DAYS = 1` 唯一定义地，`t608`「默认 1 天」用例钉住；
- 单日与范围走同一个函数（老 `:13-14` 统一 API）；坏天数（0／小数／非数字）明确拒收退 1，不静默吞成 1 天。

### 2. 幂等键三列（更正说明，本票点名）

- **更正**：`backfill.py:7` 的 docstring「幂等键：`xunji_localid + set_index`」与原 `t350:15` 的两列说法**是错的**——代码（`xunji_adapter.py:98-101` 的 SQL `WHERE xunji_localid = ? AND exercise_type = ? AND set_index = ?`）是**三列**，行为以代码为准；
- 本票 `XUNJI_IDEMPOTENT_COLUMNS = ['xunji_localid', 'exercise_type', 'set_index']`（`store.ts`，唯一定义地）；
- `t608`「两列不够」用例钉死：同 localid＋set_index、动作不同即两行（两列实现会把第二行写成 UPDATE，该用例变红——变异 A 实证）。

### 3. UPDATE 覆盖 7 列但保留 `note`／`date`

- 覆盖：`exercise_type／reps／load_kg／calories_burned／category／difficulty／xunji_title`（老 `:105-114`）＋ `updated_at`；`XUNJI_UPDATE_COLUMNS` 唯一定义地；
- 保留：`note`／`date` 不在 UPDATE 语句里（老语句同样没有这两列）——`t608`「UPDATE 保留」用例钉死（种子 `note='手填'`＋异日，新值覆盖 7 列、两列原样）。

### 4. 新仓写入路径（`exercise_log` 有列无入口 → 补上）

- `addRecord` 收 `xunjiLocalid`／`xunjiTitle`（缺省 null；INSERT 列与返回行同步加两列，既有列一字未动）；
- 回写 INSERT 经该路径（`store.ts` 调 `addRecord`，另带 `isBackfill: true`）；
- 标签：`xunji_localid`→训记单号、`xunji_title`→训记标题（纯中文，`field-labels-449` 的纯中文冻结口径仍过）。

### 5. 缺陷不照抄（写库失败仍退 0 → 修掉）

- 老形状：`_backfill_one` 写库失败回 `fetch_ok: True`（`backfill.py:139,147`），`__main__` 只看 `fetch_ok`（`:108-111`）→ 恒退 0；
- 新仓：`BackfillDayResult.err` 非空即失败；`runBackfill` 先扫「没拉到」（按拉取分类走 2／3），再扫「拉到了没写进」（走 3）——`t608`「写库失败非 0」用例钉死（`openDb` 抛错挡板：`fetch_ok: true`＋`err` 含“拉到了没写进”＋退 3；与“没拉到”文案可区分）；
- 行级单错仍记 `errors` 不中断整体（老 `:128-131` 同述）， totals 只计成功行。

### 6. 读口与限频（`fetch` 子命令）

- 包体三键原样送 `datestr`（`--full` 切 `include_full_data`，回写恒 true——要 `done` 标记）；
- 只读：`fetch` 不碰库（`t608`「只读不改库」用例：拉到 1 条训练，库内 0 行）；
- 限频缺省关（老缺省关）；`--respect-rate-limit` 打开才守 full 30s／light 15s（老 `auth.py:42-44`），状态文件与老同路径同键名；
- `--raw` 透传原始 JSON（`attempts>1` 才回写，老 `:114-115` 同述）。
