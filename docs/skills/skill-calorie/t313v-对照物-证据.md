## 9. 未确证／风险 top3

1. **对照面 ≠ 全部可观测行为**：面清单是**固定写死**的（12 表 ＋ 3 函数 ＋ 2 派生面）。若 B 段的生成物**新增**一个导出（如 `ROUTES_BY_SCENE`）或改动模块内其它副作用，本 oracle **看不见**（只冻结既有面）。真实 CLI 端到端分派亦不在面内——`src/render/helpCenter.ts:46`（唯一 `src` 消费者）只用 `routesFor`，该函数行为已由 `DIRECT_API_PROBES` 覆盖，但 `dist/cli` 侧的分派链未覆盖。
2. **快照只对建它时那份 `dist` 成立**：若有人改了 `src/triggers/routing.ts` 却**没**跑 `pnpm build`，本 oracle 比的是**旧 dist**，会给出「等价」的**假绿**。防护：复跑前必须持锁 `pnpm build`，并以脚本 `INFO: dist=… sha256=…` 行与冻结件 `meta.distSha256` 对照；本票的两条 sha 见 §4。
3. **脚本不校验快照自身完整性**（无自哈希／签名，`meta` 段不参与比对）：「快照未被篡改」靠**本次冻结 commit** 与后续「不许改快照」的纪律保证，不靠脚本自证——与协议 §2.4-5「对账查漏不防伪」同一边界；同时改代码＋改快照可互相抵消。后续 B 段复核应固定引用本 commit 的冻结件 sha256（`f8f9c355…3e27`）。
