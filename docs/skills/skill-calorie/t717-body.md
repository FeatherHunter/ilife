## Problem Statement

用户跟卡路里技能说话时，同一件事会在不同页面上得到两个答案：

- 一条 14:30 记下的饮食，在「餐别分布」页算作**加餐**，在「诊断饮食结构问题」页算作**午餐**；21:30 那条在一边算晚餐、在另一边算「加餐/夜宵」。按当刻真库数，非水的饮食记录里**五条就有一条**踩在这条分歧带上。
- 同样的蛋白占比，在「营养配比」页按 **10-20%** 判正常、在「诊断营养不均衡」页按 **15-30%** 判失衡——而判失衡用的那套数，页面上从没印过，也追不到出处。
- 把日期固定到某一天做演示或回放时，不带日期记下的那一笔会落进**真实的那一天**，而回执上印的是**被固定的那一天**、累计读的也是被固定的那一天：一条命令里出现两个「今天」。

用户没法发现这些差异的成因，也没法绕开——它不是显示问题，是**同一条事实在包里被算了两次**。

## Solution

把每一处「同一件事」收成**一个定义地**，放到共用位；谁要用都读那一处，自己不再抄一份。并据此把已经在给不同答案的页面改成同一个答案。

用户能看到的效果：跨页面不再出现互相矛盾的数字；把日期固定到某一天做回放时，写入的数据、回执上的日期、累计读的那一天是同一天；「共 N 天」永远是含首末日的闭区间，表头不会再把 N 与 N−1 混用。

## User Stories

1. 作为卡路里的使用者，我希望「这条记录属于哪一餐」在全包只有一个判断标准，这样同一份记录不会在不同页面上被算进不同的餐。
2. 作为使用者，我希望「餐别分布」页与「诊断饮食结构问题」页对同一天给出同样的餐次统计，这样我不会被两个不同的数字搞糊涂。
3. 作为使用者，我希望深夜（22 点后）吃的东西在哪一页都属于同一个餐别，而不是在一边算加餐、在另一边算别的、或被两边的窗口都漏掉。
4. 作为使用者，我希望「加餐」的定义（下午茶 ＋ 夜宵）在全包只有一个说法。
5. 作为使用者，我希望三大营养素的推荐区间在同一次会话里只有一个说法。
6. 作为使用者，我希望「某营养素占比失衡」这个判决所依据的区间，就是页面印出来的那个区间。
7. 作为使用者，我希望推荐区间追得到出处，而不是一处一个数字。
8. 作为使用者，我希望不带日期记饮水时，落库的那一天与回执上印的那一天是同一天。
9. 作为演示或回放的人，我希望把日期固定到某一天时，写入的数据、回执、累计读的是同一天，回放才复现得出来。
10. 作为使用者，我希望「今天」只有一个来源：无论走系统时钟还是走被固定的那一天，全包只有一处决定它。
11. 作为使用者，我希望「已删除／已下架」的判断在全包只有一个谓词，食品库、营养结构、导入预检、榜单给出同一份清单。
12. 作为使用者，我希望从老库迁移进来的空值不会被某些页面静默隐藏、又被另一些页面显示出来。
13. 作为使用者，我希望「本窗共 N 天」永远按含首末日的闭区间算。
14. 作为使用者，我希望「两个日期相隔几天」与「窗内有几天」是两个各有名字的口径，不会互相顶替。
15. 作为使用者，我希望「消耗多少千卡对应掉一公斤」这类常数只有一份；它改了，页面上印它的地方跟着一起改。
16. 作为使用者，我希望这次整改**不改**任何页面的文案与版式——只让数字不再自相矛盾。
17. 作为维护的人，我希望每处口径都住在共用位，改一处就够，不必满包找副本。
18. 作为维护的人，我希望能力目录之间不再互相绕圈（今天汇总结算依赖抓取层，抓取层又依赖汇总结算）。
19. 作为维护的人，我希望包对外的名字一个都不少：搬家只改「定义在哪」，不改「外面看见什么」。
20. 作为维护的人，我希望这次改动按批落地，每批有独立判据，不必等全部做完才能验收。
21. 作为维护的人，我希望共用位里的件是零依赖的——它们不许再引用任何一个能力的名字。
22. 作为未来的维护者，我希望有一道机器门，在我或别人再抄一份定义时立刻变红。
23. 作为未来的维护者，我希望那道门改坏必红、改回必绿，并能举出一个合法例外不被误判。
24. 作为未来的维护者，我希望这次改动的证据留档（哪几页变了、变在哪），后人不必重跑一遍。

## Implementation Decisions

### 一 · 住处规则（唯一原则）

按**「谁在用」**定住处，不按「谁定义的」定：写得出**两个以上能力**在用的口径 → 进**共用位**；只有**一个能力**自用的 → 留该能力目录，走该能力的门。共用位里的件必须**零依赖**，不许出现任何一个能力的名字。

本次涉及的六处口径**没有一处是单能力自用**，故**全部落共用位**。这条规则替掉了先前试过的两种切法（按「有没有主人」切不出东西；按「住处合不合法」只能排序、定不了住处）。

### 二 · 六处归一

| # | 口径 | 今天是否已产出两个结果 | 归一处的方式 |
| --- | --- | --- | --- |
| 1 | 餐别（时间窗 ＋ 归桶 ＋ 「加餐＝下午茶＋夜宵」） | **是**，真库约 22.5% 的记录落在两套边界的分歧带 | 时间窗与归桶的定义地迁入共用位；诊断侧**删掉自写的小时边界**改为读同一处；其余六处引用改指新家 |
| 2 | 营养素推荐区间 | **是**，一套上屏、另一套进判决 | 区间定义迁入共用位；诊断侧改读它；两处印它的渲染件改读它 |
| 3 | 「今天」（时钟 ＋ 日期解析） | 是，**但只在固定日期时**（生产两条路同值） | 时钟与日期位移迁入共用位；三份走系统时钟的本地时钟**删掉**；写完回执与累计读同一天 |
| 4 | 软删存活谓词（已删除／已下架） | 否（当刻真库零空值），但**没有任何约束兜底** | 两个具名谓词迁入共用位；抓取层与其余内联字面改为读它 |
| 5 | 闭区间天数（含首末日） | **不是两个结果**，是两个概念共用一个名字 | 定义地已在共用位；把另一个 +1 版**改名**（分家命名），两处同体副本改为调它；「两点跨度」那一个**保持不加 1** |
| 6 | 千卡↔体重常数 | 否 | 定义迁入共用位；分析域内另两份与三处裸字面改为读它 |

### 三 · 内容三裁（住处推不出，已由维护者裁定）

- **餐别时间窗**：取**现有那一套**——早 6-10／午 10-14／下午茶 14-18／晚 18-22／夜宵 22-6，加餐＝下午茶＋夜宵。另一套（早 &lt;10／午 &lt;15／晚 &lt;21）无注释、无测试，是漏检出来的分叉。**连带修一处自相矛盾**：夜宵窗口只写了 0-6，而 22 点后的记录会被归成夜宵，导致它既不落在「删夜宵」窗、也不落在「删加餐」窗——归一时一并理顺。
- **营养素推荐区间**：取**有出处的那一套**（蛋白 10-20%／碳水 45-65%／脂肪 20-35%，来源是旧脚本写死的 range 表）。孤儿那套（15-30／40-60／20-35）只出现在一处、无出处，作废。
- **闭区间天数与两点跨度**：**分家命名，不合并**——「两点跨度」不加 1 是此前修好的一个缺陷（表头写实际覆盖天数，不拿请求天数顶替），合并会把缺陷改回去。

### 四 · 公共接口

搬家的同时**保持包对外的名字不变**：定义搬到共用位后，原先对外转出这些名字的地方改为**从新家转出**。包外看到的导出名清单前后一致（这决定了本次不与「公开面缩窄」那一票冲突，只剩同一个文件要排窗）。

### 五 · 分批与顺序

| 批 | 内容 | 为什么这个顺位 |
| --- | --- | --- |
| 1 | **餐别**归一（含 22 点自相矛盾） | 唯一**无条件**在产出的用户可见分歧；修复成本最低（删一份自写边界） |
| 2 | **营养素推荐区间**归一 | 两套数同时在盘上，且那套孤儿数进判决 |
| 3 | **时钟 ＋ 软删谓词一起进共用位** | 不是两件事，是同一个病：抓取层被要求「不反向依赖汇总结算」，逼出了三份不认固定日期的时钟与二十九处内联谓词。一起治，抓取层才读得到同一份。**本批第一批提交项**＝两处一行级改动：删两个未使用的导入；把某历史目标函数的本地时钟定义与其默认参数**成对**去掉（单删其一必红，见 Testing Decisions） |
| 4 | 其余四件（千卡常数、逐字抄件合并、健康速率阈值统一、逐日 BMR 接正本）＋ 闭区间天数改名 | 今天都不产出两个结果 |
| 5 | **防复发门** | 可与任一批同窗 |

### 六 · 边界与预告要求

- 有**三处会改变用户可见读数**：餐别页的餐次统计、营养诊断页的失衡判决、相关判决词。它们是修 bug，但要按「页面可见读数变化」**预告并留证**（变更前后对照读数），不得静默。
- 每批一律走结构纪律的**必报五步**：先报影响清单（每行指向一个能力目录），报结构设计，再动；超线件当场报第四步；交付逐行对账。
- 判据一律用**现成门**，不新起一套。

## Testing Decisions

**什么叫好测试**：只断**外部行为**——命令出口产出的页面／信封，以及包对外的导出名。不断实现细节（不断「某函数被调了几次」、不断内部文件是否存在、不断私有件名）。

**主缝（一条）**：**命令出口**——AI 实际调用的那条路。本次每一处改动在外部都表现为「同一条命令对同一份输入给出什么产物」，所以断言打在命令产物上即可覆盖三件事：餐别统计、推荐区间与判决、固定日期下的写入／回执／累计。**优先用既有缝**：包内已有大量测试走真交付出口（spawn 真命令行），测试面改造另有票承接；本规格沿用那条出口，**不新开缝**。

**结构缝（一条，且不是测试缝）**：**防复发门**——「同一符号只允许一个定义地」的闭集断言。先例是包内已有的单源门（断言某组常量／小件只存在一份定义）。要求两条机器读数：**改坏必红、改回必绿**；并要能举出一个合法例外（搬迁期薄转出）不被误判。

**被测对象与对应用例**：

- 餐别：同一天、同一份记录，两个页面给出**同样的餐次统计**；边界样例要含 14:30、21:30、22:30 三个分歧点。
- 推荐区间：同一份记录，两个页面印出**同一个区间**，且判决依据就是印出来的那个。
- 时钟：固定日期后跑**全包回放**，写入日 ＝ 回执日 ＝ 累计日。
- 谓词：同一份库，四条读路径给出**同一份清单**（含空值行）。
- 天数：窗内天数按闭区间；两点跨度另有其名。
- 一行级改动：删本地时钟定义**必须与其默认参数同批**——单删会让一个既有断言在参数绑定期变成 `ReferenceError`（消息不含该断言匹配的 `days`），那条断言必红。

**搬迁类判据**：逐页产物**逐字节相同**（先例＝本包此前的搬家证据件用同一条判据）；对「读数会变」的三处，给出**变更前后对照读数**替代逐字节。

**变异自证**：每批至少做一次「改坏 → 红；改回 → 绿」。

## Out of Scope

- **页面可见文案与视觉版式**：一行不改。
- **台账里已登记的「按页族切姊妹件」拆法**：不与本次整改合并。
- **能力门上的新名字**：公开面缩窄另有一票；本规格只要求「搬定义、不改外面看见的名字」。
- **页面件搬回能力目录**：另有一票在跑，本次只与它排窗。
- **生产不可达的那处旧复盘件**：去留另开票，本规格只登记。
- **包外**：插件包与公共层不动。
