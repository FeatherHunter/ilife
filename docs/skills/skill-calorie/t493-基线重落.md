## 一、进场现状（复现）

`node packages/skill-calorie/scripts/gen-photo-baseline.mjs --check` ＝ `BASELINE-DIFF 10 pages`、exit 1，十页逐页 `CHANGED`。成因两股：

1. **内容面**：本轮文本／展示改造（#472／#473／#474／#476）、响应式（#484）、HELP q 支整页化（#488）改了十页正文。
2. **时间面**：多页新添的**相对时间文案**（「今天」「N 天前」）由装配层 `todayISO()` 现算，页面参数里的业务日期钉不住它。

## 二、钉时钟：① 进场时钉没钉、② 依据、③ 钉法、④ 对照读数、⑤ 一处钉不到的时钟

**① 进场时没有钉。** 脚本原有口径只钉「显式业务日期」：list 传 `today:2026-09-06`、gif 传 `days:36500`、gif-planner 传 `start/end`、add 传 `date/time`；进程环境里没有任何 `CALORIE_TODAY` 设置。钉法是本次新加的。

**② 依据（为什么显式参数钉不住）。**
`todayISO()`（`packages/skill-calorie/src/analysis/utils.ts:135`）在 `CALORIE_TODAY` 有值且形如 `YYYY-MM-DD` 时直接返它，否则现取机器时钟的 **UTC 日**。
`calorie.photo.list` 是活的例子：**数据窗口**吃页面参数 `today:2026-09-06`，而**图注的相对天数**由装配层另算一次——`src/photo/galleryDoc.ts:180` 的 `const today = todayISO()`。
同族还有两处落点：`src/photo/viewerDoc.ts:107`（detail）、`src/photo/compareDoc.ts:91`（compare）；第四处 `src/photo/pickerDoc.ts:106` 属候选页，不在十页基线内。
机器日一换，这三页正文就换字、sha 跟着漂——进场当刻是 2026-09-15，种子照 2026-09-04／05／06 的图注读作「11 天前／10 天前／9 天前」，明天即全变。

**③ 钉法（只动基线脚本，先于任何 `dispatch`／`addPhotos`）。**

```js
const PIN_TODAY = '2026-09-06';
process.env['CALORIE_TODAY'] = PIN_TODAY;
```

取值＝种子库最后一张照片的日期（2026-09-06），与 `photo.list` 窗口右端同一个日期；三张种子照的相对文案于是固定为「2 天前／1 天前／今天」，无未来日期（`galleryDoc.relativeDays` 对负数返空串）。
只影响本脚本进程：**不写**环境变量文件、不动生产默认（真实使用不设该变量即按机器时钟）、不碰真实库。
每轮还会打印一行自证，免得钉法与读数两处走散：`PIN-TODAY 2026-09-06 (machine-utc-day 2026-09-15)`（后者是当刻机器 UTC 日，只作对照、不参与取数）。

**④ 「挪一天」对照（钉法是否真的管住漂移）。**
用脚本的**逐字副本**做题针：`.scratch/t493/pin-probe.mjs` 由 `.scratch/t493/make-pin-probe.mjs` 生成——只改两处（四个相对 import 指到本目录走得到的路径；`PIN_TODAY` 允许被 `PROBE_TODAY` 覆盖），其余一字不动，所以探针与真件口径完全相同，只有「今天」这一个变量。

**⑤ 还有一处不受钉法控制的时钟（当刻无害，记为遗留）。**

## 六、附带修一处判断串线（`--write` 把「无需回写」误报成「标记块未命中」）

**症状**：首次 `--write`（十页有变化，`runId=07d9800b-5a72-4b8c-9928-7a19fc3ab2f2`）exit 0；**其后每一次 `--write` 恒 exit 1**，只打 `PIN-TODAY` 一行、连逐页读数都不打——实测到三次：`runId=4de54166-40ee-4c80-b2d1-73a870cf5dd7`、`runId=952643d3-23b4-45e9-8a69-a1a366af2d9e`、`runId=9f8f80f7-4a18-4bff-bff2-d2a3030e0df2`，三次都打「BASELINE 回写失败：标记块未命中」。本票的判据「两次 `--write` 十页 sha 一致」反而读不出来。

**根因（离盘证明）**：原判据是 `next === self` → 报「标记块未命中」。但**回算出的块与文件里那块逐字节相同时**（＝十页 sha 全没变，恰是本票要的两轮一致）`replace` 原样返回，于是「无需回写」被误判成「没命中」。对当刻盘上文件实测：

```text
marker-matched= true
recomputed-block-identical= true
so next===self when out unchanged -> guard misfires: true
```

**修法（本票写集内、同在这份基线脚本）**：标记是否命中改用 `re.test(self)` 判（块被人删了照样红，牙齿没丢）；无变化则明确报 `BASELINE-UNCHANGED` 并 `exit 0`。
**修后读数**：第四节的第二轮 `--write` ＝十页全 `same` ＋ `BASELINE-UNCHANGED 10 pages` ＋ exit 0。
