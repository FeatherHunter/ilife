## 1 做成什么样

页面结构（自上而下）：

1. **结论条**：可落地 / 有硬止 ＋ 错误 N 项 ＋ 警告 N 项 ＋ 已检查 N 个训练场次（一行读数，不再散成四张卡）。
2. **一句话读法**（口径行）：这份计划按 计划 → 周 → 日 → 时段 → 动作 五层摊开。
3. **计划级**：名字、说明、起日、等级、器械 ＋ 一颗「改计划本身」。
4. **时间线**：逐周 → 逐日 → 逐时段 → 逐动作；**每一层挂一颗「改这一层」**。
5. 空的地方**就地指出下一步该说什么**（例如「这一周还没排——想排就说『定一周计划』」）。
6. 硬止错误 / 警告折叠块（保留）。
7. 复制区：复制指令 ＋ 复制数据 ＋ 复制日志。

**勾选的三种反应**（都在一张静态页里，零刷新）：

- 勾选的胶囊**变蓝**（`:has(.ilw-mark:checked)`）；
- 该层**就地展开**「说哪句话能改它」（`.ilw-tick:has(...)~.ilw-how`），逐条排成胶囊
  （计划级＝改训练计划；周级＝定一周计划／复制训练计划；日级＝改某天训练／删某天训练／定休息日；
  时段级＝加训练动作；动作级＝改动作）；
- 右上角「**你已改的内容 N**」加一 —— 由 **CSS 计数器**现算
  （`.ilw-wiz{counter-reset:changed}` ＋ `.ilw-mark:checked{counter-increment:changed}`）。

## 2 零脚本怎么做到「就地改与计数」

本仓契约 `docs/base-paint-contract.md` 写死「禁内联脚本（AC-7 零注入面）」，故不能用脚本做交互。
本页用**原生控件 ＋ CSS** 做出三种反应（见 §1）。三条实现要点（都踩过）：

1. **计数器要排在最后**：CSS 计数器取的是**文档顺序上它之前**的累计值，把计数元素摆在页头会永远读到 0；
   故它排在全部勾选之后，再用 `position:absolute` 钉回区块右上角。
2. **`:has()` 而不是 `~`**：选钮放在 `<label>` **里面**（整块胶囊才是点击区），所以同级兄弟是 label、
   不是 input——`input:checked ~ .ilw-how` 够不着。改用 `.ilw-tick:has(.ilw-mark:checked) ~ .ilw-how`。
   （`:has()` 在 Chrome 105＋／Safari 15.4＋／Firefox 121＋ 可用；本页是给人双击打开看的页。）
3. **窄屏计数改浮动**：`position:absolute` 钉右上角在 390 宽下会挤坏页头，故 820 段改成
   `position:fixed` 的**底部浮动胶囊**，勾一颗抬头就看得见；页尾留 64px 不压住复制按钮。

**这是零脚本能做到的上限**（如实记账）：勾选与计数是真交互，展开的是那一层该用哪条写词；
但「把用户勾的选项拼成一条可执行命令」需要脚本，本页不做。要走那一步得先改契约（见 §5）。

## 14 写后回执的边界（同轮再补）——这一回**没抓到缺陷**，但把结论钉死

撤销那张回执页逐行读过，整页是人话且自洽：写入字段「确认执行」（上一轮刚修）、
写后现值「计划已撤销（配置与训练安排均为空）」、改动对照「已撤销训练计划「基准计划」（配置＋1 场，
