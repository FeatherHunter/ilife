Q2

照片要不要真的出现在页面里？

最重

为什么问

本图三类页面（看身材照／对比两张照片／删身材照快照）现在一张照片都看不到，只有文件名和一个「文件在不在」的位。而老技能当年是内嵌照片字节的：老模板里写着 <img src="${p.photo_data_base64}">、${g.gif_data_base64}。更关键的是「删身材照」这条词的 prompt 自己就要求「删除前先给我看这张照片的内容（快照）」——不内嵌，这个快照根本交不出来。这条决定了本图要不要长出一件新部件，也决定了你的「肉眼验收」到底在验什么。

判断依据

  • 你的验收方式是「把 HTML 拿到一个目录里双击打开」；交付目录与照片目录同在一棵 .db 树下（.db\calorie_html\ 与 .db\CalorieHub\）。
  • 本包没有任何图像依赖（只有 base-paint），全仓也没有内嵌图像字节的现成实现 ⇒ 内嵌是一条新能力。
  • 「不读照片字节」是有意写下的既有决定（render/photo.ts、render/wizardPort.ts 顶注），要改就是推翻它——这种事按惯例得你裁定。
A 内嵌缩略图（照老实物）B 引用照片文件路径C 维持现状
页面里看得见照片看得见看得见看不见
拷到交付目录／发飞书照样看得见图会丢—
「快照」这条要求交得出同机交得出交不出
改动量新增一件图像能力（单列票）很小零
风险页面体积、多一个依赖换机／分享即失效验收等于没验

推荐

A：内嵌缩略图（第 6 张票单列，定体积上限：每张缩略图 ≤120KB、画廊页总量设上限），并把 B 留作退路。

理由三条：① 老实物就是内嵌，照实物做不凭空设计；② 你的验收要把 HTML 拷走再开，引用路径的做法一拷就瞎；③「删身材照」的 prompt 自己就要求照片快照。
