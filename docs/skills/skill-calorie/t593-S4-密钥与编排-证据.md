## 三 · 票内定的口径

### 1. 密钥（`key.ts`，老 `auth.py:35-55／110-184`）

- 只读环境变量：`XUNJI_TRAINS_KEY` 优先→`XUNJI_API_KEY` 回退（老 `get_key` 同序）；**没有密钥文件**；
- `status` 七键与老同形，唯独 `active_key_preview` 只回前 4＋`...`＋末 2（老 `:177` 原样），全串无位可住；
- `set` 写用户级系统环境：Windows 走 PowerShell 写 `HKCU\Environment`（值走 base64，原文不进命令；老 `winreg` 同位），
  成功同步当前进程；空值／超 1024 拒收（老同值）；
- `clear` 幂等（本来没设也退 0，老同述）。

### 2. 叠加（`overlay-plan.ts`，老 `overlay.py`；缺陷修法）

- 老缺陷：`title_to_localid = {t["title"]: t["localid"] ...}`（`:80`）把同 title 多条压成一条，后面的 localid 静默丢失；
- 修法：`groupLocalidsByTitle` 按 title 收**全部** localid（保序），sessions 按序逐条 `shift` 消耗——
  同 label 第 2 个 session 拿第 2 个 localid；耗不完的 title 留 `extra_in_xunji`，耗尽的不在内；
- 其余照老：先拉训记 list（只拿 title→localid）→ 读本仓 sessions → 对账 → **单次** upsert（幂等键 `overlay_{date}_{uuid8}`，
  `localid` 已有＋`start=end=0`）；`missing` 缺省 `fail`（有缺即 err 不推），`skip` 只推匹配的；
- `matched` 由老单条目改逐 session 一项（不改写不下多 localid，见 §八·2）。

### 3. 编排（`run-sync.ts`，老 `sync_plan.py` 四步 ＋ `run_sync.py`；缺陷修法）

- 四步顺序固定：补计划 → 记心愿 → 推送（串行 N 天，45 秒限频）→ 回写（一次 `backfill --days N`，天数＝同步天数）；
  缺省 3 天／偏移 0／`dry-run` 只建状态文件（老 `run_sync.py:168-175` 同述）；状态文件与老同路径同写法；
- 老缺陷：`run_sync.py` 只在超时／抛错时判失败，子进程 rc（如推送 `fail_count>0` 退 3）只记 `results[].rc`、
  不进最终状态——推送全失败也可能 `completed` 退 0（`__main__:157-160` 只看 `status`）；
- 修法：任一步失败即停——状态 `failed` ＋ `failed_step` 点名（`推送 YYYY-MM-DD`／`回写`／`补计划`／`记心愿`）＋
  非 0 退出（码复用 `exitMap`：无 KEY→2，其余→3，用法错→1）；后步不跑（`t610` 断言回写 0 次）；
- 补计划／记心愿缺省跳过：作息管家／备忘录不在本仓，记 `skipped` 不算失败（#614 接线后换真实现，见 §九 R3）。
