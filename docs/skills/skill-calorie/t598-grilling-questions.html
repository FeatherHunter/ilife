#598 跨技能调用怎么走：第一轮三问

目标 / 边界 / 风险先定 → 下一轮再烤选项权衡与决策。看完直接回 Q1 / Q2 / Q3 即可。

背景：为什么今天一条路都跑不通

要保的链
「落地」链 Step1（补计划→作息）、Step2（记心愿→备忘录）都要调别的技能，调不通则 #599 / #600 / #612 全被堵。
两处不同形
调用方 readSkill 要 --skill/--domain/--from/--to、回 {ok, data}；被调方 skilllink read / cmd_read 要 read <skill.combo> --params JSON、回 envelope{version,skill,shape,key,data}（无 ok）。对上了才通，现在对不上。
无配置位
readSkill.command 缺省即阻断，全仓 0 调用点；combos.yaml 156 键中 schedule.* / memo.* 为 0，被调方无 key 可挂。
术语统一：下文 A = 同进程调 readSkill() 函数，B = 跨进程调对方 cmd_read / skilllink read。不再混叫「跨技能调用」。

Q1 · 目标定到哪 — 只保落地链，还是把全仓口径一次定死？

前因
票面目标是「定卡路里调别的技能这条路怎么走」，但 #593 只急需 Step1 / Step2 跑通。
后果
定小＝#598 快关、通用债后移；定大＝一次改框架＋配置位＋combos 口径，#599 / #600 要等。
选项含义
A. 只定落地链只裁 Step1 / Step2 走 A 还是 B；通用口径只写边界与例外
B. 一次定全仓连 readSkill 改形、配置位归属、combos 准入一起定死
➡️ 推荐 A（只定落地链）。落地链等不起框架重构；通用口径本轮只留接口（谁配、配在哪），实现后移。
选 A 利：快，能解 #612 阻塞；改动面小，易验收。
弊：通用债还在，需另开票。
选 B 利：一次干净。
弊：战线拉长，落地链被拖；一次改对的风险高。

Q2 · 边界是读还是写 — 本票管不管写操作？

前因
readSkill 头注写死「只读」；但 Step1（作息 ensure）/ Step2（备忘录 create）都是写。
后果
若只定读，修好 A 也救不了 Step1 / Step2；若读写一次定，则写只能走 B，选项 1（修框架）自然出局一半。
选项含义
A. 只定读写另开票；本票结论与 Step1 / Step2 脱钩
B. 读＋写一次定明写：读可二选一，写只能走 B
➡️ 推荐 B（读＋写一次定）。否则本票定了也堵不住 #599 / #600 的真需求，等于白定。
选 B 利：结论直接可用，#599 / #600 不用返工。
弊：本票要多写一条写口径。
选 A 利：票面小。
弊：Step1 / Step2 仍无路可走，#598 形同虚设。

Q3 · 风险哪条必须当门 — 验收门槛卡多严？

前因
三条风险：a) 无配置位即阻断；b) argv / 输出不同形；c) combos 无 schedule.* 可调。
后果
门槛决定 #598 关票标准：a+b 不解则一步都走不通；c 可留给 #599 / #600 配 key 时收。
选项含义
A. a+b 当门真调用读数＋改坏必红 / 还原必绿只验 a、b；c 只定归属
B. 全当门c 也要在本票配出 key 并跑通
➡️ 推荐 A（a+b 当门，c 放行）。a、b 是今天跑不通的根因；c 是执行层加 key，不必堵在本票。
选 A 利：关票快，#599 / #600 接得住。
弊：本票看不到端到端 key。
选 B 利：一次看到头。
弊：把执行票的工作前移，本票变大。
