## 2 新旧断言对照

旧（改前，「页面不许内嵌二进制」）：

```js
assert.doesNotMatch(html, /base64/);
```

新（#439，口径收窄成「只许内嵌图片」，留在 `cmd-read-t11.test.mjs` 同一用例内）：

```js
const dataUris = [...html.matchAll(/data:([^;,)"'\s]*)/gi)].map((m) => m[1].toLowerCase());
assert.ok(dataUris.some((m) => m.startsWith('image/')), '画廊页应内嵌照片，缺 data:image/…');
assert.deepEqual(dataUris.filter((m) => !m.startsWith('image/')), [], '页面只许内嵌图片，发现非图片 data URI');
```

保留的两颗牙齿：

- ① 页面**真内嵌了照片**：整页里一处 `data:image/…` 都没有即红 —— 防「内嵌退让成不嵌」这种反向失败；
- ② 除图片外**不许出现别的 `data:` URI**：夹带 `data:application/…` 之类即红 —— 这正是旧断言的原意（防止页面滥嵌二进制）。

同一处口径还改了用例标题：`T10 照片 parity：画廊/单图/对比/动图/HELP + 二进制不内嵌` → `… + 只内嵌图片`（标题原本就在描述这条被改的判据，不改就会留下与断言不符的字样；未扩大范围到其它断言）。

**为什么不是永真断言**：把页内一处 `data:image/jpeg;base64,` 换成非图片的 `data:application/octet-stream;base64,`（该页有两张内嵌照片，只换其中一张），断言 ② 当场红，读数是 `actual: [ 'application/octet-stream' ]`（见 §3 第 4 条）。页内其余 `data:` 只有照片内嵌件产出（`packages` 下产出 `data:` 的三处：`photo/photoThumb.ts:52`、`photo/gifDoc.ts:145`，都是 `image/…`）。
