## 四、与地图正文不符的说法（要回写地图）

1. **`goal_config.html` 不是「找不到、要新设计」**。地图正文写「`goal_config.html` 在旧目录里**找不到**（只有它没被引用的两个分身 `goal_config_nutrition`／`goal_config_water`），这一类要新设计」——实测：`render_goal_config.py:31-32` **逐字读盘**的正是这两张文件，它们是这个家族的**本体**，不是分身；`goal_config.html` 只是老触发词表里的一处陈旧名字（与 `main_prompt.cli` 当年指老脚本属同一类漂移）。**结论：本图没有「没有实物、要凭空设计」的页面。**
2. **写前页不是本图新发明的**。地图正文把「预检确认页」记为本图预期贡献的公共层部件之一；实测老技能这一族**本来就有写前页**：`goal_weight.html` 的 4 个 mode、`render_goal_config.py --modify-*` 的「改前 → 改后 ＋ 影响预估」、`goal_recommend.html` 的推荐页。**可以照老实物分析，不凭空设计**（与 #131 的成功路子一致）。
3. **`看目标历史完成` 与 `看体重目标进度` 的老出口都不是 `render_goal_progress.py`**：前者是数据函数（`_triggers.py:2473`），后者走 `calorie_tracker.py weight-goal-progress`（`_triggers.py:2353`）。**这两条词的「老技能怎么做」不能按同族脚本推断**。
4. **老技能里「写前」与「写后」不是按词分的，是按脚本开关分的**：营养／饮水这一族**同一张页**兼作写前对照与写后回执；体重这一族才明确两分（`goal_weight.html` / `goal_weight_result.html`）。本图若要按「写前页／写后页」切票，切法必须照开关切，不能照模板名切。
