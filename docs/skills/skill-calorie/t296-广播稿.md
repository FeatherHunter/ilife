## 三 · 你该改哪儿、不该改哪儿

| 面 | 你动它吗 |
| --- | --- |
| `src/<你的能力>/commands.ts` ＋ 该能力目录内的实现 | **只动这里**（加命令的全部动作） |
| 各汇总位（生成物） | **不动**，由 `pnpm gen` 写；手改会被 `gen:check` 抓红 |
| `src/cli/legacyCommands.ts` | 搬迁时**手删你那条**；它全场共用，**动前抢锁** |
| `src/triggers/routing.ts` | 要能被唤醒词命中就得动；手写路由表，**动前抢锁，只加／删自己那一行** |
| 页面内容、命令补齐 | **不归你**：归各自场景的图（体重归 `#154`） |
| 门（`gen:check`、两个棘轮、CI 步骤） | **只许更强不许更松**；`continue-on-error` 全仓禁用 |

**撞车怎么办**：开工前声明自己会写的路径集合；**跨图撞车停下报告，不自行改别人的行**。
两个 session 同搬两个场景 = 抢 `legacyCommands.ts` 这一支笔，这是已知未解的结构问题（归 `#297`）。

  （`packages/skill-calorie/test/cmd-write-40-persist.test.mjs`）与 `docs/research/t97-probe-receipts.mjs` 的场景行。
  读命令没有这面（实测 `test/` 下 0 件必改）。

  且 `pnpm build` 解不开。这是 `#295` 已知待修口径（`t295-复审-红队.md` 的 A4）。
  被它挡住时**不要删文件、不要改门**，报告编排者。
