## 四、6 条裁定（本图强制基准）

每条给：结论／理由一句话／可判形式（跑哪条命令 → 看哪个读数 → 等于什么）／落点票。

### 裁定 1 · 回执 op 状态机一件顶三写词

- 结论：改／加／删照片标签三条写命令同一回执形状——首屏徽章与标题随 op 切（存入／修改／删除），标签对照行随 scene 换（改前改后／加前加后／删除前删除后），无变化降级句与空标签灰底 `无` 同步。
- 理由：老页把三写词收成一页（`body_photo_receipt.html:154-165`／`:215-219`），三套各写一遍会三处口径各说各话。
- 可判形式：跑 `calorie-cmd-read calorie.photo.tag` 改／加／删各一（`op` 取 `set`／`add`／`remove`）→ 落盘 HTML 首屏徽章读数分别等于存入／修改／删除三色徽章，对照行读数分别等于改前改后／加前加后／删除前删除后 → 三组读数各自等于期望值才算实施。
- 落点：#282。

### 裁定 2 · 配置型 prompt 即 CLI

- 结论：两张过程型页的 prompt 预览区等于 bash 可执行命令，缺项等于指步骤占位句（未选照片／未填 tag 各指一步），引号转义与回执指定句照旧。
- 理由：过程型页的价值就在 prompt 那一下复制，复制的不是照抄即跑形状等于白跑一条命令。
- 可判形式：跑 `calorie-cmd-read calorie.view.gif-planner` 与 `calorie-cmd-read calorie.view.photo-log-wizard` → prompt 预览区读数等于 bash 可执行命令（含 `calorie.photo.gif`／`calorie.photo.add` 全形，见 `wizardPort.ts:195`／`:84`）；缺项时读数等于指步骤占位句（`:169`／`:78-79`）→ 两条都成立才算实施。
- 落点：#283。

### 裁定 3 · 体积横幅与三态

- 结论：看身材照超限出横幅（已嵌入 N 张／还有 M 张未嵌入），网格三态（未嵌入／文件缺失／无法读取）原因文案齐全；可见文本缺值写 `—`，复制数据保留原始空值。
- 理由：老页横幅与三态是同一套体积口径（`body_photo_gallery.html:143-151`／`:156-163`），只出 N 不出 M 等于让用户猜还有多少。
- 可判形式：跑 `calorie-cmd-read calorie.photo.list`（造超限＋缺文件）→ 读横幅 N／M 读数与三态原因文案 → 横幅含两数、每张坏图原因各有归属才算实施。
- 落点：#281。

### 裁定 4 · 浏览链与可比性

- 结论：对比页跨标签出警告行＋间隔 N 天（间隔横幅老页 `body_photo_compare.html:98` 即有）；详情页上一张／下一张首尾禁用态、无坏链（老页 `body_photo_viewer.html:74-77` 链接＋`:137`／`:142` 置灰）。
- 理由：跨标签不提示会得出假对比；上一张／下一张印数字不可点等于浏览链断在第二跳。
- 可判形式：跑 `calorie-cmd-read calorie.photo.compare` 跨标签 → 读警告行（`html.ts:173-175`）＋间隔 N 天（`photo.ts:140`）→ 两读数等于期望；跑 `calorie-cmd-read calorie.photo.detail` 首尾两张 → 禁用态无坏链 → 四读数全成立才算实施。
- 落点：#281。

### 裁定 5 · 五片段整页化与复制区分族

- 结论：`src/render/html.ts` 六个照片 render 函数（`:141` 回执、`:159` 画廊、`:170` 对比、`:180` 单图、`:186` GIF、`:215` HELP）逐页经整页装配出完整文档（落盘 HTML 含 doctype），复制区分 prompt／数据两族；`src/render/html.ts` 645 行已超线，只读不加行，新逻辑只许落在能力目录与共用件。
- 理由：现状裸片段声明了「这是一页」却不是一页（`pageShell` 只出 `section`，见 `html.ts:39-46`），而超线件加行等于把告警线当摆设。
- 可判形式：跑六出口 → 落盘 HTML 首行读数等于 doctype，且每页复制区按族出现（过程型页有 prompt 族）→ 六页全含才算实施。
- 落点：#352 牵头首定（GIF 结果页），余页随 #281／#282／#283 复用同一口径。

### 裁定 6 · 大图观看规则

- 结论：详情页大图黑底 75vh contain（老页 `body_photo_viewer.html:28-29`）；删记录说明按新硬删除口径（`manage.ts:4-5`、不可恢复），老页 `:98`「文件保留」提示作废。
- 理由：大图规则是老页唯一可看性口径；而新仓删除连文件一起删，老提示继续留会误导用户以为文件还在。
- 可判形式：跑 `calorie-cmd-read calorie.photo.detail` → 大图区样式读数等于黑底＋75vh＋contain；删记录说明读数等于硬删除不可恢复、全文不出现「文件保留」→ 两条都成立才算实施。
- 落点：#281。
