# t352 · GIF 结果页内嵌（说「做身材照GIF」跑完拿到能播放的 GIF，页里也嵌着它）

## 目标

`calorie.photo.gif`（做身材照GIF）的产物从**一段任务描述**改成**一页完整文档＋页内嵌着那份 GIF**：
用户说一句话，拿到的是能播放的动图页面（＝老技能 D5 结果页的形状），不是「请外部按本任务描述执行」。
本票只做接上：合成能力来自 #284（`gif.ts`），页面形状与体积口径来自 #341／t400 基准。

## 改法（一句话一件）

- 取数不动：`viewPhotoGif` 仍走 `photo.ts` 的 `buildGifTask`（标签／窗口／入片 id／首末日期口径一字不变；
  零匹配仍 `missing-data` → CLI exit 4，GIF 与页面都不落盘）。
- 合成与装配走本能力内**新件** `src/photo/gifDoc.ts`（271 行 LF）：① 编排 #284 的
  `synthesizeGifFromPhotos` 落盘；② 用共用件 `assembleDocPage`／`dataCopyArea` 装配整页；
  ③ 体积超预算即不内嵌、改出本地路径提示。
- 落盘位与命名沿老技能 `body_photo_tracker.py:416-417`／`:575-581`：
  `<照片目录>/gifs/<标签>_<首张日期>_<末张日期>.gif`，同名覆盖；帧序按拍摄日期正序
  （老 `:463` 的 `ORDER BY date ASC, time ASC`）。缺照片文件的那张跳过、其余照合成（老 `:480-482`）。
- `viewPhotoGif` 返回的 `data` 就是页内复制区那一份（交付层再另加 `output`）：同一份数据，不做两次取数。
- `src/render/html.ts` 超线只读（647 行 LF，本票零加行）：老裸片段 `renderGifHtml` 保留给 T10 快照测试，
  本命令出口已不再经过它。`commands.ts`／`routes.ts` 一字不动（命令名、形状、入参口径都不变）。

## 能力边界（如实照写，不含糊）

- 合成的是**容器级** GIF：合法 GIF89a 容器、循环播放（NETSCAPE 0）、帧延时 50cs、帧数＝入片张数（下限 2）。
- 每帧是**实心帧**，帧色由该张输入照片的字节哈希（FNV-1a）派生——**不是像素级光栅转码**。
  真 JPEG／PNG→GIF 像素还原需要解码器（纯 JS 约千行，或走外部执行路线），不在 #284 与 #352 射程。
- 因此本页承诺的是「拿到一份能播放、与盘上文件逐字节同源的 GIF，且页里嵌着它」；
  **不承诺**「页里看到的是照片像素」。页内字节与盘上文件同源（用例③以长度＋sha256 钉死），
  不等于画面就是用户本人的样子。
- 合成不成（未配照片目录／可读照片不足 2 张／超体积上限）即降级：页面照出、页内明示原因与替代操作。
  老实现是 `render_body_photo_gif_result.py:47-48` 直接抛；本仓为页面交付，改成页内大声说，
  不静默、也不出空白舞台。

## 帧数与体积上限

- 帧数＝入片张数，下限 2（`GIF_LIMITS.minFrames`）；GIF 体积上限 512000B，超限即抛且**不落半张**。
- 入片张数上限受既有取数口径约束：`planGif` 走 `listPhotos(..., limit: null)`，而 `photos.ts:119` 的
  `filter.limit ?? 100` 会把 `null` 落回 100 → 单次最多 100 张入片（本票不碰取数，登记为下一手）。
- 页面体积上限沿用 t341 首定的 `PHOTO_LIST_PAGE_MAX_BYTES`（1048576，定义只在 `galleryDoc.ts`，本件只引用）。
- 内嵌与否按**实测页字节**判定：装配完量一次，超上限即弃内嵌、改为本地路径提示（老页
  `body_photo_gif_result.html:99-101` 同义机制，阈值按本仓 1 MiB，不是老家的 8 MiB）。
- 实测读数（1×1 夹具）：3 张入片 → **真跑**页 65670B／GIF 117B／3 帧（收口席本轮）；
  4 张入片 → 页 66155B（收口席合并链；前席读数 66163B，差 8B 为他席在改的共用件微动）／GIF 141B／4 帧。
  断言全部按相对口径，不钉绝对字节值；
  直接驱动渲染件 2285 张 → 内嵌版 1086129B ＞上限，弃嵌后 1012949B ≤ 上限（见「移植项 3」用例）。
- 结论须写明：**在本仓现有两道上限下，CLI 那条路走不到「页超上限」这一支**（入片 ≤100 张 ⇒ 页 ≈110KB ≪ 1MiB；
  GIF ≤512000B ⇒ 内嵌最多加约 683KB base64）。这一支是体积口径的安全网，机器证据由直驱渲染件给出。
