## 二、第二步 · 结构设计

### 目录树

```
packages/skill-calorie/src/exercise/     ← 能力目录（HELP 一级分组「运动」）
├─ add.ts         记运动   写：calorie.exercise.add 族的校验与分派
├─ update.ts      改运动   写：calorie.exercise.update ／ .remove 族
├─ view.ts        看运动   读：calorie.view.exercise 全族（汇总页 ＋ 记录级明细页 ＋ 对照目标页）
├─ analysis.ts    运动分析 读：calorie.view.exercise-{distribution,strength,cardio,trend}
├─ recap.ts       运动复盘 读：calorie.view.exercise-recap
├─ rows.ts        能力内部取数（记录级行与聚合），本目录自用、不对外
└─ index.ts       能力对外唯一出口
```

**文件名的来源（铁律四：取自下一级＝子功能）**：HELP 运动组的 5 个子功能 id 是 `记运动`／`改运动`／`看运动`／`运动分析`／`运动复盘`；英文名取自仓内**现成说法** —— 前三个与后两个分别对应命令段 `add`／`update`／`view`／`recap`，中间一个取 HELP 里同义的现成词 `analysis`。不自创。

### 每件对外给什么（铁律五：一个文件不多于 5 件）

| 文件 | 对外件（能力内部件不对外） | 说明 |
|---|---|---|
| `add.ts` | 1 件：写命令分派入口 | 内部含校验、写库调用、回执数据组装 |
| `update.ts` | 1 件：改／删命令分派入口 | 同上 |
| `view.ts` | ≤3 件：汇总页装配、记录级明细页装配、对照目标页装配 | 三张页共用同一段取数（走 `rows.ts`） |
| `analysis.ts` | ≤4 件：分布页、力量总览页、有氧总览页、趋势页装配 | |
| `recap.ts` | 1 件：复盘页装配 | |
| `rows.ts` | 本目录自用（不对外） | 今天住在 `src/render/exercisePort.ts`；**记录级取数 `listPortRows` 已现成** |
| `index.ts` | ≤5 件：整个能力对外的门 | 别的能力只经这里用运动能力 |

### 一处跨界（**不整件搬，只切自己的那半**）

- `src/render/exercisePort.ts` 的 `buildReviewView` 属**场景 05 健身计划**（`calorie.view.exercise-review`＝计划复盘），不搬，留给场景 05 的图。

- `src/render/sportPortDocs.ts` 的 `buildReviewDoc` 属场景 05，不搬。
- 结论：`sportDocs.ts`／`sportPortDocs.ts`／`exercisePort.ts` 这三个「按工种起名、装了几个场景」的文件，**本图只切出运动那一份**；剩下的残件留给各自场景的图。整包重排票到位时一并收口。
