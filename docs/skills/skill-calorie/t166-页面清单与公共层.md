## 四、唤醒词与工作流程的实证缺陷（第 10 张票的输入）

`SKILL.md` 的联动速查表由 `scripts/build-help.mjs:209-221` 用**手工维护**的 `REPR` 表生成，缺项时 `:214` 的 `REPR[k] || k` **静默退回命令名**。饮食一族的实测后果：

| `SKILL.md` 行 | 现象 |
|---|---|
| `:129` | 首列是命令名 `calorie.view.dedupe` —— 这个场景**找不到底层唤醒词**（路由层有 `看食品库（去重）`） |
| `:120`／`:131` | **同一个词「看今日饮食概览」用在两条命令上**，且该词属**场景 01**（本场景的今日饮食词是 `看今日饮食`） |
| `:132` | 首列 `今日复盘` —— 本场景的词是 `饮食复盘（本周）` 等 5 条 |
| `:167` | 首列 `查高热量排行` —— 本场景的词是 `看高热量榜`（5 类榜 × 4 窗口共 21 条，表里一条都没有） |
| `:153` | 首列 `查食品库` —— 本场景的词是 `查食品（按分类）` |
| 全表 | **70 条词里绝大多数在表里没有行**：一张表一行一条命令，21 条榜单词、5 条餐别词、5 条复盘词、4 条预检词、备注词、6 条缺命令的词都查不到自己的那一步 |
| `exampleFor` | 逐条写死种子日期（`:101`／`:111`／`:119`／`:120` 的 `2026-09-xx`），照抄出来的命令指向过期时间段 |
| M6 | 写着「写键」「调写键」等**禁用词**（`docs/agents/wording.md`）；**饮食的 15 条写词不在 M6 的词 → 页映射表里** |
