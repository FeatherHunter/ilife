## 1 回改判据与理由

**① 修法必须入仓（不能让红门变成死门）**：同步能力原只在被忽略的 `.scratch/t445/` 草稿里，

- `--sync`＝落盘同步台账；`--sync --dry`＝只演练（打 `SYNC-PLAN 改=／增=／删=` 与逐条
  `SYNC-CHANGE`／`SYNC-ADD`／`SYNC-DROP`，**不写文件**，打 `SYNC-DRY ok`）；
- 只改 `begin/end` 之间那块表；§2.5-1 全流程＝先在内存算新全文 → 跑完全部断言（含**块外前后缀逐字节相同**
  与**冻结挂号值未被改写**）→ 全过才落盘 → 落盘后回读并打 `SYNC-VERIFY ok`；任一断言红即 `exit ≠ 0` 且**不落盘**；
- 红条文案末段直接点这条仓内命令：`修法：node packages/skill-calorie/scripts/check-warning-line.mjs --sync`；
- 仓内同步器自带用例：`packages/skill-calorie/test/t445-告警线门.test.mjs` 的 T8（`--dry` 不改文件、
  `--sync` 回绿、台账块外一字不动、冻结挂号值未被改写）与 T9（真包 `--sync --dry` 零改动）。

**② 生成物剔出扫描面与台账（判据 ⑧，名单以生成器自己的输出声明为准）**：`structure.md` 明写不管
「生成的资产」，而重跑 `pnpm gen` 会改生成物行数，逼无关的票来同步台账——跨图摩擦，且没人真的在编辑它。
剔除名单**不做手写常表**，只读本包 `scripts/gen-*.mjs` 的输出声明：`const <名> = join(SRC_DIR, 'a', 'b.ts')`
（名字里带 `OUT`／`TARGET(S)`／`DST`／`DEST`／`GEN…` 段）与 `targets` 数组里的 `path: join(SRC_DIR, …)`；
认不出的段（变量、模板串、拼接）一律放弃——**宁可漏剔，不可误剔**（误剔＝放宽这道门）。
当前剔出三件，运行读数逐条打 `GENERATED-SKIP <件> LF=<n>（由 … 生成，不在扫描面内）`：

|---|---|---|---|
| `src/cli/keys.ts` | 167 | `scripts/gen-cli.mjs`（`targets` 里 `path: join(SRC_DIR,'cli','keys.ts')`） | `pnpm gen` 重生成，无人手编辑 |
| `src/cli/registry.ts` | 50 | `scripts/gen-cli.mjs`（同数组 `path: join(SRC_DIR,'cli','registry.ts')`） | 同上（未超线，剔它是为了不让它以后超线时逼人来同步） |

**两条自证**（防生成器重构后判据静默失效）：本包有生成器却一条输出声明都抽不到即红
（`RED 生成物判据自证`）；扫描面里**带「勿手改」印记却没被认出**的件即红（`RED 生成物印记已认领：<件>`）。
**手写的 `src/triggers/routing.ts` 仍在扫描面内**：它 `import` 生成物，但本身是人写的逻辑与类型再导出件
（`src/triggers/routeSpec.ts` 同）——判据是「**谁生成**」，不是「谁 import 生成物」；人改了它照常挂号。
