## 1. goal_weight.html 的四个 mode

来源：`render_goal_weight.py`。这张模板由 `--mode` 四选一驱动（`argparse` 里四个值互斥必选）：

| mode | 中文场景名（SCENE） | SCENE_ID |
|---|---|---|
| `basic` | 定体重目标 | `goal_set_weight` |
| `auto_deadline` | 定体重目标(自动算截止) | `goal_set_weight_auto_deadline` |
| `with_start` | 定体重目标(含起始日) | `goal_set_weight_with_start` |
| `modify` | 改体重目标 | `goal_modify_weight` |

四个 mode 共用的底座键（`build_data` 开头无条件组装）：
`mode`、`current_weight`（`weight_log` 最新一条 `weight_kg`，四舍五入 1 位）、
`target_weight`（`get_weight_goal()` 第 0 位＝当前目标）、`deadline`（第 1 位＝当前截止）、
`start_weight`、`start_date`（`daily_goal` 表 `id=1` 的起点快照）。
另外 `data['meta']`（唤醒词／来源／思考链）**不进页面**，只随复制日志带出。
`--chain` 是强制项：没传或无效，脚本直接退 2，不出页面。

（逐 mode 的版块与数据位见下）

---

### 1.1 mode = basic —— 定体重目标

- 什么时候用：用户只说「定体重目标」，只要一个目标 kg（截止日期选填）时。
- 版块（顺序）：
  1. 标题／副标题（`title` = `定体重目标`，`subtitle` = `目标 kg + 可选截止日期`）
  2. 当前体重行（`current_weight`）
  3. 目标／截止对比
  4. 差值行（`delta_kg`）
  5. 建议速率行（`rate_check`）
  6. 填写字段区（`fields`）
  7. 命令提示（`extraPrompt`）
- 吃的数据位：
  - `current_weight` —— 最新体重记录，kg
  - `target_weight` —— 当前已设目标（回显）
  - `deadline` —— 当前截止日（回显）
  - `delta_kg` —— `current_weight - target_weight`，正数＝需减、负数＝需增；**只有当前体重与当前目标都不为空才算**，否则这个位根本不进页面
  - `rate_check` —— `build_rate_info()` 的整条字典（同一条件才算）：`gap`／`days`／`per_week`／`per_month`／`formula`／`ok`／`extreme`／`text`
  - **本 mode 的坑**：`days = _days_until(deadline) or 90`。即截止日缺失、或算出来是 0／负数时，速率一律按**写死的 90 天**算（代码里 #78 的注释承认这里曾长期写死、连用户给了截止日也算错）。
- 字段区 `fields`（`key`／`label`／`unit`／`placeholder`）：
  - `weight-goal` · 目标体重 · kg · `如 70`
  - `deadline` · 截止日期 · 无单位 · `如 2026-12-31(选填)`
- 可交互的东西：这一页**没有复制按钮**（它是填写页，不是回执）。AI 侧的约束写在 `extraPrompt` 里：目标没给或档案缺失就先问用户补齐，已经明确就直接做；速率和数字**一律照页面预计算的「建议速率」行念，禁止自行推算或编造**。

---

### 1.2 mode = auto_deadline —— 定体重目标（自动算截止）

- 什么时候用：用户给目标 kg ＋ 期望速率，要页面／AI 反推一个截止日期并做速率校验。
- 版块（顺序）：
  1. 标题／副标题（`title` = `定体重目标(自动算截止)`，`subtitle` = `目标 kg + 期望速率 → 自动推算截止日 + 速率校验`）
  2. 当前体重行
  3. 目标／截止对比
  4. 建议速率行（`rate_check`）
  5. 填写字段区（`fields`）
  6. 命令提示（`extraPrompt`）
- 吃的数据位：
  - `current_weight` —— 最新体重记录
  - `target_weight`／`deadline` —— 当前目标与截止（回显）
  - `rate_check` —— **本 mode 是写死的提示字典**：`{'ok': True, 'text': '合理速率带 0.25~1.0 kg/周,超范围会提示'}`。也就是说：`build_rate_info()` 那套公式计算**不参与本 mode**，页面只给带范围说明。
  - 注意：`build_data` 里 `delta_kg` 只在 `basic` 分支赋值，所以 `auto_deadline` 页**没有差值行**。
- 字段区 `fields`：
  - `weight-goal` · 目标体重 · kg · `如 70`
  - `rate` · 期望每周速率 · kg/周 · `如 0.5`
- 可交互的东西：同样**无复制按钮**。`extraPrompt` 要求：按用户给的速率推算合理截止日，并校验速率是否落在安全范围 `0.25~1.0 kg/周`；速率照页面预计算数字执行，禁止自行推算或编造。

---

### 1.3 mode = with_start —— 定体重目标（含起始日）

- 什么时候用：走完整的起始设定，要一次性收齐「目标 ＋ 起始日 ＋ 截止日 ＋ 起点体重」。
- 版块（顺序）：
  1. 标题／副标题（`title` = `定体重目标(含起始日)`，`subtitle` = `完整 setup: 目标 + 起始日 + 截止日 + 起点体重`）
  2. 当前体重行
  3. 目标／截止对比
  4. 起点信息（`start_weight`／`start_date` 快照，进「当前状态」KPI 区）
  5. 建议速率 —— 模板里由前端 `computeEstimate()` 按**起点体重＋起始日**现算（`D.mode === 'with_start'` 时起点换成表单值／快照值），不是渲染器给的 `rate_check`
  6. 填写字段区（`fields`）
  7. 命令提示（`extraPrompt`）
- 吃的数据位：
  - `current_weight` —— 最新体重记录
  - `target_weight`／`deadline` —— 当前目标与截止（回显）
  - `start_weight` —— 起点体重快照（`daily_goal.start_weight`，空则为 `None`）
  - `start_date` —— 起点日期快照（`daily_goal.start_date`，空则为 `None`）
  - `rate_check` —— **本 mode 未赋值**，所以页面上这条只能靠前端 `computeEstimate()` 补
- 字段区 `fields`：
  - `weight-goal` · 目标体重 · kg · `如 70`
  - `start-date` · 起始日 · 无单位 · `如 2026-08-01`
  - `deadline` · 截止日期 · 无单位 · `如 2026-12-31`
  - `start-weight` · 起点体重 · kg · `如 75`
- 可交互的东西：**无复制按钮**。`extraPrompt` 要求完整记录起始日与起点体重作为目标起点；速率与数字一律照页面预计算的「建议速率」行，禁止自行推算或编造。

---

### 1.4 mode = modify —— 改体重目标

- 什么时候用：已经有目标，用户要改目标值或截止日。
- 版块（顺序）：
  1. 标题／副标题（`title` = `改体重目标`，`subtitle` = `改目标值或截止日,显示改前/改后 + 新建议速率`）
  2. 当前体重行
  3. **改前／改后对比**（`old_goal`）
  4. 建议速率行（新目标口径）
  5. 填写字段区（`fields`，标签已带「新」字）
  6. 命令提示（`extraPrompt`）
- 吃的数据位：
  - `current_weight` —— 最新体重记录
  - `old_goal` —— **只有本 mode 有的位**：`{'weight_goal': 当前目标, 'deadline': 当前截止}`，专门供「改前」那一栏
  - `target_weight`／`deadline` —— 仍是当前值（作为改后对比的基线）
  - `rate_check` —— 本 mode 也**未赋值**，页面上的「新建议速率」靠 AI 按 `extraPrompt` 给
- 字段区 `fields`（placeholder 是**动态拼当前值**的）：
  - `weight-goal` · **新**目标体重 · kg · `当前 <current_goal>`，当前目标为空时退化成 `如 70`
  - `deadline` · **新**截止日期 · 无单位 · `当前 <deadline>`，当前截止为空时退化成 `选填`
- 可交互的东西：**无复制按钮**。`extraPrompt`：显示改前／改后，并按新目标给出建议速率；速率照页面预计算数字执行，禁止自行推算或编造。

---

### 1.5 四 mode 横向差别（重写要点）

| 比较项 | basic | auto_deadline | with_start | modify |
|---|---|---|---|---|
| `rate_check` | 有（`build_rate_info` 真算） | 有（写死提示字典） | **无** | **无** |
| `delta_kg` | 有（条件：当前体重＋当前目标都在） | 无 | 无 | 无 |
| `old_goal` | 无 | 无 | 无 | **有** |
| 字段数 | 2（目标、截止） | 2（目标、速率） | 4（目标、起始日、截止、起点体重） | 2（新目标、新截止） |
| 速率健康带 | 0.25–1.0 kg/周，`per_week >= 1.0` 判极端 | 文案 `0.25~1.0` | — | — |
| 复制按钮 | 无 | 无 | 无 | 无 |

速率（`build_rate_info`）口径，新仓照抄即可：`per_week = |gap| / days * 7`，`per_month = per_week * 52 / 12`；
`per_week >= 1.0 → 极端警告`、落在带内 → 合理、低于带 → 偏低（达成周期偏长）；
`formula` 固定格式 `<gap:.1f>kg ÷ <days>天 × 7 = <per_week:.2f> kg/周 ≈ <per_month:.1f> kg/月`；
`text` = 判定句 ＋ ` · ` ＋ `formula`。浮点用 1e-9 容差消除 `x/7x*7 = 0.9999999999999999` 这类噪声。

### 2.1 goal_weight.html 的页面骨架（四 mode 共用同一张模板，先看清一遍）

模板文件里**没有 mode 分支**，四个 mode 全靠注入的 JSON 走不同显示。骨架从下往上就这几块：

1. `header.hero` —— `eyebrow「卡路里 · 目标管理」`、`h1#title`、`div#subtitle`
2. `div.section` **当前状态** —— `h2 当前状态` ＋ `hint 体重目标进度` ＋ `div#kpis`
3. `div.section` **设置目标** —— `h2#fieldTitle`（默认 `设置目标`）＋ `hint 填写你的目标` ＋ `div#fields` ＋ `div#resultBox`
4. `section.copy-section` **确认目标** —— 说明句「确认无误后,复制下方指令发给 AI,AI 会调用写库。」＋ 按钮 `btnAdopt`「✓ 复制指令给 AI」＋ `div#copyPreview` 预览区
5. `footer` —— `卡路里 Skill · 体重目标 · 2026-08-02`
6. `div#actionbar-zone` —— 由 `window.actionBar(window.__P__)` 注入（复制数据／复制日志按钮在这里落地）

顶部固定件：`<script id="payload" type="application/json"><!--INJECT-DATA--></script>`（占位符，渲染器要求恰好出现 1 次），
`<!--SHARED-CSS-->`、`<!--SHARED-HELPERS-->` 两个共享占位符。页面拿不到 payload 或 `status !== 'ok'` 时整页换成错误回执。

**`#kpis` 的顺序（renderKpis，全部条件渲染）**：
`当前体重` → `目标` → `差距` → `截止` → `推算截止` → `建议速率` → `起始日` → `起点体重`。
最后两行（起始日、起点体重）有去重规则：只有当 `起点体重` 与 `当前体重` 相差 ≥ 0.1 才显示，刚设完目标、起点＝当前时不显示，避免和「当前体重」重复。

**`#fields` 渲染（renderFields）**：按 `D.fields` 逐条出 `<div class="field-row">`，
里面是 `f.label` ＋ `<span class="unit">f.unit</span>` ＋ `<input type="text" data-key="f.key" placeholder="f.placeholder">`。
`data-key` 就是回传用的字典键，四个 mode 共用到这五个键：`weight-goal`／`deadline`／`rate`／`start-date`／`start-weight`。

**`#resultBox` 的实时判定（renderResult ＋ computeEstimate，纯前端算，输入框一变就重算）**：
- 截止日已过 → 红条 `⚠️ 截止日期已过,请修正`
- 目标与当前持平（`gap === 0`）→ 绿条 `✅ 目标与当前持平,无需增减`
- 有截止日 → 按提交值算：`per_week >= 1.0` 出红条（极端目标）、`>= 0.25` 出绿条（合理）、否则出蓝条（偏低）；
  后面再接一条蓝条 `按 0.5kg/周 推算达成: <日期>`；三种条的文字共用同一个 `<gap:.1f>kg ÷ <days>天 × 7 = <per_week:.2f> kg/周 ≈ <per_month:.1f> kg/月` 公式
- 没填截止日 → 绿条 `✅ 差距 <需减/需增 N kg>` ＋ 蓝条 `未设截止:按 0.5kg/周 约需 <N> 周,推算达成 <日期>`
- 以上都没命中时才退回渲染器注入的 `rate_check`（红／绿／蓝按 `extreme`／`ok` 挑色），再退回 `note`

**`modify` 专属的「改前」（renderPrev）**：`old_goal` 只要存在（哪怕全是空）就走 modify 分支。
`weight_goal` 和 `deadline` 都空 → 在 `#kpis` 后面插一条蓝条 `改前:未设体重目标 · 从零开始设定`；
否则往 `#kpis` 尾巴追加两个 KPI：`改前目标`（有值才加）、`改前截止`（有值才加）。

**`with_start` 专属（computeEstimate）**：`isStart = D.mode === 'with_start'`。为真时起点不是「当前体重／今天」，
而是表单里的 `start-weight`／`start-date`，算的是**计划速率**（起点→目标），不是当前进度。

**可交互的东西（照抄要点）**：
- 唯一写死的按钮是 `btnAdopt`（`id="btnAdopt"`，`onclick="copyAdopt()"`，文字 `✓ 复制指令给 AI`），
  复制成功后会换成绿底「已复制确认指令,粘贴给 AI 即可 ✓」。
- 复制内容是 `buildPrompt()` 拼的**文本指令**，顺序固定：
  ①`D.promptHead`（模板里没给，缺省 `我已确认体重目标,请帮我写入数据库。`）
  ②每个字段一行 `  <label>: <用户填的值>`（**空着的字段会拿 `placeholder` 顶替**，单位跟着 label 后加）
  ③一行 `建议速率(页面预计算): <差> ÷ <天>天 × 7 = <x> kg/周 ≈ <y> kg/月`（极端目标再加 `(⚠️ 极端目标,健康带 0.25–1.0)`；`gap===0` 或算不出速率的模式这一行不出现）
  ④`D.extraPrompt`（即渲染器给每个 mode 写的 AI 约束句）
- `#copyPreview` 每次输入都跟着重拼，等于把「待复制文本」先给用户看一遍。
- 复制数据／复制日志两个按钮不在模板里，由共享 helper 与 actionbar 注入（源码给省略号，本文件只见落点）。

### 2.2 goal_weight_result.html —— 是写后回执吗？是。

证据（两条都硬）：`render_goal_weight.py` 里这条路径专门叫 `build_live_result()`，
头一行就是 `wg.set_weight_goal(...)` **真写库**；模板 `<title>` 原文就是 `体重目标已写入 · 卡路里`，
页面顶部还有绿点 `已写入 · 卡路里 目标管理`。所以它是**写库完成后的回执页**，输出走 `--live`（`--kg` 必填），
而四个 mode 走的是写之前的填写页。两条路径的副标题都写 `receipt`，但页面角色完全不同。

**页面骨架（六块，前三块是填写页没有的）**：
1. `header.hero`（绿色调）—— 绿点 `已写入 · 卡路里 目标管理` ＋ `div#heroNum` 大字目标值 ＋ `<small>kg</small>` ＋
   胶囊 `#deadlinePill`（`截止 <deadline>`，没截止日就隐藏）＋ `#subtitle`
2. `div.section` **已写入字段**（`hint 数据库 daily_goal 实际值`）—— `div#kpis`
3. `div.section#journeySection` **目标旅程**（`hint 起点 → 目标`）—— 进度条 `#journeyFill` ＋ 圆点 `#journeyMarker`
   ＋ 两端标签 `#journeyStart`（`起点 <b>Nkg</b>`）／`#journeyTarget`（`目标 <b>Nkg</b>`）＋ `div#journeyMeta`。
   **默认 `display:none`，只有 `journey` 字典存在才显示**（缺失时整块不出现，界面无占位提示）
4. `div.section` **当前进度**（`hint 算式透明 · 极端目标会警示`）—— `div#rateBox`
5. `div.section` **回执数据**（`hint 可分享 · 可转发 · 可截图`）—— 按钮区（模板里是空行，按钮由共享 helper／actionbar 注入）
6. `footer` —— `卡路里 Skill · 体重目标结果回执 · 2026-08-05`

**吃的数据位**：页面读的是 `D.written`（`W`，即落库快照）＋ `D.meta`（标题／时间轴），
不是填写页那份 `D.target_weight`：
- `W.weight_goal` → hero 大数字，同时进 `document.title`（`体重目标已写入 <N>kg · 卡路里`）
- `W.deadline` → 截止胶囊 ＋ KPI `截止`
- `W.start_weight`／`W.start_date` → KPI `起点体重`／`起始日`，同样受「与当前体重差 < 0.1 就不显示」的去重规则管
- `META.wake_word` ＋ `META.fetched_at` → 副标题 `<场景名> · 写入时间 <时间>`
- KPI 顺序：`当前体重`→`目标`→`差距`→`截止`→`剩余天数`→`建议速率`→`起始日`→`起点体重`；
  注意这里 `差距` 显示 `Math.abs(D.gap)`（**只给正数，不带方向**），`剩余天数` 是填写页没有的位
- `D.journey` → `{start, target, current, pct, done, total}`，填充进度条宽度与圆点位置；
  `pct <= 2` 圆点钉在 `10px`、`pct >= 98` 钉在 `calc(100% - 10px)`；meta 出 `已完成 <pct>%` 绿 chip ＋ `已减 <done> / <total> kg`
- `D.rate` → `#rateBox`：`extreme` 红条／`ok` 绿条／否则蓝条，条内是 `D.rate.text`，
  另加一行等宽字体公式块 `D.rate.formula`。**`D.rate` 为空时固定出蓝条 `未设置截止日期,无法计算建议速率。`**（填写页没这句）
- `D.est_date`（按 0.5kg/周 推算达成日）／`D.days_left`（剩余天数）→ 只往 `journeyMeta` 里追加文字
- `D.one_line` —— 一行摘要，只进复制出来的数据，不占页面版块

**可交互的东西**：唯一自己实现的复制入口是 `payloadData()`，**复制一段 JSON**（不是填写页那种文本指令），
固定 8 个字段：`written`／`current_weight`／`gap`／`days_left`／`rate`／`journey`／`est_date`／`one_line`。
模板里原本给「复制数据／复制日志」按钮留的两个位置是空的（页面第 75–78 行），实际按钮由共享 helper 与 actionbar 注入。

### 2.3 goal_weight_result.html 与 goal_weight.html 的具体差别（哪几块不同）

| 块 | goal_weight.html（四个 mode · 填写页） | goal_weight_result.html（写后回执） |
|---|---|---|
| 顶部 | 白蓝调 hero，`卡路里 · 目标管理` ＋ 标题／副标题 | 绿调 hero，**大号数字**目标 kg ＋ 截止胶囊 ＋ `已写入` 绿点 |
| 第一块 | `当前状态`：当前体重／目标／差距／截止／推算截止／建议速率／起始日／起点体重 | `已写入字段`：当前体重／目标／差距／截止／**剩余天数**／建议速率／起始日／起点体重 |
| 第二块 | `设置目标`：**输入框** ＋ 实时判定条 | `目标旅程`：**进度条 ＋ 完成%**（只在 `journey` 有值时出现） |
| 第三块 | `确认目标`：复制**指令**按钮 ＋ 复制预览 | `当前进度`：速率条 ＋ 公式块；无速率时给固定说明句 |
| 第四块 | footer 日期 `2026-08-02` | `回执数据`：复制 **JSON** 按钮；footer 日期 `2026-08-05` |
| 数据来源 | `target_weight`／`deadline`（当前值）＋ `old_goal`（改前） | `written`（落库快照）＋ `journey`／`est_date`／`one_line`（回执专属） |
| 交互 | 用户填值 → 实时重算速率 → 复制文本指令给 AI 去写库 | 用户只读、只复制 JSON 存档分享；**不能再填、不重算** |

一句话概括差别：填写页是「让用户填、实时校验、交指令」；回执页是「把已写进去的值、旅程进度、算式一起摊开给你留档」。

### 2.4 goal_status.html —— 暂停／重启单页两态

**是什么**：`render_goal_status.py` 的单张状态页，`--status paused|resumed` 二选一，
唤醒词对应 `暂停所有目标`／`重启所有目标`。**它一进 `build_data` 就调写库函数**
（`goal_manager.pause_all_goals()` 或 `resume_all_goals()`），所以这页既是回执、也只出回执，
不产出填写页，也没有 `--live` 之分。

**版块（只一块）**：
1. `header.hero` —— eyebrow `卡路里 · 目标管理` ＋ `h1#title` ＋ `#subtitle`
2. 唯一的 `div.section`，标题 `状态`，右侧 `hint` 是 `#timeHint`，里面按顺序：
   - `div#badge` —— 唯一必出的徽标：暂停态橙底 `⏸ 全部目标已暂停`；重启态绿底 `▶ 全部目标运行中`
   - `div#note` —— 说明段，默认隐藏，暂停且有 `note` 才显示
   - `div#restore` —— 恢复入口提示，默认隐藏，暂停且有 `restoreHint` 才显示（渲染时前缀一个 `🔁 `）
   - `div#receipt` —— 等宽字体回执行，默认隐藏，有 `receipt` 就显示
   - `div.copy-row` —— 两个空位（复制数据／复制日志按钮由共享 helper 与 actionbar 注入，同样只见落点）
3. `footer` —— `卡路里 Skill · 目标状态 · 2026-08-02`

**吃的数据位**（全部来自 `build_data` 组装 + `build_meta` 包的 `meta`）：
- `title` —— `暂停所有目标`／`重启所有目标`
- `subtitle` —— `临时冻结全部目标`／`从暂停恢复全部目标`
- `timeHint` —— `时间 <r['updated_at']>`
- `paused` —— 布尔，决定徽标文案与配色，也决定 note／restoreHint 是否显示：**这是本页唯一的状态开关，没有别的分支**
- `note` —— `pause_all_goals()` 返回的 `note`，只在暂停态读
- `restoreHint` —— `pause_all_goals()` 返回的 `restore_hint`，只在暂停态读
- `receipt` —— 暂停态：`id=<id> | 日期 <updated_at> | 影响 <n> 行`；
  重启态多一段：`… · <r['resume_state']>`
- `meta` —— 含 `wake_word`（场景名）与 `source`（`daily_goal.goal_paused(goal_manager)`），**不进页面**
- 额外约束：`--chain` 不传或无效一律退 2，页面不出

**可交互的东西**：模板自身**没有任何写死按钮**（`copy-row` 是空的），
全靠注入的「复制数据／复制日志」两个按钮；页面本身也不接受输入、没有实时重算。
重启态复制的回执比暂停态多带一个 `resume_state`，这是两态在数据上唯一多出来的东西。

**暂停文案的要点（新仓照抄）**：暂停只冻结目标，**记录照常**——`note` 与 `restoreHint` 都由
`goal_manager` 那条返回给出，页面不自己编。重启页**不给 note／restoreHint**，也没有「已重启」以外的说明。

## 3. 不确定

这些都是我读不出结论的地方，新仓重写时不要照抄成「已确认」：

1. **共享件里的东西我没读过**（读不了，被预算排除）：`_base_render.py` 的 `render_template`／`write_html`／
   `render_template` 对 `<!--INJECT-DATA-->`、「恰好 1 次」的校验细节；`render_goal_common.py` 的 `build_meta`／`chain_valid`／`scene_path`；
   `html_paths.py`；`goal_manager.py` 的 `pause_all_goals()`／`resume_all_goals()` 返回的 `note`／`restore_hint`／`resume_state` 原文；
   `weight_goal.py` 的 `set_weight_goal()`／`get_weight_goal()` 返回结构。
   凡是上面写着「由共享 helper 与 actionbar 注入」的按钮，**实际标签文案与复制内容我都没看到**——
   只见模板里的空位和源码里被省略号占掉的行（`goal_weight.html` 第 220–229 行、`goal_weight_result.html` 第 153–159 行、
   `goal_status.html` 第 70–78 行）。三个模板都写着「R2 双按钮:复制数据(用户口径)/ 复制日志(排障口径)」，
   但**按钮文字、日志 6 段的字段名，我读不出来**。新仓要还原这两个按钮，得另开一次取证。
2. **模板有、渲染器不给的数据位**（模板认了，实际恒为空／走默认值）：
   - `fieldTitle` —— 模板 `D.fieldTitle||'设置目标'`，`build_data` 四个 mode 都没设，恒显示 `设置目标`
   - `est_deadline`、`suggested_rate` —— `renderKpis()` 会读，`build_data` 从不产出，**这两个 KPI 实际永不出现**
   - `note`（填写页 `renderResult` 的兜底蓝条）、`promptHead`（复制指令开头）—— 同样从不产出，恒走缺省
   - `goal_weight_result.html` 里 `D.rate.formula` 与 `D.rate.text` 同时展示，意味着出现一行「判定句＋一行公式」两个块；
     渲染器 `build_rate_info` 确实同时给这两个键，这点是清楚的，但两个块视觉上是否重复啰嗦，我没见到真实页面，无法判断。
3. **`auto_deadline` 这个 mode 的自相矛盾**：它收的字段是 `期望每周速率`（`rate`），
   但同页的 `rate_check` 是写死的提示句、`extraPrompt` 又要求 AI「按页面预计算数字执行」。
   页面上**没有任何地方把用户填的 `rate` 拿去反推截止日**——反推全靠 AI 照 `extraPrompt` 做。
   我读不出老技能原本打算怎么衔接（是 AI 算、还是页面算），新仓重写时这里要重新定方案。
4. **`with_start` 的 `rate_check` 缺位**：`build_data` 没赋值，而填写页的 `#resultBox` 判定全在前端 `computeEstimate()` 里，
   只有用户真的往输入框打字才会出速率条。**页面初次打开时这一块是空的**——是否算缺陷、还是有意为之，我读不出结论。
5. **`basic` 的 90 天兜底**：`days = _days_until(deadline) or 90`，用户没给截止日时速率一律按 90 天算，
   同时页面右栏又用 0.5kg/周 另算一个「推算达成」日期。两个口径并存、是否互相打架，我没读到拍板记录。
6. **`差距` 符号不一致**：填写页显示带符号的 `delta_kg`（正＝需减），结果回执页显示 `Math.abs(D.gap)`（永远正数、丢方向）；
   正文的「需减／需增」只有填写页前端那张判定条给得出来。回执页读者看不出方向，这是我从代码确认的差别，
   但是否有意设计，我读不出。
7. **`goal_weight_result.html` 没有 mode 概念**：它用 `--scene`（默认 `basic`）只为在 meta 里自描述场景名与 `scene_id`，
   页面本身不做 mode 分支。所以「回执页有四 mode」这个说法不成立——**四 mode 只存在于填写页**。
8. **`暂停／重启` 的按钮文案**：`goal_status.html` 的 `copy-row` 是空的，两个按钮全靠注入。
   所以「暂停页上有哪些按钮、点了分别复制什么」这一点，我没能完整取证（只能确认页面自身零写死按钮）。
9. **输出路径与文件命名**：源码只说 `scene_path(场景名, 'receipt')`／`'result'`（`--live` 走 `result`），
   以及 `$DATA_DIR/calorie_html/体重目标_<TS>.html`、`目标状态_<TS>.html` 这种形态（写在各渲染器文件头注释里）；
   `scene_path` 实际拼出的文件名我没读到（`scene_path` 在 `render_goal_common.py`，超出读取范围）。
   另外同一份 `goal_weight.html` 的填写页四个 mode 输出类型都写 `receipt`，与 `--live` 的 `result` 如何区分文件名，需另查。
10. **可读性限制**：模板被共享占位符替换的 CSS／JS（`<!--SHARED-CSS-->`、`<!--SHARED-HELPERS-->`）在我看的源码里就是注释，
    所以页面上的图标、字体、动画、错误回执页 `errorReceipt()` 的实际样子，我一概没看到。本文只覆盖标记结构、占位符与数据键。
