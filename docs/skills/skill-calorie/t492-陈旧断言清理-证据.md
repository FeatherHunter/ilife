## 一、根因（两处都是「已落地的有意变更撞上陈旧断言」）

1. **render-copy-90 的 4 例红**：base-render 的 #336（`c10e5fe`）起，
   `renderActionBar` 在「有数据位而无日志位」时自动补一颗**禁用态**复制日志按钮
   （`packages/base-render/src/controls.ts:1389-1396`：文案／id 取 `ACTION_BAR_DEFAULTS.copyLogLabel`／
   `COPY_ACTION_IDS.actionBar.copyLog`，无 `data-t`、带 `disabled`）。而本件四条断言按「产出里只该有这些
   可点的复制按钮」写死了**总数**与**下标**，于是同一段产出里的按钮数由「命中数」变成「命中数 ＋ 每颗数据按钮各带一颗占位」。
2. **cmd-read-t11 的 T8 一例红**：该用例断言标题逐字为 `今日总览 <日期>`，而标题口径自 #401c（`0f1e6f2`）起
   归 `homeViewParts.ts:321` 的窗口词——`windowDays <= 1 ? '今日总览' : '近 N 天总览'`，日期区间改由副题
   （`homeDocs.ts:191-193`：`start + ' 至 ' + end`）承担。`calorie.view.home` 不传窗口参数时默认 7 天
   （`today.ts:48`），故当日标题是**近 7 天总览**。

## 四、逐处改动

`render-copy-90.test.mjs`：

1. `parseButtons` 增读 `disabled` 属性，并补两个小助手 `dataButtons`／`disabledPlaceholders`——
   不读这两个属性就分不出数据按钮与占位（占位与数据按钮的区分点正是「无 `data-t` ＋ 带 `disabled`」）。
2. ① 用例：按钮总数显式写死 4（2 数据 ＋ 2 占位，**不用 `>=` 放过**）；逐颗数据按钮断言 actionId 取
   `HELP_COPY_ACTIONS.prompt`、`data-t` 为字符串、非禁用态；逐颗占位断言 id 取
   `COPY_ACTION_IDS.actionBar.copyLog`、带 `disabled`、无 `data-t`；逐行复制文本逐字等于该行 CLI 的断言保留。
3. ② 用例（`renderHelpLookupHtml`）：一行 → 一颗数据按钮 ＋ 一颗占位，断言同样按两类分别写。
4. ③ 用例（`copyActionHtml`）：逐字 HTML 期望补上数据位带出的那颗禁用占位。
5. ④ 用例（`bindCopyAction` 端到端）：订阅面改为「数据按钮 id ＋ 占位 id（去重后 2 个）」；
   新增一条正断言——激活占位（下标 1）**不产复制、不出反馈**（无 `data-t`）；第二行数据按钮下标改 2。

`cmd-read-t11.test.mjs`：T8 的标题断言按窗口词口径重写，并补两条：旧写法
（`今日总览 <日期>`）**不得出现**、日期区间**须住副题**。
