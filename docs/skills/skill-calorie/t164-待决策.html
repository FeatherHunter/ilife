重建口径：数据层复用，页面与算法照老实物重建

口径
前因后果

你已判定这块是残次品、要照老技能重构。这句落到具体范围上，就是回答「哪些推倒、哪些留」——留错了会把残次算法带进新页面，推多了会把已经能出真数的数据层白扔。

关键信息（实测）
  • 数据层能用：读命令出的是真数，空库都是 exit 4 阻断，不是假数据。
  • 渲染层残：25 条里 24 条出旧式片段，只有 1 条走整页装配；5 个目标写命令全出片段回执。
  • 算法残：12 条「看目标」词塌成一条命令，完成率只判定热量一项（蛋白／碳水／脂肪／饮水从不判定），老技能是五项 actual＋gap＋总评分；推荐算式在档案缺项时静默按 70kg／175cm／30 岁／男性／系数 1.55 硬算。
  • 测试不拦：形状断言＋恒真断言＋只看退出码，所以上面这些一路绿灯。
推荐
数据层复用；页面层与算法口径照老实物重建；新仓已有的公共层（整页装配、复制数据三格式菜单、预检确认页形态）保留不动。
好处口径与老技能逐项对得上、可逐条验收；不用重造已经对的数据层。
代价工作量集中在本图，会动到已接线的命令与测试（按老规矩只许追加、不许乱改），不少字段要回老实物逐个取。

三处口径裁定

工作件
(a) 体重目标那 4 条算不算「必须多步交互」

老技能里它们也是两段式（先出填表页，再写库回执），新仓却判成单命令可执行——两套口径并存，得定一个。

建议照老口径翻成多步交互（与那 3 条多步交互词同批），否则「体重目标」这块的写前确认在本图里名存实亡。
(b) 过程型 HTML 的「过程」由什么承载

老技能靠命令里的 --chain 占位＋常驻交互规则承载步骤，新仓这 25 条一个都没有——「AI 从哪一步执行下去」在今天没有载体。

建议用「工作流程」字段承载（写类：预检确认页 → 复制 prompt → 执行 → 回执；读类：执行 → 结果页），不再靠 chain 占位。它就是 Q2 与 Q5 要的那一层。
(c) 「看目标完成率（按周／按月）」的逐日语义

老技能给逐日柱状字段，新仓只剩汇总，逐日被压扁了。

建议照老实物把逐日补回（算进 Q3 的重建范围）。
