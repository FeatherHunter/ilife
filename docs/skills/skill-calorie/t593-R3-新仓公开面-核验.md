### 1.3 参数够不够表达「一次训练计划」（标题／日期／重复／时段）

**另一条硬口径**：ensure **不要求** 24h 覆盖——24h 校验（首 00:00／尾 24:00／逐条相接）只在 `preview`／`upsert` 这两支跑（`src/policy/plan.ts:46-66`＋`:69-77`，分派 `src/cli/cmd_read.ts:243-251`）。所以「往某天插一条训练时段」用 ensure 是正解，用 upsert 会先把整天软删再整批插入（`src/fetch/db.ts:378-399`）并被迫凑满 24h。

### 1.4 有没有 `ensure`／幂等写法

**有，而且是原生的**：`op` 的第 3 支就是 `ensure`（`src/policy/plan.ts:130`），落库函数 `ensurePlanEvent` 显式按 **`date`＋`time_start`＋`time_end` 三元组**判身份、命中即返既有行不新插（`src/fetch/db.ts:357-366`，件头注释 `:357`：「title 只展示不参与身份」），回执分两支：`已补计划:<id>` ／ `已存在（幂等未重复）:<id>`（`src/cli/cmd_read.ts:255`）。HELP 资产里也有专场景 `ensure_event_idempotent`（`src/help/scenes/help-assets.ts:1021-1050`）。

**幂等的边界（事实）**：三元组任一不同（哪怕 title 一样、时段差 1 分钟）就是**新的一条**；软删过的旧行（`is_active=0`）不参与命中（`src/fetch/db.ts:363-365` 带 `is_active = 1`）。⇒ 调用方要「改时间」得走 `op=update`（`src/cli/cmd_read.ts:257-266`），不能靠重跑 ensure。

### 1.5 「到**日历**」还差一步（飞书）

**事实**：ensure 只写**本地** sqlite 库；推飞书是另一支 `op=sync`（`src/cli/cmd_read.ts:283-311`），它 ① 先过 `larkReady()` 四门（存在→版本→登录→日历可达，任一红即 `throw`，`src/fetch/feishu.ts:93-99`），② 按**整天**列事件（`:286` `listPlanEvents(handle, date, true)`）逐条 create／update。`lark-cli` 缺失时抛 `ScheduleFetchError` → 出口归 `exit 4`（`src/cli/cmd_read.ts:384`）。

**结论（事实＋推断）**：
- 事实：新仓能给的是「本地日程事件」这一层；「一次训练计划落进日历」＝`ensure`（本地，逐天）＋（要真进飞书才加）`sync`（整天，需 lark-cli 就绪）。
- 推断：若「落地到本周末／本月底」按天串行调用，每跑一次 sync 都是整天全量比对，不是一个「批量补计划」的复合口——批量口径（跨天汇总、总完成度）在新仓**没有**现成命令承载。

### 3.3 与仓内唯一互联 CLI 的口径差（两条，都是事实）

仓内现成的互联 CLI 是 `tooling/skilllink.mjs`（用法串 `:205`：`doctor` ／ `read <skill.combo> [--params JSON] [--html 路径]`）。它与 `readSkill` 有两处对不上：

2. **输出对不上**：`readSkill` 要求 stdout JSON 里有布尔 `ok`（`cross-skill.ts:49-51`），而 skilllink `read` 打的是 envelope 五字段 `{version, skill, shape, key, data}`（`tooling/skilllink.mjs:181`＋`packages/base-link-core/src/envelope.ts:104`，字段定义 `:24-28`）——**没有 `ok` 字段**，于是即便 argv 对了，解析这一步仍然落到 `ok:false`（`cross-skill.ts:52-54`）。

【推断】这两条是「老仓（`{ok, skill, domain, data}` 口径）搬过来的框架，没跟着新 envelope 契约改」的残留；今天这个框架**没有任何一条路能跑通**。
