## 二、根因（两条是真缺陷，一条是门的锚停在旧形态）

1. **`gifDoc`／`pickerDoc` 漏接 `pageUi` 位（真缺陷）**。`src/shared/docPage.ts:127`
   只在调用方传 `pageUi: true` 时才注入 `pageUiCss()` ＋ `pageShapeCss()`，而公共层媒体件那套规则
   （`.ilife-block-media-img{width:100%;max-width:100%;…}`、`.ilife-block-media-frame-1-1{aspect-ratio:1/1}`、
   占位框规则）全在里面。实测两页 CSS：`base-media-css=NO`、`frame-1-1=NO`；同族其余页
   （`list`／`detail`／`compare`／`add`）都是 `YES`。⇒ 这两页上的媒体框**没有比例、图按天然像素上屏**；
   候选页超预算走的 `renderMediaPlaceholder`（公共件）也因此没有框体样式。
2. **GIF 舞台只写内联样式、没挂类名（真缺陷）**。`photoUi.ts:155-156` 的
   `.phu-gif-stage{max-width:300px}` 与 `.phu-gif-stage .ilife-block-media-img{image-rendering:pixelated}`
   在 DOM 里无类名可挂 ⇒ **像素质感整条失效**（64×64 方帧放大后糊），宽度上限还在两处各写一遍。
3. **门的锚停在 #484 当时的旧形态**（测试侧）：① 只认内联宽度约束、④ 只认裸 `<div data-gif-stage>` ＋
   图上的内联 `width:min(320px,100%)`、⑤ 只认逐张内联 `max-height:160px`。#526／#527 把约束搬进
   类名规则（家族 `.phu-shot` 一族／公共层媒体件）之后，门与实现失配。
