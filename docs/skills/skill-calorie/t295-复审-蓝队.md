### A4 · `gen:check` 陈旧态识别：**主目标消除，但引入「假红」缺陷（未消除）**

- **真陈旧态（消除假绿）**：仓外临时根先 `pnpm build` 再只改声明不 build → `pnpm gen:check` **exit 1** ＋ 逐字
  `GEN-STALE FAIL：dist/ 不是这些声明的产物，继续跑会把旧声明当成事实（假绿）。先 \`pnpm build\` 再 \`pnpm gen:check\`。`

- **正常顺序（新鲜树上不假红）**：全新 `git clone` → `pnpm install --frozen-lockfile` → `pnpm build` → `pnpm gen:check`
  ＝ `GEN-CHECK PASS：键 101（写 35 ＋ 读 66）`，**exit 0**。返修证据所说的「正常顺序不再假绿」在新树上成立。
- **但判「陈旧」的手段是纯 mtime 比较，方向不对称（新缺陷 N1）**：`staleDeclarations()` 只问「源是否比 dist 新」，
  不问「dist 是不是这些声明的产物」。只要声明源的 mtime 跑到 `dist/` 前面（真内容没问题也照样），就报假陈旧。
  本席在返修树上实测到这条路径**已经发生**：返修树里 `src/weight/commands.ts` 的 mtime 比 `dist/weight/commands.js`
  新 1682195 ms，`node packages/skill-calorie/scripts/gen-cli.mjs --check`（只读）**exit 1 ＋ `GEN-STALE FAIL`**。
- **自锁循环（关键）**：按它自己的医嘱再跑 `pnpm build`，`GEN-STALE` 不消失。仓外临时根里连续两次实测：
  `git checkout -- src/weight/commands.ts` →
  `① pnpm build`（exit 0）→ `gen:check` **exit 1**（`dist/cli/legacyCommands.js 比…旧`／`dist/weight/commands.js 比…旧`）→
  `② 再 pnpm build`（exit 0）→ `gen:check` **exit 1**（同两条）。
  机理：`tsc -b`（root `package.json` 的 `build`）在「emit 出来的 JS 与现有 `dist/` 逐字节相同」时**不重写文件**，
  于是 `tsc` 既不更新 mtime、也不改内容，`dist` 的 mtime 永远停在源后面 → 门恒红，而 `gen` 同样被 `GEN-STALE` 挡死。
- **危害**：不是「门被放水」，是「门把正常的树判成坏的，且没有出口」。已直接命中客观验收线（见 探针 段）。
  修法方向（不改本席职权，只记录）：`tsc -b --force`／比对时用 dist 里的声明内容与源算出的声明做**内容**对账（如比条数／键集合／sha），
  或至少让医嘱可执行（报错串里给出能真正解开的命令）。

## 设计后果一：必填 `example` 对下游意味着什么

- **别的场景搬一条命令时，必须补 `example`——这是硬拦，不是建议。** 两道拦截点：① `CommandSpec`／`LegacyCommandDecl` 的字段必填 → `tsc` 报「缺 `example`」；② `gen-cli.mjs` 的 `merge()` 对 `typeof example !== 'string' || example === ''` 直接抛（信息里带键名与来源）。缺它 `pnpm gen` 与 `pnpm help:build` 都过不去，`SKILL.md` 无法重生成。
- **但不是所有键都需要「新写」**：`REPR` 的 `wakeWord` 在 `LegacyCommandDecl` 里是可选（缺则速查表退回键名）；`example` 则**必填且非空**，没有退回路径。这是返修新加的语义（返修前 `build-help.mjs` 的 `default: throw` 才是那个拦点，现在它退化成查表）。
- **更细的坑**：#296 若只写「加命令＝加一条声明」，下游会以为 `example` 随便填。**该字段的实质要求是「照抄即能跑」**（`pnpm help:examples:check` 会 spawn 真 CLI 断言 exit 0），不是「有个串就行」；且示例与 `--params` 形状绑在一起（无 `--params` 的写法会 exit 2／4）。
- **这条要求写进哪里了？** 代码里有（`commandSpec.ts` 注释 ＋ `gen-cli.mjs` 报错串），`legacyCommands.ts`／`build-help.mjs` 的注释也提；**票面／返修证据／（将来的）纪律文本里没有「新增必填 `example`」这句规矩**——票面只在 A3 条目里描述「101 条示例搬进声明」，属于**动作记录而非纪律**。**下游会踩，点名。#296 若不写，第 3 个场景搬第一条命令时就会撞。**
- 附一条同源风险：`gen-cli.mjs` 目前只做**结构**校验（是不是非空字符串），**不做可执行性校验**——填一个「非空但跑不通」的 `example` 能过 `gen`／`gen:check`，只在 `help:examples:check`（CI 里今天的恒红那道）才会现形。**#296 应写明「示例必须本地先跑通，别指望生成期拦」。**

## 设计后果二：#296「照抄说明」必须写进的事实（本席独立清单）
