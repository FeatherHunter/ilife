## 三 · 票内定的口径

### 1. 两条命令的形态（写键 `receipt` 形，`dryRun` 分流）

- `calorie.workout.xunji-push`（同步到训记）：审计（`verifyMovements` 经能力门，只读）→ `push-plan` 子进程 → 过程页（`dryRun`，真子进程 `--dry-run` 转换，远端未调用）／结果页（实跑）；
- `calorie.workout.xunji-backfill`（拉训记实绩）：`backfill` 子进程 → 过程页（`dryRun`，不进子进程，区间与口径预演）／结果页（实跑，逐天结局）；
- 同步处理函数是同步的，异步链隔离进子进程（`spawnSync` 一次性；存在性预检＋300 秒限时＋起不来即 exit 4）；
- 审计只提示不拦推（沿 #607 §八·7「推送前不校验动作库」：动作名原样上报；不通过的给建议名，页上可见，退出码不拦）；
- 路由 `cli` 与声明 `example` 取 `dryRun` 预演形态（种子库无 KEY 无网，实跑 exit 0；真推进行为由缺省分支承载，见 §六真出口）——有意偏离，理由见 §八·2。

### 2. 退出码翻译表（`xunjiExitToCmd`，#607 §四注记的 #614 翻译位）

| xunji 码 | 事件 | 本面码 | 备注 |
|---|---|---|---|
| 1 | 用法／取数读不出（坏日期／无计划／库不在） | 4 | 用法错调用方已在 spawn 前拦成 2；子进程的 1 是取数档 |
| 2 | 本地没配 KEY（没调网） | 3 | key 档 |
| 3 | 远端接口错（服务端拒绝／限频耗尽／超时网络／写库失败） | 4 | 取数档：外部依赖失败 |
| 3（`push-plan` 专例） | 无 KEY 走 `fail_count` 路径退 3，但逐段 `attempts: 0` 证明没调网 | 3 | 数据分流（`localNoKey`），不只看码 |
| 其余 | `verify` 专位 4 等（两链到不了） | 4 | 外部失败兜底 |

### 3. 三旧坑逐条落实（`t350` §三）

1. **退出码恒 0 → 任一步失败即非 0＋失败不落成功页**：参数错 2／无计划 4／本地缺 KEY 3／远端失败 4；`fail` 直接退，成功页只在子进程 code 0 时组装（`t614` ③a–③f 钉死）；
2. **外部调用无保护 → 预检＋限时＋失败进码**：CLI 入口不存在先拦（exit 4）＋ `spawnSync timeout` 300 秒（exit 4）＋ 起不来即 exit 4 ＋ 子进程 stderr 尾行进点名；
3. **回执渲染器不调外部 → 调用收进同一命令**：页上读数一律来自本次调用的 stdout JSON（最小形状守卫，坏即 exit 4）；本地／远端两行分开写（dryRun：本地成／远端未调用；实跑：两边计数；挡板：标数据来源）。
