# t494 · 预检确认页多出一颗「复制日志」（#336 兜底在 prompt 那一排误触发）

来源：票 [#494](https://github.com/FeatherHunter/ilife/issues/494)（map #637）。本件是交付证据，落点照 `docs/agents/doc-homes.md`。

## 一 · 现象与根因（实施前逐条复核）

- 探针：`calorie-cmd-read calorie.view.profile-wizard --params '{}' --html <新路径>`（经 `run-locked --ticket 494`）⇒ exit 0、产物 72757 字节。
- 产物解剖：`data-action-id` **三处**——`ilife-help-copy-prompt` ×1、`ilife-copy-log` ×2（其中一颗 `disabled` 且无 `data-t`），与票面 `PROBE-WIZARD` 读数逐字一致。
- 根因链：`src/profile/setup.ts` 原写 `copyArea({ prompt, data, log })` → prompt 走共用件 `promptCopyArea` → 它把 prompt 挂在 `renderActionBar` 的**数据位**上（`src/render/copy.ts:38-40`）→ 公共层 `packages/base-render/src/controls.ts:1389-1396` 的 #336 兜底（「数据位在场、日志位缺席」）**补一颗禁用态「复制日志」**；页底 `renderCopyBlock` 那条 bar（数据位 ＋ 日志位都在场）再出一颗真日志 ⇒ 同名两颗。

## 二 · 改法（一处，最小写集）

`packages/skill-calorie/src/profile/setup.ts`：新增本文件内的 `copyZone(v, envelope)`——指令块（`renderPreBlock`）＋ 指令按钮**挂日志位**（`renderActionBar({ copyLog: … })`，不触发兜底），再拼 `copyArea({ data, log })`（两者都在场，兜底同样不触发）。
actionId／文案仍取冻结表 `CALORIE_COPY_ACTION`（概念唯一出处，不另造名字），按下的仍是 prompt 原文；同款做法在目标预检页 `src/goal/precheck.ts` 的 `copyZone()`（那页的注释记了同一处兜底）。

页内三个按钮仍是「复制指令／复制数据（三格式菜单）／复制日志」，`data-action-id` 回到**两颗**。
