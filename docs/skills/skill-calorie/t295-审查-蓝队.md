## 一、五问逐条（每条给命令与输出）

### Q1 门能不能被绕过 —— 门是真的，但只有 CI 那一处兜得住
- **CI 路径**：`.github/workflows/ci.yml:34` `pnpm gen:check`，在 `pnpm build` 之后。**真 CI 实证**（`gh run view 34744069174`）：`✓ Run pnpm gen:check` 在 ubuntu／macos／windows 三平台全绿 → 这道门不是装饰。
- **本地路径**：`pnpm test` 的 glob 里**没有** gen:check。手改生成物后本地跑 `pnpm test`：改键集合／形状／标题会被对账断言（`cmd-registry-294` 对账、`test/combos-42`「形状/标题/出口逐键对齐」）拦下；**改 `build-help.mjs` 的 REPR 段改成另一个词、再重注入 SKILL.md，本地全绿**（`skill-t11` 的 `buildHelpBlock()` 与它同源，自己比自己）——只有 `gen:check` 能拦。结论：本地兜得住一半，CI 兜得住全部；「本地一定有人跑 gen:check」没有任何机制保证。
- **手改后跑生成器**：**静默覆盖**，不报错（`gen-cli.mjs:260` `writeFileSync`；标记块走 `replaceBlock` 整段替换）。这是生成物的正常语义，但意味着「手改 + 忘了重生成」不会被生成器本身发现。
- **绕过路径清单**：①改生成器模板（`renderKeysTs`／`renderReprBlock` 等）再 `pnpm gen`——`gen:check` 与 9 处对账全绿，只有人眼能发现；②`gen:check` 读 `dist/`，**先改声明不 build** 时两处门（gen:check ＋ `test/declared.mjs`）都拿旧 dist 判绿，本地全绿、CI 才红；③本地不跑 `gen:check` 就 push（依赖 CI，而 CI 现在整体是红的，见下）。

### Q2 跨平台确定性 —— 逐字节可比，这条**成立**（S1 不成立）
- 生成器输出只有 `\n`（`L.join('\n')`），`writeFileSync` 不翻译行尾，仓内 `.gitattributes` 只对 `help-template.html` 声明 CRLF，`core.autocrlf=false` → 三平台检出均为 LF。
- `gen:check` 比文本前**两侧都把 CRLF 归一成 LF**（`gen-cli.mjs:268-269`），即使某平台检出 CRLF 也不会误红。
- 排序是显式的：能力名 `readdirSync(...).sort()`，键序 `rank(kind) || 码点比较`（`gen-cli.mjs:88-90`）——不依赖文件系统顺序，不用 `localeCompare`，中文标题只作字符串值不参与排序。
- 产物里没有平台相关路径：`relative()` 只出现在控制台输出，不在文件内容里；`registry.ts` 的 import 路径是硬编码 `/`。

- **真实 CI 是最强证据**：三平台 `gen:check` 全绿。**无平台相关差异。**

### Q5 对下一个人的可用性（场景 04 运动的制定者，只读纪律文本 ＋ `src/weight/` ＋ 票面证据 ＋ #297）
