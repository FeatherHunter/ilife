## D7 · 送审决策：`triggers/routing.ts` 汇总段「暂缓」是否成立、是否最优

**结论：技术判断「成立」，账目处置「不成立」，且不是最优解。**

**第一性原理**：`src/triggers/routing.ts` 里混着**两类东西**，票面用「汇总段」一词把它们盖在一起了。
① `WAKE_ROUTES`（436 条）是**冻结 SoT 的 parity 证据**——它与 `scene-*.ts` 的 436 条唤醒词**按位对齐**（`TRIGGERS[i]` ↔ `WAKE_ROUTES[i]`），

（键 ＋ 代表唤醒词 ＋ 唯一出口命令）。第 ① 类**天生不可**从「各能力 commands.ts」派生：它是逐唤醒词的，不是逐命令的。
要让它派生，前提是各能力自己拥有路由声明（`src/<能力>/routes.ts`）——今天 0 个能力有；而**搬一个场景的一段**会立刻撞上
①的按位对齐：体重相关的路由**不是连续一段**，它散在 436 条冻结行（孪生词）与 58 条新拟词里，抽走就得在冻结表里留占位，
parity 断言（`TRIGGERS` 与 `WAKE_ROUTES` 逐位相等）与 `docs/research/t81-exec-smoke.md` 逐条快照都要动。
**这条风险是真的、且撞的是本图的证据地基**；把「路由声明住哪里、按什么顺序搬、广播什么口径」留给
`#297`（needs-human 决定票）在**形状未定**时决定，是更省的顺序。**故暂缓成立，返工重做这一段的收益为负。**
