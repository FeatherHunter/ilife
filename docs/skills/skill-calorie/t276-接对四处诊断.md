## 二 · 第 1 处：`查高热量排行` 丢 `category`（本票已接对）

**住哪**：`packages/skill-calorie/src/diet/routes.ts` 的 `list:'new', order:10` 那一行。

（`packages/skill-calorie/src/diet/ranking.ts:24`）——`if (category) { 单榜 } … 全榜`。

## 四 · 第 3 处：`看本周饮食` 路由层只有 1 天（现象属实，成因＝窗口口径差异）

**住哪**：`packages/skill-calorie/src/home/routes.ts` 第 20 行 —— `cli: '…calorie.view.diet --params \'{"window":"本周"}\''`。

**路由本身没接错**：窗口词由 `resolveWindow` 解析，`本周` 走**自然周期**这一支：

```

即新仓口径为 `[本周一, 今天]`，跨度＝**本周一至今**。

**老实物正本（只读引用，未执行其中任何脚本）**：同一句词在老技能里是**整周**，恒 7 天——

```
D:\2Study\StudyNotes\SKILLS\卡路里\scripts\render_today_meals.py:35-41   def _natural_week(week):
    start = today - timedelta(days=today.weekday())      ← 本周一

…:5   文件头对应唤醒词：「看本周饮食 / 看上周饮食 / 看本月饮食 / 看上月饮食 / …」

**「只有 1 天」是怎么来的**：新仓跨度＝周一至**今天**，所以**周一实跑恰 1 天**、周二 2 天……
走到周日才 7 天。实测读数会随跑的那一天变，票面「应为 7 天」正对老实物口径。

**因此这一条不是「接错线」而是「窗口口径差异」**，处置归 `#250`（时间说法正本在 `analysis/series.ts`）：

- **改哪**：`analysis/series.ts:83` 那一支（`本周` 回整周）——它不在本票声明路径内，且是全仓共用的时间口径；
- **牵动面**：同一支解析还养着 `上周`／`本月`／`上月`／`今年`，以及一串用 `window:"本周"` 的记录
  （`看本周主页`／`看本周运动`／`看本周目标`／`本周复盘`…）；只改饮食那一条会让饮食与运动两面对同一条词给不同的窗。
- **本票处置**：本票**不改**（路径不在声明面内，且属口径变更不是登记点改动）；请编排者裁定后转 `#250`，
  并把票面这一条的现象改写为「新仓 `本周`＝周一至今，与老实物整周不一致」。

**已排除的一支**：不是「路由参数丢了」——`{"window":"本周"}` 这一串在位且解析得出来；
也不是「处理函数不认窗口」——`viewDietOverview` 第 47 行走的就是 `defaultRange(db, params)`。
