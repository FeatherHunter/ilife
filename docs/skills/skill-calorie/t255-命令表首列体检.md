# 命令表首列体检：哪些场景找不到它的底层唤醒词

- 出处：用户 2026-09-13 三条核心思想的第 ③ 条——「**HELP HTML 里目标管理每个场景都能找到它的底层唤醒词，且 AI 知道该从该唤醒词的哪个工作流程执行下去**」。
- 本文件只报**机械可复算的事实**，不改任何东西。脚本：`.scratch/wf-goal/scan-skillmd.mjs`（只读 `packages/skill-calorie/SKILL.md` 与 `src/triggers/routing.ts`）。
- 复算：`node .scratch/wf-goal/scan-skillmd.mjs`
- 判定对象：`SKILL.md` 的命令表（`| 首列 | 命令 | 形状 | 可执行示例 |`）。**首列本该是唤醒词**——AI 就是从这一列知道「哪个场景该跑哪条命令」的。

## 〇、根因（一条就够）

命令表的首列由 `packages/skill-calorie/scripts/build-help.mjs:214` 生成：

```js
const wake = REPR[k] || k;
```

`REPR` 是**手工维护**的一张 `命令 → 代表唤醒词` 表。**表里没有这条命令时，静默退回命令名本身**——不报错、不警告，于是页面上就出现一行「`calorie.view.goal-expiring`」，而它本该是「看即将到期的目标」。

这就是「找不到底层唤醒词」的全部成因：不是缺数据，是**一处静默回退**。

## 四、由此得到的三条判据（给 #255 用）

1. **首列 !== 命令名**：命令表每一行的首列都必须是唤醒词。这一条现在有 15 处不成立。
2. **一个唤醒词只领一行**：首列不得重复。这一条现在有 6 组不成立。
3. **写词的唤醒词只许指向写命令**：`定营养目标`／`定体重目标` 这类写词不得被指到 `calorie.view.*`。

**修法不是逐行手改**（手改下次还会漂）：`REPR` 是手工表，缺项静默回退——要么把它的缺项改成**构建期报错**（照同文件 `exampleFor` 的 `default: throw` 那种做法），要么让首列改为**从路由层反查**（路由层已经有「唤醒词 → 命令」的映射，是权威源）。

## 五、本文件没有回答的

- **「AI 知道该从哪个工作流程执行下去」**这一半不在本文件：它要的是命令表旁边能看出「这条词是单条命令，还是先出预检确认页再写入」。命令表今天只有一列「可执行示例」，没有工作流程列。这条归 #255 的正文设计与 `/writing-for-agents` 的口径。
