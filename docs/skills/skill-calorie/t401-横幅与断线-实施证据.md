## 五、这行结论用了哪个位置，为什么

位置＝页首、副题行之下、数字卡之上的同档小字位。理由照 `homeDocs.ts:116-118` 的原话（逐字）：

```
    /* #401 · 结论小字排在最前（读序＝标题 → 一句结论 → 数字卡）。类名与共享页面模板里副题行那行
       同源（`blocks.ts:173` 的 `blockPart('pageShell','subtitle')`）：字号与颜色都随公共层，页面本地不写。
       副题位（`assembleDocPage` 的 `subtitle`）已被窗口那行占用，故取页身内最近的同一档小字位。 */
```

即：字号与颜色走公共层（页面本地一个字号、一处色值都不写）；副题行本身已被「窗口起止 ＋ 连续天数 ＋
有记录天数」占用，故取页身里紧挨着它的同档小字位，读序与设计稿样张甲第 2 项（结论紧跟标题）一致。

## 六、如实记账三处

1. **「深底提示条」的实物不是 `.ilife-toast`。** 设计稿第三节冲突 4 记的那条常驻提示条的样式是
   `.ilife-toast` 深底 `rgba(28,28,30,.94)`；但改前页里 `notice()` 实际出的是共享反馈区块的
   note 块 —— `<section class="ilife-block ilife-block-feedback-block">` ＋
   `<div class="ilife-block-feedback-block-note">`，样式是**浅底**（`background: var(--soft)`、
   `border: 1px solid var(--line)`、`color: var(--fg2)`）。所以本件退场的是「表格之下那条常驻结论块」，
   页面上从来就没有过 `.ilife-toast` 浮动块（CSS 段里有它的规则，标记区一次都没出）。
   分辨改前／改后的读数是 note 块 1 → 0 与结论小字 1 → 2，不是 toast 实例数（两页都是 0）。
2. **改前那条提示条把「目标」与「缺口」并排了。** 改前提示条的第二行逐字是
   `摄入 1189 卡 · 目标 1800 卡 · 缺口 1687 卡` —— 正是设计稿第三节冲突 5 要挡掉的那处并排
   （1800 与 1687 两个数基准不同，并排会被先做减法）；改后那行结论小字写成「还能吃 611 卡」并带上算式，
   611 与设计稿点名的「还能吃多少」同值。
3. **行数与票面不等。** 见第一节末句（改前 174、改后 205、未超 350）。
