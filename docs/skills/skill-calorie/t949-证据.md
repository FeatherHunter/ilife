### 1.1 判据①③那个串为什么不走「调 assertISO 就够」（本票最要紧的现场读数）

`assertISO` 的判据是 `/^\d{4}-\d{2}-\d{2}$/`——**只查形状，不查数值**，`2026-13-45` 它照放行。改前实测（探针 `.scratch/t949/probe.log`）：

```

STDOUT={…"shape":"receipt"…"message":"已改训练计划（开始日期：2026-13-45）"…}
DB_START={"start_date":"2026-13-45","updated_at":"2026-09-23 15:08:27"}
```

⇒ 只调 `assertISO`，票面判据①（`2026-13-45` ⇒ exit 2）**仍是红的**，而票面写的那条害处（坏锚点 ⇒ `weekOfDate` 得 NaN ⇒ 按日期过滤恒空 ⇒ 冒充「计划没有内容」）一模一样地留着。故按**判据**实施：加一层同族既有的严格写法 `Number.isNaN(Date.parse(v + 'T12:00:00Z'))`（与 `src/render/planPlate.ts:17` 的 `assertDate` 一族逐字同形）——挡 `2026-13-45`（月 13 ⇒ NaN），**放行 `2026-02-30`**（V8 滚到 3-2）⇒ 票面「遗留出口」那一档原样留着，不算扩范围。

**裁定出处**（编排者 2026-09-23 具名裁定 **A 支**，逐字）：「裁定 **A 支**，照你已经落的那样做，**不换样例**……B 支把判据样例换成形状坏的串＝**拿实现去凑判据**，正是协议 §2.4 第 4 条禁止的『自己加个放宽』。判据只能向上对齐，不能向下对齐。」
