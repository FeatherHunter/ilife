## 二 · 缺陷二（场景 10 台词错位）：**改接法**（票面二选一里的第 ① 条）

- 接法由 `calorie.view.goal-progress`（目标进度页：体重／热量统计）改为 **`calorie.view.anomaly --params '{"kind":"strategy_check","window":"30d"}'`**。
- 理由（判据不是感觉）：这条词声明的 `data_fields` 是 `findings`／`confidence`／`degraded`／`insight`，prompt 三问是
  「缺口是否合理 ＋ 蛋白是否足够 ＋ 运动是否有贡献」；`analysis/anomaly/overall.ts:86-104` 的 `diagStrategyCheck()` 正是这三答
  （`缺口策略合理/缺口过大/缺口不足` ＋ `蛋白达标/蛋白不足` ＋ `运动有贡献/纯靠饮食`），且早在 `DIAGNOSE_KINDS` 里、
  `diagnose()` 的 switch 里也有它那一支——**要的页面一直都在，只是没接**。改页面（给目标进度页补诊断三答）＝新造一块，
  与「收敛优先、不扩大开发量」相悖，故取改接法。
- 改动面三处 ＋ 生成物：
  1. `src/analysis/routes.ts` 新增 `order 372` 记录（原位置正好缺 372，夹在 371 与 374 之间）；`src/home/routes.ts` 删掉那条（路由记录归它 `key` 的拥有者，本件头注释的口径）。
  2. `src/triggers/scene-10-analysis.ts:117` 的 `main_prompt.cli` 与 `data_source` 同改（HELP 与真出口锁的权威源）。
  3. `src/triggers/routes.generated.ts`：`pnpm gen` 重出（`gen:check` 逐件绿）。
- 读数：路由探查 `我的减肥策略对吗 = calorie.view.anomaly :: calorie-cmd-read calorie.view.anomaly --params '{"kind":"strategy_check","window":"30d"}'`；
