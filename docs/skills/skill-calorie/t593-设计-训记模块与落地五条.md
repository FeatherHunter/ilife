### 2.3 三条硬口径

1. **行为以老代码为准，不以老文档为准**——已实测两处文档与代码不符：回写幂等键**是三列**（`xunji_localid＋exercise_type＋set_index`，文档写两列）；退出码自述（0／1／2／3／4）与实况不符（401／403 实退 3）。
2. **四个老缺陷不照抄**（行号见 #594 决议）：退出码恒 0／外部调用无保护／回执渲染器不调外部／静默吞错。外加两条：#595 的 `run-sync` 子进程退出码不进总退出码、`overlay` 丢同 title 的 localid；#594 的批量天数只进 Step 3。
3. **密钥不进仓**：只读环境变量 `XUNJI_TRAINS_KEY`（兼容 `XUNJI_API_KEY`）；`status` 只回「前 4 字＋末 2 字」预览；测试夹具与证据件一律 `REDACTED`。

## 3 落地五条（宿主侧）

### 3.1 链（老实现四步 → 新仓四步）

```
说唤醒词「落地训练」
  → 出过程型页（可复制 prompt）
  → AI 执行宿主命令：
       ① 计划已在库（calorie 读）
       ② 逐天写进日历（作息 plan.write op=ensure；要进飞书再加 op=sync）   ← #599
       ③ 记心愿（备忘录 memo.create）                                      ← #600
       ④ 推训记（xunji push-plan）→ ⑤ 拉实绩回写（xunji backfill）         ← #607／#608
  → 结果型 HTML 落盘 ＋ 回执给绝对路径
```

### 3.2 天数怎么算（R1 的硬读数）

老实现的 N **不在脚本里**（由调用方拼），且批量天数只进 Step 3、Step 4 仍只回写 1 天。新仓口径：**宿主命令自己算天数**（今天→本周日／今天→本月末），**逐天循环**，且 Step 4／5 用**同一份天数**。

### 3.3 五条路由转 `exec` 的随动

`routes.ts:32-36` 五条从 `non-exec` 转 `exec` 后：`SKILL.md` 与场景清单的文案随动、验收墙（`scene05-验收墙/`）要给这五条出格、`gen:check` 要绿。**这些随动写进对应票的交付物**，不在别的票里顺手做。

## 5 判据口径（每张票长什么样）

- 一律**挡板**（不打真实训记接口、不推真实飞书）；真机联调另开票，且**要用户在场**（KEY／扫码）。
- 每张改码票给「**改坏必红／还原必绿**」两行机器读数。
- 页面票照仓规：机检判据 ＋ 双端墙格 ＋ 肉眼终审（人填逐格清单）。
