### A4 · `gen:check` 新鲜度守卫（消灭假绿）——**第一轮：mtime 判据（已被两席复现出假红＋自锁）；第二轮：内容判据，见 ⑩**

第一轮的做法是「读声明前先查『生成器的两个输入比编译后的 `dist/` 新没有』」，陈旧即 `GEN-STALE FAIL` 并退出 1，
`gen`／`gen:check` 两条路都拦。**主目标当时成立**（`M2`：只改声明不 build 直接 `pnpm gen:check` → exit 1 ＋ 逐字
`GEN-STALE FAIL：dist/ 不是这些声明的产物…`，改前这一步是 exit 0 的假绿）。**但那条判据的方向不对称，两席各自实测出两件事**：

1. **假红**：源文件 mtime 只要跑到 `dist/` 前面（`git checkout -- .`／`git restore`／`git stash pop` 这类正常动作就会），
   内容一字没改也报陈旧；
2. **自锁（无出口）**：`tsc -b` 在 emit 与现有 `dist/` **逐字节相同**时**不重写文件**（它按内容判断项目是否 up-to-date），
   于是 `pnpm build` 既不改 `dist` 的内容也不改它的 mtime ⇒ 门恒红、医嘱无效、`pnpm gen` 一并被挡死；
   连带的硬后果是本票唯一的客观验收线（`t293-验收-命令自治.mjs` 的 P1／P3）读数成了 mtime 的函数。

第二轮把判据换成**内容印记**（`dist/.gen-inputs.json`：两个声明源逐文件 sha256，由 `pnpm build` 的 `--stamp` 写），
**mtime 判据一条不留**；三场景 exit 码与机理见 ⑩。仍不查生成物自己（`src/cli/keys.ts` 刚被 `pnpm gen` 写完），避免误报。

## ⑩ 第二轮返修：N1 判据换成内容（两席独立复现的阻塞缺陷）＋ 过程缺陷自述

### N1 · 缺陷与修法

两席各自独立复现同一条：第一轮的 `gen:check` 新鲜度守卫是**纯 mtime** 比较，方向不对称——

- **假红**：声明源的 mtime 被 `git checkout -- .`／`git restore`／`git stash pop` 这类正常动作刷新（内容一字未改）即报 `GEN-STALE FAIL`；
- **自锁**：`tsc -b` 在 emit 与现存 `dist/` **逐字节相同**时**不重写文件**（它按内容判定项目 up-to-date），
  于是 `pnpm build` 既不改 dist 的内容、也不改它的 mtime ⇒ 门恒红、**医嘱无效**，`pnpm gen` 一并被挡死。
  本席复现（该次未持锁，已按编排者要求持锁重跑）：`touch` 声明文件 → `gen:check` exit 1；`npx tsc -b` exit 0 →
  `dist/weight/commands.js` 的 mtime **原地不动**（`08:05:45Z`）→ `gen:check` **仍 exit 1**。

**改法**：判据换成**内容印记**，mtime 判据一条不留。

- 印记文件 `packages/skill-calorie/dist/.gen-inputs.json`：`{version:1, files:{'cli/legacyCommands.ts': <sha256>, 'weight/commands.ts': <sha256>}}`；
- 写入者＝**根 `pnpm build`**：`"build": "tsc -b && node packages/skill-calorie/scripts/gen-cli.mjs --stamp"`
  （只有「刚构建完」这一刻才有资格宣称 dist 是这些声明的内容产物，所以不挂在 `gen` 上）；
- 读法＝`gen`／`gen:check` 开跑前比对「印记里的 sha256」与「声明源**现在**的 sha256」：
  不符 ⇒ `GEN-STALE FAIL`（**不假绿**）；相符 ⇒ 放行（**不看时间戳，也就不假红、不自锁**）；
- 印记里没有这一条（新文件／仓外沙箱里手造的假能力）⇒ 无对照，放行；
- 印记整个缺失（没 `pnpm build` 过、或 dist 是从别处拷来的）⇒ 打一行 `GEN-STAMP WARN` 后**不判陈旧**（见下「诚实边界」）。

**为什么不用「`gen:check` 内部先跑一次 `tsc -b`」**：那会**打坏本票唯一的客观验收线**。
独立验收探针 `t293-验收-命令自治.mjs` 的沙箱只复制 `src`／`scripts`／`dist`／`combos.yaml`（**没有根 `tsconfig.json`**，
也没有 `base-link-core` 等被引用工程），且它的动态实验**手工伪造** `dist/fakecap/commands.js`（不编译、不建树），
同时要求沙箱里 `gen --check` 基线（`base.status === 0`）与 `gen`（`g.status === 0`）都绿。
在 `gen`／`gen:check` 里跑 `tsc -b` ⇒ 沙箱里必然「读不到 tsconfig」⇒ P1／P3 双双 PENDING，正好复现我们要消掉的不稳定。
故取备选解（内容印记），并由下节证明它满足三条性质：**不假绿、不假红、不自锁**。
