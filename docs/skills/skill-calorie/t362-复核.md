## 八、待裁决点：「备注」列缺值该不该写 `—`

**事实核对（打开老正本那一行）**：`D:\2Study\StudyNotes\SKILLS\卡路里\templates\body_composition_view.html:366`

```html
html += `<tr><td>${esc(r.date)}</td><td>${esc(r.body_fat_pct)}%</td><td>${esc(SRC_LABELS[r.source] || r.source)}</td>${d}<td>${esc(r.note)}</td></tr>`;
```

同文件 `:211`：`function esc(s) { return String(s == null ? '—' : s); }`
⇒ **老正本的「备注」列并不是「留空串不写 `—`」**，而是**照 `esc` 通例**：`note` 为 `null`／`undefined` 时老页**会写 `—`**；

**作者说法与实况的差**：作者在 `bodyDocs.ts:121` 的注释写「备注列照老正本 `body_composition_view.html:366` 留空串不写 `—`」。

写库统一 `input.note ?? ''`（`fetch/body.ts:252`），所以 `note` 从入口进来恒是空串而非 `NULL`，两版页面对空串都渲染空格。

**本席实测（自己造 `note = NULL` 的记录，走真出口）**：可见表「备注」格＝**空串**（`visibleCellDash=false`／`visibleCellEmpty=true`），

**结论**：这是**本票范围内的口径分歧**，不是硬故障——① 正常写入路径不产生 `NULL`（运行不可达）；② 但一旦出现（迁移／直接 SQL 导入的老库），
