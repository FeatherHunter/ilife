## 五 · 做不到／没做的三处（具名）

1. **`状态` 列没能变成「单元格里的徽章」**：`renderDataTable` 的单元格只收基元（`blocks.ts` 的 `cellText`），把徽章塞进 `<td>` 要改**公共层产出器**——本票（裁定 3）对 `packages/base-render/**` 只读。落地形态＝表内保留纯文本三态 ＋ 表下徽章列（三态天数）＋ KPI 卡状态徽章。**要真做进单元格，需另开一张公共层票**（`renderDataTable` 增 `cellHtml` 类能力），本票不代做。
2. **`caption` 三件事串一行（票面 ⑦）未形状化**：caption 的「共 N 天，其中 X 天是工作日，Y 天是周末」是 `analysis-deficit-385.test.mjs` 的逐字断言（授权 2 允许「逐字保留或改写成等价断言」）。本票**逐字保留**——理由：该串不含任何判据字符（`，` 不是并列分隔符），改它只换来一次断言改写风险，收益为零；工作日／周末两条事实仍被断言覆盖（`:211`）。
3. **宽屏「只让表与图吃掉余量」（票面 C 的第三条路）未落**：数据表 `max-width:680px` 的封顶住在公共层 `blocks.ts`（#512 的设计选择），页面侧改不动它 ⇒ 本票选 **(a) 加宽内容列**（见 §七）；若终审要 (c)，落点是公共层一条宽屏规则，**须另开票**。

## 七 · 裁定 C：宽屏余量（1440 档）

**事实（改前）**：内容列固定 `max-width:960px`（公共层 `blocks.ts` 的 `.ilife-block-page-shell`），1440 档两侧各空 240px；数据表另有 `max-width:680px` 居中封顶（`#512` 的设计）。
