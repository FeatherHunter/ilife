### 2.3 归因（本票引入，非「既有红」）

| 时刻 | 事实 |

### 2.4 为什么必须改回

1. #349 的验收判据逐字写着「撤销后读验证应为 exit 4 缺失阻断」——冻结判据不许靠改测试迁就实现。

3. 实质害处：读命令再无法区分「没有计划」与「有计划」，调用方的 fallback 全部失效。
4. 动机存疑：该空态页是**为了让 195 有一条好看的证据产物而把读命令的契约改软**——产物驱动的设计让步，不成立。

**处理**：恢复缺失阻断；`render/planDeleteVerifyDocs.ts` 随之成为无调用方的死件，按结构纪律删掉（或找它该在的正确调用点），不许留死代码。「已撤销」这一状态不会丢——撤销的回执页本就出「写后现值」表（`workout/receipt.ts` 的 `currentPlanTable`），写明「计划已撤销（配置＋会话均为空）」。

## 四、过程型页面缺可复制的 prompt（本次勘查发现的第二处真缺口）

### 4.1 现象
10 份过程型产物（`order186-process` ＋ `order187–195-process`）底部只有「复制数据／复制日志」两颗按钮，**没有可复制的 prompt**。

### 4.2 依据（两条，都在本仓内）
1. `packages/skill-calorie/SKILL.md`「Wizard Verify 铁则」节逐字写着：「页面＝静态 HTML ＋ `copyText`，**出页后由用户复制 prompt 回给 AI**，再按场景调写键。」
2. `shared/copyArea.ts` 的 `promptCopyArea()` 标签逐字是「**复制 prompt（必走）**」，且本仓**其余全部**预检确认页都摆了它：
   - `goal/precheck.ts:192-193`（目标预检页）
   - `profile/setup.ts:328-329`（档案预检页）
   - `body/wizardDocs.ts:87,152`（围度／体脂预检页）
   - `render/wizardPortDocs.ts:58,125`（身材照／GIF 预检页）

只有场景 05 的 `render/workoutPlanDocs.ts` `dualCopy()` 没传 `prompt`。后果：用户看完写前预览／构建向导，页面上没有任何指令可复制，「复制 prompt → AI 用命令执行」这一环断掉——正对着地图 Destination 的原话。

### 4.3 prompt 原文的出处（已查证）
`packages/skill-calorie/src/triggers/scene-05-workout.ts` 里 32 条词条条带 `prompt_template` 字段，逐字即用户该复制的那段。例（复制训练计划）：

> 请你加载技能 卡路里,执行唤醒词「复制训练计划」。
>
> 我想把现有训练计划复制一份作为模板(可以复制整个计划或某一周)。请告诉我复制了哪些内容、新计划/新周的标题或周次。交付 HTML 时,文字只回复精简而全面概括的信息,文字不允许超过三句话。
>
> 要复制的周次(选填,空=整个计划):____
> 新标题(选填):____

### 4.4 接法（照本仓先例，别越层）
先例 `goal/read.ts:116`：**读层**取 `prompt_template` 放进视图对象（`readonly prompt: string`，见 `goal/precheck.ts:48-49`），**页面装配层**再交给 `copyArea({ prompt })`。
故：视图类型加 `prompt: string`；取 prompt_template 的活放命令／取数层（`workout/plan.ts` 或 `workout/write.ts` 的 `previewWrite`），**不让 `render/` 去 import `triggers/`**（层级倒置）；`dualCopy` 加 `prompt` 入参走 `promptCopyArea(text, null)`（该函数天然不带三格式菜单，与已收口的冻结双按钮并存不冲突）。
结果页（176–185、201–207）与回执页**不加** prompt——它们不是预检确认页。
