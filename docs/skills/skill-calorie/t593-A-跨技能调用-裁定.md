## 一 · 契约形状

| # | 事项 | 裁定 |
|---|---|---|
| A1 | 契约单位 | **ensure 型合成写**：被调方一条命令把一条业务事实对齐到「本地库 ＋ 它的外部平台」两侧；两侧各按自然键判重；远端 id 回写本地；回执分字段报两侧状态 |
| A2 | 判重归谁 | 两侧各自判重，**责任全在被调方**；调用方**永不碰**对方的库与第三方平台 |
| A3 | 部分失败 | **回执分字段 ＋ 退出码非 0**（两者都要） |
| A4 | 远端落位 | ① 远端 id 存回本地；② 远端对象上带**可反查的归属锚** |
| A5 | 范围 | 只定契约形状、不管具体命令 |
| A6 | 三处冲突 | ① 远端不可用 → **降级照老**（不拦住本地写）；② 最终没达成 → **报告照新**（非 0）；③ 写 op **全部统一成合成写**，口径写明「覆盖 vs 跳过」由哪个参数表达 |

### 判据出处（一手实测）

- 老 `ensure-plan-event`：`作息管家/scripts/schedule_db.py:1044` 逐字「确保本地 DB 和飞书日历两边都有该事件。缺哪边建哪边」；本地键＝`(date, time_start, time_end)` 三元组（`:1054-1056`），远端键＝`(date, time_start, time_end, title)` 四元组（`:1121-1132`）。
- 老 `memo add`：`备忘录/script/memo_cli.py:158-160` 逐字「add 心愿接口的第一责任 = 本地 note + 飞书 task 一次性建好(含 due)」。
- 归属锚：作息 `schedule_db.py:1137` 描述前缀「作息管家自动同步」；备忘 `feishu_sync.py:329` 描述「原备忘 #<id>」，反向对账用 `re.compile(r"原备忘\s*#(\d+)")` 反查（`feishu_sync.py:617`）。
- 降级口径：老写路径几乎全「降级继续」；唯一「远端不可用即阻断」入口是 `cmd_feishu_resync`（`schedule_cli.py:1495-1499`）。
