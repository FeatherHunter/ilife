### 2.2 成因二：两条 Windows 语义测试（ubuntu 红，本地 Windows 绿）

CI 日志里各出现 1 次，均在 `build-test (ubuntu-latest, 22.13.0)`：

- `#87 ④b`（`packages/skill-calorie/test/output-naming-87.test.mjs:173`，败于 `:198` CLI 段）：`error: '实际落点：唤醒词HELP_20260914_004223.html'`，期望 `^唤醒词HELP_<STAMP>_2\.html$`，实际无 `_2`（`.scratch/t310/ci-87-detail.txt`）。
- `#237 ⑤`（`packages/base-render/test/output-save-html-237.test.mjs:388`，败于 `:399`）：`error: 'The "string" argument must be of type string. Received type undefined'`，即 `r.json.name` 为 undefined，`assert.match(name, …)` 接不住（`.scratch/t310/ci-237-detail.txt`）。其下一条 `⑤b` 在同一作业绿。

本地对照（Windows）：87 文件 `tests 14 / pass 14 / fail 0`（`.scratch/t310/local-87.log`）；237 文件 `tests 17 / pass 17 / fail 0`（`.scratch/t310/local-237.log`）。

根因分析（已标不确定度）：

- ④b CLI 段：单测段（`htmlFileName` 的 `toLowerCase` 比较）在任何平台都过；CLI 段走共用件 `saveHtmlFile` 的 `wx` 独占递补。预置种子是 10 个大写 `.HTML`，Windows 大小写不敏感文件系统里 `wx` 建小写同名即 `EEXIST` → 递补 `_2`；Linux 大小写敏感，小写名是另一个目录项，`wx` 一次成功 → 无 `_2`。失败读数（有种子仍落本体）与该机理逐字相符。**确定度高**（读数直接支持）。
- ⑤：用例主体 `'长'.repeat(300)` 经 `washName` 按码点截断到 180 码点（`STEM_MAX_CODE_POINTS = 180`，注释写按 Windows 单段 255 上限留余量）。180 个中文字符 UTF-8 约 540 字节 ＋ 时间戳段，Linux 单段 255 **字节**上限下 `writeFileSync wx` 报 `ENAMETOOLONG` → 测试体的 `catch` 回 `{thrown}` → `name` 为 undefined → `:399` 报错。Windows 按 UTF-16 码元计（约 201 字）不超限故绿。**确定度中**：CI 日志里该用例不打印 `thrown` 原文（测试体吞掉后只断言名字），未能逐字核对 `ENAMETOOLONG`；但字节账（540 > 255）与报错形状（name 缺席而进程 exit 0）唯一吻合，且 `⑤b`（短名）在同作业绿，旁证目录本身可写。

### S-B 成因二（两条 Windows 语义；建议归共用件 `save-html` 主人＋产品裁定）

1. 先补诊断：给 `output-save-html-237.test.mjs` 的 `spawnSave` 在 `name === undefined` 时把 `r.json.thrown` 打印进断言信息（现在吞掉，Linux 上只能猜 `ENAMETOOLONG`）。
