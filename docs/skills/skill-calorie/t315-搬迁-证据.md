## §6 落点窗口开门判据还应包含 `dist`／印记干净度（#315r 复核 S3-4，转 #320／#325）

**「开门判据＝`git status --porcelain -uall` 为空」不充分。** 生成物与它的输入印记住在 **gitignored** 的
`packages/skill-calorie/dist/`（`.gitignore` 第 2 行 `packages/*/dist/`；本席当刻 `git check-ignore` 复核成立），
`git status` 对它**完全看不见**。外来席半迁移留下的 `dist/` 与 `dist/.gen-inputs.json` 会让「读数」与「源码」
脱节，而树是干净的——复核席当刻实测：

- `GEN-STALE FAIL`：`exercise/routes.ts` 的印记 `1a094bf8…` ≠ 当刻源码算出的 `6114a81e…`（树干净），
  直接把 t293 的 P1／P3 打成**假红**；
- v3 → v4 之间**同一份印记**的 sha256 从 `D4D7DAF4…` 变成 `4AC8A9AD…` ⇒ **同一棵干净树两次读数不一致**。

**故落点窗口开门后，先做一次「基线绿」检查**：在**未做本票任何改动之前**跑

```
pnpm build → pnpm gen → pnpm gen:check
```

必须全绿。若不绿，那是**别人的残留**，不是本票的红 ⇒ 应当 **abort 并记录**（挡住者原文与时刻写进自己的
`.scratch/<票>/`，不要在不干净的基础上继续落点，也不要顺手回退／提交别人的文件）。若 `pnpm gen` 写出追踪件
（`keys.ts`／`registry.ts`／`routes.generated.ts`／`combos.yaml`／`build-help.mjs`）的差异，同样是「源码与生成物
不同步」⇒ 同样 abort 并记录。
建议再补一条印记留痕：开门时记一次 `dist/.gen-inputs.json` 的 sha256（复核席建议的 `OPEN-STAMP` 形态），
收尾再比一次——两次不一致就说明窗口内有别人的东西在动。

本票（#315）落点窗口内的门禁链本身是干净的（§3：除刻意变异那道 `mutant-gen:check` 外全 `exit=0`，收尾树为空；
本席返修时 `git status --porcelain -uall` 也为空），但**那是运气不是判据**；判据的收口归 **#320**（棘轮／终态）
与 **#325**（生成物门假绿缺口）。
