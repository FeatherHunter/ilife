判据口径（全票共用，先冻住）

  • 只观察六样：真出口退出码；落盘文件首行 <!doctype html>／含 charset／含内联样式 ≥ 2KB／无外链；剥掉标签后的可见文本里的字串与数值（须有限）；回执给的绝对路径存在可读；门的红绿读数；命令自治探针 UNACCOUNTED 计数。
  • 每条判据写成「跑哪条命令 → 看哪个读数 → 等于什么」，并配负向对照（改坏一处必红、还原必绿）。
  • 期望值只认三种来源：手算式／变更前 git 快照／需求原文——不许拿新实现自己的输出当期望值。
  • 行数一律节点口径；禁用把活派给用户、负向判据、拿「文件里有某串字符」当内容正确的证据。

三席对抗式审查与裁定

目标达成红队：FAIL采纳

最重一条：九张票里没有一张证明「用户复制到的那段 prompt 能跑完」——预检页的 prompt 构造器产出的是参数式中文，缺字段时还会退化成 // 提示串（身材照／GIF 那两页的 prompt 是带命令的）。

处置：单列一票（#366），判据写成「复制区文本去空白后逐字等于命令串 → 照它跑一次必落盘整页 → 回执绝对路径可读」。

架构合规红队：FAIL采纳

  • 「对比围度只差接线」不成立——取数缺部位名与变化率，算层要同票做。
  • 「下调棘轮」是空动作——真正要动的是三处计数门（344→345／92→91／295→296）与理由码（23→22）。
  • 「第 1–3 张可并行」不成立——写集同文件，已删掉这个说法。
  • 本包告警线（packages/skill-calorie/AGENTS.md）无人认领——单列一票（#354）。

判据红队：FAIL采纳部分驳回

采纳：逐条补假绿防线——空样例集让「逐件相同」真空成立（加「件数 ≥ 6」）；页面回显输入而非库值（改判「字段值 == 脚本查库值」并加「手改库字段页面必变」）；复制区是超集也绿（改判「逐字相等」）；门的方向写反（改判「从唤醒词表删一条代表词 → 门必红」）；肉眼验收移出门、只作展示。

驳回：它要求把「复制区文本」与「照抄执行」拆成两票——那是同一处改动的两行证据，不拆；拆分尺度按「可独立交付的改动＝一张票」定。
