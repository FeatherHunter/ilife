## 一 第一性原理：并发安全的三条，全部出自本仓协议

本仓的 `docs/subagent-concurrency-protocol.md` 已经把这件事想清楚了，我不另造规矩，只做三件推导：

1. **路径所有权（§1）**：共享同一个工作区，并发安全的唯一保障是「每票开工前声明自己会写的路径集合，只写这些路径」。⇒ 两张票能并发的**充要条件**是写面不相交。
2. **共享资源串行化（§2）**：编译／测试／git 写一律持锁；⇒ 写面相交的票**不能靠"排队"绕开**，只能靠**先后关系**。
3. **`dist` 读数要安静窗口（§2.6）**：锁不覆盖源文件写入，别人改到一半时编译出的 `dist` 是混合态，以它为前提的读数一律作废。⇒ **任何要跑真出口／量产物字节的票，都要在"本包无别的写者"时做**。

由此推出一条硬结论：**`packages/skill-schedule` 是单写者资源**。这不是偷懒——它是三处物理共享点决定的：

| 共享写点 | 谁都要碰 | 为什么绕不开 |
|---|---|---|
| `tooling/skill-html.snapshot.json` | 每一个改 HTML 的票 | 快照门是**一个文件**，覆盖 5 个技能 187 件产物；改一处 HTML 就要刷新它，刷新即重写整文件 |
| `src/cli/keys.ts`／`registry.ts`／`routes.generated.ts` | 每一个动命令登记的票 | 生成器**扫全包** `src/*/commands.ts` 再产出——别的票的半成品会被扫进来，生成物指向未提交的模块 |
| `dist/` | 每一个要跑门的票 | §2.6：混合态读数作废，必须安静窗口 |

## 四 并发怎么用（不是"不许并发"，是把并发放到不撞的地方）

| 时刻 | 主干（写包，永远只有一张） | 支线（写面不相交，可同时跑） |
|---|---|---|
| 起手 | 【结构】 | 【清单·取证】（只读老仓，写 docs） |
| 第二拍 | 【交付面】 | 【种子】（写 `scripts/` 与 `.scratch/`） |
| 形状 | 【形状】（**等人裁**） | 【链路页】的**生成器脚本可以先写好**（只读清单，不与主干撞面） |
| 八拍 | 八张域票按序 | 证据件撰写、清单回写 |
| 收口 | 【链路页】→【收口】（**等人滚墙**） | — |

两个等人点（形状、收口）之前，能自动做的都已经做完 —— 人看到的是成品，不是进度条。

## 五 对抗式审查：这份设计自己的毛病

| # | 攻击 | 处置 |
|---|---|---|
| 1 | **把「锁」写成「依赖」**：链式边让「查询域」看起来被「写入域」挡着，这是假依赖，正撞编排纪律「依赖与锁分开」 | 边照建（物理防止 > 口头提醒），但**在票面与任务清单里标注性质**：这 8 条边是**写者互斥序**（共享快照文件），不是语义依赖；真语义依赖只有三条：交付面←结构、形状←交付面＋种子＋清单、域票←形状 |
| 2 | **前沿恒为 1**：主干上永远只有一张可开工，并发名存实亡 | 并发放在支线：清单、种子、链路页生成器、证据件撰写 —— 它们与主干写面不相交，已用边证明可并行（前沿 2 张） |
| 3 | **总时长 ≈ 12 步**，能不能把 8 步压成 3 步？ | 唯一办法是**改快照门**（把单文件拆成按技能／按页族的分片），那是跨技能共用位，要另开票且中间提交会红 —— **本图不做**，记为「Not yet specified」供以后裁 |
| 4 | **链式耦合**：一个域做砸，后面七个都停 | 每张域票必须**做完即提交**（协议 §3.1 增量提交），下游从已提交的事实接手；体检的「外部阻塞」检查兜住悬挂 |
| 5 | **链序是任意的**，凭什么 write 在头？ | 理由写明：写入域最小（只有一族要出页），当**热身链头**，用来第一次验证形状配方在真页面上成立；随后按你最高频的查询族往前走 |
| 6 | **体检依赖票面声明的写面准**，声明漏了就查不出 | 写面写进票面的固定段 `## 写面`；**关票前必跑 lint**；漏声明按协议 §1 记 S1 过程违规 |
| 7 | **收口两段化后可能永远不关** | 给终止条件：复评达标即关；未达标则把剩余缺陷**逐格转票**并**由人裁**是否接受（人签字是唯一出口） |
| 8 | **前沿 2 张里有一张是 research**，若它卡住会拖住形状与所有域票 | 【清单·取证】只复述老侧事实（不设计、不裁定），是纯取证活；卡住的兜底：允许【形状】先做，清单补齐后由域票回写 |

## 六 落地步骤（说落就按这个跑）

1. **改图**：新增 `【交付面】`、`【种子】` 两票；`【骨架】` 收成 `【结构】`（交付面移出）；`【清单】` 降级为只复述事实；八张域票串成写者互斥链（7 条新边）；形状的前置改成 交付面＋种子＋清单。
2. **改票面**：每票加 `## 写面` 段（协议 §1）与「本条是写者互斥序／语义依赖」的标注；域票判据改成**按清单逐场景驱动**；收口票改成两段（审查开票 → 修完复评 ≥90 → 人签字）；补三处无主项（种子、代码层审美窄判据、新词进 frontmatter）。
3. **复跑两面**：`map-chart.mjs lint`（图体检，期望 PASS 且写面 0 撞车）＋ `map-chart.mjs verify`（子议题计数与每票被阻塞集合 expected／actual 逐条一致），两行读数贴回地图。
4. **地图正文**：Destination 把「最好看」换成可判定的程序（哪一次人裁说了算）；Notes 记这三条原理与「主干单写者、支线并行」的口径；任务清单重建并加「边性质」列。
