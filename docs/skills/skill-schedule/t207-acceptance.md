## 二、你要做的三步

### 第 1 步 重启 DSH Desktop（必须做一次）

- **为什么必须**：装机（把 `dsh-schedule-ilife` 装进 web profile）发生在今天 14:09；当前宿主主进程起于今天 00:39:55，**早于装机**；web profile 没开补丁热重载，新插件不会热生效。
- **怎么重启**：完全退出 DSH Desktop（托盘图标也要退出），再打开。
- **怎么确认已生效**：几步之后说「作息管家help」能拿到文件路径，就是生效了。想先看机器证据，重启后跑这一行：
  ```powershell
  Get-CimInstance Win32_Process -Filter "Name='DSH Desktop.exe'" | Where-Object { $_.CommandLine -notmatch '--type=' } | Select-Object ProcessId,CreationDate
  ```
  我跑过一次：`ProcessId 38516，CreationDate 2026/9/12 0:39:55`——在装机（14:09）之前，所以要重启。
- **别把这两件事看混**：profile 里已经有 `dsh-schedule-ilife -> D:\ilife\packages\plugin-schedule-ilife` 的链接（14:09 建），那是「装好了」；「宿主用上了」要等这次重启。

## 四、「不会看到」清单与成因（对照旧页时会疑惑，先看这里）

1. **84 枚「可用」徽章**看不到：新 help 模板只画「待开发」一种徽章，旧页把其余 84 条画成「可用」。属**世代差**（用户 Q11=A：视觉基准＝共享 help 模板），不是内容缺失。
2. **分组级计数胶囊**看不到：旧页每个分组标题后有「4 唤醒词／14 场景／1 待开发」三枚小胶囊；新模板只在子功能标题上留了一枚场景数。属**世代差**。
3. **hero 四项统计与生成时间**看不到：旧页页首有「5 模块／34 唤醒词／85 场景／1 待开发」＋「生成于 2026-08-11 12:56:17」；新模板页首只画一枚「85 场景」徽章，也不画生成时间（含 5 类别／34 唤醒词／85 场景／版本 2.0／更新于 … 的那句数据进了文件，模板不画它）。属**世代差**。
4. **搜索搜不到「预期说明」**：新模板的搜索只看场景卡上的字（唤醒词＋标题），不搜分组页首的说明区。实测：搜「报告空态」（这个词只出现在预期说明里）→ 页面提示「匹配 0 个场景」「没有找到相关场景,换个词试试～」，而同一个词**仍然显示**在该分组页页首。属**世代差**（旧页把预期说明拼进了每张卡的搜索词），不是内容缺失。
5. **展开／折叠按钮**看不到：旧页工具栏有「全部展开」「全部折叠」两枚按钮；新模板没有这两枚按钮。每个子功能标题仍可点开／收起（默认展开）。属**世代差**。
6. **卡内 prompt 与参数说明**改为点开可见：旧页把 prompt 与全部参数说明摊在卡面上；新模板卡面只有唤醒词、标题和「复制」，**点卡片**从底部升起弹层，参数输入框与「Prompt 预览」都在弹层里。属**有意裁定**（以共享 help 模板为准）。
7. **10 条场景由旧页「可用」改为「待开发」**：旧页只有「category 不在白名单」1 条标待开发，新页 11 条。多出的 10 条＝5 条今天没有对应命令的唤醒词（#1 准备消息／#2 同步作息／#3 增量同步／周视图／首次使用）下辖的场景，按票 #201 的票面规则补标。**内容没缺**，标注比旧页更诚实。

**那 90 条伴生信息在哪看**：**各分组页的页首**（不是每张场景卡里）。每页行数：写入与同步 15、查询与浏览 29、日程与计划 29、分析与洞察 13、辅助与管理 4，合计 90。
