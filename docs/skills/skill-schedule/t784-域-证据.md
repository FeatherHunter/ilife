## 四、本票自己裁的几处（都写进了代码注释与票面）

1. **为什么单日族只出一张页**：七个唤醒词**全在 `schedule.record.today` 这一枚 key 上**，路由表（`src/triggers/routes.generated.ts`）没给它们各自的预设，出口（`src/cli/cmd_read.ts`）只按 key 分派 ⇒ 下游分不出是哪个词来的。要么按词分页（那要改生成物 `routes.generated.ts`，票面**明令不许**），要么一张页把七个词的诉求答全。取后者：结论条 ＋ 24h 时间轴 ＋ 4 卡摘要 ＋ 分类进度 ＋ 睡眠统计 ＋ **作息库现状**，一条不缺。
2. **「作息库现状」那一块**：老侧 `status` 子命令的五条读数（总记录数／已记录天数／日期范围／最后记录日期／最后记录内容）在新仓此前只写 stderr；本票把它们摆成页尾一条事实条（走公共层 `renderFactStrip`，段名借 `heat-title` 这个已有类，**不新造类名、不新添 CSS**）。
3. **逐条时间轴从「时间轴条」换成「行列表三槽」**：公共层 `renderTimelineRows` 只有「时间／正文／附注」三槽，记录的**分类与时长**塞进附注就会堆成 `分类 · 时长`——正是分隔符门（#516）点名的那种堆法（实测 37 处命中）。改走同一公共层的 `renderListRows`（时间／做了什么／时长三槽），起止写「至」不写波浪号：同一份页从 37 处命中降到 0。
4. **「这一天还没过完」落在结论条里**，不另立段落：页型配方是 #782 人裁冻结的，件序列不因数据多寡变形。判据＝`已过分钟数 > 覆盖 且 已过分钟数 < 1440`（只在查的就是今天时给）——查过去某一天不会拿现在去衡量它。
5. **单条详情（f06）与查日程（f10）不在本票**：它们的唤醒词（查作息详情／按 ID 查记录／查日程／看日程）住在 #786 的目标清单里，写面也是 #786 的 `src/query/`。本票把这几行写在「有意不出」里并点名归谁；18 行的归属算术由探针每一次跑都断言一遍（`本域 28 行＝本族 11 行 ＋ 归 #785／#786 的 17 行`）。

## 七、遗留出口

- **本域小墙 ≠ 收口墙**：本票交的是「5 域之一」的小墙（5 格 × 双端），供 `#792` 汇总；最终那面墙与逐格缺陷清单在收口票里出，人签字也在那一段。
- **「查作息时间轴」与「今天总结」拿到的是同一张页**：按第 4 节第 1 条的口径（同一枚 key、下游分不出词）。若日后要给「时间轴」单独一张页，正路是给路由加预设（`view=timeline`）——那要改生成物，属另开一票。
- **数据里的分隔符不经我手改写**：页上「活动」是用户自己的话，原样上屏；只有起止与分类／时长的**版面串接**做了显示规范化（范围写「至」、并列换分槽）。若哪一天用户的活动名里带顿号，分隔符门会报它——那是用户的话，不是版面债。
- **票专属探针按票号认窗口**：`t783-探针.mjs` 的安静窗口判据把「持锁者票号」认作 783；本票持锁跑它会以 `ERR2`（窗口不安静）退出——那是它的既定行为（它那份读数只对 783 那一窗口有效），不是本票的失败。本票的「别域产物逐字节不变」因此改用独立读数（第三节那一行：现算 7 件与冻结清单逐件同）。
- **变异两态怎么读**：变异那两次 src 指纹**本来就该变**（改的就是源码），所以「还原一致」的判据是**还原后重跑时 src 与 dist 两枚都回到清跑那一对**（第三节末行），不是「变异那次也同枚」。
