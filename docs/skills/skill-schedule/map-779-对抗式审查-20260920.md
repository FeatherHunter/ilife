# 对抗式审查：地图 #779（2026-09-20）

> 审的对象：[【wayfinder】作息管家页面面：五域所有唤醒词出页 ＋ 链路页 ＋ 双端视觉验收墙](https://github.com/FeatherHunter/ilife/issues/779)
> 与它的 13 张子票。审法：从第一性原理问「这张图凭什么叫成了」，再逐条找能让它**兑现不了 Destination** 的地方。
> 只读取证 ／ 只写本件与地图评论，未改任何票面、未动产品代码。

## 〇 判决

**能开工，但按第一性原理有 4 处结构硬伤，不修就会在收口时说不清或必然返工；另有 7 处会让验收失真、3 处打磨项。其中 3 处是已核实的事实错误（票面命令形、读数陈旧、单位错位）。**

先说对的地方（免得审成一律否定）：原生边与自校验是真的（13 张票 sub-issue ＋ 27 条 blocked_by，expected／actual 逐条 OK）；票面五段齐、格式契约过检（零字面 `\n`、无 BOM、章节行首）；Out of scope 每一条都有出处；唯一的 HITL 票（形状）没有拖到收口才出现。

## 一 先问：这张图凭什么叫「成了」

Destination 有四句话，逐句过「可判定性」：

| Destination 的一句 | 可判定吗 | 判定者 |
|---|---|---|
| 五域下每个唤醒词走通「命令 → 真 HTML 落盘、回执给绝对路径」 | ✅ 可判 | 探针脚本（exit 码 ＋ `delivery.path` 对盘） |
| 页面在信息组织上取老之长、视觉取新之长，**做出最好看的一版** | ❌ **不可判定** | 无——「最好看」不是判据，是个愿望 |
| **85 个场景逐个交代** | ⚠️ 半可判 | 清单票有 85 行，但「交代」＝产页还是登记，判定面在 r1 一票手里 |
| vision **逐页 ≥90**，由人滚墙验收 | ⚠️ 判定者冲突 | 仓规写「视觉模型是提示器，不是证据」，这里却把它当硬线 |

**第一刀就砍在「最好看」这三个字上**：Destination 里允许出现愿望，但**必须同时给出把它变成真假的程序**。现在那个程序散在三处（形状票的人裁 ＋ z9 的 vision 分 ＋ 人滚墙），谁说了算没写死。

## 二 硬伤（A 级：不修必然跑偏）

### D1 验收单元与交付单元错位（你裁 Q2=B 之后更严重）

Q2 裁的是「**墙的格＝场景**」，可七张域票的判据全是**唤醒词**粒度：「四条唤醒词真跑 → 产物落盘」。两边的单位不一样，于是存在一条通道：**某个场景整个没做，而该域的唤醒词都跑得通，探针照样绿**。
根因：我把「交付怎么切」当成了唤醒词，把「验收按什么切」忘了跟着改。
修法：域票的探针**从清单逐场景驱动**（读本域那 N 行，逐行判「有产物」或「在有意不出名单里」），判据行写「本域 N 行场景逐行有交代」。

### D2 「有意不出」的裁定者缺位，且与域票的产物无人检测冲突

老侧「只出文本／JSON」的那 25 个场景，是我从老实现推出来的**观察名单**，不是新设计的裁定。实测已经打架：老侧 `status_default`（查作息状态）只打 5 行文本，属于那 25 个之一；可新设计的 `【查询与浏览·单日族】` 明写要给「查作息状态」出一块可见的状态区——**同一张场景，一边进产物、一边进「有意不出」，没有任何一票会红**。
根因：把「老侧没有页」误当成「新侧不该有页」，且没人负责裁定与交叉检测。
修法：r1 加一条判据——同一 `scenario_id` 不得同时出现在某域票的产物清单与有意不出名单里；并写死裁定权在 r1（域票要推翻须写明理由并回写清单）。

### D3 骨架票焊了两件不同风险的事，且它挡着 8 张票

`【骨架】`（#780）把「命令登记搬到能力目录 ＋ 接生成链」与「唤醒词命令缺省落盘（行为改变）」焊在一张票上，判据是四条命令的链；而它挡着形状 ＋ 七个域，共 8 张。
根因：把「结构就位」与「交付面就位」当成一件事排进去了——前者动的是声明与生成链（进 CI 面），后者动的是命令出口行为，风险不同、可各自红绿。
修法：`#780` 只留结构（声明搬家＋`pnpm gen`／`gen:check`／快照门／边界门）；**交付面（缺省落盘 ＋ 产物落点分家 ＋ 命名）挪进 `【形状】`**——形状票本来就要拿出产物来给人看，落盘契约在那里被真正用到。

### D4 七域的顺序与并发没说死，而它们共用生成物

七张域票各自新增声明，`pnpm gen` 写的是**全包共用**的 `cli/keys.ts`／`cli/registry.ts`／`triggers/routes.generated.ts`；快照门也是全仓 187 件一起变。真让两张域票同时开工，生成物必冲突、`gen:check` 必红。
根因：把「域自治」误当成「可以并发写」。
修法：地图 Notes 写死「**同一时刻只许一个写者动 packages/skill-schedule**，域票按序走 `tooling/run-locked.mjs`」；域票红线里补一句。

## 五 我核过的事实（不是推的）

| 我说它错 | 实测 |
|---|---|
| `measure-responsive.mjs` 的用法 | 用法头逐字：`<a.html> <b.html>` 或 `--dir <目录> --label …`；选项 `--widths 390,768,1440`（缺省三档）／`--json`／`--exclude`——**没有位置参数接目录这一形** |
| `audit-separators.mjs` 的用法 | `用法: … <a.html> [<b.html> …] | --dir <目录> [--json <路径>] [--quiet]`——票面写的「逐件点名」✅ |
| 快照门读数 | `RESULT: artifacts=187 changed=0 added=0 removed=0`（票面写 185 ❌） |
| `run-locked.mjs` 用法 | `node tooling/run-locked.mjs --ticket 88 -- <命令>` ✅ |
| frontmatter 触发词是不是派生的 | `tooling/skill-call-form.mjs` 只维护 `<!-- CALL-FORM -->` 块；`SKILL.md` 的 `description` 触发词是手写 ❌（无人负责） |
| 标签面 | `wayfinder:map`／`task`／`research`／`prototype`／`grilling` 五个都在 ✅ |

**我没能核的两件**（如实记）：① 每张域票是否真能在一个窗口里收工——这是粒度判断，得等第一张域票跑完才有读数；② 63 格外加「有意不出」一节的墙会不会太长——要等清单票出数才算得准。

## 六 建议的最小修法（一刀一刀，共 5 刀）

1. **改票面事实**（D6／D7／D13）：8 张票的命令形、快照门读数、链路页行单位——纯文本修正。
2. **改咬合**（D1／D2／D10）：域票判据改「按清单逐场景驱动 ＋ 逐字段在页上」；清单票加两个判据（冲突检测、`fields[]`）。
3. **拆风险**（D3）：交付面从 `【骨架】` 挪进 `【形状】`；`【骨架】` 收成纯结构票。
4. **补依赖与纪律**（D4／D9）：加边 `【链路页】`←清单、`【收口】`←清单；地图 Notes 写死「同包同刻一个写者」，域票红线各补一句。
5. **补两处漏项**（D5／D8／D11／D12）：域票各带本域小墙与代码层审美记录；两处触发词补词；z9 写清打分权属。

**另有一件流程漏项**：按 wayfinder 的开图流程，研究票在**开图时**就该点火 `/research` 子代理；本图开完没点火（因为盘点我已经先做完了）。剩给 `【清单】` 的 85 行映射是 AFK 活，随时可以点。

## 七 一句话结论

图的结构是对的（原生边、五段票面、可跑判据、边界清楚），**病在把「交付怎么切」和「验收按什么切」当成同一件事**——Q2 改成场景为格之后，票面判据没跟着换单位，于是留下一条「域票全绿而场景漏做」的通道。这四刀（尤其是第 1、2 刀）我建议在建图当天就落，越晚改越贵。
