# #862 · 作息设置页「HELP 产物目录」多一级（`schedule_html/help/help`）：证据

> 票：[作息管家设置页：老配置文件里的两级 html.dir 被按新算式算，HELP 落点多出一级](https://github.com/FeatherHunter/ilife/issues/862)
> 归属：`skill-schedule`（技能侧落点算式 ＋ 体检那一处）；用例在包内 `test/`
> 日期：2026-09-21 · 工作区 `D:\ilife` · 动手前 HEAD `8de9d25c`（发版后）

## 一、现场与根因

**现象**：作息管家的设置页那行只读的「HELP 产物目录」显示 `C:\Users\辰辰洋洋\.ilife\data\schedule_html\help\help`
（多出一级 `help`）；其余五家同位置都是正常的一层落点（对照：大厨的 `cook_html/help` 解析成 `<库>/cook_html/help`）。

**根因**：`html.dir` 的含义在 #843（「产物落点分家」）变了，**老配置文件里的值没跟着迁**：

1. #843 起 `html.dir` 只记**产物根**，HELP 那一级另由 `html.helpDir` 补 —— 算式
   `<库>/<html.dir>/<html.helpDir>`（`packages/skill-schedule/src/fetch/paths.ts`）。
2. 本机 `~/.ilife/schedule.yaml` 是 `html: { dir: schedule_html/help }`——**#843 之前的老默认**（那时 `html.dir`
   记的是「产物根 ＋ HELP 子目录」两级，HELP 直接落它下面）。
3. 两级值照新算式算 ⇒ `<库>/schedule_html/help/help`；同一个偏差还让**产物根**变成 `<库>/schedule_html/help`
   （页面会被塞进 HELP 目录里）。属 #762 口径的同一类：**老配置文件不该让用户为我们改的东西买单**。
4. **为什么只有作息这一家**：其余五家的同名键不是同一套形状（大厨的 `html.dir` 本身就是 HELP 目录、另有
   `sceneDir` 指产物根），老值照它们的算式算出来是对的。
5. **为什么现在才露出来**：#843 提交 `ff83a49f` 落在 09-21 13:02，而定版 `51895e0f` 是 11:42、
   registry 上 `skill-schedule@0.3.1` 发布在 11:58 ⇒ **0.3.2 是第一版带上 #843 的**；此前面板整个读不出来
   （#861 的公共层问题），这一版能读了，偏差才显形。

## 二、改了什么

| 件 | 改动 |
| --- | --- |
| `packages/skill-schedule/src/fetch/paths.ts` | 新增 `resolvedHtmlDirs()`：认 #843 之前的两级老值——**末段与生效的 `html.helpDir` 逐字相同、且值多于一段**时，把末段还给 `helpDir`；`resolveHtmlDir`／`resolveHelpDirOf`／`resolvedSchedulePaths` 三处改用它的生效值（两个算式仍是唯一的 join 处） |
| `packages/skill-schedule/src/health.ts` | 体检的产物根也改吃 `resolvedHtmlDirs().rootDir`——同一件事只有一个定义地，体检与设置页不许各算一份 |
| `packages/skill-schedule/test/t862-老值落点.test.mjs`（新） | 四条读数：老值 ⇒ 落点与升级前逐字相同（含**真出口**的 `resolved.htmlDir`）；反向对照（不认账时算出的就是 `…/help/help`，证明用例有识别力）；新形状不受影响；别的值照新算式算 |

**不迁移文件里的值**：认账发生在解析处，配置文件一个字不改——老值继续按它当年的含义生效（#762 的口径），
用户要改成新形状也照样成立。
