## 五、公共层缺口与停档（票面「若公共层今天给不出」那一条）

票面写的正路是「`CopyBlockInput.buttons` 收自定义按钮（`ActionBarButton`＝`{actionId, label, text}`）」。
**装着的 `base-paint@0.3.7` 不是这样**：`ActionBarButton`＝`{ label, kind, actionId, disabled? }`，
它的类型注释自己写着「动作条按钮**没有 `data-t` 载荷位**」——
即「把某一串文本交给它复制」的自定义按钮，公共层今天给不出（`renderCopyBlock` 的数据位恒是
标签写死的「复制数据」一颗）。

按票面那一条**停档**：四处落点**各一枚按钮、不再成对**（不再各带一对「复制数据／复制日志」），
按钮走公共层动作条的数据位 `renderActionBar({ copyData: { actionId, label, text } })`
——这是**公开面**（兄弟技能同一条：`packages/skill-calorie/src/render/copy.ts:37-39` 的
`copyActionHtml`），技能侧零手搓 HTML、零自造样式：

```
<p class="ilife-block-caliber">库目录已确认</p>
<div class="ilife-action-bar"><div class="ilife-action-row ilife-action-row-ghost ilife-action-row-ghost-single">
<button type="button" class="ilife-copy-btn ilife-copy-btn-ghost" data-action-id="ilife-sch-firstuse-copy-dbdir" data-t="<完整路径>">复制库目录路径</button>
</div></div>
```

可见行只留确认语＋按钮 label（**人话**，不印路径、不出现落点名），完整路径只进 `data-t`；
分隔符门仍只看可见文本，四张页都 0 命中。**票面留言**：若维护者要「四颗按钮住进同一个复制区动作条」，
要公共层给 `ActionBarButton` 补一个载荷位（或在 `renderCopyBlock` 上开一个自定义复制按钮位）。
