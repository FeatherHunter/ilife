## 一、这个原型要回答的问题与分支判定

**问题**：`今天总结`（单日盘）／`查日程`（日程盘）／`周视图`（热力盘）这三张页，**各由公共层哪些件、怎样组合而成**——即票面那张「页型配方表」的候选。

**分支判定**（`/prototype` 技能的两支）：这一问是「**界面应该长什么样**」，不是「逻辑／状态模型是否顺畅」——数据模型（记录／事件／7×24 矩阵）已经由老侧口径与种子库定死，要裁的是**写法与件**。

⇒ 走 **UI 分支**：同一路由（一张页）上放多个**结构不同**的候选变体，`?variant=` 直达 ＋ 底部悬浮药丸切换。

**形态与仓内先例**：仓里已有的 UI 原型先例是 `.scratch/t156-prototype`（四变体 ＋ 底栏 ＋ 原型自检）。本票照那条路子，但把「手写稿」换成**公共层真件**——因为本票要裁的就是「用哪些件」，手写 HTML 答不了这个问题。所以原型的载体是**一个生成器**（下节），变体＝真的 `base-paint` 区块／图表调用序列。

### ④ 过程中修掉的三类真缺陷（留给后来人）

1. **多根区块产出把变体标挂漏**：`renderDistributionRows` 与 `renderChips` 是「**行即件**」（不返容器）——把它们直接当一个 piece 时，只有第一个顶层元素会被挂上变体标，其余行**永远亮着**（周视图实测：A 页尾部多出两套分类行）。生成器现在有硬断言：每个 piece 顶层元素必须恰 1 个，多根当场报错（`topLevelCount`）。
2. **满宽容器里的 `gauge` 尺寸失控**：`renderChartBlock({kind:'gauge'})` 的宽高比接近 1:1，落在 880px 正文列里渲出一屏高的表盘（实测约 500px 高、数字巨大）。本原型据此改用「读数卡 ＋ 进度条」（`renderKpiCard` 的 `bar` 位）。**要不要给 `gauge` 加尺寸约束，是公共层的事，不是本票能定的。**
3. **`pageUi` 的一行四张读数卡进了窄栏**：`pageUiCss` 在 `@media (min-width:1001px)` 把 `.ilife-block-kpi-card-grid` 钉成 `repeat(4, minmax(0,1fr))`（宽屏口径）；「两栏读数盘」把读数卡放进 320px 的栏后，每张只剩约 70px，数字被折成竖排（截图为证，修前）。本原型在页内件里按栏宽改回两列。**这是「页内自造件要不要有自己的栅格档」的问题**——见第五节 H7。

### 人复看抓出的第二处缺陷（宽屏对齐：矩阵比上下两块窄一圈）

用户复看修后成品又报：「有两块区域的左侧和右侧超过了常规区域」。

- **现象**：宽屏（≥1001px）下，**读数卡那一排**与**每日汇总那几行**左右铺满 1280px，而中间的 7×24 矩阵／图例落在 880px 的文字列里 —— 上下两块各凸出一截。
- **根因**：矩阵是页内自造件，不像公共层的「读数卡／表／图表块／列表行」那样被 `pageUiCss` 的 ⑥⑧ 条收进「真二维数据满铺」那一档；本件**没写这条对齐规则**（原型里写过一条，但权重与 `pageUi` 同权且排在它前面 ⇒ 从未生效，等于一直是窄的）。
- **修法**：`pagePartsCss()` 加一条 `@media (min-width:1001px)` 规则把 `.heat-*` 三者 `grid-column: 1 / -1`。**该修法随后被人裁否掉**（见上一节：人要的是把卡片收回内容列，不是把矩阵拉宽），现已在 `src/shared/docPage.ts` 用 `BODY_SINGLE_COLUMN_CSS` 统一收成单列；本条只留作过程留痕，产物里已无这条规则。

### 人复看抓出的第一处缺陷（首版漏传色）与补的判据

用户复看成品时报了：「分类进度／分类总览的进度条**都是蓝色**，没有对应分类的颜色」。

- **根因**：`renderDistributionRows` 的 `color` 是可选项（不给＝落 `--blue`）；原型里我逐行传了色，**改写成品时漏传**——七/八条全蓝。色带与热力矩阵没漏（它们走 `pageParts` 内部算式）。
- **修法**：把色算式提成 `pageParts.categoryColor(key, order)`（原来那个内部函数），色带／矩阵／分布行三处共用它；分布行的上色由**页型函数**做（`dayPage`／`weekPage`），口径层（`queryDocs`／`planDocs`）仍然不碰颜色。
