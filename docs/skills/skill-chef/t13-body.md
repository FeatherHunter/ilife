## Question

用户 2026-09-12 裁 **乙**：把「命名与落盘」收成**共用位**，三家（私家大厨／饼干记账／卡路里）一起改成走它。用户同时裁定**对外函数名＝`saveHtmlFile`**（原拟 `saveHelpFile`，用户原话「这个名字不好。叫 saveHtmlFile 感觉更好」）。

本票要：**建共用件 ＋ 三家迁移 ＋ 门禁与发版线跟上**。

### 一、共用件对外只有一个函数

```
saveHtmlFile({ dir, stem, html, onExists? }) → { mode, path, bytes }
```

**参数（调用者给，这就是各家的自定义）**：`dir` 落哪个目录、`stem` 文件名主体、`html` 要落的整页、`onExists` 撞名策略。

**不参数（函数自己的判断，这正是它存在的理由）**：时间戳格式 `YYYYMMDD_HHMMSS`（本地时间）、同秒撞名递补规则、绝不静默覆盖、回执形状、字节数按 UTF-8 真实字节算。

> 若把这些也做成参数，它就只剩 `fs.writeFile` 包一层——仓规（铁律五）点名了这种「白占一层的转发包装」。

### 二、`onExists` 四态（用户点名要「是否开启自动递补」）

| 取值 | 撞名时怎么办 | 现状 |
|---|---|---|
| `succession`（**缺省**） | 自动 `_2`／`_3` 递补 | 三家 HELP 现在的行为 |
| `reuse`（用户点名要的「复用模式」） | 返回已有那份，不新建 | 新能力 |
| `overwrite` | 逐字覆盖，不递补 | 饼干记账 `--html` 已有先例 |
| `fail` | 明确报错退出 | 新能力 |

⚠️ **`reuse` 的判据不能按名字**：时间戳精确到秒，两次跑几乎不可能同名，按名字判复用等于没做。本票要实现的是：

- `reuse: 'byDay'` —— 当天已有同一主体的一份就返回它（对应「一天跑十次只留一份」）；
- `reuse: 'byContent'` —— 内容哈希相同就返回已有那份。

### 三、能力清单（用户点名 ＋ 本票建议）

用户点名：① `onExists` 递补开关 ② `reuse` 复用模式。

本票建议一并做（都是「不做就是个坑」的）：

- **文件名安全化** `sanitize(stem)`：Windows 非法字符 `/ : * ? " < > |`、结尾的点与空格、长度上限——**场景页一带用户输入（菜名／搜索词）就必须有**；
- **写后回读校验**：回执里的 `bytes` 必须是**实际落盘**的字节数，不是期望值。

可选开关（做成参数、默认关）：`files` 一次落多份、`dryRun` 只算不写、`keepLast: N` 只留最近 N 份。

**不做**：原子写（先写 `.tmp` 再改名）——HELP 是一次性产物，风险低，不值得加这层。

### 五、门禁与发版线
