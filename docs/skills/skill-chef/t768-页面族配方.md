# t768 三族页面配方（收敛稿）：老件骨架 ＋ 原型零件 ＋ 公共层标准件

这份文件是 #768 的**结论件**。原型（三页 × 三版）是取数用的仪器，已经取完数：九版里哪几件在新架构里活得好、哪些只是看着好、公共层缺什么——都在这张表里定下来，**域票照这张表组装页面，不再各自选形状**。

读法与来源标记：`[老]`＝老件已有的骨架或手法（老件是本仓信息架构与手法的权威）、`[型]`＝抛弃式原型里胜出的零件（附版本号）、`[层]`＝公共层现成的区块函数。原型九版当**零件库**留着：要看某一格长什么样，打开 `.scratch/t768/过程型.html?variant=A` 那样看即可；原型本身**冻结，不再改**。

## 0 三条口径

1. **骨架取老件**：分区与顺序按老件（用户亲自磨出来的那套：准备→做菜→完成、分节看谱、成功块＋变更明细＋撤销）。这不是"照抄老件"，是把老件的**信息组织**放到新骨架上。
2. **零件取原型**：九版里活下来的件（读数卡＋进度条、事实条、双栏贴顶、时间轴、变更行、页内导航），有双端读数作证。
3. **标准件取公共层**：每一个视觉单元都是一次区块函数调用；**页面不许自写样式**（今天唯一两条例外写在下面 §5，其中一条已开票）。

## 5 公共层缺口与处置

1. **正文段落件（**已开票**）**：12 个区块里没有「一段正文」的落点，原型只能用页内补丁 `.v768-prose` 顶住。步骤动作、菜谱描述、失败说明几乎每页都要它。→ 已立票（见票面 `## 遗留出口` 的回指），照 `block-toc`／`block-caliber`／`block-conclusion` 那批**页面级件**的先例做（不改 12 项闭集、不新增 token）。
2. **星级形状**：老件用 `★★★★` 显示评分。公共层没有星形件。两条路：① 走读数卡（值＝4，单位＝分）＋ 分布条——今天就能做；② 保留星形则要新件。→ **待裁一条**（我倾向 ①，理由：星级在读数上等价于「4 分」，而形状件要吃掉一次公共层票）。
3. **关系树**：老件 `派生/relation_tree.html` 的祖先／根／后代三区＋连线无落点；库里 `recipe_relations` 0 行，今天没有可显的数据。→ 不立票，记在派生域票的输入里（有数据再谈形状）。
4. **emoji 分区图标**：老件用 `🔪 ／ 🍳 ／ ❤️` 当分区图标，公共层不产 emoji。→ **待裁一条**（我倾向不引入：emoji 随平台换字形，印刷与截图不稳定；若你要保留那份亲切感，就落成公共层的一个图标位件，别让各域自写）。

## 6 我裁的四条（每条一句话可推翻）

1. **窄屏食材表用三列**（食材｜用量｜说明），分类退成第 4 项徽章行——原型 A 的四列在 390 档是每味四行（11 味＝44 行），B／C 的三列是每味三行。读数在 `读数.json`。
2. **桌面双栏只在 ≥1001 且可关**：过程型「备料贴顶＋步骤」、结果型「备料贴顶＋步骤」都是**可选档**，默认单列（手机与平板竖屏是主场景）。
3. **回执型取最省的那版**（结论条＋事实条＋变更行＋动作行），读数卡三格并入；不做大回执卡那种"主视觉卡"。
4. **过程型默认单步聚焦**（一次展开一步＋进度读数），全部步骤降级成折叠速览——照老件「做菜阶段」的原意。

## 7 铺开时域票要带的三条

1. 照本件对应族的配方表组装，**不自选形状**；每一格都是一次区块调用。
2. 产物必须跑 `node docs/skills/skill-chef/t768-质量门.mjs <该域产物目录>` 六列全绿（判据已入仓，可复用；反例六条也随件交付）。
3. 双端截图（390／1280）进册子；「老件有、这一域还没取到数」的项，按 §4 表逐条认领（认领不到的要写明为什么）。
