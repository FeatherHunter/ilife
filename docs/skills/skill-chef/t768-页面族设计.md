# t768 页面族设计：三族页面形状 ＋ 老件对照 ＋ 页面质量门

票号 #768（原型票，父图 #765）。产物：三页抛弃式原型 ＋ 双端 18 张截图 ＋ 两个器械脚本（质量门／生成器）＋ 本件。

## 0 一句话结论

三族页面各自出**三版结构不同的候选版式**（同路由多变体，`?variant=A|B|C` ＋ 底部悬浮切换条），全部走公共层装配（内容＝`base-paint/blocks` 的区块，文档＝`renderDocShell`），双端真渲染（390／1280），机审六列 0 命中、六条反例各自变红并点名。**形状未裁之前不铺开**：请维护者逐条回「过」或列出要改的地方（待裁清单见 §10）。

## 1 设计问题与分支判定

票面 Question 原文：**「这三族页面（过程型／结果型／回执型）该长什么样？」**

| 项 | 判定 |
|---|---|
| 分支 | **UI 分支**（界面应该长什么样）——照 `/prototype` 技能 §Pick a branch |
| 为什么不是逻辑分支 | 要回答的不是「状态模型顺不顺畅」（做菜模式的步骤状态已经定了），而是「同一批数据在页上怎么排、双端怎么塌、操作放哪」 |
| 产物形态 | 每族**一个自足 HTML**（双击即开，无外链、无 CDN、无外部字体），页内三个结构不同的候选版式，URL 参数 `?variant=` 决定显示哪一版，底部悬浮条可切（`←`／`→` 键同效） |
| 为什么三页不是一页 | 三族是三条「路由」：命令不同、envelope 形状不同（`list`／`detail`／`receipt`）、用户当刻在做的事不同；一页里切三族会把「族」与「版式」两件事混成一件 |

条外的一条硬口径：**标注为抛弃式**。三页的浏览器标题带「抛弃式原型 票 768」，底部悬浮条也写着，`data-prototype` 属性让判据跳过原型壳自己那些件。

## 3 三族结构

三族共用的页头形状：**眉标（品牌位 ｜ 域位，由并列分隔符机制出细竖线，字符不进产物）＋ 页标题 ＋ 事实条**——没有一个 `·`。族与族之间的差别在「页头之后放什么、操作放哪、双端怎么塌」。

### 3.1 过程型（做菜模式）

用户在流程里：需要知道「现在做第几步、这一步要什么、下一步是什么」，并且**随时能停下来看一眼备料**。

| 变体 | 骨架（自上而下） | 它赌的那件事 |
|---|---|---|
| A 单步聚焦 | 事实条 → 结论条（放大说明）→ 进度读数卡（3／6 步＋进度条）→ 六张步骤卡（当前一步展开）→ 上一步／下一步 → 备料折叠 → 收口动作（做完了记一次／看历史）→ 复制区 | 做菜时**一次只看一步**；状态外显在一张卡上，其余步骤折起来 |
| B 全步骤时间轴 | 事实条 → 结论条 → 进度读数卡 → **时间轴六行**（每行：第 N 步 ｜ 动作 ｜ 火候时长＋验收）→ 备料折叠 → 收口动作 → 复制区 | 六步一屏扫得完，**不需要「当前步」这个状态**；适合边看边做、随手上下扫 |
| C 备料工作台 | 事实条 → 结论条 → **桌面两栏**（左：备料表贴顶＋分类徽章行；右：六张步骤卡全展开）→ 收口动作 → 复制区 | **备料与步骤并排**（手机自动塌成一列）；适合灶台边一台平板／电脑 |

状态外显：A 的进度卡（当前 3／6 步、进度条 50%）与展开的那一步；切到 B／C 时状态行自动收起（B／C 没有「当前步」这个状态）。真跑时这几位由宿主驱动，原型里用页内脚本演。

### 3.2 结果型（看菜谱）

用户在看一份**已经存在的菜**：先判断「值不值得做」，再看细节。

| 变体 | 骨架 | 它赌的那件事 |
|---|---|---|
| A 摘要先行 | 事实条（难度／份量／总时长）→ 结论条（做过几次、平均几分）→ 分类徽章行＋状态徽章 → **四列食材表** → 六张步骤卡（折叠）→ 历史时间轴 → 营养口径行 → 出处折叠 → 动作 → 复制区 | 信息**全**；食材表连分类一起印（每味四列），手机上代价最大（见 §10 裁项 4） |
| B 两栏食谱卡 | 事实条 → **桌面两栏**（左：备料三列＋分类徽章；右：读数卡＋六张步骤卡**全展开**＋历史＋营养）→ 出处折叠 → 动作 → 复制区 | **照着做**：备料贴顶、步骤全出、不用点开 |
| C 分节导航 | 事实条 → **页内导航胶囊**（基本信息／食材与备料／步骤／做过的记录／来头与出处）→ 五节折叠 → 动作 → 复制区 | **长页跳转**：一屏看到全部章节名，点哪到哪；本变体另带「同版心」开关（见 §9 缺口 2） |

### 3.3 回执型（记录做菜回执）

用户刚做完一件事，需要**确认「记上了」**并知道**下一步能干什么**。

| 变体 | 骨架 | 它赌的那件事 |
|---|---|---|
| A 结论条＋事实条 | 结论条（已记下这次做菜）→ 事实条（菜／日期／评分）→ 变更行（状态 未做→已做、次数 0→1）→ 口径行 → 动作 → 复制区 | 最省；**只看「成了没有」** |
| B 大回执卡 | 浅色静态提示卡（已记录做菜 ＋ 评分与日期）→ 读数卡三格（本次评分／平均评分／累计做过）→ 变更行 → 动作 → 复制区 | 一眼看到「成了」，再用读数卡把累计说清 |
| C 时间轴回执 | 结论条 → 事实条 → 历史时间轴（这次记录所在的整条历史）→ 变更行 → 动作 → 复制区 | 把这一次**放回历史里看**：上次什么时候做的、这次排第几 |

页头分工（这几版都照同一条）：**标题只说「这是什么页」（记录做菜：辣椒炒肉），结论条说「刚发生了什么」（已记下这次做菜），事实条说细节（菜／日期／评分）**。三处各管一段，不复读——这是第一轮视觉审查抓出来的问题，改法与证据见 §8。

### 4.1 内容一条不丢：三处要有交代的地方

1. **共享动作层（复制数据／复制日志双按钮）与 5 状态**：20 个模板全有这一版式单元。新族统一用 `renderCopyBlock`（复制数据／日志）＋ `renderActionBar`（动作行）＋ `renderErrorReceipt`／`renderEmptyState`（失败与空态）承接——这三个区块是公共层既定的出口，本票三页都用了复制区与动作行，失败／空态在原型里未摆位（原型只演正常路径，见 §7 的诚实交代）。
2. **老件的过程页带了「阶段」与「撤销」**：老件用 `<div id="stage-badge">` ＋ `.stage-bar` 表阶段（`修改/*`、`历史/*`、`录入/*`、`派生/*` 八件），失败态还有 `.fail-card` 四段（五件）。新页的对应物是**状态徽章 ＋ 口径行 ＋ 变更行 ＋ 错误回执**；本票的载体（做菜模式）没有阶段徽章与失败态，所以**这一条只做了形状映射，没有在原型上出图**——它归各域纵向票（票面遗留出口已写「确认页／进度页／失败页 → 各域纵向票按需派生」）。
3. **老库自带的记法照印**：步骤正文里的 `+浏阳豆豉+小米椒(③)`、`(②)` 这类「加料 ＋ 步骤交叉引用」记法是**老库内容**。本票**原样印出**，不在页面层改写（内容以老件为权威）；它值不值得在源数据层清一次，另立票。这一条是原型上肉眼可见的「不好看」，但它是**内容债**不是版式债——按页族去重与美化会篡改源内容。

### 4.2 视觉不复刻

老件 20 个模板的类名与版式（`hero`／`stage-bar`／`.step-card`／`kpi-grid` 那一套）在新页里一个字都不出现；新页只用公共层类名前缀 `ilife-`（实测读数：产物类名里**老件类名 0 个**，唯一不是 `ilife-` 的是文档壳自带的那颗 `wrap`，与 `ilife-page` 同在一颗元素上，由公共层 `docTemplate` 产出）。老件在这里的作用只有一个：**告诉我哪几个信息必须还在**。

## 5 分隔符替代设计（`;`／`|`／`·` 分割＝该做 UI 设计）

用户原话第 5 条：「当一个内容需要通过 `;`、`|` 和 `·` 分割时代表需要进行 UI 上的设计」。本票把这条落成**六种替代形状**，并在三页原型上逐条点名：

### 6.3 两次「假绿灯」的踩坑记录（给后手）

1. **第一版重复句阈值 8 字 → 反例造不出来**。第一版注入的是「把标题复制一遍」，而标题只有 6 字，阈值 8 把注入本身滤掉了——**判据看着绿，其实是这一列根本红不了**。改法：阈值降到 6 试跑，结果抓出真页里 `锅温200度` 这类**数据格**短行重复（数据巧合，不是文案冗余），于是最终定成「≥8 字判红 ＋ 短行只报读数」，并把反例改成「复制结论条」（结论条天然够长）。教训：**反例要能造出来，才算这一列真的存在**。
