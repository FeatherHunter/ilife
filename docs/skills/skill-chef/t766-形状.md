## 第三步 · 写代码（决策＋对抗式审查）

每个决策都过一遍「删掉它，外面说得出少了什么」与「它帮目标走近还是走远」：

1. 声明不含 `run`。对抗：含 `run` 就要引 `fetch` 实现，跨能力内部引用违反铁律一；
   纯数据保持本票「纯形状搬迁」，目标「行为不变」走近。后续域票再下沉实现。
2. 路由类型本地定义。 对抗：复用卡路里类型即跨技能包依赖（A6-21 零依赖），目标「解耦」走远；本地最小最稳。
3. 生成器读源码文本。 对抗：读 `dist` 须整条打印记链，试点 scope 翻倍；文本解析＋严格校验＋逐字节比对
   已满足三成立要件中的两条（确定性、哈希锁），第三条由根 `gen:check` 进链满足。印记链缺口如实留遗留。
4. `keys.ts` 只派生键／标题／形状／来源域。 对抗：速查表块（代表唤醒词／示例派生）照卡路里先例应进
   `build-help.mjs`，本票动它等于扩共用位；试点只钉键表，判据已够（删声明即红）。
5. `sceneDir` 独立键＋休眠。 对抗：派生自 `html.dir` 会在改 HELP 落点时静默搬走域产物，
   违反「老键语义不动」；休眠无行为变化，全绿＋快照 changed=0 作证。
6. 中途修的两处生成器缺陷：① 示例串内花括号冲掉块匹配（0 条命令假绿）→ 改串感知匹配；
   ② `parseOnDisk` 正则撞上 `string[]` 里的方括号（空解析误报）→ 改锚 `=`。两处都是「门坏了」类缺陷，
   修完分别用变异红／还原绿钉死（见下）。
