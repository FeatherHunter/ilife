## 五 未做项与下一手缺什么

1. **只验了 4 页**：另外 44 页的读数留给各域席与收口席。本席给的是「公共层这一层」，域页里
   页内专属的版式与文案问题（表格列错位、结论条与摘要复读、KPI 卡孤行、长描述段断句）**一律没碰**。
2. **`视觉生动` 维的天花板**：这一维在本会话的尺子上按「有没有菜品图／插画」给分——4 页改后
   无一页超过 17，且评委每一页都在提「缺菜品图／步骤插画」。公共层的 CSS 只能把「色彩锚点与形状件」
   补到够，**再加就只剩图**。真要把这一维推到 18+，需要一条**公共层之外的**决定：技能侧要不要出
   菜品图位（`renderMediaFigure` 已有现成形状件，但本批 48 页没有任何一页的数据源里有图，
   且它的产出器会写 `loading="lazy"`，与验收墙的造册判据冲突）⇒ 建议另立票裁决「图从哪来」。
3. **`txt 精炼` 维是本批第二低（15.19）**，本席一行没动：那要改页面装配的文案（域席写集的活）。
4. **越界报备（未碰，只记录）**：
   - 派单册指定的重出命令 `regen.ps1` 内部会跑 7 个域驱动器与 `t777-run-all.mjs`，它们会**重写
     `docs/skills/skill-chef/t770…t776-册子片段.json`** 这 7 个受版本控制的件、并往
     `.scratch/t770…t776`／`.scratch/t777` 写产物。这是**指挥链指定的命令自身的副作用**，不是本席顺手改；
     那 7 个件**未提交**（不在本席写集里），交收口席统一处置。
   - 批目录落在 `.scratch/t873-公共层/批/`（而不是 `.scratch/t873-公共层/` 本身）：`t778-验收墙.mjs`
