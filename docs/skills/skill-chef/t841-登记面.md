## 四、端到端真跑：快照那几行真打得到命令

- **第 2 段 · 唤醒词层 46 条**：`routeWakeword(词, ctx)` 的产物拿去起真命令，exit 0 的 29 条／exit 4 的 17 条，
  **不符 0 条**——槽位名与 run 读的没有走散。

⚠️ **这一段当场抓到一条真缺陷（已修）**：`筛选时间` 表里声明 `needs: ['time_max']`，而
`chef.recipe.search` 原先**不认** `time_max`：`search/run.ts` 里那条「一个维度都没给」的预检只点名
`FILTER_KEYS`（不含别名键），而 `time_max`→`maxTime` 的归一写在预检**之后** ⇒ 只给 `time_max` 会被判成
「没给过滤条件」exit 2，那两行归一成了走不到的死代码（t767 §二把它记为「可收 `maxTime`／`time_max`／`time`」，
实际只收 `maxTime`）。**修法**：别名键与 `FILTER_KEYS` 一起参与预检（归一换算仍只住一处）。
修后实测 `time_max=30` → `exit 0 kind=filter:maxTime`（原为 exit 2）；`maxTime`／`time` 两个写法同样绿。
