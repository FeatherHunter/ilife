四道题

Q1

那个「反复读」的口子，最终由谁带参数？

前因后果：票面「完成的样子」自己写着「缺省态行为不变（仍然落一份新产物）」；但同一句 help 无论读几次都走缺省 ⇒ 参数永远没人传，目录永远在涨。这两条互相抵消，必须你裁一个。

还有一条现行约束：packages/skill-calorie/SKILL.md:190 今天逐字写着「别再给它加参数——缺省就是目的地交付物」；地图 #208 判定口径①也是「说一句 help 就该拿到那一份产物」。

  • 推荐A · 单加口子，缺省仍落新的

    四家都接 reuseHours（与大厨逐字同形），谁想停谁带参数。

    不推翻任何已定口径；票面「缺省态行为不变」这条验收标准原样成立；风险最小。

    目录今天照涨，只有调用方主动带参数才停——所以必须同时把用法写进各技能 SKILL.md，否则等于没修。

  • B缺省就在窗口内复用

    五家缺省自带窗口（如 24h）：同一主体一天内返回同一份，当天第一次落、之后复用。

    目录立刻停涨，不用谁记得传参；这才是「1 天内直接返回一份」的字面读法。

    要推翻地图 #208 口径①与 calorie SKILL.md:190 那句；「说一句 help 拿到新产物」的用户可见行为改变。

  • CB 的变体：缺省窗口＋「要看最新」才落新

    与 B 同，但显式给 reuseHours:0 之类即强制落最新的一份。

    兼顾「日常不涨目录」与「内容更新后能拿到最新」。

    要多定一个「怎么要求最新」的语法；语义比 B 多一层，说明面也更长。

我的建议：A ＋ 补说明面——issue 票面自己写的验收标准就是「缺省行为不变」，A 是唯一既让能力就位、又不推翻已定口径的路；再把「反复读带 --params '{"reuseHours":24}'，不涨目录」写进各技能 SKILL.md。
若你更想要 B／C：请直接说，我会把票面那条验收标准一并改掉，并在正文写明这是对 #208 口径①的裁决。

Q2

接哪几条路？

前因后果：每个 HELP 命令都不止一条落盘路——缺省 HELP 文件、mode:"lookup" 速查表、卡路里的速查台（mode:"file"，约 1 MB）、以及 --output／--html 逐字落点。大厨现状是只有缺省的 HELP 文件那一路带窗口。

  • 推荐甲 · 只接缺省 HELP 文件那一路

    四家与大厨逐字对齐：q 现找不落盘照旧，mode:"lookup" 速查表支不带窗口。

    五家一个口径；改动最小；不碰任何「扩大范围」的既有产物。

    速查表／速查台反复读仍会涨（若它们也在反复读，下一票再收）。

  • 乙所有缺省落盘路都接

    连 mode:"lookup"／mode:"file" 速查表也带同一窗口。

    目录压力一次清干净。

    动了生产上已上线产物的既有行为，超出票面「其余四家接上」的最小范围。

  • 丙连 --output／--html 也带

    用户逐字指定的落点也参与复用。

    —

    不可行：逐字落点是「用户说什么就落哪」，共用件本身也禁止 file ＋ reuse 同给（EINVAL）。

我的建议：甲——与大厨先行件逐字同形，五家一个口径；速查表要不要也接属「扩大范围」，等你点头再动。

Q4

「反复读」到底是谁在读？（影响我怎么验收）

前因后果：票面已实测否定了插件／面板这条怀疑路（六个 packages/plugin-*/src 里 help 字样命中数为 0）。真正在读的是「技能侧命令调用本身」，但「反复」的粒度你还没说过。

  • 甲同一会话里把 help 敲两遍

    窗口内应返回同一份。

  • 乙不同会话／不同天重复读

    同一天（或窗口内）仍应只留一份。

  • 丙插件／面板会读

    票面已实测否定。

我的建议：按甲＋乙理解——不论谁读第二遍，同一主体在窗口内返回同一份。验收我会两条一起测：① 连读 N 次目录文件数不增；② 窗口过期或内容真变更后仍会落新的一份（不会假装已是最新）。
