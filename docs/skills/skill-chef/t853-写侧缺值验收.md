## 三、本轮修掉的缺陷（R6）

**现象**：`chef.history.record` 的 `rating` 传空串 ⇒ `exit 2`、stderr 写「缺槽位」；同一个场景把 `rating` 整个不传 ⇒ `exit 4`、点名 `rating`。同一件事两个定义地，且空串那条不符合 #853 的对外契约（缺评分属取数失败档）。

**根因**：顶层 `runHistoryRecord` 把空串直接喂给口径校验 `validateRating`（它只认数字）⇒ `POLICY_BAD_RATING` ⇒ `exit 2`；而数据层 `recordHistory` 本来就认空串为缺值。两层对「空串」的判定不一致。

**改法**（`packages/skill-chef/src/history/run-record.ts`）：两处把空串／纯空白按「没给」归一——顶层把它读作 `null` 交给数据层统一点名，数据层把非数字串并入「缺评分」同一句。

**变异自证**（改坏必须变红、改回必须变绿）：

```text
变异态（去掉 blank 归一）  exit=9  R6：期望 4 实得 0 红 ｜ 行数变化 recipe_history  ← 真的落了一条没评分的脏数据
还原态                      exit=0  判据汇总：绿 15 ／ 红 0
```
