Q1

边界：Q4“本次不改 schema”还是不是铁律？

为什么先问它：若铁律还在，丙选项（把三列改成可空并迁移老库）本轮只能“立票出图”，不能当场做；若松动，整个裁定走向全变。

A · 还是铁律（推荐）丙只能当场立 schema 票，本票只在甲 / 乙 / 分列里选。
B · 可以松动本票直接裁“改三列为可空并迁移老库”。
➡️ 推荐 A
818 与 #773/#774/#775 正文都写了“不改 schema”，推翻会掀翻四张纵向票的前提；真要改也该走“立票出图”的口子。
选 A · 利
  • 纵向票前提不塌，可继续并行
  • 风险最小，不碰老库文件
选 A · 弊
  • “未填”只能用替代值或改必填，将就
选 B · 利
  • 最干净，“未填”如实存可空
选 B · 弊

Q2

粗细程度：一刀切还是按列分别裁？

为什么问它：评分的“未填”和用量/时长的“未填”语义完全不同 —— 0 分是合法评分，0 数量 / 0 分钟也有歧义。一刀切很可能带偏某一列。

A · 按列分别裁（推荐，丁）quantity / duration_minutes / rating 各自独立选甲或乙。
B · 必须统一三列同选甲或同选乙。
➡️ 推荐 A
三列的查询侧用法不同：rating 要进 AVG 聚合，quantity/duration 只进显示。分开裁才能给 rating 更严的口子。
选 A · 利
  • 每列按真实语义给最合适的落法
  • 统计污染可逐列隔离
选 A · 弊
  • 要定三遍，讨论多一轮
选 B · 利
  • 一次定完，最省事
选 B · 弊
  • rating 极易被带偏：0 分 vs 未填撞车
Q3

方向：接不接受“未填替代值”这个谈法？

为什么问它：乙的本质是“库里存特殊值代表没填，查询侧/统计侧认出它并剔除或换显示”，而不是存 NULL。本轮只确认方向，具体存几、AVG 剔不剔、页面显示什么留到下一轮逐列烤。

A · 接受方向（推荐）进入下一轮逐列定具体值（存什么 / 谁来剔 / 显示什么）。
B · 不接受乙直接出局，只在“页面改必填 vs 改 schema”里选。
➡️ 推荐 A
不接受乙就只剩“全改必填”（体验倒退）或“改 schema”（掀 Q4）。先留着乙谈具体值，谈不拢再毙掉也不迟。
选 A · 利
  • 卡面“选填”不用全改必填
  • 不碰 schema，边界内可解
选 A · 弊
  • 替代值会污染直接聚合，必须写进口径
  • 逐列定值多一轮讨论
选 B · 利
  • 口径最简单，无污染风险
选 B · 弊
  • 9 张卡的“选填”全改“必填”，用户多填 3 个数
