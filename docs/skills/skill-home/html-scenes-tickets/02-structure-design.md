## 目标

产出契约文档，**先报用户点头再动**：

① **形状**：8 个能力目录名（取自 HELP 一级分组：`items`／`space`／`outfit`／`stats`／`express`／`receipt`／`family`／`setup`；`link` 只留登记位、不建目录）＋每个能力的标准件（照卡路里：`index.ts` 能力门／`commands.ts`／`routes.ts`／`pages/<页族>.ts`）。
② **产物命名**（给票 4 与票 7 的硬约束）：老实现是「模板 → 一个中文名」的 1:1（`scripts/render/__init__.py:130-147`），`物品/receipt.html` 与 `物品/add_form.html` 各承担 4 条场景 ⇒ 照它落盘**会互相覆盖**。三选一，各给利弊与至少三个真实例子：(a) `<命令中文名>_<场景 id>_<戳>.html`；(b) `<唤醒词>_<戳>.html`（推荐——与老规范形态最像、人一眼看出是哪个场景；SM3-4「带物品/归物品」按老技能综合名取 `出行清单`）；(c) `<命令中文名>_<唤醒词>_<戳>.html`。
③ **页族归属表**：46 个页族 ↔ 70 条场景的对应（票 1 册子 `pages-ledger.md` 表一已给出族与场景，本票定「一族一个装配件」的落法）。
④ **域内写集**：同域多张票（items 三张、receipt 两张）靠**页族文件**天然不相交——页族落 `templates/<域>/<族>.html` 与 `src/<域>/pages/<族>.ts`，一票只写自己那几族。
⑤ **共用位所有权**：`src/render/**` 共用件、`package.json`、`SKILL.md`、派生件归票 3（唯一写者）；域票一律不碰。
⑥ **锁上限**：跑 `tooling/run-locked.mjs` 一律带 `--max-wait-ms 600000`（协议规定最多 10 分钟、不无限等；实测默认值 0＝无限等，现场最长等待 23.2 分钟）。
⑦ **页族解析规则（覆盖审计补进来的头号洞）**：今天 `src/render/templates.ts:33-58` 是「**一个命令 key → 一个模板**」的 1:1 映射，而本图要的是 **46 个页族**——一个 key 底下挂多条场景（例如 `home.item.update` 同时覆盖 移物品/数量变更/状态变更/标物品/改物品/合并物品/撤销操作/物品关联/管照片）**一个模板表达不了**。契约必须定死解析口径：**由 `(key, preset/场景) → 页族**」两层决定；并附一张**兼容词并入表**（老 `SKILL.md` 唤醒词索引表 `:122-216` 已给出）：`补物品/减物品/废物品/借物品/修物品` → 物品 receipt 族、`盘物品/盘全部` → 盘点族、`查高频` → 总览族、`查低频` → 闲置族、`看标签/合标签` → 标签管理族、`推位置/找位置` → 位置管理族、`改购物清单` → 购物清单族、三条 `(HTML)` 同族。**这张表决定 91 条唤醒词逐条能不能落到页上**，不许留空。
