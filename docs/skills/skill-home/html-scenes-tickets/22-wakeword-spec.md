## Question

唤醒词层今天**没有规格**，两个方向同时漏（本票开工前实测，逐条对账）：

| 方向 | 条数 | 事实 |
|---|---|---|
| 有场景、路由表里没有 | **3** | 联动总览／记到卡路里／记到记账 ⇒ 已裁「不做」✓ 一致 |
| **有路由、没有任何场景规格** | **20** | 居家管家 帮助×3、`(HTML)`×3、补物品、减物品、废物品、借物品、修物品、盘物品、盘全部、查高频、查低频、看标签、合标签、推位置、找位置、改购物清单——**没有 prompt、没有 `type`、没有页面归属、HELP 里查不到、验收墙没有格**：没有任何口径能判它对不对 |
| **yaml 写明的变体、路由表一条都不认** | **42** | `帮我记一下`（录物品）、`数数这里`（盘点）、`钥匙固定放哪来着`（固定位）…；且 HELP 生成器**显式跳过 `variants:` 子树**（`packages/skill-home/AGENTS.md` 立规、`scripts/lib/yaml-subset.mjs` 不收），所以两头都没有它 |

根因（第一性原理）：**唤醒词是场景的入口，不是命令的别名**。一个词的价值 ＝ 它指向那条场景的规格（prompt／期望结果／页面／验收）；词与场景脱钩，它就既不可验收、也不该存在。

## 目标

产出一份**唤醒词层规格**（`docs/skills/skill-home/wakeword-spec.md`），**先报用户点头再动**：

① **四分类原则**：每条词必须**恰好**属于 {某场景的主词 ／ 某场景的变体 ／ 技能级入口（HELP） ／ 废弃} 之一——不允许第五类「三不管」。并定死三条互推关系：`scenarios.yaml` 的主词 ＋ 变体 ↔ `WAKE_TABLE` ↔ `DEPRECATED_PHRASES`。
② **20 条无场景词逐条归宿**（每条给依据，老 `SKILL.md:122-216` 的 T5 裁决可作旁证）：变体并入宿主场景（推荐多数走这条，例如 `补物品/减物品` → 3-3 数量变更、`废物品/借物品/修物品` → 3-4 状态变更、`盘物品/盘全部` → 6-1 盘点、`查高频` → SM4-1、`查低频` → SM4-2、`看标签/合标签` → 4-1、`推位置/找位置` → SM2-1、`改购物清单` → SM5-1）／登记为废弃（三条 `(HTML)` 若裁定「默认已全量落 HTML，兼容词无意义」）／确有必要才新增场景（**默认不新增**）。
③ **42 条变体的识别口径二选一**：(a) **确定性路由也认**——把变体编进 `WAKE_TABLE`（或让 `routeWakeword` 直读内容资产），用户说什么都能命中；(b) **只由 AI 识别**——则在 `SKILL.md` 与 HELP 口径区写明边界，并**把 42 条变体从内容资产里去掉或标注为「非路由」**，不让它继续当孤儿。两条各自的代价要写清（(a) 要防最长匹配误伤、要重跑 HELP 生成链与摘要锁；(b) 减少识别面但口径诚实）。
④ **UI 面口径**：变体与无场景词在 HELP 与链路总览页里**不占新格**，只作宿主场景的别名附注（这条同时定死地图里那条悬着的雾）。
⑤ **机器门规格**（交给落地票）：四分类检查 ＋ 三向对账 ＋ 「每条词 → 场景 → 命令 key → 页族」逐行对照表，接进包内 test 门，漏一条即红。
