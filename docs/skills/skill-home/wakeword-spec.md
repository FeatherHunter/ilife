## 四分类原则

每条唤醒词必须恰好属于以下四类之一，不允许第五类「三不管」：

1. 某场景的主词：场景清单里登记的规范唤醒词，一词对一条场景。
2. 某场景的变体：口语／同义／模糊说法，挂靠唯一宿主场景，不独立成场景。
3. 技能级入口：HELP 入口词（居家管家 帮助／居家管家帮助／居家管家能做什么），不进任何业务场景。
4. 废弃：兼容词与已停用词（`查物品(HTML)`／`看物品(HTML)`／`统物品(HTML)`、联动总览／记到卡路里／记到记账），只留登记位，不路由、不建目录。

三条互推关系定死：场景清单的主词加变体 ↔ 确定性路由表 ↔ 废弃表。三表对不上即红，不许任何一表私自增删。

判定流程：先查废弃表（命中即按废弃处理）→ 再查路由表（命中即进对应场景）→ 两表皆无 → 该词为新生词，必须补分类后才能用，不许裸奔上线。

## 20 条无场景词归宿

有路由、无场景规格的 20 条，按三桶归宿（场景号沿用场景清单）：

无争议并入宿主场景：`补物品／减物品` → 3-3 数量变更；`废物品／借物品／修物品` → 3-4 状态变更；`盘物品／盘全部` → 6-1 盘点。

待裁决废弃：`查物品(HTML)／看物品(HTML)／统物品(HTML)`。裁决条件：默认已全量落 HTML 成立则登记废弃；若任一场景仍需兼容入口，改判为该场景变体并写明理由。

单审（跨命名空间等价存疑，不默认等价）：`查高频` → SM4-1、`查低频` → SM4-2、`看标签／合标签` → 4-1、`推位置／找位置` → SM2-1、`改购物清单` → SM5-1。实施时逐条复核宿主场景的 prompt 与期望结果真能接住该词，接不住则退回重裁，不许硬凑。

技能级入口：`居家管家 帮助／居家管家帮助／居家管家能做什么` → HELP，不进业务场景。

默认不新增场景：新说法先找宿主，确有必要才立新场景，立项另走票。

## 42 条变体分层口径

内容资产事实源中共 42 条变体（已逐条数过），不搞「全进表／全不进」二选一，按一条标准分层：

无槽位也能唯一命中的，才进确定性路由。正例：`帮我记一下`（动作明确、无需上下文即可定到录入）、`数数这里`（盘点意图唯一）。进表后受最长匹配约束，必须配回归用例防短词被长词吃掉。

含指代／省略／模糊的，只由 AI 识别，不进路由表。正例：`钥匙固定放哪来着`（含指代与回忆）、`那个啥在哪`、`我之前放哪了`。这类变体必须从内容资产的路由口径里移出或明确标注为「非路由」，不许继续当两头不认的孤儿。

边界文案：在技能说明与 HELP 口径区写明「规范词走确定性路由、口语变体走 AI 理解」，用户照着 HELP 说必中，随口说由 AI 兜底。

## UI 别名展示规则

变体与无场景词在 HELP 与链路总览页里不占新格，只作宿主场景的别名附注（行内或格内附注，不新增行列与页面）。

防臃肿：单场景别名附注超过上限折叠，上限数值由链路总览页实施票定，本规格只要求有上限、有折叠。

## 机器门规格

两层划分，本规格定死的层与待回填的层分开：

本规格定死：四分类检查（出现三不管即红）＋三向对账（场景主词加变体 ↔ 路由表 ↔ 废弃表，任一方向对不上即红）＋逐行对照表（每条词 → 场景 → 命令 → 页族，一行不落，缺行即红）。全部接进包内测试门，改内容资产后同批重跑 HELP 生成链并更新摘要锁，附「改坏一句即红」的负向证据。

待回填：对照表的页族列引用场景页契约的族表，契约落地后回填；回填前该列允许标「待契约」，不算红。

## 给下游票的硬约束

只给判据一句话加正反例各一行，不写全量参数：

路由与内容资产实施：`补物品 → 3-3 数量变更，正例命中数量变更，反例不得新建物品`；变体进表必须同步配最长匹配回归用例。

链路总览页实施：`盘全部 → 6-1 盘点行别名附注，正例出现在盘点行，反例不得另起一行`。

技能说明面：`改购物清单 → 归宿以单审结论为准，正例链路可复述，反例不得写死等价结论`。

## 不做

联动三词（联动总览／记到卡路里／记到记账）已裁不做，本规格不收。默认不新增场景。HELP 模板本身不动。页族解析、路由实施、链路页样式归各自下游票，本规格只给约束接口。
