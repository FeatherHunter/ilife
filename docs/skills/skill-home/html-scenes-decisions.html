一 · 交付什么

Q1

页面册子怎么切

粒度

前因：你要「所有唤醒词的对应 HTML 都开发完毕」＋「每个功能域下面的场景都开发好」。而现在 21 个骨架页服务 73 条场景，等于同一张页换数据；老技能对同样这批场景有 49 个真页面（照片墙、撤销选择、搬家清单、盘点差异、首次使用向导、健康报告、衣橱分析这些都有）。

Q9

命令默认要不要落 HTML

链路

前因：你需求 2 写的链路是「prompt → 唤醒词 → 命令 → HTML 绝对路径」。新技能默认只吐 JSON，这一跳要人工补参数，链路等于没通。命名与落盘的共用件 #183 已经做好（`base-paint/save-html`），复用不新造。

Q10

老技能自己不出页面的 13 条，补不补

范围

前因：老技能票据凭证域的 11 条写类场景（登记购买记录、登记保修、记录维修、设置保养周期、执行保养、登记证件、证件归档、更新证件、存账号、改账号等）只打 JSON 回执、不渲染页面；家庭协作那 2 条只在带 `--output` 时才落 HTML。而你要的是「所有唤醒词都有 HTML」。

二 · 怎么建

Q2

解耦范围：整包按 9 个域重排吗

架构

前因：你说「代码架构需要解耦，可以参考新卡路里的架构设计」。卡路里第一层是 src/<能力>/，每个能力有 commands.ts（命令声明）＋ routes.ts（路由）＋装配件。仓规 docs/agents/structure.md 铁律四：能力目录名取自 HELP 一级分组 —— 对居家就是那 9 个域（物品管理、空间与位置、穿搭出行、统计总览、快递购物、票据凭证、家庭协作、开始使用、联动）。现在 73 条场景要落地，却没有一个域目录可放。

Q4

页面数据从哪来

数据

前因：验收墙上每一格都是可点的真页面，所以先要定：页面上显示的数据，是跑真命令链取出来的，还是直接拼一份样例数据塞进模板。

Q5

产物落点与那条链路总览页

落点

前因：你要「输出在一个 HTML 中，点里面那个绝对产物路径就能跳转打开」。老规范是 <数据根>/home_manager_html/<命令中文名>_<时间戳>.html。另外实测一条硬约束：本机视觉工具只接受工作区内的文件（拿生产目录的文件直接渲染会被拒），而仓规要求验收墙与产物放在同一个目录。

Q6

验收墙怎么摆、分数怎么算

验收

前因：仓规 docs/agents/视觉验收墙.md 要求双端各出墙（手机 390 宽、桌面 1280 宽），每格一件真产物，格数要和清单对得上；同时又提醒「几十格是舒适区」，格数多了要按页族拆。你的要求是最后用视觉审查打分，100 分制下要到 90 分。
