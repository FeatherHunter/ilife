## 结论（用户 2026-09-21 已确认：全部按推荐）

目标：五节保留，但改「接口声明」粒度——四分类定义 ＋ 20 条归宿附表 ＋ 42 条分层口径 ＋ UI 别名展示规则（只定上限与折叠，不定样式） ＋ 机器门两层划分（本票定死的 ／ 待票 2 回填页族列的）。

边界：本票只出规格，不动源码；给票 3／票 2／票 7 的硬约束写到「判据一句话 ＋ 正反例各一行」，不写全量参数表。例：`补物品 → 3-3 数量变更，正例命中 qty，反例不得新建物品`。

风险（用户视角）：(a)最长匹配误伤 ＞ (b)口径不诚实 ＞ (c)HELP 链断裂。止血线：(a)最长匹配回归用例必须进机器门；(b)变体要么进表、要么标非路由，不许第三态；(c)维持生成器 ＋ 摘要锁。

选项权衡：20 条不默认全并入，分三桶——无争议并入（补／减／废／借／修／盘系）／待裁决（3 条 `(HTML)`，若「默认全量落 HTML」成立则废弃）／单审（查高频／查低频／看标签／改购物清单等跨命名空间等价存疑项）；默认不新增场景保留。42 条推翻 (a)/(b) 二选一，改分层——无槽位也能唯一命中的才进确定性路由（如 `帮我记一下`），含指代／省略／模糊的留给 AI（如 `钥匙固定放哪来着`），后者移出资产或标「非路由」。

决策：UI 不占新格、只作宿主别名附注；单场景别名超 N 条折叠（N 由票 7 定）。机器门：四分类检查 ＋ 三向对账（yaml 主词＋变体 ↔ WAKE_TABLE ↔ DEPRECATED） ＋ 「词 → 场景 → 命令 → 页族」对照表，其中页族列待票 2 回填。
