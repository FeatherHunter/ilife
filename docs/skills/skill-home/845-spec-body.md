## Problem Statement

用户对居家管家说一个唤醒词时，心里预期是“我这句话会进到某个场景里办成事”。但今天唤醒词层没有规格：有路由却没有任何场景规格的词（补物品、盘全部、查高频、改购物清单等）没有 prompt、没有类型归属、在 HELP 里查不到；内容资产里写明的 42 条口语变体，确定性路由一条都不认。从用户视角看，词一旦说出口，能不能命中、命中到哪，全是运气。

## Solution

出一份唤醒词层规格文档（五节，接口声明粒度），给每个词恰好一个归宿：某场景的主词、某场景的变体、技能级入口（HELP）、废弃，不许有第五类。20 条无场景词逐条归宿（三桶）；42 条变体按“无槽位也能唯一命中才进确定性路由”分层，其余留给 AI 理解并标为非路由；HELP 与链路总览页只作别名附注、不占新格；机器门分两层（本规格定死的检查＋待页族解析回填的对照列）。用户说什么，规格都能回答它去哪。

## User Stories

1. As a 居家管家用户, I want 说“补物品”进数量变更场景, so that 我补货的数量记到同一件物品上而不是新建一条
2. As a 居家管家用户, I want 说“减物品”进数量变更场景, so that 消耗掉的数量如实扣减
3. As a 居家管家用户, I want 说“废物品 / 借物品 / 修物品”进状态变更场景, so that 物品的报废、外借、维修状态有处可记
4. As a 居家管家用户, I want 说“盘物品 / 盘全部”进盘点场景, so that 随手发起的盘点有人接
5. As a 居家管家用户, I want 说“查高频 / 查低频”进统计场景, so that 常用和闲置的东西各有去处可查
6. As a 居家管家用户, I want 说“看标签 / 合标签”进标签场景, so that 标签的查与合并不断链
7. As a 居家管家用户, I want 说“推位置 / 找位置”进位置管理场景, so that 放哪和找哪问得出口
8. As a 居家管家用户, I want 说“改购物清单”有明确归宿且不等价硬凑, so that 改清单不会悄悄跑错场景
9. As a 居家管家用户, I want 用口语说“帮我记一下”也能录入, so that 不用背规范词
10. As a 居家管家用户, I want 含指代的说法（如钥匙固定放哪来着）由 AI 理解而不是路由表硬匹配, so that 话说得含糊时也不会被最长匹配误伤
11. As a 居家管家用户, I want HELP 里列出的每个词都是真能命中的, so that 帮助不撒谎
12. As a 居家管家用户, I want 在链路总览页看到变体只作宿主场景的别名附注, so that 页面不被别名淹没也能找到说法
13. As a 居家管家用户, I want 废弃词（兼容词与已停用的联动词）的行为是明确的, so that 说了旧词知道会发生什么而不是没反应
14. As a 技能维护者, I want 四分类检查接进包内测试门, so that 新增一个词而忘给归宿时机器变红
15. As a 技能维护者, I want 三向对账（场景主词加变体 ↔ 路由表 ↔ 废弃表）自动跑, so that 两头不认的孤儿词一出现就被发现
16. As a 技能维护者, I want “词 → 场景 → 命令 → 页族”逐行对照表, so that 漏一行即知
17. As a 技能维护者, I want 最长匹配回归用例在门里, so that 变体进表后短词不被长词吃掉
18. As a 路由实施者, I want 规格只给判据一句话加正反例, so that 按约束实施而不被规格抢做参数设计
19. As a 页族解析者, I want 对照表的页族列留好回填接口, so that 页族结论出来即填、不返工
20. As a 链路页实施者, I want 别名展示规则只有上限与折叠, so that 样式自主但不臃肿
21. As a 验收者, I want 规格文档章节数检查加用户点头原话, so that 交没交货一判即知
22. As a 技能维护者, I want 默认不新增场景写进规格, so that 新说法先找宿主、确有必要才立新场景

## Implementation Decisions

- 交付物是唤醒词层规格文档本身（五节，接口声明粒度）：四分类定义、20 条归宿附表、42 条分层口径、UI 别名展示规则、机器门两层划分。本规格只到判据为止，不写实现。
- 四分类：每个词恰好属于其一——某场景的主词、某场景的变体、技能级入口、废弃；互推关系定死（场景主词加变体 ↔ 路由表 ↔ 废弃表）。
- 20 条走三桶：无争议并入宿主场景、兼容词待裁决废弃、跨命名空间等价存疑项单审；默认不新增场景。
- 42 条走分层（替代二选一）：无槽位也能唯一命中的才进确定性路由，其余只由 AI 识别并标为非路由；判定标准只有这一条。
- 风险排序按用户视角：最长匹配误伤 ＞ 口径不诚实 ＞ HELP 链断裂，各配止血线（回归用例进门、不许第三态、维持生成器加摘要锁）。
- 下游约束只到“判据一句话加正反例各一行”，分别链给路由实施、页族解析、链路页三方。
- 测试缝（seam）只用一个既有最高缝：唤醒词路由函数（文本加槽位上下文 → 命令与参数），分类检查与回归用例全走它；不新增路由，不直读内容资产；文档章节数走验收命令，不进测试门。
- 本规格不改任何源码：不改场景清单、不改路由表、不碰生产库。

## Testing Decisions

- 好测试只测外部行为（词进到哪个场景、带出哪条命令），不测内部实现（匹配算法细节、生成器实现）。
- 测三样：路由函数的命中与缺槽位报错、四分类与三向对账的门、逐行对照表的完整性。
- 先例：内容资产的摘要锁加形状加双向对账测试、HELP 构建校验、既有内容对账报告的逐条对账法。
- 文档验收走章节数检查（章节数不少于五）加用户点头原话，与代码门分开。

## Out of Scope

- 不改路由表、内容资产与任何源码；不碰生产库与生产产物。
- 页族解析本身、路由实施本身、链路页样式本身归各自下游票，本规格只给约束接口。
- 默认不新增场景；确需新增另立票。
- 已停用的联动词不做；HELP 模板本身不动。

## Further Notes

- 源自 grilling 结论（用户已确认全部按推荐），风险排序取用户视角而非验收视角。
- 同图的路由清理与命令面裁定各自独立，本规格只消费它们的结论、不替它们决定。
