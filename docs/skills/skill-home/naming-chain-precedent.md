# 命名纪律 ＋ 链路四段呈现 ＋ 老原型借鉴（规格单 #859 实施）

本规格一次锁三条规则：**命名纪律**（运行期只说什么词）、**链路四段呈现**（prompt → 唤醒词 → 命令 → HTML 绝对路径各落在哪一面）、**老原型借鉴**（域票从老技能已进货的资产起步）。
三条规则各自配一道机器门，门不过即红，不许靠记忆或口碑维持。

维护者 2026-09-21 逐条点头，四条口径：① 字母码不得出现在产物文件名（取代段去掉）；② 交付物＝文档 ＋ 机器门 ＋ 代码清理一起落；③ 「词 → 命令」对照行落在速查面，HELP 页不塞新表；④ 仓库外原型登记进册子即算进货，不复制进仓。

## 一 · 命名纪律

**运行期只认三条词表**：命令键（`home.item.update`）、面向用户的命令中文名（`移物品`）、页族名（`receipt`）。读代码不需要查表，就是这条的意思。

**字母码（`1-1`、`SM2-3` 这类场景 id）只许住在两个地方**：

- 事实源：`packages/skill-home/src/help/scenarios.yaml`（老骨架逐字节副本，id 是稳定主键，不许改）。
- 机器附录：`docs/skills/skill-home/scene-pages-contract.appendix.json`（70 场景一表，机器消费）。

其余任何位置——标识符、运行期值、注释、测试、脚本、**产物文件名**——都不许出现。

**跨面引用改用 `(命令键, 预设)` 这对句柄**。契约已写死「一个（命令，预设）只到一个页族」，所以它是场景的唯一句柄，且完全落在上面的词表里；用它比用 id 更贴着路由真值。页面装配件的 `PAGE_META` 声明自己服务哪些场景时，用的就是这张对表。

**溯源注**是唯一豁免：注释行里**先写中文场景名、再附字母码**（`借用管理（SM7-1）`）。机器门按「码前面同一行里必须有中文」这一条判，形状不对即红。

**产物文件名**只有一种算法，唯一实施点在 `packages/skill-home/src/render/sceneNaming.ts` 的 `resolveSceneStem(key, 预设)`：

```
<命令中文名>_<戳>.html        例：管位置_20260922_150222.html、查快递_20260922_150225.html
```

- 命令中文名取场景清单 `html.command_cn`；戳取落盘时刻（同场景并发不互盖）。
- 名字主体就是命令中文名本身（不再拼场景 id）：说「查快递」→ 落盘 `查快递_<戳>.html`，词、命令、文件名同一套词，用户对号不用查表。
- 非法字符清洗与老技能同法：`\ / : * ? " < > |` 与首尾空格替换为 `_`。
- **唯一性靠门兜底**：70 行的命令中文名两两不重；重了即红（fail-closed，绝不静默互盖）。名字与场景的对应关系在链路总览页与墙的清单里逐行可查，不靠文件名反解。

## 二 · 链路四段呈现

一句话怎么长成一份页面：**prompt → 唤醒词 → 命令 → HTML 绝对路径**。四段分落在两面，两面各由一件生成器产出、各带一道门。

| 段 | 落在哪一面 | 守它的门 |
| --- | --- | --- |
| prompt | HELP 页的场景条（`title` ＋ `prompt_template`）；链路总览页 prompt 列 | 内容资产摘要锁 ＋ 形状检查（`test/help-assets.test.mjs`） |
| 唤醒词 | HELP 页场景条 `wake_word`（带「复制唤醒词」）；链路总览页唤醒词列 | 同上 ＋ 唤醒词三向对账（主词＋变体 ↔ 路由表 ↔ 废弃表） |
| 命令 | HELP 速查支（短语 → 命令键／命令行／一句话）；链路总览页命令列 | `test/wake-family-gates.test.mjs` 125 行对照 |
| HTML 绝对路径 | 链路总览页「绝对产物路径」列：文本 ＋ `file:///` 可点链接 ＋ 复制路径按钮 ＋ `<noscript>` 绝对路径兜底 | 生成器自检：缺件、字节对不上、行数对不上、含禁用串，一律 exit 1 并点名 |

- 总览页**不自己算文件名**，只从 `<产物目录>/manifest.json` 的 `file` 字段读——命名规则因此只有一处实现。
- 绝对路径与字节由生成当刻在盘上现算（`resolve(产物目录, file)`），换机／换检出目录重跑即对上。
- 速查支是「词 → 命令」这条中间链的落点；HELP 页与兄弟五家共用同一份场景 schema，不加路由字段。

## 三 · 老原型借鉴

**老技能是权威来源，只读参考，一行不改。** 它的设计资产先进货、再开工：

- 进货台账＝`docs/skills/skill-home/pages-ledger.md`：表一 49 行（yaml 引用的模板 → 70 场景的信息结构）＋ §三 ④ 18 行（legacy 平铺件）＋ **§六 仓库外原型附录**（10 份仓库外设计原型，含路径、字节、它是什么、新技能对位、可复跑证据）。
- **域票第一步是跑脚手架**（`packages/skill-home/scripts/new-scene-page.mjs`），照册子对应行落形状，不从白纸起；一族一装配（`templates/<域>/<族>.html` ＋ `src/<域>/pages/<族>.ts`）。
- **必需块是机器读的表**，不许手抄第二份：机器附录 `requiredBlocks` 按 46 族给四组（`fields`／`operations`／`empty`／`status`），判据件 `packages/skill-home/scripts/audit-page-blocks.mjs` 消费它做结构检查。
- **视觉 bar 由双端墙守**：手机 390 ＋ 桌面 1280 成对出，逐页留复核记录；墙生成器自检正例 exit 0、反例 exit 1 并点名；整批综合分 ≥90 由维护者终审。
- **仓库外发现的任何原型一律登记进册子 §六**——进货进的是「册子这条事实」，不是把过程稿搬进仓；判断一个文件是不是原型的口径：它是设计探索稿，不是渲染产物、审查报告或探针。

## 四 · 判据与验收

四条命令，各自 exit 0 才算这条规格被兑现：

```powershell
# ① 命名纪律（零越界 ＋ 70 行命令中文名两两不重）
node --test packages/skill-home/test/naming-discipline.test.mjs

# ② 契约与附录（含命名函数唯一稳定、真实例前缀）
node docs/skills/skill-home/check-scene-contract.mjs

# ③ 链路四段的行表与词到命令对照
node --test packages/skill-home/test/wake-family-gates.test.mjs

# ④ 墙与链路总览页的自检（正例 exit 0；把清单改坏即 exit 1 并点名）
node docs/skills/skill-home/gen-scene-wall.mjs --check <产物目录> <墙文件名>
node docs/skills/skill-home/gen-chain-page.mjs <产物目录>
```

## 五 · 不做

- 不动事实源 `scenarios.yaml` 的场景 id：它是稳定主键，且与老技能逐字节相同。
- 不动 HELP 场景 schema（共享层，六家同形）；不往 HELP 页另加路由表。
- 不把老技能本体或其原型复制进本仓：登记即进货。
- 不发版与装机（另立票）。
