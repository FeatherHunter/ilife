# base-entries 端口契约（#1200）

日期 2026-10-08；归属地图 #1197「爱生活全量中英双语」；本件是**接口冻结当刻**的契约正本，与实现同源（`packages/base-entries/src/`）。

读的人：迁移票（把显示文本搬进词条表）、#1202 试点（两处硬缝）、#1199 门禁改造（缺词条与 key 残留门）、后续真 ICU／MF2 后端。

## 1. 这一层干什么

| 件 | 干什么 | 不干什么 |
| --- | --- | --- |
| 词条表 `src/catalog.ts` | 定表形状；`MessageId` 从基准语言派生，拼错 key 编译期红 | 不管语言清单、不判语言合法性 |
| 取词 `src/resolve.ts` | 按 key 取词条；缺词条走回退链；全缺抛错 | 不求值、不格式化 |
| 求值 `src/evaluate.ts` | 可替换端口 ＋ 默认朴素实现（只认 `{name}`） | 不查表、不管回退 |
| 数字与日期 `src/format.ts` | 直接用运行时自带的 `Intl` | 不写语言分支、不硬编码任何语言的字面 |

零运行时依赖：`dependencies` 是 `{}`（门在 `tooling/check-boundaries.mjs`）。本包**不读文件、不 import 词条**——词条表是运行期数据，由调用方传进来。

## 2. 窄接口（包门 `src/index.ts`）

```ts
type MessageTable = Readonly<Record<string, string>>;
interface Catalog { readonly zh: MessageTable; readonly [language: string]: MessageTable }
const BASE_LANGUAGE = 'zh';
type MessageId<C extends Catalog> = keyof C['zh'] & string;
type MessageParams = Readonly<Record<string, string | number>>;

function defineCatalog<const C extends Catalog>(catalog: C): C;
function resolve<C extends Catalog>(
  catalog: C, language: string, id: MessageId<C>, params?: MessageParams,
  options?: { evaluate?: Evaluate },
): string;

interface EvaluateRequest { template: string; language: string; sourceLanguage: string; params?: MessageParams }
type Evaluate = (request: EvaluateRequest) => string;
function evaluate(request: EvaluateRequest): string;   // 默认后端

function formatNumber(language: string, value: number, options?: Intl.NumberFormatOptions): string;
function formatDate(language: string, value: Date | number, options?: Intl.DateTimeFormatOptions): string;

class EntriesError extends Error { readonly code: string }
class MissingMessageError extends EntriesError { readonly id: string; readonly languages: readonly string[] }
class MissingParamError extends EntriesError { readonly param: string; readonly template: string }
```

拼错 key 的防线在类型面：`MessageId<typeof catalog>` 是**字面量联合**，不是 `string`。落地读数在 `packages/base-entries/test-d/message-id.test-d.ts` 的 `@ts-expect-error`（被本包 solution 工程收进 `tsc -b`），以及测试里那条「去掉指令的副本必红」的变异读数。

## 3. 回退链

候选＝**请求语言 → 基准语言 zh → 终站 en**，按首次出现去重保序：

| 请求语言 | 链 |
| --- | --- |
| `zh` | zh → en |
| `en` | en → zh |
| `ja`（后续语言） | ja → zh → en |
| 表里没有的语言（如 `fr`） | fr（无表，跳过）→ zh → en |

- 链上哪一站有这条 key 就用哪一站，**先命中先得**。
- 链走完仍没有 → 「缺词条」策略：抛 `MissingMessageError`，带 `code`／`id`／`languages`。**不返回 undefined、不返回空串**（ADR-0004 §2）。
- 类型面 `MessageId` 从基准语言派生，正常路径到不了「全缺」这一格；但词条表是运行期数据（可来自外部文件、可被裁剪），运行期这一格仍必须显式抛错。
- `en` 是链的终站（宿主口径：缺词条回退终止于 en）；`zh` 是**基准语言**（表以它为准、`MessageId` 从它派生）。

**别把两个 zh 混成一个概念**：「基准语言 zh」（本包，词条表的权威语言）与「缺省语言 zh」（`packages/base-link-core/src/config/language.ts` 的 `DEFAULT_LANGUAGE`，语言选择的回退值）是两件事，只是值恰好相同。清单的唯一权威在 base-link-core，本包不复制。

## 4. 可换后端怎么接

端口形状：

```ts
interface EvaluateRequest {
  template: string;         // 已按回退链取到的那一条词条文本
  language: string;         // 调用方请求的语言（读者语言）：数字形态按它走
  sourceLanguage: string;   // 实际取到这条词条的语言：回退命中时与 language 不同
  params?: MessageParams;   // 插值参数；没有参数时这个键缺席
}
type Evaluate = (request: EvaluateRequest) => string;
```

接法（不改词条表、不改调用点，只多传一个参数）：

```ts
import { defineCatalog, resolve, formatNumber } from 'base-entries';

const catalog = defineCatalog({ zh: { 'calorie.total': 'ZH:{n}' }, en: { 'calorie.total': 'EN:{n}' } });

const myBackend = (request) => request.template.replaceAll('{n}', formatNumber(request.language, 3));
resolve(catalog, 'en', 'calorie.total', { n: 3 }, { evaluate: myBackend });
```

两种语言分开给，是为了让真 ICU 后端两件事都能做对：模板的复数／选择类别按 `sourceLanguage` 判（模板是用那门语言写的），数字等形态按 `language` 走（读者语言）。回退命中时两者不同——这也是调用方**唯一**能观察到「这条是回退来的」的地方。

默认后端（`evaluate`）的边界，本期**已知近似**，都在端口这一层可以替换掉：

- 只认 `{name}` 具名占位（name 首字符字母或下划线）；
- 缺参抛 `MissingParamError`，**不静默留空**；
- 其余花括号形态（`{0}` 位置参数、`{n, plural, ...}` 复数／选择）**原样留在文本里**，不报错也不替换。

MF2／真 ICU 的评估排在这条端口稳定之后（#1200 遗留出口）；届时换后端＝换一个函数，本层不动。

## 5. 加一门语言＝加一个词条文件

在本层落地成四句话：

1. **词条表的语言键就是语言**：`defineCatalog({ zh: {...}, en: {...}, ja: {...} })`——加一个键即可，不改代码、不改任何清单、不改任何门。
2. **key 集合以基准语言（zh）那份表为准**：`MessageId<typeof catalog>` 从它派生；新语言的表可以暂时空着或部分缺，缺的走回退链。
3. **新语言不需要接线**：它是链上第一站，后面自动接 zh → en；链序由本层算，调用方不传链。
4. **词条文件随包存放，命名空间＝包名**（ADR-0004 §3）：本层只吃「表对象」，词条文件放哪个目录、怎么切命名空间由各包在自己的迁移票里定——本层不读文件，故不对文件形状提要求。

## 6. 语言标识

- 本包对 `language` 只收 `string`，只做「去空白 ＋ 小写」这一条 **BCP 47 大小写不敏感**规范化（`EN`、` En ` 与 `en` 同形）。
- **可用语言清单不在这里**：唯一权威是 `packages/base-link-core/src/config/language.ts`（`AVAILABLE_LANGUAGES`／`DEFAULT_LANGUAGE`）。合法性判定（未识别的值报错并列出可用语言）归语言选择层；本层不复制清单、不代它判合法性——链上取不到表就跳过那一站。
- `formatNumber`／`formatDate` 直接把规范化后的标识交给 `Intl`；空串不是合法标识（「空串＝跟随调用方」由语言选择层先兜底），本层不代它兜底。

## 7. 判据面（门禁与迁移票读什么）

- 缺词条：`error instanceof MissingMessageError`／`error.code === 'ENTRIES_MISSING_MESSAGE'`，再看 `.id` 与 `.languages`。
- 缺参：`error.code === 'ENTRIES_MISSING_PARAM'`，再看 `.param`。
- **诊断文本不进词条表**：词条表只装显示文本；错误 message 是开发者面向的诊断串，门禁不许拿它的字面当判据（ADR-0004 §6：门只锁结构与行为）。
- 拼错 key／漏词条：类型面（`MessageId`），不是运行期门。

## 8. 未开的口（有意不给）

- **不返回「回退落点」这种二次返回**：要知落点就从端口看 `sourceLanguage`——端口是唯一观察点，取词口保持窄。
- **不做第二个取词口**（如 `lookup()`／`has()`）：等真有取用方再加，不预先设计。
- **不在本层读词条文件、不做目录扫描**：那会引运行时依赖；「从词条目录派生可用语言清单」是语言选择层的后续出口（#1198 遗留）。
- 格式化器缓存（语言＋选项，上限 64，超了整体清空）是 `format.ts` 的实现细节，不在端口上。
