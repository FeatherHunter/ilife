**为什么必须碰 `tooling/check-boundaries.mjs`（就地摆正）**：该脚本第 21–22 行原来是 `readdirSync(<link-core src>)` ＋ 逐个 `readFileSync`——`src/` 下一旦出现**子目录**（本票的 `config/`），`readFileSync` 读目录即抛错。机器读数：

```text
旧扁平写法命中：EISDIR（EISDIR: illegal operation on a directory, read）
```

即：不改它，本票一落盘 `pnpm boundaries`（CI 的一道门）就整道崩。改法＝改走本文件里**已有**的递归列 `.ts` 的 `walkSrc()`，并把它下面那处 `readdirSync`（装配原语扫描）也收成「只看文件」。

### 第二步 · 结构设计

```text
packages/base-link-core/src/
├─ index.ts        （改）包根出口：原有 4 面 ＋ config 面
├─ errors.ts       （改）＋ ConfigError（带 code 与 line）
└─ config/         （新）
   ├─ index.ts     能力门：对外 4 个值（configPaths／loadConfig／saveConfig／resetConfig）＋ 3 个类型 ＋ ConfigError
   ├─ dirs.ts      定位：resolveConfigDir／configPaths／ensureConfigDirs（门只放行 configPaths）
   ├─ yaml.ts      受限子集：parseConfigYaml／formatConfigYaml／assertConfigRecord／isConfigGroup ＋ 数据模型类型
   └─ store.ts     读写：loadConfig／saveConfig／resetConfig ＋ BACKUP_EXT ＋ LoadedConfig 类型
```

- **对外给几个**：能力门（`src/config/index.ts`）给 **4 个值**（`configPaths`／`loadConfig`／`saveConfig`／`resetConfig`）＋ `ConfigError`（经包根 errors 面）。里面厚厚的活（解析、校验、备份、建目录）一件都不出门。
- **共用件**：`yaml.ts` 与 `dirs.ts` 是这一小面的共用件，用它们的是 `store.ts`（两个都用）——都住本能力目录内，不出目录。
- **常量与类型唯一**：`CONFIG_DIR_ENV`／`CONFIG_FILE_EXT`／`DATA_DIR_NAME`／`BACKUP_EXT` 各只有一处定义；`ConfigRecord`／`ConfigGroup`／`ConfigValue` 只住 `yaml.ts`；错误码字面量只在抛出处写一次。
- **名称**：`dirs`／`yaml`／`store` 照本包既有按关注点分件的写法（`envelope`／`registry`／`runner`／`errors`），不自造工种名（无 `utils`／`helpers`／`common`）。
