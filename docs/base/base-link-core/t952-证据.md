## 八、对抗式自查（第一性原理；发现即记账，不自我豁免）

审查口径：不看「做完了没」，只看「声称的每一句，读数支持到哪一步」。四条发现：一条过程缺陷（已当场修复）、两条待维护者裁定、一条记账。

1. **过程缺陷（已修复，S1 候选，报请编排者裁定）**：第一次变异窗口（`4bcb360f`）释放锁时，源文件哈希与变异前一致，但**生成物没复位**——`dist` 仍带 M3 的变异、窗口末全仓重编 exit=1，而**窗口脚本没把内部失败传播成非 0**，包装器于是回了 `exit=0`（假绿退出）。违反 §2.5.2／§2.5.4「失败必须以干净工作区结束（**连带生成物**）」「不空不许报完成」。成因两条：`Copy-Item` 还原带回旧 mtime ⇒ `tsc -b` 判「源比产物旧」跳过重编；脚本只 `Write-Host` 不 `exit`。修复：还原后显式刷新源文件时间戳 ＋ 第二次窗口（`92525f81`）重跑三次红→绿 ＋ `bb7251de`（全仓重编 exit 0）＋ `4e752060`（55/55）。发现到复位在同一回合内，但复位前锁确曾带着不一致的 `dist` 释放过 ⇒ 按 §6.1 请编排者裁定是否具名记录（本席不得自行援引豁免）。
2. **技术缺口：声明类型比校验强（已按「最小改正」处理）**：原先 `EnvelopeDataByShape.resultset = { results: ResultsetItem[] }` 声明每项是对象，而 `assertShapeData` 只判 `results` 是数组——实测 `parseEnvelope` 接受 `{results:[42]}`／`{results:['x']}`／`{results:[null]}`。对照 `list.items: unknown[]` 的写法是**诚实**的（`unknown` 不承诺形状），`resultset` 不是 ⇒ 在 `parseEnvelope` 这个**不可信输入边界**上，类型给了不成立的保证。
   **处置（2026-09-25 裁定：只处理「确定必须处理」的一处，不扩散任务）**：删掉 `ResultsetItem`，类型收回到 `{ results: unknown[] }`——**校到哪一层，类型就承诺到哪一层**，与 `list.items` 同口径；项内五格与两种项形态由数据族在装配处定形（规格 §四 是正本，行表示法本就是规格留下的遗留出口）。
   **没有采纳**「加强校验到项级」：那是票面验收（只要求「缺 `results`／`results` 非数组被拒」）之外的新行为，属扩面，留待数据族实施票按规格自己定。判据：`tsc -b` 全仓 exit 0（`cff6cbbc`）＋ 判据件 183/183 绿（`266dbe86`）。
3. **渲染面行为放宽（已写进契约，判为有据而非缺陷）**：`strict: true` 现在放行 `resultset` 载荷，因为票面要求 `STRICT_ENVELOPE_SHAPES` 与正本逐字同步、`_T05` 又在类型层把两者钉成相等。已在契约 §3.1.1 补记「放行 ≠ 有渲染分支」；若要「渲染面整体拒绝结果集」，那是改契约校验语义的另一票。
4. **六家镜像漂移（未建票，理由待复核）**：本票让六家 CLI 各多一处「仍只认 6 形状」的潜在漂移，且无判据钉住。按 ISSUE 纪律这条**指得出读数**（每家 mirror 对 `resultset` 的接受与否可数），本可建票；未建的理由是「按家铺开的数据族票会动到这些镜像」。若该理由不成立，这就是一张该建没建的票。
