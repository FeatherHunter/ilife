## 一、这一票交的是什么（三件同一次交付，不是一个机制空转）

容忍机制要求的唯一信息是「**我们删过哪些键**」——这份信息**必须先于删除而存在**（否则删的那一刻老文件就哑），
而删完之后默认值表里**再无痕迹**能推出它。⇒ 机制、清单、**第一次真删键**必须同一次落地，否则白名单永远走不到。

- **公共层**（`packages/base-link-core/src/config/store.ts`）：`loadConfig`／`saveConfig`／`resetConfig` 多收一份
  「已退休键」叶子全路径清单（`readonly string[]`，可选参数；**没有新增对外类型**，`store.ts` 仍只导出 5 件）。
  命中的键**跳过校验、不进取值、不写回**；**整组退休 ⇒ 该组整层不写出**（空组写出去解析不回来）；
  清单自身非法 ⇒ **构造即拒**（`CONFIG_RETIRED_INVALID`）。
- **六家清单**：`packages/skill-bill/src/config.ts` 的非空（两个键），其余五家空清单（键与面板行随各自实施票）。
- **记账删键的连带**（同一次改动，缺一件即红）：
  - 技能侧：`help/helpFile.ts` 的 `HELP_FILE_STEM`、`help/helpPaths.ts` 的 `LOOKUP_FILE_STEM` 回**代码常量**；
    两个取值函数退场；`cli/cmd_read.ts` 的复用窗口清单改引常量（`HELP_REUSE_STEMS`）。
  - 插件侧：`packages/plugin-bill-ilife/src/settings.ts` 删两行（8 行 → 6 行）；
    用例 `test/config-surface-677.test.mjs` 三处跟上（行数 8→6、两处默认值断言改指常量与清单）。
    **为什么必须同批**：面板行表与技能默认值表**逐键同形**是既有用例锁死的不变式
    （`config-surface-677.test.mjs:71-74` 的 `flattenKeys(BILL_CONFIG_DEFAULTS)` 对齐），
    只删一边这条用例当场红。
