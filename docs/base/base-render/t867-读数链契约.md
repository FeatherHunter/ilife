# t867 · 读数链契约：四件读数的形状（判分引擎的输入面）

> 票：[#867](https://github.com/FeatherHunter/ilife/issues/867)（Part of [#820](https://github.com/FeatherHunter/ilife/issues/820) 任务清单序 25），承接 [#851](https://github.com/FeatherHunter/ilife/issues/851) 第 0 件。
> 这一份**只把既有形状写下来**，不新发明形状：四件读数里 `sep.json`／`resp.json`／`fmt.json` 由**三件既有 reader 产出**
> （票面「一行语义不动」），`facts.json` 由本票的装配器产出。
> 谁要改它们的语义，先改本件，再另开票——本件是这三件 reader 与判分引擎之间**唯一的一处形状定义**。
> 判分口径（权重、每维下限、七条硬扣分、折算系数）不在这里，在
> `docs/skills/skill-memo-ilife/t849-视觉基准.md` §1 与 `docs/skills/skill-calorie/t524-判分.mjs`。

## §零 怎么用这一份

```powershell
# 一条命令从「页群目录 ＋ 人核档」到 facts.json（三件缺件时由装配器现产；读数目录＝--json 的所在目录）
node tooling/run-locked.mjs --ticket <票号> -- node docs/skills/skill-memo-ilife/t867-facts.mjs --dir <页群目录> --human docs/skills/skill-memo-ilife/t867-人核档.md --json <读数目录>/facts.json

# 判分（引擎暂住卡路里域与备忘录域两份复制件，按域配置的公共层引擎归 #868；过渡期口径见 t849 §4）
node docs/skills/skill-calorie/t524-判分.mjs --dir <读数目录>          # 该件按 `name.slice(0,5)` 取页键
node docs/skills/skill-memo-ilife/t827-判分.mjs --dir <读数目录>       # 该件按文件名主体取页键，且要求 <读数目录>/pages/ 放产物
```

判分引擎读的是**读数目录**（四件同住一处）：`sep.json`／`resp.json`／`fmt.json`／`facts.json`。本链的装配器按同一条约定写文件。

## §一 `sep.json` —— 分隔符与内部标识符（节点级命中 ＋ R1–R7）

**产出者**：`packages/skill-calorie/scripts/audit-separators.mjs --dir <页群目录> --json <落点> [--quiet]`（住卡路里包，本票不改它一个字节）。

```
{
  at, dir, files, green, broken,
  totals: { R1..R7 }, nodeHitsTotal,
  rows: [ {
    path, name, bytes, totalLines,
    line: { R1..R7, hits: [ { line, tags: [..], text } ] },
    node: { R1..R7, hits: [ { n, line, tags: [..], text, ident: [..], owner, zone, run: { sep, n, segs: [..] } | null } ] }
  } ]
}
```

判据（**节点级命中全零才算绿**）：

| 号 | 语义 |
|---|---|
| R1 | 可见文本节点含 `·`（U+00B7） |
| R2 | 含 `；`（U+FF1B） |
| R3 | 同一分隔符切出连续 ≥3 个非空片段、每段 ≤40 字 |
| R4 | 含 `｜`（U+FF5C）或 `|`（U+007C） |
| R5 | 含 `、`（U+3001） |
| R6 | 含 `~`（U+007E）或 `～`（U+FF5E） |
| R7 | 内部标识符：命令键／命令原文／库表名／蛇形名／驼峰参数名／常量名／票号（七个具名子模式，命中时记在 `ident`） |

- `line`／`node` 两级的 `R1..R7` 是**计数器**，与同级 `hits[].tags` 必须对得上（本链的自检把这条钉住）。
- 判分怎么读它：`node.hits` 里**不含** R7 的处 → H1；含 R7 的处 → H2；含 R6 的处 → H4。D3 也由这一层折算。
- 退出码：0 全绿／1 有债（含解析失败件）／2 用法错或没有输入件；摘要行 `RESULT: <命中 0 的页数>/<总页数>` ＋ 末行 `PASS`／`FAIL`。

## §二 `resp.json` —— 跨宽溢出（三档 390／768／1440）

**产出者**：`packages/skill-calorie/scripts/measure-responsive.mjs --dir <页群目录> --widths 390,768,1440 --json <落点> --label <名>`（真浏览器读数，住卡路里包，本票不改它一个字节）。

```
{
  label, widths: [390, 768, 1440], at,
  rows: [ {
    file, name, inScope, bytes, sha256, images,
    widths: { "390": { innerWidth, docScrollWidth, bodyScrollWidth, images,
                       blame: [..], imgs: [ { w, h, box, fits } ], clipped: [..], clippedCount,
                       scrollers: [..], scrollerCount,
                       overflow, unfitted, why, ok, bodyOverflow } }
  } ]
}
```

- `overflow = docScrollWidth − innerWidth`；`why` 由「溢出／图放不下／视口守卫」三件事拼成，**空串＝该格过**；`ok === (why === '')`。
- 判分怎么读它：`why !== '' || ok === false` 的档就破一格 → H5（每格 −5），D4 的回归门也只看这一条腿。
- 退出码：0 全绿／1 有破格／2 缺浏览器或参数错；摘要行 `OVERFLOW-ZERO|NONZERO pages= cells= failed= scopeOutFailed= label=`。

## §三 `fmt.json` —— 版式读数（三档触摸处数、字号阶梯、公共层形状命中）

**产出者**：`docs/skills/skill-calorie/t516-判据-版式.mjs --dir <页群目录> --widths 390,768,1440 --json <落点>`（真浏览器读数，住卡路里文档目录，本票不改它一个字节）。**这一件只出读数、不判红绿**（退出码 0＝读数完整、1＝有页读不动、2＝用法错／缺浏览器）。

```
{
  at, dir, widths, files, unreadable,
  rows: [ { path, name, widths: { "390": {
    vw, docScrollW, bodyScrollW, outOfBounds, outOfBoundsList,
    shell, shellMaxWidth, shellPadding, body, bodyChildren,
    fontHist, fontSizes, minFontPx, minFontPxNoSvg, minFontOwner,
    kpiCards, kpiRows, kpiPerRow, kpiMaxSpread, paramFormCols, paramRows,
    shapes: { <公共层区块类>: 元素数 }, touchSmall, touchSmallList,
    tableTh, tableTd, tableThText, landmarks, svgCount } } } ]
}
```

- **三档触摸处数**：`widths[<档>].touchSmall`（可点元素短边 <44px 的个数，`touchSmallList` 是前 8 个明细）。
- **最小字号**：`widths[<档>].minFontPxNoSvg`（只算 HTML 元素，不含 SVG 文字；`fontSizes` 是整页字号阶梯，`minFontOwner` 是取到最小值的元素）。
- 判分怎么读它：390 档 `minFontPxNoSvg < 12` → D5 扣 5；**390／768 两档**的 `touchSmall` 求和 ＝ H6 处数（每处 −1；1440 档只记观感）。
- 判分引擎还读一个可选位 `pointerCoarse === true`（CDP 显式打开粗指针时，H6 也按触摸档数）：**本件不产这一位**，缺省即按 390／768 两档数。
- 现状如实记一条：`t849-视觉基准.md` §4 把这一件记作「三档触摸处数／字号／**触屏三件**／**断点集**」，而实测该件产出的字段里**没有**「触屏三件」（`-webkit-tap-highlight-color`／`touch-action`）与「断点集」两列 —— 那两列的读面在六列机审（账单域形状 `docs/skills/skill-bill/t407-v8-style-audit.mjs` 的 `tap` 列与断点列），归 [#869](https://github.com/FeatherHunter/ilife/issues/869)。本票一行语义不动，只把现状写进契约。

## §四 `facts.json` —— 逐页键（DOM 六列 ＋ 人核四列）

**产出者**：`docs/skills/skill-memo-ilife/t867-facts.mjs`（本票新件）。**页键＝文件名主体**（文件名里时间戳之前的那一段：`搜备忘_20260921_192606.html` → `搜备忘`；撞键即红）。

```
{
  at, ticket, dir, pagesDir, human, widths, readers: { "sep.json": 现产|复用, "resp.json": …, "fmt.json": … }, method,
  pages: { "<页键>": {
    note, file, bytes, totalLines, visibleTextNodes,
    tables, imgTags, tdDataLabel, tocEl, aspectRatio, scrollMargin,   // DOM 六列
    dupFacts, english, d1, d2, d4cut,                                  // 人核四列 ＋ 一个可选位
    judge: { <列>: { value, 判, 出处, 理由, candidate } },              // 逐列留痕：谁填、凭什么、机器候选是多少
    candidates: { english: { hits, nodes }, dupFacts: { hits, kinds } } // 机器候选与逐处明细
  } }
}
```

**DOM 六列**（正则**冻结**在 `t867-dom-probe.mjs` 的 `DOM_COLUMNS`，改表即改契约）：

| 列 | 正则 | 判分拿它做什么 |
|---|---|---|
| `tables` | `<table\b`（忽略大小写） | 有没有数据表 → 决定 D5 的表格扣分要不要问 |
| `imgTags` | `<img\b`（忽略大小写） | 有没有图 → 决定 D5 的图片容器扣分要不要问 |
| `tdDataLabel` | `td[^>]*\bdata-label=` | 表格有没有做窄屏卡片化（列头数据标签） |
| `tocEl` | `class="[^"]*\bilife-block-toc\b` | 页内目录**元素**（不是同名样式规则） |
| `aspectRatio` | `aspect-ratio` | 图片容器有没有写死宽高比 |
| `scrollMargin` | `scroll-margin-top` | 页内定位有没有做避让 |

**人核四列**（`english`／`dupFacts`／`d1`／`d2`）与一个可选位 `d4cut` 的取值口径、出处写法、判分怎么读，逐条写在
`docs/skills/skill-memo-ilife/t867-人核档.md` §一／§二：`d1`＝D1 的扣分、`d2`＝D2 的扣分、`d4cut`＝D4 的人核位（缺省 0），
`english`／`dupFacts` 是「机器候选 ＋ 人核判分」。

判分怎么读它（`docs/skills/skill-calorie/t524-判分.mjs` 与备忘录复制件的同款位）：`.dupFacts` → H3、`.english` → H7、
`.d1`／`.d2`／`.d4cut` 是扣分值、`.tables`／`.tdDataLabel`／`.tocEl`／`.scrollMargin`／`.imgTags`／`.aspectRatio` → D5 的四条腿。
另有可选顶层 `inherit`：借另一个读数目录的 `sep`／`resp`／`fmt`（判分引擎支持；本链不产这一位）。

## §五 人核档的格式（装配器的输入，机器可判）

```
### <页键>                                        ← 每页一段，页键＝文件名主体

- <列> = <数值> ｜ 判=<采纳候选|改判> ｜ 出处=<静态 …|渲染后 …> ｜ 理由=<…>
```

- 四列 `english`／`dupFacts`／`d1`／`d2` **逐页必填**；`d4cut` 可选；同一页同一列不许写两次。
- `出处` 必须以 `静态 ` 或 `渲染后 ` 开头（两种口径分流，见 §六 第 10 条）；写 `渲染后` 的列**必须**判「改判」。
- 出处里引 `#<节点号>` 时，静态口径下该节点必须**落在机器候选里**；引 `L<行号>` 时行号必须 ≤ 该页源文件行数。
- 页单是**应到名单**：人核档写了、页群目录里没有对应产物 → 红并点名缺哪一件（反向：页群目录里多出来的产物也点名）。

## §六 装配器的自检清单（红在哪几条，逐条点名到「文件＋字段＋页＋处」）

| # | 红在哪 | 退出码 |
|---|---|---|
| 1 | 用法错（缺 `--dir`／`--human`／`--json`） | 2 |
| 2 | 页群目录不存在、或目录里没有 `.html` | 2 |
| 3 | 人核档不存在 | 2 |
| 4 | 三件 reader 里哪一件报基础设施失败（exit 2：缺浏览器／参数错） | 2 |
| 5 | `--no-readers` 且三件有缺件（附现产命令） | 1 |
| 6 | 形状自检：`node.hits[].tags` 取到闭集 R1–R7 之外的值、计数器与逐处明细对不上、`overflow` 与两宽之差对不上、`ok` 与 `why` 对不上、`touchSmall` 与明细长度矛盾、缺某一档 | 1 |
| 7 | 页覆盖：三件读数里少一页／多一页 | 1 |
| 8 | 页键撞车（两个产物的文件名主体相同） | 1 |
| 9 | 人核档缺页（页群目录里有、人核档里没有）、缺产物（人核档里有、页群目录里没有）、缺列、同一页同一列写两次 | 1 |
| 10 | 出处：列没写、不以 `静态`／`渲染后` 开头、静态出处引了不在候选里的 `#节点号`、`L<行号>` 超过该页行数、写 `渲染后` 的列判的不是「改判」 | 1 |
| 11 | 机器候选对账：判「采纳候选」但取值 ≠ 候选、判「改判」但取值 ＝ 候选、判「改判」没写理由 | 1 |
| 12 | `d1`／`d2`／`d4cut` 扣了分没写理由 | 1 |

绿线：末几行给 `RESULT: 四件读数齐（sep.json＋resp.json＋fmt.json＋facts.json） 页键 N（页群产物 N 件）`、`FACTS-WROTE <落点>`、`PASS`，退出码 0。

## §七 与判分引擎的接口边界

- 引擎的输入是**读数目录**：`sep.json`／`resp.json`／`fmt.json`／`facts.json` 四件同住一处（本链按 `--json` 的所在目录落）。
- 引擎按**页键**取人核四列（`facts.pages[key]`）；页键由**按域配置**给（卡路里域是 `name.slice(0,5)`，备忘录域是文件名主体）。按域配置的公共层引擎归 [#868](https://github.com/FeatherHunter/ilife/issues/868)。
- 三件 reader 是**外部命令**，本链只按固定命令形态调用它们（缺则产、在则校）；它们的退出码 1 是「有命中」的**正常读数**，不是失败 —— 只有退出码 2 才当基础设施失败。

## §八 已知缺口：静态面与载荷渲染面

备忘录的产物页把内容放在页内 `<script id="payload" type="application/json">` 里、由页内脚本渲染。四件里靠**静态**读的部分（`sep.json` 的可见文本、`facts.json` 的 DOM 六列与两列机器候选）都要先剥掉 `<script>` 整段，因此：

- **渲染后才出现的文字**（脚本渲染出来的标题、明细行、按钮）不在静态面里：同一页渲染后有半角标点、有重复串、甚至有点号并列，静态读数可以是 0；
- 这不是「谁多谁少」的精度问题，而是**两个不同的量**：静态面量的是「静态可见文本」，渲染后才是用户看见的那一页。

本链的处置：静态候选作锚（可复算），渲染面的处数由视觉模型判分并写进「渲染后」出处；三件 reader 的语义不动，缺口另开票处置（见 `docs/skills/skill-memo-ilife/t867-证据.md` §六）。判分协议对这条的口径在 `t524-场景09-视觉整改基准.md` §4.4（vision 的结论要能用 DOM／CSS 读数或 `文件:行` 复核，复核不了写「未证」）。
