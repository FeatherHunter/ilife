## 七、与审查报告不一致的地方（如实记账）

**审查「最刺眼 5 点」的第 1 点（图被横向拉伸变形）在实机读数下不成立。**

审查给的读数是「1000px 时横轴约 1.6×拉伸、512px 时轴标签压到约 16.6px」。本次用 CDP 在四档宽度实测：

```
512   盒=450x201.72   scaleX=0.7758 scaleY=0.7758   盒比=2.231 vb比=2.231
820   盒=750x336.20   scaleX=1.2931 scaleY=1.2931   盒比=2.231 vb比=2.231
1000  盒=930x416.89   scaleX=1.6034 scaleY=1.6034   盒比=2.231 vb比=2.231
1440  盒=930x416.89   scaleX=1.6034 scaleY=1.6034   盒比=2.231 vb比=2.231
```

两轴 scale **四档全相等**，盒宽高比恒等于 viewBox 宽高比 —— `preserveAspectRatio="none"` 这个属性
在当前产物里**从未生效**（它只在「盒宽高比 ≠ viewBox 宽高比」时才有作用）。原因在 `chartsCss`：
≤720px 段那条规则把折线 svg 的盒高从**钉死 150px** 改成了 `height:auto`（`charts.ts:1915`，#424 返工时撤的），
高度自此按 viewBox 长宽比派生，非等比的前提没了。

所以：

- **本票照做**（撤 `none` 换 `meet`）：一个不生效的属性留着，将来任一处把盒高钉回固定 px，
  图内文字立刻被横向抻宽；撤掉是把隐患去掉，且**实测零视觉变化**（第 2、4 两节读数可证）。
- **但审查那句诊断词不写进本票结论**。真实可测的毛病只有一条：**行内字号断点跳变**——
  ≤720px 档把折线字号提到 20 用户单位（512 档实渲 15.52px），>720px 档是 10 用户单位
  （820 档实渲 12.93px、1000 档 16.03px）。于是 820 档的字（12.93px）比正文 15px **还小**
  ——这是本次唯一测到的真缺陷，落点正是审查 #1 点名要复核的那条断点档。
- **为什么本轮没顺手改字号**：把 820 档拉到 ≥13px 要么把字号档提到 11 用户单位、要么把 viewBox 宽
  收到 ~500，两条都会在**移动档**（390px）让 9 条横轴标签互相撞上或顶出 viewBox——`charts.ts` 的
  留白估算（`insetsFor` ＋ `LINE_TEXT_MOBILE`，`charts.ts:392-406`）正是为「390px 下不顶沿」算的，
  动它要连留白一起重算，属另一件活的量级。本票按票面写集只做「去非等比＋复核断点」，
  **#424 留下来的 `LINE_TEXT_MOBILE` 与 `insetsFor` 一律未动**。
- 审查 #1 落点里「`.ilife-charts-line .ilife-charts-xlabel` 的 20px 断点档复核」这一半，
  复核结论已写在本节，**改动留待后续票**（建议：要么按容器宽度分档重算字号与留白，
  要么把横轴标签从 9 条降到 3–4 条后整体放大字号档）。

**另记两条施工中踩到的约束（已按它们定了做法）**：

1. `test/charts.test.mjs` 的 `H.移动端满宽` 那条断言原本钉的是「line／combo／scatter 用 `none`」。
   本票是**契约变更**（票面明写「去掉 `preserveAspectRatio="none"`」），故同步改了该用例：
   标题与断言改断「七族一律等比 `meet`」，并把那条用例原本真正要保的东西（**满宽、不留左右空白**）
   补成两条 needle 断在 CSS 基规则上（`width:100%`＋`height:auto`）；`progress` 作为唯一有意例外
   单独断 `none`。覆盖清单的用例条数（88）与命中条数（74）**未变**，token 全部保留。
   除这一条外，`packages/base-render` 既有测试**一条未改**。
