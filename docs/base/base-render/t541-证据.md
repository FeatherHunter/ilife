# #541 证据：≤640 档数据表形态（公共层母版侧）

## 一、出处与归属

负责人第四轮看图（原话）：

> 「如图片 1 表格在手机上不适配，需要自适应，UI 显示需要正常。**需要调查这个表格是不是 base 库的**。我们需要封装出那种手机 UI 适配度很高的表格，能自适应手机和电脑」
> 「**其他场景的 HTML 只要有表格都有这个问题**」
> 「记得把上面所有用到如图表格的 HTML 都要进行修改，**这个表格问题比较严重**。」

**查明：是 base 组件。** 那张表是 `packages/base-render/src/blocks.ts` 的 `renderDataTable`（产物类名
`ilife-block-data-table*`，样式来自 `blocksCss()` 的 `dataTable` 区）。⇒ 改一处，全部用表的页面一起变；
各技能自己的页面代码一行不用动。

本票住 **#162（公共层母版侧）**，但它服务的是全部场景图：场景 03（#154）、04（#522／#523）、08、09、10 的
「手机端与 HELP 同档」维都吃这条规则（视觉席就是在 #523 收官时实测上报的）。

## 二、病根（第一性原理）

窄屏（≤640）那张表的行卡形态来自 `t154-r3`（负责人第三轮要求 2）——`thead` 收起、`tr` 变卡、每格一行
「标签 ＋ 值」。但**值那一轨是左对齐的**：

```css
.ilife-block-data-table td { display: grid; grid-template-columns: 5em minmax(0, 1fr); }
```

`1fr` 的值轨吃掉整行余宽，文字却贴轨的左缘 ⇒ 390 档实测值与容器右缘之间**空掉半张卡**（下表读数：
03 那页 `gap=282px`，而整格宽只有约 330px）。读起来就是「左边一小撮字，右边一大片空」。

同一族还有两处同源缺陷：

- **标签轨会被压扁**：值很长时（备注里一整句）值的伸缩项撑满余宽，标签轨按字断行 ⇒「备注」被压成
  「备／注」两行——正是这一票要消灭的那类形态（负责人截图里竖排的是表注，病根同一条）。
- **表注（`caption`）竖排**：表在窄屏已是块流，表注留缺省的 `display:table-caption` 会被压成「一个汉字宽」
  并按任意位置断行。这一半在盘上已有一份**未入库**的改动（`display:block` ＋ `width:100%`），本票一并入库。

## 三、改了什么（只动那条既有的 `@media (max-width: 640px)`）

| 落点 | 改前 | 改后 |
|---|---|---|
| `td` | `display:grid; grid-template-columns: 5em minmax(0, 1fr);` | `display:flex; align-items:baseline; justify-content:space-between;` |
| `td::before`（标签） | —— | 加 `flex: none`（标签轨不许收缩） |
| `td:not([data-label])` / `td[data-label=""]`（退化格） | `grid-template-columns: minmax(0, 1fr)` | `display: block`（满宽块级；栅格轨那两条在 flex 下已成死声明） |
| `td.cell-center` / `td.cell-right` | `min-width:0; text-align:left` | 一字不动（`min-width:0` 仍要收 #507 的 `5.5em` 下限） |

形态选择照仓内先例：`packages/skill-calorie/src/weight/weightUi.ts` 的
`.wui-strip-v .wui-fact{justify-content:space-between}`——「一组标签 ＋ 值」在本仓本来就长这样。

**长度自适应是 `space-between` 自带的**，不需要任何 JS 或断点：短值（`70.4`／`2026-09-07`）的伸缩项收到内容
宽、被推到右缘；长值（备注里一整句）的 max-content 超过可用宽 ⇒ 撑满到标签之后并换行（左对齐才好读）。

**桌面档（≥641）零变化**：新增声明全部住在那条既有 `@media (max-width: 640px)` 里，`renderDataTable` 的
产出器一行未改（`data-label` 照旧）。
