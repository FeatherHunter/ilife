## 五、架构收口（2026-10-05）：一处定义 ＋ 每页族一条发射 ＋ 22 处声明删除

**病根**：全仓 **22 处**手写 `font-size`（12.5／13／13.5／14／15px），全是 `class + element` 形态 `(0,1,1)`
——**同一个概念 22 个定义地**。级联战只是症状：任何同样 `(0,1,1)` 的地板都会与它们**打平**，而技能补丁样式
排在共享样式之后 ⇒ 后出现者胜、地板必输。**删掉这 22 处，赛道上就没有对手了。**

**改法（四处）**

1. **一处定义**：`components/page-ui/index.ts` 增 `NON_ENTRY_INPUT_TYPES`（「什么算文本录入控件」的**排除集**：
   其余 `input` 含不写 `type` 者 ＋ `select`／`textarea`）与 `textEntryFloorCss(root)`——地板规则的**唯一产出者**，
   值取 `PAGE_LIMITS.textEntryMinPx`。
2. **每页族一条发射**：`pageUiCss()`（`.ilife-page-ui`）／`helpShellSection`（`.ilife-help-shell`）／
   `renderDocShell()`（`.ilife-page`，**与是否启用 `pageUi` 无关** ⇒ 每一张文档壳页都吃得到）。
3. **22 处声明删掉**（不是改值）：base-render 9 处（含 3 处模板死代码不属活控件）＋ skill-calorie 2 ＋
   skill-home 5 ＋ skill-memo-ilife 5（其中 1 处是 label，不属控件）＋ skill-bill 1。各删点留一行指针注释。
4. **门禁枚举器改从同一份清单派生**：`test/text-entry-computed-1001.test.mjs` 里原先自己写了一份 `TEXTY` 表
   ——那是第二处定义，已换成 `NON_ENTRY_INPUT_TYPES`。

**为什么地板整条塞进 `:where()`**：`:where()` 特异度恒 0 ⇒ 地板特异度**只由页根贡献 `(0,1,0)`**：合法的
**上调**（某控件要做 18px）随手就赢它，任何**下调**由产物面计算值门禁抓。**CSS 表达不了「≥」——不等式交给
门禁，不交给级联**；这也解释了为什么 `@layer` 迁移解决不了本问题（层只规定谁赢，不规定下限）。

**踩过的坑（实测，已写进代码注释）**：`input:not([type=button])input:not([type=submit])…` 这种**连写**会拼出
非法选择器；而 `:where()` 的选择器列表是**宽容解析**——非法项被**静默丢掉**，规则照样生效但整类 `input` 漏掉
（只有 `select` 吃到地板）。产物面门禁当场读出来：`input 13.3333px`（Chrome 对 `input` 的 UA 默认值）。
修正＝一个 `input` ＋ N 个 `:not()` 复合。
