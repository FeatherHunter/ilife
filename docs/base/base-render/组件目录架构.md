# base-render 组件目录架构（迁移台账）

件名 `base-render`（包名 `base-paint`）。**本文只记两处扩展与迁移台账**，规矩正文不在这里重复抄。

## 一、规矩正文的住处（唯一事实源，别在本文再写一份）

组件层怎么组织，正文住 **`src/components/index.ts` 的件头**：

```
src/components/
  index.ts          ← 组件层总出口（新增一个组件只在这里加一行）
  README.md         ← 这一层自己的规矩
  shared/           ← 组件之间共用的小件（转义／入参校验）
  <组件名>/          ← 一个组件一个目录，目录内自足
    index.ts · attrs.ts · render.ts · style.ts · runtime.ts · README.md
```

同一条规矩在两处各写一份就会走散——**要改规矩，改那个件头**，本文只跟着改「扩展」与台账。

## 二、两处扩展（本文的裁定）

### 扩展一：布局与出口是两件事，不要绑在一起

`src/components/index.ts` 现在写着「本层**不进**冻结面、**不从根导出**」。那是把「件住哪儿」与
「名字从哪条路径出去」绑成了一件事，后果是：**凡进冻结面的组件就只能散落在 `src/` 根目录**——正是扎堆的成因。

本件裁定：

- **目录只回答「件住哪儿」；冻结面只回答「哪个名字从哪条路径出去、签名钉不钉死」。** 两条轴各自独立。
- 冻结面的名字仍从**原路径**出（根出口、`base-paint/blocks` 等五条子路径），由组件目录的 `index.ts`
  **薄转出**；`src/spec/**` 的签名**一字不动**。
- 因此组件目录既可以是冻结的（`page-nav`／`blocks` 那三族），也可以是不进冻结面的（`editable-value`）；
  区别只在出口，不在住处。

### 扩展二：族的集合按变化频率分族，族内一件一文件

`blocks.ts`（2856 行）／`charts.ts`（2230 行）这种「一族 N 个组件」，不必拆成 N 个目录
（目录数会爆炸、读者迷路）。做法：**按变化频率分族目录，族内一个组件一个文件**。
切口不要现编——`行数告警线评估.md` §3.2／§4 已经定过（页框／数据展示／输入说明；直角坐标／圆形与微型；
静态呈现／运行时），照它执行。

## 四、每批的判据（照仓规）

1. **产物逐字节相同**：搬迁前后同一批入口的产物（页面 HTML／CSS 文本／运行时 JS 文本）逐字节相同。
   `blocksCss()`／`pageShapeCss()` 这类**组装函数**尤其要盯：文本拼接顺序是产物的一部分。
2. **全量测试绿**：`node node_modules/typescript/bin/tsc -b packages/base-render/tsconfig.json` ＋
   `node --test "packages/base-render/test/*.test.mjs"`（他席在途造成的既有红照实记账，不算本批的）。
3. **出口与签名不动**：五条子路径（`.`／`blocks`／`docShell`／`help-shell`／`save-html`）与
   `SPEC_FROZEN_SURFACE` 逐条不变；消费方（6 个技能包 214 处 `base-paint/blocks` import）零改动。
4. **一批一个提交**，提交信息写明批次号与判据读数。

## 五、共享工作区：与并行席位的关系

本包由多个席位并行改（实测同一份工作区里同时有：`src/components/editable-value/**`＋`shared/**`＋
`src/components/index.ts` 的组件层抽取在途；另一席在 `help*`／`docShell.ts` 一带）。

- 分席按**目录**切：谁改哪个组件就住哪个目录，不再两人抢同一个文件——这正是本次目录化的目的。
- 动 `src/components/index.ts` 时**只加一行、不重排**，避免与另一席的同一文件冲突。
- 搬迁期间若目标目录正在被人改，**让位**、先做别的批次，不抢同一段代码。
