## 1. 告警线数字（建议）

**告警线＝350 行。数法：LF 口径，只数 `\n`。**

- 范围：本包 `src/**/*.ts`。不算：`dist/` 与 `.tsbuildinfo`（构建产物）、`test/*.mjs`（测试文件）、页面模板——`docs/agents/structure.md`「管辖」一节已把它们划在外面。`src/helpShell.ts` 系生成物（源为 `assets/help-template.html`，由 `scripts/gen-help-shell.cjs` 重写，字节锁 `test/help-shell-136.test.mjs` 校验），同样不计入手写面；它当刻 83 行，本就在 350 以内，计与不计不改变结论。
- 超线即触发必报五步的**第四步**：当场报一句「已超线，需要根据规则进行重构。」后头接一句为什么超，再给拆法或说明这次为什么先不拆。**超线是报警，不是拦路。**

定 350 的理由三条：

1. 兄弟件已是此数：`packages/skill-calorie/AGENTS.md` 与 `packages/skill-chef/AGENTS.md` 均为「350 行／LF 口径」，口径出处为用户答复（私家大厨那张图的 Q4b，逐字「`350 ＋ LF 口径，写进 packages/skill-chef/AGENTS.md`」，载 `docs/skills/skill-chef/map-chef-body.md:197`／`:212`）。同仓同数，跨包不用两套尺。
2. `docs/agents/structure.md` 结构标准写明「文件行数告警线：具体数字由各包自己定，写在各包自己的地方」。本包此前没有这条数字，往公共层加件时没有触发点（#420／#421／#418／#397 连续在同一文件加件，`blocks.ts` 一轮累计 +279 行，谁都报不出「已超线」）。补上即补触发点。
3. 公共层被多技能共用，不宜比场景包更松。350 对本包是严线（下节 8 件超线，最大件超 6 倍多），严线正好让每一次加件都报出第四步那句话。

落点：`packages/base-render/AGENTS.md`（本票新建，数字行＋范围＋第四步＋口径出处＋指向本文）。

## 3. blocks 拆件评估（不拆，只给拆法）

### 3.1 现状

`src/blocks.ts` 当刻 2304 行，对外出口约 19 个 `render*` 加 `blocksCss`（行号为当刻读数，搬迁时以当刻内容重排，不以行号为据）：

- 页框族：`renderPageShell`(218)、`renderTocBlock`(253)、`renderCaliberLine`(285)、`renderConclusionBar`(307)
- 数据展示族：`renderMiniBar`(428)、`renderDistributionRows`(458)、`renderChips`(495)、`renderChangeRows`(527)、`renderKpiCard`(565)／`renderKpiGrid`(592)、`renderDataTable`(633)、`renderChartBlock`(708)、`renderListRows`(753)
- 输入与说明族：`renderPreBlock`(799)、`renderDetailSection`(846)、`renderDisclosure`(899)、`renderParamForm`(955)、`renderEmptyBlock`(1042)、`renderCopyBlock`(1071)、`renderFeedbackBlock`(1163)
- 样式：`BLOCK_STYLE_SECTIONS`(156)＋`blocksCss`(2282)，约 12 区闭集，唯一产出者为 `blocksCss()`，只读冻结 token（`CSS_VAR_TOKENS`）加局部常量

超因一句话：页面级组合（组合冻结控件成页，与 `controls.ts` 同口径不重复定义控件签名）全住一件；三族变化频率不同（页框随整页骨架动、数据展示随各技能读数卡动、输入与说明随表单与空态文案动），同一文件加件即互相牵连。已超线，需要根据规则进行重构。本次先不拆（见 §3.3）。

### 3.2 拆法（建议，切口按变化频率）

新建 `src/blocks/` 目录三件姊妹件，本件留薄转出（子路径 `base-paint/blocks` 对外不变）：

- `src/blocks/pageFrame.ts`：页框族（`PageShellInput`／`renderPageShell`、`TocItem`／`TocBlockInput`／`renderTocBlock`、`renderCaliberLine`、`renderConclusionBar`）＋其输入类型。随整页骨架动。
- `src/blocks/dataDisplay.ts`：数据展示族（`MiniBar`、`DistributionRows`、`Chips`、`ChangeRows`、`KpiCard`／`KpiGrid`、`DataTable`、`ChartBlock`、`ListRows`）＋其输入类型。随读数卡与表动。
- `src/blocks/formFeedback.ts`：输入与说明族（`PreBlock`、`DetailSection`、`Disclosure`、`ParamForm`、`EmptyBlock`、`CopyBlock`、`FeedbackBlock`）＋其输入类型。随表单、空态、复制区动。
- 样式 `BLOCK_STYLE_SECTIONS`＋`blocksCss` 随三族共用的那一小块走：若按「样式随用处」则把各区 CSS 文本拆进对应姊妹件、`blocksCss` 留组装；若按「最小搬迁」则样式单立 `src/blocks/blocksCss.ts` 一件，三族只引用。三选一由拆件票裁定，本文推荐后者（搬迁 diff 最小）。
- 共用小件（`esc` 转义、`BlocksError`／`badInput`）提为 `src/blocks/shared.ts`，三件只经它引用，不各写一份（`structure.md` 铁律二：同一东西只有一个定义地）。
- `src/blocks.ts` 留薄转出（重导出三件＋样式组装），对外子路径与签名不变；冻结面（`src/spec/`、`src/index.ts` 出口清单、`CONTROL_*`／`STATUS_*`／`COPY_*` 常量）一行不碰。

每件预估仍超 350（三族每族约 500–800 行），拆一次到 350 以内需再按页族细分；首次拆到「一族一件＋薄转出」即恢复第四步可读性（超线行只剩该族），后续按族内页再拆由收口票认领。

### 3.3 为什么本票不拆

- 票面第 3 条已裁定：数字与拆法由维护者／用户裁定，本票先交评估与建议，不擅自拆。
- 拆件须另开票，判据写「产物逐字节相同」（照 #332 纯搬迁口径）：搬迁前后 `blocks.test.mjs`、`charts.test.mjs`、`controls.test.mjs`、`style.test.mjs` 全绿＋消费方（至少 skill-calorie 一条真实链路 `assembleDocPage → buildSharedHelpersJs → fillTemplate`）产物逐字节相同。

## 4. charts／controls／style 三件简评（是否超线＋切口）

- `src/controls.ts`（1492 行）：超。现状为静态呈现（`renderToast`(189)、`renderActionBar`(1383)、`renderStatusBadge`(1427)、`renderEmptyState`(1437)、`renderErrorReceipt`(1465)）与运行时（`createToastController`(251)、`copyText`(343)／`createCopyRuntime`(395)／`bindCopyAction`(439)、`buildSharedHelpersJs`(589)）同处一件。切口建议按「静态呈现／运行时」分两件：`controlsRender.ts`（五个 `render*`）与 `controlsRuntime.ts`（toast 控制器＋复制三件＋共享 JS 文本产出），`TOAST_ICON_GLYPHS` 随呈现走。已超线，需要根据规则进行重构。本次先不拆。
- `src/style.ts`（1383 行）：超。现状为 `STYLE_TOKENS`＋`cx`／`token`＋8 区 `SECTION_BUILDERS`(98)＋`buildStyleSheet` 组装＋`assertExtraCss` 校验同处一件。切口建议按样式区分两到三件（控件区一族、图表区转调 `chartsCss` 单列、页框区一族），组装与校验留本件。已超线，需要根据规则进行重构。本次先不拆。
