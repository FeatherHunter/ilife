## 一、折线字号随盒宽乱跳（完成）

### 根因

svg 文本的 `font-size` 写在**用户单位**上，被 viewBox 等比缩放（#507 起八族一律
`preserveAspectRatio="xMidYMid meet"`，`charts.ts:326`；盒 `width:100%;height:auto`，
`charts.ts:1854`）——两轴同倍，实渲像素 = 用户单位 × 缩放比，而

```
缩放比 = svg 盒宽 ÷ viewBox 宽(580)          （LINE_DEFAULT_WIDTH，charts.ts:763）
```

盒宽随视口变，所以**同一个用户单位在不同视口实渲出不同像素**。改前 `chartsCss` 只给了一档补偿
（≤720px 折线族一律 20 用户单位，`LINE_TEXT_MOBILE`），721px 起落回桌面档 9.5／10 单位：

| 视口 | 盒宽（实测） | 缩放比 | 改前用户单位 | 改前实渲 |
|---|---|---|---|---|
| 512px | 450 | 0.7759 | 20（移动档） | **15.52px** |
| 820px | 750 | 1.2931 | 9.5／10（桌面档） | **12.28／12.93px** |
| 1000px | 930 | 1.6034 | 9.5／10 | 15.23／16.03px |
| 1440px | 930 | 1.6034 | 9.5／10 | 15.23／16.03px |

断点两侧更明显：720px 档实渲 22.50px、721px 档掉到 13.97px（推算，见下「档带边缘」）。
→ 820px 档 12.28px 落在 512px 档 15.52px **之下**，字号随视口**非单调地跳**。

### 改前 → 改后

`charts.ts:396`（`LINE_TEXT_MOBILE` 原样保留，不改）：


改它们会牵动一批快照断言）。

### 我用的缩放比与算式 —— 来源

缩放比取自 **`docs/base/base-render/t507-视觉底座-证据.md:175-178`** 的 CDP 四档**实测**读数
（非本票新测，本票禁截图／禁构建链）：

```
512   盒=450x201.72   scaleX=0.7758 scaleY=0.7758
820   盒=750x336.20   scaleX=1.2931 scaleY=1.2931
1000  盒=930x416.89   scaleX=1.6034 scaleY=1.6034
1440  盒=930x416.89   scaleX=1.6034 scaleY=1.6034
```

三处自洽校验：① 盒宽 ÷ 580（`LINE_DEFAULT_WIDTH`）逐档等于上表 scaleX；② 盒高 = 盒宽 × 260/580
（450→201.72、750→336.21、930→416.90），说明四档量的都是 580×260 这个 viewBox；
③ 1000px 与 1440px 同值 —— 930 是卡片宽度上限，到顶后缩放比不再涨。

**算式：用户单位 = 目标像素 ÷ 该档实测缩放比**（取整到 0.1）：

```
≤720px  档：目标 15.5px ÷ 0.7759 = 19.98 → 20    （沿用 LINE_TEXT_MOBILE.tick，一字未动）
721–875px 档：目标 16.0px ÷ 1.2931 = 12.37 → 12.4
≥876px  档：目标 17.3px ÷ 1.6034 = 10.79 → 10.8
875 这个边界是**反解**出来的：10.8 单位要保证实渲 ≥15px，缩放比须 ≤ 15 ÷ 10.8 = 1.3889
→ 盒宽 ≤ 1.3889 × 580 = 805.6 → 视口 ≤ 875.6，取下沿 876。
```

### 改后四档实渲

| 视口 | 缩放比 | 用户单位 | 实渲 |
|---|---|---|---|
| 512px | 0.7759 | 20 | **15.52px** |
| 820px | 1.2931 | 12.4 | **16.03px** |
| 1000px | 1.6034 | 10.8 | **17.32px** |
| 1440px | 1.6034 | 10.8 | **17.32px** |

→ **单调不降且四档全 ≥15px**。

### 不变式：档位不许越过 20

`insetsFor` 的左留白是按 `LINE_TEXT_MOBILE.tick`（20 用户单位）估的（`charts.ts:843` 一带，留白是
**双端共用的用户单位**）。抬过 20 会让「70.5kg」这类刻度文字在**每个**视口都顶出 viewBox 左沿。
故本表只抬中间档与宽档，**移动档一字不动**，`insetsFor` 无需改动 —— 这条变的是「补刻度要不要动左留白」
那一问的答案：**不需要动**。用例里有一条不变式断言钉住它。

### 已知余量（如实记账，本次不修）

媒体查询只能按**视口**分档，缩放比却按**盒宽**走，同一档内仍然变化（档带边缘按拟合模型
`盒宽 = min(930, (视口 − 50) × 0.974)` 推算，非实测）：

| 视口 | 用户单位 | 实渲（推算） |
|---|---|---|
| 320px | 20 | 9.07px |
| 390px | 20 | 11.42px |
| 720px | 20 | 22.50px |
| 721px | 12.4 | 13.97px |
| 875px | 12.4 | 17.18px |
| 876px | 10.8 | 14.98px |

三处锯齿：窄端 320–480px 仍 <15px、720→721 有 22.5→14.0 的台阶、875→876 有 17.2→15.0 的小台阶。
有界的做法都越出本票：窄端要 ≥15px 得把用户单位抬到 33（破 20 的不变式、左留白全线变宽）；
抹平台阶要**按容器宽分档**（container query / 容器测量），是另一个量级的改动。

## 二、顶上那条无标注的网格线（**停手回执**）

### 锚点订正：`g=0` 在**底部**，不在顶部

派单写「`:469-474` `gridSvg(frame)`：`g=0` 那条在 `frame.y1`（**顶部**）」。实测该文件里
`frame.y1` 是**底边**，不是顶边：

- `charts.ts:361-366` `makeFrame`：`y0 = insets.top`（顶）、`y1 = max(y0+1, height − insets.bottom)`（底），
  `h = y1 − y0`。SVG 的 y 向下增大 → `y1` 是**底**。
- `charts.ts:423` `yAt`：`return frame.y1 - ((value-lo)/span) * frame.h` → `value = hi` 得 `y0`（顶）、
  `value = lo` 得 `y1`（底）。散点／补底面也用 `frame.y1` 当**基线**（`:966` areaPath）。

`charts.ts:471-472`：

```
for (let g = 0; g < GRID_LINES; g += 1) {
  const gy = frame.y1 - (frame.h * g) / (GRID_LINES - 1);
```

→ `g=0` → `gy = y1`（**底**）、`g=1` → 中线、`g=2` → `y1 − h = y0`（**顶**）。三条线分别在
`lo`／中点／`hi` 上。派单给的两个改法在这里的真实效果是：

- 「改成从 `g=1` 起」+ `GRID_LINES=3` → 留中线与顶线，**删掉的是底轴那条**；
- 「`GRID_LINES` 与循环一起改 2」→ `g=0,1` → 留底线与顶线，**一条都没删**。

两种都拿不到「删掉顶上那条」，且前一种比现状更糟（底轴是绘图区的基准线）。**故不照做。**

### 真正无标注的是**中线**，不是顶线

`ticksSvg`（`charts.ts:480-497`）**本来就画刻度标注**（短横线 + `fmtValue` 数字），位置
`tv = lo + (hi-lo)*i/(count-1)` → 首尾**必含** `lo` 与 `hi`，所以只要 `tickN ≥ 2`，**顶线一定有标注**
（顶线 ≡ `hi` 那条刻度）。真正对不上的是中线：`gridSvg` 固定把线画在 `lo／mid／hi` 三条上
（`GRID_LINES = 3`，`charts.ts:157`），而标注条数由**调用方**的 `yTicks` 决定（2–6，`tickCount`，`:462`）
—— 两者只在 `tickN == 3` 时才一一对应。实测调用方：

- `skill-calorie/src/weight/history.ts:420` → `yTicks = steps + 1`，`steps ∈ {5,4,3}` → **4／5／6**；
- `skill-calorie/src/analysis/multiTrendPage.ts:307 等`、`render/trendDocs.ts:383` 等 → **3**。

`tickN = 4` 时标注落在 `lo, lo+s/3, lo+2s/3, hi`，中线 `lo+s/2` **不是**任何一条刻度 → **中线无标注**；
`tickN = 6` 同样。**用户说的「无标注的那条」在几何上是中线，只是肉眼读成「上面那条」。**

所以「删」不是该做的事 —— 那条线**本该有标注**，正确的修法是**让网格线与标注一一对齐**（正是派单
第 3 件要的效果），而不是删线。这也回答了派单要我交代的「为何选删而不是标注」：**标注是可得的，
所以「标注」赢。**

### 建议的落地做法（等授权，未执行）

`gridSvg(frame, count)` 加一个条数参数：`count ≥ 2` 时按刻度位置画线（与标注 1:1），否则回落到
`GRID_LINES`（保住杆／组合／散点三族「缺省 3 条」的现状）。牵动两处**被测例钉死**的地方，须一并同步：

- `test/charts.test.mjs:278-279` 断 `grid:true` 与 bar 各有 **3** 条 `.charts-grid`；
- `gridSvg` 是折线／杆／组合／散点**四族共用**（`:1168`／`:1382`／`:1603`／`:1793`），
  改它等于改四族。

## 三、补 y 轴刻度（**停手回执**）

派单：「给折线补左轴刻度标注（三到五个数，与保留的网格线一一对齐）」。

**折线已经有左轴刻度标注**：`charts.ts:1171` 折线渲染里就调 `ticksSvg(frame, lo, hi, tickN, line.format)`，
`ticksSvg` 出短横线 + 数字（`:493-494`，走 `fmtValue(round2(tv), format)`）。缺的不是绘制，是**缺省不开**：

`charts.ts:787`（`resolveLineOptions`）：

```
yTicks: opts === undefined || opts.yTicks === undefined ? false : opts.yTicks,
```

→ `tickCount(false) = 0` → **缺省零刻度**。这不是遗漏，是被钉死的契约：

- `test/charts.test.mjs:387`：`assert.deepEqual(tickTexts({}), [], 'yTicks 缺省 false → 无刻度')`；
- `test/charts.test.mjs:1331`：`assert.equal(countOf(lineHtml(), P + 'charts-tick'), 0, 'line 的 yTicks 缺省仍 false
  （不受影响，#424 由调用点显式给）')`。

所以「在 `charts.ts` 里补刻度」＝把缺省 `false` 翻成 3～5 的数 —— 那是**改契约**，不是修 bug，得先授权
（还可能牵动冻结面 `LineChartOptions.yTicks` 的语义登记）。**故不照做。**

### 但用户看到的现象是真的 —— 触发点在调用方

`packages/skill-calorie/src/home/homeDocs.ts:243` 建的是 `kind: 'line'`，**整件没有 `yTicks`**

## 六、网格线与标注一一对齐（已执行；第二节「建议落地做法」按授权照做）

上一节把修法**命名**为「网格线与标注一一对齐」，本节是**执行**：把第二节的 `gridSvg(frame, count)`
真正落进代码，条数与位置都由**实际标注条数**决定。删线方向仍然不采（第二节已证底轴／顶线不是问题）。

### 改了什么

`packages/base-render/src/charts.ts:500-511`（原来 `:499`，无 `count` 参数）：

```ts
function gridSvg(frame: Frame, count = 0): string {
  const lines = count >= 2 ? count : GRID_LINES;
  let out = '';
  for (let g = 0; g < lines; g += 1) {
    const gy = frame.y1 - (frame.h * g) / (lines - 1);
```

`lines - 1` 的均匀标度与 `ticksSvg`（`:516`）的刻度 `ty = yAt(frame, lo + (hi-lo)*i/(count-1), lo, hi)`
是**同一个算式**，故每条网格线恰好压着自己那条刻度。`count < 2`（`yTicks:false`／非数 → `tickCount` 给 0）
回落到 `GRID_LINES`——**无标注的图不得变成空白**。`GRID_LINES` 注释同步为「无 Y 轴标注时的条数」（`:157`）。

四处调用点（`gridSvg` 是四族共用）：`:1204` 折线 → `gridSvg(frame, tickN)`；`:1829` 散点 →
`gridSvg(frame, SCATTER_Y_TICKS)`；`:1418` 杆、`:1639` 组合**不动**（两族没有 `yTicks`，本就无标注）。
