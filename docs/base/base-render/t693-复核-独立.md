## 五、回归影响专项（票面第 4 问：减动效档算不算回归）

**结论：不算回归。** 依据是真浏览器读数（不是推断）：

给栈元素补类名，确实顺带让 `@media (prefers-reduced-motion: reduce)` 里的 `.hm-toast-stack .hm-toast{transition:none}` 从「祖先类不存在、从未命中」变成「命中」。同一页面在 `reduce` 下 `transitionDuration` 由 `0.22s, 0.22s` → **`0s`**，而 `opacity=1`、`toastFullyInViewport=true`——提示卡**仍即时、完整可见**。可见性由 `.show` 类切换的终态决定（`.hm-toast{opacity:0}` → `.hm-toast.show{opacity:1}`），`transition` 只是入场过渡；协议 §4 的减动效口径要的正是「动效归零、状态照走」。

同源风险面我也查了：全仓 `hm-toast-stack` 只有 3 个落点（注入样式那条定位规则、页内 reduce 归零条、运行时赋值），**没有第 4 条**会被这次命中改写的规则；`.tab-bar` 是 z-index 600，栈 9999，压得过。

**速查台新线**（`packages/base-render/src/controls.ts`）：`feedback()` 走 `document.querySelector("." + STACK_CLASS)`，没有则 `host.className = STACK_CLASS`（`:830–835`）——**本来就按类名下发**，从未受此缺陷影响；其 `STACK_CLASS = STYLE_PREFIX + 'toast-stack'`，`STYLE_PREFIX = 'ilife-'`（`style.ts:31`），与 `hm-toast-stack` 不同名、不冲突；它的定位规则同样按类名（`style.ts:103` `.ilife-toast-stack{position:fixed;left:50%;bottom:calc(24px + env(safe-area-inset-bottom,0px));transform:translateX(-50%);z-index:9999…}`）。本次修法等于把老共享线**对齐到新线本来的形状**——方向上互相印证。

**六家技能 HELP 落盘文件**：六家消费面 40/40 绿（`6b8007e5…`）；且六家 HELP 都走同一段共享壳（`HELP_SHELL_*`），修一次即全家受益。**但注意**：修的是**生成侧**，装机的 `base-paint@0.3.2`（`C:\Users\辰辰洋洋\.dsh\profiles\web\node_modules\base-paint`）里 `dist/helpShell.js` **仍是无修复版**——我独立复核：`含 stack.className='hm-toast-stack'` = False、`含 stack.id='hm-toast-stack'` = True、版本 0.3.2（仓内版本号同为 0.3.2，靠 changeset 走发版）。⇒ **已落盘的旧 HELP 文件与装机路径下的产物不会自己变好**，需发版 ＋ 重出（HELP 产物有 24h 复用窗口）。这一条不是缺陷，而是「用户手上能不能用上」的对账必须点名项；实施者未提交的 §八 也写了同一结论，与我的读数一致。
