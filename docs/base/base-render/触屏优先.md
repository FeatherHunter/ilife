# 触屏优先（本产品的交互第一性原理）

> 起因：2026-09-24 新件墙打分。用户给了两条**硬事实**，其余交给我定：
> ① 「我们的控件会**同时在手机和电脑端**用，**不存在方向键等键盘相关的东西**」；
> ② 评分口径：1 分＝严重设计问题（多数就是键盘依赖）、2 分＝同样问题或设计丑陋、3 分＝需优化、4 分＝满意。
> 用户只做打分，不参与中间决策。

## 一、四条推导出来的法则

1. **可达性底线＝一根手指**：任何动作都必须**点得到**——命中盒 ≥44×44，且**不许只有悬停/键盘才能到达**。
   键盘（若将来真有）只能是**加速路径**，不许是唯一路径。
2. **键帽提示一律从界面上删掉**。它们不是"给桌面端的福利"，而是**噪音与误导**：手机上看到 `⌘K`／`↑↓`／
   `Esc`，用户会以为这界面坏了或者本该有键盘。（实测：`command-palette` 的三皮肤 1/1/1、`shortcut-sheet`
   2/2/2、`quick-capture` 2/2/2 —— 全是被这一条判死的。）
3. **入口必须可见**。凡"隐式入口"（按某个键才出现的东西）在本产品**不成立**：每个能力都要有一个
   **看得见、点得到的入口**（页头按钮／列表行／底部操作条）。隐藏入口＝手机上不存在该功能。
4. **手机与电脑同构**：同一份标记在 390 与 1280 都要成立（宽度只许听容器，不写视口分档、不用 `@media`
   判宽度）。手机上"少一点"靠的是**折叠与分组**，不是砍功能。

配套（仓库既有纪律，照用）：状态靠"形＋字＋色"三样；触控 44 地板；`:focus-visible` 保留给真实键盘用户
（那是无障碍，不是主路径）；`hover` 只许是增强，不许是唯一通路。

## 三、验收口径（每条都能查）

1. **零键盘痕迹**：新件的标记与文案里不出现 `⌘`／`⌥`／`⇧`／`↑↓`／`Esc`／`Tab`／`键帽`／`快捷键`／`方向键`。
   判据化：一条 grep 判据（`.scratch` 侧的检查脚本 ＋ 主控复核）。
2. **零视口分档**：不出现 `@media (max-width|min-width)`；宽度走 `@container`。
3. **触控 44**：所有可点元素命中盒 ≥44×44（含图标按钮）。
4. **两档不横滑**：390 与 1280 下都不出现内容溢出（沿用各席的溢出读数）。
5. **4 分形态回归**：改动前后，4 分形态所在的页面高度与关键读数不变（席位要报这条）。

## 五、工具与手法上的教训（都踩过，写下来免得再踩）

1. **别把"省略号"当横滑**：给了 `text-overflow:ellipsis` 的元素天生 `scrollWidth > clientWidth`——第一版探针
   把它判成"横向溢出"，于是把"3 处横滑"报成了版式坏（其中两处其实只是设计里的省略号）。修法：判据里
   跳过 `textOverflow === 'ellipsis'` 的元素。
2. **跨语言文本做正则清理，必须先分开 JS 区与 CSS 文本区**：用 `,\s*\{ → {` 去清 CSS 多余逗号时没限定作用域，
   顺手把 **JS 对象数组的逗号**也吃了（`},{` → `}{`），文件当场语法错。教训：清理要**按语法分别做**，并**带断言**
   （切不到或切完还有残留就抛错，不静默写坏文件）。
3. **模板字符串里的注释不许带反引号**：页内探针串里写了带反引号的 `text-overflow:ellipsis`，当场 SyntaxError。
   本仓已因此踩过多次（生成器脚本同理）。
4. **删整件用脚本按标记切，别手抄**：切 `shortcut-sheet` 要切"CSS 段 ＋ items 对象"两段上百行；脚本按标记切，
   切完断言"这些名字一个都不剩"，比手改可靠。**还要注意它被别的件复用的类**（87 的 ✕ 按钮被 90 复用，
   要"切掉 ＋ 交接"成中性类，不能连样式一起删）。
5. **席位派活的粒度**：一次给 10 件的大简报会**空转**（实测两席跑了三小时、一个字节没落盘）。
   ⇒ **一批 2 件、每件落盘一次、回报三行**，这才能拿到中间状态。
