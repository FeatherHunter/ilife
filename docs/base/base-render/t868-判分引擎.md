## §1 冻结值清单（唯一一处算式）

下面这些值只住在引擎里；改一处就是改全部分账。

| 项 | 冻结值 | 出处 |
|---|---|---|
| 逐维权重 | D1 15 ／ D2 20 ／ D3 25 ／ D4 15 ／ D5 25（合计 100） | `t849-视觉基准.md` §1 |
| 每维下限 | 满权 80%：D1≥12 ／ D2≥16 ／ D3≥20 ／ D4≥12 ／ D5≥20 | 同上 |
| 七条硬扣分 | H1 −2 ／ H2 −3 ／ H3 −2 ／ H4 −1 ／ H5 −5 ／ H6 −1 ／ H7 −1 | 同上 |
| 触摸档 | 390 ／ 768（显式打开粗指针时也进这一档） | 同上 |
| 判据档位 | 390 ／ 768 ／ 1440（读数器按这三档量） | `t849-视觉基准.md` §4 |
| D3 折算系数 | `{ sep: 1.2, ident: 1.5, dup: 2.0, symbol: 1.0 }` | `t524-判分.mjs` |
| D5 折算系数 | `{ font: 5, table: 6, toc: 4, image: 3 }` | 同上 |
| 过线 | 逐页 ≥90 **且**每维 ≥ 满权 80% | `t849-视觉基准.md` §1 |
| 判据数值 | 可点控件命中下限 44px ／ 正文类字号下限 12px ／ 仓内断点集合 400／640／820／1001／1200 | `packages/base-render/src/pageUi.ts` 的 `PAGE_LIMITS`（见 §2） |

算式：`页分 = max(0, Σ逐维分 − Σ硬扣分)`，逐页算、逐页判。

逐维算式的读法（与 `t524-判分.mjs` 逐条一致，如实记两处容易读错的）：

- **D3 压在硬扣分上，不再乘一遍折算系数**：`D3 = max(0, 25 − (H1×处数 ＋ H2×处数 ＋ H3×处数 ＋ H4×处数))`，
  两组折算系数只出现在逐页明细的 `coeff` 位 —— 同一笔债不收两次（`t849-视觉基准.md` §1 已如实写明）。
- **D4 只有一条腿**：回归门破一档 −5／破档（无隐藏 −5）；另加 `facts.d4cut` 一个人核位（缺省 0）。
- **H6 只在触摸档数**：非触摸档不硬扣、只记观感；桌面档的 40px 命中区不在这条算式里。

## §2 判据阈值与公共层数值同住

引擎用的三个判据数值取自公共层，引擎里不另写一份字面量：

| 值 | 住处（唯一一处定义地） | 引擎怎么取 |
|---|---|---|
| 可点控件命中下限 44px | `src/spec/controls.ts` 的 `ACTION_BAR_DEFAULTS.minHeightPx`（同一个数、同一件事） | 经 `PAGE_LIMITS.touchMinPx` |
| 正文类字号下限 12px | `src/pageUi.ts` 的 `PAGE_LIMITS.textMinPx`（⑥ 那条媒体查询的 `font-size` 就是它写出来的） | `PAGE_LIMITS.textMinPx` |
| 仓内断点集合 400／640／820／1001／1200 | `src/pageUi.ts` 的 `PAGE_LIMITS.breakpointsPx` | `PAGE_LIMITS.breakpointsPx` |

`PAGE_LIMITS` 是三样的**唯一一处定义地**（#868 追加到 `src/pageUi.ts`，页面级移动端配方与它的 CSS 同住）。
它有三处**真正在干活**的用处，不是摆设：

1. **H6 明细与下限对账**：`fmt.json` 的 `touchSmallList` 每一处都必须真的小于 `touchMinPx`
   （任一边 < 44px）—— 读数器若把阈值写成 40，明细里就会出现 42×42 这类「其实够大」的命中，引擎当场报红。
2. **正文类字号下限**：`fmt.json` 的 390 档 `minFontPxNoSvg` 低于 `textMinPx` 就吃 D5 的字号折算 −5。
3. **断点集合管档位**：读数最窄一档必须落在断点集合最窄一档（400px）及以下、最宽一档必须越过最宽一档
   （1200px）—— 只量一档的读数判不了「跨宽自适应」，引擎报红并点名。

如实记一条边界：`PAGE_LIMITS` 目前只出到 `dist/pageUi.js`，**没有开进包门**
（`base-paint` 的根出口与 `package.json` 的 `exports` 都没它）。理由是开包门要动**契约冻结面**：
根出口的每个新名字都要进 `SPEC_FROZEN_SURFACE`，那张清单又被 `docs/base-paint-contract.md` 的
标记区表格逐字绑死 —— 两处都是**共用位**，按地图「并发执行机制六条」第 2 条，不顺手改，另开小票。
本票的消费方只有一个（包内脚本 `scripts/判分.mjs`，按包内相对路径取 `dist/pageUi.js`），
包内互用不必经包门。

## §3 按域配置：只许路径与名单

配置文件是一份 JSON，**只许三个字段**，多一个字段或出现一个数字即报红：

```json
{
  "packagePath": ".",
  "readingsDir": "packages/base-render/test/fixtures/判分/夹具",
  "instances": [
    { "file": "甲-01-记录一览.html", "key": "甲-01-记录一览" },
    "甲-02-待办清单.html"
  ]
}
```

| 字段 | 是什么 | 缺省与解析 |
|---|---|---|
| `packagePath` | 域包根（相对仓根或绝对路径） | 只用来解析相对的 `readingsDir`；缺省＝当前工作目录 |
| `readingsDir` | 读数目录 | 相对路径按 `packagePath` 解析；命令行 `--dir` 优先于它 |
| `instances` | 实例名单：这次判哪些页、按什么顺序判 | 不给就用 `sep.json` 里全部读数行（同一次读数全部参与，不漏页） |

名单条目两种形态：

- **字符串**＝产物文件名（如 `甲-02-待办清单.html`）；
- **对象** `{ file, key }`：`file` 与读数行配对，`key` 与 `facts.json` 的 `pages` 键配对（`key` 缺省＝`file`）。

`facts.json` 的键按这条规则配对：名单**显式给了** `key` ⇒ 只按它（含去掉 `.html` 一次）逐字配对；
没给 ⇒ 按文件名（含与不含 `.html` 两种写法各试一次）。全试完还找不到 ⇒ **缺件点名报红，不静默取 0 分**。
名单里的页如果在读数里找不到、或读数里有页不在名单里，同样报红并点名 —— 被判的页与名单必须逐字对齐。

报红口径（都是一行点名，不吐栈）：

| 情形 | 判决 |
|---|---|
| 配置出现第四个字段（例如顶层写 `d3: 25`） | exit 1，点名「配置只许路径与名单」 |
| 配置任何位置出现数字或布尔值 | exit 1，点名「配置只许路径与名单」并指出是哪一处 |
| 名单点名的产物在读数里没有 | exit 1，点名缺哪件产物 |
| 读数里有页不在名单里 | exit 1，点名「名单外的读数」 |
| 四件读数缺件（含 `facts.json` 被挪走）／不是合法 JSON | exit 1，点名缺哪一件、落在哪个路径 |
| 命令行缺 `--dir` 且配置没给 `readingsDir` | exit 2（用法错） |

## §4 两条读数命令

```powershell
# ① 正例：引擎跑入仓夹具（含一致性自证）
node tooling/run-locked.mjs --ticket 868 -- node packages/base-render/scripts/判分.mjs --dir packages/base-render/test/fixtures/判分/夹具 --json .scratch/t868/score.json

# ② 正例：同一读数目录换另一套按域配置再跑一次，比逐页逐维最大绝对差
node tooling/run-locked.mjs --ticket 868 -- node packages/base-render/scripts/判分.mjs --dir packages/base-render/test/fixtures/判分/夹具 --config packages/base-render/test/fixtures/判分/配置/域甲.json --json .scratch/t868/score-甲.json
node tooling/run-locked.mjs --ticket 868 -- node packages/base-render/scripts/判分.mjs --config packages/base-render/test/fixtures/判分/配置/域乙.json --json .scratch/t868/score-乙.json
node tooling/run-locked.mjs --ticket 868 -- node packages/base-render/scripts/判分.mjs --compare .scratch/t868/score-甲.json .scratch/t868/score-乙.json
```

命令形态：

```
node packages/base-render/scripts/判分.mjs --dir <读数目录> [--config <按域配置.json>] [--json <落点>]
node packages/base-render/scripts/判分.mjs --compare <甲落点.json> <乙落点.json>
```

- 退出码：**0** ＝读数齐 ＋ 一致性自证差 0；**1** ＝缺件／配置违规／自证不一致；**2** ＝用法错。
- 末两行恒为：`RECONCILE …最大绝对差 = 0 ⇒ 一致（差 0）` 与 `页分 每维≥80%：…`（`--json` 的落点行印在它们之前）。
- 退出码只判「读数齐不齐 ＋ 两腿一致不一致」，**不判页分过线**：页分是读数，过线与否在报告里逐页给
  （`≥90 且每维≥80% 的页 = n/N`），不代替域票门。
- 引擎先从 `dist/pageUi.js` 取 `PAGE_LIMITS`：干净克隆上先构建（`node node_modules/typescript/bin/tsc -b packages/base-render` 或 `pnpm build`）。

## §5 一致性自证：两条腿

`--dir`／`--config` 跑完，引擎自带一次**字面公式腿**：把 §1 的公式照字面重打一遍（**不共享脚本腿的任何函数**），
逐页逐维（含硬扣分与总分）比差，差 0 才 exit 0。这条自证的作用是防「脚本里悄悄改了算式、
文档里的字面公式没跟着改」——两腿走散当即报红。

现场先例（#524）：同一页曾并存两套算式，差 43 分（20.9 vs 63.9）。本件把两腿并进**一个文件**，
自证随引擎入仓，谁改哪一条腿都会当场红。

## §6 与 `t524-判分.mjs` 的逐条差异（提取时改了什么、没改什么）

**没改**：权重、下限、七条硬扣分、触摸档、判据档位、两组折算系数、逐维算式、页分算式，逐条同值。
实测对照见证据件：新引擎与旧引擎跑同一份卡路里读数（16 页／112 项），逐页逐维**不一致项 0**。

**改了四处**（都是「缺件不静默、口径与公共层同住」这一类）：

| # | 旧件 | 本件 | 为什么 |
|---|---|---|---|
| 1 | 读数目录缺省写死 `.scratch/t524/out/readings-before` | 没有缺省：`--dir` 或配置的 `readingsDir`，都没有就是用法错 | 域路径不许硬编码进公共层引擎（那正是「按域配置」要治的） |
| 2 | `facts.pages[k] ?? {}` —— 页键缺失静默取 0（照满权算） | 页键缺失＝缺件点位报警、exit 1 | 缺一页人核列就照满分算，是把打分面做成了不可复算 |
| 3 | 字面腿的 H6 只数 390／768，脚本腿还认「显式粗指针」 | 两腿都认粗指针 | 旧件两腿在 `pointerCoarse` 为真时会走散；自证要真能自证 |
| 4 | 页键＝`name.slice(0,5)`（卡路里命名假设） | 页键由名单给（`key` 或文件名） | 页键是域的命名，不该冻进公共层算式 |
