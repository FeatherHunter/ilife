# 选中态与皮肤语言（第一性原理下的口径）

> 起因：2026-09-24 新皮肤墙打分。用户给 `terminal` 51/51 全否、`blueprint` 51/51 全否，
> `ink` 43 件 4 分、8 件低分，原话是「给评分中2分的都出现了UI BUG比如有黑色什么的」。
> 本文件是这次重建的**唯一口径出处**：改哪一件、改成什么，都照这里的法则表，不照个人口味。

## 一、现场读数（先把事实钉住）

- 8 件没过：`filter-chips` 2、`invoice-lines` 3、`number-stepper` 2、`punch-strip` 2、
  `scale-bar` 3、`sort-toggle` 2、`step-flow` 2、`window-picker` 2。
- **对照实验**（`皮肤预览/ink-问题件.mjs`：同一份标记／同一份样式段，左列 `paper`、右列 `ink`）：
  用户说的"黑块"**两列都在**。
  ⇒ 结论一：**这不是 `ink` 皮肤的渲染错误**，是件自己的表达在 `ink` 下被放大成"坏掉的样子"。
- 黑块是什么：件把**正文墨色当成了"面"**——
  `filter-chips` 选中片、`sort-toggle` 选中项、`window-picker` 选中档、`number-stepper` 选中预设、
  `step-flow` 已完成圆点与连接线、`punch-strip` 有数格、`scale-bar` 有数格。
- 顺带查到两处**不跟皮肤**的硬编码字面：`scale-bar` 超目标 `#a83228`、`punch-strip` 虚线 `#d8d2c2`
  与朱红描边 `#b3402b`。在 `ink` 下，`scale-bar` 的"正常档"（皮肤主色朱砂）与"超目标档"（死红）
  几乎分不开 ⇒ **语义丢了**。

## 二、第一性原理（为什么这是范畴错误）

1. **皮肤的存在理由**：同一份标记换一套语言。任何"选中／强调"的表达若把**观感写死**，
   皮肤就只剩换字色——换皮不换"选中长什么样"，皮肤就没干活。
2. **`ink` 的定义是"主文字"**（`skin/contract.ts`：`ink: 主文字（读数、标题）`）。
   拿**字色去当面**，等于把"反白"这种机器／仪表盘语汇硬塞进「纸面 ＋ 发丝线 ＋ 零投影 ＋ 2px 圆角」
   的语言里；在那套语言里，一块实心近黑矩形**没有对应的语汇**，只能读成印刷坏斑。
3. **契约早就为"面"备好了取值**：`accent`（非文本：条／边／底与大字）、`accent-soft`（强调软底）、
   `accent-ink`（强调底上的字）、`accent-text`（强调色的文本档）。契约的注里连"选中行"都点了名——
   `surface-2: 次要面（软底块、表头、选中行）`。
   ⇒ **选中＝强调（皮肤的主色），不是"反白"。**
4. **对比地板不许降**：新组合必须逐条算，读数写进判据（见第五节）。
5. **语义色不许被强调色顶替**：超目标／危险＝`danger`，达标＝`ok`，提醒＝`warn`。

## 三、法则（选中／填充四档，件只读 token、不认皮肤）

| 形态 | 取值 |
|---|---|
| **有文字的选中面**（片、档、段、胶囊，以及**格里有读数**的格） | 底 `accent-soft`；字 `accent-text`；描边 `accent`；✓ 与侧标 `accent`；字重 700 |
| **无文字的点／格／条**（勾选框、圆点、已完成连接线、进度填充、刻度格、"有／无"型的格） | 实底 `accent`（图形对比 ≥3:1 即可）。**这一档不许放正文**——理由见下面那条实测 |
| **整行／整块选中**（一行记录、一整个区块） | 底 `surface-2` ＋ 左侧 2px `accent` 侧标；行内主字仍 `ink` |
| **语义档**（超目标／逾期／危险／达标） | `danger`／`danger-soft`、`ok`／`ok-soft`、`warn`／`warn-soft`——**不许借 `accent` 或 `ink`** |

分界只有一条：**这块面上有没有正文级的字**。有字就走"软底＋主色字＋主色描边"（保住文本对比），
没字就走"主色实底"（图形对比足够，且最省视觉预算）。

**为什么"有字的格"也必须走软底**（实测，不是洁癖）：`accent-ink` on `accent` 在四套里是
paper 5.76／broadsheet 18.82／**neutral 4.02**／ink 5.15 —— neutral 那套**过不了 4.5 的文本地板**。
契约给 `accent-ink` 的定位是"强调底上的字色"，但那一档只保到图形级；所以**强调实底上只许放图形、
勾、大写字母级的大字**，正文（≤15px 的读数、标签）一律走软底那一档。`punch-strip` 的"有数格"
就是被这条纠正的：格里那枚 10.5px 读数是真字，故它从"无文字格"改归"有文字的格"。

## 四、禁止（判据会拦）

**判据落点**：`packages/base-render/test/组件样式纪律.test.mjs` 的「组件层样式纪律 ⑦」——
它不从源码字符串判，而是**调各件的样式函数、判产出 CSS**（与 ⑥ 同一口径），本层的件一件不漏（豁免名单里的冻结面除外）。

1. **禁止任何件用 `ink`／`ink-2`／`ink-3` 做 `background`**：字色只做字。
   **判据口径**：只有"`background` 的值**整个就是**墨色 `var()`"（如 `background: var(--ilife-ink, var(--fg, #1d1d1f))`
   或 `background: var(--fg)`）才判红——也就是"实心墨块"这一种。**淡洗不算**：
   `color-mix(in srgb, var(--ilife-ink) 13%, var(--ilife-surface))` 这类把墨色**掺进**面里的写法是合法的面
   （`skeleton` 的占位块就这么用），不判。
2. **禁止件样式里出现不在兜底链里的颜色字面量**：判据把产出 CSS 里所有 `var(...)`（含嵌套）剥掉，
   剩下的 `#rrggbb`／`rgb()`／`hsl()` 一律判红。兜底链 `var(--ilife-x, var(--old, #fallback))` 里那一处是**允许的**
   （老页面零接线要用它）。
3. **禁止皮肤层写件级选择器**：皮肤只给取值（`.ilife-skin-<名>{--ilife-…}`），不写 `.ilife-block-*`。
4. **禁止把"选中"写成"反白"**（`background: ink; color: surface`）——这正是本次要清掉的写法。

## 五、对比地板（实施后逐条算，读数进判据）

必须成立（新增的这一批）：

| 组合 | 用途 | 地板 |
|---|---|---|
| `accent-text` on `accent-soft` | 有文字的选中面 | ≥4.5:1 |
| `accent-ink` on `accent` | 强调实底上的字（若用到） | ≥4.5:1 |
| `accent` vs `ground`／`surface`／`accent-soft` | 无文字的点格条与描边 | ≥3:1 |
| `danger` on `ground`／`surface`／`surface-2` | 超目标／危险 | ≥4.5:1 |
| `ink`／`ink-2`／`ink-3` on `ground`／`surface`／`surface-2` | 三档文字 | ≥4.5:1（既有） |
| `ok`／`warn`／`danger` on `surface`／`ground`／自己的软底 | **语义色当字**（语义档的字就是这三支） | ≥4.5:1 |
| `ok` vs `danger`／`warn` vs `ok`／`warn` vs `danger` | 三支语义色互相分得开 | ≥1.2:1 |

**实测读数**（`accent-text` on `accent-soft` ／ `accent` on `accent-soft`）：

| 皮肤 | `accent-soft` 旧 → 新 | accent-text | accent |
|---|---|---|---|
| paper | `#f6f1e6`（＝surface-2，空转） → `#f7dfd8` | 6.18 → **5.47** | 5.20 → **4.60** |
| broadsheet | `#f4f1ea`（＝surface-2，空转） → `#e8e3d8` | 16.69 → **14.71** | 16.69 → **14.71** |
| neutral | `#eef4ff` → `#e4efff` | 5.16 → **4.90** | 3.64 → **3.46** |
| ink | `#f7e6df` → `#f6ddd3` | 5.81 → **5.42** | 4.51 → **4.22** |

**顺带修掉的一个空转 token**：`paper` 与 `broadsheet` 的 `accent-soft` 原本与 `surface-2` **逐字节同色**
⇒ 那两套皮肤里"强调软底"没有任何效果；而档位段 `-seg`、表头这些容器本来就是 `surface-2` 底，
于是选中片在里面**等于没有底**，只靠描边与字重撑（2026-09-24 由改 `window-picker` 的席位报出）。
`accent-soft` 的定义是"**accent 的淡洗**"——本就该与"次要面"分得开，故四套一律重定档，
并把这条钉进判据（见第七节末）。

**顺带修掉的第二个撞色**：`paper` 的 `danger`（#a83228）与 `accent`（砖红 #b5392a）只差 **1.14:1**
⇒ 那套皮肤里"超目标档"与"正常档"在观感上一个样，语义档白设（2026-09-24 由改 `scale-bar` 的席位报出）。
`danger` 压深到 `#8d2118`（vs accent 1.52:1、对 ground 7.54:1），并把"`danger` 与 `accent` 至少要差 1.2:1"
钉进判据。

| 皮肤 | `danger` vs `accent`（旧 → 新） |
|---|---|
| paper | 1.14（撞色） → **1.52**（起于本条；未再动） |
| broadsheet | 2.49 → **2.19**（「语义色当字」那一批把 `danger` 压深一档后重算） |
| neutral | 1.66 → **2.06**（同上：`danger` 压深一档后重算） |
| ink | 1.80（`danger` 未动） |

**顺带修掉的第三处踩线**：`accent-soft` 成了"全层选中面的底"以后，**弱字压上去**也要过 4.5——
paper 的 `ink-3` on `accent-soft` 只有 **4.48**（差 0.02，2026-09-24 由席位算出来报的），压深到 `#6b6154`
（on soft 4.77／on ground 5.15／on surface 5.96／on surface-2 5.38）。四套现状：paper 4.77／
broadsheet 4.52／neutral 4.57／ink 4.80，都过；判据已钉。

**补上的一处判据缺口：语义色当字**（2026-09-24 由对抗式审查席量出来，皮肤层判据席补齐）：

起因是 `neutral` 的 `ok`（`#1f8c3d`）当正文级字压在 `surface`（`#ffffff`）上只有 **4.31 < 4.5**，

`danger` 对 `accent`、`accent-ink` 对 `accent`、`ink-3` 对 `accent-soft`）**没有一条**管「语义色当字」。

## 六、皮肤集合（收敛到四套）

保留：`paper`（缺省，原型墙胜出者）／`broadsheet`／`neutral`／`ink`。
删掉：`terminal`（终端暗色）／`blueprint`（蓝图工程）——两套被用户整体否掉（51/51 全 `-`）。

**留下的一处"看着仍是黑"的地方，要说清**：`broadsheet` 的 `accent` 就是**墨黑**（`#14110d`）——那是这套
皮肤的**身份**（报刊的黑白语汇：强调＝加重的那一道黑），不是本次要清的"拿字色当面"。区别在**面上有没有字**：
本套的"有文字的选中面"现在走 `accent-soft`（浅暖灰）＋ `accent-text`（墨黑字）＋ `accent` 描边 ⇒ **不再是黑块**；
只有"无文字的点／格／条"（进度填充、中位线、刻度）仍是黑的——那套语汇里黑就是重音。看新件墙 C 列时按这条读
（2026-09-24 由新件席用像素扫描报出"C 页 126 个近黑块"，逐点只有 `#14110d` 与 `#3d372f` 两支，
即本套的 `accent`／`accent-text`；这不是件的问题，故**不动皮肤取值**）。

理由（第一性原理）：留下的每一套皮肤都是一份**承诺**——对比地板、判据、清单、README、维护成本。
**不能被选中的皮肤只剩负债**，且留在注册表里会诱人误用。删掉是可逆的（历史在 git 里）。
