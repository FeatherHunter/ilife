## 一、改了什么

### ① 折线族顶上两条账（`charts.ts`）

| 落点 | 内容 |
|---|---|
| `charts.ts:451-452` | 新增 `LINE_TICK_TOP_MIN = 21`、`LINE_PEAK_HEADROOM = 0.1`（取值来由写在 `charts.ts:429-450` 的注释里） |
| `charts.ts:380,392` | `Insets` 加 `minTop`；`insetsFor` 的 `top` 由 `padY + valueHeight` 改成 `Math.max(padY + valueHeight, minTop ?? 0)` |
| `charts.ts:519-537` | 新增 `lineDomainOf()`：`domainOf` 之上给**上端**补峰值余量，显式 `yMin`／`yMax` 原样返回 |
| `charts.ts:906,922` | `renderLine` 改用它取共享域；`insetsFor` 传 `minTop: tickN === 0 ? 0 : LINE_TICK_TOP_MIN` |

两条算式：

- **标注进框**：刻度文字的落点是基线 `y = ty + labelDy`，实渲文字盒高 ≈1.33em、基线以上 ≈1.04em。
  顶端那条（`i = count−1`）的 `ty` ＝ 绘图区上沿，旧留白只认 `padY + valueHeight`（`showValues:false` 时仅 8 用户单位），
  而 ≤720px 档字号是 20 用户单位 ⇒ 盒子探出 viewBox 上沿被裁。留白是双端共用的**用户单位**，
  故按**最大那一档字号**算：`ceil(1.04 × 20) = 21`。
- **峰值余量**：旧口径两端各外扩 6% ⇒ 峰值只离顶端刻度线 `0.06 ÷ 1.12 = 5.36%` 的绘图区高。
  新口径解 `(hi′ − max) ÷ (hi′ − lo) = r` → `hi′ = (max − r·lo) ÷ (1 − r)`，`r = 0.1`（复审给的判据是 8–12%），
  下端 6% 不动。**显式 `yMax` 不补**：域的边界是调用方的语义（「画到这儿」）。

### ② 表格宽度上限（`blocks.ts:1518-1531`）

```css
.ilife-block-data-table {
  margin: 16px 0;
  overflow-x: auto;
  border: 1px solid var(--line);
  border-radius: 12px;
  background: var(--card);
  max-width: 680px;      /* ← 本票新增 */
}
```

- 只加**一条**声明，加在**基座规则**里（不另开 `@media`）：`max-width` 只在可用宽超过它时才生效，
  窄屏（≤640 档列宽远小于 680）本就不触发 ⇒ 512 档逐值不变；也免得同一条基座规则被写第二遍
  （`ui-fix-154` 的「基座规则恰 1 条」守卫就是防这个 —— 试过写成 `@media (min-width: 641px)` 段内一条，
  该守卫立刻 `实为 2` 变红）。
- 卡**左对齐**（不居中）：左缘是全页的主对齐轴（页壳／KPI 栅格／图表卡／复制区一律 `left=20`），
  收窄后的卡仍与它们同线；右缘留给空白，不新增一条对齐轴。

## 五、与票面不一致处（如实记账）

1. **票面说「有 `yMax` 时不加 pad 导致峰值贴顶」——本页的折线并没有传 `yMax`。**
   真产物里这条折线只有 `yTicks`／`labels`／`format`，共享域走的是 `domainOf` 的**两端各 6% 外扩**
   （实测刻度 87.66／669.5／1251.34 ＝ 数据 150..1189 各外扩 62.34）。所以贴顶不是 `yMax` 分支造成的，
   而是「对称 6% 时上端只剩 5.36% 余量」。改法照票面要的结果做（补上端余量），落点仍在这一带；
   顺带把显式 `yMax` 分支的反向账写进用例（显式域照抄、不补余量）。
2. **复审引的「中缝 305px」与本票量法不同**：复审记的是「日期列右缘 137.2 → 首个数字左缘 442.2」，
   本票量的是「日期**字形**右缘 123.2 → 首个数字**字形**左缘 516.13」＝ **392.93px**。
   两法量的都是同一处空档，本票一律用后一种（`Range` 取字形盒），改前改后同一把尺子。
3. **820 档比票面多给了一档**：票面要 512／820／1000／1440 四档，复审只报了 512 与 1000／1440；
   820 档改前 `relTop = −2.78px`（也在裁），改后 14.03px。
4. **表卡收窄后右缘与其它区块不再同线**（卡宽 680 对内容列 960）：这是收窄的必然结果。
   左缘（主对齐轴）保持同线；未选「居中」（复审也提了这一条）——居中的话表卡左缘会离到 160px，
   与页壳／KPI 栅格／图表卡／复制区的 `left=20` 断掉。
5. **数值列仍偏宽**（281.94px 对内容 ~28px）：上限只压到「三列读起来均匀」这一档（中缝 253.93 ≈ 列宽量级）。
   再收要动表宽上限本身，属另一票的事。
