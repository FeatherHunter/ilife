# base-render 单据族组件（纸面 ＋ 主数字头 ＋ 刻度条 ＋ 账目行 ＋ 明细行 ＋ 打孔格带）

用户 2026-09-24 认可两套原型（`.scratch/diet-ui-proto/v2-小票.html`／`v2-大字.html`）后下的指令：
「将里面有价值的组件封装成 base 库的公共组件，单独有自己的目录和源码。需要封装时考虑到质量、拓展性、参数能力等。」

本文记**抽了什么、为什么这么切、出口走哪条路、怎么验**。组件本身的用法住各自目录的 `README.md`（本文不重复抄）。

## 一、抽了哪六件（一族六目录）

| 目录 | 出口 | 替掉的错法（原型里真实存在的丑法） |
|---|---|---|
| `src/components/sheet-frame/` | `renderSheetFrame`＋`sheetFrameCss`＋**`sheetCss()`（族样式汇总）** | 每张同族页各写一套纸面样式；拿"卡片"当"纸"（卡里套卡） |
| `src/components/summary-head/` | `renderSummaryHead`＋`summaryHeadCss` | 同一个数在首屏说两到三遍；主数字与目标同级同字号 |
| `src/components/scale-bar/` | `renderScaleBar`＋`scaleBarCss` | 只给一个 `46%`（读者没法逐格数）；超目标时形状不管 |
| `src/components/ledger-rows/` | `renderLedgerRows`＋`ledgerRowsCss` | 「标签：值」用冒号串（值列参差不齐）；用表格装两列清单 |
| `src/components/entry-rows/` | `renderEntryRows`＋`entryRowsCss` | 一条记录写成一整句；用七列表格装"一条记录" |
| `src/components/punch-strip/` | `renderPunchStrip`＋`punchStripCss` | 逐日只说一句「有记录 1/7 天」（报得出数量、报不出哪几天）；用折线讲 7 天日级读数；逐日做成六列表（窄档卡片化成一列七块） |

**族人**：六件都在同一张纸上成立（同一份纸边、同一套小标题字距、同一档行距），所以 `sheetCss()`
汇总六段的样式，调用方一行挂全族（与 `pageShapeCss()` 汇总导航族／横条族同一条口径）。

## 二、为什么这么切（不是按原型里的块名切）

- **按"数据形状"切，不按"视觉位置"切**：原型里的小票页有"账目块"与"明细块"两块，大字页有"事实三格"——
  但它们的数据形状只有两种：**一列标签→值**（账目行）与**一条记录一行**（明细行）。切在数据形状上，
  大字版把账目行换成三格排版也不用换组件。
- **同一份数只许一条路**：值／目标这一份数，三个原型形态（条形码／细线／刻度尺）都收在 `scale-bar`
  一件的 `variant` 里，**不立三个组件**（"一个概念在公共面上只留一条路"，见 `#950` 收口那条裁定）。
- **印章不另立组件**：它是"这一页要注意的那一处"，只在主数字头的脚行出现；另立一个"徽标"组件
  就是给同一件事开第二条路（`renderStatusBadge` 已经是"态"的形状）。
- **无运行时的组件不设 `attrs.ts`**：那条目录规矩的用途是「渲染与运行时共用同一份事实」，
  本族五件都是纯标记产出（零 DOM、零内联脚本），没有第二个读者。

## 三、出口走哪条路（不动冻结面）

- 从 **`base-paint/blocks`** 出（`src/blocks.ts` 末尾 `export * from './components/index.js'`，
  本族五件在 `src/components/index.ts` 各加一行）。
- **不进根出口**（`src/index.ts`）⇒ `SPEC_FROZEN_SURFACE` 与契约签名测试一个字都不用动。
- 判据件里有一条专门钉这条：`root.renderSheetFrame === undefined`（层规：组件层不入冻结面）。
- 样式 scope 在 `.<prefix>page-ui` 之下 ⇒ 不开 `pageUi` 的页**零命中**；开 `pageUi` 但没挂
  `sheetCss()` 的页也零变化（加法式的机械保证）。

## 四、参数能力（扩展性）要点

- `sheet-frame`：`variant`（素纸／小票纸）／`notch`／`cutLine` 三个开关，**两枚装饰都不占版面**
  （撕口圆心落在纸边线上、裁线是纸底一条虚线）⇒ 开关不改任何列的 x、不加页高。
- `summary-head`：`size`（40／56／92px）× `face`（无衬线／衬线）= 六档，**只改字号与字面**，
  槽位与盒模型不动（同一页换档不重排）。
- `scale-bar`：`variant`（条形码／细线）＋`cells`（4–64 格）；两形态根高一致（换形态不跳版）。
- `ledger-rows`：`kind`（普通／合计）＋`leader`（点线／不画）。
- `entry-rows`：五个槽位各自可选 + `absentLine`（"缺了哪几餐"是**没什么**，不是一条记录）。

## 五、怎么验（判据）

- 判据件：`packages/base-render/test/sheet-family.test.mjs`（32 条，六组）。
  四类断言：① 形状（类名与结构）② 边界（空数组／越界／非法枚举／非对象入参 ⇒ `BlocksError`）
  ③ 样式纪律（非空、scope 在 `.ilife-page-ui`、无 `:root`／`!important`／Q14 禁入 token、不新立 token 名）
  ④ 层红线（`dist/components/**` 剥字面量后零 DOM；只从 `blocks` 出、根出口没有）。
- 几何不变量写进样式段常量并在判据里对账：`SUMMARY_HEAD_VALUE_PX`／`SCALE_BAR_DEFAULT_CELLS`／
  `ENTRY_ROW_TIME_MIN_WIDTH_PX`／`ENTRY_ROW_NOTE_INDENT_PX`。
- 编译：`node node_modules/typescript/bin/tsc -b packages/base-render/tsconfig.json` → `TSC-EXIT=0`。

## 六、与"目录化批次②"的关系（并行席位）

同一工作区里另有席位在做目录化批次②（`src/pageShapes.ts` → `src/components/page/**`、
`src/pageUi.ts` → `src/components/page-ui/**`）。本族**一行都不碰**那两处：
既不进 `pageShapeCss()` 的汇总链（本族自带 `sheetCss()`），也不给 `renderDayStrip` 加形态
（"时间格带"那一件归批次①的 `page-bars`，要加形态在那一边另说）。
动 `src/components/index.ts` 时只加行、不重排（批次纪律）。
**2026-09-24 追加一句**：原型那排「这 N 天」**没有**做成 `renderDayStrip` 的一个 `variant`——
两者虽同讲"N 天"，但一个是**一行提要**（日期＋圆点＋值，带一行事实）、一个是**一排打孔格**
（值进格、选中套红圈），共用输入但标记与几何全不同；塞进同一个函数等于把两件东西焊在一起，
且 `page-bars` 是全仓共用的根出口件（改它要惊动别的域）。故按第七节另立 `punch-strip`。

## 七、2026-09-24 保真轮（用户四条缺陷里的 ① 与 ④）

出处＝用户原话「从第一性原理出发，对抗式审查下，将 11 个场景的 UI 风格都按照原型处理好」。

- **① 数字「0」不是同一个字体**（用户连问两轮「为什么数字 0 还是不变」）。
  上一轮只把**纸面正文**栈按原型排了序（Windows 命中雅黑），数字仍继承正文字面。
  真因：**原型给数字另写了 `--mono`**（`.total .n`／`.line .v`／`.item .t,.g,.kcal`／`.code-row .pct`／`.punch`），
  Windows 上命中 **Consolas，它的 0 带一条斜杠**。证据＝1200×900 截图按原始像素裁剪放大后的对比：
  样张 860 的 0 **带斜杠**、落地页 860 的 0 **是完整椭圆**（`.dsh-vision-router` 裁图），
  低分辨率整页视图看不出这处差异（同一对比里整页视图判成"相同"）。
  改法＝两条栈一起照抄原型，落在一处（`src/components/shared/typography.ts` 的
  `PAPER_SANS_STACK`／`PAPER_MONO_STACK`），**正文归 sans、八个数字位归 mono**：
  `summary-head` 的值与分母／`ledger-rows` 的值／`entry-rows` 的时间·克数·值／`scale-bar` 两端读数／
  `punch-strip` 的日期与格内值。真机复核（无头 Chrome ＋ CDP，390 档，`getComputedStyle`）：
  八个槽位的 `font-family` 全部＝`ui-monospace, SFMono-Regular, "SF Mono", Menlo, Consolas, …`。
- **④ 样张右侧那件「这 7 天」控件**：落成第六件 `punch-strip`（`.punch` 一族逐字对照）。
  接线在 `src/render/dietDocs.ts` 的 `buildViewDietDoc`：**刻度条与账目之间**（原型顺序：
  刻度 → 这 7 天 → 账目）；窗口 ≤7 天＝整窗都在格上（标题「这 N 天」），更长的窗口格上只放
  **最近 7 天**（标题「近 7 天」），整窗逐日的清单仍住「按日汇总」账目行；单日窗不出格带。
  红圈＝这一页正在细看的那天（餐别分布落点日），那天没记录就退到**最近一个有记录的天**
  （原型那枚红圈永远套在实心格上）。**一处有意偏离**：缺数格写 `—`（原型是空格）——
  同页自己的口径行就写着"缺值一律写成 —"，`emptyMark: ''` 可一键退回原型的空盒。
- **形状判据**：格宽走份数（`flex: 1 1 0`）⇒ 总宽恒等于容器宽。真机实测（390×760，CDP）：
  视口 390／文档 `scrollWidth` 390（**零横滑**）、`overflowing: []`；纸面 16..374，格带 37..353
  （七格 37..77…313..353，格宽 40–46px）。样式段常量：`PUNCH_STRIP_BOX_HEIGHT_PX`／
  `PUNCH_STRIP_BOX_RADIUS_PX`／`PUNCH_STRIP_MAX_CELLS`（14 格上限，超了顶 `BlocksError`）。
- 判据件：`packages/base-render/test/sheet-family.test.mjs`（32 条）＋ 消费侧
  `test/diet-list-t271.test.mjs`（骨架含格带）／`test/551-diet-subtitle.test.mjs`
  （② 与 ④ 两条判据随版式改成"小标题节点零债"与"格带份数宽"）。
