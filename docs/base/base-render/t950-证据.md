### 10.1 `renderChipRow` 同名两实现（**待裁定**，本次未擅改）

- **事实**：`base-paint/blocks` 早有同名一件（`blocks.ts:635`，`#728`；入参 `{ items: [{ text }], tailHtml? }`，
  产出容器类 `ilife-block-chip-row`）；本批又在根上立了**第二件**（`pageNav.ts:80`；入参
  `{ chips: [{ label, tone? }], role?, extraClass? }`）。两件**入参形状不兼容**、**类型名同为 `ChipRowInput`**、
  **产出的容器类名相同**。
- **为什么这是真缺陷**：同一个容器类的样式因此在两层各定义一次——`blocks.ts:1878` 的
  `.ilife-block-chip-row { margin: 0 0 8px }`（特异性 0,1,0）与 `pageNavCss.ts:23` 的
  `.ilife-page-ui .ilife-block-chip-row { margin: 0 }`（0,2,0）。同属性同元素，页面层那条**必胜**：
  在开 `pageUi` 且调 `pageShapeCss()` 的页上，既有 `blocks` 消费者的胶囊行**悄悄丢了 8px 下边距**。
- **当场读数（给影响面定界）**：
  - 调用点 **8 处 / 7 个文件**（skill-bill ×4、skill-chef ×3），**全部**从 `base-paint/blocks` 引、**零处**从根引
    ⇒ 本批**没有踩响任何既有页面**，是**埋着的坑**：谁把 import 从 `base-paint/blocks` 改成 `base-paint`
    （README「速查三问」原先正是这么指路的），调用会当场抛 `bad-input`（新实现读 `input.chips`，读到 `undefined`）。
  - CSS 那半：`skill-bill` 不调 `pageShapeCss()` ⇒ 不受影响；`skill-chef` 受影响，但它自己的皮肤里已有
    更高特异性的 `chip-row` 规则（如 `cook/page-css.ts:124` 为 0,3,0），**(0,2,0) 那条只在 chef 未覆盖的
    上下文里夺权**——可见位移量未经实拍，故这里只报「级联层已夺权」，不报「肉眼可见」。
- **三解**：
  - **A**：**只留一件**——`tone?` 并进 `blocks` 的 `ChipItemInput`，`role?`／`extraClass?` 并进它的
    `ChipRowInput`，语气 CSS 落 `blocksCss`，根出口转出**同一实现**，删掉 `pageNav.ts` 的第二个实现与
    `pageNavCss.ts` 那两条 `chip-row` 规则。新参数缺省 ⇒ 既有 8 处调用点**逐字节不变**（不给即逐字节相同）。
    代价：`blocks.ts` 再多几行（该件已超线、已有拆法声明）。
  - **B**：两件都留，把根上那件**改名**，README 分别指路。代价：同一件事两个名字长期并存。
  - **C**：维持现状，只在 README 挂警戒块。代价：把坑留给下一个人。
