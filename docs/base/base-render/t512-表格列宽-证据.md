## 一、改了什么（`blocks.ts:1603-1608`，注释 `1588-1602`，数据表样式区）

```css
@media (min-width: 641px) {
  .ilife-block-data-table td.ilife-block-data-table-cell-left:first-child {
    width: 1%;
    white-space: nowrap;
  }
}
```

`width:1%` 把该列的**目标宽**压到最小，`nowrap` 让它的 `min-content` ＝ `max-content` ＝ 内容自然宽，
两下一夹，列宽**恰好收在内容上**；余下的整段行宽由 `table-layout:auto` 归 auto 的数值列。

三条取舍（都按上面这段的注释落盘）：

| 取舍 | 为什么不那么做 | 机器读数 |
|---|---|---|
| 只钉**行首列**，不钉所有 `cell-left` | 本层没有「这一列是日期」的信号（`left` 是缺省，表里人人 `cell-left`），行首是唯一既有信号；把所有 left 列一律钉住会把「左列装长文本」的表整表重排 | 账单候选表（真产物，5 列）：数值列由 **99.11px → 375.22px**；且 `nowrap` 拿掉长文本列的折行兜底 |
| 只在**桌面档**（`min-width:641px`，640 断点的桌面侧，不新增断点值） | `nowrap` 与 ≤640 档 #457 的「靠折行换不横滚」硬碰 | 512 档：所有 left 列钉住的版本在**真账单页**上容器横滚 **12px**（478 → 490.48）；本版 0 |
| 不改数值列自己的规则 | 「数值列的**下限**」（#507 的 `min-width:5.5em`）与「数值列的**余量**」（本票）是两件事 | 数值列规则里 `width*` 命中数 = 0（用例 ③ 断言） |

**试过但否掉的两条**（同一探针、同一页）：

- `width: max-content`：Chrome **不认**表单元格上的这个关键字，三档读数与改前**逐值相同**（等于没改）；
- 数值列 `width:45%`：把行首列挤到 95.81px ⇒ 820／1000／1440 三档**日期列折行 7 格**。

## 五、与票面不一致处（如实记账）

1. **票面引的 415px 是另一版日期串长法**：那一版日期格是满长 `2026-09-07（今日）`
   （`.scratch/t507/看今日主页.html`，改前代码出的旧产物）；本轮真出口重出的页日期格是 `09-07（今日）`
   （另一席改过页面日期长法），故改前基数是 353.02px，不是 415.23px。**两种内容都量过**，
   收窄结论一致：415.23 → 152.25（满长）／353.02 → 116.13（短式）。
2. **820 档行首列只占表宽 15%**（116.13px；其余两列各 330.94px）—— 按内容给的结果，不另设最小宽；
   改前同档是 286.69px，即行首列原本随档位一起变宽。
3. **数值列变很宽**（1000／1440 档 420.94）是票面要的「数值列占余量」的直接结果；若后续要收，
   属另一票的事（本票不动数值列规则）。
