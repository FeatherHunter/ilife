## 一、改了什么（只写声明路径）

1. `packages/base-render/src/blocks.ts`
   - `ParamFieldInput` 加 5 个可选字段（旧五字段一字未动）：`readonly?: boolean`／`step?: string | number`／
     `min?: string | number`／`max?: string | number`／`options?: readonly string[]`。
   - `renderParamForm`：`readonly:true` → `<input>` 落裸 `readonly`；`step／min／max` 落同名属性，
     任一出现即补 `type="number"`（无它浏览器不执行数字约束）；`options` 给了即渲染 `<select>`
     代替 `<input>`（`value` 命中项 `selected`；`hint` 化作首项 `value=""` 禁选占位；
     `readonly` 化作 `disabled`，因 `select` 无 `readonly`；与 `step／min／max` 互斥）。
   - 校验（`bad-input`）：`step／min／max` 非数字串／非有限数、`step <= 0`、`min > max`、
     `options` 空数组／空串项／与数字约束同给，一律抛。
   - 旧调用（全不传新字段）走的老字串模板逐字保留：`type`／`readonly`／`step／min／max`／`select`
     四段全为空串 → 与改前逐字节一致（判据见 §二）。
2. `packages/base-render/test/blocks.test.mjs`：只在 B-09 段后追加 `describe('B-09 表单只读与步进约束（#397）')`
   5 条新用例；`:325-338` 既有断言一字未动。
3. 本证据件＋`docs/base/base-render/t397-gate-runs.md`（运行记录导出，对账源）＋`.changeset/t397-param-constraints.md`。
