# 数据族：规格

- **出处**：2026-09-25 与维护者 grill 定案。本文**只记数据族**。
- **适用**：六个技能共用一套规则——`skill-calorie`／`skill-bill`／`skill-schedule`／`skill-home`／`skill-chef`／`skill-memo-ilife`。卡路里先行，其余照抄。
- **状态**：架构与语法已定；文末「待复核」两处尚未显式复核。
- **关系**：本文管数据族一族；命令面的另两族（视图族／写族）不在本文。[技能调用契约.md](技能调用契约.md) 管「怎么调」，[命令登记纪律.md](命令登记纪律.md) 管「加改命令怎么登记」，[技能侧与插件侧-分层与职责.md](技能侧与插件侧-分层与职责.md) 管分层与归属。

## 一、是什么

**数据族＝命令面上的一族读命令，把库里的行（事实）按一张查询单交给程序消费**（插件为主）。

四个定义性特征：

1. **只读**；写是另一族的事。
2. **不生成 HTML，也不生成任何文件**（没有"要页"的消费者）。
3. **不给模型看**：不进技能说明面（SKILL.md 速查表），不进唤醒词路由；插件程序看得见。
4. **允许返回空集**；空是事实，不是错误。

**边界**：需要业务定义才算得出来的派生量（今日缺口、TDEE、连续记录天数、达标率、异常点……）**不住在这一族**——它们的唯一产地是视图族。

## 二、键（每个技能两条）

| 键 | 作用 |
|---|---|
| `<技能>.data.query` | **引擎键**：吃一张查询单（或一组），回结果集 |
| `<技能>.data.schema` | **目录键**：回「允许暴露的表 ＋ 各表列与类型」，与校验用的是同一份 |

例：`calorie.data.query`、`calorie.data.schema`、`bill.data.query`……

## 三、查询单（结构化 JSON）

查询模型是**结构化查询单**，不是 SQL 文本，也不是每命令自定义参数。理由：可机械校验（表名对着目录、字段对着该表真实列）、跨六家同形、可原样回显、无注入面。

```json
{
  "queries": [
    {
      "id": "近30天体重",
      "from": "weight_log",
      "join": [{ "table": "user_profile", "type": "left", "on": [{ "left": "user_profile.id", "right": "weight_log.id" }] }],
      "select": ["date", "weight_kg"],
      "where": { "and": [{ "field": "date", "op": "gte", "value": "2026-09-01" }] },
      "groupBy": ["date"],
      "agg": [{ "fn": "avg", "field": "weight_kg", "as": "avg_kg" }],
      "orderBy": [{ "field": "date", "dir": "desc" }],
      "page": { "size": 500, "next": null }
    }
  ]
}
```

| 成员 | 含义 |
|---|---|
| `id` | 可选，调用方自己的标识，原样回在结果里 |
| `from` | 表名，必须在该技能「允许暴露的表」里 |
| `join` | 连接；**语法层同时留两种写法**——显式 `on`（先做）与预定义关联路径（后续加法式扩） |
| `select` | 取的列；缺省＝该表全部可暴露列 |
| `where` | 条件；`and`／`or` 组合，操作符按字段类型校验 |
| `groupBy` | 分组 |
| `agg` | 聚合：`sum`／`avg`／`count`／`min`／`max` |
| `orderBy` | 排序 |
| `page` | 页大小与续取凭据（`next` 由上一次结果回传） |

**单表查询与跨表查询都提供**；一次调用只进**一个技能**的出口，所以「跨表」是一库之内的跨表，跨技能取数仍需多次调用。

## 四、返回（`shape: resultset`）

```json
{
  "shape": "resultset",
  "data": {
    "results": [
      {
        "id": "近30天体重",
        "ok": true,
        "query": { "…": "本次查询单原样回显" },
        "fields": [{ "name": "date", "type": "TEXT" }, { "name": "weight_kg", "type": "REAL" }],
        "rows": [{ "date": "2026-09-25", "weight_kg": 70.5 }],
        "total": 12,
        "next": "不透明凭据"
      }
    ]
  }
}
```

四条规则：

1. **`results` 与请求一一对应、同序**，每项回显自己那张查询单；
2. **单项失败不毁整批**：未知表／未知字段／条件非法／该项执行失败，都在**那一项**里回 `{ "ok": false, "error": { "code": "…", "message": "…" } }`，其余项照常跑完（请求级错误——不是对象、不是数组——才非 0 退出）；
3. **`next` 是不透明凭据**：调用方当黑盒，据此续取；实现按查询类型自选（行查询走游标、聚合查询走偏移）；
4. **「不设上限」的确切含义**：不限**总共能取多少**（靠 `next` 一直续取），但**单次响应有页大小**——否则一次查询就能把宿主进程的内存与 stdout 拖死。

`resultset` 是**新增**的 envelope 形状，六家共用；写进公共层正本（`packages/base-link-core/src/envelope.ts` 的 `ENVELOPE_SHAPES`），并同步 `base-render` 里的那份拷贝与契约签名判据。因数据族不渲染，五家 `render/html.ts` 的形状 switch 不受影响。

## 五、目录白名单

| 部分 | 从哪来 |
|---|---|
| **表清单**（允许暴露哪些表） | **各家显式声明** |
| **列目录**（那些表有哪些列、什么类型） | 运行时 `PRAGMA table_info` **现读**，不维护第二份清单 |
| 目录键 `<技能>.data.schema` | 把上面同一份回给调用方（校验用的目录与返回的目录是同一份，不会两处漂移） |

**表清单必须显式、不能"库里有什么就给什么"**，理由有据：居家管家的 `accounts` 表含 `encrypted_password` 列，配套还有主密钥文件 `.master.key`（`packages/skill-home/src/fetch/paths.ts:23,73-83`）；六家库里还有 `is_deleted`／`is_backfill`／`xunji_localid`／`seed_key` 这类内部列，以及"旧表改名保留"的老表。

## 六、实现归属

| 内容 | 住哪 |
|---|---|
| 查询单解析、目录校验、结果集装配、`resultset` 形状、错误语义、登记位 | **公共层**（`base-link-core`：它已是 envelope／registry／runner／校验的家，六家都是它的运行时依赖） |
| 表清单、库落点 | **各技能自己的包**（表与列本来就在各家 schema 里） |

若不共用，这一族会重演现有的老毛病：六份各自实现的参数解析与交付装配（现状：六份 `params.ts`、六份交付件，只有落盘那一小件共用）。

## 七、登记（不给模型看）

- **主做法 ①**：声明里加**显式标记**（如 `surface: 'program'`），生成器据此把它从**速查表**与**唤醒词路由**里跳过。
- **兜底 ②**：按键前缀约定（`<技能>.data.*`）排除。

落地要点：生成器是**六份**（每家一个 `scripts/gen-cli.mjs`，根 `gen:check` 串跑），且生成物与声明形态在六家不齐（bill 只出 registry、chef 只出 keys、schedule／home／memo 出 keys＋registry）；`example` 必填，`wakeWord`／`flows` 可缺。

## 八、错误

- 沿用现状：**退出码分档 ＋ 非 0 时 stderr 一行报文**，不新增第二条错误通道。
- 数据族新增几条码：未知表／未知字段／查询单非法／内部错误。
- **单次响应内的单项错误**走第四节第 2 条（那一项里回错误对象），不改退出码。

## 九、落地顺序

**卡路里先行**：先做到能跑通、判据齐，再照抄铺另外五家。

理由：与仓库既有惯例一致；六家 schema 形态差异大（卡路里 11 表、bill 1 表、schedule 3 表、home 16 表、chef 17 表、memo 2 表且**包内无 DDL**），样板能先把共用件的边界撞出来。

## 十、验收读数（五条，全部机器可判）

1. 同一张查询单经数据族拿到的行，与直接对该库跑等价 SQL 的结果**逐字段相等**（含 `NULL`）；
2. **非法表名／非法字段被拒**，报文指出是哪一处；
3. **空集是合法结果**（`rows: []`、`total: 0`），不是错误；
4. **续取拼接**（用 `next` 连续取到的行拼起来）与一次性取完**不重不漏**；
5. **单项失败不毁整批**：坏项带错误、好项照常返回。

## 十一、待复核（两处按提案落，若与你的想法不同，改这一处即可）

1. **行以「列名→值」的对象给**（自描述、面板直接用），而不是「数组＋列名表」（更省体积）；
2. **`next` 作不透明凭据**（调用方不解它）。
