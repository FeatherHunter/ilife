# 视觉验收墙：技能 HTML／UI 的最终验收

**适用**：`packages/skill-*` 开头的技能，凡是产出 HTML／UI（结果页、过程页、回执页、HELP 页、预检确认页、任何落盘的 `.html`）。
**一句话**：这类技能的**最终验收**用**视觉验收墙**做 —— 把这一批产物铺成一页，人滚动看完再签字。

用词沿本仓既有口径（`docs/agents/wording.md`）：「验收」是正式词（票面五段的第 2 段就叫**验收命令**，见 `docs/agents/编排纪律.md`），本文不另造词。本文管的是**地图怎么切票、票面怎么写、收口要多出什么**；做法细则在 §6 起。

**怎么被读到**：仓根 `AGENTS.md` 的「视觉验收墙」一节是它的触发行，三条分支 —— 改到 HTML／UI、给这类图**切票／收口**、要**逐页审版式**（挤、塌列、被藏起来的横滚那类判据抓不到的缺陷）—— 命中任一条就来读本文。

---

## 0 先认清墙在验收链里的位置

技能的验收有五条路，缺一条都不算收口：

| # | 谁判 | 判什么 | 出口 |
|---|---|---|---|
| ① | 机检判据 | 真不真（数据、结构、文案） | 命令退出码 |
| ② | 机审判据 | 双端自适应、触摸目标、触屏三件、分隔符懒政、英文裸词、重复句 | 判据脚本的逐列读数 |
| ③ | 双端截图 | 「挤」「丑」这类判据抓不到的 | 截图 ＋ 逐页结论 |
| ④ | **人** | **最终验收** | **墙 ＋ 逐格缺陷清单** |
| ⑤ | 负责人 | 签字收口 | 签字 |

**墙是第 ④ 条的工具**：它把人的验收从「点开 N 次、每次看一页」变成「滚动一遍看全」。**墙不产出判据**——谁要机器读数，别去墙里要。

**为什么最终验收非墙不可**：真实缺陷里有整整一类（12 周时第 11、12 周被横滚藏起来；390 宽下 5 列表挤成竖条；回执页把内部函数名 `getPlan` 印上屏）**只有双端真渲染才看得见**，判据再全也照不到。

## 1 触发条件

**命中即整图带墙**：本图改动落在 `packages/skill-*/src/render/**`、任何产出 HTML 字符串的件、或页内样式（`*Css.ts`）、或页上可见文案。

**不命中**：纯数据层、纯命令登记、纯测试、纯文档。

**冻结一批产物**：动第一张票之前就定好——本图要出多少份产物、**各自的名称**（发布名规则）、谁生成。这份册子在后面每一张票里复用，不重定（见 §2）。

**完成的样子**：能说出「本图出几份产物、名字怎么来的、清单在哪」，且有票面写下了这句话。

## 2 切票：墙怎么进票面

地图设计者（`docs/agents/编排纪律.md`）照下面四条做：

1. **留一张收口票**：最后一张专门收口，票面的**验收命令**就是墙生成器的自检命令（`node <生成器> <产物目录> <输出名>`，绿＝退出码 0）。
2. **其余票各自加一条产出判据**：该票的产物必须在册子里、能被墙读到（跑生成器时它那格在）。
3. **先验形状**：形状没定的页（新交互、新控件）先切一张**原型票**，形状由人裁过再铺开 —— 别拿墙去验收一个还没定形的页。
4. **票面五段照旧**（`编排纪律.md`：目标、验收命令、不许动的东西、交付物路径、遗留出口），只加本图口径：交付物路径那一段写清本图产物落在哪个**产物目录**（墙与发布都从那份清单读）。

> **一条词义说明（别把两件事混成一件）**：票面「验收命令」是可跑的机器命令 —— 墙那条命令跑的是**生成器的自检**（exit 0／1）。**墙本身不是命令，是给人看的证据**：同一张收口票里，「自检 exit 0」进第 2 段，「墙 ＋ 逐格缺陷清单」进第 4 段交付物路径。

**完成的样子**：每张票的验收命令都能独立跑绿；收口票的验收命令就是墙的自检命令，交付物里写明墙与缺陷清单的落点。

---

## 3 收口：最终验收怎么走

按序，前一步不绿不进下一步：

1. **① 与 ② 全绿**。机检全过、机审六列 0 命中。
2. **发一批产物**：按 §2 预定的名称复制成「给人看的名字」，落进**同一个产物目录**（墙页与产物必须同目录，iframe 的相对路径才落得到）。
3. **出墙**：双端各一张 —— **手机墙 390 宽**（看塌列）、**桌面墙 1280 宽**（看排布）；格高一致。
4. **出索引**：总索引页按页面族分组，**末尾列清「哪些有意不出产物及其原因」** —— 这一段省掉最多追问。
5. **自检**：生成器的链接自检 exit 0，且**反例**也走过（见 §4）。
6. **人看**：拿真实浏览器滚一遍两张墙（双击文件即可，不起服务也照看），把缺陷**逐格**记下来。
7. **交出去**：墙 ＋ 逐格缺陷清单 ＋ 自检退出码，三样一起。

**完成的样子**：三样齐 ＋ 负责人能一页看完所有产物。

---

## 4 完成判据：墙这一票怎么算过

| 判据 | 怎么跑 | 绿的样子 |
|---|---|---|
| **正例** | `node <生成器> <产物目录> <输出名>` | 打印「N 格；链接 M 条；缺失 0 -> 可发」并 **exit 0** |
| **反例**（必跑） | 故意在清单里写一个不存在的文件名，再跑一次 | **exit 1 且点名那份** —— 走不出这条，说明自检永远不会红，等于没有 |
| **人看过** | 浏览器滚一遍两张墙 | 缺陷**逐格**成清单（哪一格、什么症状、要不要改）；看完没缺陷也算结论，但要说明**看了哪些格** |
| **格数对得上** | 墙页的格数 vs 清单条目数 | 相等，且少任何一件都有交代（在索引页的「有意不出」一节里） |

一条红线：**别把「墙出得来」当成「验收过了」**。墙是必要条件（没有它，人就只能抽查），不是充分条件。

---

## 5 证据件落哪

- **墙页与产物**：都落**同一个产物目录**（`.scratch/<票号或批名>/` 即可，不必入仓）。它们与生成器**要能重出**，不是交付物。
- **生成器脚本**：**入仓**（`docs/skills/<件名>/` 下、带票号或批名）。只活在 `.scratch/` 的生成器，下一批人用不上。
- **收口证据**：生成器跑一次的读数 ＋ 逐格缺陷清单 ＋ 负责人签字，落 `docs/skills/<件名>/`（同票号前缀）。
- **总索引页**：与墙放一起（同一产物目录）；它是给人的**细看入口**，不替代墙。

**完成的样子**：下一批人只跑一个命令就能重出这一批墙。

## 6 做法（细则与活样板）

### 6.1 两个前提

1. **清单**：机器可读的「哪份是哪个产物的哪一类页」（字段至少：序号、类型、标题、文件名）。没有清单就别让墙猜文件名。
2. **命名规则**：产物原名常不可读（`order176-result.html`），发布时按人读得懂的名字复制一份。**同一个名字只在一处算出来**——发布脚本与墙生成器要么共用同一份 `slug` 规则（逐字相同），要么清单里直接存最终的发布名；两侧不一致＝全墙集体死链。

### 6.2 生成器骨架（一个 node 脚本，无依赖）

```js
import { existsSync, readFileSync, writeFileSync } from 'node:fs';
import { join } from 'node:path';

const SRC = process.argv[2] ?? '<产物目录>';
const OUT = process.argv[3] ?? '<批名>-手机墙.html';
const W = 390, H = 820, COLS = 3;             // 格子尺寸 = 要量的那个视口；列数按格子宽定
const all = JSON.parse(readFileSync(join(SRC, '<清单文件>.json'), 'utf8')).rows;
const rows = all.filter((r) => r.file && existsSync(join(SRC, r.file)));
const dropped = all.filter((r) => !rows.includes(r));   // 清单点名、盘上没有 → 报出来，不静默剔

const esc = (s) => String(s).replace(/[&<>"]/g, (c) => ({ '&': '&amp;', '<': '&lt;', '>': '&gt;', '"': '&quot;' }[c]));
const cells = rows.map((r) => `  <figure>
    <figcaption><a href="${esc(r.file)}" target="_blank" rel="noopener">${esc(r.seq + ' ' + r.wake)}</a>
      <span>${esc(r.kind)}</span></figcaption>
    <iframe src="${esc(r.file)}" width="${W}" height="${H}" title="${esc(r.wake)}"></iframe>
  </figure>`).join('\n');

const page = `<!doctype html><html lang="zh-CN"><head><meta charset="UTF-8">
<meta name="viewport" content="width=device-width,initial-scale=1"><title>${esc(OUT)}（${rows.length} 格 × ${W} 宽）</title>
<style>
*{margin:0;padding:0;box-sizing:border-box}
body{font-family:-apple-system,BlinkMacSystemFont,"PingFang SC","Microsoft YaHei",sans-serif;background:#f5f5f7;color:#1d1d1f}
.wrap{padding:24px 20px 60px}
h1{font-size:22px;font-weight:600;margin-bottom:6px}
.sub{color:#6e6e73;font-size:13.5px;margin-bottom:20px;line-height:1.7}
.grid{display:grid;grid-template-columns:repeat(${COLS},${W}px);gap:18px;align-items:start;justify-content:start}
figure{background:#fff;border:1px solid #d2d2d7;border-radius:12px;overflow:hidden}
figcaption{display:flex;justify-content:space-between;align-items:baseline;gap:8px;padding:8px 10px;font-size:12.5px;font-weight:600;border-bottom:1px solid #e8e8ed}
figcaption a{color:#007aff;text-decoration:none}
figcaption span{color:#86868b;font-weight:400;font-size:11.5px}
iframe{display:block;border:0;background:#fff}
</style></head><body><div class="wrap">
<h1>手机墙 · ${rows.length} 格 × ${W} 宽</h1>
<div class="sub">每格是一份产物在 ${W} 宽下的<b>真实渲染</b>（可交互）。点标题在新标签打开整页。这一页给人看，不是交付产物。</div>
<div class="grid">
${cells}
</div></div></body></html>
`;
writeFileSync(join(SRC, OUT), page, 'utf8');

/* 生成完自己就查一遍：正例 exit 0；反例（清单点名却没有文件）必须 exit 1。 */
const refs = [...page.matchAll(/(?:src|href)="([^"#]+\.html)"/g)].map((m) => m[1]);
const dead = refs.filter((r) => !existsSync(join(SRC, decodeURIComponent(r))));
const clean = dropped.length === 0 && dead.length === 0;
const bad = [...dropped.map((r) => r.file), ...dead];
console.log('墙 ' + OUT + '：' + rows.length + ' 格；链接 ' + refs.length + ' 条；'
  + (clean ? '缺失 0 -> ' + OUT + ' 可发'
    : '缺 ' + bad.length + ' 件 -> ' + bad.join('、')));
process.exit(clean ? 0 : 1);
```

四个常量决定全部成品：**产物目录、格子宽、格子高、列数**。这段代码在两个用例上都跑过（正常 `exit 0`／清单点名缺件 `exit 1` 并点名）。

### 6.3 四条形制

1. **每格一件真产物，不塞缩略图**：`iframe` 里跑真 HTML——媒体查询按格子宽生效、页签能点、复制按钮能点。缩略图会把「窄屏塌列对不对」这件事量丢。每格标签里写：编号 ＋ 点开整页的标题 ＋ **一句「这一格该确认什么」**。
2. **成对出**：手机墙与桌面墙只有格子宽不同（390／1280），窄的 3 列排、宽的 1 列排。
3. **宽产物要缩小就整体缩**，别改视口：`const SCALE = W <= 500 ? 1 : Math.min(0.5, 600 / W)`，外面套一个 `overflow:hidden` 的定尺寸框、里面 iframe 用 `transform:scale()`。视口仍是 `W`（所以按 `W` 截的图与墙上看到的是同一版式）。算式实测：`W=390→1.000（390px）`、`W=1280→0.469（600px）`、`W=1440→0.417（600px）` —— 嫌小就调大那个 `600`，能并排的列数会跟着变少。
4. **能出墙就出，但几十格是舒适区**：墙页本身只有几 KB（实测 1,983 字节），重的是格子；12 格 × 各 6.1 MB 的嵌图产物（79.4 MB）0.8 秒画完。产物里带大图（见过 18.8 MB 一页）时**按页族拆成几张墙**，别凑一屏。

### 6.4 起点

**复制 `docs/skills/skill-calorie/t154-mobile-wall.mjs`**：它已经带着缩放、`auto-fill`、页族分组、内建链接自检；改两个常量（产物目录、清单文件名）就能用。**但它有个假绿灯**——先按「盘上有没有」过滤清单、再只查页面引用，于是缺件被静默剔掉、自检照样报「缺失 0」；照抄时把 §6.2 的 `dropped` 判据补上。

其余可用件：`t351-v11-mobile-wall.mjs`（最朴素的形制）、`.scratch/t351-preview/gen-scene09-wall.mjs`（把**机器读数挂上墙**，每格标出该页三档横向溢出像素）、`t351-v11-publish-preview.mjs`（发布 ＋ 总索引页，与墙生成器共用 `slug` 规则）、`.scratch/t351-preview/server.mjs`（只读预览台，双击打不开时的兜底）。

## 7 坑（看到这个症状 → 这么办）

| 症状 | 真因 | 处置 |
|---|---|---|
| 下半页格子永远空白 | 生成器给 iframe 加了 `loading="lazy"` | 别加；见到整片空白先查有没有它 |
| 截图里靠后的格子空白 | `fullPage` 整页截图只栅格化靠前的行 | 用浏览器滚动看；靠前的行在截图里正常，可自证 |
| 自检报「缺失 0」却是假的 | 缺件被过滤掉、只查了页面引用 | `dropped` 与 `dead` 一起判（§6.2） |
| 清单读出来 `Unexpected token` | JSON 带了签名（BOM） | 存不带签名的 UTF-8 |
| 格子里的样式全丢 | 产物引了外链 CSS／绝对路径／跨目录图片 | 产物必须与墙页同目录或单文件自足；点标题打开整页时最容易露 |
| 右边的格子看不见 | 横滚被藏（`overflow-x:auto` ＋ 隐滚动条） | 宁可换行铺开（`flex-wrap`／`auto-fill`） |
| 视觉模型说某格大片空白 | 它可能判对，也可能**编出产物里根本没有的页名** | **视觉模型是提示器，不是证据**——结论落到自己看过的图上 |
| 点进第二跳找不到文件 | 墙页在预览目录、产物在原目录，两边不是同一套副本 | 交付前把**整批**产物＋墙页复制到同一目录 |

**墙能验的地方**：版式、塌列、挤、层级、可读性、双端差异。
**墙不能验的地方**：数据对不对、命令键对不对、边界路径走没走到 ——那些归机检判据；**墙上看不出错 ≠ 对**。

## 8 收口自检清单

- [ ] 本图动过 HTML／UI？→ 命中触发条件（§1），本图带墙
- [ ] 图开始时就把本图产物册子（份数、名称规则、产物目录）写进票面
- [ ] ① 机检全过、② 机审六列 0 命中，才进墙
- [ ] 双端各一张墙（390／1280），格高一致；格数与清单对得上
- [ ] 生成器自检**正例 exit 0 ＋ 反例 exit 1 点名**都走过
- [ ] 生成器未加 `loading="lazy"`；清单不带签名
- [ ] 每格标签有编号、点开整页的链接、一句「该确认什么」
- [ ] 总索引页有「有意不出产物及其原因」一节
- [ ] 人用浏览器滚过两张墙，缺陷**逐格**成清单
- [ ] 墙 ＋ 逐格缺陷清单 ＋ 自检退出码，三样一起交；**没有墙不签字，有墙也不等于签了字**
