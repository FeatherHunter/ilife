# 照抄说明（一页以内，可直接贴给别的 session）

> 卡路里命令登记与分派的新形状由 `#293`（`#294` 接缝 ＋ `#295` 生成物）交付。
> 下面是**你搬自己那一段要照做的全部动作**。只读这份 ＋ `packages/skill-calorie/src/weight/` 就能开工，
> 不必回头问人。规矩的「为什么」与判据见 `docs/agents/命令登记纪律.md`。

## ① 新命令怎么写

在 `src/<你的能力>/commands.ts` 里加一行声明，六件事写全：`kind`／`key`／`shape`／`title`／`wakeWord`／`example`；
处理函数住同一个能力目录。**加一条命令要改的就是这一处加它那个子功能文件。**

- `example` **必填且非空，没有退回路径**（`wakeWord` 缺了会退回键名，`example` 不会）。
  它要**照抄即能跑**——生成期只拦空／缺，跑不跑得通由 `pnpm help:examples:check` 拦，而那道门今天带着票外既有红。
  **先在本地把示例跑通再提交**，别把恒红的门当兜底。
  示例与 `--params` 的形状是绑在一起的：**要参数的键不写 `--params` 照抄即 exit 2／4**（那正是它的来意）；
  照 `src/weight/commands.ts` 里同形命令的写法抄，别自己编参数名。
- 新起一个能力：`commands.ts` 里**恰好导出一个声明数组**（多导一个数组生成器即抛），并在该能力 `index.ts` 再导出。
- 参考实现：`packages/skill-calorie/src/weight/commands.ts`（9 条）＋ `src/weight/index.ts`（那道门）。

## ② 共用位什么时候才能动、动前要不要抢锁

共用位＝把各家声明汇到一处的那些文件（设计正本里叫「汇总位」，本纪律一律叫「共用位」——同一批文件）。
**哪些在名单里以 `pnpm gen:check` 的逐件输出为准**，别背名单。

| 情形 | 动作 |
| --- | --- |
| 日常加／改一条命令 | **零接触**共用位。它们由 `pnpm gen` 重生成，`pnpm gen:check` 守 |
| 新增一个能力 | 建 `src/<能力>/commands.ts` ＋ `index.ts` 转出 → **先抢 `gate.lock` ＋ 广播**，再跑生成链 |
| 改生成器／类型形状／底座 | 同上：**先抢锁 ＋ 广播**，这是框架级变更 |

- **生成物手改无效**：`pnpm gen:check` 比盘上文件与生成器输出，不等即红并指出第一处差异。看到红就改权威声明再 `pnpm gen`。
- **陈旧守卫会大声拦住你，但它自身的判据以生成器实际实现为准**：只改 `src/` 不 `pnpm build` 时，
  生成器读到的是旧 `dist/`，旧声明会被当成事实（假绿）——守卫就是拦这个的，报 `GEN-STALE FAIL` 时**照它给的医嘱先重建**。
  若照做后仍红，那是守卫自身的缺陷（`#295` 复审报过一条：判据曾按修改时间比较，正常动作刷新时间戳就会误报，
  且 `pnpm build` 解不开；见 `t295-复审-红队.md` 的 A4）。
  **别自己删文件、别改门**：报告编排者，并按下一条重建链重试。
- **生成链四步，少一步会静默停在旧键数**：`pnpm build → pnpm gen → pnpm build → pnpm help:build`。
  两次 build 各有用处：**第一次**把 `src/` 的声明编译成 `dist/`（生成器读的是编译后的模块，TS 不能直接被 node 引），
  并调 `--stamp` 给声明源打上内容印记；**第二次**把 `pnpm gen` 刚改写的生成物里那三件 TS
  （`cli/keys.ts`、`cli/registry.ts`、`triggers/routes.generated.ts`——`#313` 起最后一件才进 `pnpm gen`／`gen:check`）
  编译进 `dist/`，好让分派层读到新的键表、路由层读到新的路由表（另两件产物 `combos.yaml` 镜像与
  `scripts/build-help.mjs` 不经 `tsc`，故不在此列）。少任何一次都会按旧内容走。
  需要 `combos.yaml` 镜像连着更新时再跑 `node packages/base-combos/scripts/gen-present.mjs`。
- **抢锁一律走**：`node tooling/run-locked.mjs --ticket <你的票号> -- <命令…>`（口径见 `docs/subagent-concurrency-protocol.md` §2／§2.4）。

## ③ 撞车怎么办

- 开工前**声明自己会写的路径集合**（文件级），只写这些路径。
- **跨图撞车：停下报告，不自行改别人的行。** 尤其这几处是全场共用、谁都在写：
  - **路由声明**：住 `src/<能力>/routes.ts`（一能力一件，**动前抢锁**）。
    `src/triggers/routing.ts` 的记录面**已搬进生成物**（`src/triggers/routes.generated.ts`，生成器
    `scripts/gen-routes.mjs`：`pnpm gen` 写盘、`pnpm gen:check` 比对），日常**零接触**；
    `routing.ts` 自己**不承接记录数据**（只剩类型再导出与 `routesFor`／`routingSummary` 这类逻辑，不在生成器 `targets` 里），加／删唤醒词不动它；
  - 各能力目录之外的任何共用位。
- **未搬迁清单那一层住处已在 `#708` 退役**（`src/cli/legacy/` 23 件 —— 十个命令分片与十个路由分片
  ＋ 两个汇总件 ＋ 类型件 —— 连同它那把「只许变短」的棘轮一起删除，理由载
  `docs/adr/0002-legacy-ratchet-retirement.md`）。`#708` 之后加／删一条命令**只有一条路**：
  声明住能力目录两件（`src/<能力>/commands.ts` ＋ `src/<能力>/routes.ts`），其余全是派生。
  碰见老写法（改 `legacy/scene-NN.ts`、下调棘轮上限）就是拿到了过期说明——按票号找编排者要新形状。

## ④ 你恢复开工前，先做三件事

1. **`git pull`**——别人的生成物与棘轮已经入仓，基线不对后面全白做。
2. **看 `git status --short`**：**出现不属于你的路径就停下报告**——别 `git add`、别还原、别问都不问就往下干。
   那是别人的未提交工作。
3. **确认 `.scratch/locks/gate.lock` 不存在**——冻结期出过一次**锁龄 68 分钟的死锁**，
   它会让你的抢锁动作无限等待（抢回口径见并发协议 §2／§2.4，**别照抄旧脚本**）。
   见到锁且锁龄异常，先按协议判活再处置，处置完把结论报告编排者。

## ⑤ 四条会被你踩到的实测事实

- **搬迁 vs 新增，`test/` 下的改动面不一样**（别把这两句混起来读）：
  - **搬迁**一条既有命令 → `test/` 下 **0 件**必改（计数断言已改成与权威声明对账，键集一变自动跟上）；
  - **新增**一条命令 → 只写自己能力目录的声明：`commands.ts` 一条命令声明，要能被唤醒词命中就再在
    `src/<你的能力>/routes.ts` 里加一条路由声明，然后 `pnpm gen` 重生成——
    `src/triggers/routing.ts` **不必手改、也别手改**——记录住生成物 `src/triggers/routes.generated.ts`，
    它自己不承接记录数据（只剩类型再导出与 `routesFor`／`routingSummary` 这类逻辑）。
    `test/calorie-routing-81.test.mjs` 的路由覆盖断言仍守着这一条（覆盖数 ≠ 权威声明数即红），
    但它守的现在是**生成物**，不再是你手写的那一行。
- **写命令比读命令多一处**：加／删一条**写**命令，除上面的动作外还要补逐键落库断言
  （`packages/skill-calorie/test/cmd-write-40-persist.test.mjs` 的落库块）与
  `docs/research/t97-probe-receipts.mjs` 的场景行。这是 `#101` H2 覆盖门的既有要求，不是计数数字。
- **删命令会先撞类型门**：`RouteKey` 是编译期约束（类型唯一处 `src/triggers/routeSpec.ts`），
  删了声明不先动自己那份路由声明（`src/<能力>/routes.ts`／`src/cli/legacy/routes/scene-NN.ts`）
  就过不了 `packages/skill-calorie` 的类型门（红队实测：`TS2820`）。
- **命令集一变，还有几处 parity／快照要手跟**（都住在卡路里自己的测试与归档里，不是共用位）：
  `docs/research/t81-exec-smoke.md` 快照、
  `packages/skill-calorie/test/help-center-106.test.mjs` 的场景数、
  `docs/research/t97-probe-receipts.mjs` 的 `SCENARIOS`（加／删**写**命令时）。
  这些是既有 parity 证据，**不是计数数字**——别把它们改回去手写数字，也别删断言。
