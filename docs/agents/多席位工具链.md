# 多席位工具链（#1313）

一席一工作树（git worktree）的机械动作已工具化：建树、收回子工作树的改动、跑测试各一条命令，
另有现成的包级门禁 `tooling/gate.mjs`。四件都在仓库根执行，读数逐行机读、末行 `RESULT:`；失败给原因，不猜。

## 1. 建工作树：`node tooling/worktree-init.mjs`

`~bash
node tooling/worktree-init.mjs --path D:/ilife-wt-t1204 --branch impl/t1204
`~

做四件事：`git worktree add`（特性分支或 `--detach`）→ `pnpm install --offline --frozen-lockfile`
→ 写 `<树>/.scratch/README.md` 当该席位的落脚页（必读文档、编译入口、跑测试与收票命令）
→ 打一行读数 `WORKTREE path=… head=… branch=… base=… install=ok|planned|skipped|failed scratch=… existing=… dry=… ms=…`。

- 重复执行不会重建已注册的树（`existing=true`）；**是否重装依赖由安装状态决定，不靠 existing 猜**：
  每轮安装结果写进 `<树>/.scratch/worktree-init-install.json`（`install: ok|failed`）。
  上一轮 `ok` 才跳过（`install=skipped`）；上一轮 `failed` 或没有状态文件，就重试安装，仍失败则
  `install=failed`、exit 1 —— 不把「上次没装成」洗成 PASS。
- `--no-install` 是显式跳过（`install=skipped`，不读写状态文件），依赖由调用方自己负责。
- `--dry` 只打印将执行的 git／安装命令、不落盘：`install=planned|skipped`，`--json <file>` 仍会写
  （`dryRun: true`）；`--json` 的字段：`root/path/head/branch/base/existing/added/install/scratch/dryRun/durationMs/verdict`。
- 建树后先读 `<树>/.scratch/README.md`，不要从零摸仓库结构。
- 退出码：0 成功（或已存在且依赖就绪）；1 依赖安装失败（树已建好，可手补）；2 用法／前置不满足（目标非空、基线不存在）。

## 2. 收子工作树的改动：`node tooling/premerge-child.mjs`

`~bash
node tooling/premerge-child.mjs --child D:/ilife-wt-t1204 --base <建树时的 SHA>
`~

子树的改动常在集成树前进之后才收回来。**不要按「盘面上有变动的文件」直接覆盖**——那是拿子树的旧基线
覆盖集成树的新提交（历史上真实覆盖过常量的新增分支、场景接线与测试件）。本工具做三方合并：
base＝子工作树建树时的提交，ours＝当前树现状，theirs＝子树现状。

- **改动清单＝子工作树 `base..HEAD` 已提交的改动 ∪ 工作区未提交的改动**（两者都收）。
  只看 `git status` 会把「先 commit 再交回」的产出当 0 件放过（历史读数：copy=0 却 PASS）。
- 前置校验（不满足即 exit 2）：`--child` 与 `--root` 必须同一仓库（git common dir 相同）；
  `--base` 必须存在且是子工作树 HEAD 的祖先（子树可以前移，但不能拿别的基线来收）。
- 当前树该路径没动过（与 base 逐字节相同）⇒ 子树版本写回（新增／修改／删除照抄），
  普通文件保留 exec 位、符号链接按链接目标重建（不写成普通文件）。
- 两边都动过 ⇒ 文本跑 `git merge-file`；干净合入写回，冲突则把 ours／base／theirs 三个版本落到
  侧车（sidecar）目录，打 `CONFLICT path=… detail=…` 并以 exit 1 结束。
- **双方都删同一路径 ⇒ noop（不是冲突）。**
- 二进制、一边删一边改、双方各自新增同名、类型变化（普通文件⇄符号链接）⇒ 一律判冲突，不猜。
- **两阶段写回**：先把全部路径算成计划，只要有一处冲突，本轮**整棵树一个字节都不写**（只落冲突侧车）。
  `PRE-MERGE` 行的 `copy/merge/delete/noop` 是计划数，`applied=false`；JSON 另有
  `applied`、`actions`（`path/action/detail/sidecar`）与 `dryRun`。无冲突才进入写回阶段（`applied=true`）。
- `--dry` 只算不写，但冲突照样逐条打 `CONFLICT`、exit 1（侧车不落盘）。
- 缺省跳过 `.scratch/**` 与 `node_modules/**`；更多前缀用 `--skip a/**,b`。
- 冲突侧车缺省在 `.scratch/premerge-conflicts/<时间戳>/<路径>/{ours,base,theirs}`。
- 退出码：0 无冲突；1 有冲突（本轮未写回任何路径）；2 用法／git 前置条件不满足；
  3 内部错误（如 `git merge-file` 自身失败；本轮未写回，侧车可能已落）。

## 3. 跑测试：`node tooling/run-tests.mjs`

`~bash
node tooling/run-tests.mjs packages/base-render/test          # 一个目录（其下 *.test.mjs）
node tooling/run-tests.mjs packages/skill-bill/test/t689-页面指纹.test.mjs
node tooling/run-tests.mjs --all                              # 全量套件（与 pnpm test:suite 同一条路）
`~

**不要用 `node --test <多个 glob>` 跑全量。** 默认并行度会把多个测试文件同时拉起来，
而浏览器测试每件各起一个 headless Chrome——实测 15 秒内 382–473 个 chrome.exe，机器 thrash，
表现为「测试挂住／日志停滞／几百秒后被 kill」。

本驱动逐件开一个 `node --test`（缺省 `--jobs 1`）：每件一个墙钟（wall-clock）超时（缺省 10 分钟，
到点杀进程树、判 `timeout`；杀完必进收尾，等 `KILL_EXIT_WAIT_MS` 仍无 close 就强制返回，不把驱动挂死）。
TAP 打出末行汇总（`# duration_ms`）后进程仍赖着不退，则由完成守卫杀进程树并判 `hung`——
**hung 是独立结局，不是 pass**：它照常采信测试结果（pass/fail 读数来自 TAP），单列在 `hung=` 计数里，
不影响 PASS 判定；`--json` 汇总同口径。失败件只回日志尾部，明细落
`.scratch/test-logs/<路径折 __>-<hash8>.tap.log`（加路径哈希，避免 `a/b.test.mjs` 与 `a__b.test.mjs` 撞名）。

- `--jobs N` 开并发（只在确定没有重资源测试时用）；`--list` 只列清单；`--json <file>` 落结构化汇总。
- 全量清单只有一份事实源：`tooling/test-suite.mjs` 的 `SUITE_GLOBS`。`pnpm test:suite`（本驱动 `--all`）、
  `pnpm test`（`tooling/check-real-home-untouched.mjs --run`，另有真实 home 快照隔离与命令 exit 0 门禁）
  与 `gate.mjs --full` 都从这一份取；**清单同源，但隔离/门禁不同源**：验收收尾走 `pnpm test`，
  排查单件/分区走本驱动。
- 末行 `RESULT: PASS|FAIL files=… pass=… fail=… timeout=… hung=… error=…`。

## 4. 已知红与新树「假绿」

新树与主目录的已知红**不是代码差异**：主目录里有些残留物会让同一件测试在主目录假绿、在新树真红。
2026-11-02 实测 683 件里 61 红；这 61 件中有 56 件与主树逐件同值（同一文件、同一失败读数），
其余差异件要逐条按下列残留物来源比对（已确认四条如下；差异件多于四条时按同法逐件比对，否则「多几件」会被误当成代码回归）：

- `packages/plugin-manager/test/config-panel-1160.test.mjs`、`config-panel-1164.test.mjs`：脚本读未跟踪的 `.scratch/1155-real-panel-prototype.html`（原型留档不在 git 里），新树报 `PIXEL_T1_PARAM proto=missing`。
- `packages/skill-bill/test/check-line.test.mjs`：仍 import 已不存在的 `dist/query/checkLine.js`；主目录的陈旧 dist 让它过，新树 `ERR_MODULE_NOT_FOUND`。
- `packages/skill-home/test/express.test.mjs`：长跑偶发崩（无 TAP 汇总），单跑 5/5 绿。

判红线以逐件读数（`# RESULT file=… status=… pass=… fail=…`）为准，不要拿主目录的绿当基线；
差异件多于上表时按同法逐件比对，不靠总数推断。

## 何时用哪个

| 场景 | 命令 |
| --- | --- |
| 开一张票／派一个子代理 | `worktree-init.mjs`，再把 `<树>/.scratch/README.md` 指给对方 |
| 子代理交回改动 | `premerge-child.mjs` → 有冲突先按侧车裁决 |
| 改完一包想验证（构建＋该包测试） | `node tooling/gate.mjs --scope <包目录>`（内部 `tsc -b` → 该包 `test/*.test.mjs`；`--client` 补前端产物） |
| 排查单件／分区 | `run-tests.mjs <该包 test 目录或不带 --all 的路径>` |
| 收尾全量验证 | `pnpm test`（真实 home 门禁，清单同源）；要逐件读数用 `pnpm test:suite`（本驱动 `--all`） |
