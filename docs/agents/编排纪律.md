# 编排纪律：下发任务十条 · 拆票十条

把活交给 subagent 之前、把一张地图切成 issue 之前读本文。窗口内的机械步骤（目录锁、落点、证据、量刑）在 [`subagent-concurrency-protocol.md`](../subagent-concurrency-protocol.md)；本文只管三件事：**怎么切、怎么派、怎么收**。

本机过程草稿里存着本轮地图的实测案例（37 条硬规则，每条对应一次真实事故）：`.scratch/t314-319/编排状态.md`。该目录不入仓，只在本机可读。

## 为什么（三条不变量）

1. **上下文是唯一会耗尽的资源。** 磁盘与票面是长期记忆，对话只是运输通道。⇒ 证据落盘、回执有界、接任者读文件而不是读聊天记录。
2. **判据决定质量上限。** 席位做到什么程度由你给的判据决定：判据模糊，它就提前收工并自行发挥边界；判据穷尽且先红后绿，它才肯下笨功夫。
3. **写者只能有一个。** 并发只提高吞吐，不替代排序。把并发花在只读的活（复核、探查、起草）上，写活的并发用一把锁串起来。

## 本轮的五个成本大头（实测）

| 大头 | 现象 | 省它的办法 |
| --- | --- | --- |
| 验证面比实现面贵 | 判据脚本自己改了三次（每版都要独立复核）——判据脚本也是「从没被执行过的代码」 | 判据脚本先做夹具双向验证（真例假例各半），把「判据精度」单列一张票 |
| 改一处、全仓重测 | `pnpm gen` 是整棵树，全量 1492 条测试每次都要跑 | 一张票 ≈ 一次全量，所以票要切到一次窗口做完；按能力分片是另一张票（`#321`） |
| 规则总在事故之后追加 | 每条硬规则都对应一次真实的浪费 | 事故 ⇒ 规则 ⇒ **同时改进简报模板**；席位读的是简报，不是纪律文件 |
| 编排者上下文最短 | 席位每次回执哪怕 800 字，二十次就是一次爆窗口 | 回执固定形状（判定／机器证据／路径），细节一律留在盘上 |
| 串行化的真实代价是基线漂移 | 窗口跨天 ⇒ 重测全部前置 | 写活的窗口压到一次做完，只读活全部并行 |

## 简报八格

派活就是填这八格。缺一格，席位会自己补一格——它补出来的那一格通常是错的。

| 格 | 写什么 |
| --- | --- |
| 派给 | 席位名与职责（一个席位一条判据） |
| 任务 | 一句话，动词开头 |
| 上下文 | 只给需要的切片：文件 ＋ 行段，或你切好的片段 |
| 判据 | 能跑出真／假的命令，或一份**有限**枚举清单 |
| 红线 | 不许碰的清单（共享 `dist`、更强基线、别人的文件、历史重写、`--force`），每条配一句正向目标 |
| 交付 | 磁盘路径 ＋ 回执形状：判定／机器证据／路径 |
| 自证 | 改坏一处 ⇒ 判据必须变红；改回 ⇒ 变绿；另附反假绿对照 |
| 交棒 | 上下文将尽时写哪个补丁文件、交代下一手什么 |

## 十条 · 下发任务

1. **一个席位一条判据。** 判据是席位的终止条件；「看看有没有问题」没有终止条件，席位只能自己宣布完成。派活前先写出那句能跑出真／假的命令；写不出来就先别派。
2. **简报自足。** 席位看不到这场对话。路径、命令、判据、交付形状、红线全写进简报；漏一个路径，它就在全仓里找，时间与上下文双爆。
3. **切给席位的是片段，不是整本。** 要求先检索再读（先定位到行段，再读一百行以内）；台账、脚本、日志由你切好贴进简报。本轮有席位为了做一个五行的决定读了 34 KB 计划。
4. **给模板，不给白纸。** 复杂脚本一律「照抄 `<已有脚本>` 再改 N 处」。从零写 30 KB 脚本，等于席位先把自己的上下文吃掉，还扔掉模板里上一次事故留下的断言。
5. **交付物落盘，回执限量。** 大输出写文件；回执只给判定 ＋ 机器证据 ＋ 路径。保护的是编排者的上下文：二十次八百字回执就是一次爆窗口。
6. **要自证，不采信自述。** 要求变异自证（改坏一处必须变红、改回必须变绿）＋ 反假绿对照（`mtime`、暂存区、`??` 被当成通配符）。自述是数据，不是证据。
7. **红线写进简报。** 席位读简报的程度远高于读纪律文件。每条红线都配一句正向目标（「只改 X 文件里属于本票的那 28 行」），否则红线读起来像操作建议。
8. **阻塞等待，不要轮询。** 长命令用一次阻塞读到结束标记；席位反复 poll 会把同一份日志灌进上下文好几遍。轮询留给不占席位的编排者。
9. **预算里写交棒。** 「上下文将尽时不要硬撑：把补丁写进 `<路径>`，交代下一手缺什么。」本轮七次耗尽里至少三次本可以变成干净交接。
10. **出活与复核分席。** 复核席的输入是提交号 ＋ 判据清单，不是作者的解释；被审文本一律自己复跑。「作者兼复核」等于没有复核。

## 十条 · 拆票

1. **先立终点与雾，再切票。** 一张票 ＝ 把某块雾变成「已定决策」或「已交付产物」的最小步。说不出它消掉哪块雾，这张票就是多余的。
2. **按判据切，不按文件／功能切。** 一张票要能独立跑红、独立跑绿；按目录切会切出「谁都不绿」的票。
3. **粒度 ＝ 一次窗口做完。** 含实现 ＋ 自证 ＋ 证据。做不完就再切一刀——窗口跨天，基线就漂移，全部前置要重测。
4. **先切一张验形状的最小票。** 挑一张能证明新形状走得通的最小票先交付，其余票照它的形状切；形状没验之前，别的票都在赌。
5. **依赖是 DAG，锁是闸门。** 谁先谁后写成依赖，同时只许一个写者交给锁。别拿锁代替排序，也别指望依赖能省掉锁。
6. **票面五段固定**：目标／验收命令／红线／交付物路径／遗留出口。缺红线的票，边界由席位替你定。
7. **一票一作者，票间接口是主干事实。** 交接只通过已 push 的提交与生成物；「我在等你那半边」不是状态。
8. **先立冻结面，判据只许收紧。** 冻结面立好之前切票，票与票会互相改判据；判据（棘轮）只能收紧，放宽要另开票。本轮冻结面 ＝ 老场景文件 ＋ 老路由测试。
9. **派生票当场开号互链。** 复核发现、文案补齐、缺陷，一律转成有编号的票，并在原票面写「遗留转 `#NNN`」。留在对话里的遗留项会蒸发。
10. **关票条件写进票面。** 判据全绿 ＋ 证据入仓 ＋ 独立复核过线 ＋ 遗留转票 ＝ 100%。这一条不写清楚，「接近完成」会永久滞留——本轮十一张票靠它才关得掉。

> 见到新事故，先补一条规则，再把这条规则写回简报模板；只加进本文的规则，下次照样会被踩。
