# 编排纪律：地图设计者十一条 · 地图执行者十二条

地图设计者切票，地图执行者派活、盯窗口、收活——两种角色都先读本文。

**三条原理**：上下文是唯一会耗尽的资源；判据决定质量上限；同一时刻只允许一个执行者在写。

地图分两种：**功能图**（找路——把「要做什么」的雾逐张清成决定）与**收容图**（把无主孤儿票推到终局：关闭／做完／转出）。收容图的跨领域是**设计，不是污染**——它存在的理由正是「这些条不属于任何功能图」；砍掉它的领域面（例如「CI 类不进地图」）只会把孤儿问题重建一次。

窗口内的机械做法——谁写哪些文件、命令排队、留痕格式、评审量刑——见 [`subagent-concurrency-protocol.md`](../subagent-concurrency-protocol.md)。

本仓的架构与命令纪律见 [`docs/agents/structure.md`](structure.md) 与 [`docs/agents/命令登记纪律.md`](命令登记纪律.md)。技能里有几条命令、什么算一个能力目录，都在那两份里。

没有票的一人一活，照「地图执行者」那半做：判据、简报、自证、提交范围四条照旧适用。

## 地图设计者

**先冻基线**　开工前写明哪些老行为不许动，并给每条配一个能判出真假的动作。　违反：基线没冻就别切票。

**一条判据一张票**　一张票只写一条能跑出真或假的命令，票面判据与命令一一对上。　违反：写不出命令就合并或重切。

**按判据切**　切票看能不能独立跑红、独立跑绿，不按目录或功能块切。　违反：把谁都不绿的票拆开重切。

**一次做完**　粒度按一次窗口能收工定：实现、自证、证据都含在里面。　违反：做不完就再切一刀。

**先验形状**　先切一张能证明新形状走得通的最小票，它跑通了再照它铺开其余票。　违反：形状没验之前不开大票。

**依赖与锁分开**　依赖写清谁先谁后，锁只管同一时刻的写者，两样不许互相顶替。　违反：顺序含糊就当场补依赖。

**票面五段固定**　目标、验收命令、不许动的东西、交付物路径、遗留出口，五段缺一不可；其中“遗留出口”只登记去处，不等于开票指令（开票另按第十条三问）。　违反：缺段退票。

**判据先行**　判据先用真例假例各半验过自身，再开实现票。　违反：判据改了就重跑一遍真假对照。

**一票一作者**　一张票只有一个作者，票与票之间只通过已提交并推上去的事实交接。　违反：出现互相等对方那半边，就补依赖或合并。

**遗留当场开票（开票凭判据）**　复核发现的遗留与缺陷，先过三问再开票：一，能复现吗（给出复现命令与读数）；二，有现存票或 MAP 能认领吗（有就回写那张，不另起新票）；三，是已承诺的目标吗（想法与改进一律写进文档，不占票）。三问全过，才当场转成有编号的票并回写原票；暂无 MAP 认领的先记文档，攒到有 MAP 再认领。同一收口要批量开票的，先由编排者逐条裁定去留。　违反：留在对话里的遗留项会蒸发，当场补票；无复现、无归属的票是噪音，退回关闭。

**判据可终止**　一张票的验收必须能在有限步内给出真或假：要么**本地可判**，要么写成「改动落地 ＋ 点名外部确认（谁触发、看哪个读数）＋ 确认失败怎么办」三件齐全（收容图尤其要）。　违反：判据要的读数本地物理上拿不到（如只有某个 CI 作业／某台特定机器能给），票面又留着「待确认」当完工——退回重写判据或补上外部确认出口，不许挂着。（#638 #344 实测：四类里三类本地可判、第 ④ 类只有 macOS CI 能给，正确处置是「改法落地＋点名两个作业与两条用例＋说明失败怎么办」，而不是拖到最后才碰。）

## 地图执行者

**一任务一判据**　写不出真或假命令的活不派。　违反：拆到能写出命令为止。

**简报自足**　路径、命令、判据、不许动的东西、交付物形状全写进派单。　违反：缺项退回重发。

**省着用上下文**　只给需要的片段，要求先检索再读，长命令一次阻塞等到结束。　违反：发现它全仓乱找或反复查看，就补切片或由你接管等待。

**给模板不给白纸**　复杂脚本一律照抄已有的脚本再改几处。　违反：先指定参照文件。

**交付落盘回执限量**　大输出写文件，回执只给判定、机器证据、路径；取证与写成报告分两段派。　违反：回执超长就要求重发摘要。

**要自证不要自述**　改代码或产物的活，一律要求改坏一处必须变红、改回必须变绿（纯文档活不要求跑测试）；每张要自证的票都要给出「变异红／还原一致」两行机器读数；新断言与门脚本入仓须附"改坏必红"负向证据。　违反：没有变异自证的活退回。

**红线写进派单**　每条禁止配一句正面目标，两者一起交给执行者。　违反：出现越界就把该条禁令补进下一张派单。

**派单里写交棒**　上下文将尽时把补丁写到哪里、下一手缺什么，提前写进派单。　违反：交接不清就重派。

**出活与复核分开派**　复核的一方只信提交号与自己的复跑。　违反：作者自评不算复核。

**收活看提交范围**　提交只含自己的文件。　违反：范围不清的交付不收。

**触 CI 尽早推**　会进 CI 面的改动（测试、构建配置、生成链、`.gitattributes` 一类）落地即推；地图开工时先推一次建立 CI 基线。　违反：把需要 CI 确认的判据堆到地图收尾才碰——那等于把「并行的背景确认」变成「串行的尾巴」。（#638 实测：14/15 已关才第一次撞 CI，最后卡在一次 push 的授权上；早推则确认与施工并行。）

**收活看生成物**　回滚后把生成物重新生成，并把生成记录更新。　违反：生成一致性不为绿的交付不收。
