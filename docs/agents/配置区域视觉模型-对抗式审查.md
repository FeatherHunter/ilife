**谁审的（2026-09-22，两席独立 + 我一轮）**：
- 第一席：把模型复制到 `.scratch/vit-review/`，追加探针后用本机 Chrome 无头 `--dump-dom` 驱动真状态机实测（`.scratch/vit-review/` 可弃，产物是读数不是结论）。
- 第二席：模型 ↔ 六家真源逐条对账（`packages/plugin-*/src/settings.ts`、`plugin-*/src/client.ts`、`skill-*/src/config.ts`）＋ 翻已关定稿票 ＋ 查跨包锁判据。
- 我：第一性原理那一轮（判据＝① 能被实现而无须发明 ② 不会被误读 ③ 与真实约束对得上 ④ 覆盖用户真会走到的状态）。

**审查结论一句话**：这份东西现在是**设计依据**，不是**落地依据**。差三件事：真源没接上（靠手抄，已漂 6 处以上）· 错误态整块没设计 · 落地会破跨包锁。

## P0 —— 不改完不能当落地依据

### 1. 错误态在结构上不可达（实测）
`fill()` 是「写一次闩锁」不是缓存：槽位填过就再也写不进去，唯一出口是重建 DOM。就绪态在快面就把徽标槽用空串占死 ⇒ 模板里那枚「红要留给真错误」的红色徽标**根本没有落点**；`.ic-dot.is-bad` 定义了却无人触发。三处绕过账本的写法（`dot.className`／`spath.title`／`sver.hidden`）恰好就是会变陈旧的那三处。
**修法**：`fill` 改幂等写；槽位带「已渲染的数据版本」。

### 2. 让第 1 条不发作的是 demo 自己的整块重建——而那正是 React 不做的事（实测）
点一次状态按钮，25 个槽里 **24 个重新带进场动画**：文件头声称修好的闪烁在这条路径上原封不动。且这套「必须重建才正确」的耦合照搬进 React（原地重渲染）立刻串数据——实测原地切技能：标题还是「作息管家」，行里却填进了备忘录的值。
**修法**：改「按 skill 挂载 / 按数据版本重渲染」；撤销窗口、重读对脏值的处置写进模型。

### 3. 状态机缺 `saving` / `error`
真实写入是「备份＋写＋重读」，异步且会失败。②③ 共用同一个徽标分支、文案都是「1 项未保存」，而徽标正是设计里唯一「滚到哪儿都抬头可见」的元素 ⇒ 它恰恰分不出「待保存」与「待确认写入」。另：离开脏态无守卫（② 未保存时切技能，草稿静默消失，「放弃」是死按钮）。

### 4. 列宽阈值双重错估 → 9 行被无谓拆两行（实测）
实测每列 **6.048px**（注释按 6.6 估）、可用宽 **264/247px**（注释按 250 估）⇒ 真阈值 40–43，注释写 **34**。逐条可复现的误判：记账 `…\goals.json`(35 列/212px/可用 264)、卡路里库文件名(40/242/264)、卡路里产物目录名(37/224/264)、卡路里 GIF 子目录(41/244/247)、作息库文件名(41/248/264)、作息 HELP 产物目录名(43/260/264)、居家 `.master.key`(36/218/247)、大厨库文件名(37/224/264)、大厨 HELP 产物目录名(39/236/264)。**每行白吃 25px 行高**，而真机可视高度只有约 580px。
**修法**：阈值按实测每列像素 × 该行容器实际宽度算；或不用字符数估宽，交给 CSS。

### 5. 骨架不留高度 + 换行决策在填充期 ⇒ 快面一次性长高 194px（实测）
实测 `shellH 533 → 727`（+194），而「真机可视高度」线画在 580。元凶是 `is-wide` 在填充期才决定，被第 4 条错估放大。

### 6. 行表靠手抄真源，已经漂了六处以上
| # | 模型 | 真源／定稿 |
|---|---|---|
| ① | 作息 `HELP 产物目录名`、居家 `HTML 产物目录名`、大厨 `HELP 产物目录名`／`场景产物目录名` | 真源**没有「名」**（`plugin-schedule-ilife/src/settings.ts:89`、`plugin-home-ilife/src/settings.ts:91`、`plugin-chef/src/settings.ts:91,100`）；#761／#793／#795 逐字要求过去掉 |
| ② | 卡路里 `训记调用限时`／`落地调用限时` | 真源是**带单位**的「训记调用限时（秒）」（`plugin-calorie/src/settings.ts:152,160`） |
| ③ | 居家 `html.dir` 的 `hint`（写了） | **是死字段**：渲染器只读 `r.sub` 不读 `r.hint`，而 #793 明确要求保留居家独有的取值语义 |
| ④ | 备忘那一行写成 `sub:` | 真 `hint` 是「数据目录下的库文件（备忘不建库，显示的是会落在哪）。」 |

### 7. 控件形状与已关定稿冲突，且会直接打红跨包锁
- **只读目录行的「浏览」按钮被我删了**，换成自创的「复制／打开」——#747／#793 定稿是「按钮保留但不可点击」。
- **`浏览…` 带省略号**——#747 第 27 行明令「面板文案的省略号要去掉」，跨包锁 `test/panel-copy-743.test.mjs:222-247`（⑧）要求**源码面零 `…`** ⇒ 照抄模型落地的当下就把锁打红。
- **「用默认位置」是自创控件**，六家真实面板没有。
- **高级组写死 `<details … open>`**——真机默认收起（`plugin-bill-ilife/src/settings.ts:36` #675 冻结口径、`client.ts:595-600`）。
- **`xunji.key` 被我做成密码框 + 占位「未配置」、不给按钮**——#748 定稿是「保持可改，控件形态不动」。

### 8. 核心抽象站不住：`fixed` 这一类没有真身，`owner` 指错两处
- 我把「训记动作库路径」归为 `fixed`（技能自带·不跟任何可改项）。**真实它是 `readonly` ＋ `resolveFrom:'catalog'` 的配置键**（用户可在 yaml 里指到别处），面板显示的是技能解析后的值；我给的示例值还缺一整段（真实形如 `…/xunji/data/训记官方动作.json`，见 #748 定稿）。
- **`settings.ts` 里根本没有 `owner` 这个概念**——真实的从属关系是各 `client.ts` 里硬编码的跟随表（`plugin-calorie/src/client.ts:525-531` 的 `DB_FOLLOWERS`／`PHOTOS_FOLLOWERS`，`plugin-bill-ilife/src/client.ts:323-328`）。
- `owner` 指错：记账「备份文件名前缀」我挂在 `db.dir`，真算式是 `join(backupDir, stem+'<时间戳>.db')` ⇒ 它挂**备份目录**（而备份目录自己才是数据目录的派生）；卡路里 `photos.gifs` 真实**同时**挂在 `db.dir` 与 `photos.dir` 两张表上（丢掉「改数据目录→照片目录→GIF」这条链）。
**修法**：类别由真实字段派生（`readonly`＋`resolveFrom` ⇒ 派生、`control:'number'` ⇒ 数值），删掉 `fixed`；从属关系改读各家真 `followKeysOf`。

### 9. 慢面数据全仓不存在；拆分成本被低估——但有便宜路子
- **fast 有现成字段**：`config.get` 回执的 `path`／`dataDir`／`created`／`values`／`resolved` 六格够铺完「配置文件路径＋可改行＋只读行」。
- **slow 一格都没有**：目录体积／文件数／条数／最近写入全仓不存在；体检报告每条只有 `id/title/status/message/action/source`，表数只住在一句话里。
- **备忘是「全有全无」的实锤**：`lark` 格就住在 `config.get` 回执里、技能侧读配置时同步跑探测、面板一次 RPC 20s 超时（`plugin-memo-ilife/src/client.ts:145`）。作息已经现成两发。
- 硬拆要动约 30 处（六家各动 `contract.ts`／`bridge.ts`／`index.ts`／技能侧 `cli/config.ts`／`cmd_read.ts` 白名单），还要重算体检整批时限断言。
**修法（省事且已注册）**：慢面**复用现成的 `config.check`**，只往体检报告加结构化数字字段，不给六家各开新通道；备忘另需把 `lark` 搬出 `config.get`。

### 10. 落地会破两道跨包锁 + 一道边界门
- `test/panel-copy-743.test.mjs` ⑤：要求六家源码里有平铺的 `const S = {` 且逐项逐字同形——**模型改成类名 CSS 后取不到 `const S = {`，直接红**。
- `test/panel-copy-743.test.mjs` ⑧：源码面零 `…`（见 P0-7）。
- `test/panel-type-739.test.mjs` 全部四条：零 `font` 简写、零字族、字号一律 `em`——模型用的是 `font:` 简写 + `font-family` + 绝对 px。
- `test/plugin-p10-boundaries.test.mjs` 的定时器三件套：模型的阶段推进 `setTimeout` 与 5s 撤销倒计时都会触发。
- `plugin-*/src/client.ts` 头声明「禁 DOM 直写」，把 `document.getElementById`／`innerHTML` 这套挡在门外 ⇒ 必须改写成 React 状态机。
**修法**：先把「样式表逐项同形」与「字号/字族」两道锁的判据**搬到共用渲染件上**，再动六家 `client.ts`。

## 两席确认「站得住」的（别返工）

1. **行数与可改/只读逐家对得上**：6／11／4／3／5／4 行、可改 1／3／2／1／1／1，与 `test/panel-copy-743.test.mjs:154-186` 钉死的定稿一致；顶栏计数也对。
2. **token 全是真的**：模型用的 14 个 alias 都在 DSH 主题包里定义（含 `--dsw-alias-state-warn-primary`／`-error-primary`）。顺带一个反向读数：**现状六家 `client.ts` 用的 `--dsw-alias-border` 与 `--dsw-alias-label-error` 在 DSH 全仓都没有定义**——现状早就在走硬编码回退，模型这部分反而是对的。
3. **`position:sticky` / `<details>` / `color-mix()` 三件都有先例，可行**：吸底条已在这六个面板里上线（`plugin-bill-ilife/src/client.ts:77`）；`<details>` 已是高级组本体；DSH 应用自己用了 39 处 `color-mix()`。token 定义在 `body` 上，插件面板渲染在正常 DOM 子树里，继承得到。
4. **defaults 类读数逐项核过**（`photos.dir`／`xunji.stateDir`／三个数值／`key.file`／大厨两个产物目录），与 `skill-*/src/config.ts` 一致。
5. **六家 `db.dir` 的标题与 hint 逐字对得上**；「居家/大厨没有备份文件名前缀那一行」也对。
6. **`<details>` 空组不渲染**（备忘／作息／大厨无高级组）与真实 `advanced.length === 0 ? null : …` 一致；行序与 `CONFIG_ITEMS` 一致。
7. 几何细节：`is-dirty` 输入框 1px→2px 描边与 padding 5→4 对消、宽高不变 ✓；`WIDE_COLS=66` 够用（只需调 `NARROW_COLS`）；`midCols` 算术自洽、不切代理对；定时器清理与两面槽位互斥 ✓。

## 建议的动手顺序

1. **抽共用行渲染件**（住 `dsh-life-pack`，六家已 import 它的 `./directory-browser*`），**并把两道跨包锁的判据搬到该件上** —— 否则动六家 `client.ts` 的当下就红。
2. **行表改成由各家 `settings.ts` 派生**（标题／说明／可改只读／分级／控件种类／跟随关系），消灭手抄漂移（P0-6/7/8）。
3. **补错误态与取数拆分**：`saving`／`error`（读取失败／值非法不可写／写入失败）、慢面复用 `config.check`、备忘 `lark` 搬出 `config.get`（P0-1/3/9）。
4. **修几何**：阈值按实测（40–43 列）、骨架给 badge/bar 留高度、`is-wide` 提前到骨架期决定（P0-4/5）。
5. **最后才碰 React 重渲染模型**：按数据版本重渲染，别照抄 demo 的整卡重建（P0-2）。

**两处要人裁**（模型与已关定稿相反，不能默认改）：只读目录行的「浏览」按钮要不要保留但不可点；高级组默认收起这点无争议（照真机），但**「复制／打开」这排自创动作要不要进真面板**需要你点头——它不在任何定稿里。
