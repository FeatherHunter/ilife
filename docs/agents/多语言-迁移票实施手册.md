# 多语言迁移票实施手册（#1197，实现者子代理用）

本文件是 28 张迁移票（#1203–#1229、#1232）的**统一开工手册**：每个实现者子代理按本手册干活，交回时按 §8 格式汇报。
真相源：`tooling/i18n-ticket-scope.json`（每票文件清单）、`tooling/i18n-codemod.ledger.json`（分类）、
`docs/agents/多语言-位置四分规则.md`（七类处置）、`docs/agents/多语言-渲染语言上下文.md`（m() 与 key 命名）、
`docs/agents/多语言-门禁改造-验收命令.md`（门的读法）。

## 0 角色与纪律

- 你只改**本票清单内的包**（一个包）＋该包的直接调用方接线点＋该包测试；**不改**其它包。
- **禁止任何 git 写操作**（不 add／commit／checkout／switch／reset／stash／restore／clean／worktree）。工作区改动由 Lead 收集。
- **禁止**改 `tooling/i18n-scope.json`、`tooling/i18n-ticket-scope.json`、`tooling/*.snapshot*.json`、`test/t689-页面指纹*.json`、`AGENTS.md` 行数台账、`package.json`／`pnpm-lock.yaml`（共享清单/账本由 Lead 串行做）。
- **禁止**改生成件（文件头含「机器生成／禁手改／GENERATED」或落在 `*.generated.ts`／`sceneData.ts`／`helpAssets.ts`／`helpShell.ts`／`cli/keys.ts`）。遇到这类件：跳过，写进交回报告「不迁（生成件）」。
- 不跑全仓 `tsc -b`、不跑 `pnpm build`／`pnpm gate:i18n`、不跑页面指纹/快照账本（Lead 统一做）。
- 编译入口写死：`node node_modules/typescript/bin/tsc -b`（**整个仓库**；本工作树是独立 worktree，只编单包会因 `base-paint` 等未构建依赖报 TS2307，全仓编一次就把依赖都建好）。
- 迁移完的中文若属**开发报文**（`throw new *Error(...)`、`fail('CODE','…')`、`badInput(...)`、`assertXxx(...)`、`console.*`）**不迁**（迁移器已跳过；若它误迁了，改回中文字面量并删掉对应词条）。

## 1 前置检查

```powershell
node node_modules/typescript/bin/tsc -b   # 整个仓库，必须 exit 0（这一步同时把依赖包的 dist 建好）
```

## 2 统一行尾（本仓 core.autocrlf=true，检出的票内文件是 CRLF；迁移器只写 LF，遇 CRLF 会整件 UNSUPPORTED）

```powershell
node -e "const fs=require('fs');const F=JSON.parse(fs.readFileSync('.scratch/ticket-files.json','utf8'));for(const f of F){const s=fs.readFileSync(f,'utf8');if(s.indexOf(String.fromCharCode(13))>=0)fs.writeFileSync(f,s.split(String.fromCharCode(13,10)).join(String.fromCharCode(10)))}"
```

（`.scratch/ticket-files.json` 由派单准备脚本生成；若没有，就用本票清单路径。）

## 3 跑迁移器

```powershell
node tooling/i18n-migrate.mjs --ticket <票号> --dry    # 先看：会改哪些、UNSUPPORTED 哪些
node tooling/i18n-migrate.mjs --ticket <票号>          # 实跑（写前备份 .scratch/i18n-migrate-backup/）
```

- 末行读数：`RESULT: files= migrated= skipped= entries= unsupported=`；`unsupported` 非零会 exit 1 且**整件不写盘**，按报告里点名的手工处理（通常是 HTML 结构串、模板串里的表达式、比较位、生成件）。
- 迁移器只迁 **copy／concat** 类中文字面量：单字面量 → `m('key')`；`+` 链在链顶整句化成一条 `m('key', { p1: String(...) })`；模板串同理。key 形如 `<包目录>.<路径折->.c001`。
- 它会给文件补 `import { m } from '<相对 entries/index.js>';`，并按文件往 `packages/<包>/src/entries/{zh,en}.ts` 追加条目（zh＝原字面量逐字节；en 空串草稿）。空表（`export const zh = {} as const satisfies MessageTable;`）会自动展开成标准多行表。
- 幂等可重跑；重跑前先 `--dry` 确认上一轮已经 0 可迁。
- `--files a,b` 只处理点名的件（相对仓库根、正斜杠）。传单件时也能用。
- 报告的 UNSUPPORTED 原因里，**「展开运算符」只在「整条链自己就是被 spread 的值」时才报**；`{ ...buildReceipt('…' + id) }` 这种正常形状不再误判。

## 4 手工处置（迁移器之后）

1. **残留**：用临时 scope 跑 keys 门看红单（见 §6）。真残留按 §5 处理。比较位（`includes(...)`／`===` 等）由迁移器跳过、门也放行；**开发者报文的豁免只有三类**——`throw new *Error(…)`、`badInput(…)`、`assert*(…)`——其余调用（`fail(…)`、`console.log(…)` 等）的实参**会**被门判红，故迁移器已与门逐项对齐、会照迁（早期版本跳过 `fail` 是错的：那会留下「迁移器说没问题、门却红」的假绿假红）。
2. **整句化**：若原代码是「前缀 + 变量 + 后缀」两侧拼接，迁移器会把变量位置变成 `{p1}`／`{p2}`（非字面量包 `String()`）。检查语义没变；需要换序/复数等语义差异时手工改。**这类改动在交回报告里逐处申报「原句 → 模板」**，供 Lead 第二方比对。
3. **判据位**：拿显示文本比字面量的代码（`x === '没给'`）必须改成看**控制标记/布尔位**（参考 `packages/skill-bill/src/write/blockedSlots.ts` 的 `missing?: boolean`），不许用本地化文本做判据。
4. **模块级场景对象 → 改为函数＋按语言重建（#1204 已定样板）**：场景件常见形状是先写一堆模块级常量、再 `export const SCENE: Scene = {…}`。这类件迁移器会对整对象报 `SKIP_MODULE_CONST`（在模块加载期取词会永远拿到 zh）。做法是把对象包进构建函数：

```ts
import { runWithLanguage } from 'base-entries';
// …原有常量不动…

function buildScene(): Scene {
  return {
    // …原对象内容原样搬进来…
  };
}

export const SCENE: Scene = buildScene();   // 模块加载期＝zh 上下文，产物逐字节不变

/** 按语言重建本场景（#1197：文案经词条层，语言是运行期参数）。 */
export function sceneBorrow(language: string): Scene {
  return runWithLanguage(language, buildScene);
}
```

搬完之后再跑迁移器：对象里的字面量会变成 `m('key')`（对象级字面量在 `buildScene()` 执行期取词，`sceneBorrow(language)` 时语言已进上下文）；嵌套在 `(ctx) =>` 回调里的字面量也是渲染期取词，同样正确。然后在场景路由（如 `scene.ts` 的 `sceneFor`）里把「非 zh 且 kind=本型」分支接到 `sceneXxx(language)`（已有已迁件 `scene-installment.ts` 可照抄签名）。

5. **`m` 名字遮蔽**：迁移器注入的是 `m()`，文件里已有的局部变量／参数／解构名 `m` 会遮住它（报 `m 遮蔽`）。把那些名字改成语义名（`slot`／`candidate`／`mark`／`miss`／`parts`／`month` 等），再重跑。**不要**改成别的取词别名。

6. **带 HTML 结构的整句（`SKIP_HTML_STRUCTURE`）**：迁移器跳过「整句里带 HTML 标签」的串。**这道跳过不是许可留下中文**：keys 门对含 `<`/`>` 的串按代码片段放行，所以这类中文会静默漏掉（假绿）。凡是**会渲染到页面上的用户可见文案**，必须手工把字符串拆成「结构 ＋ `m('key')` ＋ 结构」（照 #1205 的 `saySheet.ts` 样板），结构部分原样留在源码里。纯结构／无中文文案的串才可跳过（在报告里逐条说明）。

7. **链里嵌条件表达式（迁移器报「链内有条件分支／嵌套表达式还含着待迁文案」）**：先把条件表达式里含中文的分支抽成一个局部变量（用 `m()` 取词），再让外层 `+` 链只拼「字面量 + 变量」；重跑迁移器即可整句化外层链。

8. **模块级常量里的早期取词（硬规则）**：`m()` 读的是**运行期语言上下文**（`runWithLanguage`）。因此：
   - 只有在**渲染/请求执行期被调用的函数体内**才可调用 `m()`；
   - **不得**在模块顶层 `const X = m(...)` 或模块级常量表里取词（那时上下文还没进入，永远拿到 zh）；
   - 模块级中文常量表若在渲染期使用，改为**函数**（如 `function titles(){ return { ..., scene: m('k') } }`）并在调用点调用；若该常量被跨包导入，**不要改导出形状**，改为补一个函数并让本包调用点用它，交回报告里写明跨包调用方待接线。
5. **数据不译（ADR-0004 三条）**：写进数据库/命令词汇/文件名/唤醒词的中文取值不迁不译，保持中文字面量：分类名、账户名、标签（如 `#借入`）、命令键、唤醒词、单位词若属数据。迁移器误迁的改回并从 zh/en 表删 key。把这些串汇总进报告 §8.4「需 Lead 加 allowlist」。
   注意 #1320 起 allowlist 是「文件＋字面量」登记（`{files, texts, why}`）：同一串在别的文件（尤其界面位）出现不会被这条豁免遮住，所以数据位与界面位必须逐处分开报，别把「这串以前放行过」当理由。
6. **payload 类件本波不迁（Lead 另立专项）**：文件头带「唯一事实源／事实源／逐字落地」或正文是**契约附录派生的大块数据对象**（如 home 的 `items/pages/*.ts` 的 `REQUIRED_BLOCKS`、各包 `declaration.ts`、`wake-assets.ts`）属 `payload` 类。它们要**整件搬家＋消费方改成按语言懒构**，不是机械迁移；本波不登记进 scope、不动源码，只在报告 §5「不迁件」里列出（路径＋理由），由 Lead 的 payload 专项处理。**不要把 payload 件里的中文就地改成 m() 调用**（模块加载期取词＋契约冻结）。

7. **已有迁移件的显式签名**：`base-render/src/components/progress-list/model.ts`、`skill-bill/src/write/` 已迁 12 件用的是**显式 `language: string` 参数**（不是 `m()`）。调用它们时传 `currentRenderLanguage()`（从 `base-entries` 导入），不要改成默认参数。

## 5 英文列

- 用回填器起头再人工通读：
```powershell
node tooling/i18n-fill.mjs --pkg <包名> --list-pending --out .scratch/pending.json
node tooling/i18n-fill.mjs --pkg <包名> --map .scratch/en.json
```
- **禁止空串**（#1306：空串＝未录，缺词条门判红）。每一条 en 都必须是可用英文。
- 翻译口径：整句意译、保留 `{p1}`/`{p2}` 占位符与前后空格/标点结构；用户数据名（分类、账户、标签）原样保留中文；界面里的示例命令、CLI 命令样例原样保留。
- 占位符集合必须 zh/en 相等（params 门会判）。

## 6 验证（本票范围，按序全跑并贴读数）

```powershell
# 1) 编译（必须 0）
node node_modules/typescript/bin/tsc -b packages/<包名>

# 2) 两道门（用派单时给的临时 scope 文件）
node tooling/check-i18n-entries.mjs --scope .scratch/scope-<票号>.json
node tooling/check-i18n-keys.mjs    --scope .scratch/scope-<票号>.json

# 3) 本包测试（列名由派单给；node --test 直跑）
node --test packages/<包名>/test/<相关件>.test.mjs

# 4) 迁移器收口读数（应为 migrated=0 且 unsupported=0）
node tooling/i18n-migrate.mjs --ticket <票号> --dry
```

门的绿线：entries `RESULT: files=<≥本票件数> keys=<n> missing=0 blanks=0`；keys `RESULT: files=<同> literals=<n> residue=0`。
若 keys 门红单里有你认为该豁免的串：**不要改门**，把串逐条列进报告 §8.4（格式：`<字面量> — <文件:行> — <为什么不译>`）。
若 entries 门报某文件 blind（0 key／没 import）：说明该件无可迁文案 → 从临时 scope 去掉并在报告里注明「不迁（无用户可见文案）」，同时把该路径报给 Lead 从 `i18n-scope.json` 摘除。

## 8 交回报告（必须按此结构，中文）

1. **改动文件清单**（分三组：源码 / 词条表 / 测试），逐件一行，注明迁移器 vs 手工。
2. **读数**：tsc 退出码；两门 `RESULT` 行原文；node --test 的 tests/pass/fail；迁移器 `RESULT` 行；fill 的 `RESULT`。
3. **整句化申报**：每处「原句 → 模板＋占位符」一行（没有就写「无」）。
4. **需 Lead 加 allowlist 的字符串**：每条形如 `字面量｜文件:行｜理由`（没有就写「无」）。#1320 起 Lead 会把它落成 `{files, texts, why}`；同一字面量在多个数据位文件出现要分行列全——豁免只对登记过的文件生效。
5. **不迁件**：本票清单里跳过或摘除的文件及理由（生成件／无用户可见文案／冻结契约面）。
6. **接线点**：改了哪些调用方；是否还有未接线的跨包调用方（列文件:行）。
7. **未解问题／风险**（没有就写「无」）。

## 9 判定完成的标准

- 全仓 tsc 绿；两门本票范围绿；迁移器对本票 `migrated=0 unsupported=0`；en 列无空串；本包测试绿。
- 「写模式跑完」不算完成；「门绿但只登记了部分文件」也不算——必须本票清单里的**可迁件**全部登记并有英文。

## 10 收票对账（Lead 串行做，不在实现者写集内）

票级清单 `tooling/i18n-ticket-scope.json` 分三区，收票时把本票 `files` 里的件按结论搬走（**三种处置互斥，一件只归一处**）：

- `migrated`：已迁入词条层的件，**同时**必须出现在 `tooling/i18n-scope.json` 的 `files` 里（登记＝受两道门真判）；
- `excluded`：判定不迁的件，**必须写 `reason`**（生成件／冻结契约面／非用户可见报文三类之外的「不迁」要单独说明）；
- `files`：仍未迁的件（清空即本票收工）。

收票后跑 `node tooling/check-i18n-ticket-scope.mjs`，必须 `problems=0`（三分区互斥、已迁件与 scope 对齐、每票 totals 与三处按 ledger 复算一致）；`--selftest` 用**内置合成夹具**跑六条变异自证（夹具零问题／漏件／票间重叠／条数不符／不迁无理由／未迁记成已迁必红）也要过——夹具自带待迁件，不依赖真实清单里「还剩待迁件的票」，故全部票收口（各票 `files` 为空）后仍可跑、仍可红。

若本票改动让**英文列**页面产物变化（如共享样式资产里的注释进了词条），重录对应账本并申报：`node packages/skill-bill/scripts/gen-page-fingerprints.mjs --lang en --write --declare-layout-change <票号>`；中文列照旧必须逐字节不变（`--check` 44/44）。
