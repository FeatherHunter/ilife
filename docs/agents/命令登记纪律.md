# 命令登记纪律

**这份管什么**：一条命令的事实**住哪儿**、共用位**谁生谁改**、老命令**谁搬谁删**。
**叫法**：本纪律一律说「**共用位**」；设计正本（命令登记与分派-方案.html／-冲突为何消失.html）里说的「汇总位」就是它——同一批文件，两个叫法，本纪律只用「共用位」。
范围＝所有按这套形状做命令登记的技能件。参考实现在 `packages/skill-calorie`，其他件照抄形状即可——
本份只管形状，不管各件自己的命令内容。

**最长的一句**：**一条命令的事实只有一个定义地，就是它自己的能力目录；所有共用位都是那个定义地的派生件。**

## 一 · 为什么要有这份（违反它会坏在哪）

这条形状不是审美，是为了解掉一个已经算过的账。改前：一条命令的事实（键／形状／标题／代表唤醒词／示例／处理函数）
散在 8 个以上的位置；各图 session 同时改命令时，**必须写同一批共用位**，于是每次并行都撞同一支笔。
`docs/skills/skill-calorie/命令登记与分派-冲突为何消失.html` 把这份账逐处对过：改前 6 处共用写点，改后 0 处。

所以**成立要件**是三条**同时为真**，缺一条这份形状就塌：

1. **确定性**——同一份声明跑两次 `pnpm gen`，产物逐字节相同；
2. **哈希锁**——产物入仓且「产物 ≠ 生成器输出」即可判定为假；
3. **机器校验在 CI 里真跑**——判定不靠人记得跑，靠 CI 每轮跑。

**「我们用了生成器」不是目的。** 生成器只是达成上面三条的手段：一个不接 CI 的生成器、
一个产物不入仓的生成器、一个排序不确定的生成器，三者都满足不了任何一条。
判据要问的是「这三条现在是不是同时为真」，而不是「有没有 `scripts/gen-cli.mjs` 这个文件」。

## 二 · 四条形状

### 形状一 · 新命令只声明在自己能力目录

一条命令的六件事写在 `src/<能力>/commands.ts` 的那一行里（`kind`／`key`／`shape`／`title`／`wakeWord`／`example`），
处理函数住同一个目录。**加一条命令要改的就是这一处加它那个子功能文件。**

**写命令不写 `shape`**（#703）：写命令一律 `receipt` 形，那件事实的唯一定义地是生成器
（`packages/skill-calorie/scripts/gen-cli.mjs` 合成 `cli/keys.ts` 的 `CALORIE_WRITE_COMBOS`），
写声明上再写一遍就是同一件事的第二处定义（`kind: 'write'` 与 `shape: 'receipt'` 是同一件事实的两种说法）。
写命令的**整页回执端口**挂在声明的 `doc:` 位上（`WriteCommandSpec.doc`，与 `run` 同类的运行时引用），
分派层只认声明、不逐家列名——第 7 个带整页回执的能力不必改 `cli/`。

坏在哪：写进共用位就等于给所有并行 session 建了一个共用写点，冲突面立刻回来；
写两处声明，同一件事迟早算出两个结果（`docs/agents/structure.md` 铁律二）。
机器拦：生成期同键两处声明直接抛（`packages/skill-calorie/scripts/gen-cli.mjs` 的 `merge()`），
`src/cli/registry.ts` 的运行期查表再拦一道。

`example` 是**必填且非空**的字段，没有退回路径（`wakeWord` 可缺，缺了速查表退回键名；`example` 不行）。
它要的是**照抄即能跑**，不是「有个串就行」——生成期只拦空／缺，
**跑不跑得通由 `pnpm help:examples:check` 拦**，而那道门今天带着票外既有红。
所以示例**先在本地跑通再提交**，别把恒红的门当兜底。

### 形状二 · 共用位由生成器写，人只在两种情形碰

共用位＝那些把各家声明汇到一处的文件。**哪些文件在名单里，以 `pnpm gen:check` 的输出为准**
（它逐件打 `GEN-CHECK ok <路径>`，见 §四）。

人碰共用位只有两种情形：

- **新增一个能力**——建它的 `src/<能力>/commands.ts`（**恰好导出一个声明数组**，多导一个数组生成器即抛），
  并在该能力的 `index.ts` 再导出那个数组（生成的 `registry.ts` 从 `../<能力>/index.js` 取）；
- **框架级变更**——生成器本身、类型形状、共用底座。

**这两种情形都要先抢 `gate.lock` 并广播**（抢锁口径见 `docs/subagent-concurrency-protocol.md` §2／§2.4，
勿照抄旧脚本）。理由：这一刻你写的是所有并行 session 都要用的东西，写完之前别人不能在同一条链上跑。

**生成物手改无效**：`pnpm gen:check` 比对盘上文件与生成器输出，不等即红并逐行指出第一处差异。
看到红就去改权威声明，然后 `pnpm gen` 重生成。

**生成器读的是编译后的声明**（`dist/`），所以「声明变了但没重建」会被一道**陈旧守卫**拦住并报 `GEN-STALE FAIL`
——它拦的是**假绿**（拿旧声明当事实），不是浪费你一步。判据是**内容印记**
（`dist/.gen-inputs.json`：声明源逐文件 sha256，由 `pnpm build` 在 `tsc -b` 之后调 `gen-cli.mjs --stamp` 写入），
**不看时间戳**——所以 `git restore`／`touch` 这类只动时间戳的正常动作不会让它误报。

被它拦住时**照它的医嘱重建**：跑 `pnpm build`（重建 `dist/` 并重打内容印记）再跑一次。
**别绕过 `pnpm build` 直接调 `tsc`**——打印记那一步挂在 `build` 里，绕过它印记不会更新。
**别自己删文件、别改门**：删 `dist/` 是治症状，改门是拆了拦假绿的那道闸。照上面的医嘱重建；仍红则上报编排者。

守的覆盖面有三条边界，**照它写的意思别越推**（都在 `gen-cli.mjs` 的 `staleDeclarations()` 里）：

1. **印记整个缺失时不判陈旧**：打一行 `GEN-STAMP WARN` 后放行，只查编译产物在不在。
   取向是**不假红优先**——无从判断的状态不当红用，宁可少拦一次，也不重演「假红＋自锁」。
   CI 上不会踩到这条（`pnpm build` 无条件重打印记，且排在 `gen:check` 之前）。
2. **印记里没有某条声明时放行**（新文件／仓外沙箱里的假能力，无对照）。
   于是有一个**已知缺口**：**新增能力目录后改它的声明内容，报的是下游 `GEN-CHECK FAIL`，不是 `GEN-STALE FAIL`**
   ——因为那时印记里还没有这条，守卫无从对照。
   **所以「没报陈旧」不等于「没问题」**：判定权在下游那道「生成物 ≠ 生成器输出」上。
   把「印记缺该声明且它已有编译产物也算陈旧」这条留给后续动生成器的票，本份不越权改。
3. **命中陈旧时报的是「源的内容与上次 `pnpm build` 时不同」**，逐条列出源路径与两个 sha 前缀，**医嘱可执行**（重建必重打印记）。

### 形状三 · 老命令就地搬迁（**过渡住处已退役**，`#708`）

92 条搬迁波次已结束：未搬迁清单那一层**过渡住处** `src/cli/legacy/`（按场景分片的 `scene-NN.ts`
＋ 同号的 `routes/scene-NN.ts`）已随 `#708` 一次性删除。为什么撤、当时为什么可以撤、
将来若再出现「先集中登记、再分批搬走」的局面该怎么做，记在 `docs/adr/0002-legacy-ratchet-retirement.md`。

现在加／删一条命令**只有一条路**：声明住它自己的能力目录——`src/<能力>/commands.ts`（命令事实）
＋ `src/<能力>/routes.ts`（路由声明）；写盘走 `pnpm gen`，比对走 `pnpm gen:check`。
「一个键恰住一处」这条判据仍在，只是换了钉法：`cmd-registry-294.test.mjs` 钉的是
**能力目录的声明里一个键恰出现一次**＋**`src/cli/legacy/` 这个目录不许回来**。

机器拦：`packages/skill-calorie/test/cmd-registry-294.test.mjs`（键集与定义地单源 ＋ 老路容器缺席）
＋ `pnpm gen:check`（生成物 == 生成器输出）。

**棘轮只剩一个**：

| 棘轮文件 | 钉住什么 | 你什么时候要动它 |
| --- | --- | --- |
| `packages/skill-calorie/test/cmd-registry-294.test.mjs` | 分派层两个文件的 `case` 冻结清单 ＋ 那两个文件的行数上限 ＋ 老路容器缺席 | 加／删一条命令碰分派层时（新命令住能力目录，通常不必动它） |

### 形状四 · 两道机器门 + 一个必须手跟的口径

| 门 | 在哪 | 谁加 `case` 谁变红 |
| --- | --- | --- |
| 生成物门 | `pnpm gen:check`（CI 里 `build-test` 作业真跑） | 手改任一件生成物即红 |
| 棘轮 | `packages/skill-calorie/test/cmd-registry-294.test.mjs` | 往分派层加 `case` 即红 |

分派层两个文件的**允许清单只许变短**，`case` 只许随搬迁减少。要加新命令就住能力目录，别往 switch 里加分支。

**还有一处必须手跟，但 `#313` 起改法变了**：新键要能被唤醒词命中，得有一条**路由声明**。

路由的**声明**住各能力目录（`src/<能力>/routes.ts`）——`#708` 之后这是唯一一处声明面
（未搬迁时另住 `src/cli/legacy/routes/scene-NN.ts`，那层容器已退役）。加／删一条命令动的是**自己那一份**，动前**抢锁**。
记录面住**生成物** `src/triggers/routes.generated.ts`：生成器 `scripts/gen-routes.mjs`，进 `pnpm gen` 写盘与
`pnpm gen:check` 逐件比对，日常**零接触**——加／删唤醒词动的是声明，不动这个文件。
`src/triggers/routing.ts` **不承接记录数据**（只剩类型再导出与 `routesFor`／`routingSummary` 这类逻辑），
它**不在生成器 `targets` 里、也不进 `gen:check` 的逐件比对**：手改它那道门不报红，兜住它的只有
`test/calorie-routing-81.test.mjs` 的覆盖对账与独立验收探针「记录面不许回到它身上」的判据；加／删唤醒词别改它。
哪些能力今天已搬、各自对应哪个 `routes.ts`＝**会过期的名单**，不抄在这里，以 `pnpm gen` 的逐件输出为准（同 §二·形状二）。
顺序仍是硬约束：与冻结场景表逐位对齐由声明里的 `order` 字段保（生成器按它排），换文件搬记录也不打乱。

漏了它会红在两处：`test/calorie-routing-81.test.mjs` 的「路由覆盖数 ≠ 权威声明数」与
`packages/skill-calorie/test/cmd-registry-294.test.mjs` 的「代表唤醒词路由回同键」。
**删**命令时它更早暴露：`RouteKey` 是编译期约束（类型唯一处 `src/triggers/routeSpec.ts`），
删了声明直接过不了 `packages/skill-calorie` 的类型门。

## 三 · 判据（照这四条查，别查感觉）

1. **加一条命令，`git status` 里除声明与生成物之外还有没有手写文件？**
   有，就是这份形状还没做到。实测口径：已搬迁的读命令 `test/` 下 0 件；
   写命令另有逐键落库断言要补（见《照抄说明》）。
2. **手改一件生成物，`pnpm gen:check` 红不红？**
   红＝门有鉴别力；绿＝门坏了。基线红不是放宽门的理由。
3. **加一条命令要碰几处？**（`#708` 起没有「搬走一条」这一步了）
   只有两处：`src/<能力>/commands.ts` ＋ `src/<能力>/routes.ts`；其余全是派生。
   若你还得去动第三处手写文件，那就是这份形状还没做到。
4. **加／删一条命令之后，独立验收探针的三桶里 `UNACCOUNTED` 是不是空的？**
   跑 `node docs/skills/skill-calorie/t293-验收-命令自治.mjs`，看 `P1` 那一行。
   探针把「加一条命令要碰的面」分三桶：① 已派生（不用手改）／② 受纪律约束的共用位
   （必须手改但已被纪律认下）／③ **漏网面**（既没派生也没纪律覆盖）。
   `routing.ts` 落 ① 不落 ②（记录面是生成物，见 §一）：② 空着是实况，不是探针坏了。
   **`UNACCOUNTED` 非空 ⇒ 还有面没被认下**，那就是这份形状的新缺口，报上去，别当成探针误报。
   它比 `pnpm gen:check` 管得宽：`gen:check` 只管「生成物 == 生成器输出」，
   探针还管「有没有第四类手写面悄悄长出来」。

## 四 · 本份不写的两件事（写明为什么）

- **不列共用位名单**：那几件正在变成生成物，名单必然过期。判据是
  `pnpm gen:check` 的逐件输出，以它为准（生成器 `packages/skill-calorie/scripts/gen-cli.mjs`）。
- **不抄行数基线、条数上限**：它们住在棘轮文件里（`packages/skill-calorie/test/cmd-registry-294.test.mjs`）。
  查基线去读那个文件，不读这份。（`legacy-ratchet-295.test.mjs` 那份随未搬迁清单一起在 `#708` 退役，见形状三。）
  **量行数用节点口径**：棘轮的冻结值是 `readFileSync(f,'utf8').split('\n').length - 1` 算出来的，
  和记事本／`Get-Content` 显示的行数不是同一个数；口径错了会对着文件怀疑棘轮误报。
