# 合成写判据（接缝 · 断言模板 · 偏离收口）

- 出件票：#659（横切票，`Part of` 地图 #658；规格 #657）
- 适用：`skill-schedule`、`skill-memo-ilife` 两个技能的写侧（跨件共用，故落 `docs/agents/`）
- 裁定依据：`docs/skills/skill-calorie/t593-A-跨技能调用-裁定.md`（第一、三、五节）
- 一句话：**「逻辑一致」不是口号，是一份以老代码为准的不变量清单 ＋ 每条至少一条机器读数**。

## 一 · 契约形状：ensure 型合成写

被调方对外的一条写命令，语义是「把一条业务事实对齐到**本地库 ＋ 它的外部平台**两侧」。判据六条，缺一条即不算合成写：

| # | 判据 | 机器读在哪 |
|---|---|---|
| 1 | 两侧各按**各自的自然键**判重；判重责任全在被调方 | 远端挡板留痕里「建对象」的次数 |
| 2 | 远端对象的**标识回写**本地 | 本地库行的标识列 |
| 3 | 远端对象上带**可反查的归属标记** | 「建对象」那次调用的描述参数 |
| 4 | 回执**分字段**报两侧状态（本地侧、远端侧、远端标识） | 出口回执行 |
| 5 | 远端不可用**不拦住本地写入**，但回执要如实标明，且退出码反映「这一趟算不算达成」 | 远端挡板切不可用那一跑的退出码 ＋ 回执 |
| 6 | 写命令语义统一（覆盖 vs 缺则补由参数讲清，不是两条命令） | 参数面上的 `op` |

两侧自然键**不必相同**。老实现里作息侧本地是 `(date, time_start, time_end)` 三元组、远端是 `(date, time_start, time_end, title)` 四元组——这正是「各按各自自然键」的实例。

## 二 · 接缝与两个注入点

**接缝只有一个**：技能的统一出口（命令行边界，spawn 包内 `dist/cli/cmd_read.js`）。**不立内部模块接缝**（搬进来的老件都是内部件），**不立常驻的老实现对拍接缝**（老实现要弃）。

| 注入点 | 新实现怎么给 | 老实现怎么给 |
|---|---|---|
| 临时数据目录 | `SKILLS_DB_PATH` | 同一个 `SKILLS_DB_PATH`（老实现也认） |
| 可替换的远端平台挡板 | `LARK_CLI_PATH` 直指挡板（`packages/skill-schedule/src/fetch/feishu.ts:16`） | 没有覆盖点，喂它的查找链：`PATH` 首位放挡板 ＋ `APPDATA` 指向挡板根的 `npm/lark-cli.cmd` |

机器件：`tooling/contract-seam.mjs`（接缝件）＋ `tooling/contract-lark-stub.mjs`（替身 lark-cli）。

**前置门不可省**：老实现那一侧是喂查找链进去的，所以每一跑都要让老进程**自己报出**解析到的 `lark-cli` 路径（`assertStubIsTheOne()`），不在挡板目录内即抛——保证「对拍」永远不会碰到真飞书。常驻用例里有这条门的空门反证。

## 三 · 四条读数断言模板

每条移植过来的能力**至少四条读数**，逐条点名，不许合并成一句「通过了」：

| # | 读数 | 判什么 |
|---|---|---|
| ① | 重复调用不重复写 | 本地不增行、远端不重复建对象 |
| ② | 回执分字段 | 本地侧／远端侧／远端标识三格各能单独读到 |
| ③ | 远端不可用时降级 | 本地照样成，且回执如实标明远端侧没成 |
| ④ | 归属标记写对且可反查 | 远端对象上的锚写对，能从远端反查回本地 |

模板的机器部分＝`tooling/contract-seam.mjs` 的 `fourReadings(spec)`：调用方只给三个钩子（`act`／`remoteOff`／`receipt`／`marker`），它返回逐条 `{id, name, verdict, reading}`。**照抄的调用点**见 `test/synthetic-write-659.test.mjs` 的「T4 四条读数模板」。

四条读数之外的判据（分片拉取、孤儿清理、同槽清理、反向对账）按各自能力另立读数，见两侧不变量清单。

## 五 · 有意偏离清单：怎么追加、谁签

**清单正本**＝裁定件第四节那张表（`D-01`～`D-12` 骨架）。本件定它的收口机制，不另立第二份正本。

1. **谁追加**：**落地那张票自己**追加。移植时发现「照抄会坏 / 老实现本身有缺陷 / 新仓形态不允许」的，一律在那一票里往表里加一行，**编号续排**（本票已续到 `D-14`：见裁定件第四节末两行）。
2. **谁签**：**本图负责人**（地图 #658 的负责人）签。追加行随该票的验收一起看；本图负责人不在场时，由该票所在席在自己票里写明「偏离行待签」，**不自行宣布已签**。
3. **每条必须四格**：老行为 → 新行为 → 为什么 → 出处（`老文件:行号` 或 `新文件:行号`）。
4. **每条必须两行机器读数**：
   - **改坏必红**：把行为改回老样子（或把新行为改坏）→ 哪条读数变红（写命令 ＋ 实测结果）。
   - **还原必绿**：改回正确行为 → 同一条读数变绿（写命令 ＋ 实测结果）。
   - 两行都要能**复跑**，不能只贴结论。读数落在：对拍件（老侧 = 基准态）或常驻用例（新侧 = 当刻态）。
5. **当刻还凑不齐两行的**（例如「补幂等键」这种能力在老实现里压根没有、新实现也还没落地）：**照实写「还原行待落地（属主票）」**，不许拿「老行为」冒充「还原态」。落地票摘下这一行时，同时把常驻用例里对应的缺口登记改成达标（见下）。
6. **缺口登记与清单必须同步**：`test/synthetic-write-659.test.mjs` 里那张 `REGISTERED` 表就是「当刻态」的机器版。**修好行为而没改登记 → 用例红**；**改坏行为而登记说达标 → 用例红**。这就是收口动作，不需要额外的人肉检查。
