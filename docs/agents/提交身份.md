`.git/config` 与 `core.hooksPath` 是本机配置、不入库；换机器或新克隆后由 agent 补一条：

```

```

钩子文件本身入库，随 `core.hooksPath` 对本仓**全部 worktree** 生效——`git worktree add` 出来的副本不用逐个重挂。**真开口不止 `--no-verify` 一处**（2026-10-18 逐条真跑出来的六处，别只记一个）：① `git commit --no-verify` 关掉提交侧守卫；② `git -c core.hooksPath= commit` 直接把钩子目录换空（实测能一路提交成功）；③ `cherry-pick`／`rebase`／`am` **保留原作者身份，而且根本不跑 commit-msg**（读数见上表 `50f39d74` 行）；④ `commit-tree`／`hash-object` ＋ `update-ref` 直造对象，不走 `git commit`；⑤ 本机 `core.hooksPath` 是 repo-local 配置、**不入库**，新克隆／换机器不补这一条，两层守卫一起消失；⑥ POSIX 克隆上还有权限位这一道（`git ls-files -s tooling/git-hooks/*` 现值 `100644`，Linux／macOS 下 git 会跳过不可执行的钩子并给提示；Windows 本机 `core.filemode=false`，实测钩子照常跑）。③④ 由推送侧兜住——只要提交要离开本机，pre-push 都会点名；①⑤⑥ 只能靠人守，② 是明着拆守卫。

守卫覆盖到哪、漏在哪，分三档记：

- **推送侧兜得住**：③ `cherry-pick`／`rebase`／`am`（保留原作者身份、不跑 commit-msg）、④ `commit-tree` 直造对象——它们造出来的提交只要一推就被 pre-push 点名（实测 `50f39d74`、`607ca374` 两例都是 exit 1）。注意它查的是**整条推送范围**：把末端的提交改成本人，不能洗掉它下面历史里的旧身份提交（实测 C 例 push 仍 exit 1，直到用 `rebase --exec` 把范围内每条都重写）。
- **只能靠人守**：① `--no-verify`、⑤ 没补 `core.hooksPath`、⑥ POSIX 权限位。
- **本轮没验的**：本机提交后从不推送；第三方工具直写对象库、`git fast-import`、`git replace`；GitHub 侧的归并。这些一律不能当成「已堵」。日常自查读数见第四节。

## 四、复查命令

```powershell
git config --local --get user.name ; git config --local --get user.email   # 期望：王辰浩 / 975559549@qq.com

  ForEach-Object { git -C $_ var GIT_AUTHOR_IDENT ; git -C $_ var GIT_COMMITTER_IDENT }   # 期望 30 行全是本人

git log --format=%ce master | Group-Object | Sort-Object Count -Descending  # 现值 本人 3319＋muse-spark@local 325＋noreply@github.com 25＋agent@local 2
git shortlog -sne --all                                                    # 期望一行 3707（注意：它恒为一行，判不了漏网，见下）
git ls-files -s tooling/git-hooks/                                         # 期望 commit-msg 与 pre-push 都在；权限位现值 100644（见 §二⑥）
# 推送前自查：把要推的分支推给一个一次性裸库，看 pre-push 放不放行（不碰 origin）
git init --bare D:\temp\idcheck.git
git push D:/temp/idcheck.git <要推的分支>:refs/heads/check                 # 期望 exit 0；被点名就是有漏，按 §二修法重做
```

三个取数坑：① `--author='x'` 这种把单引号写进参数里的写法，在 PowerShell 下会把引号原样交给 git，得到零命中——写 `--author=x`，或干脆按 `%ae` 分组数；② 比对身份字符串时把两侧输出各写一个文件再比 SHA256（或直接打十六进制），别在控制台里肉眼看中文——本轮肉眼看「本地配置＝历史作者」时实际比到的是 HEAD 的 `muse-spark`，是十六进制读数把它抓出来的；③ **别用 `git shortlog -sne` 判断有没有漏网**——`.mailmap` 在位时它永远是「一行 王辰浩」，漏网的旧身份提交被归并进去、看不出来；只有按 `%ae`／`%ce`（原始字段，不经 `mailmap`）分组才数得出来。
