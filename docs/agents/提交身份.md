`.git/config` 与 `core.hooksPath` 是本机配置、不入库；换机器或新克隆后由 agent 补一条：


- 上面三道拦截只管**此后**的提交。要让历史 SHA 上的身份也变成用户本人，只能重写历史（`git filter-repo`）：`master` 3668 个提交里 3340 条作者要换身份，其余提交因父提交变化也要重算 SHA；牵连 100 个 ref、8 个 tag、37 条远端 ref、4 个 stash，且必须强推。一旦别人的工作在旧主线上，重写会把他们的产出孤儿化（本仓 2026-09-15 实测发生过两次，见 `docs/subagent-concurrency-protocol.md`）。**用户未授权改写历史，本轮不做**；要改，由用户点名后单独立项。
- 不改历史时，归并已经生效的地方：`git shortlog`、`git log --format='%aN <%aE>'`、`git blame` 都显示归并后的身份。一处反直觉读数：`.mailmap` 在位时 `git log --author=975559549@qq.com` 会把作者为 `muse-spark@local` 的提交**一并**命中（命中 HEAD `91ac32ab`；对照 `--author=nobody-xyz@nope.invalid` 零命中，排除过滤器失效）——按 `--author` 数「本人提交条数」会偏高，要按 `%ae` 分组数。
- GitHub 侧（贡献者页、`contributors?anon=1`）是否按 `.mailmap` 归并，本仓不承诺，以 `gh api 'repos/FeatherHunter/ilife/contributors?anon=1&per_page=100'` 读数为准（本轮未复查）。

## 四、复查命令

```powershell
git config --local --get user.name ; git config --local --get user.email   # 期望：王辰浩 / 975559549@qq.com
git config --local --get core.hooksPath                                    # 期望：<repo>/tooling/git-hooks
git hook run commit-msg                                                    # 期望 exit 0
git worktree list --porcelain | Select-String '^worktree ' |
  ForEach-Object { $_.Line.Substring(9) } |
  ForEach-Object { git -C $_ var GIT_AUTHOR_IDENT ; git -C $_ var GIT_COMMITTER_IDENT }   # 期望 30 行全是本人
git log --format=%ae master | Group-Object | Sort-Object Count -Descending  # 期望只剩 975559549@qq.com
git log --format=%ce master | Group-Object | Sort-Object Count -Descending
git shortlog -sne --all                                                    # 期望一行 3707
```

两个取数坑：① `--author='x'` 这种把单引号写进参数里的写法，在 PowerShell 下会把引号原样交给 git，得到零命中——写 `--author=x`，或干脆按 `%ae` 分组数；② 比对身份字符串时把两侧输出各写一个文件再比 SHA256（或直接打十六进制），别在控制台里肉眼看中文——本轮肉眼看「本地配置＝历史作者」时实际比到的是 HEAD 的 `muse-spark`，是十六进制读数把它抓出来的。
