# 多语言 · 渲染语言上下文与机械迁移（规格 #1197 的执行层）

状态：已落地（2026-11-01，规格 #1197 迁移期）。上游决定见 `docs/adr/0004-多语言文本外置.md`。

## 1. 要解决的问题

1,214 个源文件、约 4.25 万条含中文的字符串要搬进词条层，跨 28 张迁移票；票面写集**互不重叠**。
若语言按参数逐链下传：

- 调用方常落在**别的票**的文件里——单票改完自己那批，编译期必然还有一批「调用方没传语言」，单票无法绿；
- `base-paint`（`packages/base-render`）组件被各技能页调用，组件先要语言、调用方又得先有语言才能传，形成环；
- 每个渲染函数、每个组件属性都要新增一维参数，接口膨胀且容易被漏传（#1307 已实证「漏传＝静默中文」）。

## 2. 决定：语言经运行期上下文传递，取词走每包一个 m()

- `packages/base-entries/src/language-context.ts`：`runWithLanguage(language, run)` 进入上下文，
  `currentRenderLanguage()` 读当前值；**未进入上下文时返回基准语言 `zh`**——不启用多语言时产物逐字节不变（ADR-0004 第 7 条不变量）。
- 实现是 `base-entries` 内的**进程内上下文栈**（模块级变量 ＋ `try/finally` 还原）：本包零运行时依赖，ADR-0004 §4 的收窄规则明写公共层零依赖包「图无环、不含 `node:` 与第三方」，`node:async_hooks` 会破这条（本包还被 base-render 组件间接引用）。回调返回 Promise 时语言保持到 settle 再还原。
- 限制（写进契约，不许默默依赖）：同一进程内**两段异步渲染交错**会互相覆盖语言。本仓不存在这种调用（技能一律子进程起 CLI、测试串行）；将来若出现，改成注入式上下文端口（调用方把自己的上下文实现传进 `resolve`／`evaluate`），不许在这个模块里偷偷引入 `node:`。
- 技能 CLI 是唯一语言入口：`resolveLanguageOrFail(process.argv.slice(2))`（#1198 语言选择链：argv ＞ `language.text` ＞ caller ＞ zh，未识别值报错并列出可用语言）解析一次，随后
  `runWithLanguage(language.text, ...)` 包住本次命令剩余执行。配置命令（不渲染页面）保持在上下文之外。
- 每个包在 `packages/<pkg>/src/entries/index.ts` 导出取词函数：

  ```ts
  export function m(id: <Pkg>MessageId, params?: MessageParams): string {
    return resolve(<PKG>_CATALOG, currentRenderLanguage(), id, params);
  }
  ```

  迁移后的源码调用 `m('key')` / `m('key', { p0: expr })`；回退链、占位符求值、缺词条抛错仍全部住 `base-entries`，各包不复制机制。
- 已迁移 12 件的**显式 `language` 参数签名保持可用**（写域 #1304／#1306／#1307 的接线不回退）；上下文与显式传参是两条入口，同一个 `resolve`，不产生第二套语义。

## 3. key 命名（第一轮＝派生命名）

`<包目录>.<相对 packages/<pkg>/src 的路径去 .ts、非字母数字折成 ->.<四位序号>`

例：`skill-bill.write-blockedSlots.c001`。

- 全仓唯一：包目录打头、路径段与序号保证不撞；缺词条门要求全仓 key 唯一（同语言多份表重复 key 即红）。
- 形状满足缺词条门的 key 正则（末段小写字母开头）：`c001` 合法。
- 不以 `bill.` / `calorie.` / … 开头——那些前缀留给冻结的命令键。
- 序号在同一文件内按出现顺序递增，重跑幂等；语义化命名（如 `progress-list.remain`）留给首批试点件，其余第一轮不追可读性。

## 4. 词条表布局与写入

- 每包三件：`src/entries/zh.ts`（基准语言，key 权威）、`src/entries/en.ts`（同 key 英文）、`src/entries/index.ts`（`defineCatalog` ＋ `m()` ＋ key 类型）。
- 迁移器按文件**追加一节**到 zh.ts / en.ts（不重排既有条目）：节前注释 `/* ── <相对路径>（#<票> 迁入）── */`；zh 值逐字等于改造前字面量；**en 先写空串**，由本票内回填。
- #1306 口径：空串＝未录，缺词条门 `blanks=` 判红——空英文列只许当票内草稿，**不许进提交**。

## 5. 执行器（tooling/）

### 5.1 `tooling/i18n-migrate.mjs`

TypeScript AST 改写器，把票面文件清单里的用户可见中文搬进词条表并把源码换成 `m(...)`：

```text
node tooling/i18n-migrate.mjs --ticket 1205          # 按 tooling/i18n-ticket-scope.json 的文件清单
node tooling/i18n-migrate.mjs --files a.ts,b.ts --dry --json
node tooling/i18n-migrate.mjs --selftest
```

- 只迁「上屏文本」：单字面量 → `m('key')`；`+` 链／带插值模板串 → **整句化**为一条 `{p0}`… 模板（字面量片段逐字进模板、非字面量操作数成为具名参数），保住拼接顺序与 String 化行为；
- 不迁：命令键、用户数据、比较／匹配用的串、dev 失败报文（`fail(...)`、`assert*`、`new *Error(...)` 的实参）、生成件（`.generated.ts`、`helpAssets.ts`、`sceneData.ts`、`helpShell.ts`、`cli/registry.ts` 等）；
- **fail-closed**：拿不准的形状（spread、条件分支、JSX、正则）整件报 `UNSUPPORTED` 并不写盘，留人处理；每个「不迁」都出现在报告里，不许静默丢；
- 写前备份到 `.scratch/i18n-migrate-backup/`，清单落 `.scratch/i18n-migrate/`；重跑幂等（已迁移文件 0 改动）；末行 `RESULT: files= migrated= skipped= entries= unsupported=`。

### 5.2 `tooling/i18n-fill.mjs`

英文回填：`--list-pending --pkg <pkg> --out <.json>` 取出待译条目（`{key, zh}`），翻译后 `--pkg <pkg> --map <json>` 按 key 写入 en.ts。

- 只填空串；未知 key、重复 key、空白译文一律报错不写；
- 重写 en.ts 时保持与 zh.ts 相同的 key 顺序与表头注释。

## 6. 每张迁移票的标准流程

1. 开工单：确认文件清单来自 `tooling/i18n-ticket-scope.json`（不手抄）；先 `node node_modules/typescript/bin/tsc -b` 基线绿。
2. 迁移：`node tooling/i18n-migrate.mjs --ticket <n>` → 看 `RESULT` 与清单，处置 `UNSUPPORTED`／`skip` 项（生成件改生成器，不手改生成物）。
3. 补英文：`--list-pending` → 翻译 → `--map` 回填；payload／可运行样例等按既有先例 en 可等于 zh，但须在票面记明。
4. 登记范围：把本票文件路径加进 `tooling/i18n-scope.json` 的 `files`（由 Lead 串行改，避免共享清单并发写）。
5. 验证（六条，缺一不可）：
   ① 全仓 `node node_modules/typescript/bin/tsc -b` exit 0；
   ② 两道门先红后绿（`check-i18n-entries` 的 `missing=0 blanks=0`；`check-i18n-keys` 的 `residue=0`；`--language en` 时无中文上屏由 ③ 的 CLI 抽样证明）；
   ③ 中文列逐字节不变：改前／改后 `git hash-object` 同一文件同值（以及该技能既有快照门 `--check`）；
   ④ 英文列新录（英文页／英文 CLI 抽样，偏离登记账本）；
   ⑤ `pnpm gate:i18n`（含占位符门 `check-i18n-params`）绿；
   ⑥ CLI 端到端：同一命令 `--language en` 无中文、`--language zh` 与改前逐字节相同。
6. 提交只暂存本票路径，票面如实更新读数。

## 7. 边界与已知遗留

- 生成件不手改：改生成器（如 `docs/skills/skill-bill/1079-say-数据生成器.mjs`）后重生成，属同票工作。
- 跨包重复串（#1231）在迁移后按「单一来源派生」收口，不在各票里手工合并。
- 词条表 key 全仓唯一这一条由缺词条门守；跨包共用词另立命名空间。
- 语言链的英文**产物级**验收（设 `language.text: en` 后整页英文）归 #1198 收口票；迁移票只保证本票范围。
