## 2. 问题 1：走 spawn 子进程的测试有多少条，各自靠什么隔离

### 2.1 计数口径（可复算）

三条正则，都只读文本、不跑测试：

1. **测试件**＝目标目录下 `*.test.mjs` 文件数。
2. **走 spawn 的测试件**＝该文件里出现 `node:child_process` 的 `*.test.mjs` 文件数。
3. **spawn 调用点**＝目标目录全部 `*.mjs` 里 `spawnSync\(|execFileSync\(|execSync\(|spawn\(` 的匹配次数（`grep -c` 口径，含 import 行以外的调用与注释里的同形串；import 行形如 `{ spawnSync }` 不带左括号，故不计）。
4. **用例声明数**＝上述走 spawn 的文件里 `^\s*(?:test|it)\(` 的匹配次数（含 `describe` 内的 `it`）。
   ⚠️ 它是「这些件里的用例总数」，**是「走 spawn 的测试条数」的上界**——用例与 spawn 的连线在 helper 里，用例级精确切分无法用正则完成（见 §6）。

复算命令（本机 PowerShell，只读）：

```powershell
$root='D:\ilife'
$dirs=@('test','packages\skill-bill\test','packages\skill-calorie\test','packages\skill-chef\test','packages\skill-home\test',
        'packages\skill-memo-ilife\test','packages\skill-schedule\test','packages\plugin-bill-ilife\test','packages\plugin-calorie\test',
        'packages\plugin-chef\test','packages\plugin-home-ilife\test','packages\plugin-memo-ilife\test','packages\plugin-schedule-ilife\test')
$reSpawn='spawnSync\(|execFileSync\(|execSync\(|spawn\('
foreach($d in $dirs){
  $p=Join-Path $root $d
  $files=@(Get-ChildItem -LiteralPath $p -Filter *.mjs -File -Recurse)
  $tf=@($files | Where-Object { $_.Name -like '*.test.mjs' })
  $spawnFiles=@(); $cases=0; $sites=0; $inproc=0
  foreach($f in $files){
    $t=[System.IO.File]::ReadAllText($f.FullName)
    $sites += ([regex]::Matches($t,$reSpawn)).Count
    if($f.Name -like '*.test.mjs'){
      if($t -match 'process\.env\.ILIFE_CONFIG_DIR\s*='){$inproc++}
      if($t.Contains('node:child_process')){
        $spawnFiles+=$f.Name
        $cases += ([regex]::Matches($t,'(?m)^\s*(?:test|it)\(')).Count
      }
    }
  }
  "{0}: 测试件={1} 走spawn件={2} spawn调用点={3} 用例声明={4} 进程内设变量件={5}" -f $d,$tf.Count,$spawnFiles.Count,$sites,$cases,$inproc
}
```

## 4. 问题 3：三种替代机制各有什么代价（只列事实）

### ① 子进程把 `HOME`／`USERPROFILE` 指到临时目录

**`os.homedir()` 在这台 Windows 上到底读哪个变量（本机实测，Node v24.19.0）：**

| 探针设置 | `os.homedir()` 返回 |
|---|---|
| 原样（`USERPROFILE=C:\Users\辰辰洋洋`、`HOME` 未设） | `C:\Users\辰辰洋洋` |
| `USERPROFILE=C:\__fake_up` ＋ `HOME=C:\__fake_home` | `C:\__fake_up` |
| 删掉 `USERPROFILE`，只设 `HOME=C:\__fake_home` | **`C:\Users\辰辰洋洋`（`HOME` 无效）** |
| `USERPROFILE=C:\__fake_up2`，删掉 `HOME` | `C:\__fake_up2` |

⇒ 事实：**`os.homedir()` 在 Windows 上认 `USERPROFILE`，不认 `HOME`；删掉 `USERPROFILE` 会回落到系统 API 取真实用户目录，仍然是真实家目录。**
（另：本机 `HOMEDRIVE=C:`、`HOMEPATH=\Users\辰辰洋洋`，但上面两行实测说明决定权在 `USERPROFILE`。）

- 这个口子属于系统环境变量，不是「我们自己定义的环境变量」（与维护者那句话的口径相容）。
- **要改的件**：`test/helpers/config-test-base.mjs:29-39`（把 `setupConfigTestBase` 改成设 `USERPROFILE`／`HOME`，并按平台分叉）、
  六家 helper（§1.2 五处）、**216 个进程内设 `process.env.ILIFE_CONFIG_DIR` 的件**、**199 个走 spawn 的件**（子进程 env 里换变量名）、
  `test/config-694.test.mjs`（A1 `:70-76` 要重写；A2 `:78-85`「默认落点派生自 `os.homedir()`」这条**不变**）、
  各包 `config-695.test.mjs` 与 `*-fetch.test.mjs` 里「缺 `ILIFE_CONFIG_DIR` 即响亮失败」那一族用例
  （例：`packages/skill-home/test/fetch.test.mjs:58-66`、`packages/skill-chef/test/fetch.test.mjs:113-123`、
  `packages/skill-home/test/cli.test.mjs:109-110`、`packages/skill-chef/test/cli.test.mjs:134`、`test/synthetic-write-659.test.mjs:53-64`）。
- **测试要不要改写**：要（面最广）。
- **先例**：**没找到**。`grep -rn 'USERPROFILE'` 在 `packages/` 下零命中；仓里没有一处给子进程改 `HOME`／`USERPROFILE`。
- 另一条事实：`NODE_TEST_CONTEXT` 那道门的判据要一起重写（它今天比的正是「有没有设 `ILIFE_CONFIG_DIR`」）。

### ② 测试全改进程内直调（不经 CLI 出口）

- **仓内已有的反向口径（先例，但只立在本包）**：`packages/skill-calorie/AGENTS.md:88` 起「测试面口径（#702 立，只立在本包）」——
  `:94` 要求断言打在**生产真正走的那条路**（页面走 `dist/cli/cmd_read.js`／`cmd_write.js` 那条 spawn 路；
  同逻辑不 spawn 时走同件的 `dispatch(key, params, db)`）；`:98` 记着机器门 `scripts/check-page-assert.mjs`（spawn 真交付出口又断它成功的件，必须把 stdout 解析成 envelope，只断 `exit 0` 是假绿）；
  `:102` 「生产不走的缝不算缝」；`:105-106` 「算法正本的单元测试」是明文例外；`:109` `scripts/check-one-path.mjs`；`:115` 两个门各有 `--selftest`。
- **⇒ 代价一**：这一改会把该族交付面判据整族降级，并且要连着改 `check-page-assert.mjs` 的判定面（它只把 spawn 真出口的件纳入判定）。

## 5. 问题 4：把「用非环境变量的情况在某个非生产库的路径做测试」落成可行方案

> 三个方案都写成「改哪些件 ＋ 判据怎么设」。三者的覆盖面对比放在最后，不替维护者选。

### 方案一：落点函数加可选入参 ＋ `base-link-core` 加模块级注入点（进程内），CLI 加 `--config-dir`（跨进程）

  - `packages/base-link-core/src/config/index.ts` ＋ `src/index.ts`：转出注入函数与新签名。

  - 六家 `test/helpers/*`：把「写 `process.env.ILIFE_CONFIG_DIR`」换成「调注入点 + 回 argv 片段」。
  - 216 个进程内件与 183 个 A 类 spawn 件：赋值行／env 格换成新口子。
- **判据怎么设**
  1. `node --test test/config-694.test.mjs`：A1（`:70-76`）改成「注入点生效」；A4（`:92-102`）改成「注入点为空 ＋ `NODE_TEST_CONTEXT` 非空 ⇒ 抛」，并保留那条反向对照；
  2. 负向对照：不带 `--config-dir`、不注入时落 `~/.ilife`——这条要在 `USERPROFILE` 指向临时目录的子进程里跑（否则当场写真实库）；
  3. 生产不许调注入点：一道 grep 门（`packages/*/src` 里除 `base-link-core` 外零命中；`config/index.ts` 只薄转出）；

  1. 一次 `node packages/skill-calorie/dist/cli/cmd_read.js <读命令> --config-dir <tmp>` → 产物落 `<tmp>/data/`；

  4. `packages/skill-calorie/scripts/check-page-assert.mjs` 与 `check-one-path.mjs` 仍绿（交付面判据一条不降级）。
- **先例**：**没找到** CLI 级的落点参数先例（本次 `grep` 未命中任何 `--config-dir` 一类的开关）；各包 CLI 现成的 argv 开关只有 `--params` 与 `--html` 两个（用例里逐字可见，如 `packages/skill-bill/test/t411-query-skeleton.test.mjs:40`）。
