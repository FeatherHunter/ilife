# #1199 门禁改造：迁移票验收命令回填清单

本文件是 **#1199 门禁改造**的产物之一：给 **28 张迁移票**（地图 #1197 的子票）回填「改完这一件，该跑哪几条命令、看哪几行读数」。
口径依据：`docs/adr/0004-多语言文本外置.md` §6「门只锁结构与行为，不锁文案字面」，以及 `docs/agents/结构纪律`（`docs/agents/structure.md`）。

## 0. 一句话形状

| 层 | 唯一定义地 | 谁读它 |
|---|---|---|
| 语言闭集与缺省语言 | `packages/base-link-core/src/config/language.ts`（产品侧） | 门不 import 它，只按 `tooling/i18n-langs.mjs` 的 `LANGUAGES` 对账 |
| 语言列账本路径与排印名册 | `tooling/i18n-langs.mjs`（门侧） | 各门 `import`，不各写一套 |
| 已迁入词条层的文件清单 | `tooling/i18n-scope.json`（状态账号本） | 缺词条门 ＋ key 残留门 |

**中文列＝存量路径**（文件名不带语言段），**英文列＝`<主体>.snapshot.en.json`**。语言身份由**文件名**承载，账本正文一个字段都不加——加字段就是改字节，就是破坏「中文列逐字节不变」。

## 1. 迁移票开工前 / 收尾各跑什么（逐条命令＋看哪行）

### 1.1 未声明差异为零（每张迁移票必跑）

```
pnpm snapshot:html:check        # 中文列 194 件账本：看 COLUMN zh / RESULT / changed / added / removed 三行
pnpm snapshot:html:check --lang en   # 英文列：看 COLUMN en recorded=<n> 与 PENDING 行
```

- **中文列**：`changed=0 added=0 removed=0` 才算「未声明的差异为零」。任何一件变都要在票面**先申报**。
- **英文列**：`recorded=<n>` 是**已记**的偏离件数，`PENDING` 行表示「英文列还没有对照读数」——那不是绿，也不是红，是「还没有英文页」。

### 1.2 calorie 列（只对卡路里线的票）

```
node tooling/calorie-html-snapshot.mjs --check          # 中文列 2 件：看 OK/RESULT 两行
```
英文列按 `tooling/calorie-html.snapshot.en.json` 另起（形状与主账本英文列同）。

### 1.3 两道新门（每张迁移票收尾必跑）

```
node tooling/check-i18n-entries.mjs     # 缺词条门：看 SCOPE/TABLES/RESULT 三行
node tooling/check-i18n-keys.mjs        # key 残留门：看 SCOPE/RESULT 两行
```

- 范围为空时两道门都印 `EMPTY-SCOPE 范围 0 件：扫描面为空——缩面＝放宽，不许空转当绿` 并 exit 0；**这个读数必须贴进证据**。
- 迁移票把**本票改完的件**逐条写进 `tooling/i18n-scope.json` 的 `files`，两道门才开始真判。
- 残留（`RED 文案残留：<文件>:<行> [<语言>] ...`）不许往 `allowlist` 里塞——那是放宽。

### 1.4 排印／结构门（改了版式或文本形状的票）

```
node --test packages/base-render/test/style.test.mjs              # 最小字号下限
node --test packages/base-render/test/t897-legend-min-font.test.mjs
node --test packages/base-render/test/text-entry-min-font-1001.test.mjs
node packages/base-render/scripts/check-rendered-text.mjs --dir <页群目录>   # 渲染面 ⑤⑥（需本机 headless Chrome）
node packages/base-render/test/separator-probe.mjs <结果型 HTML>            # 分隔符门 R1/R2/R3
node tooling/check-typography-langs.mjs                                     # #1199 排印门语言无关化（名册＋版式读数基线）
```

`node tooling/check-typography-langs.mjs` 的读数形状（迁移票贴证据用）：

```
ROSTER: 产品侧=["zh","en"] 门侧=["zh","en"] 同值=true
STRUCTURAL（语言无关，所有语言同一套）: overflow, noWrap, fontFloor, touchTarget, boxModel
REGISTER zh: separators=["·","｜","；"] maxSegChars=40 fontFloorPx=11 boxGridPx=4 bareLatinIsFault=true
REGISTER en: separators=[] maxSegChars=80 fontFloorPx=11 boxGridPx=4 bareLatinIsFault=false
BASELINE: 存续债 1 条（OVERFLOW@甲-02-待办清单.html@390）· 命中 1 · 新增 0 · 已清 0
RESULT: langs=2 structural=5 fixtures=9 violations=0
PASS: 结构约束语言无关（5 条）× 语言阀值分列（2 门）＋ 版式夹具 9 条读数（存续债 1 条已登记、新增 0）
```

**版式读数基线**：既有版式夹具里已有 1 处与结构约束冲突的读数（`甲-02-待办清单.html@390` 的 `outOfBounds=1`），在 `tooling/check-typography-langs.mjs` 的 `FIXTURE_BASELINE` 里**逐条登记为存续债**。台面上新出现的读数＝红（新债不许静默进来）；基线里有而台面上没有的＝红（债还清了要显式改基线）。

**语言无关的结构约束**（所有语言同一套，不许按语言放宽）：不溢出／不换行／最小字号下限／可点面积下限／盒模型 4px 栅格。
**语言相关的书写阀值**（每种语言一套，出处 `tooling/i18n-langs.mjs` 的 `LANG_REGISTERS`）：并列分隔符集／并列段长上限／半角标点集／允许清单／是否判裸拉丁词／字号下限。

### 1.5 命令关键字（冻结，不译）

```
pnpm gen:check     # 生成物 ≠ 生成器输出即红；命令关键字改动必须走这条路
pnpm boundaries    # 结构边界门（含 #1199 新增的公共层依赖白名单：base-* 之间只许依赖零依赖的公共层包）
pnpm base:floor    # 依赖下界门（扫描面为空也红）
```

`pnpm boundaries` 里 #1199 新增的那条读数形状：

```
OK: 公共层零依赖包至少得有一个（实得 2：base-link-core、base-render）
OK: 公共层包之间的依赖白名单：base-render 只许依赖零依赖的公共层包（base-link-core、base-render）；实得越界 无（全部公共层依赖：base-link-core）
```

> 这条是**收窄**不是放宽：旧的「render 无运行时依赖」被换成「公共层之间的依赖只许指向零依赖的公共层包」。存量 `base-render`／`base-combos` 对 `base-link-core` 的依赖照旧合法（link-core 本身就是零依赖包）；`base-entries` 一旦入仓，它必须零运行时依赖才能被依赖。

## 2. 语言列接口契约（给迁移票与门作者）

### 2.1 账本文件

| 语言 | 主账本 | calorie 账本 |
|---|---|---|
| `zh`（缺省，基准） | `tooling/skill-html.snapshot.json`（194 件，逐字节冻结） | `tooling/calorie-html.snapshot.json`（2 件） |
| `en` | `tooling/skill-html.snapshot.en.json` | `tooling/calorie-html.snapshot.en.json` |

英文列账本形状（**记录形**，只记偏离中文列的产物，不做同哈希全量复制）：

```json
{
  "lang": "en",
  "basedOn": "tooling/skill-html.snapshot.json",
  "readonlyUntilMigrated": true,
  "artifactCount": 0,
  "records": { "<产物 id>": { "sha256": "<32hex>", "bytes": 123, "note": "为什么偏离中文列" } }
}
```

三条完整性判据（本门自己判，违反即红）：

1. 键集必须是中文列 `artifacts` 的**子集**（英文列不许凭空多产物）；
2. 记录的 `sha256` **必须 ≠ 中文列同件**（相等＝没记＝空转绿，`loadLangColumn` 直接抛）；
3. `lang` 与 `basedOn` 必须显式写对（不许沉默地指向别的账本）。

### 2.2 词条表（缺词条门的输入）

| 项 | 值 |
|---|---|
| 目录 | `packages/base-entries/src/entries/` |
| 文件名 | `<lang>.json`（`zh.json`／`en.json`；加语言＝加一条 `LANGUAGES` 名册＋加一个文件） |
| 形状 | 顶层对象，键＝词条 key（`<命名空间>.<名字>`），值＝该语言的词条 |
| 调用形态 | 源文件 `import` 词条层（模块名含 `base-entries`），按 `e('ns.id')`／`t('ns.id')`／`ent.t('ns.id')` 取词条 |

> ⚠ 词条包本体归 **#1200**（`packages/base-entries`）。本文件里的目录／调用形态是**门侧的读取契约**；#1200 冻结接口后若形状有出入，改的是 `tooling/check-i18n-*.mjs` 的读取口径与本文，**不是**把清单挪走。

### 2.3 已迁入清单（状态账号本）

`tooling/i18n-scope.json`：

```json
{ "files": ["packages/skill-bill/src/...ts"], "allowlist": [] }
```

- `files`：**已迁完**的仓库相对路径（正斜杠）。范围为空时两道门显式报「范围 0 件」并 exit 0。
- `allowlist`：逐条豁免**字面量原文**（放行只许是「语义上本就不该进词条的位」：命令关键字冻结／用户数据不译／派生件）。

## 3. 基座自带的两处红（**不是** #1199 引入，迁移票别把它算自己头上）

### 3.1 `pnpm snapshot:html:check` 在基座直接崩（已修）

```
$ node tooling/skill-html-snapshot.mjs --check        # 基座 5cb95a72
FAIL: BillRenderError: 无法渲染形状：resultset
    at collectArtifacts (tooling/skill-html-snapshot.mjs:149)
[exit=1]
```

原因：`bill.data.query`／`bill.data.schema` 落在 `resultset` 形状（数据族，#952「不参与渲染」），而门的 6 形状名册与载荷夹具里都没有它 → **门自己摔死、读数作废**。
#1199 的处置：形状闭集拆成「渲染面 6 ＋ 非渲染面 1」，`assertShapeClosure()` 自证每一件都有夹具；非渲染面不取片段（不塞进产物账本），只要求渲染入口**显式拒绝**。

### 3.2 中文账本陈旧 ＋ 影响面标记（待裁）

```
$ node tooling/skill-html-snapshot.mjs --check
COLUMN zh  artifacts=193 ledger=tooling/skill-html.snapshot.json
compare → changed=49 added=[] removed=['memo/frag/memo.stats'] staleText=0 markers=89
```

- `changed=49`：`bill/keys`／`chef/keys` 各多 2 条 `resultset` 键；`home` 37 件、`memo` 9 件、`schedule` 1 件——账本记的是更早那一次采集。
- `removed=1`：`memo/frag/memo.stats` 已不在当刻产物里。
- `markers=89`：31 件产物含 base-paint 命名空间标记，全部落在 `home`／`memo`（这两家已按票迁到 base-paint）。`MARKER_ALLOW` 现行 `{}`。
- ⚠ `--write` 在标记命中时**一个字节都不写**（先校验后落盘）⇒ 不扩 `MARKER_ALLOW` 就没法重录，这道门会一直红。**这是既有死结，要维护者裁**（见 #1199 证据）。
