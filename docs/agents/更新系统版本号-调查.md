# 更新系统版本号调查（2026-10-07）

> 一句话：本仓不再拥有更新语义，只剩薄接线；版本号分三层——上游更新器、本地七包、七个更新目标。

## 1. 上游更新器 dsh-plugin-update

**政策（2026-10-10 `38318ad6` 复归）**：声明恒为 `latest`（更新系统一直自动用最新），新鲜度由锁保证——`tooling/check-publish.mjs` 的 `--pre` 门只认两条：声明 == `latest` ＋ 锁落版本 == 线上最新。声明一钉确定档，这条 required 门立刻红（门在第 136 行）。

| 读数位置 | 版本 | 说明 |
| --- | --- | --- |
| `packages/plugin-manager/package.json`（dependencies） | `latest` | 声明恒定，不钉确定档 |
| `pnpm-lock.yaml`（importers 的 `packages/plugin-manager`） | `0.12.0` | 2026-10-11 集成读数：specifier `latest` / version `0.12.0` |
| `packages/plugin-manager/node_modules/dsh-plugin-update/package.json` | `0.12.0` | 嵌套实际装机版本（解析落点 `node_modules/.pnpm/dsh-plugin-update@0.12.0/`） |
| `https://registry.npmjs.org/dsh-plugin-update` → `dist-tags.latest` | `0.12.0` | 线上最新（2026-10-11 02:2x 读数，2026-10-10 17:56Z 发布） |

**为什么声明用 `latest` 而不是钉版本**：钉过两次，两次都回退——`1244` 的 `ef05a95a` 钉 `0.10.0`，同日 `38318ad6`（PR #1263）改回 `latest` 并让 `publish:pre` 回绿。

**升版手法（2026-10-11 实测，两步）**：pnpm 11 对 dist-tag 声明**不向前重解析**——`pnpm up dsh-plugin-update` 与 `pnpm up dsh-plugin-update --latest` 都回 `Already up to date`，锁纹丝不动。可行路径是：

1. 声明临时钉成目标版本 → `pnpm install --no-frozen-lockfile`（锁解析到目标版本）；
2. 声明改回 `latest` → 再 `pnpm install --no-frozen-lockfile`（锁只剩 specifier 一行变化，version 保持目标版本）；
3. `pnpm install --frozen-lockfile` 复核锁自洽。

即 `ef05a95a` ＋ `38318ad6` 那对提交的真实形状。两次 install 之间**不要**顺手改别的包，不然锁的 diff 会越出更新包条目（现场：本次 4 行，只含 `dsh-plugin-update`）。

**接线面（版本无关的形状）**：本仓只走三个子路径出口——`dsh-plugin-update/batch`（`createMultiHostUpdate`）、`dsh-plugin-update/entry-batch`（`mountUpdateBatchEntry`）、`dsh-plugin-update/panel-batch`（类型）。0.10.0 → 0.12.0 这三个子路径的 `.d.ts` 逐字节未变，`entry-batch.js` 也未变（变的只是 `host-batch.js`／`panel-batch.js` 实现体与 host/panel/store 内部），故薄接线零改动；装机实测三个出口齐在且各可调用。
