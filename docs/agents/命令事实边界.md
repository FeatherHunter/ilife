# 命令事实边界（一处口径）

**一句话**：一条命令的事实只住它自己的能力目录（`src/<能力>/commands.ts` 那一行 ＋ 同目录的处理函数）；
所有共用位都是那个定义地的派生件（生成器出、机器门守），人日常零接触。

## 边界三问（照此判，不查感觉）

1. **选实现／取数吗？** 是 ⇒ 住能力目录（声明 ＋ 处理函数）；共用位只做薄查表。
2. **只有一个能力用吗？** 是 ⇒ 留在那个能力目录里；写得出两个以上在用才进共享件，
   且共享件头必须写清是哪几个在用（`shared/writeParts.ts` 同例）。
3. **是生成物吗？** 是 ⇒ 以 `pnpm gen:check` 的逐件输出为准，手改即红；改权威声明再重生成。

## 归属裁定（#330 两处）

| 手写表 | 归属 | 理由 |
| --- | --- | --- |
| `profileReceiptDoc`（三条档案写命令→整页回执，旧住 `src/cli/write.ts`） | 能力目录 `src/profile/receipt.ts`，经 `src/profile/index.ts` 转出，分派层只调门 | 只有一个能力（基础信息）在用；声明与实现本就在 `src/profile/`，端口跟过去后分派层不再出现任何命令名字面量 |
| `writeSuffixFor`（21 条命令→落盘文件名内容标识段，旧住根 `src/output.ts`） | 共享件 `src/shared/contentSuffix.ts`，根输出件只改引用＋再导出（测试导入面不变） | 六个能力共用（饮食／喝水／体重／运动／身材照／食品库）；纯 params 派生、不读库；整搬、行为逐字不变 |

## 非目标（写明不算什么）

- 这两处都不选实现、不取数：`profileReceiptDoc` 只换回执整页，
  `writeSuffixFor` 只产文件名片段。故它们不是 `#320` 字面的「分派分支」，
  而是同族欠账——#330 收，不回头改 #320 的达成措辞。
- 落盘名的最终仲裁（独占创建＋同秒递补）仍在共用件 `base-paint/save-html`，
  本页不管（见 `src/output.ts` 头注与 #237 记账）。
