六家技能的「交付面」：缺省落点的现状与对齐成本

调查对象：skill-bill／skill-calorie／skill-chef／skill-home／skill-memo-ilife／skill-schedule ＋ 对应六个 DSH 插件
口径：源码逐行读 ＋ 真出口真跑（隔离家目录）＋ 票面沿革　　成文：2026-09-22

实测 隔离家目录真跑得到的读数 源码 盘上源码的行号 票面 issue／证据件里的原文 估计 量级判断，不是读数

三句话读完

  1. 「说一句话就落一份 HTML」是技能自己决定的事，不是宿主工具给的参数：六家的 agent 工具完全同形，只传 key ＋ --params，谁也传不进 --html。
  2. --html <路径> 的真实语义是「指定落点」，不是「落不落页的总开关」。决定落不落页的是缺省落点有没有做。这个口六家 CLI 都有，但缺省落点四家做了、两家没做。
  3. 没做的两家缺口不一样大：饼干记账只差「落盘这一步」（页面本身已是整页，出口也接上了）；私家大厨的页面已经造好（六个域各一件 pages.ts ＋ cook 域三页，页壳走 render/sceneShell.ts），缺的是「命令出口 → 那些页」这一段接线——现在跑命令给 --html，写出来的还是一个裸 <section> 段。

一、这件事的结构：从一句话到一份文件，中间有四层

① 唤醒词用户说「查区间」「看今日主页」；模型把它翻成一条命令键（bill.record.range）。
② agent 工具通道DSH 里＝插件注册的工具（run_bill_command 等）。它在宿主进程里 spawn 技能入口，argv 恒为 [入口, key, --params JSON]。
③ 技能唯一出口CLI（bill-cmd-read 等）。解析 --params／--html／--timeout，取数、装配页面，stdout 打一行 envelope。
④ 落盘「要不要写文件、写哪儿、叫什么名」——由出口里那一处判据决定；写了就在 envelope 顶层追加 delivery{mode,path,bytes}。

关键在④那一处判据，六家的写法不一样

同样是「非 HELP 的命令」，判据写法分两种：

// 四家的写法：总是落一份（--html 只是「改落点」的可选覆盖）
delivery = deliverHtml({ explicit: o.html, target: {dir: …, stem: …}, html: 页面 });

// 饼干/大厨的写法：只有给了 --html 才落
if (help)            delivery = deliverHtml({ … HELP 的落点 … });   // 只有 HELP
else if (o.html)     delivery = deliverHtml({ explicit: o.html, … }); // 其它命令：不给就不落
所以「饼干记账为什么要传 HTML 参数」这个问法要改一下：不是需要传，而是这一家还没做「缺省落点」，把「指定落点」的可选项当成了「落页的唯一出口」。在另外四家，--html 是可选覆盖；在饼干与大厨，它是唯一出路。

三、差异其实只有四个可判的格子

格问题六家的一致情况
① 交付不给 --html 落不落页？不一致：四家落（卡路里／作息／居家／备忘）、两家不落（饼干／大厨）
② 回执落页时 stdout 顶层回 delivery{mode,path,bytes} 吗？path 是绝对路径、bytes 等于磁盘真实字节吗？落了页的都回；大厨给 --html 也不回
③ 产物写出来的是「能直接打开的整页」还是「一个 <section> 段」？五家整页；大厨的命令出口是片段——它的页面装配件已有（六件 pages.ts ＋ cook 三页），缺的是接线
④ 命名与落点文件名主体一处定义吗？页面与 HELP 落点分家吗？已对齐的三家按 #843 做了「落点分家 ＋ 命名一处定义」；饼干/大厨没有这条规矩
⑤ 通道模型能指定落点吗？六家一致不能：插件工具只传 key ＋ --params

五、对齐的成本：分三档，各写各的

先立判据（照最近一次做这件事的 #843，别自己发明）

  1. 非 HELP 的命令原样调用就落一份整页；
  2. stdout 顶层回 delivery{mode,path,bytes}：path 绝对路径、bytes＝磁盘真实字节（回执即真相）；
  3. 命名与落点一处定义：页面落产物根目录、HELP 落自己的子目录，两处不撞名；
  4. 不给 --html 与给 --html 是同一份正文，差别只在落点；
  5. 变异自证：改坏落点值／删掉交付段必须变红，改回必须变绿，两行读数写进证据件。

C 档：给六家插件工具加 --html 通道 —— 建议不做

  • 改动本身小：六个 src/skill-tool.ts（每个一行 argv ＋ 一个可选参数）＋ 各自测试。
  • 但不做的理由更硬：落点该由技能自己按通式定。让模型每次自己编路径，等于把「命名一处定义」（#843 的判据③）打破；而且 --html 是逐字覆盖写，模型给的路径一旦重复就会互相覆盖。
  • 结论：技能侧补齐缺省落点之后，这条通道就没有存在价值了；真要留，也应留成「少数需要固定文件名」的显式口，而不是主路。
