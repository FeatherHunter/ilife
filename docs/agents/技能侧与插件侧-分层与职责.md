# 技能侧与插件侧：分层与职责

- **出处**：2026-09-25 与维护者讨论产出的架构分层（本文只记**分层与职责**，字段、参数、判据等细节不在本文）。
- **适用**：一对包（纯技能包 ＋ DSH 插件包）；本仓六家同形。
- **状态**：分层已定；标「**待定**」的项由维护者另拍。
- **关系**：本文管「谁在哪一层、各管什么」；[技能调用契约.md](技能调用契约.md) 管「怎么调」，[命令登记纪律.md](命令登记纪律.md) 管「加改命令怎么登记」。

## 一、分层与职责（正本）

```text
技能侧（纯技能包，无 DSH 代码）
    DB ────────────── 事实层：表与迁移，技能自己的地盘
     ↑
    取数／口径层 ───── 口径的唯一产地（怎么算、缺怎么报）
     ↑
    命令面 ────────── 三个族（数据族／视图族／写族）
     ↑
    出口 ──────────── 唯一可执行入口 ＝ 进程边界
     ↑
    交付 ──────────── 每条命令声明形态：页／文本／无产物

插件侧（DSH 插件包，依赖只指向技能）
    发现面 ── 技能提供方：把 SKILL.md 放进发现层（agent 才知道有这个技能）
    调用面 ── agent 工具：宿主进程里跑出口（跨技能组合由模型编排）
    呈现面 ── 面板：自选族、自绘 UI；设置页：只配置，不干活
```

## 二、每一层的边界

| 层 | 管什么 | 边界（不管什么） | 归属 |
|---|---|---|---|
| 事实层（DB） | 表结构与迁移；库文件是事实的落点 | 不含口径、不做呈现 | 技能侧 |
| 取数／口径层 | 派生量怎么算、缺怎么报 | 不管调用形态、不管呈现 | 技能侧（**口径的唯一产地**） |
| 命令面 | 对外可调用的全部命令，分三族；唯一接触面的内侧 | 不管谁消费、不管画面 | 技能侧（能力目录声明 ＋ 派生聚合） |
| 出口 | 唯一可执行入口＝进程边界；参数 → 分派 → envelope | 不实现业务 | 技能侧 |
| 交付 | 每条命令声明的产物形态：页／文本／无产物 | 不再是全局铁则（见第四节） | 命令自己声明 |
| 发现面 | 把技能说明面放进发现层 | 不取数 | 插件侧 |
| 调用面 | agent 工具：宿主进程里跑出口 | 不做跨技能编排（**由模型编排**） | 插件侧 |
| 呈现面 | 面板：自选族、自绘 UI；设置页：只配置，不干活 | 不直连库、不 import 技能实现 | 插件侧 |

**唯一接触面**：`key ＋ 参数 ＋ shape ＋ data ＋ delivery`。技能与插件之间只有这一个面，没有第二条。

## 三、命令面的三个族与两个方向

| 族 | 定位 | 谁消费 |
|---|---|---|
| **数据族** | 事实出口：与库中实体对应，参数可局部或全量读 | 插件（面板为主） |
| **视图族** | 成品出口：含口径派生量的成品（今天的命令面） | 模型（唤醒词 → 交付物）＋ 面板按需引用 |
| **写族** | 动作出口 | 模型与面板共用 |

```text
命令面 ──┬── 方向 A：给 skill（模型）── 唤醒词 → key → 交付物
         └── 方向 B：给插件（面板）── 自选族 → 事实或成品 → 面板自绘
```

**派生量的取舍在调用方**：不在乎差异 ⇒ 走数据族自己处理；在乎 ⇒ 走视图族，直接用技能算好的那一份。架构不替调用方做这个选择。

## 四、交付形态是命令的属性

产物形态（页／文本／无产物）由**每条命令自己声明**，默认策略可以统一，个别命令可以覆盖。

原来的「HTML-First 铁则」据此**降级为默认交付策略**，不再是全局强制（讨论结论）。

## 五、相对今天的差异

| 项 | 今天 | 目标 |
|---|---|---|
| 数据族 | 只有零散先例（按天饮食、照片列表、按日聚合） | 补齐成完整的族（覆盖实体，局部／全量） |
| 交付 | 全局 HTML-First 铁则 | 降级为「每命令声明的交付策略」 |
| 视图族 | 现状（137 条键） | 不变 |
| 写族 | 现状（54 条键） | 不变（形态见第六节待定项） |
| 面板 | 存根 | 三个族都可挑，UI 自绘 |

## 六、待定（由维护者拍）

1. **写面形态**：保持「一动作一条命令」，还是按字段／表对齐写。
2. **交付默认形态**，以及哪些命令不落产物。
3. **数据族的键名与参数形状**（骨架已定：按实体、局部／全量可读；具体形状待定）。
4. **数据族对模型的可见性**：是否进说明面／唤醒词路由（今天所有读命令的声明都会顺带进 SKILL.md 速查表）——这一项若单列，属新机制。
5. **面板自算与引用的边界**（维护者定：取舍由调用方）。
6. **判据**：现有那条针对视图族；数据族要不要另加、怎么定。
