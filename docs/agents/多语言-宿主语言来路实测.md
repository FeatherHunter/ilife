## 2. 三条候选路径逐条结论

### ① 读宿主设置 locale.preference ——可用（有条件，唯一可复现路径）

- 是什么：`@deepseek-ai/dsh-client-locale` 在宿主半边只做一件事——把 `locale` 设置命名空间注册进 settings（唯一字段 `preference`，`.volatile()` 进设置表单）；宿主半边不注册语言、不提供 `t`。
- 读数：desktop patch 尾部 `preference: zh`（上节）；设置 → 通用里由该插件自己注册“语言”行（`client.js:1553-1560`，`locale: SETTINGS_NS`），内置只有 `zh/en`（`LOCALE_IDS=["zh","en"]`），`zh` 回退 `en`。
- 三个硬限制（底稿 §3）：用户没显式选过时该条目不存在（浏览器临时语言不落盘）；非 loopback 页面的选择只在进程内（README "What the Host half does"）；读取面是 settings/configForms（按 profile 条目 id `locale` 读表单），不是一等 API。web profile 本次实测即“不存在”情形。
- 作为参数传给技能命令行的可行形状（本次只到探针级）：插件侧读到 `preference`（读不到按 ADR 缺省 `zh`），以显式 argv（如 `--language <BCP47>`）传给技能；技能侧由 #1198 新增该参数（只加不改），空串＝跟随调用方。正式接线归 #1198，本票不加参数面。

### ② 客户端语言快照经 RPC 下传 ——不可用（对技能）

- prompt RPC 只传时区不传语言：浏览器侧 `Intl.DateTimeFormat().resolvedOptions().timeZone` 随每次 prompt RPC 上行（`client.js:1724-1745`），同一 `resolvedOptions()` 的 `locale` 从不上传。
- `AccountClientMetadata.locale` 只走平台请求头：`x-client-locale: platformWireLocale(client.locale)`（`zh→zh_CN` 其余 `en_US`），消费方是登录页与平台头（`main.js:5908-5911`），不进技能调用链。
- 技能调用链无语言位：`run_bill_command` 等只搬运 envelope（`skill-tool.ts:20-26`）；`dsh-ctx.ts` 的 `readonly locale?: string` 是槽注册选项（字典命名空间，如 `"approval"`），7 个插件零处传入、运行期 bundle 无此字段（类型擦除），与用户语言无关。
- 登记原因：该路径在“宿主→平台”存在，在“宿主→技能”不存在；要走必须新增参数面（归 #1198），不是现成可复现路径。

### ③ 桌面外壳语言桥 ——不可用（对 Node 技能）

- 存在但够不着：桌面主进程 `app.getPreferredSystemLanguages()/app.getLocale()` → `resolveDesktopStartupLocale`（只分 `zh/其它`）→ IPC `localeBootstrap` 返回 `{languages, preference}` → 客户端 locale 插件（`__DSH_LOCALE__.read()` 每次刷新重读）。全链在 Electron 壳与浏览器半边。
- 技能是独立进程（`resolveNodeBin`，Electron 宿主加 `ELECTRON_RUN_AS_NODE=1` 再 spawn 唯一出口），无 IPC 通道，无 `ctx.locale`（`provide("locale")` 唯一一处在浏览器半边 `client.js:1526`；宿主半边 `provide` 清单无 locale）。
- 登记原因：该桥是“壳→页面”的启动语言，不是“宿主→技能”的运行时参数；Node 侧无支持的读取 API。

## 3. 对实现的决定性影响

- 插件与技能之间语言传递的实现方式：采用路径①。插件侧读 settings（以 patch 文件为底的可复现读数），显式 argv 透传；技能配置文件 `language.text/language.format`（空串＝跟随调用方，最终回退 `zh`）＋ 命令行覆盖（#1198）；未识别值报错并列出可用语言。
- 客户端 UI 文案若要走宿主官方通道，另有一条与本票无关的路：在 client 插件里 `inject:['locale']` → `ctx.locale.register(自己的ns,{zh,en})` → 槽注册写 `locale:自己的ns`（渲染器注入 `t`）。技能产物（HTML/回执/工具返回文本）不在该体系内，只能由产物生成方自定语言（本结论）。
- 宿主侧不能新增语言：`addLanguage` 是客户端 API；宿主侧只认 zh/en（`resolveDesktopLocale`、`platformWireLocale` 均只分 zh/其它；`zh` 一律按 `zh-CN` 处理，无区域区分）。BCP 47 预留（日语等）只约束技能侧参数形状，不代表宿主会透传第三语言。
