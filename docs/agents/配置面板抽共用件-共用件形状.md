# 配置面板抽共用件 · 共用件形状（2026-09-22 裁定）

本文是 wayfinder 图 [#898](https://github.com/FeatherHunter/ilife/issues/898) 的裁定票
[#900](https://github.com/FeatherHunter/ilife/issues/900) 的**决定**落盘件；只写裁定了什么、为什么、后续实施票拿什么当判据。
读数出处一律引 `docs/agents/配置面板抽共用件-事实底数.md`（下称**事实底数**）。

## 一、四条裁定

### 1 · 共用件吃到哪一层：一层收到底，只开一个出口

`dsh-life-pack`（`packages/plugin-manager`）加**一个** exports 键，装整个配置面板：样式表、行渲染、
卡片骨架、状态机、取值与填值、脏基线、配置 RPC 三件套、人话报错。六家只留通道名 ＋ 行表 ＋ 三个可选钩子
（跟随映射、卡片标题、自家附加块）。**不另开第二个出口**。

- 差异面实测很小：六家 `src/contract.ts` 的 `config.get`／`config.save`／`config.reset`／`config.check`
  四个端点常量逐字相同，取数层唯一真变量是 `RPC_CHANNEL`；六家 `client.ts` 前七个 `useState` 同串同序；
  `Row` 63 行逐字相同；卡片骨架 246 行只差注释（事实底数 §2、§3）。
- **不单开「逻辑出口」的理由**：本包最像通用面板状态机的 `useHealthPanel`
  （`packages/plugin-manager/src/health-panel.ts:39`）全仓只有一个调用点（`src/client.ts:290`），
  本仓照样没给它单开出口。开第二个出口没有第二消费方＝预先设计，撞
  `docs/agents/structure.md:71`「共用位是从第二个用法里长出来的，不是预先设计的」。将来真长出第二个用法再开。
- 对外给的名字共 5 个以内（对齐铁律五）：`Row`（供跨包锁改指向）、`ConfigItem`、
  `ConfigControl`／`ConfigTier`（类型）、面板组件本体。`readPath`／`writePath` 降为内部实现。

### 2 · 错误态：三支收，确认与撤销不做

收三支错误：整面读取失败（一屏错误）、写入失败（保存失败）、值非法回落（那一行给提示 ＋ 一行黄字说明按默认走）。
**v3 的「保存前一行 diff 预览确认」与「保存后 5 秒撤销窗口」不落地**，v4 起以本裁定为准。

- 三支的分类逻辑**已经存在**，只是没地方摆：`humanizeConfigFailure` 按「解析／不认识／类型／缺席」四类
  补一句接下来怎么办（`packages/plugin-bill-ilife/src/client.ts:137-144`），而四类全部压成一行文本（`S.error`）。
  收件＝把这条文本升格成按类落位的槽位。
- 确认与撤销是**新交互功能**（撤销还要一个计时器，会撞 `test/plugin-p10-boundaries.test.mjs` 的定时器三件套），
  与「六份手写变一份」正交，绑一票卖不划算。

### 3 · 草稿守卫：什么都不做

不拦切页签，也不做草稿缓存。

- **切技能那一跳草稿本来就丢不了**：页签面板按 `visitedIds` 过滤后保持挂载，只切 `hidden` 属性
  （`packages/plugin-manager/src/client.ts:427,436,442`；宿主同法见
  `@deepseek-ai/dsh-client-ui-settings-plugins/lib/client.js:502-511`，`only` 是过滤器见
  `dsh-client-ui-renderer/lib/client.js:867`）。`useState` 活着，草稿就在。
- 真卸载只有两个点：切走设置区块、关掉设置弹窗。两个点都在本图不许碰的范围（总管不许改；
  关弹窗是用户主动动作，按放弃处理）。宿主也没有可挂的钩子（`guard`／`canLeave`／`beforeLeave`／`intercept`
  在设置与 slots 两包零命中），且没有组件状态持久化 API。

### 4 · 控件层：本轮不接本体 primitives

不引入 `@deepseek-ai/dsh-client-ui-primitives`，本轮沿用现有内联 style ＋ DSH 主题别名。

- **能接（已实测）**：宿主前端有静态种子表（`dsh-client-modules/lib/client.js:303`），
  第三方 `dshmarket/client/client.js:30` 同法已在跑；npm 上 `0.1.5-rc.2` 带完整 `lib/types/`，
  按本仓 tsc 设置（NodeNext／strict／skipLibCheck）实测退出码 0。
- **不接的代价是定稿层面**：`Button` 是药丸形（`border-radius 18px`／`height 36px`／无 border）且写死
  `font-size: 14px`（`.sm` 12px，`lib/Button.module.css:12,32`）；`Input` 14px；`DisclosureRow` 是受控组件
  （必填 `open`／`expandable`／`onToggle`／`icon`）；高级组要从非受控 `<details>` 换掉；按钮字面还要按 v3 改。
  这些与本票「六份变一份」正交。
- **未决（带读数，不是「以后再定」）**：v4 要不要切 primitives——等 v3 定稿三条（只读行零浏览按钮／
  两档按钮字面合一为「浏览文件夹」／复制进面板）落地，且对抗式审查剩余项（几何阈值 40–43 列／骨架留给徽标与
  底栏的高度／慢面复用 `config.check`／值非法那行黄字的落点）清完之后再裁。

  加出口的机械做法＝源文件进 `tsconfig.client.json` ＋ `package.json` exports 加键。

## 三、这一票买到什么、买不到什么

- **买到**：六份手写 →**一份源码编译六次**。以后改一次共用面板，六个技能一起变，不再有人手改六份、漏掉一份。
- **没买到**：六个插件的成品里**仍然各带一份这份代码**——子路径会被打进各家自己的 `dist/client.js`
  （`alwaysBundle: (id) => !CLIENT_EXTERNALS.includes(id)`，六份 `tsdown.config.ts:35`），
  所以上游改一次仍要重建六个插件 ＋ 总管各自上版本号。它治的是「各写各的会写歪」，不是「磁盘上只剩一份」。
