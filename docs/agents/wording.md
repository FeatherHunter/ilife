# 用词纪律

改代码、写文档、写 issue 一律用右边那列的词；左边是黑话，禁用。

## 文件名

| 禁用（黑话） | 一律写 |
| ------------ | ------ |
| 茎 | 文件名主体 |

**文件名主体**：文件名里时间戳之前的那一段。`卡路里_HELP_20260910_183829.html` 的主体是 `卡路里_HELP`。老代码／老文档里写的「茎」就是它。

英文标识符沿 Python `pathlib.PurePath.stem` 的官方叫法（`buildHelpFileName(stem, …)`、`HELP_FILE_STEM`），不是黑话，不改名；中文文案一律不写「茎」。

## 卡路里：命令与流程

| 禁用（黑话） | 一律写 | 说明 |
| ------------ | ------ | ---- |
| 键 | 命令 | `calorie.diet.add` 这样的东西一律叫「命令」。只在真指键盘按键时才写「键」 |
| 写键／读键／补写键 | 会改数据库的命令／查询命令／加一条会改数据库的命令 | 「写键」是代码类型名 `CalorieWriteKey`，不是中文词，不许当中文用 |
| 99 键／95 键 | 99 条命令／95 条命令 | 同上 |
| 非执行词 | 现在没有命令可执行的唤醒词 | 或精简为「没有命令可执行的唤醒词」 |
| 执行桶／非执行桶 | 有命令可执行／没有命令可执行 | 代码里的 `kind: 'exec'`／`'non-exec'` 是标识符，中文说明照此写 |
| 缺键 | 缺命令 | |
| 闭不了环／打通 | 跑不通／跑得通（一条流程能从头走到尾） | |
| 过程型／结果型／回执 | 沿用（这三个是用户裁定的正式词） | 不要改写成「流程页／结果页」以外的说法 |
| 向导（wizard） | 预检确认页 | 代码里的 `wizard` 是标识符；中文说明用「预检确认页」 |

## 卡路里：HTML 与组件

| 禁用（黑话） | 一律写 | 说明 |
| ------------ | ------ | ---- |
| 渲染轨／执行层轨／补写键（作分轨名） | 页面交付／命令补齐 | 这两类是**不同性质的工作**，分开列票，用这两个词 |
| 分轨／三段分置 | 分开列票／按性质分三种去处 | |
| 壳 | help 模板／共享页面模板 | #131 已裁定：只说 help 模板，不说壳（采访区原文除外） |
| 渲染层／渲染活 | 页面交付 | |
| 底座 | 已经有用的实现／已落实的机制 | 判断语，不是组件 |
| 基座（当「已经有用的东西」讲时） | 已经能用的部分 | |
| 升格 | 提取到公共层 | 指把重复出现的组件从场景里提到共享位置 |
| 独占交互 | 只有这一个场景用得到的交互 | |
| 同构合并 | 形状相同的合并成一张 | |

## 卡路里：计划与验收

| 禁用（黑话） | 一律写 | 说明 |
| ------------ | ------ | ---- |
| 携带执行 | 本图要交货（不只出决定，还要交出能跑的东西） | #131／#143 的 Notes 用词，可以留，但正文解释一次 |

## 通用

| 禁用（黑话） | 一律写 |
| ------------ | ------ |
| 赋能 | 让……能做 |
| 抓手 | 办法 |
| 闭环（当「完成」讲时） | 跑通 |
| 对齐（当「商量一致」讲时） | 商量一致 |
| 颗粒度 | 粗细程度 |
| 打通 | 跑通 |
| 收敛 | 合并／统一 |
| 沉淀 | 记下来／提取到公共层 |

> 这份清单不长，但**卡路里这一批图会大量写到命令、页面、组件**，所以上面三张卡路里表是重点。见到不在表里的新黑话，**补一行再继续**。
