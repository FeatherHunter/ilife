# Subagent 并发执行协议（编排者与各 subagent 约定，逐条生效）

> 正本。2026-09-09 转正。
> 适用：同一工作区内多个 subagent 并发执行。每个派单必须附带"先读本文件并逐条遵守"的要求，否则本协议不自动生效。
> **怎么切票、怎么派活、怎么收活**见 [`agents/编排纪律.md`](agents/编排纪律.md)（下发任务十条 ＋ 拆票十条 ＋ 简报八格）；本文件只管窗口内的机械步骤与量刑。

## 0. 总原则

**共享同一个工作区**（单一 git 仓库、单一依赖目录、单一编译产物目录）。因此并发安全的唯一保障是**路径所有权 ＋ 共享资源串行化**。任何"我只是顺手改一下别人的文件"都会静默损坏他人的工作。

## 1. 路径所有权（硬约束）

- 每票在开工前必须**声明自己会写的路径集合**（文件级，写进派单），只允许写这些路径。
- **禁止**修改其他票已声明占用的路径。需要跨票改动时：**报给编排者并转票**，本次一律不碰那个路径 —— 不碰不等于停工，自己声明范围内的活照常做完再交。
- 各自证据文件写**归属件目录** `docs/<类别>/<件名>/t<票号>-*`（类别＝`skills`／`plugins`／`base`，件名见 `docs/agents/doc-homes.md`；同一件的多个票共用一个目录，靠票号前缀保持**文件级**不重叠）。`docs/research/` 是历史归档，**不再新增**。工作草稿写 `.scratch/t<票号>/`；changeset 文件名各自唯一（`.changeset/<票号专属名>.md`）。

## 2. 共享资源串行化（目录锁）

以下操作**必须持锁**执行：跑编译、跑测试、`git add`／`git commit`（共享编译产物目录、增量编译状态文件、git index）。
**不需要持锁**：读文件、编辑自己路径下的文件、`grep`、`git status`／`git diff`／`git log`。
**凡是会改动工作区的动作都算写者**：只读演练（dry-run）、变异电池、清理**同样必须持锁**，且退出时工作区必须为空 —— 只读演练不是"不回滚"，是"不提交"。

锁协议（pwsh，复制即用；锁目录创建是原子操作）：

```powershell
$lock = 'D:\ilife\.scratch\locks\gate.lock'
New-Item -ItemType Directory -Force -Path 'D:\ilife\.scratch\locks' | Out-Null
while ($true) {
  if (Test-Path $lock) {
    $age = (Get-Date) - (Get-Item $lock).LastWriteTime
    if ($age.TotalMinutes -gt 10) { Remove-Item $lock -Recurse -Force -ErrorAction SilentlyContinue; continue }  # 抢回死锁
    Start-Sleep -Seconds 10; continue
  }
  try { New-Item -ItemType Directory -Path $lock -ErrorAction Stop | Out-Null; break }
  catch { Start-Sleep -Seconds 5 }
}
try {
  # ===== 持锁区：编译 / 测试 / git add / git commit =====
} finally {
  Remove-Item $lock -Recurse -Force -ErrorAction SilentlyContinue
}
```

- 持锁区尽量短：把要跑的命令**一次写完**，不要持锁做阅读／编辑。
- **抢锁前先看进程表**：只读锁记录（`owner.json`）不足 —— 它只持锁期间存在，里面可能留着上一轮的 pid。再查一次进程表里有没有同票的活加锁进程；**有 ⇒ 不抢**（否则会把"尸体锁"抢成两个写者）。
- 跑完立刻在 `finally` 里释放；**不要**持锁等待人工输入。
- 抢锁失败／被人挡住的**完成判据**：重试有上限（等 15 秒重试、最多 10 分钟），超时就把挡住者的现场（原文与时刻）写进日志并上报编排者 —— 不无限等，也**不得替别人回退文件**。

### 2.1 依赖与临时目录（硬约束）

1. **禁止**在仓库内任何位置运行包管理器的安装／新增命令（唯一例外：编排者持锁显式授权）。缺依赖的正确处置＝**停手上报**，不要自行装。
2. 需要「安装态实证」时，安装目标必须落在**仓库之外**的独占临时目录（带票号与随机后缀），且该目录**必须先写最小工程文件**，确保包管理器不会向上解析到工作区根。
3. **任何递归删除前必须先做路径守卫**：断言目标绝对路径以自己声明的临时根开头，且**不在**依赖目录、源码目录、文档目录、测试目录、工具目录、`.git` 之下；守卫失败即抛错退出。
4. 临时目录用完即清；**不得**把临时根放在多席共用的草稿目录下供多个 agent 互相删除（各自用带票号与随机后缀的独占目录）。
5. 发现共享依赖目录异常、或编译因缺件失败 → **立即停手上报编排者**，不要自行重装。

### 2.2 终端输出节流（上下文保护，硬约束）

**事实**：一次全量测试的输出可达十几万字节（约合单执行者上下文预算的四分之一以上），而**一次全绿的全部信息量就是退出码**。把成功日志全文读进上下文是最大浪费。

**规则**：

1. 长命令一律落盘：把标准输出与标准错误重定向到文件，紧随其后打印一个**唯一标记行**与退出码；等标记行出现，然后只读**最后 5 行**确认退出码。
2. 退出码非 0 时才检索失败签名（`FAIL|✖|not ok|AssertionError|Error`），只读命中行及前后 10 行；修完重跑后同样只看尾 5 行。
3. 证据脚本必须打机器可读摘要行（`RESULT: n/m`、`PASS/FAIL`）；复核只读摘要行＋退出码，明细留在文件里备查，**不读全文**。
4. 禁止重复读同一份输出；禁止把大日志文件通读进上下文。
5. 变异／探针脚本的输出同样适用：只看"红没红（fail>0）＋ 还原 sha 是否一致"两行。

### 2.3 锁等待留痕必须落盘（硬约束）

**起因**：包装器原先只把等待量打印到终端 —— 等了多少随终端滚屏消失，事后**无法复核**「那一刻锁是否被别人持有」，也无法复核「某次运行到底有没有走锁」。

**规则**：

1. 加锁包装器**必须**把等待与运行信息**落盘**（默认锁目录，可用参数覆盖），不得只打印到终端：
   - 持锁者现场（`pid`／`ticket`／`cmd`／`startedAt`／`waitedMs`）：持锁期间存在、释放时删除；
   - 运行记录：**追加**一行机读记录 `RUN ticket=<票号> cmd=<命令> waitedMs=<n> exit=<n> at=<ISO>`（值含空格时以双引号包裹）。
2. 等待量**必须**能在上述落盘文件里复核；**只打印到终端的等待量视为不可复核**，审查中**不得**作为「当时锁为空」的证据。
3. 锁记录写在未受版本控制的目录下，第三方看不见 ⇒ 收尾时把本次窗口内的运行条目**导出到受版本控制的路径**并在证据里引用，导出件可直接当对账源复核。

### 2.4 机械门禁：编译／测试必须经持锁包装器（硬约束）

1. **一切**编译、测试（含全量门禁、靶向测试、变异轮重建）**必须**经加锁包装器执行。包装器负责：按 §2 抢锁（抢回判定**先探活**：活 owner **一律不抢回**，owner 已死且其记录属于当前锁 → 立即抢回，无 pid 可探 → 锁龄超阈值兜底）、按 §2.3 落盘留痕（`START`／`RUN`／`LOCK-STOLEN` 三类行，均带 `runId`）、释放前先校验归属，**写记录失败即以非 0 退出**。
2. **证据对账**：证据文件里**声称**跑过的每次运行，都必须在运行记录里找到**一对一**对应条目；缺失即非 0 退出并逐条列出缺失项。默认严格口径：① 证据里没有声明即 FAIL；② 窗口内存在**无人声明**的运行条目即 FAIL；③ 声明**必须引运行标识（`runId`）**，只认标识相同的条目（同命令的历史条目不得顶替）；④ **只认领退出码为 0 的条目**（跑了却失败不得充作门禁证据）。规范写法＝单行 `GATE-RUN runId=<runId> cmd=<命令>`；没有该声明的运行**不计入**对账，也**不得**当作门禁证据引用。
3. **放宽必须留痕**：任何放宽开关（允许无声明／允许未声明／允许非 0／允许无标识）**必须**在证据里留一行 `GATE-RELAX flag=<开关> reason=<理由>`，否则非 0 退出；**私自放宽＝S1-交付缺陷**（§6）。
4. **裸跑与门禁的鉴别力边界**：不经包装器直接跑编译／测试＝ §6 的 **S1-过程违规**。但机械门禁**只能对账「已声明」的运行**；**裸跑本身不可机械检测**（有的测试跑完不写任何产物、不留时间戳痕迹），故裸跑只能靠**自认／举报／审查**发现。对账**查漏不防伪**（日志与工具同在可写工作区），**造假按 S1-交付缺陷处置**。
5. **门禁工具的自证测试须单独触发**：包装器与对账工具自身的测试**不在**常规全量测试的范围内（纳入会与包装器嵌套抢锁），须**手工或 CI 单独触发** —— 不得据此认为全量测试已覆盖门禁工具自身。
6. **受控裸跑探针的具名授权**：为验证门禁识别力（如「裸跑是否被漏检」），**编排者可具名授权一次受控裸跑探针**：须在**派单**中写明（授权对象／一次性／命令范围／只读要求），并在**证据**中留痕。经具名授权的探针**不适用**第 4 条的违规判定；**未经具名授权的裸跑一律按 S1-过程违规处置**。该授权**不类推**，也不得由实施者／审查者自行援引（同 §6.1）。
7. **条款修订的广播义务**：任何协议条款**生效后**，编排者**必须把该条款广播给所有在飞 session**。**因未广播导致在飞 session 违反新条款的，归因编排者，不判该 session**（按「规则生效前派单、且未被告知」处理，不计入 §6.1 的「再犯」）。

### 2.5 会动工作区的脚本（硬约束）

1. **失败即不落盘（fail-closed）**：写工作区的脚本，其内部断言是**前置条件**，不是事后报表 —— 任一断言红 ⇒ **本次运行不写盘**（不写新件、不回写被改件），并以非 0 退出、把红条打印出来。「先写回再报告有红」＝ **S1-过程违规**（已经产生了需要回滚的既成事实）。落地顺序恒为：**先在内存里算出产物 → 跑完全部断言 → 全过才落盘**；默认只演练不落盘，只有显式打开写开关的步骤才落盘。
2. **按当刻内容变更，不按预备记录变更**：删除集／改写集只能由「本票拥有的键或范围」在**当刻工作区内容**上派生。**禁止**把行号、字节偏移、行数、预备期快照的比对结果当作变更依据 —— 别人先落点之后它们就会漂移，而漂移是**设计里就允许的**（命中 0 次记「已被别人做掉」、命中多次即抛错）。共享件只许定点删除，**禁止整文件覆盖**。
3. **窗口自带回滚**：任一步红 ⇒ **当次窗口内**做完两件事：① 逐文件点名还原自己改过的受版本控制的文件；② 逐条点名删除自己新建的件。**禁止**用整目录还原或清空未跟踪件的批量命令（§3）。回滚自身也会红 ⇒ 回滚必须**容忍自身失败并继续把工作区清干净**。
4. **离开时工作区为空**：收尾**唯一判据**＝「没有未提交改动、也没有未跟踪件」（逐条列出，含新建目录内部的件）。**不空就不许释放锁、不许报完成** —— 半成品留在树里会让后面的票全部开不了窗。承接 §5 第 3 条：判「工作区为空」时必须**连生成物与生成记录一并检查**，不看生成物会误判为干净。

## 3. git 纪律（最危险区）

- **禁止**：`git stash`、`git checkout -- .`、`git reset --hard`、`git clean`、`git restore .`、切分支（`git switch`／`git checkout <branch>`）。这些会**摧毁并发伙伴的未提交工作**。
- 只允许 `git add <自己声明的路径>` ＋ `git commit`（持锁）。**不要 `git add -A`／`git add .`**。
- 主干**只许追加提交**：`--amend`／`--force*`／`rebase` 一律禁用（并发窗口下会让别人的提交被裹进混合提交，或让中间提交成孤儿）。
- **不要 push**（编排者统一收口）。

### 3.1 提交纪律（硬约束）

- **增量提交**：每完成一个有意义步骤（实现一块／补一组测试／补证据／跑完门禁）就**立即持锁 commit**，不要攒到最后。**宁可多 commit，也不要让成果停留在未提交状态**——未提交的代码无法溯源、无法恢复。
- **提交信息用中文、说清做了什么**，格式：`feat(<票号>): <一句话概括> ＋ <关键落点／文件／验证>`。
  - 正例：`feat(87): 输出命名规范复刻（默认目录＋同秒后缀＋中文 command 名）＋ 新增 paths.ts 解析与 12 条单测`
  - 反例：`update`、`fix bug`、`feat(87): 修改` —— 无信息量，禁止。
- 为防终端代码页损坏中文信息：用写文件的方式先落一份 UTF-8 消息文件 → 用文件提交；提交后回读提交信息自检中文正常。
- **提交一律限定路径**：先复核暂存区文件名清单**只应含自己声明的件**，再用限定路径的写法提交（见 §3.2）。
- **收尾时工作区必须干净**（自己路径下无未提交改动、无未跟踪文件）；报告里给出**全部 commit sha ＋ 提交信息**清单。

### 3.2 提交与证据的三条限定（硬约束）

1. **提交限定路径**：先 `git diff --cached --name-only` 复核暂存区**只应含自己的件**，再 `git commit -- <路径>`（不靠 `git add -A`／`git add .`）。**多出来的件一律先撤出暂存区再提交**，不许"一起提交了事"。
2. **对已入仓证据件的收窄／改写，原文必须落受跟踪路径**：收窄前的原文要提交进仓库，`.scratch/` 只作临时副本 ⇒ 否则「收窄」在版本史上不可见，等于事后改数。
3. **结论类评论不回头改**：已发出的结论评论保持原样；改状态时在**正文或新评论**里写清**取代关系**（谁取代谁、据哪次运行），不做静默编辑。
4. **别人留下的未提交改动＝无主 diff**：执行者中途死掉留下的未提交改动，**不许当既成事实采信**。接手者必须先量现场（改动清单／逐件统计 ＋ 旧新内容哈希），再**自行判定完成度** —— 补齐、还原、重做都合法，且接手者保持「非受益者」身份。判「能不能接管」的最小证据＝语法检查通过 ＋ 改动的每处标题能逐条对上任务清单。

## 4. 终端使用

- 需要终端时**使用 sidebar 终端**（标题 `<票号>-<用途>`）→ 长命令按 §2.2 落盘＋等标记＋只读尾 5 行 → 结束前关闭终端释放。
- 不要用非交互工具跑长命令；不要开多个终端；长跑命令在同一终端内顺序执行。
- **交棒要写停止点**：接任者读盘不读对话 ⇒ 交接必须写明「从哪个标记行之后接、下一手缺什么」。

## 5. 验收与报告

- 门禁口径以派单给出的**变更前基线**为准；基线由编排者冻结，任何人不得自行改口径。
- 每票必须自证：**变异自证**（故意破坏 → 对应测试变红 → 还原变绿；**默认源码级变异**，还原＝按文件还原；编译产物级为例外，需在报告里论证必要性；变异须持锁＋跑前哈希＋还原自证，清理须路径守卫）。**生成物不是源码**：生成物的「还原」要用重新生成把它复位，不能用版本控制命令复位（生成物常在忽略清单里，版本控制看不见它）。
- **回滚必须连生成物与生成记录一起复位**：只还原受版本控制的源码而不同步编译产物，下一窗一开就吃**假红** —— 冻结测试是从编译产物导入的，里面留着回滚前写法的产物。回滚后必须**两步连做**（缺一即假）：按当刻源码**重新编译**该包作用域 ＋ **重新生成记录**。**只重编不重签** ⇒ 一致性检查记陈旧；**只重签不重编** ⇒ 拿旧产物签字。**完成判据**＝重编＋重签之后一致性检查为绿 ＋ 受版本控制件无改动，二者缺一不算回滚成功。

### 5.1 审查者纪律

- **独立复跑**：不采信实施者任何结论；每句"已满足／已绿"都要自己跑。实施者不得兼任自己票的审查者。
- **自设新探针**：必须至少设计 **1 个被审脚本覆盖不到**的新变异或新探针（专打"脚本自我满足"盲区）；没有此条，审查结论不予采信。
- **归属标注**：每个缺陷必须标注**本票引入／本票范围／范围外发现**；范围外发现不得单独决定 FAIL（只能 S3＋转票措辞），除非它直接证伪本票的验收结论。
- **单票审查是初审**：关闭口径以**合并点安静态复核**为准；复核的**核心维度是「收窄是否变成放宽」**（必须自造真·权威写死的样例，证明改动后仍被抓）。
- 分数（如用）只是次要摘要：判定＋缺陷清单才是正文；五维（契约一致 30／证据真实可复现 25／新旧对照 20／工程红线 15／文档同步 10）供参考，不跨票比较。
- 证据入仓归属件目录 `docs/<类别>/<件名>/t<票号>-*.md`（类别与件名见 `docs/agents/doc-homes.md`）＋ 可复跑脚本；**必须被 git 跟踪**。
- 报告 ≤1200 词：① commit sha ＋ 改动文件清单；② 逐条验收「怎么满足＋证据位置」；③ 门禁实测；④ 变异自证；⑤ 偏离记账；⑥ 未做／未确证；⑦ 风险 top3。
- 完成后**停止**，等编排者安排对抗式审查。

## 6. 量刑与违规判定

**缺陷分级**：**S1**＝关闭阻塞项（契约违反／用户可见回归／证据造假或私自放宽／数据丢失风险）；**S2**＝关闭前必须修完，除非编排者书面改期并给出具名票号；**S3**＝记账跟进，不阻塞关闭。

**量刑律**：任一 S1 → **FAIL**（分数再高也否决）；均分 <85 → **FAIL**；无 S1 且均分 ≥85 → **PASS**。

**违规**：未经声明改动他人路径、绕过锁跑编译／测试／git、使用危险 git 命令、违反 §2.1／§2.2 = **S1 违规**，该票成果作废并重做。

### 6.1 S1 的两类：交付缺陷与过程违规

> 两类的**列举范围完全沿用上文字面**，本节只规定**后果路径**与**记录条件**。

**① 分类**：**S1-交付缺陷**＝契约违反／用户可见回归／证据造假或私自放宽／数据丢失风险；**S1-过程违规**＝绕过锁跑编译／测试／git／未经声明改动他人路径／危险 git 命令／违反 §2.1／§2.2。前者后果**字面不变**：成果作废并重做，任一即 FAIL。

**② 过程违规的记录条件**（不重做的唯一合法形式，四条缺一不成立）：为了给违规留一条**可追踪的记录路径**、而不必把交付物本身作废重做，过程违规可以记入记录而不重做 —— 条件是：

1. **复跑证明无分歧**：审查者持锁独立复跑被质疑运行所涉的测试／门禁，结论与该次运行一致；
2. **等待量可复核**：按 §2.3 落盘，使「当时锁是否为空」可被独立复核；
3. **门禁可对账**：按 §2.4 让编译／测试经持锁包装器执行，并可用对账工具复核；
4. **具名书面记录**：由**编排者**在票面出具书面记录，引条号（本 §6.1）、声明**一次性**（仅限本次事件）、声明**不类推**（不得作为后续同类违规的先例）。

**③ 效力**：四条齐备 ⇒ 该违规记 **S3（记账跟进，不阻断关闭）**，交付物本身的技术面验收结论不受影响。**同一票或同一执行者再犯** ⇒ 记录路径**关闭**，按上文**字面作废并重做**。

**④ 权力边界**：记录是**编排者的具名行为**；**实施者／审查者无权自行援引**本条，也不得把「零实质风险」「锁当时为空」当作自行豁免的理由（审查者只能出建议，不能出裁决）。

**⑤ 未走记录路径时**：违反 §2.1／§2.2／§2.4 第 4 条，或危险 git 命令，一律按 S1-过程违规**判 FAIL 且字面作废并重做**；§5／§5.1 的验收与审查纪律不因本节改动（审查者仍须独立复跑，实施者仍不得兼任自己票的审查者）。
