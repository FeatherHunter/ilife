# Subagent 并发执行协议（编排者与各 subagent 约定，逐条生效）

> 正本。2026-09-09 转正。
> 适用：同一工作区内多个 subagent 并发执行。**派单即适用**：派单里按条号点出本单适用的协议条款；条款**生效后**编排者必须把该条款广播给所有在飞 session（**因未广播导致在飞执行者违反新条款的，归因编排者，不判该执行者**）。
> **怎么切票、怎么派活、怎么收活**见 [`agents/编排纪律.md`](agents/编排纪律.md)；本文件只管窗口内的机械步骤与量刑。

## 0. 总原则

**共享同一个工作区**（单一仓库、单一依赖目录、单一编译产物目录）。因此并发安全的唯一保障是**路径所有权 ＋ 共享资源串行化**。任何"我只是顺手改一下别人的文件"都会静默损坏他人的工作。

## 1. 路径所有权（硬约束）

- 每票在开工前必须**声明自己会写的路径集合**（文件级，写进派单），只允许写这些路径。
- **禁止**修改其他票已声明占用的路径。需要跨票改动时：**报给编排者并转票，本次不碰那个路径**；那一片自有它的主，自己声明范围内的活继续做到交付（不碰 ≠ 停工）。
- 各自证据文件写**归属件目录** `docs/<类别>/<件名>/t<票号>-*`（类别＝`skills`／`plugins`／`base`，件名见 `docs/agents/doc-homes.md`；同一件的多个票共用一个目录，靠票号前缀保持**文件级**不重叠）。`docs/research/` 是历史归档，**不再新增**。工作草稿写 `.scratch/t<票号>/`；changeset 文件名各自唯一（`.changeset/<票号专属名>.md`）。

## 2. 共享资源串行化（锁域与目录锁）

**凡会改动工作区或生成物的操作必须持锁**：编译、测试、`git add`／`git commit`、快照、变异电池、只读演练（dry-run）、清理。
**不需要持锁**：读文件、编辑自己路径下的文件、检索、`git status`／`git diff`／`git log`。
只读演练不是"不回滚"，是"不提交" —— 它同样会动工作区，同样要持锁，退出时同样必须为空。

**分锁域执行**（避免嵌套抢锁自堵）：

- 常态：经**加锁包装器**跑（它负责抢锁、留痕、释放）；包装器不可用时才手工用下面的目录锁，并在证据里留痕（§2.3）。
- **落点窗口**：整个窗口由**外层包装器**持锁；**窗口内一切步骤一律直接调用，不得再次抢锁**。窗口内嵌套一次包装器就会引入第二把锁 —— 实测连子进程都没起来、CPU 冻结 20 秒后被强行杀链、窗口走减半的 abort 路径。窗口的留痕由外层包装器与窗口日志共同承担。

目录锁（pwsh，复制即用；锁目录创建是原子操作）：

```powershell
$lockDir = '.scratch/locks'          # 或环境变量覆盖；不要写死盘符
$lock = Join-Path $lockDir 'gate.lock'
New-Item -ItemType Directory -Force -Path $lockDir | Out-Null
while ($true) {
  if (Test-Path $lock) {
    $age = (Get-Date) - (Get-Item $lock).LastWriteTime
    if ($age.TotalMinutes -gt 10) { Remove-Item $lock -Recurse -Force -ErrorAction SilentlyContinue; continue }  # 无 pid 可探时的兜底
    Start-Sleep -Seconds 10; continue
  }
  try { New-Item -ItemType Directory -Path $lock -ErrorAction Stop | Out-Null; break }
  catch { Start-Sleep -Seconds 5 }
}
try {
  # ===== 持锁区：编译 / 测试 / git add / git commit / 变异 / 清理 =====
} finally {
  Remove-Item $lock -Recurse -Force -ErrorAction SilentlyContinue
}
```

- 持锁区尽量短：**只做会改动工作区的动作，一次做完**；不持锁做阅读／编辑，也不持锁等人或等输入。
- **抢锁前先探活，再抢回**：不能只看锁龄、也不能只读持锁者记录（它只持锁期间存在，里面可能留着上一轮的 pid）。顺序＝① 读持锁者记录拿 pid；② 再查**进程表**里有没有同票的活加锁进程；③ **活进程一律不抢回**；④ 无 pid 可探（记录缺失／是残留）才按锁龄兜底抢回。只看锁龄就会把活着的持有者当死锁抢掉，抢出两个写者。
- 跑完立刻在 `finally` 里释放；**不要**持锁等待人工输入。
- 抢锁被人挡住时的**完成判据**：按固定间隔重试到明确时限（等 15 秒重试、最多 10 分钟），超时就把挡住者的现场（原文与时刻）写进日志并上报编排者 —— 不无限等，也**不得替别人回退文件**。
- 失败必须以**一棵干净的工作区**结束（§2.5）：不空就不许释放锁、不许报完成。

### 2.1 依赖与临时目录（硬约束）

1. **禁止**在仓库内任何位置运行包管理器的安装／新增命令（唯一例外：编排者持锁显式授权）。缺依赖的正确处置＝**停手上报**，不要自行装。
2. 需要「安装态实证」时：安装目标用带票号与随机后缀的**仓库外独占目录**，该目录**必须先写最小工程文件**再装，确保包管理器不会向上解析到工作区根。
3. **任何递归删除前必须先做路径守卫**：断言目标绝对路径以自己声明的临时根开头，且**不在**依赖目录、源码目录、文档目录、测试目录、工具目录、`.git` 之下；守卫失败即抛错退出。
4. 临时目录用完即清；**不得**把临时根放在多席共用的草稿目录下供多个 agent 互相删除（各自用带票号与随机后缀的独占目录）。
5. 发现共享依赖目录异常、或编译因缺件失败 → **立即停手上报编排者并保留现场日志**（恢复由编排者持锁统一做），不要自行重装。

### 2.2 终端输出节流（上下文保护，硬约束）

**事实**：一次全量测试的输出可达十几万字节（约合单执行者上下文预算的四分之一以上），而**一次全绿的全部信息量就是退出码**。把成功日志全文读进上下文是最大浪费。

**规则**：

1. 长命令一律落盘：输出重定向到**本票独占目录**下的日志文件（相对路径在回执里给出），紧随其后打印一个**唯一标记行**与退出码；等标记行出现，然后只读**最后 5 行**确认退出码。**不要**把日志散落在自造的目录名下，收尾时找不到它。
2. 退出码非 0 时才检索失败签名（`FAIL|✖|not ok|AssertionError|Error`），只读命中行及前后 10 行；修完重跑后同样只看尾 5 行。
3. 证据脚本必须打机器可读摘要行（`RESULT: n/m`、`PASS/FAIL`）；复核只读摘要行＋退出码，明细留在文件里备查，**不读全文**。
4. 禁止重复读同一份输出；禁止把大日志文件通读进上下文。
5. 变异／探针脚本的输出同样适用：只看"红没红（fail>0）＋ 还原后是否与原内容一致"两行，并给出这两行的机器读数。

### 2.3 锁的留痕必须落盘（硬约束）

1. 加锁包装器**必须**把等待与运行信息**落盘**（写到锁目录，可用参数覆盖），不得只打印到终端：
   - 持锁者记录：`pid`／`ticket`／`cmd`／`startedAt`／`waitedMs`。
   - 运行记录：**追加**一行机读记录 `RUN ticket=<票号> cmd=<命令> waitedMs=<n> exit=<n> at=<ISO>`（值含空格时以双引号包裹）。
2. 等待量**必须**能从上述落盘文件复核；**只打印到终端的等待量视为不可复核**，审查中**不得**作为「当时锁为空」的证据。
3. **持锁者记录只在持锁期间存在、释放即删** ⇒ **它不在不等于没走包装器**；判断"有没有走包装器"看**运行记录**里的持锁行（`START`／`RUN`），不看这个文件在不在。
4. **对账源必须可追踪**：运行记录写在未受版本控制的锁目录下，第三方无法复核 ⇒ 收尾时把**本票声明过的**运行条目**导出到受版本控制的归属件路径**，并在证据里引用该导出件（导出件可直接当对账源复核）。导出件按票号范围抄录即可，不要求覆盖某段时间内的全部条目。

### 2.4 机械门禁：编译／测试的加锁执行与对账（硬约束）

1. **一切编译、测试**（含全量门禁、靶向测试、变异轮重建）都**必须在持锁状态下跑**，区别只在**由谁持锁**：
   - 自己**没有**持锁 ⇒ **经加锁包装器执行**（由它抢锁、留痕、释放）；
   - 自己**已经**持锁（落点窗口、变异电池、只读演练、清理）⇒ **直接调用，不得再次抢锁**。
   包装器负责：按 §2 抢锁（含探活）、按 §2.3 落盘留痕（持锁／运行／抢回三类行，均带**运行标识**）、释放前先校验归属，**写留痕失败即以非 0 退出**。
2. **证据对账（只对账声明过的运行）**：证据文件里**声称**跑过的每次运行，都必须在运行记录里找到**一对一**对应条目；缺失即非 0 退出并逐条列出缺失项。声明的规范写法＝单独一行 `GATE-RUN runId=<运行标识> cmd=<命令>`，标识从运行记录的对应行抄录。**没有该声明的运行不计入对账，也不得当作门禁证据引用** ⇒ 声明要**边跑边补**，不要收工后集中补一轮。
3. **默认口径**：① 证据里没有声明即失败；② 声明**必须引运行标识**，只认标识相同的条目（同命令的历史条目不得顶替）；③ **只领退出码为 0 的条目**（跑了却失败不得充作门禁证据）。因此**违规只落在"有人声称跑过的运行"上**：声称了却没有对应留痕才判违规；**没有声称的运行不按裸跑追究**（干活时的调试红、故意变异红都属正常，不必逐条写进证据；对账查漏不防伪，造假按 S1-交付缺陷处置）。
   - **旧的严格反向对账是可选开关**：`check-gate-audit.mjs --require-undeclared`（可再配 `--since`／`--until` 界定一段窗口）才要求「窗口内不得存在无人声明的运行条目」。默认**不开**——它把调试期的每一次红都逼成报表工作，收益不抵成本（2026-09-18 维护者裁定，票 #710）。`--allow-undeclared` 保留为兼容用的空开关。
4. **放行只有一种**：放宽**余下的**默认口径（`--allow-no-claims`／`--allow-nonzero`／`--allow-no-runid`）**必须由编排者在派单里具名授权**（授权对象／一次性／范围），证据里**引用该授权句**，并按授权范围逐条复核；未经授权的放宽＝**S1-交付缺陷**。不存在"自己加个开关就能过"的通用放行口。
5. **直调与内嵌**：自己已经持锁时（落点窗口、变异电池、只读演练、清理），一律直接调用等价的底层命令（编译器／测试运行器），**不得**在持锁区里再包一层加锁包装器（§2）。直调的运行同样要按第 2 条声明与对账。
6. **门禁工具的自证测试须单独触发**：包装器与对账工具自身的测试**不在**常规全量测试的范围内（纳入会与包装器嵌套抢锁），须**手工或 CI 单独触发** —— 不得据此认为全量测试已覆盖门禁工具自身。
7. **受控探针的具名授权**：为验证门禁识别力（如"漏声明是否能被抓住"），**编排者可具名授权一次受控探针**：须在派单中写明（授权对象／一次性／命令范围／只读要求），并在证据中留痕。经具名授权的探针不适用第 3 条的违规判定；**未经具名授权的同类行为一律按 S1-过程违规处置**。该授权**不类推**，也不得由实施者／审查者自行援引（同 §6.1）。

### 2.5 会动工作区的脚本（硬约束）

1. **失败即不落盘**：写工作区的脚本，其内部断言是**前置条件**，不是事后报表 —— 任一断言红 ⇒ **本次运行不落盘**（不写新件、不回写被改件），并以非 0 退出、把红条打印出来。「先写回再报告有红」＝ **S1-过程违规**（已经产生了需要回滚的既成事实）。落地顺序恒为：**先在内存里算出产物 → 跑完全部断言 → 全过才落盘**；默认只演练不落盘，只有显式打开写开关的步骤才落盘。
2. **按当刻内容变更，不按预备记录变更**：删除集／改写集只能由「本票拥有的范围」在**当刻工作区内容**上派生。**禁止**把行号、字节偏移、行数、预备期快照的比对结果当作变更依据 —— 别人先落点之后它们必然漂移，而漂移是**设计里就允许的**（命中 0 次记「已被别人做掉」、命中多次即抛错）。共享件只许定点删除，**禁止整文件覆盖**。
3. **窗口自带回滚**：任一步红 ⇒ **当次窗口内**做完两件事：① 逐文件点名还原自己改过的受版本控制的件；② 逐条点名删除自己新建的件。**禁止**用整目录还原或清空未跟踪件的批量命令（§3）。回滚自身也会红 ⇒ 回滚必须**容忍自身失败并继续把工作区清干净**。
4. **离开时工作区为空**：收尾**唯一判据**＝没有未提交改动、也没有未跟踪件（逐条列出，含新建目录内部的件 —— 只看目录名会漏）。**不空就不许释放锁、不许报完成**：半成品留在树里会让后面的票全部开不了窗。承接 §5：判「工作区为空」时**连生成物与生成记录一并检查**，不看生成物会误判为干净。

### 2.6 指纹绑定与安静窗口（硬约束，#540）

`dist` 是**共享可变**产物，而 §2 的锁**不覆盖源文件写入**：写者 A 持锁编译时，写者 B 可能正改到一半 ⇒ `tsc -b` 编出的可能是一棵**不自洽的树的快照**；此后任何**以 `dist` 为前提**的读数（真出口跑 CLI、变异两态、产物字节）都可能读到**混合态**，出假红假绿。故：

1. **指纹绑定（以 `dist` 为前提的读数必须与当刻编译指纹同证）**：同一次运行里给出「`src` 相关件指纹 ＋ `dist` 相关件指纹 ＋ 结论」**同一行**机器读数（做法：外层持锁，窗内按第 5 条直调 `node docs/agents/t540-指纹绑定.mjs --scope <包>`）。窗口内 `src` 有漂移（改字节／新增／删除）⇒ 该读数**一律作废**（非 0 退出）并**点名**漂移件；只报产物字节、不报编译指纹的读数**不得**当门禁证据（同 §2.3 第 2 条：没有一对一留痕的运行不计入对账）。
2. **安静窗口（这类读数一律挪到合并点安静态执行）**：承 §5.1「关闭口径以**合并点安静态复核**为准」——① 开窗前先确认没有别的席位在改本包 `src`（看 `git status --short -- packages/<包>/src` 与锁目录 `owner.json` 的属主）；② 读数窗口内不得有别人的源文件写入，做不到「无写者」时用第 1 条把该窗口**判**出来（漂移即作废），**不得**用「重跑一次碰运气」代替判定；③ 结论只对本窗口有效且**绑定 `src-sha`**：`src-sha` 一变，之前以该 `dist` 为前提的读数全部作废，须在安静态重跑。
3. **「多加一次 `--force` 重编」不是解法**：它只把窗口收窄，不解决读到混合态；也不得据此放松第 1、2 条。

### 2.7 全仓锁的候选改法（未实施）

- **现象**：所有编译／测试／git 写共用一把全仓锁（`tooling/run-locked.mjs` 的 `.scratch/locks/gate.lock`）。实测等待：本席一条命令等 **140 秒**；一个夜跑窗口里有一席连续占用数小时（#921 lane），另一席（#915 的五家技能交付）整晚大段在排队。
- **候选改法（两级锁）**：① **包级** —— 同一个包的两个 `tsc -b`／`build:client` 串行，不同包可并行（各包 `dist/` 是它的私有写面）；② **全仓级** —— 留四类：上游（`plugin-manager`）被重建时、仓根 `test/*` 的跨包判据（`panel-copy-743`／`panel-type-739`／`plugin-p10-boundaries` 等要同时读多个包的 `dist`）、`git add/commit`（索引全仓只有一个）、`pnpm install`／`pnpm gen`（共享 store）。
- **前提**：包级并行只在「上游不需要重建」时成立 —— 六家插件的 `tsconfig.json` 都 `references` `../plugin-manager`，`tsc -b` 会顺手编译上游，故实现时得先用 `tsc -b --dry` 之类的探法把这一情形拦到全仓级。
- **状态**：**未实施**，仅登记（维护者 2026-09-23：不轻易开票）。

## 3. git 纪律（最危险区）

- **禁止**：`git stash`、`git checkout -- .`、`git reset --hard`、`git clean`、`git restore .`、切分支（`git switch`／`git checkout <branch>`）。这些会**摧毁并发伙伴的未提交工作**。
- 只允许 `git add <自己声明的路径>` ＋ `git commit`（持锁）。**不要 `git add -A`／`git add .`**。
- **主干只许追加提交**：`--amend`／`--force*`／`--force-with-lease`／`rebase` 一律禁用（并发窗口下会让别人的提交被裹进混合提交，或让中间提交成孤儿）。
- 推送按当轮口径：默认**由编排者统一收口**；当轮若已授权各票自行推送，就按限定路径提交后**立即推送**（不留"不推不关"的悬置票）。

### 3.1 提交纪律（硬约束）

- **增量提交**：每完成一个有意义步骤就**立即持锁提交**，不要攒到最后。**宁可多提交，也不要让成果停留在未提交状态**——未提交的改动无法溯源、无法恢复。
- **提交信息用中文、说清做了什么**，格式：`feat(<票号>): <做了什么> ＋ <改到的文件／跑过的判据>`。
  - 正例：`feat(87): 输出命名规范复刻（默认目录＋同秒后缀＋中文命令名）＋ 新增 paths.ts 解析与 12 条单测`
  - 反例：`update`、`fix bug`、`feat(87): 修改` —— 无信息量，禁止。
- 为防终端代码页损坏中文信息：先把提交信息落一份 UTF-8 文件，用文件提交；提交后回读提交信息自检中文正常。
- **提交前逐项核对**：① `git diff --cached --name-only` 复核暂存区**只应含自己声明的件**；② 新文件（测试／证据／changeset）必须逐条点名加进暂存区，**别漏**；③ 自查工作区时用**含未跟踪目录内部件**的写法，否则全未跟踪的新目录只列目录名。
- **树上可能有别人的在途件**：自查"只含自己的件"永远只对自己声明的路径做，**不要求整棵树为空**；别人的改动不归本票处理，也不得被本票的提交带进去（§3.2）。
- **收尾时自己声明路径下必须干净**；报告里给出**全部 commit sha ＋ 提交信息**清单（只在这一处给，别处引用它）。

### 3.2 提交与证据的三条限定（硬约束）

1. **提交限定路径**：先 `git diff --cached --name-only` 复核暂存区**只应含自己的件**，再 `git commit -- <路径>`（不靠 `git add -A`／`git add .`）。**多出来的件一律先撤出暂存区再提交**，不许"一起提交了事"。
2. **对已入仓证据件的收窄／改写，原文必须落受跟踪路径**：收窄前的原文要提交进版本库，草稿目录只作临时副本 ⇒ 否则「收窄」在版本史上不可见，等于事后改数。
3. **结论类评论不回头改**：已发出的结论评论保持原样；改状态时在**正文或新评论**里写清**取代关系**（谁取代谁、据哪次运行），不做静默编辑。
4. **别人留下的未提交改动＝无主 diff**：执行者中途死掉留下的未提交改动，**不许当既成事实采信**。接手者必须先量现场（改动清单／逐件统计 ＋ 旧新内容哈希），再**自行判定完成度** —— 补齐、还原、重做都合法，且接手者保持「非受益者」身份。判「能不能接管」的最小证据＝语法检查通过 ＋ 改动的每处标题能逐条对上任务清单。

## 4. 终端使用

- 需要终端时**使用 sidebar 终端**（标题 `<票号>-<用途>`）→ 长命令按 §2.2 落盘＋等标记＋只读尾 5 行 → 结束前关闭终端释放。
- 不要用非交互工具跑长命令；不要开多个终端；长跑命令在同一终端内顺序执行。
- **等不到输出不要反复等**：sidebar 终端在睡眠之后可能不再吐输出（实测三席撞过）⇒ 换一个终端继续，并在回执里交代。
- **交棒要写停止点**：接任者读盘不读对话 ⇒ 交接必须写明「从哪个标记行之后接、下一手缺什么」。

## 5. 验收与报告

- 门禁口径以派单给出的**变更前基线**为准；基线由编排者冻结，任何人不得自行改口径。
- 每票必须自证：**变异自证**（故意破坏 → 相关测试变红 → 还原变绿；**默认源码级变异**）。**还原＝逐文件取回自己改过的受跟踪件**（不是整目录还原，也不是禁用清单里的批量取回）；**生成物按既定的重新生成流程复位**，取回改动对生成物不成立（它在忽略清单里，取回改动会留陈旧产物）。变异须在持锁期间做、释放锁前复原，清理须路径守卫，并给出"红／还原一致"两行机器读数。
- **回滚必须连生成物与生成记录一起复位**：只还原受版本控制的源码而不同步编译产物，下一窗一开就吃**假红** —— 冻结测试是从编译产物导入的，里面留着回滚前写法的产物。回滚后必须**两步连做**（缺一即假）：按当刻源码**重新编译**该包作用域 ＋ **重新生成记录**。**只重编不重签** ⇒ 一致性检查记陈旧；**只重签不重编** ⇒ 拿旧产物签字。**完成判据**＝重编＋重签之后一致性检查为绿 ＋ 受版本控制件无改动，二者缺一不算回滚成功。

### 5.1 审查者纪律

- **独立复跑**：不采信实施者任何结论；每句"已满足／已绿"都要自己跑。实施者不得兼任自己票的审查者。
- **自设新探针**：必须至少设计 **1 个被审脚本覆盖不到**的新变异或新探针（专打"脚本自我满足"盲区）；没有此条，审查结论不予采信。
- **归属标注**：每个缺陷必须标注**本票引入／本票范围／范围外发现**；范围外发现不得单独决定 FAIL（只能 S3＋转票措辞），除非它直接证伪本票的验收结论。
- **单票审查是初审**：关闭口径以**合并点安静态复核**为准；复核的**核心维度是「收窄是否变成放宽」**（必须自造真·权威写死的样例，证明改动后仍被抓）。
- 分数（如用）只是次要摘要：判定＋缺陷清单才是正文；五维（契约一致 30／证据真实可复现 25／新旧对照 20／工程红线 15／文档同步 10）供参考，不跨票比较。
- 证据入仓归属件目录 `docs/<类别>/<件名>/t<票号>-*`（类别与件名见 `docs/agents/doc-homes.md`）**并进版本库**；可复跑脚本随证据一起入仓；对账导出件按 §2.3 第 4 条同办。
- **回执（报告）的形状就按本条执行**：第一行判定（PASS／FAIL／未完成）；第二段机器证据，只给提交 sha、运行标识、退出码、摘要行（如 `RESULT: n/n`、`GATE-RUN runId=`）；第三段逐条路径（改动件、证据件、日志件）；第四段未做项与下一手缺什么。长度上限 1200 词，缺格与超长都不算交付。
- 完成后**停止**，等编排者指派：**修改前**先把未做项与下一手缺什么写进交接文件，回执只给判定／机器证据／路径。

## 6. 量刑与违规判定

**缺陷分级**：**S1-交付缺陷**＝契约违反／用户可见回归／证据造假或私自放宽／数据丢失风险 ⇒ 成果**作废并重做**；**S2**＝关闭前必须修完，除非编排者书面改期并给出具名票号；**S3**＝记账跟进，不阻塞关闭。

**量刑律**：任一 S1-交付缺陷 → **FAIL**（分数再高也否决）；均分 <85 → **FAIL**；无 S1-交付缺陷、且不存在未经记录的过程违规，且均分 ≥85 → **PASS**。

**违规（就在此列一次，别处不再复述）**：未经声明改动他人路径、绕过锁跑编译／测试／git、使用危险 git 命令、违反 §2.1／§2.2／§2.5 第 1 条 = **S1-过程违规**，默认按上文**字面作废并重做**。

### 6.1 S1-过程违规的具名记录条件

**① 记录条件**（不重做的唯一合法形式，四条缺一不成立）：为给过程违规留一条**可追踪的记录路径**、而不必把交付物本身作废重做，须同时满足：

1. **复跑证明无分歧**：审查者持锁独立复跑被质疑运行所涉的测试／门禁，结论与该次运行一致；
2. **等待量可复核**：按 §2.3 落盘，使「当时锁是否为空」可被独立复核；
3. **门禁可对账**：按 §2.4 让编译／测试在持锁状态下跑并留下运行记录，可被对账复核；
4. **具名书面记录**：由**编排者**在票面出具书面记录，引条号（本 §6.1）、声明**一次性**（仅限本次事件）、声明**不类推**（不得作为后续同类违规的先例）。

**② 成立判据**：第 1–3 条各出一条机器读数（持锁复跑结论／等待量行／对账结果）即可判成立，不必在同一套补偿上反复跑。

**③ 效力**：四条齐备 ⇒ 该违规记 **S3（记账跟进，不阻断关闭）**，交付物本身的技术面验收结论不受影响。**同一票或同一执行者再犯** ⇒ 记录路径**关闭**，按上文**字面作废并重做**。

**④ 权力边界**：记录是**编排者的具名行为**；**实施者／审查者无权自行援引**本条，也不得把「零实质风险」「锁当时为空」当作自行豁免的理由（审查者只能出建议，不能出裁决）。

**⑤ 未走记录条件时**：违反 §2.1／§2.2／§2.4 第 3 条／§2.5 第 1 条，或使用危险 git 命令，一律按 S1-过程违规**判 FAIL 且字面作废并重做**；§5／§5.1 的验收与审查纪律不因本节改动（审查者仍须独立复跑，实施者仍不得兼任自己票的审查者）。
