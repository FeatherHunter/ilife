一、#125 到底是什么（前因后果）

1.1 起因：一张表、两套说法

运动记录用的是「软删除」——删除时只是打上删除标记，行仍留在库里。问题出在：有的路径认这个标记，有的不认。

软删一条运动记录之后，你做的事修复前的回执应该是什么
按记录编号再改它（calorie.exercise.update） 「已更新运动 #2」 · exit 0 ❌ 「记录 ID 2 不存在」 · exit 4
按记录编号再删一次（calorie.exercise.remove） 「已删除运动 #2（软删除…）」 · exit 0 ❌ 「记录 ID 2 不存在」 · exit 4
按日期删同一批 「无运动记录（…）」 · exit 4 ✅ 一直是对的
为什么算缺陷：同一张表、同一条记录，「存不存在」这件事在写层有两种答案。用户按回执行事（以为改成功/删干净了），而记录早已被排除在查询与统计之外——回执与事实不符。

1.2 修法（已完成）

做法
按编号的改／删补上同一个过滤条件 COALESCE(is_deleted, 0) = 0，与按日／按范围路径、与读层统计口径（#120 的 EX_ALIVE）逐字同款；删除落库的 UPDATE 同加该条件以防竞态。
效果
三条路径行为一致：首次删 exit 0；任何路径重复删一律 exit 4；is_deleted IS NULL 的历史活行不受误伤（COALESCE 保住）。
