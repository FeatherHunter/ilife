# 维护者裁定（2026-09-09）：连带提交他人代码不构成缺陷

> 触发：#120 蓝队审查判 S1（`4d98e5f` 的文件级 `git add` 连带 #97 在 `src/cli/write.ts` 的未提交 WIP `measureCliNames`，且证据/票面称「不触碰 M5 回执逻辑」）。
> 维护者原话：「首先将其他人修改的代码 commit 提交了 并没有问题。因为都是为了完成目标写的代码」

## 裁定

1. **「提交里含他人未提交代码」本身不构成缺陷**（不论是否同票）：这些代码都是为达成同一目标而写，属正常协作结果。→ 蓝队 D-1 中的**「越权提交他人 WIP」部分予以撤销**。
2. **降级项（S3，记账）**：证据/票面若**声称未触碰某范围**而提交内容实际含该范围改动，**须如实补注归属**（写清「该 hunk 属 #97 的 M5 工作，经共享 index 连带入本提交」），但**不判 S1、不阻断关闭**。理由：归属标注是可追溯性要求，不是造假；且连带是共享 index 的机制性结果。
3. **仍然成立的真缺陷**：蓝队 D-2（对账声明缺 `--until` → 按其声明命令实测 `exit 1 / undeclared=3`）属**证据可复现性**问题，**须修**（S2）。
4. **共享 index 纪律（`dispatch-rules.md §4.6`）改为建议性**：`git commit --only <路径…>` ＋ 提交前核对 `git diff --cached --name-only` **推荐**用于归属清晰，**违反不判 S1**。唯一仍属缺陷的是「证据陈述与提交内容不符」，按第 2 条按 S3 记账处理。

## 影响

- **#120**：D-1 的 S1 撤销 → 该票**不再因 D-1 阻断关闭**；关闭前只需修 D-2（对账窗口）与 D-3／D-4（runId 窗口、行号文案），并补 D-1 的归属注记（S3）。
- **#88 实施 B 段**：**不受本条影响**——那笔是「**持锁但未用规定包装器**」（可审计性缺失），与「连带他人代码」是两回事，其处置仍待维护者裁定。
- 蓝队审查的其余结论（路径/禁区 0 命中、四门＋靶向独立复跑全 exit 0、canonical delta 新增 0、白名单 0 行、tracker 纪律）**继续有效**。
