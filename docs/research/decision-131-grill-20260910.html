Q16 · 死槽传不传 待拍

前因后果

C 解剖模板发现两个死槽：subtitle、meta_blocks——模板只读不渲染。但实物照传了 subtitle（"10 分类 · 436 场景 · 更新于…"）。传了没人看，不传少数字节。Q3 要"纯像素一致"，死槽不影响像素；但"字节级像不像"没人定过。

关键信息

实物 5 键：skill_name／title／subtitle／contact／groups；version／recommendations／init_banner 等全未传。
成本：跟传只多几十字节；不传则实物 diff 多一行。
风险：未来模板若启用死槽，不传的一方先缺。

选项对比

选项内容利弊
A（推荐）跟传（照抄实物 5 键形态，连尸体都像）字节级也像；未来启用不断档多传一个无用字段，有洁癖的人难受
B不传，干净JSON 最小与实物 diff 永久差一行；对账时每次都要解释
推荐 A。拍板后动作：5 键形态写进 T2 验收断言。

Q17 · 两层 token 以谁为准 待拍

前因后果

C 发现两套 :root：模板自带（--bg:#f2f2f7…）vs 注入 token A 组（--bg:#f5f5f7…），后加载覆盖，像素差 1–3 灰阶。Q10 的截图比对必须先定"标准答案是哪一套"，否则 diff 出来不知道谁对谁错。另有 esc() 双定义，转义表字面一致，风险低。

关键信息

用户看到的＝覆盖后（注入层生效）。
加载序（实物）：模板 style → SHARED-CSS，严禁"合并去重"。
差值：约 1–3 灰阶，肉眼难辨、机器可测——正好是 Q10 阈值争论的来源。

选项对比

选项内容利弊
A（推荐）以覆盖后（注入层）为准，新版保持同一加载序与用户所见一致；比对基准唯一模板裸文件单看是另一套灰——新人会懵，需注释说明
B以模板自带为准，注入层改成同值单文件自洽改了注入层＝改了实物，违背"按老来"
推荐 A。拍板后动作：Q10 的 vision 比对基准＝覆盖后截图；加载序进回归断言。
