② 违规到底是什么

协议原文（两句）

subagent-concurrency-protocol.md §2：以下操作必须持锁执行：pnpm build／tsc -b、pnpm test／node --test、git add／git commit。不需要持锁：读文件、编辑自己路径下的文件、grep、git status／diff／log。

§6：违规：未经声明改动他人路径、绕过锁跑 build/test/git、使用危险 git 命令、违反 §2.1／§2.2 ＝ S1 违规，该票成果作废并重做。

实际发生的事：实施者在核对第一处变异（MUT-A）是否还原干净时，直接跑了一次 node --test 做只读自检，没有走锁。它在自己的证据文件 docs/research/t88-impl-a.md §7-5 里主动如实登记了这件事，并请编排者裁决。

为什么这条规则这么硬：多个 agent 共用同一个工作区、同一个 node_modules、同一个 dist/。锁保护的正是这些共享可变状态——build 写 dist/ 与 .tsbuildinfo，git add 写索引。两个 agent 同时写，会静默损坏对方的产物，而且不会有报错。

建议：默认 --dry-run，写需显式 --write；并把「白名单文件未被改动」做成机械判据（现已有 git diff 0 行这一条，但只在人工流程里）。
