# 规格：卡路里技能架构（本体图终态）

## Problem Statement

作为卡路里的使用者与维护者，我在 TS 重构后遇到三个具体问题：

第一，新版没有提供与旧版质量（UI ／ 功能）一样的 HELP HTML——说「卡路里HELP」打不开旧版那种完整能力速查台；第二，SKILL.md 没有复刻旧版全部唤醒词与对应的 HTML 产出——agent 听到唤醒词却拿不到该有的页面；第三，新架构下 base-* 共享层缺失（控件层、图表层、HELP 模板、payload 契约），"改一处样式、所有技能生效"做不到，六个技能各自复制同一段 CSS。

同时，这些结论此前只散落在对话与未纳入版本控制的草稿里：新开的 session 不知道这个技能是怎么跑起来的，维护者过一段时间也要重新问一遍。

## Solution

把卡路里技能的**终态架构**写成规格并归档：单一真相（CLI ＋ envelope）、三态交付（含交付信号）、三层路由（发现／路由／执行）、共享层归属规则（base-paint ／ 技能包 ／ 插件 client）、以及"技能 → 插件"的单向能力面。规格随仓版本控制，并在 issue tracker 留一份可检索的条目。

## User Stories

1. 作为纯技能用户，我想说「卡路里HELP」就打开完整能力速查台，以便一眼看全这个技能能干什么。
2. 作为纯技能用户，我想说任意一个旧版唤醒词都能拿到对应的 HTML 页面，以便不用记 key。
3. 作为纯技能用户，我想在无法保存文件的场景下也能拿到结果，以便在受限环境里照样用。
4. 作为纯技能用户，我想在没有模板匹配时得到结构化文字答案，以便不必被 HTML 绑架。
5. 作为纯技能用户，我想在中间态页面里填好数据后一键复制出 prompt，以便交给 AI 完成写入。
6. 作为纯技能用户，我想复制按钮有明确反馈，以便知道复制成功了。
7. 作为纯技能用户，我想所有页面共用同一套设计变量，以便不需要重新学。
8. 作为纯技能用户，我想 HELP 页视觉与旧版标杆一致，以便迁移后不降级。
9. 作为纯技能用户，我想生成的 HTML 文件名可预期（中文命令 ＋ 时间戳），以便我能找到它们。
10. 作为纯技能用户，我想渲染失败时看到明确错误回执，以便知道下一步做什么。
11. 作为 agent，我想调 CLI 后从 stdout 拿到一行 envelope，以便不用解析多段输出。
12. 作为 agent，我想 envelope 里带交付信息（模式／路径／模板／字节数），以便知道渲染成没成功、文件在哪。
13. 作为 agent，我想参数错误与缺数据有不同退出码，以便决定重试还是报缺。
14. 作为 agent，我想读到门面文档就知道唯一出口与口径，以便第一次就调对。
15. 作为 agent，我想能查唤醒词到 key 的映射，以便处理我没记住的词。
16. 作为 agent，我想知道哪些唤醒词"命中但不执行"，以便不承诺做不到的事。
17. 作为 DSH 用户，我想装一个插件就自动带上技能且技能目录可查，以便装上即用。
18. 作为 DSH 用户，我想在面板里看到与直读一致的数，以便相信面板。
19. 作为 DSH 用户，我想在面板里新增／删除数据并得到带 id 与影响行数的回执，以便确认真的写进去了。
20. 作为 DSH 用户，我想面板复用技能的设计变量而不是搬 HTML，以便两边看起来一样但各自可维护。
21. 作为维护者，我想 CLI 是唯一真相、HTML 与面板只是呈现，以便不会出现两套数。
22. 作为维护者，我想渲染是纯函数，以便页面测试不依赖真机。
23. 作为维护者，我想共享控件／图表／样式只写一次，以便改一处所有技能生效。
24. 作为维护者，我想共享层零运行时依赖，以便不引入供应链风险。
25. 作为维护者，我想改配色时有主题接缝，以便一个技能的浅色主题不强行推给其余技能。
26. 作为维护者，我想新增能力只需在少数几处声明，以便不因耦合而拖延。
27. 作为维护者，我想新增 key 只能追加不能改名，以便不静默破坏已有调用。
28. 作为维护者，我想有一道"示例可执行"门，以便门面文档里的命令照抄就能跑。
29. 作为维护者，我想能只读打开任意库（备份／他人库），以便取证时不冒任何写入风险。
30. 作为维护者，我想在只读连接下不触发迁移，以便审计可复现。
31. 作为后续技能的开发者，我想照抄卡路里这套架构改常量就接上，以便不重新设计。

## Implementation Decisions

- **单一真相**：技能能力 ＝ 77 个 key 的 envelope。HTML 与面板是同一 envelope 的两种呈现；禁止出现第二真相。
- **唯一出口**：所有数据操作只经 `calorie-cmd-read`（argv ＋ JSON ＋ exit）。禁止直连数据库；插件禁止 import 技能实现。
- **envelope 形状**：`{skill, key, shape, version, data}`；`shape ∈ stat/list/detail/analysis/receipt`。
  - 勘误注记（#92）：上句 `shape` 实为 **6** 个——以 `packages/base-link-core/src/envelope.ts:9-11` 的 `ENVELOPE_SHAPES` 为准（`list`／`detail`／`stat`／`receipt`／`analysis`／`fallback`）；本行原列举漏 `fallback`（降级载荷），属**不完整列举**，不是契约分叉。
- **交付信号（已拍方案 A）**：扩 envelope 增加 `delivery{mode, path?, template?, bytes?}`；stdout 仍保持"一行 JSON"契约。
- **三态交付**：① 文件态（默认，可写文件系统）② 内联态（无法写文件时 envelope 带 html 片段）③ 文本态（无模板或用户要求时给结构化文本）。三态同源。
- **回传态（第 4 态）**：中间态页面把用户填写的字段序列化为可粘贴文本，供 AI 再次调用 CLI。依赖共享层控件（复制＋反馈）与复制文本序列化能力。
- **三层路由**：发现层＝门面文档（其中键表由构建期生成，手改会被覆盖）＋ 插件注册的技能提供方；路由层＝唤醒词表（436 条，逐条 sha 断言）；执行层＝CLI key。点面板不走唤醒词。**补注（#81，不改本行结论）**：路由层＝唤醒词表（436 条 sha 冻结、本票零改动，作 parity 证据）＋ 路由表 `packages/skill-calorie/src/triggers/routing.ts`（436 条逐条恰落「可执行 326／命中但不执行 110」一桶 ＋ 34/77 无入口键补新拟入口 ＋ 1 条覆盖修复入口，零 py 命令引用）；`exec` 桶不变量＝「在标准种子库＋真实路径替换下实跑 exit 0」（可复跑 smoke `docs/research/t81-exec-smoke.mjs`／快照 `.md`），判据＝「只要存在一条能达成其所述能力的单命令（同 key ＋ 参数，实跑 exit 0）就入 exec」，仅语义上必须多步交互的 5 条 wizard 词留 non-exec。两处同源断言见 `test/calorie-routing-81.test.mjs`，逐条证据见 `docs/research/t81-route-evidence.md`。
- **HTML-First 铁则**：唤醒词命中且模板清单有对应页 → 必须渲染并打开；无模板才可文字答；渲染失败必须给错误回执，严禁手写 HTML 兜底。
- **唤醒词可达性**：436 条须逐条落入"可执行／命中但不执行"两桶；后者覆盖明确不做的一批（定时复盘／训记／营养表／落地）。
- **技能侧保持分层管线**（`cli → fetch → analysis → render`），**不六边形化**；显式化两个接缝：数据接缝（打开库／取数层）与呈现接缝（渲染函数）。
- **共享层归属三类**：跨技能复用且与领域无关 → base-paint；依赖宿主（浏览器／DOM／DSH 交互）→ 插件 client；其余 → 技能包。
- **base-paint 零运行时依赖**：图表与控件必须自包含，不得引入第三方库。
- **占位符注入**：由 base-paint 统一填充共享样式与脚本占位符；技能可保留私有模板，但必须走同一填充器。
- **主题接缝**：设计变量分层，使单个技能的主题变更不静默重刷其他技能。
- **区块组件**：把页面表达为"数据 → 约 12 个合规区块组件"，页面只写数据映射，避免每页自造轮子。
- **键表冻结**：新增能力只许追加 key，禁止改名；计数断言保留（刻意冻结），同步更新注册与文档。
- **数据库访问**：驱动为 Node 内置 SQLite。每次 CLI 调用打开一次库并执行建表／迁移语句——在 schema 已最新的库上**实测零字节变化**；真正改库的只有写键、schema 落后时的首次升级、以及罕见的热日志恢复。
- **只读路径**：新增只读打开函数（只读连接 ＋ 跳过建表／迁移），用于只读介质、他人库、备份与取证基线。
- **写库回执契约**：写操作回执必须含 id、时间戳、影响行数、写入字段摘要。
- **打包与装载**：技能包必须把门面文档与页面资产纳入发布，并有真正的装载路径；否则"唤醒词 → HTML"可以全绿而安装包里页面不可达。
- **输出命名**：产物路径遵循「目录 ＋ 中文命令 ＋ 时间戳 ＋ 冲突后缀」，并支持显式指定输出路径。

## Testing Decisions

- **只测外部行为**：CLI 的 stdout envelope、退出码、产物文件；面板与同键直读的对数；渲染产物与视觉规格的对照。不测内部实现细节。
- **接缝（第一性原理：理想是一个；本规格定两个）**：
  1. **主接缝——CLI 进程边界**：整个架构的对外契约都收在这一处。spawn 进程，断言 envelope 全字段、退出码语义、`--html` 产物存在与内容、交付信号字段。一次覆盖 key 表／参数校验／取数／口径／渲染／交付。
  2. **共享层模块边界（base-paint）**：它是六个技能共用的地基，且"零运行时依赖"必须在这一层自己的边界上断言；用 fixture 驱动注入器与区块组件，不依赖任何技能。
- **不单列为接缝**：渲染纯函数（主接缝更便宜的取样，属辅助单测）；插件桥（主接缝的**传输变体**，断言集相同，只额外断言错误映射）。
- **先例**：本仓已有 envelope 全字段断言、写键回执断言、渲染快照断言、边界门禁（零依赖／装配归属）、客户端工厂包门禁——新测试沿用同一形态，不另造体系。
- **门禁**：占位符零残留、id 唯一、复制实现单一来源；门面文档示例可执行；计数断言（77）；共享层变更后的其余技能快照回归门。
- **证据分级**：合成库证据与真实数据证据必须显式标注，不得混用；空库"同文一致"不能当作数值一致的证据。

## Out of Scope

- 面板功能全面化的定义（属全面面板图）。
- 其余五个技能的本体工作（照抄卡路里样板）。
- npm 发布窗口与脏 manifest 重发。
- 四类边缘能力（定时复盘／飞书发送归档／训记同步／mmx vision）的处置。
- 逐字 vendoring 旧版模板与脚本（已否决：会引入全局脚本，违反共享层约束）。

## Further Notes

- **规格来源**：本规格由一次讨论 ＋ 三份独立对抗式审查（依赖／并发、完备性、第一性原理）收敛而成；审查判原工作清单"不是计划"，整改后才成立。
- **旧基线**：对照物位于独立的 SKILLS 仓（含门面文档、73 个模板、渲染脚本、视觉标杆）；唯一未进版本控制的是两个真实 HELP 实例，已列为冻结项。
- **验收尺度**：不要求 DOM 同构；HELP 页按视觉标杆逐值验收，内容页按区块级规格验收；证据形态为可复现产物 ＋ 截图 ＋ 交互记录。
- **遗留待定**：数据库连接未设 busy timeout（并发写会立刻报锁），属一行代码的低成本加固，是否单独立票待定。
- **可读版本**：同目录下的 HTML 版为同一内容的可读呈现。
