# ADR-0004：文本外置与多语言（中英先行）

- 状态：已决定（2026-10-08，负责人认可）
- 语境：整个爱生活（3 个公共层包 ＋ 6 个技能 ＋ 7 个插件）把全部显示文本写死在源码里——实测 1,697 个源文件、254,854 行、47,296 条含中文的字符串字面量；`Intl.` 出现 0 次；语言变量全仓无人读取。宿主 DSH 的多语言能力只在浏览器一侧（词条注册、回退链终止于 en）；Node 侧没有任何翻译接口，而技能是独立进程、由插件调用。产品将来可能面向英文与其它语言用户。

## 决定

1. **目标＝文本外置**：全部件的显示文本搬进词条表；**加一门语言＝加一个词条文件，不改代码**。英文按需——先立机制、后按需翻译。
2. **机制住公共层，零运行时依赖**：查表、缺词条、回退链、语言选择、类型安全 key 在公共层；**消息求值走可替换端口**，实现由消费方提供（先接 ICU 语义的实现）；日期、数字、货币用运行时自带的 `Intl`。
3. **词条随包存放**，命名空间＝包名；跨包共用词进公共层共用命名空间；同一句话的多份副本改由**单一来源派生**。
4. **语言选择**：各技能配置文件 `language.text`／`language.format`（空串＝跟随调用方），命令行参数可覆盖，缺省回退 `zh`；未识别的值**报错并列出可用语言**；值是 BCP 47 标识，为日语等后续语言预留。
5. **三条不译**：命令关键字冻结；用户数据不译；唤醒词按语言**增补**，且路由表**按语言只加载一套**（避免同一意图两套词表造成命中歧义）。
6. **门只锁结构与行为，不锁文案字面**：删"把具体文案当判据"的断言；排印门改成语言无关的结构谓词并分语言名册；中文产物哈希基线保留并**扩成语言矩阵**；新增缺词条与 key 残留门。
7. **不变量：未声明的差异为零**——不启用多语言时全部产物与改造前逐字节一致；拼接串改整句造成的差异必须**预先申报**、由第二方逐处比对。

## 后果

- 新增文本必须走词条；多语言齐备后，每次文案修改要在两种语言上各写一遍（**永久成本，已知情接受**）。
- **机制载体不预设**：新增公共层包还是住 base-render 组件层共用位，由试点读数裁决（插件层可达性 ＋ 结构门改动成本）。
- 文件名策略、唤醒词增补范围另行裁决。
- 推进顺序：改写器 → 试点（两处硬缝）→ 按包铺开 → 收口（旧写法清零／安装态验证／人签字）；每张迁移票的判据是**本地的**（该范围残留计数 ＋ 中文列哈希）。
- 证据与调查底稿：`docs/agents/多语言方案-决策简报.html`、`.scratch/i18n-survey/`（8 份现场调查）；地图见议题 1197。
