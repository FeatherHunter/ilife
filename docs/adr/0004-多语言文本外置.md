# ADR-0004：文本外置与多语言（中英先行）

- 状态：已决定（2026-10-08，负责人认可）
- 语境：整个爱生活（3 个公共层包 ＋ 6 个技能 ＋ 7 个插件）把全部显示文本写死在源码里——实测 1,697 个源文件、254,854 行、47,296 条含中文的字符串字面量；`Intl.` 出现 0 次；语言变量全仓无人读取。宿主 DSH 的多语言能力只在浏览器一侧（词条注册、回退链终止于 en）；Node 侧没有任何翻译接口，而技能是独立进程、由插件调用。产品将来可能面向英文与其它语言用户。

## 决定

1. **目标＝文本外置**：全部件的显示文本搬进词条表；**加一门语言＝加一个词条文件，不改代码**。英文按需——先立机制、后按需翻译。
2. **机制住公共层，零运行时依赖**：查表、缺词条、回退链、语言选择、类型安全 key 在公共层；**消息求值走可替换端口**，实现由消费方提供（先接 ICU 语义的实现）；日期、数字、货币用运行时自带的 `Intl`。
3. **词条随包存放**，命名空间＝包名；跨包共用词进公共层共用命名空间；同一句话的多份副本改由**单一来源派生**。
4. **语言选择**：各技能配置文件 `language.text`／`language.format`（空串＝跟随调用方），命令行参数可覆盖，缺省回退 `zh`；未识别的值**报错并列出可用语言**；值是 BCP 47 标识，为日语等后续语言预留。
5. **三条不译**：命令关键字冻结；用户数据不译；唤醒词按语言**增补**，且路由表**按语言只加载一套**（避免同一意图两套词表造成命中歧义）。
6. **门只锁结构与行为，不锁文案字面**：删"把具体文案当判据"的断言；排印门改成语言无关的结构谓词并分语言名册；中文产物哈希基线保留并**扩成语言矩阵**；新增缺词条与 key 残留门。
7. **不变量：未声明的差异为零**——不启用多语言时全部产物与改造前逐字节一致；拼接串改整句造成的差异必须**预先申报**、由第二方逐处比对。

## 落地记录（2026-10-08 本轮）

8. **机制载体＝新公共层包 `base-entries`**（#1200 落地，载体裁决读数见 `docs/agents/多语言-载体裁决-读数.md`）：插件层可达（七个插件按 `createRequire.resolve('skill-<名>/package.json')` ＋ spawn 进程边界定位入口，新包可达但要加精确版本依赖＋发布链顺序），而「住 base-render 组件层共用位」对插件**完全不可达**。接口：`defineCatalog`／`MessageId<C>`（从基准语言 zh 派生，**拼错 key 编译期红**）／`resolve`（回退链 请求语言 → zh → en，全缺抛 `MissingMessageError`，绝不返 undefined）／可换求值端口 `Evaluate`（请求对象带 `language` 与 `sourceLanguage`，供真 ICU 后端判复数与选择类别）／`formatNumber`／`formatDate`（走运行时 `Intl`）。
9. **「零运行时依赖」收窄成一条可判规则**（#1199 落地，判据住 `tooling/check-boundaries.mjs`）：公共层包之间**只许依赖同样零依赖的公共层包**（图无环、不含 `node:` 与第三方）。旧的「base-render 的 `dependencies` 必须空」据此撤下——它不是被放宽：白名单外的任何公共层依赖照旧红。存量边（base-render／base-combos → base-link-core）与新边（base-render → base-entries）都在这条规则内。
10. **中文列账本逐字节不动，英文列另起账本**（#1199 落地）：`tooling/skill-html.snapshot.json` 的 194 条数值一字不改（改前改后 `git hash-object` 同值），英文列走 `tooling/skill-html.snapshot.en.json`（**只记与中文列不同的产物**——同哈希全量复制＝空转绿，门当场抛）。语言身份由**文件名**承载，账本正文不加 `lang` 字段（加字段＝改字节＝破坏中文列不变）。
11. **两道新门起步即绿，且范围为空要显式报数**：`tooling/check-i18n-entries.mjs`（缺词条）与 `tooling/check-i18n-keys.mjs`（key 残留）读 `tooling/i18n-scope.json` 的「已完成迁移」清单；清单为空时打「PASS: 范围 0 件（显式报数：这一轮什么都没查，不是「查过没问题」）」——空转绿是假绿，照 `check-base-floor` 的先例办。排印门 `tooling/check-typography-langs.mjs` 走语言无关结构约束（5 条）× 语言阈值名册（zh／en），并钉死「结构约束 id 不许出现在任何语言名册里」（按语言放宽即红）。

12. **空白词条＝未录；同 key 占位符集合必须跨语言一致**（#1306 落地）：`resolve` 读到空串／纯空白按「未录」跳过该站继续沿链取，全缺才抛 `MissingMessageError`（第 8 条「绝不返 undefined」因此扩成「绝不返空串」）；`tooling/check-i18n-entries.mjs` 增 `blanks=` 读数并逐文件点名判红；新增第三道门 `tooling/check-i18n-params.mjs`——同一包内同一条 key 在 zh／en 的 `{name}` 集合必须相等（少一个参＝`{name}` 原文上屏，多一个参＝`MissingParamError`），只缺语言列不判红。两门共用读表口径 `tooling/i18n-tables.mjs`。写模式的空英文列因此只许当票内草稿，不许进提交。

13. **渲染语言经运行期上下文传递，取词收敛到每包一个 m()**（#1197 迁移执行器落地，细节见 `docs/agents/多语言-渲染语言上下文.md`）：显式 `language` 参数逐链下传在 1,214 件／28 票的写集切分下不可行（调用方在别的票的文件里；base-paint 组件与技能包成环），故 `base-entries` 增 `runWithLanguage(run)`／`currentRenderLanguage()`（进程内渲染期上下文栈；不引 `node:`、不破零依赖，未进入上下文＝zh，不启用多语言时逐字节不变；同一进程内两段异步渲染交错不支持——技能一律子进程 CLI），各技能 CLI 解析一次语言后包住 dispatch；每包 `entries/index.ts` 导出 `m(id, params)`＝`resolve(本包 CATALOG, currentRenderLanguage(), id, params)`。key 第一轮＝派生命名 `<包目录>.<路径折 ->.<四位序号>`（全仓唯一，满足缺词条门正则）。机械改写器 `tooling/i18n-migrate.mjs` 负责 AST 级抽取／整句化（fail-closed、幂等、写前备份），英文回填走 `tooling/i18n-fill.mjs`；已有 12 件的显式签名与 #1307 接线不回退。

14. **迁移清单分三区：待迁／已迁／不迁，不迁必须写理由**（#1232 收票时定，判据住 `tooling/check-i18n-ticket-scope.mjs`）：票级清单 `tooling/i18n-ticket-scope.json` 每件只在 `files`（待迁）／`migrated`（已迁，必须同时登记进 `i18n-scope.json`）／`excluded`（不迁，必须写 `reason`）三处之一出现；已迁并集＝scope 已登记件，待迁＋不迁并集＝ledger − scope。**不迁不是漏件**：生成件（`helpShell.ts` 等走生成器）、`#74–#78` 冻结契约面（`spec/index.ts`／`spec/text.ts`／`spec/help.ts`／`spec/controls.ts`：常量值改动须走契约变更流程，本地化点在消费组件，如 `#1202` 的状态字消费件）、开发期报文（`output/saveHtml.ts` 的 `throw err(...)`）都在此列。收票时把该票 `files` 里的件按结论移入 `migrated`／`excluded`，跑 `node tooling/check-i18n-ticket-scope.mjs` 必须 `problems=0`。

15. **语言清单从词条目录派生，加语言不改逻辑代码**（#1322 落地）：`tooling/gen-entry-catalogs.mjs` 扫描 `packages/*/src/entries/*.<lang>.ts`，为每包生成 `src/entries/catalog.generated.ts`（静态 import 各语言表，浏览器束可用），并为语言选择层生成 `packages/base-link-core/src/config/languages.generated.ts` 的 `AVAILABLE_LANGUAGES`；14 个 `entries/index.ts` 只接生成对象，`tooling/i18n-langs.mjs` 的 `LANGUAGES` 与生成器共用同一扫描（`tooling/entry-languages.mjs`）。加一门语言＝加 `<lang>.ts`（或 `<分册>.<lang>.ts`）＋跑 `pnpm gen` 重生成数据清单，不改任何逻辑 `.ts`；加完先 `pnpm gen` 再 `pnpm gen:check`（只加文件直接跑 `--check` 会因 STALE 报红，这是预期的「清单没重生成」）。三处**数据清单**不属于逻辑代码，加语言时要一并补：①`tooling/shared-copy.json` 的共享词条段要补该语言的列（生成器按表列派生，不手改 `.ts`）；②`tooling/i18n-langs.mjs` 的 `LANG_REGISTERS` 是各语言排印规则数据，未登记时排印门显式打 `MISSING-REGISTER`（其余门与 `tsc -b` 照跑），补名册即绿；③词条文件命名沿用 `<语言>.ts`，语言段为小写 canonical 形（`zh-hant` 合法，`en-US` 不是合法文件名）。缺词条门按包发现语言：某包没有该语言表就跳过该包（回退 zh），不再对全仓逐包判「缺这门语言的表」；语言清单是**并集**，故某语言只覆盖部分包时其余包回退 zh，缺词条门主输出用 `COVERAGE: <语言>=<有表包数>/<已建表包数>` 显式报覆盖，不静默。

### 本轮登记的两条既有红（不是本票引入）

- `pnpm snapshot:html:check` 在基座即红两处：中文账本陈旧（账本 194 条 vs 当刻 193 条、49 件 sha 漂移、`memo/frag/memo.stats` 已不存在）与影响面标记（home／memo 两家 31 件 89 处含 `ilife-base` 等 base-paint 命名空间标记，而 `MARKER_ALLOW` 为空）。**处置＝如实登记、不动标记门、不重录**（重录会改中文列数值，与「中文基线不动」冲突）。
- `pnpm gate:audit` 无 `--evidence` 时 exit 2、`test/ci-gates-295.test.mjs` 的「CI 不许出现 continue-on-error」断言与现行 ci.yml 冲突：基座同形，本轮只登记。

## 后果

- 新增文本必须走词条；多语言齐备后，每次文案修改要在两种语言上各写一遍（**永久成本，已知情接受**）。
- **机制载体不预设**：新增公共层包还是住 base-render 组件层共用位，由试点读数裁决（插件层可达性 ＋ 结构门改动成本）。
- 文件名策略、唤醒词增补范围另行裁决。
- 推进顺序：改写器 → 试点（两处硬缝）→ 按包铺开 → 收口（旧写法清零／安装态验证／人签字）；每张迁移票的判据是**本地的**（该范围残留计数 ＋ 中文列哈希）。
- 证据与调查底稿：`docs/agents/多语言方案-决策简报.html`、`.scratch/i18n-survey/`（8 份现场调查）；地图见议题 1197。
