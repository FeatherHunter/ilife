# ADR-0002：卡路里「未搬迁清单」的棘轮与场景分区一并退役

- 状态：已决定（2026-09-17，用户原话：「全部按照推荐来」；裁定载 #705）
- 语境：`packages/skill-calorie` 曾把 92 条未搬迁命令放在一个清单文件里，并装了一道只许变短的棘轮。`#313` 起把清单按场景切成 `src/cli/legacy/scene-01.ts` … `scene-10.ts`，理由是并发的多个会话同搬两条命令会抢同一支笔。分区之后棘轮的牙齿改成钉「10 个分片之和」，条数上限 `92`、声明行数上限 `119`。

## 决定

- `#705` 实测：92 条已全部搬进各能力的声明件，10 个命令分片与 10 个路由分片**全空**，棘轮两边**实测都是 0**。
- 据此**一次性退役**：删 `src/cli/legacy/` 全部 23 件、删三件测试侧的件（`test/legacy-partition-313.test.mjs`／
  `test/legacy-ratchet-295.test.mjs`／`test/legacy-frozen-295.mjs`）、摘 `scripts/gen-cli.mjs` 与
  `scripts/gen-routes.mjs` 的 legacy 入口（扫场景分区、跨场景同键守卫、印记里对空分片的覆盖）。
- 「92 条未搬迁键一条不丢」这条事实改由**能力目录这一面**成立：`test/cmd-registry-294.test.mjs` 钉
  「能力目录的声明里一个键恰出现一次」＋「定义地之集恰为生成物注册表的键集」，不再依赖那 23 个空文件。
- **测试侧对账面 `test/declared.mjs` 保留**、只改写法（#705 原写「删 `test/declared.mjs`」；#708 写规格前的
  接缝确认查出它的消费者是**十二件测试**，不是三件——删它会把一次删除做成一次迁移，故按「保留 ＋ 改写法」落）。
- **退役由用户一次性拍定**，不留给下一位路过的人猜；本记录即那次拍板的长期留存。

## 后果

- 「未搬迁清单」这个概念在卡路里包内不再存在，`src/` 下不再有「只住文件头注释的空分片」。
- 会失掉的是「场景分区」这层容器本身。分区存在的唯一理由是并发窗口——92 条命令的搬迁波次已经结束，窗口已经关闭。
- 失去的还有「新命令不许再住进未搬迁清单」这道自动门。该门的功能由 `test/cmd-registry-294.test.mjs` 的两条断言
  承担：**「那批空清单与它的容器必须不存在」**（`src/cli/legacy/` 目录与冻结键集夹具都不许回来——数组为空是
  「清单还在」，目录不存在才是「清单不在」）与「声明只有能力目录一处」（铁律二的常规断言，不依赖本退役）。
- 若将来再出现「一批命令要先集中登记、再分批搬走」的局面，那是一个**新的**迁移窗口，应当按当时的并发形态重新设计容器，而不是复活这份清单。
