## 一、形状：为什么判据住技能侧

票面「开工前的形状裁定」第一条。一句话的理由：**每条检查项的有效值只有技能源码算得出来**（例：`resolveDbDir()` 里「`db.dir` 空串＝按默认落点」，落点是 `configPaths(stem).dataDir`；库文件名、产物目录名、包内预置件的位置同样只在技能里）。插件包对技能的全部能力是 spawn `cmd_read` 与读 stdout 信封，它看不到这些算式；判据若落在插件层，就得把六家的算式各抄一份进六个插件包，`#695` 一落地就集体走散。

于是三层分工：

| 层 | 干什么 | 判据/文案归谁 |
| --- | --- | --- |
| 技能侧（六家各一件 `src/health.ts` ＋ `src/cli/health.ts`） | 真的读盘、算有效值、出判据 | **判据与文案的唯一真相** |
| 插件包（六家各一件 `config.check` 端点） | 把技能那份报告原样交回面板 | 一个字都不重写 |
| 总管（`src/health-*.ts`） | 一次取数、总览一行、各家一张表 | 零特例：不认任何一家，只认报告形状 |

报告形状的面板侧镜像住 `packages/plugin-manager/src/health-contract.ts`；技能侧那份住 `packages/skill-calorie/src/health.ts`（其余五家同形）。

## 十三、第七轮：截图复评逮到的一处真缺陷（已修）与两条红

### 13.1 真缺陷：一条跨盘旁证把整张表的落点缩写全拖没

**现象**（看实拍才发现的）：备忘录那张体检表里，七八条落点**一条都没缩**、整片是 `C:/Users/…/AppData/Local/Temp/t706-shot-…` 这种长明文；而记账那张表缩得好好的。同一份代码走两条数据出两种结果，说明缺陷在数据这一侧。

**根因**：缩写原先是「先给一份报告算**一个**公共前缀，再拿它去缩每一条」。备忘录报告里有一条 `配了但目录不在：D:/ilife/media。`——**另一个盘**的旁证。一条旁证就把「公共目录前缀」算成空串，于是 C 盘那七八条全部原样印出。记账报告里没有跨盘旁证，所以它看着是对的。

**改法**（`packages/plugin-manager/src/health-view.ts`）：缩写从「一个前缀」改成「**按根分开的一组前缀**」。

- `dirPrefixesOf(report)`／`dirPrefixesIn(text)`：按根（盘符）分组，**每个根各自**算公共目录前缀；某个根下只有一条落点时不算（没有第二条可比，缩出来是瞎猜）；一组前缀按长短排序，缩的时候最长的先命中（缩短后不歧义）。
- `shortenPathsIn(text, prefixes)`：只按**扫得出来的那一段段落点**去缩，不再做全串替换——既不误伤更长的路径，也不会把一段路劈成半截。
- 表头那行不再印「（公共前缀 …）」把屏幕让给内容，前缀落到悬停里；每条报文的原文也进了悬停（要查证的人悬停能看到整条）。

**证据**（机器读数，非目测）：

```
备忘录那张表： 可见文字里的长路径 = 0 处（去掉悬停属性后计数）
  配置文件 …/memo.yaml · 数据目录 …/data ／ 不在：…/data ／ 不在：…/data/memo.db。 ／ 配了但目录不在：…/media。
记账那张表：   同上（本轮之前就缩、无回归）
新增两条用例咬它（tests 43 → 43+2 里的这两条）：
  · 一个盘上的旁证不许把别的盘的落点缩写全拖没（按根分开算前缀）
  · 同一路径出现在多条报文里时，逐条都缩（不是只缩第一处）
```
