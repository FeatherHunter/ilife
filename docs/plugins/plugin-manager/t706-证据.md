## 一、形状：为什么判据住技能侧

票面「开工前的形状裁定」第一条。一句话的理由：**每条检查项的有效值只有技能源码算得出来**（例：`resolveDbDir()` 里「`db.dir` 空串＝按默认落点」，落点是 `configPaths(stem).dataDir`；库文件名、产物目录名、包内预置件的位置同样只在技能里）。插件包对技能的全部能力是 spawn `cmd_read` 与读 stdout 信封，它看不到这些算式；判据若落在插件层，就得把六家的算式各抄一份进六个插件包，`#695` 一落地就集体走散。

于是三层分工：

| 层 | 干什么 | 判据/文案归谁 |
| --- | --- | --- |
| 技能侧（六家各一件 `src/health.ts` ＋ `src/cli/health.ts`） | 真的读盘、算有效值、出判据 | **判据与文案的唯一真相** |
| 插件包（六家各一件 `config.check` 端点） | 把技能那份报告原样交回面板 | 一个字都不重写 |
| 总管（`src/health-*.ts`） | 一次取数、总览一行、各家一张表 | 零特例：不认任何一家，只认报告形状 |

报告形状的面板侧镜像住 `packages/plugin-manager/src/health-contract.ts`；技能侧那份住 `packages/skill-calorie/src/health.ts`（其余五家同形）。

### 本轮修掉的一处真缺陷

体检表里那一行会印成 `去哪修：去哪修：把配置改回去…`——各家技能交回的 `action` 里**已经自带**「去哪修：」这个前缀，面板又加了一次。改法：面板侧只印一层（`actionText()` 剥开头那一次，别的一字不动），技能侧文案一个字不改。这条是**看实拍才发现的**，机器用例咬不到（它只断言 `action` 是字符串）。
