# 返修（第二轮，2026-09-20 晚）

## 现场（维护者真机）

装机 0.3.5 后点目录行，只弹一句：**「打不开系统文件夹对话框（directoryPicker.pick needs the native
capability; the composed picker serves "browse"）：请直接在框里填绝对路径。」**

## 三条根因

1. **入口三态按 `pick` 在不在判（主因）**。客户端命名空间上的三条动词**都在**——它们按
   `TYPERT_REMOTE.descriptors` 生成，与组合里服务哪种能力无关——所以 `pickerModeOf` 永远判成 `native`，
   每次都去唤一次被组合拒掉的系统对话框。「组合里服务哪种能力」在客户端**问不出来**：只有真调一次、
   看它拒没拒（`directory-picker/unavailable`）才知道。
2. **`list`／`createDirectory` 的回执也是信封**（`{ok:true,value}`／`{ok:false,error}`，出处
   `dsh-api-gateway/lib/client.js` 的 `invoke()`）。原先把命名空间直接当 `DirectoryBrowseFace` 用，
   等于把信封当列举结果：图上会是「读出来了但一行都没有」的空目录，**不报错**，所以更难发现。
3. **`DirectoryBrowserFromRow` 不订阅状态**。列举是异步落定的；没有 `useSyncExternalStore`，
   这一帧画完就没有下一次重画，图上永远停在「正在读取…」。

2 与 3 当时没暴露，只因为 1 让这条路一次都没走进去。

## 现在的形状

- `pickerModeOf` **先认两格浏览原语**（都在＝应用内浏览器这条路可能通），只有单独的 `pick` 才算 `native`。
- 新增 `browseFaceOf(raw)`：拆信封、失败按回执码抛 `BrowseAnswerError`；**透传参数个数照宿主的规矩**
  （描述符按「业务参数个数 ＋ 1」判有没有 `AbortSignal`，显式传 `undefined` 会在 `AbortSignal.any` 上炸，
  故本件从不传 signal）。
- 新增共用件 `openRowBrowser(...)`：**先开应用内浏览器**；宿主回 `refusalCode` 才收起图、交给调用方换路。
  策略只有这一处，六家不再各写一份。
- 行的接线改 `React.useSyncExternalStore(row.subscribe, row.state)`；`DirectoryRowBrowser` 因此多一格
  `subscribe`。
- **`directory-picker/unavailable` 这个码住各家 `dsh-ctx.ts` 镜像**（`DIRECTORY_PICKER_REFUSED`），
  共用件只照比不认名——解耦守卫那条「零宿主知识」照旧绿。
- 顺带修：面包屑第一格原先串了「上一级」那颗按钮的文案，现在每一格写它自己那一层的名字。

# 第三轮：本机「根」那一行（Windows 上点得到别的盘）

## 现场

维护者看图后问：进得去 `C:\…` 了，**怎么到 D 盘**？Linux／macOS 又会怎样？

## 为什么原先到不了（三条事实，都核过源码）

1. 宿主那条目录选择接缝只有 `list`／`createDirectory` 两格（`dsh-api-workspace-controller` 的
   `TYPERT_REMOTE.descriptors`：`directoryPicker/pick`、`/list`、`/createDirectory`），**没有「列卷／列根」**；
2. 面包屑是宿主拿 `dirname` 一路往上算（`dsh-host-directory-picker-browse` 的 `ancestryCrumbs`），
   到盘根就停——`C:\` 的上一级还是 `C:\`，所以别的盘不在任何可点位置；
3. 第一方的文件接口（`workspaceFiles`）动词是 `list／stat／read／readAll／readBytes／readRelated／changes`，
   也没有列卷；浏览器里更没有卷清单接口。

Linux／macOS 无此问题：根就是 `/`，所有卷都是它下面的挂载点（macOS `/Volumes/<卷名>`、Linux
`/media/<用户>/<卷标>`、`/mnt/…`），从根往下走就能到；且那两个平台上系统对话框是活的
（桌面启动器只在 win32 把 `directory-picker` 那行停掉、换成 browse 那一对），我们的代码被拒时会自动换它。

## 分层做法（各自只碰自己那份事实）

| 层 | 件 | 干什么 |
| --- | --- | --- |
| 取数（宿主） | `src/roots.ts`（新） | **一次系统调用**换整份清单：`[IO.DriveInfo]::GetDrives() \| % { $_.Name + "\|" + $_.DriveType }`；只读元数据（`IsReady`／卷标那类字段会真去问设备，掉线的映射网络盘会把调用拖住），3 秒超时、60 秒缓存、**任何失败回空**；非 Windows 直接回空 |
| 电话 | `update-contract.ts`／`update-host.ts` | 电话表加一格 `ilife-manager.roots`（**恒成功**：列不出来是空清单，不是错误码——面板据此只是不画那一行） |
| 客户端取数 | `directory-browser-roots.ts`（新） | 把一通电话拆成根清单：`createRootsSource({getCall, base, endpoint, method})` + 纯函数 `readRootsAnswer`。**不认识宿主**：三个名字由各家从自己的 `dsh-ctx.ts` 镜像传进来；取不到＝空清单 |
| 状态 | `directory-browser-state.ts` | 图的状态多一格 `roots`；`open()` 时**不等它**地问一次（落定了推一次重画），问过就不再问 |
| 视图 | `directory-browser-parts.ts`（新）／`directory-browser-ui.ts` | 路径行下面多一行「其他磁盘：`[C:\] [D:\] [E:\]`」，**两个以上根才画**，点它进那一层；顺带把样式与四行控件切到 parts 件 |
| 六家 | `src/client.ts`／`src/dsh-ctx.ts` | 建一次 rootSource 传进浏览器；三个宿主字面量住各家镜像 |

不需管理员，也不碰设备。
