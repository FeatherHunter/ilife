## 解耦守卫咬住什么（票面「高度解耦」的机械判据）

1. **共用件零宿主知识**：`directory-browser-*.ts` 的**代码**里不出现 `remote.`／`directoryPicker`／`directory-picker`（注释里解释「为什么不认识宿主」允许）。源码与产物两份都查。
2. **六家零互引**：六家源码两两 36 组检查，任一家不出现别家包名。
3. **六家只经能力门**：从 `dsh-life-pack` 取东西只许走 `dsh-life-pack`／`…/directory-browser`／`…/directory-browser-ui` 三条；deep-import `dist/` 具体文件即红。
4. **接线真落地**：六家各至少用到一条子路径（防「接了一半」）。

## 实现期被用例逮到的三个错（留在票据里作证）

1. **草稿筛选整条是死的**：`sameLevel` 判等把分隔符加到比较式**右边**，与「掐掉尾分隔符后相等」的写法相反 ⇒ 永远不相等、筛选恒为空。
2. **`parentOf('C:\')` 会切成 `'C:'`**：`C:` 是「当前盘」不是「上一层」，回上一级会多跑一趟列举、甚至跨盘。用例数的是**列举次数**，所以逮住了。
3. **两条子路径必须真能 `require`**：总管那条 `./client` 是 loader 工厂包（`window.__ModuleLoader__.load` 注册壳），六家 client 束 `require` 它会拿到**空 exports**——这一步不做，六家接上去就是运行时全炸。现在有用例在 Node 里直取两个子路径跑通。

## 未做项（如实记）

1. **真机点屏那一跳没做**：要在 Windows 桌面版的爱生活面板真点一次目录行——看「浏览…」是否开出自绘浏览器、能否进目录／新建文件夹、选定后是否回填该行且保存后仍在。本席无 GUI 点击能力。
2. **`dsh-life-pack` 尚未升版发版**：六家按 `^0.3.2` 声明依赖，本票新增的两条子路径只在仓内；装机要生效须先发 `0.3.3`，再走 #727 那条发版窗口。发版需维护者在浏览器批 2FA。
3. **`pickDirectory` 在五家仍是本地五行实现**（大厨那份已收口）：本仓用例加载器取不到子路径的具名导出，故暂留；等加载器换成真 `require` 后再并进共用件。
4. **远程／SSH 部署的真机读数没有**：自绘浏览器在那两种部署下应同样可用（它只经 `list`／`createDirectory`），但本席只在 Windows 桌面这一种组合上有读数。
