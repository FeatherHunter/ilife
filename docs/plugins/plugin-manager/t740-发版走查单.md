# #740 发版走查单（总管 `dsh-life-pack` 0.3.0 → **0.3.1**）

维护者口径：「发版」＋「**应该让我从用户的视角通过 DSH 命令进行安装和升级**」＋「或者是我们的面板
爱生活这个配置面板需要支持能够安装更新当前的这个插件」。⇒ 本席只做**发布**（npm 那一步需要维护者在
浏览器里批准 2FA），**装机与升级由维护者本人**用 DSH 命令或面板完成。

## 1 这一版对外行为（相对已发布的 0.3.0）

1. **更新区每个状态都给得出下一步**（票 #740 三轮对抗式审查）：待重启按事实判；六态从「无动作」
   改成画在那一行上的「重新检查」；**失败的行**一律补「重新检查」；写着「下面这条命令」的行命令块真出来；
   待重启横幅退成一行总账。
2. **配置体检取数面改到导航表**（票 #735）：六家的体检通道名不再走「槽注册选项」（那格被宿主白名单丢掉），
   改读导航表镜像；面板到各家的电话形状改回载体基段（真机 404 的根因）＋ 体检整批时限 60 s
   （六家 `spawnSync` 串行，按一家算必然误报超时）。
3. 客户端类型门修好（`tsconfig.client.json` 的 include 补上手写声明件 `src/dsh-plugin-update.d.ts`）。
4. 面板**本能管自己**：七个更新目标里第一位就是 `dsh-life-pack` 自己（`update-targets.ts`：
   `key='life-pack'`、`phonePrefix='ilife-life-pack'`），所以「装上更新」对**当前这个插件**同样成立——
   装完是「磁盘 0.3.1 / 正在运行 0.3.0」，面板会说「重启 DSH（退出后重新打开）后生效」（第 1 条那套状态机）。

| `dependencies` | `{"dsh-plugin-update":"^0.1.1"}`（无 `workspace:`，即 `--post` 门要断的那一条） |

**一处要记的环境事实**：`check-publish.mjs --post` 与向导 STAGE 4 走的是**本机 default registry**
（`npm config get registry` = `https://registry.npmmirror.com`，镜像有复制延迟），所以发布后立刻复核会是
`FAIL: … npm view 失败（未发布或复制延迟）`。**那不是发布失败**：同一条查询显式指 npmjs 时立刻返回
`0.3.1`，且 shasum／integrity／dependencies 三项逐字对得上（上表）。镜像追上后 `--post` 自然转绿。

> 顺带一条对装机有用的推论：**面板与更新包一律走官方源**（`dsh-plugin-update` 的
> `commands.js:44`／`config.js:5`／`reader.js:101` 都把 `https://registry.npmjs.org/` 当缺省），所以面板那条
> 「装上更新」不受镜像延迟影响；**手敲的 DSH 命令要自己带 `--registry=`**（见 §5）。


## 5 装机与升级（**维护者本人**，两种视角任选）

**视角一：DSH 命令**（会话里 `dsh` 与 `pnpm` 两条命令在 PATH 上）

```
dsh plugin --profile web add --save-exact dsh-life-pack@0.3.1 --registry=https://registry.npmjs.org/
```

**视角二：我们的面板**（这正是本版要验的那条路）

1. 打开 DSH → 设置 → 爱生活（面板题头的「检查更新」）；
2. 第一行就是**爱生活总管自己**：应显示「有新版本 0.3.1（正在运行 0.3.0）。点「装上更新」。」；
3. 点「装上更新」→ 装完那一行应变成「磁盘上装的是 0.3.1；正在运行的是 0.3.0。重启 DSH（退出后重新打开）后生效。」，
   横幅一行总账点名「爱生活」；
4. 退出 DSH 再打开 → 版本行应是 0.3.1，那一行回到「已是最新版本 0.3.1。」。

> 若面板那一行给不出「装上更新」，读数与截图请回帖到 #740——那正是本版要验的状态机。

## 6 第二次窗口：`0.3.1 → 0.3.2`（第四轮真机截图那条）

旧快照根本不到达守卫。**`0.3.2` 是这条改正的头一版。**
