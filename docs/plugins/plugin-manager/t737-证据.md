## 四、根因与两版修法（修哪一处才不算白修）

**根因**：「屏上那行」的版本号是**手写常量**，与包版本是两份各自维护的事实 ⇒ 定版只 bump `package.json` 时
它可以无声漂开一整版。第一版补了一条门去钉住「两份事实相等」——门能让漏改变红，但**源仍是两份**。

**第二版把源减成一份**：版本号不再出现在插件源码里，宿主运行时读自己这份包的描述文件：

```
装机上那份 dist/manager-version.js  →  ../package.json（同目录树的包描述文件）
```

于是「屏上那行 ≡ 装机包版本」是**构造性**事实，不靠人记、也不靠门补救；定版只剩改 `package.json` 一处。

## 五、新机制的形状（三层，一处定义一处用）

| 层 | 件 | 做什么 |
| --- | --- | --- |
| 宿主读值 | `src/manager-version.ts`（新增，只许宿主半引用：import 了 `node:fs/path/url`） | `managerPackageJsonPath()`＝`dist/manager-version.js` → `../package.json`；`readManagerVersion()` **永不抛**：读不到／非 JSON／没这个字段／空串一律回 `VERSION_UNKNOWN` ＋ `warn` 留痕（含路径与原因），只解析 `version` 字段，不缓存、不轮询 |
| 电话 | `src/update-contract.ts` 的 `MANAGER_ACTIONS.version = 'ilife-manager.version'` ＋ `VERSION_UNKNOWN = 'unknown'`（两侧共用的唯一定义）；`src/update-host.ts` 挂进总管自有电话表 | 入参 `{}`，回包 `{version}`；恒成功（「读不到」也是一种要给面板看的事实，不是错误码） |
| 面板渲染 | `src/update-client.ts` 的 `loadManagerVersion(call)`（单次、无轮询，失败回 `unknown`）；`src/client.ts` 的 `useManagerVersion` ＋ 那行文案 | 面板是浏览器产物、禁 node 内建，故**只渲染宿主给的值**；初值与读不到都是 `unknown`（与卡路里 #130 同一口径） |

`src/nav.ts` 里的 `MANAGER_VERSION` **删除**，原位留一条注释指路（版本号读哪里、为什么不再手写）；
包名 `MANAGER_PLUGIN` 仍是唯一定义，面板那行改用它拼。
