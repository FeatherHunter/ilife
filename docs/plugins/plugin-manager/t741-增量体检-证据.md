# 票 #741 证据：配置体检「按家增量」出结果

## 一、维护者反馈（真机，2026-09-20，`dsh-life-pack@0.3.2`）

> 「体检一次也能看到结果了。但是我看他是所有插件全部体检好后全量提示出来的。可以增量提示吗？就是每个插件都并发检查，此外每个插件的每一项出了结果就更新到 UI 上？」

## 二、读码结论（三层，逐层给事实）

| 层 | 现状 | 能不能改 |
| --- | --- | --- |
| **面板侧** | `health-panel.ts` 的 `run()`：先把各行全置 `running`，再 `await loadHealthReports(...)`，**等整批落定**才 `setRows(next)` ⇒ 最慢那家不回话前屏上一直「体检中…」，然后一次全出 | **能改，本票就改这一层** |
| **宿主侧** | 六家的宿主半用 `spawnSync`（各单品 `src/bridge.ts` 的 `readViaCli`，`SPAWN_TIMEOUT_MS = 20_000`）⇒ 六通电话在同一个宿主线程上**排队**干（这正是 #740 第二轮把整批时限从 25 s 改成 60 s 的原因） | 要「真并发」得把六个包的桥改成异步 `spawn`——跨六包，另开票 |
| **报告粒度** | 一家的报告是**一次** `spawnSync` 拿回来的整份 `{ items: [...] }`（技能侧 `config.check` 一次算完所有项） | 「每一项出来就更新」需要技能侧改产出协议（逐项／流式）；按现有契约（判据住技能侧、插件只透传）不划算 |

## 三、改了什么（只动总管包）

1. `health-fetch.ts`：取数口加一格可选的「一家好了就回调一次」——`loadHealthReports(call, tabs, onRow?)`。
   回调在**那一家落定当刻**触发（不是攒齐再给）；回调抛错被吃掉（画图是旁路，不是取数本身）。
   取数入口**仍然只有一处**（`health-706.test.mjs` 那条结构门照旧守着）。
2. `health-panel.ts`：`run()` 改成按家 patch 状态（函数式 `setRows`——两家可能在同一拍落定，
   直接读旧 state 会丢一次），全部落定后再收 `running`。渲染台的调试图照旧：每家落定多打一行
   `row=<id> ok=… err=…`，末尾仍打 `rows=N err=… first=…`。

**效果**：点一次「体检一次」之后，屏上是**陆续**出结果的（哪家先跑完哪家先画），不再等齐了才全量冒。
总耗时不变——它由宿主侧那个串行决定，不由面板决定。

## 四、判据与枪

| 判据 | 内容 |
| --- | --- |
| 增量（新，`health-706.test.mjs` B 组） | 假传输口＋一个手动放行的延迟 promise：**慢那家还挂着时**，快那家必须已经回调出去（`arrived === ['dsh-fast']`）；慢的放行后再回调一次；回调抛错不许把整批拖下水 |
| 结构（既有） | 取数件里 `loadHealthReports(` 的调用点**只有一处**（面板不许绕开它自己调通道） |
| 变异 `MUT-741-A` | 把「一家落定就回调」改回「攒齐了一起给」（真机那条全量冒出来的写法）⇒ 增量判据变红 |
| 变异 `MUT-741-B` | 去掉回调外面的 try/catch ⇒ 「回调抛错不许拖下水」那半条变红 |

## 六、本票**不做**的两件（留给下一手，已在本票开票说明里写明）

1. **六家桥改异步 `spawn`**（真并发：wall clock 从「六家之和」降到「最慢那家」）。要一起想的代价：
   并发之后「陆续出现」会变成「几乎同时出现」——两件事可以并存（并发跑 ＋ 按家画），但那是六个包的改动。
2. **按项增量**（技能侧逐项产出／流式回包）：需要动六个技能包的产出协议；按现行契约（判据住技能侧、
   插件只透传、一次 spawn 一份报告）不做。
