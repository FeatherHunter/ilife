### G3 红的最小复现（仓外临时目录，19 行）

```
npm pack skill-memo-ilife（0.2.1）→ 隔离目录 npm install（base-link-core 从 registry 解析）
装进来的 base-link-core = 0.3.0
导出键：ENVELOPE_SHAPES, ENVELOPE_VERSION, EnvelopeError, LinkCoreError, RegistryError,
        RunnerError, assertShapeData, createEnvelope, createRegistry, isEnvelope,
        parseEnvelope, parseRegistryKey, runCombo          ← 没有 loadConfig／saveConfig／resetConfig

```

不是产品缺陷。这与走查单开头那句一一对应：先发公共层。

### 6.3 G3 那两条红：根因与处置（都不是产品缺陷，但都必须先处理）

1. **公共层缺配置面**（首次红的主因）：干净装机里 `base-link-core` 落 0.3.0 ⇒ 新技能 `import { loadConfig }` 直接 `SyntaxError`。
   处置＝先发 `base-link-core`／`base-combos` 0.3.3（§6.1）。**最小复现**：隔离目录装 `skill-memo-ilife@0.2.1` tarball ＋ registry 解析 base-link-core，
   `node -e "import('skill-memo-ilife/cli')"` → `The requested module 'base-link-core' does not provide an export named 'loadConfig'`。
2. **门里的备忘布景还是旧口径**（第二次红的唯一一条 `memo.stats exit4`）：技能侧自 #695／#722 起「库在哪」由配置文件定，
   旧布景（`SKILLS_DB_PATH` ＋ `<db>/memo` 空目录）已不再被技能读取，而 `memo.stats` 要找 `<数据目录>/memo.db`。
   处置＝`tooling/check-publish.mjs` 的 G3 断言改成冻结口径：给每家一个隔离 `ILIFE_CONFIG_DIR`，数据目录落在其中，
   备忘库按老 schema 建空库（布景件取 `tooling/contract-seam.mjs` 的 `initMemoTestDb`，与技能单测同源，不另抄一份 DDL）。
   **顺带收掉一个副作用**：此前 G3 会让五家技能把 HELP 产物写进维护者真实的 `~/.ilife/data/`；现在全部落在临时目录。

> 另记一条环境坑：npm 的 packument 缓存会让「刚发布的版本」在本地解析里看不见（`--prefer-online` 也不一定穿透）。
> 复跑门时用冷缓存（`npm_config_cache` 指向空目录）一次就过；`--post` 同理，读副本复制延迟用带 cache-buster 的直连复查确认。
