### G3 红的最小复现（仓外临时目录，19 行）

```
npm pack skill-memo-ilife（0.2.1）→ 隔离目录 npm install（base-link-core 从 registry 解析）
装进来的 base-link-core = 0.3.0
导出键：ENVELOPE_SHAPES, ENVELOPE_VERSION, EnvelopeError, LinkCoreError, RegistryError,
        RunnerError, assertShapeData, createEnvelope, createRegistry, isEnvelope,
        parseEnvelope, parseRegistryKey, runCombo          ← 没有 loadConfig／saveConfig／resetConfig
node -e "import('skill-memo-ilife/cli')"
  → CLI 导入 ERR: The requested module 'base-link-core' does not provide an export named 'loadConfig'
```

**结论**：`base-link-core` 若不先发 0.3.3，新技能在**任何**干净装机里都起不来；G3 的红是门在正确拦人，
不是产品缺陷。这与走查单开头那句一一对应：先发公共层。

## 3 发布顺序与命令（维护者执行；OTP 只在人手上，不进聊天）

前置：`npm login`（本机现 `ENEEDAUTH`，registry 默认是 npmmirror，发布必须显式 `--registry=https://registry.npmjs.org/`）。

1. **公共层（无 wizard，直接发）**
   ```
   cd D:\ilife\packages\base-link-core && npm publish --access public --registry=https://registry.npmjs.org/
   cd D:\ilife\packages\base-combos   && npm publish --access public --registry=https://registry.npmjs.org/
   ```
   发完立刻复核：`npm view base-link-core version --registry=https://registry.npmjs.org/` → `0.3.3`
2. **重跑 G3**（`node tooling/check-publish.mjs --fresh-tmp`）——此时应转 **PASS**；若不转，停在这里查，别继续往下发。
3. **五家技能**（先技能后插件：插件对技能是精确 pin）
   ```
   "C:\Program Files\Git\bin\bash.exe" D:/ilife/packages/skill-calorie/scripts/wizard-publish.sh
   "C:\Program Files\Git\bin\bash.exe" D:/ilife/packages/skill-chef/scripts/wizard-publish.sh
   "C:\Program Files\Git\bin\bash.exe" D:/ilife/packages/skill-home/scripts/wizard-publish.sh
   "C:\Program Files\Git\bin\bash.exe" D:/ilife/packages/skill-memo-ilife/scripts/wizard-publish.sh
   "C:\Program Files\Git\bin\bash.exe" D:/ilife/packages/skill-schedule/scripts/wizard-publish.sh
   ```
4. **五家插件**
   ```
   "C:\Program Files\Git\bin\bash.exe" D:/ilife/packages/plugin-calorie/scripts/wizard-publish.sh
   "C:\Program Files\Git\bin\bash.exe" D:/ilife/packages/plugin-chef/scripts/wizard-publish.sh
   "C:\Program Files\Git\bin\bash.exe" D:/ilife/packages/plugin-home-ilife/scripts/wizard-publish.sh
   "C:\Program Files\Git\bin\bash.exe" D:/ilife/packages/plugin-memo-ilife/scripts/wizard-publish.sh
   "C:\Program Files\Git\bin\bash.exe" D:/ilife/packages/plugin-schedule-ilife/scripts/wizard-publish.sh
   ```
   （也可一条命令按依赖序发：`node tooling/publish-chain.mjs --live --only base-link-core,base-combos,skill-calorie,skill-chef,skill-home,skill-memo-ilife,skill-schedule,dsh-calorie,dsh-chef,dsh-home-ilife,dsh-memo-ilife,dsh-schedule-ilife`
   —— 注意它走的是 `npm publish`，stdout 必须是 TTY，否则会 `EOTP`。）
5. **发后复核**：`node tooling/check-publish.mjs --post`
6. **装机验收**：把范围里的六家换成新版（`dsh plugin add …` 或 link 本仓）＋ 跑探针
   （照 `docs/plugins/plugin-manager/t678-真机验收证据-0.2.6.md` 那支，七个目标应全 `panelRegistered=true`）
   ＋ 重启宿主后逐家改一项配置看是否落盘。
7. **收口**：[四家单品的已发布产物缺少爱生活页签槽注册](https://github.com/FeatherHunter/ilife/issues/723) 的 ○→● 随本票一起关。

## 5 风险与遗留

- **发布后装机不会自动更新**：`dsh-life-pack` 的「检查更新」能查到六家新版，但要点了才装；装完必须重启宿主才生效（这就是 `pending-restart` 那一态）。
- 各技能 `AGENTS.md` 里「硬前提 `base-paint@0.3.2`」的文案已陈旧（现 0.3.3），本次只动与本次发版相关的版本行，未做这句的订正。
- 发布窗口与其它图互斥：本单定版时 `git status` 干净（除本票新增的文档件），记账那一席已把写集提交。
