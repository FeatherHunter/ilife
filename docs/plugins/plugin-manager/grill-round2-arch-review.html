Q4 单页还是分页

问题：A 以单页完整显示为基础，翻页动效只作点缀；B 必须分页，每页一屏，带舒展翻页动效；C 单页与分页各做一个原型，看后再定。

背景

卷轴内容区现在固定三段（SealScrollProps progress/status/plan，seal-scroll.ts 177～191 行），手册要多节，得扩展新类型。浮层挂在卡片里面绝对定位（S.dialog 上沿悬在章下面，左右各留半 em，155～157 行），宽度随内容走，窄卡时收满（popInner maxWidth 100%，158～161 行）。单页写长了会把卡片撑高；分页要在浮层里多记一套状态（当前第几页、焦点、滚动位置），和现有“点别处即关、不锁滚动”（415 行）合不来。

推荐答案

选 C：单页和分页各做一个原型，对比后再定。架构终态倾向 A，也就是单页为基础。

选项对比

选项优点缺点
A 单页为基础从头到尾连续可查，锚点直达；浮层不用多记状态；现有展开动画直接拿来用长文把卡片撑高，节与节之间靠锚点找
B 必须分页每屏字少，看着不累要多管一页状态和焦点；和“点别处即关”合不来；内容一增一减就得重分页
C 各做原型再定看到实物再选，不靠猜；做原型的代价比返工小多花一个原型的时间

对抗式审查

先挑 C 的毛病：如果原型只比谁好看，不比 390 宽、长文、增删三档，等于白做。再挑 A 的毛病：单页超过三屏又没有节内导航，照样没法读。所以 C 的原型必须带验收条件（390 宽不塌列、节锚点点得到、加一节不用改框架），否则多花的时间换不回决定。审查完还是选 C，验收条件先行。

从第一性原理出发

手册是拿来查的，第一位的是好定位、能搜索、链接长期有效。分页把搜索和锚点都切断了，状态成本永远背着；单页加节锚点三条都满足，成本只付一次。所以终态选 A：单页完整为基础，翻页动效只作点缀（复用 240ms 舒卷，识别到减少动态就关掉）。

Q5 风格如何定

问题：A 锁死卷轴加 HELP 章风格，不做其他；B 以该风格为起点，再做 2～3 个低保真原型比选；C 完全开放，不预设卷轴。

背景

现有视觉是锁死的：外框底色边线照抄对应那枚印（materialOf 和印共用调色板，214～223 行），糙边滤镜印和框各一条（外框 scale 6.5，300～305 行），纸面颜色写死（PAPER_BG #fdfaf2，深色下不跟主题跑，75～80 行）。手册比三段小卷长得多，硬套小卷的外框会显笨重，第一轮已经指出过。

推荐答案

选 B：认得出的部分锁死，只比版式。锁调色板、滤镜、纸面这三样；比入口位置、卷面分节、导航这三样。

选项对比

选项优点缺点
A 锁死和印章一眼是同一家；不用评审，最快大内容套小卷，大概率显笨重，到时候返工更贵
B 起点加比选认得出是同一家，版式又有得比；评审有标准要花评审的时间
C 完全开放选择最多没有起点，评审没有标准，讨论收不住

对抗式审查

挑 B 的毛病：如果比选把标识也改了，B 就滑成了 C。守住办法：原型只许动版式，调色板、滤镜参数、纸面色一律不许动，动了就出局。审查完还是选 B，加这条出局线。

从第一性原理出发

标识是让人一眼认出这是同一家，靠取值固定；版式是把内容装下，得看实物验证。一个靠锁死，一个靠原型，所以选 B：标识锁死在同一份调色板和滤镜上，版式用原型验证。

Q6 大纲分几节

问题：手册分哪几节讲插件使用、技能使用、HELP HTML 使用？要不要“出错去哪”一节？总管要不要单列一组？

背景

Q3 定的是三组（插件使用、技能使用、HELP HTML 使用），总管没有单独的能力。内容源已经盘过（t1192 证据）：插件走 plugin 七件，技能走 skill 六件的 SKILL.md，HELP 走各家 src/help。你之前要求不按七家重复写，HELP 全文也不搬进来。

推荐答案

卷首一句话（只带路，不替代 HELP）＋三组正文（每组写打开方式、常用两步、出错去哪一句话）＋附录“出错去哪”。总管不单列。

选项对比

选项优点缺点
三组无附录最薄出错的指引散在各组里，找不着
三组加附录（推荐）正文只讲用法，出错的集中一处；以后加一节不用改框架多出一节
按七家分节每家都全同样的东西写七遍，和 Q3 定好的冲突，出局

对抗式审查

挑附录的毛病：如果附录把各家告警文案抄进来，两份文字迟早对不上。避开的办法：附录只写“去哪看”（面板只看 message 那一句），具体文案一个字不抄。审查完还是加附录，加这条引用线。

从第一性原理出发

手册只负责带路。正文回答“怎么用”，附录回答“坏了去哪”，是两类问题，放两处。七家分节回答的是“每家是什么”，那是 HELP 的活。所以三组加附录，总管不单列。

Q7 链接规则怎么写

问题：细节链到各家帮助页面，链接写死文件名，还是写指引？相对路径还是绝对路径？

背景

HELP 文件名里带时间戳（主体_YYYYMMDD_HHMMSS_N.html，放在 xxx_html/help 这类目录下），每次生成都变。六家主体已经落定（饼干记账_HELP 等）。写死一个带时间戳的文件名，第二次生成就失效。

推荐答案

时间戳不写死。固定写三样：数据目录下的目录名（比如 schedule_html/help）、文件名主体（比如作息管家_HELP）、通式说明（主体_时间戳.html，取最新的）。面板里能解析就用相对路径直链，否则用文字指引。

选项对比

选项优点缺点
写死文件名一点就开第二次生成就成死链，出局
文字指引（推荐）长期有效，和时间戳机制合得来要多找一步
相对路径直链一点就开，版本更新也不怕只有面板能解析时才成立，得先实现支持

对抗式审查

挑文字指引的毛病：用户找不到数据目录，指引就是空话。兜底的办法：每条指引必须写清“动手点哪里”（面板哪一行、哪个按钮），只给目录不给动作就出局。审查完还是指引为主、直链为辅。

从第一性原理出发

链接要的是长期可达。时间戳文件名天生会变，长期不变的只有目录、主体、通式三样。所以链接写不变的三样，会变的那样不写。

Q8 窄屏、主题、动效

问题：窄屏下如何排？深浅主题跟不跟？动效降级怎么做？

背景

窄卡兜底已经有了（popInner maxWidth 100%，长行自动换行、高度自己长）。纸面颜色写死是故意的：跟了深色变量，纸会被染黑。面板也有现成的降级（hover:none 关悬停，prefers-reduced-motion 和 update:slow 关过渡，config-panel-view.ts 133～140 行）。

推荐答案

窄屏走单列，纸宽收满，节锚点顶置；纸面颜色写死不跟主题，外框和控件跟主题变量；动效只留 240ms 舒卷，识别到减少动态或慢速更新就关掉，触屏关悬停。

选项对比

选项优点缺点
纸面跟主题深色下整体统一纸被染黑，印章走样，出局
纸面固定（推荐）深浅两下印章都一致；定稿就是这么定的深色下纸面偏亮，得靠边线压住
动效常开展开时有动感开了减少动态的用户会难受，出局

对抗式审查

先问纸面：深色下亮纸晃眼怎么办？边线和圆角能收住，而且纸只占浮层那一块，不是整页，可以接受。再问单列：桌面会不会太空？最大宽度卡住居中，不拉满。

从第一性原理出发

纸面撑着标识，深浅下都固定；控件是操作层，跟主题变量走。动效不影响信息完整，缺席也行，所以可以降级。结论和推荐一样。
