## 二、改了什么

1. **取值面换家**（`nav.ts` ＋ `client.ts`）：面板拿「包名 → 本家客户端通道」不再走页签槽条目的自定义 options 格，改走总管自己那张各家表。为什么这么改，写在 `nav.ts` 的 `ManagerTab.channel` 头上：各家注册时**也**交了一份通道名，但装机槽位面不透传自定义注册选项（条目 options 只留 `{key,id,order,label,priority}`），总管读那一格恒是空串。
2. **镜子收口**（`dsh-ctx.ts`）：读侧（`SlotLedgerEntry.options`）删掉 `channel` 一格；写侧（`SlotsRegisterOptions.channel`）留着并注明原委——上游哪天开始透传自定义选项，可以一行切回账本。六家注册里那一格**没删**（同理由）。
3. **两态分开说**（`health-view.ts`）：汇总行的尾巴改成「N 家没有体检出口」；一家出口都没有时直接给红字那句「没有可体检的家：N 家都没有体检出口（通道名没登记上）」；有出口的全绿但有没出口的家时不再冒称「六家正常」，改成「有出口的都正常」。这样屏幕上不会再出现「按钮哑着、字却写『还没体检』」这种自相矛盾的态。
4. **两条判据**：`test/plugin-p10-boundaries.test.mjs` 新增跨包对齐门（真 import 六家 `dist/contract.js` 与总管 `dist/nav.js` 逐家比，另断通道名是单段路由名）；`packages/plugin-manager/test/health-706.test.mjs` 新增「两态不许同话」（含混合态把「几家没有出口」数出来）。

## 五、第二轮（真机发现）：第二条断链——面板到各家的电话形状写错了

维护者按第一轮的装了机、点了「体检一次」：按钮**这次有反应了**（回显「体检中…」＝第一轮那条链通了），
但取数没回来、摘要行仍是一句「还没体检」——看起来还是「按钮坏了」。这就是**第二条断链**。

**根因（读真机载体实现 ＋ 装机产物对证）**

载体是 `connection.rpc.call(第一段, 第二段, {method, payload})`（`dsh-client-connection/lib/client.js`）：
URL ＝ `` `${第一段}/${第二段}` ``，信封 `method` ＝ 第二段。而面板那份 `health-fetch.ts` 传的是
**通道名 ＋ 端点名**（`/ilife-calorie` ＋ `config.check`）⇒ URL 拼成 `/ilife-calorie/config.check`，
那个地址上没有任何人注册过路由 ⇒ 六家全 404。各家宿主半注册的真地址是 `'/api' + RPC_CHANNEL`
（装机六家逐家读数一致），信封认的 `method` 是 `ilife-calorie` 那一段。

同形先例：总管自己的电话在 #678 就栽过同一处（`update-contract.ts` 里那句「传错第一段就是 404：真机上踩过一次」）。

**为什么屏上看着像「按钮坏了」**：六家的错只画在**那家页签里的体检表**上，摘要行只显示「取数过程本身的错」
（`health.error`）；于是取数整批失败时摘要行一声不吭，用户看到的仍是「还没体检」。

**这一轮改了什么**

1. `health-fetch.ts`：调用形状改成 `call(CARRIER_BASE, phoneOf(通道名), { method: 端点名, payload: {} }, 信号)`；
   传输口的类型与更新面**同一张脸**（`HealthCallFace = CallFace`，一张脸一处定义）。
2. `update-contract.ts`：新增一处常量 `CARRIER_BASE = '/api'`（总管自己的电话也改引用它），把「第一段是什么」
   收成一处定义。
3. `health-panel.ts`：新增 `summaryErrorOf`——取数过程本身的错优先，**一家报告都没回来**时把第一条家错误顶到
   摘要行（`client.ts` 改用它）。这一格是一条独立判据（见下）。
4. 判据两条：`health-706.test.mjs` 的取数用例改成断言真实载荷形状（`['/api','ilife-calorie',{method,payload}]`）＋
   新增「报告一份都没回来时家错误要顶到摘要行」；`test/plugin-p10-boundaries.test.mjs` 新增**载体基段两侧一致**
   （六家宿主半注册在 `'/api' + RPC_CHANNEL`，总管那侧是 `CARRIER_BASE`）。
