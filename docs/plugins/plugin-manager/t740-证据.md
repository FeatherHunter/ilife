## 二、改了什么

1. **待重启改按事实判**（`update-view.ts` 的 `restartPendingOf`）：判据是「磁盘上的版本 ≠ 正在跑的版本」，与原因码无关。真机那次正是因为按原因码判，把「该重启」漏成了「上次安装被打断」。
2. **拦截态一律带出路**（`actionForBlocked`）：`installation-changed` → 按钮「重新检查」（就地重查这家、重绑指纹）；`recovery-required` → 按钮「重试安装」（更新包语义就是重跑一次收尾）；其余四种面板代劳不了 ⇒ 不给按钮，改摊那条可复制命令，并在命令上方写清**它是干什么的**。
3. **装成一家 ⇒ 其余各家的旧快照作废**（`markStaleOthers`）：七家共用同一份使用范围清单，刚那次安装改写了它，别家再拿旧快照去装必然被守卫拦下。作废只作废别家（装成那家保持原样），原对象不改写（纯函数）。
4. **「没东西可装」时不说拦截**：已经是最新的那一家不再挂「安装清单变了」＋一条重装命令（真机上那条纯噪声）。
5. **全表文案重写**（`update-contract.ts` ＋ `update-view.ts` ＋ `update-panel.ts`）：每条按「事实 → 后果 → 动作」三段写，动作必须是用户做得到、且面板上真有的那一步。清掉的自造词与口语：半截任务、电话没接上、宿主半、回执异常、还出现就重装、查宿主日志、没跑成、对不上、不要重试旧编号、一次查七家。重启动作统一写成**「重启 DSH（退出后重新打开）」**。

**核实过、结论「不必改」的两条**：

- **`recovery-required` 的「重试安装」会不会空转**：更新包的 `install` 要凭证，凭证只在可装态签发（`service.js:256`）⇒ 在「磁盘 ≠ 运行中」那一态确实装不了。但事实判据 `restartPendingOf` **先于**拦截分支，所以那一态给的是「重启 DSH」；「重试安装」只在「磁盘 == 运行中、上一次作业留了记录」时出现——那时 `canInstall` 可以为真，重试就是上游说的「重新点一次安装」。两支各自成立。
- **待重启那句写「新版 X」**：手工降级时「新版」不实 ⇒ 改成「磁盘上装的是 X；正在运行的是 Y。重启 DSH（退出后重新打开）后生效。」（只换措辞，判据不变）

**已知盲区（如实记账）**：

- 面板 hook 的接线（`act(target, action)` 传对动作、作废真的画出来）**没有渲染级判据**；只有纯函数判据 ＋ 一条「四个按钮名确实进了浏览器束」的交付面判据。真正的接线由真机那一步兜。
- 体检那半边（#735）：六家并发 spawn 的**总耗时**没在真机量过（技能侧 spawn 上限 20 s、面板超时 25 s）。真机首跑若撞上限，读数会写「体检超时（25s）：技能没在时限内回话。」，那时再谈放宽。
