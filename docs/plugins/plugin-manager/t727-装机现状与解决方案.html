0. 结论（先看这三行）

结论一：面板外壳是全的，配置那一半在「你装得到的世界」里是 0/6

总管 dsh-life-pack@0.2.6 已经是你本机在跑的那一版，所以「检查更新／星／气泡／配置体检／作者其他插件」这些外壳部件都在。 但六个技能设置页里：四家的产物根本没有往页签槽注册（作息／居家／大厨／记账，页签是 ○）， 另两家的产物是只读面（备忘录／卡路里，页签是 ● 但只能看不能改）， 六个技能包的产物连配置读写命令都没有。截图里看到的每一处不对，都归到这一条。

结论二：差的是「发版」这一个动作，不是代码

本仓 packages/*/dist 已经全部就绪：六个技能都有 config.js／health.js， 六个插件的 client.js 都带页签槽注册与配置体检通道。 而 npm 上的版本号与本仓 package.json 完全相同（生活包 0.2.6、卡路里 0.2.5、其余 0.2.0）， 同号不能重发 ⇒ 只能 bump 版本后重发。22 个子票关掉 ≠ 用户装得到

结论三：正式发版的最后一步只能由你按下；本机装机这一步我可以现在就做

我做不到的：本机 npm 未登录（npm whoami 报 ENEEDAUTH），发布要你的账号与 2FA； 以及「重启宿主」会让当前会话结束，得你点。

我能做的：把本仓产物直接链进你的 DSH 范围（~/.dsh/profiles/web）＋ 跑完机器判据， 你在重启后立刻能改配置、能跑体检 —— 这条路不需要 npm 凭据，而且你的范围里 2026-09-16 之前就是这么用的（有备份为证）。

2. 问题在哪儿（按层拆到根因）

根因层：发布滞后（唯一真根因）

  • 本仓 12 个包的改动没有一个伴随版本号 bump：dsh-life-pack 0.2.6／dsh-calorie 0.2.5／其余五家插件 0.2.0；skill-calorie 0.2.4／其余五家技能 0.2.0 —— 与 npm 上完全同值。
  • npm 的规则是「一个版本号只能发一次」，所以这些改动原地发不出去，只能 bump 后重发。
  • 公共层 base-link-core 更极端：本仓 0.3.3，npm 只有 0.3.0 ⇒ 配置读写件（src/config/）从未到达任何装机。

症状层 1：四家插件产物里没有页签槽注册（＝ issue #723）

装机 dsh-schedule-ilife／dsh-home-ilife／dsh-chef／dsh-bill-ilife 的 dist/client.js 里， 连 ilife.config-tab 这个字符串都不存在 ⇒ 面板永远看不到它们。 这一层 #723 已经写准，且已收编为发版票的子票。

症状层 2：两家的产物是只读面，而且注册时没带体检通道

装机 dsh-memo-ilife@0.2.0／dsh-calorie@0.2.5 注册的是 {name, id, order, label} 四项， 没有 channel；页面画的是 SETTING_ROWS 只读行（源码注释自陈「P10 脚手架」）。 而总管算体检目标集的那一行是 rows.filter((row) => row.channel.length > 0) ⇒ 目标集是空数组 ⇒ 点「体检一次」对 0 家跑，灯永远是灰的。

这一层 #723 没有覆盖（它只管「有没有注册」），它属于发版票那一圈。

症状层 3：六个技能产物没有配置命令与体检命令

装机六个技能包都没有 dist/config.js／dist/health.js（六个里 skill-memo-ilife 的 config 键命中数为 0） ⇒ 面板即使换成新页，也没有后端可读写。

症状层 4：装机技能仍按已退休的环境变量定位库（那条红字的来历）

装机 skill-memo-ilife@0.2.0 的 dist/cli/cmd_read.js 里仍是 const p = process.env.SKILLS_DB_PATH; if (!p) fail(1, 'SKILLS_DB_PATH 未设置（无默认值，必设）')。 你的用户级环境变量里 SKILLS_DB_PATH = D:\2Study\StudyNotes\.db， 它拼出的库目录 D:\2Study\StudyNotes\.db\memo 不存在（该目录下有 MemoHub 与 memo.db，没有 memo 子目录） ⇒ 技能以退出码 4 报「取数失败：memo DB 目录不存在」⇒ 面板原样印成红字。

另五个同类变量也还在（MEMO_DB_PATH／MEMO_MEDIA_DIR／CALORIE_PHOTOS_DIR／CHEF_OUTPUT_DIR／HOME_PHOTOS_DIR）。

症状层 5：目的地第 3 条「总管总设置区」整块没有做

面板 meta 只有两行静态字（packages/plugin-manager/src/client.ts:306-311）， 全局数据目录／六家配置文件位置／「重置为默认」三件都不存在，也没有对应子票。

开工前置：工作区现在不干净

git status：25 件改动，全部落在 packages/skill-bill/src（另一席在途；其 dist 今天 15:04 刚被编译过）。 按 docs/subagent-concurrency-protocol.md §2／§3，发版窗口开窗前必须确认工作区干净 —— 这一条会直接影响「记账」这一格的节奏。

3. 我打算怎么解决

路线 A：本机装机（不需要 npm 凭据，今天就能看到功能）

  1. 备份：把 ~/.dsh/profiles/web/package.json 与 pnpm-lock.yaml 按该目录既有命名习惯留一份带日期的备份。
  2. 改声明：六个插件由注册表版本改成 link:D:/ilife/packages/plugin-*； 六个技能与 base-link-core 用 overrides 指向本仓（插件对技能是精确 pin，不覆盖就仍会装旧技能）。
  3. 安装：在该范围下跑 pnpm install（本机 pnpm 11.8.0）。
  4. 机器判据：跑 t678 那支探针，七个目标应全部 panelRegistered=true（现在只有 3 个 true）。
  5. 重启宿主（你点「重启」按钮；重启会结束当前会话），然后逐家点开验收。

依据：这个范围在 2026-09-16 之前就是用 link: 跑的（有 package.json.bak-unlink-20260916123136 与 pnpm-lock.yaml.bak-* 为证）， 并不是我发明的新做法，而是本仓既有的真机验收路径。

风险（要你知情）：① 记账那一格会链到另一席在途的 skill-bill 产物（其 dist 已含配置面，但源码在改）； ② 改的是你的真实使用范围，所以备份与回滚命令我先写好；③ 不改本仓任何源码、不动 git。

发版顺序：公共层（base-link-core）→ 技能（六个）→ 插件（六个，它们精确 pin 技能版本）。 顺序反了会装到旧技能。

只有你能做的：① npm login（现在本机未登录）；② 发布时的 2FA 确认；③ 点「重启宿主」。

路线 C：那条红字（不属于本图，但要一起收）

它的根因是「装机技能还是迁移前那版」，所以随技能换代自然消失。换代后还剩一个只有你能定的口径： 新技能读 ~/.ilife/memo.yaml 的 db.dir，而现在那份配置里 db.dir 是空串（＝用默认数据目录 ~/.ilife/data）。 你现有的库文件在 D:\2Study\StudyNotes\.db\memo.db（我核实过它存在），所以换代时要把 db.dir 指到 D:\2Study\StudyNotes\.db， 新技能才会读到你原来的笔记；这一步是「改一项配置」，不用写代码。
