## 一、动手前的一条硬发现（裁定前提被证伪）

`#674` 的接法 (a) 写的是「总管宿主半给六个包名各调一次 `createHostUpdate`」；实施时按源码与实测核对，**这条前提只对「更新包装在目标包内部」的那一家成立**：

- 更新包默认读取器从**它自己的文件位置**向上找同名包（`reader.ts:170`、`containingPackage`），再用「找到的包 vs 磁盘已装包」比对（`reader.ts:218-232`）；
- 六个单品与总管是**兄弟包**（都住 `<使用范围>/node_modules/`），向上找不到同名包 ⇒ `runningVersion` 为 null ⇒ 每家电话必回 `unknown-profile`；即便硬给运行版本号，`sameLoadedPackage` 永远为假 ⇒ 一律落 `installation-changed`。

复现命令（只读，跑在仓库外的探针里）：

```sh
node -e "const {createRequire}=require('module');const {pathToFileURL}=require('url');const r=createRequire('C:/Users/辰辰洋洋/.dsh/profiles/web/package.json');import(pathToFileURL(r.resolve('dsh-plugin-update')).href).then(async m=>{const c=m.createHostUpdate({},{pluginId:'probe',prefix:'probe',targetPackageName:'dsh-calorie'});console.log(JSON.stringify(await c.handlers[c.phoneNames.updateStatus]({})))})"
```

读数：`{"ok":false,"error":"unknown-profile","errorKind":"unknown-profile"}`
（同一探针以 `dsh-life-pack` 为目标也是同一读数——因为更新包在 `web` 使用范围里只有一份被提升到顶层的副本，不在任何目标包内部。）

**处置**：不另起接法，仍走「总管统管」，只用更新包**公开的接缝** `readerOverrides.readInstalled`（`host.ts:141`、`:211`）自备环境读数。裁定里用户定的四件（落点、按钮形态、查七家、待重启横幅）一件没变。代价：总管多一个模块（`src/update-env.ts`，约 190 行），其中「包是否完整」那段是照更新包 `reader.ts:84-109` 重写的（它没有对外出口）。

## 七、0.2.6：三态（本版实现）

0.2.5 的第二态把两件不同的事说成了一件，是本版要修的：

- **产物里没有注册代码**（作息／居家／大厨／记账的已发布 0.2.0，票 #723）——等它发新版才对得上，重启与重装都不会变；
- **产物里有注册代码、只是还没送到浏览器**（装完还没重启宿主）——重启就好。

两件都显示同一句「要等它发新版」：前一件说对了，后一件把用户支到了一件没用的事上。本版把「已装产物里有没有爱生活页签槽的注册代码」作为一个**独立读数**从宿主交到面板：

| 态 | 判据 | 文案 | 动作 |
|---|---|---|---|
| 没装 | 磁盘上无该包 | 「未安装[dsh-x]，装上后这个页签就能用」 | 给「装上」 |
| 产物缺注册 | 装了、但产物里没有槽名 | 「这一版插件包比爱生活页签槽还旧：等它发新版；重启与重装都不会变」 | 无 |
| 装了没接上 | 装了、产物有槽名、槽里却没有它 | 「插件已装也在跑，设置页没送到浏览器：重启宿主；仍不行看宿主日志」 | 无 |

实现要点三条：

1. **第三态要的第三个事实只能从产物里读**：`readPanelRegistered`（`update-env.ts`）读该包 `exports['./client']` 出口文件里有没有槽名字面量（产物是构建期打包的，字面量会原样留下）。版本号答不出这件事。判据缺席（读不到文件／出口形状认不出／出口不是普通文件）一律 false——**不给肯定结论**；按文件大小与 mtime 缓存，装完不重启也能改态。
2. **两处事实分开给面板**：账本事实（`inLedger`，`client.ts` 传）答「接没接上」；装机读数（`installedVersion`／`panelRegistered`）答「装没装、重装有没有用」。老宿主没给 `panelRegistered` 时退回「装了没接上」，不猜成「没装」。
3. **装成功后重取目标表**：否则缺席卡会拿着挂载时那份读数继续说「未安装」，直到用户刷新页面（装上缺席包时最容易看到）。

### 这一版踩到的两个工具坑（别再踩）

1. **`tsc -b` 增量会让变异自证假绿**：改一处源码后 `tsc -b` 按 `.tsbuildinfo` 判「不必重编」，dist 里还是旧产物 ⇒ 测试读到的是**没被改坏**那一份，变异读数报绿，看着像「改坏了都不红」，其实什么都没改到。本席实测复现：给 dist 打标记 → `tsc -b` → 标记仍在；`tsc -b --force` → 标记被覆盖。**变异一律带 `--force`。**
2. **`cmd.exe` 读不了 LF 行尾的 `.cmd`**：本仓编辑工具写出的是 LF，`cmd.exe` 会**从错误偏移**读取（命令名被截首字母，报 `'_EXIT' is not recognized`）。要编排多步命令就用 node ＋ `spawnSync(..., { shell: true })`，别写 `.cmd`。

### 一条已知代价（留给裁定）

「产物缺注册」这一态对**四家 0.2.0** 是长期态：#723 那四家只要不发带注册代码的新版，用户就会一直看到「等它发新版」。本版照 #674 的裁定实现（这仍显著优于 0.2.5 之前的假话「未安装」），是否另起票追四家的注册接线，由 #723 那条线定。

## 八、版本号攒窗口发（经验，来自本票六轮真机迭代）

0.2.1 到 0.2.6 连着发了六版，每版都动真机（发布要人过 2FA／`dsh plugin add`／重启宿主／人工点验）。**只有阻塞主链的红值得单独发一版**，其余攒到一个窗口一起发：

- **阻塞主链的红**：功能在真机上走不通（0.2.3 的 404、0.2.5 的「点了必然失败」）⇒ 当版就发。
- **可攒的**：文案措辞、结果浮层交互、槽名归位 ⇒ 攒到下一版，跟「阻塞红」或下一次真机窗口一起发。

理由：本票每版的成本主要不在改代码，而在「人过 2FA ＋ 装真机 ＋ 重启宿主 ＋ 人工点验」这条人机协作链上；一版一发就是把这套成本乘以版数。
