### 真机三连（验收第 1 条：保存后重启宿主仍然在）

走的是面板按按钮时真正跑的那条路：插件宿主侧 `dist/bridge.js` → 技能 CLI 的配置 key。

```
MODE=真机（默认落点）
BEFORE:        path=C:\Users\辰辰洋洋\.ilife\calorie.yaml  db.name="calorie_data.db"  created=true
AFTER-SAVE:    写入 db.name="t676-reading.db"
ON-DISK-HAS-MARKER: true
AFTER-RESTART: 新进程读到 db.name="t676-reading.db"（created=false）
RESTORED:      db.name="calorie_data.db"
RESULT: PASS（改前有值 / 改后落盘 / 新进程仍在）
```

「新进程」＝宿主重启后要面对的局面：配置文件是唯一真相，值不在内存里、只在盘上。探针跑完把改过的那一项**还原**，不留痕。

### 变异自证（验收第 5 条：改坏一处必须变红、改回必须变绿）

改哪儿：`src/settings.ts` 的行表键 `key: 'db.name'` → `key: 'db.names'`（页面因此与技能侧配置表对不上）。

```
MUTANT-RED      fail=4 exit=1
RESTORED-GREEN  fail=0 exit=0 byteIdentical=true
```

**一处读数教训**：第一版探针只在改源码后直接跑测试，量到 `fail=0 exit=0`（假绿）——因为测试读的是 `dist/`，改 `src` 不重建量不到。探针已改成「改完先重建再跑」，两行读数才是上面这两行。
