## 二、测试迁移做了什么

新增两件基座（`packages/skill-calorie/test/helpers/`）：

- `config-test.mjs`：`calorieConfigDir(dir, extra?)`（写 `ILIFE_CONFIG_DIR` ＋ `<dir>/calorie.yaml`，
  默认 `db.dir=dir`、`xunji.stateDir=<dir>/xunji-state`；缺 `dir` 即响亮报错）、
  `freezeClock(iso)`（`--require test/freeze-clock.cjs` ＋ `FAKE_NOW_ISO`）、
  `pinProcessClock(iso)`（当刻进程＋子进程一起钉）、`configTestBase()`（模块级隔离基座）。
- `land-fixture.mjs`：**跨技能出口 fixture**——配置里的 `land.scheduleCli`／`land.memoCli` 指向它，
  它按 `T676_LAND_FIXTURE`（JSON）吐回执、按 `T676_LAND_FIXTURE_LOG` 留调用痕。

逐件迁移（机械部分由脚本做，特殊件手工改）：
`SKILLS_DB_PATH: X` → `ILIFE_CONFIG_DIR: calorieConfigDir(X)`；`CALORIE_TODAY: X` → `...freezeClock(X)`；
`CALORIE_PHOTOS_DIR: X` → 写进 yaml 的 `photos.dir`；模块级 `process.env.CALORIE_TODAY = X` →
`pinProcessClock(X)`；`CALORIE_FORCE_PROD`／六个挡板变量 → 删除；每件测试文件加一行模块级
`process.env.ILIFE_CONFIG_DIR = configTestBase()`（进程内调 dist 代码也要有隔离基座）。

**三处刻意的口径改变（影响 3 件挡板测试，见 §三「未做的事」）**：
训记那两步（推送／回写）走包内训记模块入口、本票没给它配出口，故那几件测试从「挡板全绿的结果页」
改成「没配 KEY 即确定性失败（`attempts: 0`，不调网）」——逐天读取、fail-fast、本地/远端分清这些
**契约仍然被断言**，只是不再有一条通往「成功结果页」的挡板路。
