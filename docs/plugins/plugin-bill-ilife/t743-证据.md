## 四处各自是什么（现象 → 根因 → 改法）

| # | 现象（维护者原话） | 根因（源码读数，非猜测） | 改法 |
| --- | --- | --- | --- |
| 1 | 「选择文件夹…」点了没反应 | 平台那次调用回的是**信封**不是路径：`@deepseek-ai/dsh-api-gateway/lib/client.js` 的 `invoke()` 是 `if (!result.ok) return {ok:false,error:…}; return {ok:true,value:result.value};`（失败不抛、成功也不回裸值）；第一方消费方 `@deepseek-ai/dsh-client-ui-workspace/lib/client.js:99-103` 就照信封拆。六家 `pickDirectory()` 写的是 `if (typeof picked === 'string' && …)` ⇒ 信封不是串，**一律判成「用户取消」**：不写值、不报错、按钮看着是死的；被拒那一路（组合里是 browse 后端）同样被吞 | `dsh-ctx.ts` 把 `DirectoryPickerFace.pick` 声明成信封回执 `DirectoryPickerAnswer`；`client.ts` 新增 `readPickAnswer(raw)` 归一三态（选中／取消／供不了），`pickDirectory` 只经它解；被拒时人话带上平台原话；等对话框期间给一行「已唤起系统文件夹对话框…」 |
| 2 | 「数据目录」没预填 | `db.dir` 那一行取值空着就是空的，用户得自己拼绝对路径；而落点技能早算好了（`base-link-core` 的 `configPaths()` → `join(configDir,'data')`，`ILIFE_CONFIG_DIR` 接管后同样逐字相同） | 行表加 `prefillFrom?: 'dataDir'`（只有 `db.dir` 标）；`toDraft(values, prefill)` 在取值空着时把回执里那条绝对路径直接显示出来；`dirty` 基线用同一个函数算 ⇒ 打开面板不会凭空变「未保存」 |
| 3 | 面板文案太长、带开发期口径 | 例：「库文件与备份的根目录。留空＝按默认落点（配置目录下的 data/），也就是改造前那个位置。」——「落点」「改造前那个位置」是仓内口径，不该写给用户 | 六家 57 处行文案换短句（≤2 句、≤40 字、零开发期口径词）；高级组副文案改「不常改。留空＝用默认值。」；页脚改「`<包名>` 本页只配置；<自家动词>在对话里说。」；报错人话去掉「先确认技能包已构建（packages/…/dist/…）」这类仓内路径 |
| 4 | 头部两行间距两家不一样 | 实测 3 : 3——{记账／卡路里／备忘录} 的 `info` 写了 `margin: '6px 0 0'`，{大厨／居家／作息} 没写，六家同形面破了 | 三家去掉 `margin`，六家对齐到「不写」（间距由标题的 `marginBottom` 与下方 `rows` 块决定，次级两行成一段落） |
